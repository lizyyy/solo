# 晨检用药管理系统 - 本地运行说明

## 项目概述
本系统用于解决幼儿园/小学晨检体温、用药嘱托和家长确认的数字化管理问题，避免纸质流转的混乱。

## 核心功能
1. **数据导入**：支持晨检CSV、用药授权JSON、班级名单上传
2. **智能分类**：自动将数据分为正常项、待确认项、失败项
3. **失败追踪**：失败记录保留原始字段和建议处理方式
4. **幂等性保证**：同一批材料再次提交不会重复生效
5. **隔离追踪**：发热隔离记录可从历史追踪来源批次和记录

## 业务规则覆盖
- ✅ **发热隔离**：体温≥37.3°C自动触发隔离，创建隔离记录
- ✅ **药品过期**：检查药品有效期，过期药品禁止使用
- ✅ **家长未确认**：未确认的用药授权进入待确认状态

## API接口说明

### 提交数据
```
POST /api/submit
Content-Type: multipart/form-data

参数：
- morning_check: 晨检CSV文件
- medicine_auth: 用药授权JSON文件
- class_list: 班级名单文件

返回格式：
{
  "code": 200,
  "message": "处理完成",
  "batch_id": 1,
  "summary": {
    "total": 8,
    "normal": 4,
    "pending": 1,
    "failed": 3
  },
  "data": {
    "normal_items": [...],
    "pending_items": [...],
    "failed_items": [
      {
        "student_id": "S002",
        "student_name": "李小红",
        "class_name": "一年级1班",
        "record_type": "morning_check",
        "original_data": {...},
        "rule_triggered": "发热隔离规则",
        "suggestion": "体温37.5°C，超过37.3°C警戒线..."
      }
    ]
  }
}
```

### 查询学生隔离历史（重点关注）
```
GET /api/isolation/student/{student_id}

返回：
{
  "code": 200,
  "data": {
    "student_id": "S002",
    "isolation_history": [
      {
        "id": 1,
        "temperature": 37.5,
        "source_batch_id": 1,      // 可追溯到提交批次
        "source_record_id": 2,     // 可追溯到具体记录
        "isolate_start": "2024-...",
        "is_active": true,
        "notes": "晨检体温异常: 37.5°C"
      }
    ],
    "is_currently_isolated": true
  }
}
```

### 其他接口
- `GET /api/batch/{batch_id}` - 查询指定批次处理结果
- `GET /api/batches?limit=10` - 查询最近提交批次列表

## 数据库结构
- `submission_batches`: 提交批次表，通过batch_hash实现幂等性
- `health_records`: 健康记录表，保存所有处理记录及原始数据
- `isolation_history`: 隔离历史表，关联source_batch_id和source_record_id实现溯源

## 关键技术点
1. **SHA256哈希**：计算提交内容哈希值，防止重复提交
2. **SQLAlchemy ORM**：数据持久化及关系管理
3. **规则引擎模式**：可扩展的业务规则校验
4. **原始数据保留**：失败项完整保存原始数据用于人工复核
