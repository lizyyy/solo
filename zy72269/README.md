# 水下管线巡检标记系统

> UNDERWATER PIPELINE INSPECTION MARKING SYSTEM

为设备工程师设计的专业巡检数据管理工具，完整保留原始备注，不将材料洗成干净数据。

---

## 核心设计原则

⚠️ **楼层剖面草图的备注经常比正式表还重要，设备工程师许工要求别把这些材料洗成一行干净数据。**

### 关键业务规则

1. **原始备注永不清洗** - 所有导入材料（手写备注、拍照记录、错口径标记）完整保留
2. **冲突不自动裁决** - 障碍物备注与楼层剖面草图矛盾时，仅列示冲突证据，由许工手动选择确认或驳回
3. **Z轴不自动修正** - 检测到可能按旧习惯写反时，仅标记"待现场复核"，留给现场班组确认
4. **四大自检必过** - 重复导入检测、Z轴方向检查、补录后重算、导出一致性校验

## 技术栈

- **前端框架**: React 18 + TypeScript
- **构建工具**: Vite 5
- **样式方案**: TailwindCSS 3
- **状态管理**: Zustand (支持本地持久化)
- **3D可视化**: Three.js + @react-three/fiber + @react-three/drei
- **路由**: React Router 7
- **数据解析**: SheetJS (Excel) + PapaParse (CSV)
- **数据持久化**: IndexedDB (Dexie.js) + LocalStorage
- **图表**: Recharts
- **导出**: jsPDF + xlsx

## 核心功能模块

### 1. 数据导入 (`/import`)

支持三种材料类型导入：

| 材料类型 | 说明 |
|---------|------|
| 正常材料 | 标准巡检数据 |
| 错口径材料 | 管径可能存在错误的数据 |
| 补录材料 | 后续补充录入的数据 |

**导入流程：**
```
选择材料类型 → 上传文件 → 预览数据 → 执行自检 → 确认导入
```

### 2. 路径回放 (`/replay`)

- 3D管线可视化展示
- 时间轴控制，支持播放/暂停/跳转
- 历史版本对比
- 点击标记点查看详情和原始备注

### 3. 冲突处理 (`/conflicts`)

> **重要：系统仅列示冲突证据，不自动裁决**

冲突类型：
- 障碍物不匹配
- 位置不匹配
- 管径不匹配

处理流程：
```
查看两边证据 → 许工手动选择确认/驳回 → 填写裁决理由 → 永久保存
```

### 4. Z轴复核 (`/abnormal`)

> **重要：Z轴方向按旧习惯写反时，别急着归正常，留给现场班组复核**

- 自动检测Z轴正方向异常（旧习惯向下为正，新标准向上为正）
- 异常记录标记为"待现场复核"
- 现场班组提交复核记录（姓名、结果、签字、照片）
- 只有复核确认后才更新坐标

### 5. 自检中心 (`/self-check`)

四大必检项：

| 检查项 | 说明 |
|--------|------|
| 重复导入检查 | 比较坐标精度到小数点后4位 |
| Z轴方向检查 | 检测是否按旧习惯写反 |
| 补录后重算 | 补录材料导入后自动重新计算路径 |
| 导出一致性检查 | 验证导出数据与系统数据一致 |

### 6. 报告导出 (`/report`)

- 支持 PDF 和 Excel 两种格式
- 可选是否包含原始备注数据
- 报告包含：巡检标记、冲突记录、Z轴复核、自检报告
- **强烈建议勾选"包含原始备注数据"**

### 7. 样例演示 (`/sample`)

新人学习指南，9步完整流程：
1. 创建巡检任务
2. 导入正常材料
3. 导入错口径材料
4. 导入补录材料
5. 查看路径回放
6. 处理冲突记录
7. 复核Z轴异常
8. 执行系统自检
9. 生成巡检报告

## 三步核心工作流

设备工程师许工按以下三步完成巡检标记处理：

### 第一步：第一次导入

数据录入员导入"水下管线巡检标记"原始材料
- 系统自动执行导入前自检
- **完整保留所有原始备注**，包括手写、照片、存疑备注

### 第二步：补看楼层剖面草图

设备工程师许工查看楼层剖面草图
- 系统自动检测障碍物备注与草图的冲突
- **列出冲突证据**（左侧巡检标记、右侧草图数据）
- **不自动裁决**，等待许工手动确认或驳回

### 第三步：路径回放更新

根据复核结果更新路径回放
- Z轴方向写反的记录**保持待复核状态**
- **不自动修正坐标**，留给现场班组确认
- 所有操作记录永久可追溯

## 开发规范

### 代码规范
- 组件文件 <= 300行，超出则拆分
- 类型定义优先使用TypeScript
- 工具函数使用纯函数写法
- 所有用户操作记录时间戳和操作人

### 状态管理规范
- 全局状态使用Zustand Store
- 组件本地状态使用useState/useReducer
- 派生状态使用useMemo计算

### 数据完整性规范
- 原始备注永不修改，仅追加
- 每次操作记录操作人和时间戳
- 导入数据前必须执行完整性校验
