# 保险犹豫期退保批处理系统

## 系统概述

专为保险客服处理犹豫期退保设计的批处理系统，自动化完成签收日期核对、回访记录检查、已扣费用核算，避免手工改表和截图。

## 核心特性

### 1. 数据校验
- **签收日期校验**: 自动核对签收日期，检测签收日期晚于申请日期的异常
- **回访记录检查**: 检查是否有回访记录、回访是否成功、是否有录音留痕
- **扣费流水核对**: 核对扣费记录，检测重复扣费和已扣费未退费情况

### 2. 版本管理
- **数据多版本**: 不直接覆盖前一版数据，保留历史版本
- **重复编号检测**: 检测重复的保单号和申请编号
- **晚到材料预警**: 标识延迟到达的材料

### 3. 异常优先暴露
- **签收日期争议**: 自动识别并高亮显示
- **已扣费未返**: 优先暴露资金风险
- **重复提交退保**: 检测重复申请，避免重复处理

### 4. 核心流程串联
- 犹豫期计算 → 退费重算 → 录音留痕 → 申请幂等 → 报告导出

### 5. 异常处理
- 不吞掉任何异常
- 即使暂时处理不了，也给出清楚的下一步操作建议

## 配置说明

编辑 `config.yaml` 自定义系统行为：

```yaml
surrender:
  cooling_off_days: 15                    # 犹豫期天数
  fee_deduction_rates:
    initial_fee: 0.10                     # 初始费用扣除比例
    management_fee: 0.05                  # 管理费用扣除比例

validation:
  require_sign_date: true                 # 是否必须有签收日期
  require_visit_record: true              # 是否必须有回访记录
  require_fee_record: true                # 是否必须有扣费记录
```

## 输出报告

运行完成后，报告将生成在 `data/output` 目录：

### Excel报告 (surrender_batch_YYYYMMDD_HHMMSS.xlsx)
包含以下工作表：

1. **批处理汇总**: 整体统计概览
2. **处理明细**: 每笔申请的详细处理情况
3. **异常清单**: 所有异常及其处理建议
4. **犹豫期分析**: 犹豫期使用情况分析
5. **退费明细**: 详细的退费计算明细
6. **数据版本**: 各数据源的版本信息

### CSV文件
- `处理明细.csv`
- `异常清单.csv`
- `犹豫期分析.csv`
- `退费明细.csv`

### 处理说明 (处理说明_YYYYMMDD_HHMMSS.txt)
- 关键异常的重点提醒
- 处理建议

## 异常类型说明

| 异常级别 | 说明 | 响应时效 |
|--------|------|---------|
| 严重 | 影响资金安全或合规性 | 24小时内处理 |
| 高 | 影响业务流程正常进行 | 3个工作日内处理 |
| 中 | 需要关注但不紧急 | 本周内处理 |
| 低 | 一般提醒 | 可在常规巡检中处理 |

### 常见异常及处理建议

1. **签收日期争议**
   - 问题：签收日期晚于申请日期
   - 建议：核实签收日期真实性，联系客户确认

2. **已扣费未退费**
   - 问题：保费已扣但尚未完成退费
   - 建议：优先处理退费流程，避免资金风险

3. **无回访记录**
   - 问题：保单无任何回访记录
   - 建议：立即安排回访并录音

4. **重复退保申请**
   - 问题：同一保单多次提交退保
   - 建议：以最新有效申请为准，标记重复申请

## 运行机制

### 批处理流程

1. **数据加载阶段**
   - 扫描输入目录，按文件名模式匹配
   - 按文件修改时间排序，保留多版本
   - 解析并验证数据格式

2. **流程构建阶段**
   - 按保单号关联所有数据
   - 构建完整的退保处理上下文

3. **核心计算阶段**
   - 计算犹豫期使用天数
   - 判断是否在犹豫期内
   - 计算应退金额和扣费明细

4. **异常检测阶段**
   - 检测14类异常
   - 按严重程度排序
   - 生成处理建议

5. **报告生成阶段**
   - 导出Excel多工作表报告
   - 导出CSV格式数据
   - 生成重点提醒文本报告

### 幂等性保证

系统通过申请编号和保单号的组合键来保证幂等性：
- 同一申请不会被重复处理
- 重复申请会被标记并提示人工确认

## 注意事项

1. **数据安全**: 请勿将真实的客户敏感数据提交到版本控制
2. **备份机制**: 重要数据请定期备份
3. **异常处理**: 所有异常都会被记录，不要忽略任何警告
4. **版本管理**: 输入文件会按时间戳保留，不会被覆盖
5. **人工审核**: 系统仅辅助处理，最终决策需人工确认

## 常见问题

**Q: 输入文件的列名必须严格按照规定吗？**
A: 系统支持中英文列名，如"保单号"和"policy_no"均可识别。

**Q: 可以处理部分缺失的数据吗？**
A: 可以，缺失数据会被标记为异常，在报告中提示补全。

**Q: 同一保单有多条签收记录怎么办？**
A: 系统会检测到并标记为异常，提示人工确认哪条有效。

**Q: 如何自定义犹豫期天数？**
A: 修改 config.yaml 中的 `cooling_off_days` 配置项。
