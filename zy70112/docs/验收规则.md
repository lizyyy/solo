# 农险灾损报案 API 验收规则

## 一、报案流程验收

### 1.1 报案创建
**验收标准：**
- 用户能创建报案草稿，必须包含：农户姓名、身份证号、手机号、保单号、作物类型、灾害类型、灾害发生时间
- 系统自动生成报案编号，格式为 `NBYYYYMMDDXXXX`
- 创建后自动记录第一条状态日志：从（无）到 `DRAFT`（草稿），操作人、原因、时间完整记录

**验收步骤：**
1. 调用 POST /api/reports 创建报案
2. 检查返回数据包含完整的报案信息和自动生成的报案号
3. 查看 status_logs 确认初始状态已记录

### 1.2 信息补全（草稿状态）
**验收标准：**
- 只有 DRAFT 状态可以修改基本信息、添加/删除地块、添加/删除天气证据、上传照片
- 提交后（SUBMITTED 及之后状态），基本信息锁定，只能查看不能修改
- 照片上传后自动创建版本记录，同类型照片多次上传自动增加版本号，只保留最新版本为激活状态

**验收步骤：**
1. 在 DRAFT 状态下修改农户信息，确认成功
2. 添加地块坐标和面积，确认关联到当前报案
3. 添加天气证据（气象数据），确认关联到当前报案
4. 上传照片，确认版本号自动递增
5. 将状态改为 SUBMITTED 后，尝试修改信息，确认失败

### 1.3 提交报案
**验收标准：**
- 提交前检查必备材料：
  - 至少有 1 个地块
  - 至少有 1 条天气证据
  - 至少有「灾害全景」和「作物特写」两类照片
- 提交后状态从 DRAFT 变为 SUBMITTED，状态日志记录完整

**验收步骤：**
1. 调用 GET /api/reports/:id/check-readiness 检查提交条件
2. 补齐所有材料后再次检查，确认 ready: true
3. 调用 POST /api/reports/:id/submit 提交
4. 确认状态变为 SUBMITTED，状态日志新增记录

## 二、照片版本管理验收

### 2.1 照片上传与版本
**验收标准：**
- 照片类型必须是预定义类型：灾害全景、作物特写、地块边界、灾害细节、对比照片
- 同一类型照片多次上传，版本号自动递增（1, 2, 3...）
- 只有最新版本的照片标记为 is_active = 1
- 历史版本照片保留在数据库中，可查询但不参与业务判断

**验收步骤：**
1. 上传一张「灾害全景」照片，确认 version = 1, is_active = 1
2. 再次上传同类型照片，确认 version = 2, is_active = 1，第一张 is_active = 0
3. 调用 GET /api/reports/:id/photos/all 查看所有版本历史

### 2.2 照片回滚
**验收标准：**
- 支持将某类照片回滚到指定历史版本
- 回滚后目标版本变为 is_active = 1，之后版本变为 is_active = 0
- 回滚操作不删除任何照片记录，只改变激活状态

**验收步骤：**
1. 确认某类照片已有多个版本
2. 调用 POST /api/reports/:id/photos/:photoType/rollback 指定回滚到版本 1
3. 确认版本 1 变为激活状态，版本 2+ 变为非激活

## 三、查勘派工验收

### 3.1 派工
**验收标准：**
- 只有 SUBMITTED 状态可以派工
- 派工必须指定查勘员 ID、查勘员姓名
- 派工后状态从 SUBMITTED 变为 DISPATCHED
- 状态日志记录：操作人、原因「派工给: 查勘员姓名」

**验收步骤：**
1. 在 SUBMITTED 状态调用 POST /api/reports/:id/dispatches 派工
2. 确认派工记录创建，状态变为 DISPATCHED
3. 检查状态日志完整记录

### 3.2 查勘完成
**验收标准：**
- 更新派工状态为 COMPLETED 时，报案状态自动变为 INSPECTED
- 支持记录实际查勘时间、备注信息

**验收步骤：**
1. 调用 PUT /api/dispatches/:id，设置 status = 'COMPLETED'
2. 确认报案状态变为 INSPECTED
3. 检查状态日志记录

## 四、赔付估算验收

### 4.1 估算计算
**验收标准：**
- 只有 INSPECTED 状态可以创建赔付估算
- 估算公式：受损面积 × 受损比例 × 单位价格
- 计算规则完整保存在 calculation_rules 字段中，包含：公式、所有参数、计算结果
- 不隐藏计算逻辑，便于后续复核

**验收步骤：**
1. 调用 POST /api/reports/:id/claims 创建赔付估算，传入：
   - affected_area_sqm: 受损面积（平方米）
   - damage_ratio: 受损比例（0-100）
   - unit_price: 单位价格
2. 检查返回的 estimated_amount 是否符合公式计算
3. 查看 calculation_rules 字段，确认公式和参数完整保存

### 4.2 赔付审批
**验收标准：**
- 只有 PENDING 状态的赔付可以审批
- 审批后状态变为 APPROVED
- 支持设置实际赔付金额（可与估算金额不同）
- 记录审批人、审批时间

**验收步骤：**
1. 调用 POST /api/claims/:id/approve 审批
2. 确认状态变为 APPROVED，actual_amount 已记录
3. 确认 approved_by、approved_at 已记录

## 五、状态流转规则验收

### 5.1 状态机验证
**验收标准：**
- 状态转换严格按以下规则执行，不允许跳步：
  - DRAFT → SUBMITTED
  - SUBMITTED → DISPATCHED / REJECTED
  - DISPATCHED → INSPECTED / REJECTED
  - INSPECTED → APPROVED / REJECTED
  - APPROVED → CLOSED
  - REJECTED → SUBMITTED / CLOSED
  - CLOSED → （不可转换）
- 任何非法转换都返回错误
- 每次状态变更都记录到 status_logs 表

**验收步骤：**
1. 创建报案，确认初始状态为 DRAFT
2. 尝试直接跳转到 INSPECTED，确认返回错误
3. 按正常流程依次转换状态，每次都检查状态日志
4. 确认 CLOSED 状态后无法继续转换

### 5.2 状态日志完整性
**验收标准：**
- 每条状态日志包含：
  - report_id: 关联报案
  - from_status: 源状态（初始状态为 null）
  - to_status: 目标状态
  - operator: 操作人
  - reason: 变更原因
  - timestamp: 变更时间
- 从报案创建到结案的完整链路可追溯

**验收步骤：**
1. 完成一个完整报案流程（创建 → 提交 → 派工 → 查勘 → 估算 → 审批 → 结案）
2. 查看该报案的所有 status_logs
3. 确认每个状态变更都有完整记录

## 六、数据关联关系验收

### 6.1 关联关系验证
**验收标准：**
- 一个报案（reports）可以关联：
  - 多个地块（plots）
  - 多条天气证据（weather_evidences）
  - 多张照片（photo_versions）
  - 多次派工记录（dispatches）
  - 多次赔付估算（claims）
  - 多条状态日志（status_logs）
- 所有关联通过 report_id 外键建立
- 查询报案详情时，自动聚合所有关联数据

**验收步骤：**
1. 为一个报案添加多个地块、多条天气证据、多类照片
2. 调用 GET /api/reports/:id 获取详情
3. 确认返回数据包含：
   - plots 数组
   - weather_evidences 数组
   - photos 数组（激活版本）
   - all_photos 数组（所有版本）
   - dispatches 数组
   - claims 数组
   - status_logs 数组
   - summary 对象（汇总统计）

### 6.2 汇总信息验证
**验收标准：**
- 每个报案的 summary 字段包含：
  - plot_count: 地块数量
  - weather_count: 天气证据数量
  - photo_count: 激活照片数量
  - latest_dispatch_status: 最新派工状态
  - latest_claim_status: 最新赔付状态
  - estimated_amount: 估算赔付金额

**验收步骤：**
1. 添加/删除关联数据
2. 每次操作后查看 summary 是否正确更新

## 七、导出功能验收

### 7.1 业务复核导出
**验收标准：**
- 导出格式支持 JSON 和 CSV
- CSV 导出包含中文列名，带 BOM 头，Excel 可直接打开
- 导出内容服务于业务复核，包含：
  - 报案基本信息
  - 关联数据统计（地块数、天气证据数、照片数）
  - 查勘信息（查勘员、状态、时间）
  - 赔付信息（估算金额、实际金额、受损面积、受损比例）
  - 状态变更历史（JSON 格式完整记录）
  - 详细关联信息（JSON 格式）

**验收步骤：**
1. 调用 GET /api/export/reports?format=csv 导出
2. 用 Excel 打开，确认中文字段名正确显示
3. 检查「状态变更历史」列包含完整的操作链路
4. 调用 GET /api/export/reports 导出 JSON 格式，确认数据完整

### 7.2 汇总统计导出
**验收标准：**
- GET /api/export/summary 返回：
  - 按状态统计：各状态报案数量
  - 赔付汇总：已审批赔付数量、估算总金额、实际总金额

**验收步骤：**
1. 创建多个处于不同状态的报案
2. 审批部分赔付
3. 调用汇总接口，确认统计数据正确

## 八、业务规则可复查性验收

### 8.1 规则配置
**验收标准：**
- 所有业务规则定义在配置文件中，不硬编码在逻辑里：
  - 合法作物类型
  - 合法灾害类型
  - 状态定义和中文映射
  - 照片类型
  - 状态转换规则
- 可通过 GET /config 接口查看当前配置

**验收步骤：**
1. 访问 GET /config
2. 确认返回所有业务配置项

### 8.2 规则检查接口
**验收标准：**
- GET /api/reports/:id/check-readiness 接口返回：
  - ready: 是否满足提交条件
  - missing: 缺少的材料明细（地块、天气证据、照片类型）
- 不通过临时变量判断，每次都基于实际数据重新计算

**验收步骤：**
1. 创建不完整的报案
2. 调用 check-readiness，确认 missing 正确标识缺少项
3. 补齐材料后再次调用，确认 ready 变为 true

## 九、串案防护验收

### 9.1 数据隔离
**验收标准：**
- 所有关联表都通过 report_id 严格关联
- 修改一个报案的照片不会影响其他报案
- 照片版本按 report_id + photo_type 独立计数

**验收步骤：**
1. 创建两个独立报案 A 和 B
2. 为 A 上传「灾害全景」照片
3. 为 B 上传「灾害全景」照片
4. 确认两个报案的照片版本号各自独立

### 9.2 状态锁定
**验收标准：**
- 状态 SUBMITTED 之后，不能修改基本信息、删除地块、删除天气证据
- 只能进行状态流转和补充操作（如派工、查勘、赔付）

**验收步骤：**
1. 将报案提交（SUBMITTED）
2. 尝试修改农户信息，确认失败
3. 尝试删除地块，确认失败
4. 尝试删除天气证据，确认失败
