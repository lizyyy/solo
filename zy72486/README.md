# 社区微循环公交 - 网格员巡查表管理系统

## 项目简介

"社区微循环公交"是专门为城更项目经理和网格员设计的巡查表管理系统。系统确保数据可溯源、过程可追溯、结论可复核。

## 核心功能

### ✅ 基础自检覆盖
- **重复导入检测**：自动识别完全重复的记录，包括批次内重复和跨批次重复
- **街道边界检测**：自动标记位于两个街道边界上的点位，留给项目经理复核
- **补录后重算**：所有修改都有记录，修改后状态自动同步到所有复用记录
- **导出一致性**：页面展示、接口返回、Excel 导出读取同一份数据源

### ✅ 跨批次复用与新增识别
- **重复上传检测**：第二次导入同一份巡查表时，自动查询数据库已有记录
- **复用记录标识**：已存在的记录标记为「复用」，继承已有处理状态、施工告示、复核结论
- **新增记录标识**：真正新增的记录标记为「新增」
- **状态同步**：修改源头记录后，所有批次中的复用记录自动同步更新

### ✅ 多维度导出报告
- **巡查明细 Sheet**：包含经度、纬度（支撑地图导出）、原始行号、来源、状态等24个字段
- **汇总报告 Sheet**：总记录数、待处理、需复核、已复核、边界点位、复用、新增等统计
- **边界点位专页 Sheet**：集中展示所有边界点位的来源、处理状态、结论、施工告示

### ✅ 数据溯源
- 保留原始 Excel 行号（`original_row_number`）
- 记录所有人工改动（`manual_edits` 字段）
- 变更日志（`change_logs` 表）记录每一次修改的字段、新旧值、操作人、时间、原因
- 原始结论和当前结论分开存储，永不覆盖

### ✅ 四步完整流程
1. **网格员巡查表第一次导入** → 系统自动自检（重复+边界）
2. **城更项目经理阿宁补看施工告示** → 补充施工告示，复核边界点位
3. **网格员巡查表第二次导入** → 自动识别复用记录与真新增
4. **地图导出更新** → 导出包含多Sheet、经纬度的完整报告

### ✅ 边界点位特殊处理
- 包含"交界、边界、路口、交叉口、转角、边"等关键词的地址自动标记
- 街道字段包含"、"的多街道点位自动标记
- 状态设为"需复核"（`needs_review`），不会自动归为正常

## 快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 启动服务

```bash
python app.py
```

服务将在 `http://localhost:5000` 启动

### 3. 体验完整流程

#### 第一步：导入巡查表
1. 打开浏览器访问 `http://localhost:5000`
2. 点击上传区域，选择 `samples/网格员巡查表样例.csv`
3. 系统自动检测：
   - 1条重复记录（第7行与第2行完全相同，批次内重复）
   - 3条边界点位（和平路口站、滨河路边界站、工业大道站）

#### 第二步：项目经理补看施工告示
1. 在记录列表中找到标记为"需复核"的边界点位记录
2. 点击"编辑"按钮
3. 补充"施工告示"信息，例如：
   - "工业大道站：2026年6月10日-6月12日道路半幅施工，公交临时停靠点向北迁移50米"
4. 操作人填写"阿宁"，修改原因填写"补看施工告示"
5. 状态改为"已复核"并填写复核意见：
   - "经核实施工告示内容属实，同意调整方案，边界点位责任暂由朝阳街道牵头协调"

#### 第三步：第二次导入同一份巡查表（验证复用）
1. 再次选择 `samples/网格员巡查表样例.csv` 上传
2. 系统自动识别：
   - 9条复用记录（继承第一次导入的状态、施工告示、复核结论）
   - 0条新增记录
   - 边界点位的复核状态已同步
3. 页面显示「复用」/「新增」标记，以及来源批次信息

#### 第四步：导出完整报告
1. 选择第二次导入的批次
2. 点击"导出 Excel"按钮
3. 导出的 Excel 包含3个Sheet：
   - **巡查明细**：24个字段，包含经度、纬度（可支撑地图导出）
   - **汇总报告**：统计总记录数、待处理、需复核、已复核、边界、复用、新增
   - **边界点位专页**：集中展示边界点位的来源、处理状态、结论、施工告示、复核意见

## 数据结构说明

### inspection_records 表（巡查记录表）

| 字段 | 说明 |
|------|------|
| original_row_number | 原始 Excel 行号 |
| import_batch_id | 导入批次号 |
| record_source | 记录来源：new_import/new_boundary/reused/batch_duplicate |
| is_reused | 是否复用记录（0/1） |
| reused_from_record_id | 复用来源记录ID |
| reused_from_batch_id | 复用来源批次号 |
| is_cross_batch_duplicate | 是否跨批次重复（0/1） |
| longitude | 经度（支撑地图导出） |
| latitude | 纬度（支撑地图导出） |
| original_conclusion | 原始巡查结论（永不修改） |
| current_conclusion | 当前结论（可修改） |
| status | 状态：pending/needs_review/reviewed/duplicate |
| is_boundary_point | 是否边界点位（0/1） |
| is_duplicate | 是否批次内重复（0/1） |
| manual_edits | 人工改动记录 JSON |
| construction_notice | 施工告示补录 |
| reviewer/review_time/review_comment | 复核信息 |

### change_logs 表（变更日志表）

记录每一次字段修改的完整历史，用于审计和回溯。

## API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/import | 导入巡查表 |
| GET | /api/records | 查询记录列表（支持 status、batch_id 过滤） |
| PUT | /api/records/:id | 更新记录 |
| GET | /api/records/:id/changes | 获取单条记录的变更历史 |
| GET | /api/batches | 获取导入批次列表 |
| GET | /api/export | 导出 Excel |
| GET | /api/stats | 获取统计数据 |

## 自检逻辑说明

### 重复检测
- 使用 MD5 哈希算法对每行所有字段生成指纹
- **批次内重复**：同一批次内指纹重复即标记为 `duplicate` 状态
- **跨批次重复**：导入前查询数据库已有记录指纹，匹配到即标记为复用记录，继承已有状态

### 边界点位检测
- 地址关键词匹配：交界、边界、路口、交叉口、转角、边
- 街道字段包含"、"表示属于多个街道
- 自动标记为 `needs_review`（需复核）状态，**不会自动归为正常**

### 复用记录同步
- 当修改一条记录时，所有复用该记录的其他批次记录自动同步更新
- 包括：current_conclusion、construction_notice、status、reviewer、review_time、review_comment
- 同步更新也会记录到 change_logs，便于审计

## 注意事项

1. **边界点位不会自动归为正常**：必须由项目经理人工复核后才能改为"已复核"状态
2. **原始结论永不覆盖**：修改只会更新 `current_conclusion`，`original_conclusion` 永远保留导入时的值
3. **所有修改可追溯**：每一次修改都会记录在 `change_logs` 表和 `manual_edits` 字段中
4. **导出数据与页面一致**：导出的 Excel 与页面展示、API 返回的数据来源完全一致
5. **复用记录自动同步**：修改源头记录后，所有批次中的复用记录会自动同步状态、施工告示、复核结论
6. **第二次导入自动识别**：重复上传同一份巡查表不会重复录入，而是标记为「复用」并继承已有处理结果
7. **导出包含经纬度**：Excel 导出包含经度、纬度字段，可直接支撑地图导出和可视化
