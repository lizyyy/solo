# 民宿保洁排班重试补偿队列服务

## 快速启动

### 1. 启动服务

```bash
# 方法一：使用启动脚本
chmod +x start.sh
./start.sh

# 方法二：手动执行
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python3 init_db.py
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

服务启动后访问：http://localhost:8000/docs 查看API文档

## 默认账号

| 角色 | 用户名 | 密码 | 权限说明 |
|------|--------|------|---------|
| 主管 | admin | admin123 | 全部权限，可创建用户、补偿入账、关闭记录、死信恢复 |
| 录入员 | entry | entry123 | 创建记录、查看记录 |
| 复核员 | reviewer | review123 | 创建记录、状态更新、重试入队、人工审核 |

## 数据源类型

| 数据源 | 枚举值 | 说明 |
|--------|--------|------|
| 订单日历 | order_calendar | 订单系统同步的日历数据 |
| 保洁群消息 | cleaning_group | 保洁工作群的消息记录 |
| 维修备注 | maintenance_note | 维修部门的备注信息 |

## 重试分类

| 分类 | 枚举值 | 说明 |
|------|--------|------|
| 房间冲突 | room_conflict | 房间时间安排冲突 |
| 布草更换 | linen_change | 连住换布草冲突 |
| 临时退房 | temp_checkout | 临时退房导致的保洁安排冲突 |
| 数据不一致 | data_mismatch | 新旧口径数据不一致 |
| 系统错误 | system_error | 系统处理错误 |
| 其他 | other | 其他原因 |

## CURL 命令顺序

### 第一步：获取Token

```bash
# 获取管理员Token
ADMIN_TOKEN=$(curl -s -X POST "http://localhost:8000/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=admin&password=admin123" | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")

# 获取录入员Token
ENTRY_TOKEN=$(curl -s -X POST "http://localhost:8000/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=entry&password=entry123" | python3 -c "import sys,json; print(json.load(sys.stdin)['access_token'])")
```

### 第二步：提交各类数据源记录

```bash
# 1. 提交订单日历记录
curl -X POST "http://localhost:8000/records" \
  -H "Authorization: Bearer $ENTRY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "source": "order_calendar",
    "source_id": "ORD20240115001",
    "room_no": "101",
    "guest_name": "张三",
    "checkin_date": "2024-01-15T14:00:00",
    "checkout_date": "2024-01-18T12:00:00",
    "cleaning_type": "daily",
    "is_continuous_stay": true,
    "linen_change": true,
    "price": 388.00,
    "content": "连住3天，第2天换布草"
  }'

# 2. 提交保洁群消息
curl -X POST "http://localhost:8000/records" \
  -H "Authorization: Bearer $ENTRY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "source": "cleaning_group",
    "source_id": "WX20240115_0830",
    "room_no": "102",
    "guest_name": "李四",
    "temp_checkout": true,
    "content": "客人临时退房，需要加急保洁"
  }'

# 3. 提交维修备注
curl -X POST "http://localhost:8000/records" \
  -H "Authorization: Bearer $ENTRY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "source": "maintenance_note",
    "source_id": "FIX20240115001",
    "room_no": "103",
    "content": "空调维修后需要深度清洁"
  }'

# 4. 提交手工改价表
curl -X POST "http://localhost:8000/records" \
  -H "Authorization: Bearer $ENTRY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "source": "manual_price",
    "room_no": "104",
    "price": 299.00,
    "content": "手工改价-会员折扣"
  }'
```

### 第三步：查看失败清单

```bash
# 查看所有失败记录（含验证失败）
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" \
  "http://localhost:8000/records/failed" | python3 -m json.tool

# 查看所有记录列表
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" \
  "http://localhost:8000/records?status=pending" | python3 -m json.tool
```

### 第四步：更新状态和分类

```bash
# 假设RECORD_ID是第一步返回的记录ID
RECORD_ID=1

# 更新状态为失败并标记重试分类
curl -X PUT "http://localhost:8000/records/$RECORD_ID/status" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "failed",
    "comment": "连住换布草冲突：退房保洁与续住布草更换时间重叠",
    "retry_category": "linen_change"
  }'
```

### 第五步：加入重试队列

```bash
# 将失败记录加入重试队列
curl -X POST "http://localhost:8000/records/$RECORD_ID/retry" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}'

# 查看重试队列
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" \
  "http://localhost:8000/retry-queue" | python3 -m json.tool
```

### 第六步：人工审核接管

```bash
# 人工审核通过
curl -X POST "http://localhost:8000/records/$RECORD_ID/review" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "comment": "已核实，可以重新安排",
    "approve": true,
    "retry_category": "room_conflict"
  }'
```

### 第七步：补偿入账

```bash
# 补偿入账
curl -X POST "http://localhost:8000/records/$RECORD_ID/compensate" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 150.00,
    "reason": "冲突导致的保洁加班费"
  }'
```

### 第八步：关闭记录

```bash
# 关闭记录
curl -X POST "http://localhost:8000/records/$RECORD_ID/close?comment=处理完毕" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

### 第九步：查看报表和导出

```bash
# 查看汇总报表
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" \
  "http://localhost:8000/reports/summary" | python3 -m json.tool

# 店长看板（主管权限）
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" \
  "http://localhost:8000/reports/manager-dashboard" | python3 -m json.tool

# 导出所有记录
curl -H "Authorization: Bearer $ADMIN_TOKEN" \
  "http://localhost:8000/reports/export" -o all_records.csv

# 导出失败记录
curl -H "Authorization: Bearer $ADMIN_TOKEN" \
  "http://localhost:8000/reports/export-failed" -o failed_records.csv
```

### 第十步：追溯单条记录完整轨迹

```bash
# 查看记录详情（含重试历史、补偿记录、操作日志）
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" \
  "http://localhost:8000/records/$RECORD_ID" | python3 -m json.tool

# 查看操作日志
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" \
  "http://localhost:8000/logs/record/$RECORD_ID" | python3 -m json.tool
```

## 死信处理和恢复

```bash
# 查看死信记录
curl -s -H "Authorization: Bearer $ADMIN_TOKEN" \
  "http://localhost:8000/records?status=dead_letter" | python3 -m json.tool

# 恢复死信记录（重置重试次数）
curl -X POST "http://localhost:8000/records/$RECORD_ID/revive?reset_retries=true" \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

3. 重新获取Token
4. 查看历史记录：`curl -s -H "Authorization: Bearer $ADMIN_TOKEN" "http://localhost:8000/records" | python3 -m json.tool`
5. 验证失败原因、人工意见、最终状态是否完整保留
