# 商业街外摆时段审批系统

阿宁和巡检员交接用的审批系统，别只靠口头约定。

---

## 快速开始

```bash
pnpm install
pnpm run dev
```

打开浏览器访问 `http://localhost:5173`

---

## 三步流程怎么走

就三步，别搞复杂了：

1. **第一步：导入无障碍坡道记录**
   - 把 Excel/CSV 拖进去就行
   - 系统自动检测同一小区有没有新旧两个名字
   - 有冲突的自动标红，别急着归正常

2. **第二步：阿宁补看夜间采样点**
   - 点进记录详情，找到「夜间采样点记录」那块
   - 点「阿宁补看」，填好采样点有没有、在哪、可信度多高
   - 新旧名称冲突不影响这步，可以先做

3. **第三步：给街道会看的摘要更新**
   - 采样点补看完了，就可以更摘要了
   - 摘要写清楚：坡道情况、采样点情况、有什么问题
   - 有名称冲突的，走完三步还要等巡检员确认名称，才算完

## 边界规则（代码里也写了，两边要一致）

### 📌 同一小区有新旧两个名字怎么判？

- **触发条件**：同一个地址/坐标对得上，但小区名字有两个版本
- **系统行为**：自动标记「待巡检员复核」，不会自动合并
- **阿宁你记着**：别自己删哪个名字，留给巡检员定
- **巡检员这边**：在记录详情页点「确认最终名称」，填好就生效
- **证据保留**：旧名新名都留着，`hasNameConflict` 标记也不删，以后查起来知道曾经有过争议

### 📌 三处数据怎么保证一致？

- **单一数据源**：页面展示、导出明细、接口返回，读的都是同一份 `approvalRecords`
- **修改入口唯一**：任何改动必须走 `updateRecord()` 那套逻辑，不许直接改数据
- **怎么验证**：在「摘要导出」页点「立即校验」，看哈希值对不对得上
- **不一致怎么办**：别强行导出，先找技术看数据

### 📌 改错了怎么回滚？

- 每一步操作都留了脚印，在记录详情页拉到「操作历史」
- 找到要回滚的那一步，点「回滚」，再确认一次就行
- 回滚操作本身也会记一笔，谁回滚的、回滚到哪了，都能查到
- 原始行号永远不变，回滚多少次都能追溯到最开始导入的那一行

### 📌 证据链怎么留？

每条记录永久保留：
- **原始行号**：`originalLineNumber`，导入后永不修改、永不删除
- **人工改动**：每次修改生成 `HistoryEntry`，含操作人、时间、修改前后值
- **处理状态**：状态变更时间线完整，谁改的、什么时候改的，一目了然
- **怎么查**：点进记录详情，往下拉就是完整证据时间线

### 📌 碰到拿不准的怎么办？

- 采样点和坡道记录对不上？→ 两边数据都留着，标个差异，巡检员现场去核
- 小区名字三个版本？→ 都存着，别删，巡检员最终确认
- 导出报错？→ 别硬导，先校验一致性

## 代码里的关键文件

| 文件 | 说明 |
|------|------|
| `src/types/index.ts` | 数据类型定义，改字段先改这 |
| `src/store/useAppStore.ts` | 状态管理，所有数据修改逻辑在这 |
| `src/data/boundaryRules.ts` | 边界规则文案，和 README 同步更新 |
| `src/utils/export.ts` | 导出逻辑，三处一致性校验在这 |
| `src/data/mockRecords.ts` | 演示数据，正式上线前删掉或换成接口 |

## 角色权限说明

| 角色 | 能做什么 |
|------|----------|
| **城更项目经理（阿宁）** | 导入记录、补看采样点、更新摘要、回滚操作 |
| **市政巡检员** | 确认新旧名称、复核最终状态、追溯证据、回滚操作 |
| **街道审批人员** | 看摘要、导明细 |

## 技术栈

- React 18 + TypeScript

- Zustand 状态管理

- xlsx + papaparse 处理导入导出
