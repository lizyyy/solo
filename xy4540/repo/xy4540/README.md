# 景区公厕保洁风险管控系统

## 项目简介

这是一个本地桌面应用，用于景区公厕保洁主管日常风险管控工作。系统整合多种数据源，自动识别风险点，支持人工改判和本地保存，并能导出交接单和审计明细。

## 功能特性

### 数据导入
- **巡检记录 (CSV)**: 厕位巡检二维码扫描记录
- **传感器数据 (JSONL)**: 氨气浓度、客流传感器数据
- **清掏记录 (JSON)**: 化粪池清掏车到场记录
- **投诉记录 (JSON)**: 游客异味投诉记录

### 风险识别规则
系统自动识别以下5类风险：

1. **漏巡风险**
   - 巡检间隔超过预设阈值（默认60分钟）
   - 早间首检延迟
   - 风险等级：中/低

2. **异味超阈风险**
   - 氨气浓度连续3个周期超过阈值（默认25ppm）
   - 风险等级：高（>37.5ppm）/ 中（>25ppm）
   - 建议措施：暂停开放 / 加派保洁

3. **客流突增未补给风险**
   - 单小时客流超过阈值（默认50人）
   - 早晚高峰时段加倍关注
   - 风险等级：高/中
   - 建议措施：加派保洁

4. **清掏逾期风险**
   - 距离上次清掏超过预设周期（默认30天）
   - 逾期7天以上升级为高风险
   - 风险等级：高/中
   - 建议措施：安排清掏

5. **重复投诉风险**
   - 2小时内收到2起及以上投诉
   - 单日收到3起及以上投诉
   - 异味投诉升级为高风险
   - 风险等级：高/中
   - 建议措施：加派保洁

### 人工改判与备注
- 支持人工改判系统建议措施
- 支持添加备注信息
- 改判和备注本地持久化保存
- 支持标记已处理

### 导出功能
- **Markdown 交接单**: 按风险等级分类展示，适合交接班使用
- **JSON 审计明细**: 完整的审计数据，包含原始数据摘要

## 验证流程

### 快速验证（使用示例数据）

1. **启动应用**
```bash
python main.py
```

2. **加载示例数据**
   - 点击界面右上角的 **"加载示例数据"** 按钮
   - 弹出提示框显示"示例数据已加载"

3. **开始风险分析**
   - 确认分析日期为 `2026-05-05`（示例数据的日期）
   - 点击 **"开始风险分析"** 按钮
   - 系统提示检测到的风险数量

4. **验证风险识别**
   检查风险列表中是否包含以下类型的风险：

   - **漏巡风险**: 东门入口公厕 (T001) 在 10:00-12:30 之间有2.5小时的巡检间隔
   - **异味超阈风险**: 东门入口公厕 (T001) 早高峰、午间、晚高峰都有连续超标的情况
   - **客流突增风险**: 中心广场公厕 (T002) 午间时段客流超过80人阈值
   - **清掏逾期风险**: 
     - 北门停车场公厕 (T003) 上次清掏 2026-03-15，已逾期50天（周期30天）
     - 山顶观景台公厕 (T004) 上次清掏 2026-02-01，已逾期93天（周期45天）
   - **重复投诉风险**:
     - 东门入口公厕 (T001) 8:15、8:30、9:00 连续收到投诉
     - 中心广场公厕 (T002) 单日收到4起投诉
     - 北门停车场公厕 (T003) 晚高峰收到3起投诉

5. **使用筛选功能**
   - 尝试按 **公厕** 筛选（选择"中心广场公厕"）
   - 尝试按 **风险类型** 筛选（选择"异味超阈"）
   - 尝试按 **风险等级** 筛选（选择"高风险"）
   - 观察表格内容的变化

6. **查看风险详情**
   - 点击任意一行风险记录
   - 右侧面板显示完整风险信息：
     - 基本信息（风险ID、公厕、时段、等级等）
     - 详细描述
     - 措施信息（系统建议、人工改判、最终措施）
     - 备注
     - 原始数据摘要

7. **人工改判**
   - 选择一条风险记录
   - 在"改判措施"下拉框选择一个选项（如"暂停开放"）
   - 在"备注"框输入一些文字（如"已安排保洁人员前往处理"）
   - 点击 **"保存改判"** 按钮
   - 观察表格中"最终措施"列的变化

8. **标记已处理**
   - 选择一条已处理的风险记录
   - 点击 **"标记已处理"** 按钮
   - 观察该行文字变为灰色斜体

9. **导出交接单**
   - 点击 **"导出 Markdown 交接单"** 按钮
   - 选择保存位置和文件名
   - 打开导出的文件查看内容，确认包含：
     - 风险概览表格
     - 高/中/低风险详情（按等级分类）
     - 交接说明

10. **导出审计明细**
    - 点击 **"导出 JSON 审计明细"** 按钮
    - 选择保存位置和文件名
    - 打开导出的文件查看内容，确认包含：
      - 导出时间
      - 数据源统计
      - 完整的风险列表（含原始数据）
      - 统计信息

### 完整验证（使用自有数据）

1. **准备数据文件**

   **巡检记录 CSV 格式**:
   ```csv
   toilet_id,station_id,inspect_time,inspector,status,notes
   T001,S001,2026-05-05 06:00:00,张三,正常,
   T001,S001,2026-05-05 07:00:00,张三,正常,
   ```
   字段说明：
   - `toilet_id`: 公厕编号
   - `station_id`: 厕位编号
   - `inspect_time`: 巡检时间（格式：YYYY-MM-DD HH:MM:SS）
   - `inspector`: 巡检人员
   - `status`: 巡检状态（正常/异常）
   - `notes`: 备注

   **传感器数据 JSONL 格式**:
   ```json
   {"toilet_id": "T001", "timestamp": "2026-05-05T06:00:00", "ammonia_level": 15.5, "passenger_flow": 10}
   {"toilet_id": "T001", "timestamp": "2026-05-05T06:15:00", "ammonia_level": 18.2, "passenger_flow": 12}
   ```
   字段说明：
   - `toilet_id`: 公厕编号
   - `timestamp`: 记录时间（格式：YYYY-MM-DDTHH:MM:SS）
   - `ammonia_level`: 氨气浓度（ppm）
   - `passenger_flow`: 客流人数

   **清掏记录 JSON 格式**:
   ```json
   [
     {
       "toilet_id": "T001",
       "arrival_time": "2026-04-01 08:00:00",
       "truck_id": "QT-001",
       "volume_emptied": 12.5,
       "notes": "正常清掏"
     }
   ]
   ```
   字段说明：
   - `toilet_id`: 公厕编号
   - `arrival_time`: 清掏车到达时间
   - `truck_id`: 清掏车编号
   - `volume_emptied`: 清掏体积（立方米）
   - `notes`: 备注

   **投诉记录 JSON 格式**:
   ```json
   [
     {
       "toilet_id": "T001",
       "complaint_time": "2026-05-05 08:15:00",
       "complaint_type": "异味",
       "description": "卫生间异味很大",
       "reporter": "游客王先生"
     }
   ]
   ```
   字段说明：
   - `toilet_id`: 公厕编号
   - `complaint_time`: 投诉时间
   - `complaint_type`: 投诉类型（异味/卫生/设施）
   - `description`: 投诉描述
   - `reporter`: 投诉人

2. **导入数据**
   - 点击对应类型的导入按钮
   - 选择准备好的数据文件
   - 确认导入成功提示

3. **分析和操作**
   - 参考"快速验证"步骤3-10

## 配置说明

公厕配置在 `main.py` 的 `_load_default_toilets` 方法中定义，可根据实际情况调整：

```python
{
    "T001": ToiletInfo(
        toilet_id="T001",
        name="东门入口公厕",
        location="景区东门入口处",
        total_stalls=12,
        inspection_interval_minutes=60,   # 巡检间隔（分钟）
        emptying_cycle_days=30,           # 清掏周期（天）
        ammonia_threshold=25.0,            # 氨气阈值（ppm）
        peak_flow_threshold=50             # 客流阈值（每小时）
    )
}
```

## 本地存储

应用会自动将风险分析结果（包含人工改判和备注）保存到 `local_data.json` 文件中。下次启动应用时会自动加载。

## 风险等级颜色说明

- **高风险**: 红色背景 (#FFC8C8)
- **中风险**: 黄色背景 (#FFF0C8)
- **低风险**: 绿色背景 (#E6FFE6)
- **已处理**: 灰色斜体文字

## 常见问题

**Q: 为什么没有检测到风险？**
- 请确认数据文件的时间格式是否正确
- 请确认分析日期设置正确
- 请确认数据中确实存在风险条件

**Q: 如何调整风险识别阈值？**
- 修改 `main.py` 中对应公厕的 `ToiletInfo` 配置
- 或者修改 `risk_engine.py` 中的规则逻辑

**Q: 数据导入后可以再次导入吗？**
- 可以，新导入的数据会追加到现有数据中
- 重新分析时会使用全部已导入的数据
