# 压载水换舱记录复核工具

一个本地桌面GUI工具，供船务安全员在靠港前复核压载水换舱记录使用。

## 功能特性

- 📥 **多格式数据导入**：支持航次计划CSV、压载舱传感器JSONL、海区规则YAML、人工记录JSON
- 📊 **时间线重建**：整合传感器数据和人工记录，重建每个压载舱的换舱时间线
- 🔍 **风险检测**：自动检测以下风险类型：
  - 海区违规排放
  - 排放量超标
  - 传感器断采
  - 人工记录冲突
  - 泵阀状态冲突
  - 缺失传感器数据
  - 跨时区问题
- 🎯 **风险筛选**：支持按风险等级、类型、确认状态筛选
- ✅ **人工确认**：支持对检测到的问题进行人工确认并添加备注
- 💾 **持久保存**：自动保存分析状态
- 📤 **报告导出**：支持导出 issues.csv 和 ballast_report.md

## 边界处理

- **跨时区航次**：自动识别和处理多时区数据
- **缺失传感器**：检测并报告缺失传感器数据的压载舱

## 安装与启动

### 环境要求

- Python 3.8+
- tkinter（Python内置，通常随Python一起安装）

### 步骤

1. **安装依赖**

```bash
cd /path/to/zy8208
pip install -r requirements.txt
```

2. **启动程序**

```bash
python main.py
```

## 使用流程

### 快速开始（使用示例数据）

1. 启动程序后，点击菜单栏的 **文件** → **加载示例数据**
2. 或者在概览页点击 **📦 加载示例数据** 按钮
3. 点击 **🔍 执行完整分析** 按钮
4. 查看检测到的风险问题
5. 对问题进行人工确认
6. 导出报告

### 详细流程

#### 1. 导入数据

可以通过以下方式导入数据：

- **航次计划 CSV**：包含船舶信息、出发港、目的港、航点等
- **传感器数据 JSONL**：压载舱的液位、温度、密度、体积等实时数据
- **海区规则 YAML**：各海区的压载水排放规则
- **人工记录 JSON**：船员手动记录的换舱操作

#### 2. 执行分析

1. **重建时间线**：整合传感器数据和人工记录，创建每个压载舱的操作时间线
2. **检测风险**：根据海区规则和操作记录，自动检测潜在风险

#### 3. 查看与筛选风险

- **风险等级**：严重、高、中、低
- **风险类型**：海区违规、排放量超标、传感器断采等
- **确认状态**：未确认、已确认

#### 4. 人工确认问题

1. 在风险问题列表中选择一个问题
2. 查看问题详情
3. 输入确认人姓名和备注
4. 点击 **✅ 确认问题** 按钮

#### 5. 导出报告

支持导出以下文件：

- **issues.csv**：所有风险问题的详细列表
- **ballast_report.md**：完整的压载水换舱复核报告
- **analysis_state.json**：分析状态（用于后续恢复）

## 示例数据说明

示例数据模拟了一个从新加坡到上海的航次（VOY-2026-05-001），包含以下场景：

### 航次信息

- **船舶**：Ocean Star
- **航线**：新加坡 → 南海 → 越南近岸 → 台湾海峡 → 上海
- **时长**：2026-04-25 至 2026-05-05

### 包含的风险场景

1. **传感器断采**：部分时间段传感器数据缺失
2. **跨时区数据**：航次穿越UTC和中国标准时区（CST_CHINA）
3. **缺失传感器**：部分压载舱（如BW-05至BW-12等）无传感器数据
4. **海区违规风险**：部分排放操作发生在限制区域
5. **人工记录**：包含船员手动记录的泵阀操作

## 数据格式说明

### 航次计划 CSV

```csv
voyage_id,vessel_name,departure_port,departure_time,arrival_port,arrival_time,waypoints,timezone
VOY-2026-05-001,Ocean Star,Singapore,2026-04-25T08:00:00,Shanghai,2026-05-05T14:00:00,"[{""lat"": 1.3521, ...}]",UTC
```

### 传感器数据 JSONL

每行一个JSON对象：

```json
{
  "timestamp": "2026-04-25T08:00:00",
  "tank_id": "BW-01",
  "level": 85.5,
  "temperature": 28.5,
  "density": 1.025,
  "volume": 8550.0,
  "status": "normal",
  "timezone": "UTC"
}
```

### 海区规则 YAML

```yaml
zones:
  - zone_id: "ZONE-001"
    zone_name: "新加坡港内及近岸"
    description: "新加坡港及近岸50海里范围内，禁止排放压载水"
    latitude_min: 1.0
    latitude_max: 2.0
    longitude_min: 103.5
    longitude_max: 104.2
    max_discharge_volume: 0.0
    is_prohibited: true
```

### 人工记录 JSON

```json
{
  "records": [
    {
      "record_id": "REC-001",
      "timestamp": "2026-04-25T10:00:00",
      "tank_id": "BW-01",
      "operation_type": "DISCHARGE_START",
      "volume": 8540.0,
      "operator": "张船长",
      "pump_status": "RUNNING",
      "valve_status": "OPEN",
      "notes": "开始排放压载水",
      "timezone": "UTC"
    }
  ]
}
```

## 风险类型说明

| 风险类型 | 说明 | 风险等级 |
|----------|------|----------|
| 海区违规排放 | 在禁止排放区域进行排放操作 | 严重 |
| 排放量超标 | 排放量超过海区限制 | 高 |
| 传感器断采 | 传感器数据中断超过阈值 | 高/严重 |
| 人工记录冲突 | 人工记录与传感器数据不一致 | 高 |
| 泵阀状态冲突 | 泵阀状态与实际操作不一致 | 中 |
| 缺失传感器数据 | 压载舱无传感器数据 | 高 |
| 跨时区问题 | 同一舱存在多时区数据 | 中 |

## 常见问题

### Q: 程序无法启动？

A: 请检查：
1. Python版本是否为3.8+
2. 是否已安装依赖 `pip install -r requirements.txt`
3. tkinter是否可用（Python通常内置）

### Q: 如何添加自定义数据？

A: 参考示例数据格式，创建对应格式的文件，然后通过程序的导入功能加载。

### Q: 导出的文件在哪里？

A: 默认保存在 `output/` 目录下。
