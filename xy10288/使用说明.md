# 乡镇集市摊位抽签器 使用说明

## 📋 系统概述

这是一套专为乡镇集市设计的摊位分配管理系统，兼顾老摊主权益、品类相邻约束和公平抽签原则。系统支持：
- 摊主名单管理（区分老/新摊主）
- 摊位布局配置
- 品类相邻约束规则
- 公平随机抽签算法
- 结果冻结与申诉机制
- 工作区持久化（刷新不丢失）
- 数据导出功能

---

## 📝 标准操作流程

### 步骤 1：管理品类约束

进入 **"📦 品类约束"** 标签页：

1. **添加品类**：
   - 点击 **"➕ 添加品类"**
   - 输入品类名称（如：蔬菜、水果、服装、水产、熟食）
   - 点击保存

2. **设置相邻约束**：
   - 点击 **"🔗 添加约束"**
   - 选择两个不能相邻的品类（如：水产 和 服装）
   - 点击保存
   - 常见约束建议：
     - 水产 ↔ 服装（气味影响）
     - 熟食 ↔ 水产（卫生考虑）
     - 蔬菜 ↔ 水果（可根据实际情况）

### 步骤 2：管理摊主名单

进入 **"👥 摊主名单"** 标签页：

1. 点击 **"➕ 添加摊主"**
2. 填写信息：
   - **姓名**：必填
   - **联系电话**：选填
   - **经营品类**：必须从已添加的品类中选择
   - **摊主类型**：老摊主 / 新摊主
3. 点击保存
4. 重复添加所有摊主

**统计卡片**：实时显示总摊主数、老摊主数、新摊主数、品类数

### 步骤 3：配置摊位

进入 **"🏠 摊位管理"** 标签页：

1. 点击 **"➕ 添加摊位"**
2. 填写信息：
   - **摊位编号**：必填（如：A1、A2、B1）
   - **区域**：选填（如：东区、西区）
   - **位置**：必填（顺序数字，用于判断相邻关系）
3. 点击保存

**注意**：位置编号决定了相邻关系。例如：
- 位置 1 和位置 2 相邻
- 同一区域内的摊位才会判断相邻

### 步骤 4：执行抽签

进入 **"🎲 抽签"** 标签页：

#### 4.1 配置抽签规则（可默认）

- **老摊主优先**：勾选后老摊主优先分配摊位
- **品类相邻约束**：勾选后会检查并避免违规相邻
- **随机打乱**：勾选后会随机打乱抽签顺序

#### 4.2 抽签前检查

1. 点击 **"🔍 开始检查"**
2. 系统会自动检查：
   - ✅ 摊主是否添加
   - ✅ 摊位是否配置
   - ✅ 品类是否完整
   - ⚠️ 数量是否匹配
   - ⚠️ 是否有约束配置
3. 如有错误，返回修复；如有警告，可忽略或调整

#### 4.3 开始抽签

1. 点击 **"🎲 开始抽签"**
2. 观察抽签过程日志：
   - 📌 步骤说明
   - ℹ️ 配置信息
   - ✓ 分配成功
   - ⚠ 无法分配

3. 抽签完成后，系统会显示：
   - 成功分配数量
   - 未分配数量
   - 剩余摊位数量

### 步骤 5：查看与处理结果

进入 **"📋 结果"** 标签页：

#### 5.1 查看分配详情

表格显示：
- 摊位编号和区域
- 摊主姓名和经营品类
- 摊主类型（老/新）
- 相邻品类（用于检查约束）
- 状态（正常/待复核）

#### 5.2 标记申诉

1. 找到需要申诉的记录
2. 点击 **"申诉"** 按钮
3. 填写申诉原因
4. 点击 **"标记为待复核"**

待复核的记录会：
- 高亮显示（黄色背景）
- 状态变更为"待复核"
- 统计在"待申诉"数量中

#### 5.3 冻结结果

确认结果无误后：
1. 点击 **"🔒 冻结结果"**
2. 确认冻结
3. 冻结后：
   - 无法修改分配结果
   - 无法发起申诉
   - 显示冻结提示条
   - 如需修改，点击 **"🔓 解冻结果"**

### 步骤 6：数据导出

进入 **"📤 导出"** 标签页：

#### 导出选项

| 导出类型 | 格式 | 内容 |
|---------|------|------|
| 摊主名单 | CSV | 所有摊主详细信息 |
| 摊位信息 | CSV | 所有摊位配置 |
| 抽签结果 | CSV | 最终分配结果 |
| 完整工作区 | JSON | 全部数据（可导入恢复） |

#### 导入工作区

1. 点击 **"选择文件"**
2. 选择之前导出的 JSON 文件
3. 点击 **"导入"**
4. 确认覆盖当前工作区

## 🔧 核心功能说明

### 品类相邻约束算法

系统在分配时会检查：
1. 同一区域内的相邻摊位（位置号±1）
2. 如果相邻摊位已有分配，检查品类约束
3. 如果冲突，跳过该摊位，尝试下一个

### 老摊主优先机制

当启用"老摊主优先"时：
1. 先分配所有老摊主
2. 再分配新摊主
3. 保持老摊主的相对稳定性

### 公平随机算法

使用 Fisher-Yates 洗牌算法：
- 确保每个摊主有平等的机会
- 可复现性：相同配置下，每次结果不同（公平性）

### 本地存储

- 使用浏览器 LocalStorage
- 刷新页面后自动恢复
- 所有操作自动保存

## ⚠️ 注意事项

1. **数据备份**：定期导出完整工作区作为备份
2. **浏览器兼容性**：建议使用 Chrome、Firefox、Safari 最新版本
3. **清除数据**：点击"🗑️ 清空全部"会删除所有数据，请谨慎操作
4. **冻结不可逆**：冻结后需要解冻才能修改，建议确认无误后再冻结
5. **位置编号**：相邻判断依赖位置编号，同一区域内连续编号

## 📊 统计指标说明

### 摊主统计
- 总摊主数：已添加的所有摊主
- 老摊主数：标记为"老摊主"的数量
- 新摊主数：标记为"新摊主"的数量
- 品类数：已配置的品类总数

### 摊位统计
- 总摊位数量：已配置的所有摊位
- 可用摊位：状态为"可用"的摊位
- 已分配摊位：状态为"已分配"的摊位

### 结果统计
- 分配总数：抽签成功分配的数量
- 老摊主：分配成功的老摊主数量
- 新摊主：分配成功的新摊主数量
- 待申诉：标记为待复核的记录数量

## ❓ 常见问题

**Q: 为什么有些摊主没有分配到摊位？**
A: 可能原因：1) 摊主数量 > 摊位数量；2) 约束太严格，找不到合适位置；3) 摊位位置配置有问题。

**Q: 如何修改已分配的结果？**
A: 如果结果未冻结，可以重新抽签覆盖；如果已冻结，需要先解冻，再重新抽签。

**Q: 数据存储在哪里？**
A: 存储在浏览器的 LocalStorage 中，清除浏览器数据会丢失。建议定期导出备份。

**Q: 可以在手机上使用吗？**
A: 可以，系统做了响应式设计，支持手机和平板访问。

**Q: 如何导入之前备份的数据？**
A: 在"导出"标签页，选择之前导出的 JSON 文件，点击导入即可。
