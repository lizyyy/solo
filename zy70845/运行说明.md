# 便利店运营数据统一处理平台 - 本地运行说明

## 项目概述

本项目解决便利店运营数据导入混乱问题，统一处理货架盘点、销售数据、补货单，进行标准化校验和分类。

## 功能特性

- ✅ 支持 CSV/JSON 多格式文件上传
- ✅ 业务规则校验（少补/多补校验、临期品校验、SKU别名映射）
- ✅ 数据分类返回（正常项、待确认项、失败项）
- ✅ 失败记录保留原始字段和处理建议
- ✅ 幂等处理机制（同批次号重复提交不重复生效）
- ✅ 点位编号支持

## 快速开始

```bash
npm run dev
```

后端API: `http://localhost:4000`

## 使用样例数据测试

项目根目录提供了3个样例数据文件：

1. **sample-inventory.csv** - 货架盘点数据
   - 包含正常商品、临期商品、格式错误的数量

2. **sample-sales.json** - 销售数据
   - 包含SKU别名（如"可乐"映射到"可口可乐500ml"）

3. **sample-replenishment.csv** - 补货单数据
   - 包含少补（低于预期销量30%）、多补（超出预期销量3倍）情况

### 测试步骤：

1. 访问 `http://localhost:5173`
2. 确认批次号（如：BATCH-123456）和点位编号（如：STORE-001）
3. 分别上传三个样例文件：
   - 盘点数据 (CSV): 选择 `sample-inventory.csv`
   - 销售数据 (JSON): 选择 `sample-sales.json`
   - 补货单 (CSV/JSON): 选择 `sample-replenishment.csv`
4. 点击"开始处理"按钮

### 预期结果：

- **正常项**: 格式正确且符合业务规则的记录
- **待确认项**: 临期商品、少补/多补预警、SKU未找到映射
- **失败项**: 数量格式错误等严重问题（保留原始数据+处理建议）

## 业务规则说明

### 1. SKU别名映射

系统内置别名映射表，自动识别商品别名：

| 标准SKU | 标准名称 | 别名示例 |
|---------|----------|----------|
| SKU001 | 可口可乐500ml | 可乐、可口可乐、Coca-Cola |
| SKU002 | 百事可乐500ml | 百事、Pepsi |
| SKU003 | 农夫山泉550ml | 矿泉水、饮用水 |
| SKU004 | 康师傅红烧牛肉面 | 方便面 |
| SKU005 | 乐事薯片原味75g | 薯片、乐事薯片、Lays |

### 2. 少补/多补校验

- **少补**: 补货量 < 预期销量的 30%
- **多补**: 补货量 > 预期销量的 3 倍

### 3. 临期品校验

- 距过期日期 < 30 天 → 待确认
- 已过期 → 失败

## 幂等机制

使用相同批次号（Batch ID）重复提交时，系统会直接返回历史处理结果，不会重复处理数据。

测试方式：
1. 第一次提交数据，记录返回的批次号
2. 使用相同批次号再次提交
3. 查看返回结果顶部的黄色提示"该批次已处理过，返回历史结果"

## API接口

### 数据导入

```
POST /api/import
Content-Type: multipart/form-data

参数:
- batchId: 批次号
- storeId: 点位编号
- inventoryCsv: 盘点CSV文件 (可选)
- salesJson: 销售JSON文件 (可选)
- replenishmentForm: 补货单文件 (可选，支持CSV/JSON)
```

### 查询批次结果

```
GET /api/import/batch/:batchId
```

### 获取所有批次列表

```
GET /api/import/batches
```

## 常见问题

### Q: 如何添加新的SKU别名？

A: 编辑 `api/services/ruleEngine.ts` 中的 `skuAliasMap` 数组。

### Q: 如何调整校验阈值？

A: 编辑 `api/services/ruleEngine.ts` 中对应的规则参数。

### Q: 数据是否持久化存储？

A: 当前为演示版本使用内存存储，重启后数据会清空。生产环境建议接入数据库。
