# 铁路检修天窗排程 CLI

## 安装运行

```bash
npm install
npm run build
```

可执行文件位于 `dist/index.js`，或者使用以下命令运行：

```bash
npm run dev -- [命令] [参数]
```

## 样例入口

项目包含 `sample-data.json` 样例数据，覆盖：
- 3 个工区（郑州、许昌、开封）
- 5 个封锁区段（京广线、陇海线）
- 9 项资源（人员、机械、材料）
- 4 个天窗（昼间/夜间）
- 6 个检修任务（包含冲突场景）

## 核心操作

### 1. 导入数据

```bash
npm run dev -- import sample-data.json
```

- 支持重复导入，相同 ID 自动更新
- 自动校验引用关系（资源必须属于存在的工区）

### 2. 运行排程

```bash
npm run dev -- run
```

- 首次运行执行排程
- 重跑时自动清理上次排程结果，避免数据膨胀
- 如需强制重跑：`npm run dev -- run --force`

### 3. 查看状态

```bash
npm run dev -- status
```

显示上次运行结果、数据统计、最近运行记录。

### 4. 查询异常

```bash
npm run dev -- conflicts
```

支持筛选：
- 按类型：`--type time|resource|block|workzone`
- 按严重程度：`--severity warning|error`

### 5. 查看排程结果

```bash
npm run dev -- schedule
```

支持筛选：
- 按工区：`--workzone wz-001`
- 按日期：`--date 2026-05-12`

### 6. 导出报告

```bash
npm run dev -- export report.xlsx
```

生成 Excel 报告，包含：
- **概览页**：整体运行状态和关键指标
- **排程结果**：按时间排序的已排程任务
- **资源使用**：各资源使用率统计
- **异常冲突**：所有冲突详情
- **数据清单**：天窗计划和任务明细

## 如何检查结果

### 排程完成率
```bash
npm run dev -- stats
```

查看核心指标：排程完成率、已排程/未排程任务数、冲突数量。

### 关键约束验证
1. **时间约束**：任务必须完全落在天窗时间内
2. **区段约束**：同一封锁区段同一时间不能被多个任务占用
3. **工区约束**：同一工区同一时间只能执行一个任务
4. **资源约束**：资源使用不能超过可用数量

### 重跑一致性
连续执行 `run` 两次，第二次需加 `--force` 强制重跑。比较结果应一致，无数据重复。

### 导出文件检查
打开 `report.xlsx`，重点检查：
- 概览页数据是否与 CLI `stats` 一致
- 排程结果是否有时间重叠
- 资源使用页使用率是否合理（≤100%）
