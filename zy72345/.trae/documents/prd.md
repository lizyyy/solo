## 1. 产品概述

"公平分摊成本计算"是一款面向教研团队的成本分摊计算与审核系统，解决抽样名单导入、参数调试、边界样本识别与人工复核的全流程问题。目标用户为教研负责人（吴老师）、学生助教及数据录入人员，核心价值在于让边界规则可追溯、数据变更可审计、异常样本不遗漏。

## 2. 核心功能

### 2.1 用户角色

| 角色 | 注册方式 | 核心权限 |
|------|----------|----------|
| 教研负责人 | 管理员邀请 | 审核边界样本、确认待处理记录、查看历史变更、管理参数调试表 |
| 学生助教 | 管理员邀请 | 复核边界样本、导入抽样名单、查看计算结果 |
| 数据录入员 | 管理员邀请 | 导入抽样名单、查看基础报表 |

### 2.2 功能模块

1. **仪表盘页面**：系统概览、待处理记录提醒、最近操作流、快捷入口
2. **抽样名单管理页面**：名单导入（去重）、名单列表、名单详情与关联参数
3. **参数调试表页面**：参数查看与编辑、边界规则配置、参数变更历史
4. **公平分摊成本计算页面**：计算结果展示（3D/图表切换）、边界样本高亮、点击回溯源数据
5. **边界样本报告页面**：异常样本列表、待处理/已确认状态管理、复核工作流
6. **变更历史页面**：操作审计日志、备注修改前后对比、全量变更追踪

## 3. 核心流程

用户主要操作流程如下：教研负责人或数据录入员首次导入抽样名单 → 系统自动识别边界样本（如负数被旧表当缺失）→ 边界样本自动标记为"待处理"，不自动归入正常 → 教研负责人补看参数调试表，确认或调整参数 → 参数变更触发边界样本报告更新 → 教研负责人在边界样本报告中逐条审核，确认或转交学生助教复核 → 学生助教添加复核意见 → 教研负责人最终确认，记录状态变为"已确认"。

```mermaid
flowchart TD
    "A[首次导入抽样名单]" --> "B[系统自动识别边界样本]"
    "B" --> "C[边界样本标记为待处理]"
    "C" --> "D[教研负责人补看参数调试表]"
    "D" --> "E{参数是否需调整}"
    "E" --> "是" --> "F[修改参数，记录变更历史]"
    "F" --> "G[边界样本报告自动更新]"
    "G" --> "H[教研负责人审核边界样本]"
    "E" --> "否" --> "H"
    "H" --> "I{是否转交复核}"
    "I" --> "是" --> "J[学生助教添加复核意见]"
    "J" --> "K[教研负责人最终确认]"
    "I" --> "否" --> "K"
    "K" --> "L[记录状态变为已确认]"
    "L" --> "M[计算结果更新]"
```

重复导入同一批抽样名单的流程：

```mermaid
flowchart TD
    "A[导入抽样名单]" --> "B{名单指纹是否已存在}"
    "B" --> "是" --> "C[跳过重复记录，仅更新备注等元数据]"
    "C" --> "D[变更历史记录本次导入操作]"
    "B" --> "否" --> "E[正常导入，执行边界样本识别]"
    "E" --> "F[数量不翻倍]"
```

## 4. 用户界面设计

### 4.1 设计风格

- 主色调：深蓝灰 (#1e293b) 配琥珀色 (#f59e0b) 强调色，传达专业严谨但不沉闷
- 辅助色：翡翠绿 (#10b981) 表示已确认，玫瑰红 (#ef4444) 表示异常/待处理
- 按钮风格：圆角矩形，主按钮带微妙阴影，次按钮为描边风格
- 字体：标题使用 Noto Serif SC（衬线体），正文使用 Noto Sans SC（无衬线体）
- 布局风格：左侧固定导航栏 + 右侧内容区，内容区采用卡片式布局
- 图标：Lucide Icons，线条风格统一
- 异常/待处理元素使用脉冲动画吸引注意

### 4.2 页面设计概览

| 页面名称 | 模块名称 | UI元素 |

### 4.3 响应式设计

- 桌面优先设计，主要适配 1280px+ 宽度
- 导航栏在 768px 以下收起为汉堡菜单
- 表格在小屏幕下转为卡片列表
- 3D场景和图表自适应容器宽度

### 4.4 3D场景指引

- 环境：深色背景配柔和环境光，营造数据分析氛围
- 灯光：主方向光从右上方照射，补光从左下方，异常样本加红色点光源
- 相机：默认 45 度俯视，支持旋转缩放，聚焦异常样本时相机平滑过渡
- 交互：悬浮显示数据标签，点击打开详情面板并高亮关联数据
- 后处理：轻微泛光效果（bloom），异常样本发光增强
- 性能预算：目标帧率 60fps，最多渲染 5000 个数据点

## 5. 边界规则规范（代码与文档同步）

以下边界规则必须同时写入代码逻辑和 README 文档：

| 规则编号 | 边界场景 | 判定逻辑 | 修正方式 | 回滚方式 |
|----------|----------|----------|----------|----------|
| BR-001 | 负数样本被旧表当成缺失 | 值 < 0 且旧表标记为"缺失" | 标记为边界样本，状态设为"待处理" | 从变更历史回滚至标记前状态 |
| BR-002 | 重复导入同一批名单 | 名单指纹（hash）已存在 | 跳过重复记录，仅更新元数据 | 删除本次导入的元数据更新 |
| BR-003 | 参数值异常（超出合理范围） | 参数值 < 0 或 > 999999 | 拒绝保存，提示合理范围 | 无需回滚，操作被阻止 |
| BR-004 | 备注仅修改单条 | 检测到仅备注字段变更 | 正常保存，历史记录标记为"备注修改" | 从变更历史回滚备注 |

## 6. 错误提示规范

| 内部错误码 | 用户可见提示 |
|------------|--------------|
| ERR_DUP_IMPORT | "这份抽样名单已经导入过了，不会重复计算数量" |
| ERR_NEG_AS_MISSING | "发现负数样本被旧表标记为缺失，已标记为待处理，请教研负责人确认" |
| ERR_PARAM_OOB | "参数值超出合理范围（0 ~ 999999），请检查后重新输入" |
| ERR_SAVE_FAIL | "保存失败，请稍后重试。如果问题持续，请联系技术支持" |
| ERR_ROLLBACK_FAIL | "回滚失败，该变更可能已被后续操作依赖，请联系技术支持" |
| ERR_PERMISSION | "您没有执行此操作的权限，请联系教研负责人" |
