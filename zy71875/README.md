# 食堂备餐预测系统

一个基于 React + FastAPI + SQLite 的食堂备餐智能预测系统，帮助食堂管理人员根据历史数据预测未来的备餐需求，减少浪费，提高效率。

## 功能特性

### 🍚 核心功能
- **数据导入**：支持 Excel (.xlsx/.xls) 和 CSV 格式导入历史用餐数据
- **智能预测**：基于加权移动平均算法，结合日期因子和菜品分类系数进行智能预测
- **批量复核**：支持批量复核数据，复核后的数据作为历史数据参与预测
- **数据修正**：支持修改预测或实际数据，所有修改都有完整的操作留痕
- **历史记录**：完整记录预测批次、文件导入、数据修正的所有历史操作
- **数据导出**：支持导出为 Excel 或 CSV 格式，包含完整的模型说明和筛选条件

### 🎯 设计亮点
- **友好的错误提示**：所有错误信息都转换为一线同事能看懂的人话，不显示技术术语或堆栈信息
- **批量处理稳定性**：重复运行预测不会重复生成数据，已复核的记录自动跳过，不会越跑越多
- **屏幕与导出一致**：导出的筛选条件与当前屏幕显示范围完全一致，模型说明同步导出
- **操作留痕**：所有数据修改都记录修改人、修改时间、修改前后的值和原因

## 技术栈

### 后端
- **FastAPI**：高性能 Python Web 框架
- **SQLAlchemy**：ORM 框架，操作 SQLite 数据库
- **Pandas**：数据处理和文件导入导出
- **Scikit-learn**：预测算法支持
- **Pydantic**：数据验证

### 前端
- **React 18**：前端框架
- **Ant Design 5**：企业级 UI 组件库
- **Vite**：构建工具
- **Axios**：HTTP 客户端
- **React Router**：路由管理

## 快速开始

### 环境要求
- Python 3.8+
- Node.js 16+

### 一键启动
```bash
# 给脚本添加执行权限（已添加可跳过）
chmod +x start_all.sh backend/start.sh frontend/start.sh

# 一键启动前后端
./start_all.sh
```

### 分别启动

#### 启动后端
```bash
cd backend
./start.sh
```
后端服务地址：http://localhost:8000
API 文档地址：http://localhost:8000/docs

#### 启动前端
```bash
cd frontend
./start.sh
```
前端访问地址：http://localhost:3000

### 首次运行步骤

1. **启动后端服务**：进入 `backend` 目录，运行 `./start.sh`
   - 首次会自动创建虚拟环境并安装依赖
   - 数据库会自动创建在 `backend/data/canteen.db`

2. **导入示例数据**：
   - 启动后访问 http://localhost:3000
   - 进入「数据导入」页面
   - 上传 `backend/data/示例数据.csv` 或自己整理的数据
   - 也可以使用模板下载功能，按照模板格式整理数据

3. **生成预测**：
   - 进入「备餐预测」页面
   - 选择要预测的日期范围
   - 点击「开始预测」生成预测数据

4. **复核数据**：
   - 进入「数据复核」页面
   - 核对预测和实际数据
   - 选择记录后点击「批量复核」

5. **导出数据**：
   - 进入「数据导出」页面
   - 设置筛选条件
   - 点击「预览导出内容」确认范围
   - 点击「确认导出」下载文件

## 使用说明

### 📁 导入数据格式
必需列：日期、餐次、菜品名称
可选列：菜品分类、预测份数、实际份数、单位、单价、备注

餐次支持多种写法：
- 早餐：早餐、早饭、早、morning、breakfast、1
- 午餐：午餐、中饭、午、noon、lunch、2
- 晚餐：晚餐、晚饭、晚、evening、dinner、3

### 📊 预测算法说明
1. **基础权重计算**：
   - 最近7天：权重 50%
   - 最近14-8天：权重 30%
   - 最近30-15天：权重 20%

2. **日期因子调整**：
   - 工作日：1.0
   - 周末：0.75
   - 法定节假日：0.5
   - 开学/返工第一周：1.2

3. **菜品分类系数**：
   - 热菜类：1.0
   - 主食类：1.1
   - 汤品类：0.8
   - 冷菜类：0.6
   - 小吃类：0.5

### ⚠️ 约束条件
1. 同一日期、同一餐次、同一菜品只能有一条记录
2. 已复核的记录不允许修改，如需修改请先取消复核
3. 批量预测时，已复核的记录会被自动跳过
4. 单次预测的日期范围最多 365 天

## 常见问题

### Q: 后端启动失败，提示端口被占用？
A: 请确保 8000 端口没有被其他程序占用，或者修改 `backend/main.py` 中的端口配置。

### Q: 前端无法连接后端？
A: 请确保后端服务已启动，检查 `frontend/vite.config.js` 中的代理配置是否正确。

### Q: 导入文件时提示格式错误？
A: 请下载导入模板，按照模板格式整理数据，确保包含必需的列。

### Q: 预测生成的数据太少或太多？
A: 可以检查历史数据是否充足（建议至少有7天的历史数据），或者调整预测时的日期范围。

### Q: 已复核的数据发现错误怎么办？
A: 已复核的数据不允许直接修改，请联系管理员在数据库中取消复核状态后再修改。

## 错误提示对照表

| 技术错误 | 用户友好提示 |
|---------|------------|
| UNIQUE constraint failed | 这条记录已经存在了（相同日期、餐次和菜品） |
| value_error.date | 日期格式不正确，请使用 YYYY-MM-DD 格式 |
| value_error.number.not_ge | 数值不能为负数 |
| Record not found | 找不到这条记录，可能已被删除 |
| RECORD_ALREADY_REVIEWED | 这条记录已经复核过了，不能再修改 |
| EMPTY_MEAL_TYPE | 餐次不能为空，请填写早餐、午餐或晚餐 |
| INVALID_MEAL_TYPE | 不认识的餐次，请填写早餐、午餐或晚餐 |
| INVALID_DATE_RANGE | 开始日期不能晚于结束日期 |
| DATE_RANGE_TOO_LARGE | 日期范围太大了，最多只能选择 365 天 |
| MISSING_REQUIRED_COLUMNS | 导入的文件缺少必要的列 |
| INVALID_FILE_TYPE | 不支持的文件格式，请上传 Excel 或 CSV 文件 |
| EMPTY_FILE | 上传的文件是空的 |
