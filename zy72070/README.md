# 地下停车诱导模型

CAD导出点位与现场采集数据对齐工具，面向数据分析人员使用。

> 让乱材料能对得上，让判断过程有迹可循。

---

## 一、快速开始

### 1. 环境要求

- Node.js >= 16
- npm 或 pnpm / yarn

### 2. 安装依赖

```bash
npm install
```

### 3. 启动开发服务器

```bash
npm run dev
```

启动后访问：**http://localhost:3000/**

> 默认端口 3000，如被占用时Vite会自动使用下一个可用端口。

---

## 二、完整操作流程

### 第1步：导入数据

启动后进入**数据导入页** (`/`)，有两种方式开始：

| 方式 | 说明 |
|------|------|
| 加载样例数据 | 一键加载预置的"地下停车诱导模型 - 样例数据，包含所有典型异常场景 |
| 上传文件 | 支持 JSON、CSV 格式导入 |

**样例数据包含的场景：**

- ✅ 1条顺利通过记录（数据完整、坐标一致）
- ⚠️ 1条需人工确认记录（坐标接近阈值边界）
- 📋 1条CAD旧口径记录（字段命名与新标准不同）
- 🔄 坐标偏移异常
- 🔤 设备重名异常
- 📷 缺照片异常
- 🏢 跨楼层异常
- 🗺️ 坐标系不一致数据（分别渲染，不强行合并）

**文件导入说明：**

1. 点击「下载模板」获取标准 JSON 模板
2. 按照模板格式准备数据（支持 `devices` 和 `cadPoints` 两个数组）
3. 拖拽文件到上传区域，或点击选择文件
4. 确认导入前会显示解析结果（设备数、CAD点数）
5. 点击「确认导入」完成

---

### 第2步：工作台操作

进入**主工作台** (`/workspace`)，采用三栏式布局：

```
┌─────────────┬─────────────────────────────────┬─────────────┐
│             │                                 │             │
│  参数面板   │          2D场景视图             │  设备明细   │
│             │                                 │             │
│             ├─────────────────────────────────┤             │
│             │                                 │             │
│             │          冲突检测区               │             │
│             │                                 │             │
└─────────────┴─────────────────────────────────┴─────────────┘
```

#### 左侧：参数面板

实时联动，修改后自动重算：

| 参数 | 作用 | 默认值 |
|------|------|--------|
| 诱导距离阈值 | 设备间超过此距离视为独立诱导单元 | 50m |
| 坐标容差 | CAD与现场坐标差在此范围内视为匹配 | 5m |
| 坐标系处理方式 | 分别渲染 / 统一到A系 / 统一到B系 | 分别渲染 |

**视图控制：**
- 放大 / 缩小
- 旋转（每次90度）
- 重置视图

#### 中间：2D场景视图

- 鼠标滚轮：缩放
- 鼠标拖拽：平移
- 点击设备：选中查看
- 楼层切换：B1层 / B2层
- 不同坐标系设备用**虚线边框**标记
- 设备颜色表示状态：
  - 🟢 绿色：正常
  - 🟡 黄色：待确认
  - 🔴 红色：异常
  - ⚪ 灰色：未处理

#### 底部：冲突检测

列出所有自动检测到的问题，每条包含：
- 问题类型与严重程度
- 双方证据（现场数据 / CAD数据）
- 建议动作（口语化描述）
- 可点击「标记已解决」

#### 右侧：设备明细

- 按状态筛选：全部 / 正常 / 待确认 / 异常 / 未处理
- 点击「展开按钮展开详情：
  - 检测结果（评分依据）
  - 关联冲突
  - 判定历史
- 快速操作：通过 / 待确认 / 驳回

---

### 第3步：参数联动验证

调整左侧参数面板的**坐标容差**滑块：

1. 将容差从 5m 调整到 10m
2. 观察中间场景视图中设备颜色变化
3. 观察右侧设备明细的状态统计变化
4. 观察底部冲突检测列表更新

所有更新为实时联动，无需手动刷新。

---

### 第4步：人工判定

在设备明细中：

1. 展开某条待确认记录
2. 查看检测结果和关联冲突
3. 点击「通过」/「待确认」/「驳回」
4. 系统自动记录：操作人、时间、当时的参数快照

---

### 第5步：保存与报告

点击顶部「保存方案」按钮保存当前状态。

点击「查看报告」进入**报告页** (`/report`)：

| 功能 | 说明 |
|------|------|
| 方案概览 | 项目名称、操作人、时间 |
| 数据统计 | 正常/待确认/异常/未处理 数量统计 |
| 判定历史 | 所有人工判定记录（时间线） |
| 完整报告 | Markdown 格式，可复制可下载 |
| 导出完整方案 | JSON 格式，包含所有数据，可交接给同事继续处理 |

## 三、数据格式说明

### JSON 导入格式

```json
{
  "devices": [
    {
      "id": "dev-001",
      "name": "诱导摄像头-B1-01",
      "type": "camera",
      "floor": "B1",
      "x": 100,
      "y": 150,
      "coordSystem": "A",
      "hasPhoto": true,
      "source": "field",
      "matchedCadId": "cad-001"
    }
  ],
  "cadPoints": [
    {
      "id": "cad-001",
      "oldName": "CAM_OLD_001",
      "newName": "诱导摄像头-B1-01",
      "layer": "设备层-摄像头",
      "floor": "B1",
      "x": 100,
      "y": 150,
      "coordSystem": "A"
    }
  ]
}
```

### 字段说明

**设备 (Device)**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 设备唯一标识 |
| name | string | 设备名称 |
| type | enum | camera / sensor / indicator |
| floor | string | 所在楼层，如 B1、B2 |
| x | number | 横坐标 |
| y | number | 纵坐标 |
| coordSystem | enum | A / B |
| hasPhoto | boolean | 是否有现场照片 |
| source | enum | field（现场）/ cad（CAD导出） |
| matchedCadId | string | 匹配的CAD点位ID |

**CAD点位 (CadPoint)**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 点位唯一标识 |
| oldName | string | 旧口径字段名（可选） |
| newName | string | 新口径字段名 |
| layer | string | CAD图层 |
| floor | string | 所在楼层 |
| x | number | 横坐标 |
| y | number | 纵坐标 |
| coordSystem | enum | A / B |

## 六、数据持久化

所有数据自动保存到浏览器 LocalStorage（key: `parking-guidance-storage`），包括：

- 设备列表
- CAD点位
- 参数设置
- 判定记录
- 方案元数据

刷新页面不丢失，导出完整方案JSON可备份和交接。

---

## 七、典型使用场景

### 场景1：首次处理新项目

1. 从CAD导出点位，整理成JSON/CSV格式
2. 导入数据，查看自动匹配结果
3. 调整参数阈值，观察匹配效果
4. 对异常记录逐一复核
5. 人工给出判定，保存方案
6. 导出报告发给同事

### 场景2：同事接手继续处理

1. 打开导入之前导出的完整方案JSON
2. 查看之前的判定历史和参数设置
3. 补充新材料（新导入的数据）
4. 继续处理未解决的冲突
5. 更新后重新导出
