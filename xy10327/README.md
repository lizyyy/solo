# 共享琴房时段锁定台

一个完整的琴房预约管理系统，支持门店前台操作、预约管理和收入统计。

## 功能特性

### 核心功能
- 📅 **日历视图**：按日/周查看琴房预约情况，实时显示琴房状态
- 🏠 **房间状态**：实时查看各琴房的空闲/使用状态
- 📋 **预约管理**：完整的预约生命周期管理
- 📊 **统计分析**：收入统计、利用率分析、热门顾客排行

### 业务流程
- ✅ **新建预约**：选择琴房和时段，自动检测冲突
- 🔑 **办理签到**：顾客到场，开始计时
- ⏰ **迟到释放**：超过15分钟未签到自动释放（保留历史记录）
- ➕ **申请续时**：使用中可申请续时，需确保后续时段空闲
- 🔄 **临时换房**：可更换到其他空闲琴房
- 📤 **导出功能**：支持CSV格式导出预约记录

### 业务规则
1. **冲突检测**：同一琴房同时段只能有一个有效预约
2. **迟到规则**：超过15分钟未签到，系统自动释放该预约
3. **续时规则**：续时段必须空闲，不能挤占下一位顾客
4. **状态流转**：所有状态变更记录操作日志
5. **数据完整性**：迟到释放、换房等操作均保留历史记录

## 技术架构

### 前端
- **框架**：React 18 + TypeScript
- **构建工具**：Vite 5
- **UI组件**：Ant Design 5
- **日历组件**：react-big-calendar
- **端口**：3000

### 后端
- **框架**：Express.js + TypeScript
- **数据库**：SQLite
- **时间处理**：dayjs
- **端口**：3001

## 安装与运行

### 前置要求
- Node.js >= 18
- npm 或 yarn

### 快速开始

1. **安装依赖**
```bash
npm install
```

2. **初始化数据库并插入样例数据**
```bash
npm run seed
```

3. **启动开发服务器**
```bash
npm run dev
```

4. **访问系统**
- 前端：http://localhost:3000
- 后端API：http://localhost:3001

### 单独启动

```bash
# 仅启动后端
npm run dev:server

# 仅启动前端
npm run dev:client
```

## 使用指南

### 1. 造数步骤

执行以下命令初始化测试数据：

```bash
npm run seed
```

该命令会：
- 创建1家门店（琴韵中心店）
- 创建3间琴房（A1标准、A2豪华、B1练习）
- 创建6位会员顾客
- 插入8条预约记录（覆盖所有业务场景）
- 记录状态流转日志

### 2. 日常操作

#### 新建预约
1. 点击右上角「新建预约」按钮
2. 填写顾客姓名、联系电话
3. 选择琴房（显示价格和容量）
4. 选择预约时间范围（最小30分钟）
5. 可点击「检查时段可用性」提前确认
6. 点击「确认预约」完成

#### 办理签到
1. 在「日历视图」或「预约管理」找到目标预约
2. 点击操作按钮中的「办理签到」
3. 系统自动记录签到时间，状态变为「使用中」
4. 如果迟到超过15分钟，签到会被拒绝

#### 申请续时
1. 找到「使用中」的预约
2. 点击「申请续时」
3. 选择续时时长（30分钟/1小时/2小时/3小时）
4. 系统自动检查续时段是否可用
5. 如可用则续时成功，费用自动追加

#### 迟到释放
1. 找到「已预约」但超时未到的预约
2. 点击「迟到释放」
3. 确认后预约状态变为「迟到释放」
4. 该琴房时段被释放，可重新预约
5. 原预约记录保留，可在历史中查看

#### 临时换房
1. 找到需要换房的预约
2. 点击「临时换房」
3. 选择目标琴房
4. 系统检查目标琴房该时段是否可用
5. 确认后完成换房，原预约标记为「已换房」

### 3. 搜索与筛选

#### 预约管理页面筛选
- **关键词搜索**：支持顾客姓名、电话、预约编号
- **状态筛选**：多选，支持同时筛选多种状态
- **琴房筛选**：按特定琴房筛选
- **日期范围**：按预约日期筛选
- **重置按钮**：一键清除所有筛选条件

#### 统计分析页面
- 支持按日期范围查看统计数据
- 自动计算收入、完成率、利用率等

### 4. 导出日报

1. 进入「预约管理」页面
2. 使用筛选条件过滤需要的数据（如选择今天的日期）
3. 点击「导出」按钮
4. 系统自动生成CSV文件并下载
5. 可使用Excel打开查看和编辑

导出字段包括：
- 预约编号
- 顾客姓名
- 联系电话
- 琴房
- 开始时间
- 结束时间
- 状态
- 总金额
- 已付金额
- 是否续时
- 备注
- 创建时间

### 5. 统计数字动态更新

所有操作都会实时影响统计数据：

| 操作 | 影响的统计项 |
|------|-------------|
| 新建预约 | 总预约数 +1 |
| 完成退房 | 已完成 +1，总收入 +金额 |
| 取消预约 | 已取消 +1 |
| 迟到释放 | 迟到释放 +1 |
| 换房 | 换房记录 +1 |
| 续时成功 | 总收入 +续时费用 |

刷新页面或点击「刷新」按钮即可看到最新统计。

## API 接口说明

### 门店
- `GET /api/stores` - 获取所有门店

### 琴房
- `GET /api/rooms` - 获取所有琴房
- `GET /api/rooms?storeId={id}` - 按门店获取琴房
- `GET /api/rooms/:roomId/availability` - 检查时段可用性

### 顾客
- `GET /api/customers` - 获取所有顾客

### 预约
- `GET /api/bookings` - 获取预约列表（支持筛选）
- `GET /api/bookings/:id` - 获取单个预约详情
- `POST /api/bookings` - 创建预约
- `POST /api/bookings/:id/checkin` - 办理签到
- `POST /api/bookings/:id/release-late` - 迟到释放
- `POST /api/bookings/:id/extend` - 申请续时
- `POST /api/bookings/:id/change-room` - 临时换房
- `POST /api/bookings/:id/complete` - 完成退房
- `POST /api/bookings/:id/cancel` - 取消预约
- `GET /api/bookings/:id/logs` - 获取状态变更日志

### 统计
- `GET /api/statistics` - 获取统计数据
- `GET /api/statistics?start={}&end={}` - 按日期范围统计

## 状态流转说明

```
pending (待确认)
    ↓
confirmed (已预约) ←─ 新建预约
    ↓                     ↓
    ├─→ checked_in (已签到)
    │        ↓
    │   in_use (使用中) ←─ 续时(不改变状态)
    │        ↓
    │   completed (已完成)
    │
    ├─→ late_released (迟到释放)
    │
    ├─→ cancelled (已取消)
    │
    └─→ room_changed (已换房)
              ↓
         新预约: confirmed/in_use
```

## 数据库结构

### 主要表
- `stores` - 门店信息
- `rooms` - 琴房信息
- `customers` - 顾客信息
- `bookings` - 预约记录（核心表）
- `status_logs` - 状态变更日志（审计追踪）
- `revenue_records` - 收入记录
- `system_settings` - 系统配置

## 故障排查

### 端口冲突
如果端口3000或3001被占用：
```bash
# 查看占用进程
lsof -i :3000
lsof -i :3001

# 结束进程（替换PID为实际进程号）
kill -9 PID
```

### 数据库问题
重新初始化数据库：
```bash
# 删除旧数据库
rm server/data/piano.db

# 重新造数
npm run seed
```

### 依赖安装失败
尝试清理缓存后重新安装：
```bash
rm -rf node_modules package-lock.json
npm install
```
