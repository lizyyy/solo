# 🏛️ 博物馆夜间临时撤展 - 策略小游戏

## 游戏简介

博物馆收到威胁情报，需要在安保人员巡逻到前将所有高价值文物从展厅护送到安全出口。这是一个回合制策略游戏，玩家需要安排保管员的移动路线，避开安保人员的视野，处理各种约束条件。

## 技术栈

- **TypeScript** - 类型安全的 JavaScript
- **Vite** - 下一代前端构建工具
- **纯前端** - 无需后端服务，本地即可运行

## 游戏规则

### 核心机制

- **回合制**：每回合玩家可以控制保管员移动，然后安保人员巡逻
- **载重限制**：每个保管员有最大载重量，不同文物重量不同
- **展柜锁定**：展柜需要先解锁才能取文物
- **安保视野**：安保人员有视野范围，进入视野会被发现
- **随机事件**：会出现电力故障等随机事件

### 胜利条件

在 20 回合内将所有 5 件高价值文物安全转移到安全出口。

### 失败条件

- 保管员被安保人员发现
- 超过 20 回合仍未完成任务

### 游戏元素

#### 地图元素

- **🧱 墙壁**：不可通行
- **⬜ 地板**：可通行
- **🔒 锁定展柜**：需要先解锁
- **📦 解锁展柜**：可取走文物
- **🚪 安全出口**：存放文物的目标点

#### 角色

- **👨‍💼 保管员**：玩家控制的角色
  - 老王：最大载重 5
  - 小张：最大载重 4

- **👮 安保人员**：自动巡逻的敌人
  - 有固定巡逻路线
  - 有视野范围（箭头指示方向）

#### 文物

| 文物名称 | 重量 | 价值 |
|---------|------|------|
| 埃及法老黄金面具 | 3 | 1,000,000 |
| 达芬奇素描手稿 | 1 | 800,000 |
| 中国青花瓷瓶 | 2 | 600,000 |
| 罗马帝国金币 | 1 | 400,000 |
| 文艺复兴油画 | 4 | 1,200,000 |

#### 事件卡

- **电力故障**：第 5、12 回合触发，持续 2 回合，安保视野减半
- **安保警觉**：第 8 回合触发，持续 2 回合，安保视野增加
- **展柜故障**：第 3 回合触发，一个展柜自动解锁

## 操作指南

### 基本操作

1. **选择保管员**：点击地图上的保管员（👨‍💼）选中
2. **移动**：选中后点击相邻的可通行格子（会高亮显示）
3. **解锁展柜**：移动到锁定展柜（🔒）位置后，再次点击展柜解锁
4. **取走文物**：展柜解锁后，再次点击展柜取走文物
5. **存放文物**：移动到安全出口（🚪）后，点击出口位置存放所有携带的文物
6. **结束回合**：点击"结束回合"按钮，安保人员开始巡逻

### 策略建议

1. **观察巡逻路线**：安保人员有固定巡逻路线，提前规划避开路线
2. **注意视野范围**：安保人员的箭头指示视野方向，避免进入视野
3. **合理分配载重**：根据文物重量合理分配给不同保管员
4. **利用停电时机**：电力故障时安保视野减半，这是移动的好时机
5. **多个保管员配合**：两个保管员可以同时行动，提高效率

## 游戏导出

游戏结束后，会提示是否导出游戏数据。导出的文件包括：

### 1. replay.json

包含完整的游戏回放数据，包括：
- 游戏 ID 和时间戳
- 初始配置（地图、角色、文物等）
- 所有玩家操作记录
- 最终游戏状态

### 2. review_report.md

游戏评估报告，包括：
- 游戏结果和基本信息
- 保管员表现统计
- 遇到的事件列表
- 检测到的风险
- 表现总结
- 改进建议

## 自定义配置

可以通过修改 `src/config/sampleConfig.ts` 来自定义游戏配置：

- **地图**：修改 `sampleMapGrid` 数组
- **文物**：修改 `artifacts` 数组
- **展柜**：修改 `displayCases` 数组
- **保管员**：修改 `custodians` 数组
- **安保人员**：修改 `guards` 数组
- **事件卡**：修改 `eventCards` 数组
- **游戏参数**：修改 `maxTurns` 和 `totalArtifactsToSecure`

## 开发说明

### 核心模块说明

1. **MapSystem**：负责地图数据管理、路径查找、格子访问判断
2. **EventSystem**：负责事件卡管理、随机事件触发
3. **RulesEngine**：负责所有游戏规则判定
4. **GameStateMachine**：管理游戏状态和回合制逻辑
5. **ExportSystem**：处理游戏数据导出
6. **GameController**：协调所有模块，处理用户输入
7. **UIRenderer**：负责界面渲染

### 添加新功能

1. 如需添加新的游戏规则，在 `RulesEngine.ts` 中添加
2. 如需添加新的事件类型，在 `EventSystem.ts` 中添加
3. 如需修改界面，在 `UIRenderer.ts` 和 `style.css` 中修改

## 注意事项

- 游戏使用纯前端技术，刷新页面会重置游戏进度
- 导出的文件会下载到浏览器的默认下载目录
- 游戏完全在本地运行，不会上传任何数据
