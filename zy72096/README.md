# 音乐版权长尾收益计算工具

公式、单位、边界值和结果解释全部摆在明处，做完不用手工对第二遍。

## 快速开始

```bash
# 运行计算（最常用）
python -m music_royalty run data/sample_import.csv

# 仅检查冲突，不做计算
python -m music_royalty check-conflicts data/sample_import.csv

# 人工调整参数（不会被后续运行的默认值覆盖）
python -m music_royalty update-param M003 decay_factor 0.88

# 标记例外记录
python -m music_royalty mark-exception M003 --note "公播渠道特殊合同"

# 查看持久化参数
python -m music_royalty show-param M003
```

## 输入格式

CSV 文件，首行为列名。列名不需要完全统一，工具自动映射常见别名：

| 标准字段 | 接受的列名（部分） |
|---|---|
| record_id | 编号、ID、序号、曲目编号 |
| work_title | 作品名、曲名、歌曲名、名称 |
| revenue_type | 收益类型、类型、版权类型 |
| play_count | 播放量、播放次数、流量 |
| play_count_unit | 播放量单位（次/万次/百万次） |
| per_play_revenue | 单次收益、每次收益、单价、千播收益 |
| per_play_revenue_unit | 收益单位（元/次、元/千次、美元/流） |
| decay_factor | 衰减系数、衰减率、长尾系数 |
| platform_share | 平台分成、平台比例、平台抽成 |
| rights_share | 版权分成、版权比例、词曲分成 |
| months_since_release | 距发行月数、发行月数、月数 |
| share_format | 分成格式（小数/百分比） |
| currency | 币种（CNY/USD/人民币/美元） |
| source | 来源、数据来源 |

示例 CSV 见 `data/sample_import.csv`。

## 收益类型

- 流媒体播放
- 同步授权
- 下载收益
- 公播收益

## 计算公式（透明展示）

```
净收益 = 播放量(次) × 单次收益(元/次) × 衰减系数^(距发行年数) × (1 - 平台分成) × 版权方分成
```

每条记录的明细报告会逐步展示：
1. 播放量标准化（万次→次）
2. 单次收益标准化（元/千次→元/次，美元/流→元/次）
3. 衰减计算（衰减系数^年数）
4. 毛收益计算
5. 平台分成扣除
6. 版权方分成计算
7. 净收益结果
8. 如需汇率换算，展示 USD→CNY 步骤

## 参数优先级

1. **参数表持久化值**（最高优先级，人工调整后不会被默认值覆盖）
2. **导入数据中的字段值**
3. **内置默认值**（衰减系数=0.90，平台分成=0.60，版权方分成=0.70）

## 人工调参不覆盖

通过 `update-param` 命令修改的参数会标记为"人工调整"，后续 `run` 命令不会用默认值覆盖：

```bash
# 周姐手工把 M003 的衰减系数调为 0.88
python -m music_royalty update-param M003 decay_factor 0.88

# 再次运行计算，M003 的衰减系数仍是 0.88，不会被默认的 0.90 覆盖
python -m music_royalty run data/sample_import.csv
```

## 冲突处理

当参数表中的值与导入数据不一致时：

```bash
# 先检查冲突
python -m music_royalty check-conflicts data/sample_import.csv
```

工具会展示：
- 参数表的值和来源
- 导入数据的值和来源
- 建议操作（不会替用户拍板）

确认后选择：
- 以参数表为准：无需操作
- 以导入数据为准：运行 `update-param` 更新参数表

## 例外记录

例外记录不会被忽略，仍然参与计算和汇总，但在报告中会标注：

```bash
# 标记例外
python -m music_royalty mark-exception M003 --note "公播渠道特殊合同，衰减系数人工调为0.88"

# 例外记录在汇总中可见，不会悄悄消失
```

## 异常清单怎么看

运行 `run` 命令后会生成 4 个文件到 `output/` 目录：

| 文件 | 内容 |
|---|---|
| `royalty_detail_*.txt` | 每条记录的完整计算过程、参数来源、边界警告、冲突、审计记录 |
| `royalty_summary_*.txt` | 汇总金额、按类型统计、例外/边界标注 |
| `royalty_result_*.csv` | 结构化结果，可用于后续分析 |
| `royalty_conflicts_*.txt` | 仅列出参数冲突及建议操作 |

**查看异常**：
1. 先看汇总报告的"各记录净收益一览"，带 ★ 的是例外，带 ⚠ 的是边界警告
2. 再看冲突清单，逐条确认是否需要调整
3. 有疑问的记录，去明细报告查完整计算过程和审计记录

**汇总与明细一致性**：汇总数字由明细逐条累加，两者一定一致。如发现不一致请以明细为准并核查。

## 审计追踪

每条计算记录保留：
- 原始数据来源（如"老师讲义2024Q2"、"业务表版权组"）
- 处理时间（ISO 格式）
- 每个参数的取值来源（参数表/导入数据/默认值）
- 参数变更记录（谁、何时、从什么值改为什么值）

## 边界值

| 参数 | 下限 | 上限 | 说明 |
|---|---|---|---|
| 播放量 | 0 | 1万亿 | 超出会触发警告 |
| 单次收益(元/次) | 0 | 100 | 超出会触发警告 |
| 衰减系数 | 0.0 | 1.0 | 0.85-0.95 为常见范围 |
| 平台分成 | 0.0 | 1.0 | 应为小数 |
| 版权方分成 | 0.0 | 1.0 | 应为小数 |
| 距发行月数 | 0 | 600 | 50年以上会触发警告 |
