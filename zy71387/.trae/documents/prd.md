## 1. 产品概述

数据血缘断点追踪系统——当数据仓库字段变更时，自动追踪下游报表、ETL任务和API受影响范围，输出业务同事也能看懂的风险清单。解决"改一个字段，炸一片报表却没人知道"的问题，面向数据分析师、数据工程师和业务运营人员，适合放入日常巡检流程。

## 2. 核心功能

### 2.1 用户角色

| 角色 | 进入方式 | 核心权限 |
|------|---------|---------|
| 数据分析师 | 直接访问 | 查看血缘图谱、触发影响扫描、导出风险报告 |
| 数据工程师 | 直接访问 | 以上 + 登记ETL任务、管理字段别名、补录血缘 |
| 业务运营 | 直接访问 | 查看风险清单、确认影响范围、接收巡检通知 |

### 2.2 功能模块

1. **血缘图谱页**：以可视化有向图展示字段级血缘关系，支持搜索定位、点击展开上下游、高亮断点
2. **影响扫描页**：输入变更字段，一键扫描所有下游报表/任务/API，输出受影响清单与严重程度
3. **别名归并页**：管理字段别名映射，自动归并同一字段的不同叫法，处理"一个字段N个名字"的混乱情况
4. **风险清单页**：汇总当前未解决的血缘断点、未登记下游、状态矛盾项，按严重程度排序
5. **巡检报告页**：一键生成可导出的巡检报告（含图谱截图、风险条目、变更记录），支持PDF/Excel导出

### 2.3 页面详情

| 页面名称 | 模块名称 | 功能说明 |
|---------|---------|---------|
| 血缘图谱 | 图谱画布 | 力导向有向图，节点=字段/表/任务/报表/API，边=依赖关系，断点红色虚线 |
| 血缘图谱 | 搜索与定位 | 按字段名/别名搜索，定位到图中节点并高亮其上下游链路 |
| 血缘图谱 | 节点详情抽屉 | 点击节点弹出右侧抽屉，展示字段类型、来源任务、下游数量、最近变更时间 |
| 影响扫描 | 变更字段输入 | 支持输入字段名或从变更单导入，自动匹配别名 |
| 影响扫描 | 影响范围面板 | 树形展示下游链路，每层标注类型（表/ETL/报表/API）和状态 |
| 影响扫描 | 严重程度标识 | 🔴高-核心报表断裂 / 🟡中-非核心任务受影响 / 🟢低-别名可自动映射 |
| 别名归并 | 别名映射表 | 展示所有字段及其别名，支持手动添加/合并/拆分别名 |

| 风险清单 | 风险条目列表 | 每条含：风险类型、涉及字段、影响范围、严重程度、状态（待处理/已确认/已忽略） |

| 巡检报告 | 导出 | 支持PDF和Excel格式导出 |

## 3. 核心流程

### 3.1 顺利流程：字段变更 → 影响追踪 → 确认无风险

分析师收到数仓变更通知后，在系统输入变更字段名，系统自动匹配别名、追踪血缘图谱找到所有下游，输出影响清单。分析师确认影响范围均在预期内，标记为已确认，生成巡检报告归档。

### 3.2 卡住例外：隐藏字段+未登记下游 → 血缘断点

工程师改了一个内部隐藏字段（如`_etl_batch_id`），该字段未在字段字典登记，但实际被下游ETL任务引用。系统在别名归并时发现此字段无正式登记记录，在风险清单中标记为"未登记字段-高危"，同时发现该ETL的下游报表虽然登记了血缘，但报表中引用的`batch_id`字段未关联到隐藏字段。此时需要工程师手动补录别名关系和血缘链路。

## 4. 用户界面设计

### 4.1 设计风格

- **主色调**：深蓝灰(#1a1f36)为主背景，搭配青蓝(#00d4ff)作为高亮/链接色，红色(#ff4757)作为危险/断点色，黄绿(#2ed573)作为安全色
- **风格**：工业监控台风格（Industrial Dashboard），深色背景配亮色数据点，类似运维监控大屏但更精致
- **字体**：标题用 JetBrains Mono（代码/数据感），正文用 Noto Sans SC
- **布局**：左侧固定导航栏 + 右侧内容区，内容区顶部面包屑+操作栏，主体区域自适应
- **按钮**：圆角4px，主要操作青蓝实色，危险操作红色描边，常规操作灰色描边
- **图标**：使用 lucide-react 图标库

### 4.2 页面设计概览

| 页面名称 | 模块名称 | UI要素 |
|---------|---------|--------|
| 血缘图谱 | 图谱画布 | 深色背景，节点圆形/方形/菱形区分类型，边有方向箭头，断点红色虚线，力导向布局，支持缩放拖拽 |
| 血缘图谱 | 搜索栏 | 顶部搜索框，输入时下拉候选字段名+别名，选中后图谱居中定位到目标节点 |
| 血缘图谱 | 详情抽屉 | 右侧滑出，深色卡片，字段信息+上下游列表+变更历史 |
| 影响扫描 | 输入区 | 左侧面板，支持手动输入和粘贴变更单，变更单格式自动解析 |
| 影响扫描 | 影响树 | 右侧树形结构，每层节点带类型图标和状态标签，展开/折叠动画 |
| 别名归并 | 映射表 | 表格布局，主字段名粗体，别名列表标签式排列，冲突项红色背景 |
| 别名归并 | 操作区 | 行内编辑别名，拖拽合并，冲突解决弹窗 |
| 风险清单 | 列表 | 卡片列表，左侧色条标识严重程度，右侧操作按钮，支持筛选排序 |
| 巡检报告 | 报告预览 | 类似文档预览的布局，顶部统计摘要，中部风险条目，底部变更记录，右上角导出按钮 |

### 4.3 响应式

桌面优先设计，最小支持1280px宽度。图谱画布自适应容器尺寸。

## 5. 演示数据设计

### 5.1 顺利流程数据

- 字段：`user_order.amount`（订单金额）→ 下游链路完整登记
  - ETL任务：`dws_order_agg`（日汇总）→ 报表：`日订单汇总看板` → API：`/api/order/summary`
  - 别名：`amount` = `订单金额` = `order_amt` = `total_amount`
- 变更：`amount` 字段精度从2位变4位
- 扫描结果：3个下游全部命中，均为低风险（精度变更不影响逻辑）

### 5.2 卡住例外数据

- 字段：`_etl_batch_id`（ETL批次号，隐藏字段，未登记在字段字典）
  - 下游ETL：`dws_user_profile` 实际引用了 `batch_id`（未登记的别名）
  - 下游报表：`用户画像报表` 引用了 `batch_id` 但血缘登记指向 `user_id`
  - API：`/api/user/profile` 返回了 `batchId` 字段但未登记血缘
- 变更：`_etl_batch_id` 字段类型从INT改为STRING
- 问题：别名未归并 → 血缘链路断裂 → 下游ETL会静默失败 → 报表数据串行 → API返回类型错误
- 风险：🔴高危-未登记字段 + 🔴高危-血缘断点 + 🟡中危-下游任务未登记
