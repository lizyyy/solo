# 十分钟清场 - 展会志愿者疏散训练游戏

一个用于展会志愿者训练的俯视角疏散模拟游戏，帮助志愿者练习处理入口拥堵、老人儿童慢速通行、临时封路和广播指令等复杂场景的决策能力。

## 项目结构

```

├── package.json            # 项目配置
```

## 功能特性

### 核心游戏功能
- **网格地图系统**：可编辑的网格关卡，支持墙壁、入口、出口、障碍物
- **多样化人群**：
  - 🔵 普通人群：速度1.0，耐心100
  - 🟡 老人：速度0.5，耐心80（更容易焦躁）
  - 🔴 儿童：速度0.7，耐心60（最容易焦躁）
  - 🟢 残障人士：速度0.3，耐心120（更稳定但最慢）
- **志愿者交互**：
  - 拖拽移动志愿者到任意位置
  - 设置指引方向引导人群绕行
  - 影响范围内人群提升耐心值
- **突发事件系统**：
  - 临时封路
  - 广播指令（安抚/紧急）
  - 医疗紧急情况
  - 额外人群涌入
  - 设备故障
- **计分系统**：
  - 疏散奖励：10分/人
  - 时间奖励：1-2分/秒（提前完成）
  - 恐慌惩罚：-20~-30分/人
  - 志愿者移动惩罚：-5分/次
  - 广播使用惩罚：-15分/次
- **失败条件**：
  - 超过10分钟时限
  - 恐慌人数超过20%~30%（根据关卡难度）

### 数据持久化
- **本地最高分**：每个关卡独立记录前10名高分
- **回放记录**：记录所有操作动作用于复盘
- **游戏存档**：支持保存和读取游戏状态
- **设置存储**：保存游戏配置

### 导出功能
- **Markdown复盘报告**：包含完整的
  - 基本信息（关卡、时间、得分）
  - 人员统计（疏散/恐慌/剩余）
  - 人群构成分析
  - 行动记录时间线
  - 事件触发记录
  - 计分明细
  - 评估与改进建议

## 快速开始

### 环境要求
- 现代浏览器（Chrome、Firefox、Safari、Edge）
- Node.js（仅用于运行测试和本地服务器）

### 启动游戏

#### 方式一：直接用浏览器打开
最简单的方式，直接在浏览器中打开 `index.html` 文件即可。

但需要注意：某些浏览器（如Chrome）出于安全考虑，阻止本地文件的fetch请求。如果遇到关卡无法加载的问题，请使用方式二。

#### 方式二：使用本地HTTP服务器（推荐）

1. 安装依赖：
```bash
npm install
```

2. 启动开发服务器：
```bash
npm start
```

3. 打开浏览器访问：
```
http://localhost:8080
```

#### 方式三：使用Python服务器
如果不想安装Node.js，可以使用Python的内置服务器：

```bash
# Python 3
python -m http.server 8080

# Python 2
python -m SimpleHTTPServer 8080
```

然后访问 `http://localhost:8080`

### 游戏操作

1. **选择关卡**：从下拉菜单选择想要挑战的关卡
2. **开始游戏**：点击「开始」按钮开始计时
3. **控制志愿者**：
   - 点击并拖动金色的「志」字图标可以移动志愿者
   - 点击选中一个志愿者后，使用方向按钮（↑↓←→）设置指引方向
   - 点击「✕」清除方向指引
4. **使用广播**：
   - 😌 安抚广播：提升人群耐心，但有使用惩罚
   - ⚡ 紧急广播：加速人群移动，但会降低耐心
5. **处理事件**：游戏进行中会弹出突发事件对话框，需要选择应对策略
6. **暂停/继续**：点击「暂停」按钮暂停游戏
7. **重置**：点击「重置」按钮重新开始当前关卡
8. **导出报告**：游戏结束后点击「导出复盘报告」下载Markdown格式的详细报告

## 关卡数据结构

关卡使用JSON格式定义，可以自定义创建新关卡。

### 基本结构

```json
{
  "id": "关卡唯一标识",
  "name": "关卡显示名称",
  "description": "关卡描述",
  "duration": 600,
  "totalPeople": 30,
  
  "population": {
    "normal": 0.6,
    "elderly": 0.2,
    "child": 0.15,
    "disabled": 0.05
  },
  
  "grid": {
    "width": 16,
    "height": 10,
    "tiles": [
      "wall", "wall", "...",
      "...", "entrance", "...",
      "...", "exit", "...",
      "wall", "wall", "..."
    ]
  },
  
  "volunteerPositions": [
    { "x": 8, "y": 4 }
  ],
  
  "events": [
    {
      "id": "event_1",
      "type": "broadcast_announcement",
      "triggerType": "time",
      "triggerTime": 60,
      "description": "事件描述"
    }
  ],
  
  "scoring": {
    "pointsPerEvacuation": 10,
    "timeBonusPerSecond": 1,
    "penaltyPerPanic": 20,
    "penaltyPerVolunteerAction": 5,
    "penaltyPerBroadcast": 15,
    "panicThreshold": 0.3
  }
}
```

### 瓦片类型

| 类型 | 说明 |
|------|------|
| `floor` | 可通行的地面 |
| `wall` | 不可通行的墙壁 |
| `entrance` | 入口（人群生成点） |
| `exit` | 出口（疏散目标） |
| `obstacle` | 障碍物 |
| `volunteer_spawn` | 志愿者出生点 |

### 事件类型

| 类型 | 说明 |
|------|------|
| `broadcast_announcement` | 广播指令事件（需要玩家选择） |
| `temporary_blockage` | 临时封路 |
| `medical_emergency` | 医疗紧急情况 |
| `additional_crowd` | 额外人群涌入 |
| `equipment_failure` | 设备故障 |

### 广播类型

| 类型 | 效果 |
|------|------|
| `calm_message` | 安抚广播：提升耐心 |
| `general_evacuation` | 紧急疏散：加速但降低耐心 |
| `specific_exit` | 指定出口 |
| `warning_message` | 警告广播：大幅加速但降低耐心 |

## 技术说明

### 核心模块说明

#### 1. levels.js (关卡数据模型)
- 定义瓦片类型、人群类型、游戏状态
- 提供关卡数据验证函数
- 实现人员和志愿者对象创建
- 初始化游戏状态

#### 2. state.js (状态管理)
- 实现游戏状态转换（开始/暂停/结束）
- 提供动作记录系统
- 实现计分计算
- 检查游戏结束条件

#### 3. pathfinding.js (寻路和拥堵)
- 实现A*寻路算法
- 检测拥堵和人群碰撞
- 更新人员移动和状态
- 应用志愿者引导效果

#### 4. events.js (事件系统)
- 定义5种突发事件类型
- 实现事件触发检测
- 应用事件效果到游戏状态
- 提供事件卡UI数据

#### 5. save.js (存档系统)
- 使用localStorage持久化数据
- 保存/读取最高分
- 保存/读取回放记录
- 保存/读取游戏状态

#### 6. export.js (导出系统)
- 生成Markdown格式复盘报告
- 包含详细统计和评估
- 提供下载功能

#### 7. render.js (渲染系统)
- Canvas游戏画面渲染
- 网格、人员、志愿者绘制
- UI状态更新
- 事件卡和广播消息显示

#### 8. game.js (游戏主控制)
- 整合所有模块
- 游戏主循环
- 用户输入处理
- 关卡加载

### 游戏循环

```
requestAnimationFrame →
  计算时间增量(deltaTime) →
    更新人员移动和状态 →
    检查事件触发 →
    应用事件效果 →
    检查游戏结束 →
    计算得分 →
  渲染画面 →
  更新UI →
  继续循环
```

### 寻路算法

使用A*算法（A-star）进行路径规划：
- 启发函数：曼哈顿距离
- 考虑因素：
  - 瓦片可通行性
  - 当前拥堵情况（人群密度增加移动成本）
  - 临时封路

### 拥堵检测

当人员满足以下条件时视为拥堵：
1. 周围0.8单位范围内有其他人员
2. 前方路径被其他人员阻挡
3. 阻塞时间超过3秒

拥堵时：
- 耐心值加速下降
- 尝试寻找其他路径
- 状态变为"阻塞"（显示为橙色）

### 数据存储

所有数据存储在浏览器的localStorage中：

| Key | 说明 |
|-----|------|
| `evacuation_sim_high_scores` | 各关卡最高分记录 |
| `evacuation_sim_replays` | 回放记录（最近20条） |
| `evacuation_sim_saves` | 存档列表（最近10条） |
| `save_{levelId}_{timestamp}` | 具体存档数据 |
| `evacuation_sim_settings` | 游戏设置 |

## 常见问题

### Q: 为什么打开index.html后关卡不加载？
A: 这是因为浏览器的安全策略阻止了本地文件的fetch请求。请使用本地HTTP服务器（如`npm start`或`python -m http.server`）来运行游戏。

### Q: 如何创建自己的关卡？
A: 复制现有关卡JSON文件，修改以下内容：
1. 修改`id`和`name`字段
2. 调整`grid.tiles`数组定义地图
3. 设置`volunteerPositions`志愿者初始位置
4. 配置`events`事件列表
5. 在`index.html`的关卡选择下拉框中添加新关卡

### Q: 游戏数据存储在哪里？
A: 所有数据存储在浏览器的localStorage中，清除浏览器数据会丢失这些记录。

### Q: 如何导出复盘报告？
A: 游戏结束后点击「导出复盘报告」按钮，会自动下载Markdown格式的报告。可以使用任何Markdown编辑器（如Typora、VS Code）打开查看。

### Q: 志愿者的影响范围有多大？
A: 志愿者的影响半径默认为2个瓦片单位。在范围内的人群会：
1. 耐心值得到提升
2. 如果设置了方向指引，会被引导到指定方向
