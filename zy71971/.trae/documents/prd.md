## 1. 产品概述

合同条款问答管理系统，面向客服、质检和知识库运营团队，解决合同条款问答中灰度结论与报表不一致、争议记录无法溯源、数据操作口径混乱等核心问题。系统提供自动判断与原因展示、争议记录待确认标记、以及重复导入/撤回修正/筛选导出的一致性操作，确保每条结论可复核、可追溯、可解释。

- 目标用户：客服团队、质检团队、知识库运营、业务负责人
- 核心价值：把争议记录从"不敢确认"变为"有据可查"，让业务负责人不看代码也能理解判断原因和下一步操作

## 2. 核心功能

### 2.1 用户角色

| 角色 | 权限说明 |
|------|----------|
| 运营人员 | 导入合同条款、查看问答结果、标记待确认、导出报表 |
| 质检人员 | 审核灰度结论、复核争议记录、查看判断原因、确认/驳回 |
| 业务负责人 | 查看仪表盘总览、审批争议记录、查看原因与下一步建议 |
| 管理员 | 系统配置、用户管理、数据字典维护 |

### 2.2 功能模块

1. **问答总览页**：仪表盘展示待确认数量、灰度冲突数、敏感词漏检数等关键指标，附趋势图和异常告警
2. **条款问答页**：合同条款的问答记录列表，支持自动判断、判断理由展示、筛选与导出
3. **争议复核页**：灰度结论与报表不一致等争议记录的集中复核，含原因链和下一步建议
4. **导入管理页**：合同条款的批量导入、重复检测、撤回修正操作，确保操作口径一致
5. **质检报表页**：质检周报与明细，含争议记录的复核原因（不只是总数）

## 3. 核心流程

### 3.1 合同条款导入与判断流程

用户上传合同条款 → 系统自动解析条款 → 执行三重检测（答案来源断链检测、灰度结论一致性检测、敏感词脱敏检测）→ 根据检测结果标记状态（正常/待确认）→ 待确认记录进入争议复核队列

```mermaid
flowchart TD
    "上传合同条款" --> "解析条款内容"
    "解析条款内容" --> "答案来源断链检测"
    "解析条款内容" --> "灰度结论一致性检测"
    "解析条款内容" --> "敏感词脱敏检测"
    "答案来源断链检测" --> "判断结果汇总"
    "灰度结论一致性检测" --> "判断结果汇总"
    "敏感词脱敏检测" --> "判断结果汇总"
    "判断结果汇总" --> "是否全部通过?"
    "是否全部通过?" -->|"是"| "标记为正常"
    "是否全部通过?" -->|"否"| "标记为待确认 + 记录判断理由"
    "标记为待确认 + 记录判断理由" --> "进入争议复核队列"
```

### 3.2 争议复核流程

争议记录进入复核队列 → 质检人员查看争议原因和证据 → 执行复核操作（确认/驳回/标记已知问题）→ 更新记录状态 → 同步更新报表数据

```mermaid
flowchart TD
    "争议记录入队" --> "查看争议原因与证据"
    "查看争议原因与证据" --> "查看下一步建议"
    "查看下一步建议" --> "复核决策"
    "复核决策" -->|"确认"| "转为正常记录"
    "复核决策" -->|"驳回"| "退回修正 + 记录驳回原因"
    "复核决策" -->|"已知问题"| "标记为已知问题 + 定期复查"
    "转为正常记录" --> "同步更新报表"
    "退回修正 + 记录驳回原因" --> "修正后重新检测"
    "修正后重新检测" --> "再次进入判断流程"
```

## 4. 用户界面设计

### 4.1 设计风格

- 主色调：深青灰(#1a2332)搭配琥珀色(#f59e0b)作为强调色，传达专业与警示感
- 辅助色：翠绿(#10b981)表示正常/已确认，玫红(#ef4444)表示异常/待确认，天蓝(#3b82f6)表示信息/操作
- 按钮风格：圆角6px，中等阴影，状态标签使用药丸形(pill)设计
- 字体：标题使用 Noto Serif SC 衬线体传达法律/合同感，正文使用 Noto Sans SC 无衬线体保证可读性
- 布局风格：左侧固定导航栏 + 右侧内容区，卡片式布局，表格式数据展示
- 图标风格：线性图标，2px描边，与文字等高对齐

### 4.3 响应式设计

- 桌面优先设计，最小宽度1280px保证数据表格可读性
- 平板端导航栏折叠为汉堡菜单，表格支持水平滚动
- 移动端仅保留核心查看功能，操作功能引导至桌面端
