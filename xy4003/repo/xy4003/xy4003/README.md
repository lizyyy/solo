# 物业寄存管理系统

一个给小型物业前台使用的全栈 Web 小工具，专门登记住户寄存钥匙和临时放行条。

## 功能特性

- **工作台界面**：左侧录入表单，右侧查询列表，操作便捷
- **数据持久化**：本地 SQLite 数据库，刷新页面或重启服务后数据不丢失
- **防重复录入**：同一房号同一手机号如有"待领取"记录，录入时自动拦截并提示
- **状态流转**：支持三种状态（待领取、已领取、已过期），领取时记录领取时间和操作人
- **自动过期检测**：查询时自动检查并标记过期记录（不覆盖历史状态）
- **CSV 导入导出**：支持批量导入导出，导入时逐行校验并给出明细

## 安装和启动

### 前置要求

- Node.js 14+
- npm 或 yarn

### 安装依赖

```bash
cd xy4003
npm install
```

### 启动服务

```bash
npm start
```

服务将在 `http://localhost:3000` 启动。

## 主要功能验证

### 1. 新增寄存记录

1. 打开 `http://localhost:3000`
2. 在左侧表单填写：
   - 房号：如 `1栋101`
   - 住户姓名：如 `张三`
   - 手机号：如 `13800138000`
   - 寄存物类型：选择 `钥匙` 或 `临时放行条`
   - 领取人（可选）：如 `李四`
   - 有效期：选择开始和结束日期
   - 备注（可选）：补充说明
3. 点击「提交登记」
4. 右侧列表将显示新增的记录

### 2. 防重复校验

1. 使用**相同房号**和**相同手机号**再次提交
2. 系统会提示：`该房号手机号已有待领取记录`
3. 必须先领取或过期后才能再次录入

### 3. 查询和筛选

- **按房号搜索**：输入房号（支持模糊匹配）
- **按手机号搜索**：输入手机号（支持模糊匹配）
- **按状态筛选**：选择「待领取」、「已领取」、「已过期」或全部
- 点击「搜索」或「刷新」按钮更新列表

### 4. 领取确认

1. 在列表中找到「待领取」状态的记录
2. 点击右侧「领取」按钮
3. 在弹出的确认框中输入**操作人姓名**（必填）
4. 点击「确认领取」
5. 记录状态变为「已领取」，同时记录领取时间和操作人

### 5. 自动过期检测

- 每次查询列表时，系统会自动检查有效期
- 有效期结束日期早于当前日期的「待领取」记录，会自动标记为「已过期」
- 已领取的记录不会被修改

### 6. CSV 导出

1. 点击页面右上角「导出 CSV」
2. 系统将下载所有记录，包含以下字段：
   - ID、房号、住户姓名、手机号
   - 寄存物类型、领取人、有效期开始/结束
   - 备注、状态、创建时间、更新时间
   - 领取时间、领取操作人

### 7. CSV 导入

1. 点击页面右上角「导入 CSV」
2. 选择符合格式的 CSV 文件（建议先导出一份作为模板）
3. 系统将逐行处理，完成后显示结果：
   - **成功**：有效且无重复的记录
   - **跳过**：已有待领取记录的重复数据
   - **失败**：缺少必填字段或其他错误
4. 点击「关闭」后列表自动刷新

## API 接口说明

### 记录管理

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/records` | 查询记录（支持参数：room_number, phone, status） |
| GET | `/api/records/:id` | 获取单条记录 |
| POST | `/api/records` | 新增记录 |
| PUT | `/api/records/:id/status` | 更新状态（支持：已领取、已过期） |
| GET | `/api/records/check-expired` | 手动触发过期检查 |

### CSV 操作

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/csv/export` | 导出所有记录为 CSV |
| POST | `/api/csv/import` | 导入 CSV 文件（multipart/form-data，字段名：file） |

## 数据库表结构

```sql
CREATE TABLE records (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  room_number TEXT NOT NULL,        -- 房号
  resident_name TEXT NOT NULL,       -- 住户姓名
  phone TEXT NOT NULL,               -- 手机号
  storage_type TEXT NOT NULL,        -- 寄存物类型
  receiver_name TEXT,                -- 领取人
  valid_from TEXT NOT NULL,          -- 有效期开始
  valid_to TEXT NOT NULL,            -- 有效期结束
  remarks TEXT,                      -- 备注
  status TEXT NOT NULL DEFAULT '待领取',  -- 状态
  created_at TEXT NOT NULL,          -- 创建时间
  updated_at TEXT NOT NULL,          -- 更新时间
  received_at TEXT,                  -- 领取时间
  received_by TEXT                   -- 领取操作人
)
```

## 注意事项

1. **数据存储**：数据库文件位于 `data/storage.db`，请确保目录有写入权限
2. **手机号格式**：前端会校验 11 位手机号格式
3. **过期逻辑**：仅在查询时自动检查，已领取记录不受影响
4. **并发安全**：适用于单用户前台场景，高并发场景建议加锁
