# 可复用物资回收称重台

一个用于大型志愿活动后勤组的本地桌面 GUI 工具，用于管理可复用物资的回收登记、称重校验、押金结算和异常追踪。

## 功能特性

### 核心功能
- **物资管理**：导入物资清单 CSV，管理帐篷、马甲、对讲机、电源线等可复用物资
- **借出/归还**：支持扫码或手工登记归还，实时称重校验
- **破损登记**：支持破损拍照和备注，追踪破损责任
- **规则引擎**：自动检测异常情况
  - 重复归还检测
  - 缺件检测
  - 重量异常检测
  - 押金不匹配检测
  - 超时未归还检测
- **撤销操作**：所有操作支持撤销，记录完整审计日志
- **数据导出**：支持多种导出格式
  - Markdown 结算单
  - CSV 异常表
  - JSON 审计包

### 界面展示
- 按摊位/志愿队展示回收进度
- 实时异常检测提示
- 完整的操作日志查看

## 数据模型说明

### 核心实体

| 实体 | 说明 | 主要字段 |
|------|------|----------|
| Team | 志愿队/摊位 | 队伍编号、名称、摊位号、联系人 |
| Material | 可复用物资 | 条形码、类型、名称、规格、标准重量、状态 |
| BorrowRecord | 借出记录 | 借出编号、队伍、借出时间、预计归还时间、押金金额、押金条编号 |
| BorrowItem | 借出明细 | 借出记录ID、物资ID、数量、已归还数量 |
| ReturnRecord | 归还记录 | 归还编号、对应借出记录、归还时间、总重量、实退押金 |
| ReturnItem | 归还明细 | 归还记录ID、物资ID、数量、实测重量、是否破损 |
| DamageRecord | 破损记录 | 破损类型、描述、照片路径、责任人、预估费用 |
| AnomalyRecord | 异常记录 | 异常类型、描述、状态、解决方案 |
| AuditLog | 审计日志 | 操作类型、实体类型、操作前后数据、操作人 |

### 状态枚举

**物资状态 (MaterialStatus):**
- AVAILABLE = "可用"
- BORROWED = "借出"
- RETURNED = "已归还"
- DAMAGED = "损坏"
- LOST = "丢失"

**归还状态 (ReturnStatus):**
- PENDING = "待归还"
- PARTIAL = "部分归还"
- COMPLETED = "已完成"
- OVERDUE = "已超时"

## 本地验证流程

### 第一步：导入基础数据

1. 启动程序后，点击菜单栏 `文件` -> `导入`
2. 按顺序导入以下文件（都在 `data/` 目录下）：

   **a. 导入物资清单**
   - 选择 `导入物资清单 CSV`
   - 选择 `data/materials.csv`
   - 包含 20 条物资数据：帐篷、马甲、对讲机、电源线等

   **b. 导入队伍/摊位**
   - 选择 `导入队伍/摊位 CSV`
   - 选择 `data/teams.csv`
   - 包含 8 个志愿队

   **c. 导入借出记录**
   - 选择 `导入借出记录 CSV`
   - 选择 `data/borrow_records.csv`
   - 包含 6 条借出记录，每条对应物资已借出

   **d. 导入现场回收 JSONL (可选)**
   - 选择 `导入现场回收 JSONL`
   - 选择 `data/field_records.jsonl`
   - 包含 2 条额外的借出记录

### 第二步：查看回收进度

导入完成后，左侧面板会显示：
- 所有志愿队/摊位的列表
- 每队的借出/归还数量
- 当前状态（待归还/部分归还/已完成）

可以使用：
- 搜索框：按队伍编号、名称或摊位号筛选
- 状态筛选：只显示特定状态的队伍

### 第三步：进行归还登记

1. 在左侧面板选中一个志愿队（如 `志愿者第一大队`）
2. 在右侧 `详情` 标签页的 `借出详情` 表格中，选择一条借出记录
3. 点击工具栏的 `归还登记` 按钮，或使用菜单操作

#### 归还登记窗口操作：

1. **扫码或手工输入**
   - 在条形码输入框输入物资条形码（如 `MAT001`）
   - 按回车或点击 `添加` 按钮
   - 系统会自动检查：
     - 该物资是否属于本次借出
     - 是否已归还过（防重复）

2. **添加所有待归还物资**
   - 依次添加：`MAT001`、`MAT006`、`MAT011`、`MAT016`
   - 已添加的物资会显示在列表中

3. **称重校验 (可选)**
   - 列表中的 `重量(kg)` 列可编辑
   - 修改后系统会自动与标准重量对比
   - 重量差异超过阈值（默认 ±5% 或 ±0.5kg）会触发异常提示

4. **破损登记**
   - 点击某物资的 `破损` 复选框
   - 在弹出的对话框中：
     - 选择破损类型（轻微磨损/明显损坏/严重损坏/丢失/其他）
     - 填写破损描述
     - 可选择上传照片（支持 jpg/png/bmp）

5. **异常检测**
   - 添加物资过程中，底部 `异常检测` 区域会实时显示：
     - 重复归还警告
     - 缺件提示（与借出数量对比）
     - 重量异常
     - 押金不匹配
     - 超时归还

6. **结算信息**
   - `实退押金`：默认为借出时的押金金额，可修改
   - `接收人`：填写接收人姓名（可选）
   - `备注`：添加备注信息

7. **确认归还**
   - 点击 `确认归还` 按钮
   - 确认对话框会显示归还物资数量和实退押金
   - 确认后系统会：
     - 保存归还记录
     - 更新物资状态
     - 更新借出状态
     - 记录异常（如有）
     - 写入审计日志

### 第四步：测试异常场景

#### 场景 1：重复归还
- 添加 `MAT001` 后，再次尝试添加同一个条形码
- 系统会提示 `重复归还` 警告

#### 场景 2：缺件检测
- 只添加部分物资（如只添加 2 件，借出记录有 4 件）
- 异常区域会显示 `缺件` 提示

#### 场景 3：重量异常
- 添加 `MAT001` 后，将重量从 15.5kg 改为 5.0kg
- 异常区域会显示 `重量异常` 提示

#### 场景 4：押金不匹配
- 将 `实退押金` 从 500.00 改为 300.00
- 异常区域会显示 `押金不匹配` 提示

#### 场景 5：超时归还（需要模拟）
- 选择一个预计归还时间已过的借出记录
- 或在测试时修改系统时间

### 第五步：撤销操作

1. 点击菜单栏 `编辑` -> `撤销`，或工具栏的 `撤销` 按钮
2. 或切换到 `操作日志` 标签页查看所有可撤销操作
3. 点击撤销后：
   - 确认要撤销的操作
   - 系统会恢复操作前的状态
   - 该日志标记为 `已撤销`

### 第六步：导出数据

#### 导出 Markdown 结算单
1. 在左侧面板选中一个志愿队
2. 点击 `文件` -> `导出` -> `导出 Markdown 结算单`
3. 选择保存路径
4. 生成的文件包含：
   - 队伍基本信息
   - 汇总统计（借出/归还数量、押金、破损费用）
   - 借出记录详情
   - 归还记录详情
   - 破损记录
   - 异常记录

#### 导出 CSV 异常表
1. 点击 `文件` -> `导出` -> `导出 CSV 异常表`
2. 选择保存路径
3. 包含所有异常记录，可用于后续处理

#### 导出 JSON 审计包
1. 点击 `文件` -> `导出` -> `导出 JSON 审计包`
2. 选择保存路径
3. 完整的审计数据，包含：
   - 所有队伍信息
   - 所有物资信息
   - 所有借出/归还记录
   - 所有破损/异常记录
   - 所有操作日志

## 规则引擎说明

### 检测规则

| 规则类型 | 触发条件 | 处理方式 |
|----------|----------|----------|
| 重复归还 | 同一物资在本次借出中已归还过 | 禁止添加，提示错误 |
| 缺件 | 归还物资数量 < 借出物资数量 | 记录警告，允许继续 |
| 重量异常 | 实测重量与标准重量差异超过阈值 | 记录警告，允许继续 |
| 押金不匹配 | 实退押金 ≠ 应交押金 | 记录警告，允许继续 |
| 超时归还 | 归还时间 > 预计归还时间 | 记录警告，允许继续 |

### 重量阈值配置

在 `src/rules/rules_engine.py` 中：
```python
WEIGHT_TOLERANCE_PERCENT = 0.05  # 5% 百分比容差
WEIGHT_TOLERANCE_KG = 0.5        # 0.5kg 绝对值容差
```

实际容差取两者中的较大值。

## 导入文件格式说明

### 物资清单 CSV (materials.csv)
```csv
barcode,material_type,material_name,specification,weight_kg,description
MAT001,帐篷,3x3米帐篷,蓝色 3*3米,15.5,标准蓝色帐篷
```

| 字段 | 必填 | 说明 |
|------|------|------|
| barcode | 是 | 物资条形码，唯一标识 |
| material_type | 是 | 物资类型（帐篷/马甲/对讲机/电源线等） |
| material_name | 是 | 物资名称 |
| specification | 否 | 规格型号 |
| weight_kg | 否 | 标准重量(kg)，用于重量校验 |
| description | 否 | 描述说明 |

### 队伍/摊位 CSV (teams.csv)
```csv
team_code,team_name,booth_number,contact_person,contact_phone
TEAM001,志愿者第一大队,A01,张三,13800138001
```

| 字段 | 必填 | 说明 |
|------|------|------|
| team_code | 是 | 队伍编号，唯一标识 |
| team_name | 是 | 队伍名称 |
| booth_number | 否 | 摊位编号 |
| contact_person | 否 | 联系人姓名 |
| contact_phone | 否 | 联系电话 |

### 借出记录 CSV (borrow_records.csv)
```csv
borrow_code,team_code,borrow_date,expected_return_date,deposit_amount,deposit_slip_code,borrower_name,barcodes
BR001,TEAM001,2026-05-01 08:00:00,2026-05-01 18:00:00,500.00,DEP001,张三,MAT001,MAT006
```

| 字段 | 必填 | 说明 |
|------|------|------|
| borrow_code | 是 | 借出编号，唯一标识 |
| team_code | 是 | 对应的队伍编号 |
| borrow_date | 是 | 借出时间，格式：YYYY-MM-DD HH:MM:SS |
| expected_return_date | 否 | 预计归还时间 |
| deposit_amount | 否 | 押金金额(元) |
| deposit_slip_code | 否 | 押金条编号 |
| borrower_name | 否 | 借出人姓名 |
| barcodes | 是 | 借出物资条形码，多个用逗号分隔 |

### 现场回收 JSONL (field_records.jsonl)
每行一个 JSON 对象：
```json
{"borrow_code": "BR007", "team_code": "TEAM007", "borrow_date": "2026-05-01 10:00:00", "expected_return_date": "2026-05-01 18:00:00", "deposit_amount": 100.0, "deposit_slip_code": "DEP007", "borrower_name": "吴九", "barcodes": ["MAT001", "MAT006"]}
```

字段含义同 CSV 格式，barcodes 为数组类型。

## 数据存储

- 数据库：SQLite
- 位置：`data/recycle_station.db`
- 首次运行时自动创建

## 注意事项

1. **条码唯一性**：系统通过条形码识别物资，确保条码唯一
2. **重量校验**：需要提前在物资清单中设置标准重量才能启用
3. **撤销限制**：撤销操作只能按时间顺序逆序进行
4. **数据备份**：定期导出 JSON 审计包进行备份
5. **图片存储**：破损照片只记录路径，不存入数据库，注意图片路径变更

## 故障排查

### 界面启动失败
- 检查 Python 版本 >= 3.9
- 检查 PyQt5 是否正确安装：`pip install PyQt5`
- 检查是否有其他依赖缺失

### 导入失败
- 检查 CSV 文件编码（推荐 UTF-8）
- 检查必填字段是否完整
- 检查条形码是否重复

### 数据库错误
- 删除 `data/recycle_station.db` 重新启动（会清空所有数据）
- 检查磁盘空间和权限
