# 耳返频段冲突记录系统

老周你好，这是咱琴行的耳返频段冲突记录本。音乐老师过来问的时候，你就按这里写的来，别慌。

---

## 一句话说清楚

同一首歌可能有俩名字：现场叫的名和版权登记的名。这不是啥稀罕事，咱按规矩来：先别急着归正常，留给音乐老师看看再说。

---

## 核心规矩（边界规则）

### 1. 同一首歌有俩名字怎么办？

**怎么判断：**
- 现场名填了，版权名也填了
- 俩名字还不一样

比如：现场叫"青花瓷(即兴版)"，版权叫"青花瓷"

**怎么处理：**
- 自动标记为"待音乐老师复核"
- 别手快直接点"正常"
- 老师看完说没问题，再改状态

**怎么撤回：**
- 要是误判了，撤回到"待复核"就行

> 老周记：就像一把吉他有俩名，学生叫"木吉他"，进货单叫"民谣吉他"，先别忙着贴标签，问清楚再说。

### 2. 状态怎么改？

状态就像调琴弦，一步一步来：

```
待复核 → 正常 / 异常 / 待老师复核
待老师复核 → 正常 / 异常 / 待复核
正常 ↔ 异常 ↔ 待老师复核
```

> 老周记：不能从"断弦"直接跳到"调好"，得一步一步拧。

### 3. 改记录要留痕

谁改的、改了啥、原来啥样、为啥改，一个都不能少。

> 老周记：就像调音师留便签，下次调的时候能看到上回咋调的。音乐老师追问时，能拿出证据来。

## 三步标准流程

### 第一步：授权期限页第一次导入

老周你把授权期限页的内容导进来，系统自动：
- 记下原始行号（第几行来的，别丢）
- 检查是不是一首歌俩名字
- 双名的自动标"待老师复核"，其他的先"待复核"

### 第二步：琴行店长老周补看调音师留言

你把调音师写的小纸条内容补进去：
- 找到对应记录
- 把留言写上
- 系统自动记下来是谁补的、什么时候补的

### 第三步：给店长看的周报更新

所有状态确认没问题了，点"生成周报"：
- 系统自动统计正常多少、异常多少、待复核多少
- 留一个版本号，下次能撤回来

---

## 撤回操作

### 场景：老周误把调音师留言当成新材料，周报发错了

点"撤回上一版周报"：
- 周报回到上一个版本
- 记录状态也同步退回去
- 就像吉他弦拧多了，往回拧半圈

### 场景：单条记录状态改错了

找到那条记录，点"撤回状态改动"：
- 回到上一个状态
- 双名歌曲会退回到"待复核"

---

## 三个地方看同一份数据

你放心：
- 页面上看到的
- 导出来的Excel
- 接口返回给别人的

都是同一份数据，不会一个地方显示异常、另一个地方消失。

每条记录都能查到：
- 原始行号（从授权期限页第几行来的）
- 人工改动记录（谁改的、改了啥）
- 当前处理状态

## 给技术人员看的

### 数据模型

```
ConflictRecord {
  id: 唯一标识
  originalRowNumber: 原始行号
  song: {
    liveName: 现场名
    copyrightName: 版权名
    hasDualNames: 是否双名
  }
  band: 频段
  conflictDescription: 冲突描述
  processingStatus: 处理状态
  workflowStep: 当前流程步骤
  engineerMessage: 调音师留言
  manualChanges: [人工改动记录]
  importedBy: 导入人
}
```

### 状态枚举

- `pending_review` - 待复核
- `normal` - 正常
- `abnormal` - 异常
- `needs_teacher_review` - 待音乐老师复核

### 流程步骤

- `initial_import` - 第一次导入
- `engineer_message_added` - 已补看留言
- `weekly_report_updated` - 已更新周报
