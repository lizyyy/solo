# 推送频控后端服务 - 运行与验收手册

## 一、服务启动

### 环境要求
- Node.js 16+
- npm 7+

### 从空环境启动步骤

1. 进入项目目录
```bash
cd /path/to/project
```

2. 安装依赖
```bash
npm install
```

3. 启动服务
```bash
npm start
```

你会看到输出：
```
已连接到推送频控数据库
推送频控后端服务已启动: http://localhost:3000
```

服务默认监听 3000 端口，首次启动会自动创建 SQLite 数据库文件 `frequency_control.db`，并初始化 4 条默认频控规则。

## 二、核心功能验收

```json
      "状态": "启用"
    },
    {
      "规则名称": "用户小时限1条",

      "时间范围": "每小时",
      "限制条数": 1,
```

### 2. 创建一个活动

请求：
```bash
curl -X POST http://localhost:3000/api/activities \
  -H "Content-Type: application/json" \
  -d '{
    "name": "双十一全场满减",
    "scene": "promotion",
    "priority": 10,
    "status": "active"
  }'
```

预期返回：
```json
{
  "success": true,
  "message": "活动「双十一全场满减」创建成功，优先级10",
  "data": {
    "活动ID": "xxxx-xxxx-xxxx",
    "活动名称": "双十一全场满减",
    "所属场景": "promotion",
    "优先级": 10
  }
}
```

**验收要点**：优先级数字越大优先级越高，高优先级活动不会被低优先级的频控抢占。

记录返回的活动ID，后续会用到（记为 `$ACTIVITY_ID`）。

### 3. 发送第一条推送（应该成功）

请求：
```bash
curl -X POST http://localhost:3000/api/messages/send \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "user_001",
    "device_id": "device_iphone_123",
    "activity_id": "$ACTIVITY_ID",
    "content": "双十一大促来啦！"
  }'
```

预期返回（成功情况）：
```json
{
  "success": true,
  "status": "发送成功",
  "message": "已通过所有频控检查并成功发送",
  "message_id": "xxxx-xxxx",
  "check_summary": [
    {
      "rule_name": "用户日限3条",
      "dimension": "用户",
      "current_count": 0,
      "limit_count": 3,
      "status": "pass",
      "reason": "当前0条，未超过3条限制"
    },
    {
      "rule_name": "设备活动去重",
      "status": "pass",
      "reason": "该设备在本活动中未发送过"
    }
  ]
}
```

**验收要点**：
- `check_summary` 显示每条规则的检查结果和原因
- `current_count` 是发送前的计数
- 用户成功加入用户桶

### 4. 触发用户小时级频控（应该被拦截）

默认规则：用户每小时限发 1 条。

请求（立即再次发送，使用同一个 user_id）：
```bash
curl -X POST http://localhost:3000/api/messages/send \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "user_001",
    "device_id": "device_iphone_123",
    "activity_id": "$ACTIVITY_ID",
    "content": "再发一条试试"
  }'
```

预期返回（被拦截）：
```json
{
  "success": false,
  "status": "被频控拦截",
  "message": "发送被频控规则拦截",
  "current_block": {
    "rule": "用户小时限1条",
    "reason": "用户[user_001]在1hour内已发送1条，达到1条上限"
  },
  "last_processing": {
    "time": "2026-05-10Txx:xx:xx.xxxZ",
    "result": "允许发送",
    "status": "allowed"
  }
}
```

**验收要点**：
- 明确告诉你「被频控拦截」，不是错误码
- `current_block.reason` 用自然语言解释为什么被拦
- `last_processing` 告诉你上一次的处理结果

### 6. 触发设备去重

使用不同用户但相同设备再发一次：

```bash

  -H "Content-Type: application/json" \
  -d '{
    "user_id": "user_002",
    "device_id": "device_iphone_123",
    "activity_id": "$ACTIVITY_ID",
    "content": "换个用户同个设备"
  }'
```

预期返回：
```json

  "status": "被频控拦截",
  "current_block": {
    "rule": "设备活动去重",
    "message": "该设备在本活动中已收到过推送"
```

## 三、默认规则说明

首次启动会自动创建以下 4 条规则：

| 规则名称 | 限制维度 | 时间范围 | 限制条数 | 说明 |
|---------|---------|---------|---------|------|
| 用户日限3条 | 用户 | 每日 | 3条 | 单个用户每天最多收3条推送 |
| 用户小时限1条 | 用户 | 每小时 | 1条 | 避免短时间重复打扰 |
| 设备日限2条 | 设备 | 每日 | 2条 | 同一台设备每天最多收2条 |
| 场景活动高峰限5条/分钟 | 场景 | 活动高峰 | 5条 | 大促场景下每分钟最多发5条 |

可以通过以下接口管理规则：
- `POST /api/rules` - 新增规则
- `PUT /api/rules/:id` - 更新规则
- `PUT /api/rules/:id/toggle` - 启用/停用
- `DELETE /api/rules/:id` - 删除

## 四、核心业务规则说明

### 频控检查顺序
1. 用户级频控（先检查用户日限、再检查小时限）
2. 设备级频控
3. 场景级频控
4. 设备活动去重（同一设备在同一活动中只能收一次）

任一规则不通过则立即拦截。

### 活动优先级
- 数值越大，优先级越高
- 统计数据按优先级排序展示
- 高优先级活动不会被低优先级活动的频控影响（各自独立计数）

### 补偿机制
- 首次失败后 5 分钟自动重试
- 第二次失败后 15 分钟自动重试
- 最多重试 3 次
- 也支持手动触发补偿

## 五、快速体验场景

### 场景一：验证用户日限
```bash
# 发3条都应该成功（使用不同的设备，避免设备级去重）
for i in 1 2 3; do
  curl -X POST http://localhost:3000/api/messages/send \
    -H "Content-Type: application/json" \
    -d "{
      \"user_id\": \"test_user_100\",
      \"device_id\": \"device_$i\",
      \"activity_id\": \"$ACTIVITY_ID\",
      \"content\": \"第${i}条\"
    }"
  echo ""
  sleep 1
done

# 第4条应该被「用户日限3条」拦截
curl -X POST http://localhost:3000/api/messages/send \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "test_user_100",
    "device_id": "device_4",
    "activity_id": "$ACTIVITY_ID",
    "content": "第4条"
  }'
```

### 场景二：验证卡点查询
```bash
# 先被拦截一次（上面已完成）
# 再查卡点
curl "http://localhost:3000/api/messages/block-point?user_id=test_user_100&device_id=device_4&activity_id=$ACTIVITY_ID"
```

### 场景三：活动高峰场景
创建一个「秒杀」场景活动，优先级设为最高：
```bash
# 创建活动
ACTIVITY_ID_SECKILL=$(curl -s -X POST http://localhost:3000/api/activities \
  -H "Content-Type: application/json" \
  -d '{"name": "限时秒杀", "scene": "seckill", "priority": 100}' | grep -o '"活动ID":"[^"]*"' | cut -d'"' -f4)

# 快速发送5条
for i in 1 2 3 4 5 6; do
  curl -X POST http://localhost:3000/api/messages/send \
    -H "Content-Type: application/json" \
    -d "{
      \"user_id\": \"seckill_user_$i\",
      \"device_id\": \"seckill_device_$i\",
      \"activity_id\": \"$ACTIVITY_ID_SECKILL\",
      \"content\": \"秒杀通知\"
    }"
  echo ""
done
```

第6条会被「场景活动高峰限5条/分钟」拦截。
