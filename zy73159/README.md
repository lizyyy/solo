# 深海采样报告汇总工具

港口工程师老何专用 —— 月底复核不再翻烂记录本。

## 先跑哪条命令？

```bash
python -m deep_sea_report --input ./sample_input --output ./output
```

或者更短：

```bash
python -m deep_sea_report -i ./sample_input -o ./output
```

## 跑完看什么？按顺序来

| 顺序 | 文件 | 用途 | 看什么 |
|------|------|------|--------|
| 1 | 终端屏幕 | 快速概览 | 总数、已确认/待补件/退回各多少条、经纬度反写几条 |
| 2 | `output/summary_report.csv` | 汇总表 | 用 Excel 打开，按状态排序筛选；站名带逗号不会被截断 |
| 3 | `output/screenshot_notes.txt` | 截图说明 | **复核专用**，每条记录的问题详情、来源行号、原始内容都在这 |
| 4 | `output/raw_records_with_issues.json` | 原始数据追溯 | 保留原始记录本的一字一句，脏数据不擦除 |

> 💡 老何习惯：先看终端摘要心里有数，再开 CSV 过一遍，最后对着截图说明逐条复核。

## 能干什么

- **指定输入输出目录**：`-i` 输入，`-o` 输出，灵活方便
- **可靠 CSV 解析**：站名里带逗号用引号包的（比如`"带,逗号站"`）能正确识别，不再整列错位
- **多编码兼容**：自动识别 UTF-8 / GBK / GB2312 等常见编码
- **经纬度反写检测**：数值越界 + 方向标识错位双重判断，标出来源行号和影响范围
- **保留原始来源**：每条记录都能追溯到哪个文件、第几行、原始内容是什么
- **脏数据不瞎改**：只标记问题，不自动修正，痕迹全留着
- **状态三分法**：已确认 / 待补件 / 退回，月底复核一目了然
- **解析失败不丢行**：字段数不对、CSV 格式坏的行，归入待补件并说明原因
- **重跑不丢备注**：上次加的备注、截图说明，下次重跑还在

## 常用操作

### 正常汇总

```bash
python -m deep_sea_report -i ./sample_input -o ./output
```

### 清空历史重新来

```bash
python -m deep_sea_report -i ./sample_input -o ./output --reset
```

## 输入文件格式

支持 CSV / TXT / TSV，自动识别分隔符（逗号、制表符、分号、竖线）。

### 关于站点名里有逗号

标准 CSV 写法是用双引号把字段包起来，工具会正确处理，**不用手动改数据**：

```csv
站点编号,站点名称,采样时间,纬度,经度,...
ST104,"带,逗号站",2024-06-11 09:00,30.1111°N,121.2345°E,...
ST101,"蓝鲸湾,A区,一号站",2024-06-10 08:30,31.2345°N,121.6789°E,...
```

### 表头关键字（自动识别，不区分大小写）

| 字段 | 识别关键字 |
|------|-----------|
| 记录编号 | 编号、id、序号、记录号、站点编号 |
| 站点名称 | 站点名称、站点名、站名、站点、站号、station、站位 |
| 采样时间 | 采样时间、采样日期、时间、日期、time、date、观测时间 |
| 纬度 | 纬度、北纬、南纬、lat、latitude |
| 经度 | 经度、东经、西经、lon、lng、longitude |
| 深度 | 深度(m)、深度、水深、depth |
| 温度 | 温度(℃)、温度、水温、temp、temperature |
| 盐度 | 盐度(‰)、盐度、sal、salinity |

### 经纬度写法（都支持）

- 十进制度：`31.2345`、`-25.1234`
- 度分格式：`31°30'N`、`31°30.5'`
- 度分秒格式：`31°30'15"N`
- 带方向标识（前/后都可）：`N 31°30'`、`121°30'E`、`32.1234 N`

## 状态分类规则

| 状态 | 含义 | 典型场景 |
|------|------|----------|
| ✅ 已确认 | 关键字段齐全、经纬度解析正常 | 站名/时间/经纬度都有且合理 |
| 📋 待补件 | 能补，先挂着等材料 | 经纬度反写、缺字段、CSV 行解析失败、字段数不对 |
| ❌ 退回 | 根本没法用 | 经纬度乱写（abc 之类），完全无法解析 |

> 老何习惯：待补件列个清单催船上补；退回收件直接邮件打回，附截图说明里的来源行号。

## 输出文件说明

### `summary_report.csv`
汇总报表，Excel 友好（UTF-8 BOM 编码）。带逗号的站名会自动用双引号包裹，Excel 打开时完整显示。

### `screenshot_notes.txt`
截图说明文件。按**已确认 / 待补件 / 退回**三段分组，每条含：
- 来源文件 + 行号
- 原始内容（一字不改，脏数据原样保留）
- 问题列表 + 影响范围 + 来源行
- 老何之前写的备注、截图说明（重跑会保留）

### `raw_records_with_issues.json`
完整原始记录，JSON 格式。保留了从船上记录本读出来的原始内容，只在旁边追加问题标记，绝不修改原始数据。需要追溯的时候看这个。

### `report_state.json`
状态存档文件。记录了每条记录的**备注**、**截图说明**、状态。下次重跑会自动加载，老何写过的人工说法一个字都不会丢。
想清空重来加 `--reset` 参数。

## 样例材料说明

| 文件 | 用途 |
|------|------|
| `sample_input/log_book_01.csv` | 基础样例：标准写法、反写、缺字段、乱写等场景 |
| `sample_input/log_book_02.csv` | 第二船数据：N/E 前置写法、纯数字经纬度等 |
| `sample_input/log_book_03_comma_test.csv` | **逗号站名样例**：带双引号的多逗号站点名 + 字段数不匹配坏行 |

三个样例文件一起跑（默认就是这样），覆盖日常会碰到的大部分脏数据场景。
