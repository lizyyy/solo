# 殡仪馆冷藏柜流转管理系统

## 项目概述

本系统是为殡仪馆值班员设计的本地桌面工具，用于管理冷藏柜流转，自动检测异常情况，重建逝者和冷藏柜的流转时间线。

## 主要功能

- **数据导入**: 支持导入逝者信息、冷藏柜日志、交接记录和规则配置
- **时间线重建**: 按逝者和冷藏柜两个维度重建流转时间线
- **异常检测**: 自动检测以下异常情况：
  - 温度超窗：冷藏柜温度超出正常范围
  - 同柜重叠占用：同一冷藏柜被多人占用时间重叠
  - 交接签收缺失：交接记录缺少签收确认
  - 跨午夜归属错位：占用时间跨午夜需确认值班归属
  - 字段缺失：数据记录缺少必填字段
  - 重复交接：存在重复的交接记录
- **筛选查询**: 支持按日期、柜号、问题类型、状态筛选
- **状态管理**: 人工标记已处理，本地保存处理状态
- **导出功能**: 导出问题列表(CSV)和冷藏柜审核报告(Markdown)

## 系统要求

- Python 3.8+
- 依赖库：pandas, pyyaml, python-dateutil

```bash

```

### 方式二：指定数据目录

如果数据文件不在默认的 `sample_data` 目录，可以通过菜单手动导入：

1. 启动程序后，点击菜单 `文件` -> `导入数据文件...`

## 使用说明

### 界面介绍

主界面分为三个主要区域：

1. **筛选条件区**（顶部）：
   - 开始日期/结束日期：按时间范围筛选问题
   - 柜号：按冷藏柜编号筛选
   - 问题类型：按异常类型筛选
   - 状态：按处理状态筛选（全部/未处理/已处理）

2. **问题列表区**（左下）：
   - 显示所有符合筛选条件的问题
   - 点击列表项可查看详情
   - 严重程度颜色标识：
     - 红色：严重(Critical)
     - 橙色：高(High)
     - 灰色：已处理

3. **详情与统计区**（右部）：
   - 问题详情：显示选中问题的详细信息
   - 统计信息：显示问题总数、严重程度分布等

### 操作流程

#### 1. 数据导入

首次使用需要导入数据文件。如果使用示例数据，程序会自动加载 `sample_data` 目录下的文件。

#### 2. 查看问题列表

数据加载后，问题列表会自动显示所有检测到的异常。

#### 3. 筛选问题

使用顶部筛选条件缩小问题范围：
- 输入日期范围（格式：YYYY-MM-DD）
- 选择特定柜号
- 选择问题类型
- 点击「应用筛选」按钮

#### 4. 查看详情

点击列表中的问题项，右侧会显示：
- 问题基本信息（ID、类型、严重程度）
- 涉及的逝者和柜号
- 时间范围
- 问题描述
- 相关记录
- 处理信息（如果已处理）

#### 5. 查看时间线

选中问题后，点击「查看时间线」按钮，可以打开时间线查看窗口：
- 逝者时间线：显示该逝者的所有流转记录
- 冷藏柜时间线：显示该冷藏柜的占用历史和温度记录

#### 6. 标记已处理

选中未处理的问题，点击「标记为已处理」：
1. 输入处理人姓名
2. 输入处理备注（可选）
3. 确认后，问题状态会更新为已处理
4. 处理记录会自动保存到本地 `local_state.json`

#### 7. 导出报告

##### 导出问题列表

点击菜单 `文件` -> `导出问题列表 (CSV)`，选择保存位置，生成 `issues.csv` 文件。

CSV文件包含以下列：
- 问题ID、问题类型、严重程度
- 逝者ID、柜号
- 开始时间、结束时间
- 是否已处理、处理人、处理时间
- 问题描述、处理备注

##### 导出冷藏柜审核报告

点击菜单 `文件` -> `导出审核报告 (MD)`，选择保存位置，生成 `chamber_review.md` 文件。

报告包含：
- 问题概览（总数、已处理/未处理、按类型/严重程度统计）
- 每个冷藏柜的详细状态（当前占用、占用历史、温度记录、相关问题）
- 未处理问题详情
- 已处理问题记录

#### 8. 状态管理

##### 备份状态

点击菜单 `文件` -> `导出状态备份`，将当前的处理状态保存为JSON文件。

##### 恢复状态

点击菜单 `文件` -> `导入状态备份`，选择之前备份的状态文件：
- 选择「是」：合并现有状态和导入的状态
- 选择「否」：完全替换现有状态

#### 9. 查看冷藏柜状态

点击菜单 `查看` -> `查看所有冷藏柜状态`，可以查看所有冷藏柜的：
- 当前状态（空闲/占用中）
- 当前占用者
- 入柜时间
- 问题总数
- 未处理问题数

#### 10. 导出逝者时间线

点击菜单 `查看` -> `查看逝者时间线`，选择逝者ID后可以导出该逝者的完整时间线。

## 文件格式说明

### deceased.csv（逝者信息）

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| deceased_id | 字符串 | 是 | 逝者唯一标识 |
| name | 字符串 | 是 | 姓名 |
| gender | 字符串 | 否 | 性别 |
| birth_date | 日期 | 否 | 出生日期 (YYYY-MM-DD) |
| death_date | 日期 | 否 | 死亡日期 (YYYY-MM-DD) |
| cause_of_death | 字符串 | 否 | 死亡原因 |
| contact_person | 字符串 | 否 | 联系人 |
| contact_phone | 字符串 | 否 | 联系电话 |
| remarks | 字符串 | 否 | 备注 |

### cold_chamber_logs.jsonl（冷藏柜日志）

每行是一个JSON对象，字段：

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| log_id | 字符串 | 是 | 日志唯一标识 |
| chamber_id | 字符串 | 是 | 冷藏柜编号 |
| deceased_id | 字符串 | 否 | 逝者ID |
| operation_type | 字符串 | 是 | 操作类型（入柜/出柜/温度检查等） |
| temperature | 数值 | 否 | 温度（摄氏度） |
| timestamp | 日期时间 | 是 | 操作时间 (YYYY-MM-DD HH:MM:SS) |
| operator | 字符串 | 否 | 操作员 |
| remarks | 字符串 | 否 | 备注 |

### handover.csv（交接记录）

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| handover_id | 字符串 | 是 | 交接记录唯一标识 |
| deceased_id | 字符串 | 是 | 逝者ID |
| handover_type | 字符串 | 否 | 交接类型（入柜/出柜/转柜） |
| from_chamber | 字符串 | 否 | 源柜号（转柜时） |
| to_chamber | 字符串 | 否 | 目标柜号 |
| from_person | 字符串 | 否 | 交出人 |
| to_person | 字符串 | 否 | 接收人 |
| handover_time | 日期时间 | 否 | 交接时间 |
| is_signed | 布尔 | 否 | 是否已签收（True/False） |
| signed_by | 字符串 | 否 | 签收人 |
| signed_at | 日期时间 | 否 | 签收时间 |
| remarks | 字符串 | 否 | 备注 |

### rules.yaml（规则配置）

YAML格式，包含规则列表：

```yaml
rules:
  - rule_id: "TEMP_RANGE_001"
    rule_name: "冷藏柜温度范围"
    rule_type: "temperature"
    min_value: -25.0
    max_value: -15.0
    description: "冷藏柜温度应保持在-25°C到-15°C之间"
    is_active: true
```

## 本地状态存储

程序会在运行目录自动创建 `local_state.json` 文件，用于存储：

- 已处理问题的状态
- 处理人信息
- 处理时间
- 处理备注

该文件在程序启动时自动加载，关闭时自动保存。

## 常见问题

### Q1: 启动时提示"未加载数据"

A: 需要导入数据文件。可以：
1. 将数据文件放入 `sample_data` 目录
2. 或通过菜单 `文件` -> `导入数据文件...` 手动选择

### Q2: 日期格式有什么要求？

A: 支持以下日期格式：
- YYYY-MM-DD HH:MM:SS
- YYYY-MM-DD HH:MM
- YYYY/MM/DD HH:MM:SS
- YYYY/MM/DD HH:MM
- YYYY-MM-DD
- YYYY/MM/DD

### Q3: 如何添加新的冷藏柜？

A: 冷藏柜列表是从日志数据中自动提取的。只要在 `cold_chamber_logs.jsonl` 中添加包含新柜号的日志记录，系统会自动识别。

### Q4: 修改规则后需要重新导入数据吗？

A: 是的。规则在数据导入时生效。修改 `rules.yaml` 后需要重新导入数据才能应用新规则。

### Q5: 处理状态会丢失吗？

A: 不会。处理状态保存在 `local_state.json` 中，下次启动会自动加载。建议定期使用 `文件` -> `导出状态备份` 功能进行备份。

## 故障排查

### 导入数据失败

1. 检查文件格式是否正确
2. 检查CSV文件的编码（建议使用UTF-8）
3. 检查JSONL文件每行是否是有效的JSON
4. 检查YAML文件的缩进（YAML对缩进敏感）

### 温度超窗检测异常

1. 检查 `rules.yaml` 中的温度范围配置
2. 检查日志中的温度值格式是否正确（应为数值）
3. 确认温度单位是摄氏度

### 状态保存失败

1. 检查运行目录是否有写入权限
2. 检查磁盘空间是否充足
3. 尝试以管理员权限运行
