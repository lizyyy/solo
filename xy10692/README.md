# 直播培训资格处理系统

前后端一体的直播培训回放资格处理工具，支持观看时长校验、测验成绩处理、回放补学审批和证书资格管理。

## 功能特性

- 📊 **统计卡片**: 观看记录总数、观看合格数、测验通过率、回放审批通过数、资格证书总数
- 🔍 **搜索过滤**: 按直播场次、用户名、资格状态筛选
- ✅ **复核面板**: 观看时长校验、测验成绩处理、回放补学保存、一键全部处理
- 📝 **变更历史**: 保留所有修改的前后值，支持按责任人和处理时间筛选
- 📤 **报告导出**: 导出CSV格式的资格处理报告
- 🔒 **结果稳定**: 用户刷新页面或重复点击时，结果保持一致

## 技术栈

- **后端**: Node.js + Express + SQLite
- **前端**: React + Axios
- **数据导出**: csv-writer

## 本地启动

### 1. 安装后端依赖

```bash
npm install
```

### 2. 初始化数据库并导入样例数据

```bash
npm run init-db
```

### 3. 安装前端依赖

```bash
cd client
npm install
cd ..
```

### 4. 启动开发环境（同时启动前后端）

```bash
npm run dev
```

或者分别启动：

```bash
# 启动后端 (端口 3001)
npm run server

# 启动前端 (端口 3000，新开终端)
cd client
npm start
```

### 5. 访问应用

打开浏览器访问: http://localhost:3000

## 主要API接口

### 观看记录相关

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/watch-records/:session_id/:user_id` | 获取用户观看记录 |
| POST | `/api/validate-watch-time` | 校验观看时长资格 |

### 测验成绩相关

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/quiz-scores/:session_id/:user_id` | 获取测验成绩 |
| POST | `/api/process-quiz-score` | 处理测验成绩资格 |

### 回放补学相关

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/replay-studies/:session_id/:user_id` | 获取回放记录 |
| POST | `/api/save-replay-study` | 保存回放补学并审批 |

### 资格证书相关

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/qualifications` | 获取资格列表（支持筛选） |
| POST | `/api/process-qualification` | 一键处理全部资格项 |

### 其他接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/sessions` | 获取所有直播场次 |
| GET | `/api/statistics` | 获取统计数据 |
| GET | `/api/change-history` | 获取变更历史 |
| GET | `/api/export-report` | 导出资格报告CSV |

## 资格判定标准

| 项目 | 合格标准 |
|------|----------|
| 观看时长 | 观看百分比 ≥ 80% |
| 互动积分 | 总积分 ≥ 10分 |
| 测验成绩 | 得分 ≥ 60分 或 标记为通过 |
| 回放补学 | 回放观看时长 ≥ 直播时长的80% |
| **整体合格** | (观看合格 **或** 回放合格) **且** 测验合格 |

## 会失败的操作

以下操作会导致失败，请避免：

### 1. 未输入处理人姓名

```
操作: 点击任何处理按钮（校验观看、处理测验等）但未填写"处理人姓名"
结果: 弹出错误提示 "请输入处理人姓名"
```

### 2. 回放补学时长不足

```
操作: 输入回放观看时长 < 直播时长的80%
结果: 回放审批标记为不通过，不会更新资格状态
```

### 3. 请求不存在的记录

```
操作: 通过API请求不存在的session_id或user_id
结果: 返回 404 错误 "观看记录不存在" 或 "直播场次不存在"
```

### 4. 重复提交

虽然系统设计为幂等的（重复点击结果稳定），但短时间内频繁重复点击可能导致：
```
结果: 变更历史中会产生多条相同的记录
```

## 数据库表结构

1. **live_sessions**: 直播场次
2. **watch_records**: 观看记录
3. **interaction_records**: 互动记录
4. **quiz_scores**: 测验成绩
5. **replay_studies**: 回放补学
6. **certificate_qualifications**: 证书资格
7. **change_history**: 变更历史（审计日志）

## 注意事项

1. 处理资格前必须填写"处理人姓名"，否则所有操作都会失败
2. 变更历史最多显示20条最新记录，导出报告会包含所有符合筛选条件的数据
3. 所有日期时间均为服务器本地时间
4. 样例数据为随机生成，因此观看时长、测验成绩等都是随机值
