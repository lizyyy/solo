# 合唱分声部练习跟踪系统

## 一、系统边界规则（** 所有规则已写入代码，不依赖口头约定 **）

### 1. 曲目别名表导入规则

| 场景 | 判定规则 | 处理方式 | 回滚方式 |
|------|----------|----------|----------|
| 首次导入新曲目 | song_code 不存在 | 新增记录，version=1 | 在 song_alias_history 中保留 v1 快照，可手动恢复 |
| 重复导入同批曲目 | song_code 已存在且内容无变化 | 跳过，不增加数量 | 无需回滚 |
| 重复导入但修改了字段 | song_code 已存在但字段有差异 | 更新记录，version+1 | 在 song_alias_history 中保留旧版本，查看「历史」对比改前改后 |
| 只改了一条备注 | remark 字段变化 | 标记为 remark 变更，version+1 | 历史记录中明确显示 "改前: xxx → 改后: xxx" |

**关键点**：重复导入不会让记录翻倍。所有变更均生成版本历史，可追溯每次修改的具体字段。

---

### 2. 临时替补判定规则（** 核心边界 **）

| 替补来源 | 是否自动标记为"正常" | 复核责任人 |
|----------|----------------------|------------|
| 群消息（只在群里说了一句） | ❌ 否，标记为「待复核」 | 票务同事 |
| 书面通知 | ✅ 是，自动通过 | - |
| 其他 | ✅ 是，自动通过 | - |

**判定逻辑（已写入 server.js 第235-238行）**：
```
if (has_substitute && substitute_source === '群消息') {
  is_verified = 0; // 待票务同事复核
}
```

**复核流程**：
1. 许老师录入临时替补，选择来源为「群消息」
2. 系统自动标记为「待复核」，不进入分账
3. 票务同事在「概览」页面的待复核列表中点击「复核通过」
4. 复核通过后，状态变为「已复核」，可参与分账

**回滚/修改**：未复核的记录可直接编辑；已复核的记录保留变更历史。

### 3. 课时签到照片关联规则

| 场景 | 处理方式 |
|------|----------|
| 照片上传时 | 记录 class_date、photo_path、uploader |
| 创建练习记录时 | 可下拉选择已上传的签到照片关联 |
| 点击练习记录中的「查看照片」 | 溯源跳转到照片详情，显示关联的练习记录 |
| 查看照片详情时 | 显示所有关联该照片的练习记录，可点击溯源 |

**双向溯源**：
- 练习记录 → 签到照片（点击"查看照片"）
- 签到照片 → 练习记录（照片详情中显示关联列表）

### 4. 3D/图表展示服务复核规则

| 展示模式 | 溯源能力 |
|----------|----------|
| 柱状图 | 点击数据点 → 显示数值 |
| 饼图 | 图例清晰标注，切换不丢失数据 |

**规则**：漂亮画面只是锦上添花，**待复核的临时替补记录永远在概览页最下方以表格形式呈现**，点击任意记录可直接：
- 溯源到曲目别名表
- 溯源到课时签到照片
- 查看变更历史
- 执行复核操作

### 5. 分账明细生成规则

| 场景 | 处理方式 |
|------|----------|
| 记录已复核 | 生成分账明细 |
| 记录待复核（群消息替补） | 不生成分账，等待票务同事复核 |
| 重复生成分账 | 跳过已生成的记录，不重复创建 |
| 分账生成后修改练习记录 | 分账保留历史值，如需更新需重新生成 |

**标准三步流程**：
```
第1步：导入曲目别名表
  ↓
第2步：许老师上传课时签到照片 + 录入练习记录（含临时替补标记）
  ↓（群消息替补自动进入待复核状态）
第3步：票务同事复核通过 → 生成分账明细
```

## 三、标准操作流程示例

### 场景：走完一个完整的三步流程

1. **导入曲目别名表**
   - 进入「曲目别名表」→ 点击「导入曲目」
   - 粘贴示例数据：
     ```
     S001,黄河大合唱,黄河,高声部,经典曲目
     S002,茉莉花,,中声部,必学曲目
     S003,歌唱祖国,,低声部,
     ```
   - 确认导入，查看版本号

2. **许老师录入练习记录（含临时替补）**
   - 进入「课时签到」→ 上传当天的签到照片
   - 进入「练习记录」→ 新增记录
   - 选择日期、学生、曲目、照片
   - ✅ 勾选"存在临时替补"，来源选择「群消息（需复核）」，填写替补人员
   - 保存后，该记录自动标记为「待复核」

3. **票务同事复核 + 生成分账**
   - 进入「概览」，在下方待复核表格中找到该记录
   - 点击「溯源」查看详情（可跳转到曲目、照片）
   - 确认无误后点击「复核通过」
   - 进入「分账明细」→ 点击「生成分账」，选择对应日期
   - 分账明细自动生成，仅包含已复核记录

## 四、数据模型说明

| 表名 | 用途 | 核心字段 |
|------|------|----------|
| song_aliases | 曲目别名表 | song_code(唯一), version, is_deleted |
| song_alias_history | 曲目版本历史 | 每个版本的完整快照 + change_type |
| attendance_photos | 课时签到照片 | class_date, photo_path, uploader |
| practice_records | 练习记录 | has_substitute, substitute_source, is_verified |
| practice_history | 练习变更历史 | field_name, old_value, new_value, changed_by |
| settlement_details | 分账明细 | practice_id, total_amount, status |
| operation_logs | 操作日志 | operation_type, old_data, new_data, can_rollback |

---

## 五、回滚机制说明

系统不做自动回滚，但所有关键操作均保留完整历史：

1. **曲目别名变更**：每个版本的完整内容都在 song_alias_history 中，点击「历史」可对比任意版本
2. **练习记录修改**：每个字段的变更都在 practice_history 中，明确显示"改前 → 改后"
3. **操作日志**：所有增删改操作都在 operation_logs 中留痕，包含操作人、时间、新旧数据

如需回滚，找到对应历史版本的内容手动恢复即可。
