# 语义去重阈值试算系统

帮助评测运营小孟解释阈值试算结果，解决"少数类样本被总指标盖住"后算法工程师追问前后不一致的问题。

## ✨ 核心特性

- 🎯 **三步标准流程**：导入召回候选表 → 补看/调整参数YAML → 阈值回放更新
- ⚠️ **少数类自动检测**：自动识别被总指标盖住的少数类样本，暂不归为正常，留给算法工程师复核
- 📝 **人性化回放报告**：每条样本说明「为什么被留下、还缺什么材料、下一步该找谁」
- 📜 **完整审计追踪**：谁改了什么、为什么改、改完影响哪些结果，全部可追溯
- 🔌 **三种接入方式**：命令行 CLI、HTTP API、可扩展小看板
- 🎓 **内置演示数据**：包含召回候选表、参数YAML、一次人工修正、一次重跑，方便给新人讲流程

## 🚀 快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 一键运行完整演示

```bash
python cli.py demo
```

这会走完完整三步流程，并在 `./demo_output/` 目录下生成所有中间文件和报告。

### 3. 生成演示数据文件

```bash
python cli.py init-demo --output ./demo_data
```

会生成三个文件：
- `recall_candidates.csv` - 召回候选表（6条样本，含2条少数类）
- `params_initial.yaml` - 初始参数配置
- `params_updated.yaml` - 调整后的参数配置

## 📖 三步标准流程

### 第一步：导入召回候选表，运行阈值试算

```bash
python cli.py run ./demo_data/recall_candidates.csv ./demo_data/params_initial.yaml
```

系统会自动：
- 计算每条样本的语义得分是否通过阈值
- 检测少数类样本占比是否低于警戒值
- 标记「少数类被总指标盖住」的样本，暂不归为正常
- 生成回放报告，说明每条样本的处理原因

### 第二步：评测运营小孟人工复核与修正

```bash
# 查看演示中是如何做人工修正的
python cli.py demo
```

修正时需要记录：
- 操作人（谁改的）
- 修改原因（为什么改）
- 修改了哪些字段
- 影响了哪些样本

### 第三步：调整参数YAML后重跑

```bash
python cli.py rerun ./demo_data/recall_candidates.csv \
    ./demo_data/params_initial.yaml \
    ./demo_data/params_updated.yaml
```

调整参数后阈值回放会自动更新，同时保留完整的审计轨迹。

## 🎛️ 可调参数说明

| 参数名 | 说明 | 默认值 |
|--------|------|--------|
| `dedup_threshold` | 去重阈值，高于此值的样本会被判定为重复 | 0.85 |
| `minority_weight` | 少数类加权系数，提升少数类的得分权重 | 1.2 |
| `overall_metric_weight` | 总指标权重 | 1.0 |
| `minority_boost_enabled` | 是否启用少数类增强 | true |
| `min_minority_ratio` | 最小少数类占比，低于此值会触发「被总指标盖住」标记 | 0.05 |

## 🔌 API 接口

启动API服务：

```bash
python api.py
```

然后访问 `http://localhost:8000/docs` 查看交互式文档。

### 主要接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/trial/run` | 上传CSV，运行阈值试算 |
| POST | `/trial/correct/{run_id}/{sample_id}` | 人工修正单条样本 |
| POST | `/trial/rerun/{run_id}` | 使用新参数重跑 |
| GET | `/trial/{run_id}/report` | 获取回放报告 |
| GET | `/trial/{run_id}/audit` | 获取审计日志 |
| POST | `/demo` | 运行完整演示 |

## 📊 回放报告解读

每条样本的回放报告会包含：

### 💡 为什么被留下/被过滤
用自然语言解释，而不是冷冰冰的系统日志，例如：
> 少数类样本（量子计算），当前少数类占比33.3%低于阈值40.0%，应用加权系数1.2提升得分

### 📋 还缺什么材料
如果是少数类样本，会列出需要补充的材料，例如：
- 补充该类别标注样本量数据
- 确认少数类加权策略合理性

### 👤 下一步找谁
明确指向责任人：
- 👨‍💻 算法工程师 - 需要复核少数类加权策略
- 👩‍💼 评测运营小孟 - 需要补充业务材料
- ✅ 无需处理 - 流程已走完

## 📜 审计日志

每次操作都会记录审计日志，包括：
- 操作时间
- 操作人
- 操作类型
- 修改原因
- 修改的字段（旧值→新值）
- 影响的样本列表

这样当算法工程师追问「为什么前后不一致」时，小孟可以直接拿出审计日志说明每一步改动的原因。

## 🎯 设计要点

1. **少数类别急着归正常**：只要触发「被总指标盖住」标记，就自动标记为待算法工程师复核，不会自动归为正常
2. **参数驱动回放**：修改YAML参数后重跑，回放报告自动更新，无需手工修改
3. **小而真的演示数据**：6条样本（4条普通 + 2条少数类），完整演示从发现问题到解决问题的全流程
