# 社区食堂营养配餐器 - 使用说明

## 项目概述

这是一个专为社区食堂老年人配餐设计的营养管理系统，核心功能包括：
- 🧂 **盐摄入量控制**：每餐不超过1.7克（每日5克）
- 🥚 **蛋白质需求计算**：根据体重自动计算目标摄入量（1.0-1.2g/kg体重/天）
- 💰 **成本控制**：按个人预算进行配餐
- ⚠️ **忌口规则管理**：支持过敏原、慢性病、饮食偏好等多种规则

## 快速开始

### 1. 启动系统

**方式一：直接打开（推荐）**
- 用浏览器直接打开 `index.html` 文件即可使用

**方式二：本地服务器**
```bash
# 在项目目录下执行
python3 -m http.server 8000
# 然后访问 http://localhost:8000
```

### 2. 加载样例数据

进入仪表盘，您会看到三个按钮：

- **📥 加载成功样例**：包含3位老人、10道菜品、3个基础忌口规则
  - 张大爷：健康老人，无特殊限制
  - 李奶奶：高血压、海鲜过敏
  - 王爷爷：糖尿病、低糖饮食
  
  配餐结果应该都是 **"方案通过验证"** ✅

- **📥 加载拦截样例**：包含3位有严格限制的老人、8道可能触发问题的菜品
  - 赵大爷：海鲜过敏
  - 孙奶奶：糖尿病+低盐+低预算
  - 钱爷爷：严重高血压（极低盐）
  
  配餐结果会出现 **"方案被拦截"** 🚫 或 **"方案待复核"** ⚠️

- **🗑️ 清空数据**：清空所有数据，从空白开始

## 功能模块详解

### 📊 仪表盘

- **统计卡片**：实时显示菜品、老人、规则、配餐计划数量
- **关键假设说明**：解释系统的营养标准和计算依据
- **快速开始指南**：5步操作流程

### 🍳 菜品管理

**添加菜品**：
1. 点击"➕ 新增菜品"
2. 填写以下信息：
   - **菜品名称**：例如"清蒸鲈鱼"
   - **分类**：主菜/配菜/汤品/主食
   - **盐含量(克)**：必须填写
   - **蛋白质(克)**：必须填写
   - **成本(元)**：必须填写
   - **食材标签**：逗号分隔，用于忌口匹配
   - **说明**：可选

**重要提示**：
- 食材标签是忌口匹配的关键！例如"白灼虾"应包含"虾"、"海鲜"等标签
- 盐含量是指这道菜的盐含量（不是钠含量）

### 👴 老人档案

**添加老人**：
1. 点击"➕ 新增老人"
2. 填写以下信息：
   - **姓名/性别/年龄**：基本信息
   - **体重(kg)**：用于计算蛋白质需求
   - **每餐预算(元)**：用于成本控制
   - **饮食偏好**：普通/软食/流食/低脂/低糖
   - **关联忌口规则**：多选（按住Ctrl或Command键）
   - **备注**：特殊情况说明

**蛋白质自动计算**：
- 目标蛋白质 = 体重 × 1.0~1.2g/kg ÷ 3餐
- 例如65kg老人：每餐21.7~26g蛋白质

### ⚠️ 忌口规则

**添加规则**：
1. 点击"➕ 新增规则"
2. 填写以下信息：
   - **规则名称**：例如"海鲜过敏"
   - **规则类型**：
     - 过敏原：违反会直接拦截
     - 慢性病忌口：违反会直接拦截
     - 饮食偏好：违反只显示警告
     - 宗教饮食/药物冲突：违反会直接拦截
   - **规避食材**：逗号分隔，精确匹配食材标签
   - **包含食材**：可选，必须包含的食材
   - **描述**：规则详细说明

**特殊盐限制规则**：
- 规则名称包含"极低盐"：每餐盐限0.5克
- 规则包含"低盐"或"3克"：每餐盐限1.0克
- 默认：每餐盐限1.7克

### 📋 配餐计划

**生成配餐**：
1. 选择一位老人
2. 选择日期和时段（早餐/午餐/晚餐）
3. 点击"🔄 生成配餐方案"

**结果解读**：

✅ **方案通过验证（绿色）**
- 所有约束都满足
- 可以直接执行

⚠️ **方案待复核（橙色）**
- 存在可接受的问题，需要人工确认
- 常见原因：
  - 成本略超预算
  - 蛋白质略低于目标
  - 饮食偏好不完全匹配
- 可以选择保存并执行，也可以调整后重新生成

🚫 **方案被拦截（红色）**
- 存在严重问题，不可执行
- 常见原因：
  - 违反过敏原规则
  - 盐量严重超标
  - 没有可用菜品能满足所有规则
- 必须调整菜品或规则后重新生成

**套餐对比**：
- 系统会生成多个可能的方案
- 在下方的"替代方案对比"表格中可以查看
- 标记"✓"的是该指标最优的方案

**操作按钮**：
- 💾 **保存方案**：保存到数据库
- 📤 **导出当前方案**：导出为CSV文件
- 🔄 **重新生成**：清空结果重新生成

### 📤 导出管理

**三种导出方式**：

1. **按日期导出**
   - 选择开始和结束日期
   - 导出该时间范围内的所有配餐计划

2. **按老人导出**
   - 选择一位老人
   - 导出该老人的所有配餐计划

3. **导出全部**
   - 导出所有保存的配餐计划

**导出格式**：CSV文件，包含以下字段：
- 老人姓名、日期、时段
- 状态（通过/待复核/拦截）
- 菜品列表
- 总盐量、总蛋白质、总成本
- 问题列表、备注

## 系统约束和假设

### 营养标准（可在 data.js 中调整）

```javascript
SALT_LIMIT_PER_MEAL = 1.7    // 每餐盐上限（克）
SALT_LIMIT_DAILY = 5.0       // 每日盐上限（克）
PROTEIN_PER_KG_LOW = 1.0     // 每日每kg体重蛋白下限（克）
PROTEIN_PER_KG_HIGH = 1.2    // 每日每kg体重蛋白上限（克）
MEALS_PER_DAY = 3            // 每日用餐次数
```

### 忌口规则优先级

1. **过敏原** → 最高优先级，违反直接拦截
2. **慢性病忌口** → 高优先级，违反直接拦截
3. **药物冲突** → 高优先级，违反直接拦截
4. **宗教饮食** → 高优先级，违反直接拦截
5. **饮食偏好** → 低优先级，违反仅警告

### 配餐生成规则

- 自动组合：主食 + 主菜 + [配菜] + [汤品]
- 优先选择：低钠盐、高蛋白、低成本的组合
- 多方案生成：提供2-3个方案供对比选择

## 数据存储

- 所有数据保存在浏览器的 localStorage 中
- 清除浏览器数据会导致数据丢失
- 建议定期导出重要数据备份

## 常见问题

**Q: 为什么总是生成"待复核"方案？**
A: 检查：
1. 菜品的盐含量是否偏高
2. 老人的预算是否设置过低
3. 蛋白质目标是否能达到

**Q: 如何让某个菜品不会被选中？**
A: 有两种方式：
1. 在菜品管理中删除该菜品
2. 添加一条忌口规则，规避该菜品的食材标签

**Q: 如何调整营养标准？**
A: 编辑 `data.js` 文件中的 `CONSTANTS` 对象

**Q: 数据会丢失吗？**
A: 数据保存在浏览器本地存储中。清除浏览器缓存或更换浏览器会丢失数据。建议定期导出CSV备份。
