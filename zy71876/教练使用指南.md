# 救援物资分配工具 - 教练使用指南

## 快速开始

### 1. 启动工具
```bash
python cli.py
```

### 2. 准备数据文件

**约束说明样例** 放在 `samples/constraints_sample.csv`

**物资清单** 放在 `samples/materials_sample.csv`

**需求点数据** 放在 `samples/demand_points_sample.csv`

---

## 核心操作流程

### 第一步：导入约束说明

1. 选择菜单 `1. 导入约束说明`
2. 输入路径：`samples/constraints_sample.csv`

**提示**：约束规则可以随时补充和修改，导入后可通过 `11. 查看约束覆盖情况` 检查哪些规则被应用。

---

### 第二步：导入基础数据

1. 选择 `2. 导入物资清单` → 输入 `samples/materials_sample.csv`
2. 选择 `3. 导入需求点` → 输入 `samples/demand_points_sample.csv`

**口径说明**：
- 需求点CSV中的 `需求_物资ID` 列名格式要与物资ID对应
- 优先级数字越大，优先级越高

---

### 第三步：执行自动分配

选择 `4. 执行自动分配`

**每条分配记录自动包含**：
- 判断理由：为什么这么分配
- 下一步：接下来要做什么
- 状态标记：已确认/待补/人工修改

---

### 第四步：查看和调整

1. **查看记录**：选择 `5. 查看分配记录`，输入ID可看详情
2. **人工调整**：选择 `6. 人工调整分配`，保留修改痕迹
3. **确认记录**：选择 `7. 确认分配记录`，状态变为"已确认"

---

## 高级功能

### 重复导入处理
- 导入分配记录时自动去重（同一物资+同一需求点只保留一条）
- 每条导入自动生成批次ID

### 撤回修正
选择 `10. 撤回导入批次`：
- 查看所有导入批次
- 按批次ID撤回整批数据
- 撤回后数据完全移除，不留下残留

### 筛选后导出
选择 `9. 导出分配记录`，可按状态筛选：
1. 全部
2. 已确认
3. 待补充
4. 人工修改

**口径一致保证**：导入和导出使用相同的字段定义。

---

## 收尾工作

### 如何放约束说明样例
将你的约束规则CSV文件放在任意位置，导入时输入完整路径即可。

**推荐格式**（放在 `samples/` 目录下）：
```
约束ID,名称,类型,说明,规则,优先级,启用
C001,规则名,类型,说明,规则表达式,1,是
```

### 去哪看约束被覆盖
选择 `11. 查看约束覆盖情况`
- ✓ 已覆盖：分配时实际用到的规则
- ✗ 未覆盖：可能需要补充数据或调整规则

### 导出模型说明前怎么复核

**导出前检查清单**：

- [ ] 所有约束规则是否都已覆盖？（菜单11）
- [ ] 待补充记录是否都有合理理由？
- [ ] 人工修改记录是否都填写了修改说明？
- [ ] 高优先级需求点是否已满足？
- [ ] 分配总量是否不超过库存总量？
- [ ] 是否已保存最新工作区？（菜单13）

**生成模型说明**：
选择 `12. 生成模型说明文档`，输出给参赛队的说明文档包含：
1. 处理口径说明
2. 约束规则应用情况
3. 分配记录分类统计（已确认/待补/人工修改分开）
4. 详细的每条记录和理由
5. 复核检查清单

## 参赛队收到的模型说明结构

```
救援物资分配模型说明

【一、处理口径说明】
→ 6条统一处理原则

【二、约束规则应用情况】
→ 每条规则标记是否被覆盖

【三、分配记录分类统计】
→ 已确认/待补/人工修改 分别计数

【四、已确认分配记录】
→ 每条记录：ID | 物资 | 需求点 | 数量
→ 判断理由：XXX
→ 下一步：XXX

【五、待补充分配记录】
→ 同上格式

【六、人工修改记录】
→ 包含原数量和修改痕迹

【七、复核检查清单】
→ 6项待勾选项
```

## 工作区保存/加载

- **保存**：菜单 `13. 保存工作区`（保存为JSON）
- **加载**：菜单 `14. 加载工作区`（从JSON恢复）

建议每次重大操作后保存工作区。

---

## 字段定义参考

### 分配记录核心字段
| 字段 | 说明 |
|------|------|
| 判断理由 | 自动分配的计算依据 |
| 下一步 | 后续操作建议 |
| 状态 | 已确认/待补/人工修改 |
| 应用约束 | 触发了哪些约束规则 |
| 原分配数量 | 人工修改前的数值 |

### 口径一致原则
1. 导入和导出使用相同字段名
2. 状态枚举值全程一致
3. 批次ID贯穿导入/撤回流程
4. 人工修改永久保留痕迹
