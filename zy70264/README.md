# 养老餐配送温度追踪台

## 项目概述

一个针对养老餐配送场景的温度追踪、签收管理、退餐审核和补偿管理系统。核心关注：
- **温度追踪**：配送过程中的温度实时监控，识别温度异常
- **签收退餐**：老人餐食签收和退餐登记，区分风险等级
- **补偿规则**：基于温度异常和退餐原因的自动补偿计算
- **食品安全**：高风险事件自动触发安全事件记录

## 技术栈

- **后端**：Node.js + Express + SQLite (better-sqlite3)
- **前端**：Vue 3 + Element Plus + ECharts
- **数据格式**：JSON + CSV（导出）

## 快速开始

```bash

cd server
npm install

# 进入前端目录
cd ../client

```

### 2. 启动服务

```bash
# 终端1 - 启动后端（端口3000）
cd server
npm start

# 终端2 - 启动前端开发服务器（端口5173）
cd client
npm run dev
```

### 3. 访问应用

打开浏览器访问：http://localhost:5173

## 使用说明（完整演示流程）

### 第一步：初始化补偿规则

首次使用前，需要初始化补偿规则：
1. 进入 **数据概览** 页面
2. 点击蓝色按钮 **【初始化补偿规则】**
3. 提示成功后，可前往 **补偿规则配置** 查看规则详情

### 第二步：创建示例数据

提供两组完整的示例数据，覆盖正常和异常场景：

#### 场景A：顺利样例（全部正常，无拦截）
1. 在 **数据概览** 页面，点击绿色按钮 **【创建顺利样例数据】**
2. 系统自动创建：
   - 1个配送批次（午餐，10份，5位老人）
   - 1个温度片段（全部正常，65-75°C）
   - 5条签收回执（全部正常签收）
   - 0条退餐记录
   - 0条待审核补偿

3. 体验流程：
   - 进入 **配送批次管理**，查看新建的批次
   - 点击 **详情**，查看：
     - **温度片段**：展开查看温度曲线图，所有点在55-85°C正常范围内，显示"正常"
     - **签收回执**：5位老人全部签收2份
     - **退餐记录**：空（无退餐）
     - **补偿记录**：空（温度正常，无补偿）
     - **安全事件**：空（无异常）

#### 场景B：异常拦截样例（触发待复核）
1. 在 **数据概览** 页面，点击橙色按钮 **【创建异常拦截样例数据】**
2. 系统自动创建：
   - 1个配送批次（晚餐，8份，4位老人）
   - 2个温度片段（1个正常 + 1个异常）
   - 4条签收回执
   - 2条退餐记录（高风险，进入待审核）
   - 多条待审批补偿（温度异常 + 退餐触发）

3. 关键差异点演示：

   **🔴 温度异常识别**
   - 进入批次详情 → **温度片段**
   - 第二个片段"配送途中-异常"会显示红色警告边框
   - 展开查看：温度曲线大部分低于55°C（正常下限），系统标记为"异常"
   - 异常原因显示：`温度异常: 异常比例60.0%, 连续异常15个点`

   **🔴 高风险退餐拦截**
   - **退餐记录** 标签页：
     - 钱爷爷：退餐原因"温度过低"（T001，高风险），状态"待审核"
     - 周爷爷：退餐原因"变质异味"（F002，高风险），状态"待审核"
   - 低风险退餐（如"老人不在家"）会自动通过，无需审核

   **🔴 补偿待审批**
   - 批次完成后，系统自动计算补偿：
     - 温度异常触发：¥200固定补偿 + 餐费20%比例补偿
     - 退餐触发：温度问题¥50/份，食品安全¥100/份
   - 所有自动生成的补偿进入 **待审批** 状态

### 第三步：处理审核流程

#### 1. 退餐审核
1. 进入 **退餐审核** 页面
2. 看到2条待审核记录：
   - 钱爷爷：温度过低（高风险）
   - 周爷爷：变质异味（高风险）
3. 操作：
   - 点击 **通过**：确认退餐有效，计入退回份数
   - 点击 **拒绝**：驳回退餐申请
4. 通过后，退餐状态变为"已通过"，批次退回份数自动更新

#### 2. 补偿审核
1. 进入 **补偿审核** 页面
2. 上半部分是 **待审批补偿** 列表
3. 查看补偿详情：
   - 温度异常补偿：整批次级别的补偿
   - 退餐补偿：针对具体老人的补偿
4. 操作：
   - 点击 **通过**：补偿生效
   - 点击 **拒绝**：取消该补偿
5. 审批后记录进入下方 **补偿审批历史**

#### 3. 食品安全事件
1. 进入 **食品安全事件** 页面
2. 高风险退餐（F001/F002）和严重温度异常会自动创建安全事件
3. 事件信息包含：
   - 事件类型（温度异常/食品安全）
   - 严重程度
   - 受影响人数
   - 详细描述
4. 处理完成后点击 **关闭**

### 第四步：数据导出

进入 **数据导出** 页面，可导出以下CSV文件：
- 配送批次数据
- 温度监控数据
- 补偿记录数据
- 安全事件数据

支持按日期范围筛选，文件为UTF-8 BOM编码，Excel可直接打开。

## 核心业务规则

### 温度标准
- **正常范围**：55°C ~ 85°C
- **异常判定**：
  - 异常点占比 > 30%
  - 或连续异常 > 10个点
- **高风险**：异常比例 > 60%

### 退餐风险分级
| 风险 | 原因码 | 原因 | 是否需审核 |
|------|--------|------|-----------|
| 高 | T001 | 温度过低 | 是 |
| 高 | T002 | 温度过高 | 是 |
| 高 | F001 | 发现异物 | 是 |
| 高 | F002 | 变质异味 | 是 |
| 中 | T003 | 保温箱温度异常 | 自动通过 |
| 中 | F003 | 外观损坏 | 自动通过 |
| 中 | O002 | 数量不符 | 自动通过 |
| 中 | O003 | 配送延迟 | 自动通过 |
| 低 | O001 | 老人不在家 | 自动通过 |

### 补偿规则
系统预置4条规则（可在"补偿规则配置"中修改）：

1. **温度异常补偿-固定**：触发时补偿¥200
2. **温度异常补偿-比例**：触发时补偿总餐费的20%
3. **温度退餐补偿**：每份补偿¥50
4. **食品安全退餐补偿**：每份补偿¥100

## API接口概览

| 模块 | 接口 | 说明 |
|------|------|------|
| 批次 | GET /api/batches | 批次列表 |
| 批次 | POST /api/batches | 新建批次 |
| 批次 | POST /api/batches/:id/complete | 完成批次（触发补偿计算） |
| 温度 | GET /api/temperature/batch/:id | 温度片段列表 |
| 温度 | POST /api/temperature | 添加温度片段 |
| 签收 | POST /api/receipts | 添加签收 |
| 退餐 | GET /api/returns/pending | 待审核退餐 |
| 退餐 | POST /api/returns/:id/approve | 通过退餐 |
| 退餐 | POST /api/returns/:id/reject | 拒绝退餐 |
| 补偿 | GET /api/compensations/pending | 待审批补偿 |
| 补偿 | POST /api/compensations/:id/approve | 通过补偿 |
| 规则 | GET /api/compensations/rules | 补偿规则列表 |
| 报表 | GET /api/reports/dashboard | 仪表盘数据 |
| 导出 | GET /api/reports/export/* | CSV导出 |
| 示例 | POST /api/sample-data/normal | 创建顺利样例 |
| 示例 | POST /api/sample-data/abnormal | 创建异常样例 |
