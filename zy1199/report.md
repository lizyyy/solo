| 预估耗时 | 1394.2 ms |
| **预估吞吐量** | **71.73 MB/s** |

### 瓶颈分析

⚠️ **磁盘 I/O 瓶颈**

> 磁盘 I/O 饱和 (100.0 Mbps)，读取 100.0 MB 需要约 1000 ms

### 拷贝链路详情

**方式**: mmap + write

> 内存映射方式：减少一次内核到用户的拷贝

#### 传输步骤

**步骤 1**: mmap() 系统调用
- 数据流向: `文件` → `用户态虚拟地址空间`
- 操作类型: 地址映射（无拷贝）
- 优化: ✅ 内存映射，建立页表映射

**步骤 2**: 缺页异常触发读取
- 数据流向: `磁盘` → `内核页缓存`
- 操作类型: DMA 拷贝

**步骤 3**: 用户态直接访问
- 数据流向: `页缓存（通过 mmap 映射）` → `用户态处理`
- 操作类型: 直接访问（无拷贝）
- 优化: ✅ 通过虚拟地址直接访问物理页

**步骤 4**: write() 系统调用
- 数据流向: `用户态缓冲区` → `内核 Socket 缓冲区`
- 操作类型: 用户态 -> 内核态 拷贝

**步骤 5**: 协议栈发送
- 数据流向: `Socket 缓冲区` → `网卡`
- 操作类型: 内核态拷贝

#### 关键要点

- mmap 将文件映射到用户态虚拟地址空间
- 访问时通过缺页异常将数据读入页缓存
- 用户态可以直接访问页缓存（无需拷贝）
- write 时仍需要一次用户态到内核态的拷贝
- 比 read+write 少一次拷贝，但需要管理 mmap 生命周期

## 2. good_sendfile_dma_sg

### 性能指标

|------|-----|
| 用户态拷贝次数 | 0 次 |
| 内核态拷贝次数 | 1 次 |
| **总拷贝次数** | **1 次** |
| 上下文切换 | 2 次 |
| 系统调用 | 3 次 |
| 预估 CPU 占用 | 9.0% |
| 预估耗时 | 1000.7 ms |
| **预估吞吐量** | **99.93 MB/s** |

### 瓶颈分析

⚠️ **网络瓶颈**

> 网络带宽饱和 (100.0 Mbps)，传输 100.0 MB 需要约 1000 ms

### 拷贝链路详情

**方式**: sendfile (零拷贝)

> 真正的零拷贝：数据在内核态完成传输，无需用户态参与

#### 传输步骤

**步骤 1**: sendfile() 系统调用
- 数据流向: `文件描述符` → `Socket 描述符`
- 操作类型: 内核态完成所有操作
- 优化: ✅ 零拷贝系统调用

**步骤 2**: 内核读取文件
- 数据流向: `磁盘` → `内核页缓存`
- 操作类型: DMA 拷贝
- 优化: ✅ DMA Scatter-Gather

**步骤 3**: DMA SG 直接发送
- 数据流向: `页缓存` → `网卡`
- 操作类型: 无拷贝（仅描述符传递）
- 优化: ✅ DMA Scatter-Gather + TCP 分片卸载

#### 关键要点

- sendfile 在内核态完成从文件到 Socket 的传输
- 完全避免用户态和内核态之间的数据拷贝
- 配合 DMA SG 可以实现真正的零拷贝（仅描述符传递）
- 上下文切换次数最少（仅 2 次系统调用）
- 适合大文件静态资源传输（如 CDN、文件下载）
- 限制：无法在用户态处理数据（如修改、加密）

| 预估 CPU 占用 | 100.0% |
| 预估耗时 | 1044.4 ms |
| **预估吞吐量** | **95.75 MB/s** |

### 瓶颈分析

⚠️ **CPU 瓶颈**

> CPU 密集型操作: TLS 加密/解密, 数据压缩/解压, 用户态数据拷贝

### 拷贝链路详情

**方式**: read + write

> 传统方式：数据在内核态和用户态之间多次拷贝

#### 传输步骤

**步骤 1**: read() 系统调用
- 数据流向: `磁盘` → `内核页缓存`
- 操作类型: 内核态拷贝

**步骤 2**: 内核 -> 用户态
- 数据流向: `内核页缓存` → `用户态缓冲区`
- 操作类型: 内核态 -> 用户态 拷贝

**步骤 2.5**: 数据压缩
- 数据流向: `原始数据` → `压缩数据`
- 操作类型: 用户态 CPU 计算
- 优化: ✅ 压缩比 2.0:1

**步骤 3**: write() 系统调用
- 数据流向: `用户态缓冲区` → `内核 Socket 缓冲区`
- 操作类型: 用户态 -> 内核态 拷贝

**步骤 3.5**: TLS 加密
- 数据流向: `用户态明文` → `用户态密文`
- 操作类型: 用户态 CPU 计算

**步骤 4**: 协议栈发送
- 数据流向: `Socket 缓冲区` → `网卡`
- 操作类型: 内核态拷贝

#### 关键要点

- 需要 2 次用户态拷贝（read 时从内核到用户，write 时从用户到内核）
- 需要 2 次内核态拷贝（磁盘到页缓存，Socket 缓冲区到网卡）
- 上下文切换次数多（每次 read/write 都需要切换）
- 适合小文件或需要在用户态处理数据的场景

## 术语说明

| 术语 | 说明 |
|------|------|
| **用户态拷贝** | 数据在用户态和内核态之间的拷贝，涉及上下文切换，开销较大 |
| **内核态拷贝** | 数据仅在内核态内部的拷贝，开销相对较小 |
| **DMA 拷贝** | 直接内存访问，由 DMA 控制器完成，不占用 CPU |
| **零拷贝** | 避免用户态和内核态之间的数据拷贝，如 sendfile + DMA SG |
| **页缓存** | 内核缓存磁盘数据的机制，命中时可避免磁盘 I/O |
| **DMA Scatter-Gather** | DMA 分散收集，支持非连续内存块的直接传输 |
