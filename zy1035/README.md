# WebRTC 文件互传演练台

一个基于 WebRTC DataChannel 的本地点对点文件互传工具，无需登录网盘，无需复杂配置。

## 功能特性

- 🏠 **房间码机制**：创建房间码，另一台电脑输入房间码加入
- 📁 **多文件支持**：支持同时选择多个文件传输
- ⏸️ **暂停/继续/取消**：传输过程中可随时暂停、继续或取消
- 📊 **实时进度**：显示每个文件的进度、传输速度和剩余时间
- 🔒 **完整性校验**：传输完成后自动进行 SHA-256 哈希校验
- 📋 **日志记录**：实时显示传输日志
- 📜 **历史记录**：传输历史保存到 localStorage，刷新页面不丢失
- 🔄 **断线重连**：连接断开时可重新加入房间

## 使用方法

### 测试方式（单台电脑）

1. **打开两个浏览器窗口**，都访问 `http://localhost:8080`

2. **窗口 A（发送方）**：
   - 点击「创建房间」按钮
   - 复制生成的 6 位房间码（例如：ABC123）

3. **窗口 B（接收方）**：
   - 在输入框中输入房间码 `ABC123`
   - 点击「加入」按钮

4. **等待连接**：
   - 双方会看到「点对点连接已建立」的提示

5. **发送文件**：
   - 在窗口 A 中，点击「选择文件」或拖拽文件到区域
   - 选择多个文件后点击「全部发送」或单独发送某个文件
   - 观察实时进度、速度和剩余时间

6. **接收文件**：
   - 窗口 B 会自动接收文件
   - 接收完成后自动进行 SHA-256 校验
   - 校验通过后可以点击「下载」按钮保存文件

### 多台电脑使用

确保两台电脑在**同一局域网**内：

## 技术实现

### 核心流程

```
1. 信令连接 (WebSocket)
   ↓
2. 创建/加入房间
   ↓
3. WebRTC 握手 (Offer/Answer/ICE)
   ↓
4. DataChannel 建立
   ↓
5. 文件分片传输 (每片 16KB)
   ↓
6. SHA-256 完整性校验
   ↓
7. 下载/保存
```

### 分片格式

每个数据片包含：
- 4 字节：片索引 (Uint32)
- 4 字节：片大小 (Uint32)
- N 字节：实际数据

### 控制消息

| 消息类型 | 用途 |
|---------|------|
| FILE_OFFER | 发送方提出文件传输请求 |
| FILE_ACCEPT | 接收方接受请求 |
| FILE_PAUSE | 暂停传输 |
| FILE_RESUME | 恢复传输 |
| FILE_CANCEL | 取消传输 |
| CHUNK_ACK | 片确认 |
| FILE_COMPLETE | 发送完成，附带 SHA-256 |
| HASH_RESULT | 校验结果返回 |

## 常见问题

### Q: 为什么需要信令服务？
A: WebRTC 需要一个"中间人"来交换连接信息（SDP Offer/Answer 和 ICE Candidates）。两台电脑直接无法知道对方的网络地址，信令服务负责传递这些握手信息。

### Q: 文件内容是通过服务器传输的吗？
A: **不是**。信令服务只用于建立连接，实际文件数据通过 WebRTC DataChannel **点对点直接传输**，不经过服务器。

### Q: 为什么刷新页面后历史记录还在？
A: 历史记录保存在浏览器的 localStorage 中，是持久化存储的。可以在「历史」标签页手动清空。

### Q: 传输中断后能续传吗？
A: 目前支持**暂停后继续**，但断线重连后需要重新传输（WebRTC 连接状态无法跨页面持久化）。

## 开发说明

如需修改：

- 分片大小：修改 `public/js/utils.js` 中的 `CHUNK_SIZE`（默认 16KB）
- 端口：修改 `server.js` 中的 `PORT` 或设置环境变量
- 自动下载：修改 localStorage 中的 `autoDownload` 设置

---

**测试提示**：推荐先用小文件（几十 KB）测试基本流程，确认正常后再测试大文件。
