# 高校实验动物笼位分配API系统

## 一、系统概述

本系统专为高校实验动物房设计，核心目标是解决**临时转笼容易违规**的业务痛点。系统通过品系、性别、隔离三大规则引擎，确保每一次笼位分配都符合规范，并提供可复核的分配记录。

### 核心业务主线

```
品系规则 + 性别规则 + 隔离规则 → 笼位分配引擎 → 可复核的分配记录 → 报表/看板
```

```bash
  -H "Content-Type: application/json" \
  -d '{"code":"SD","name":"SD 大鼠","description":"广泛用于营养学研究"}'
```

### 第三步：进行笼位分配

#### 3.1 初始分配

系统会自动验证品系、性别、隔离兼容性。

```bash
# 获取动物ID和笼位ID
curl http://localhost:3000/api/animals
curl http://localhost:3000/api/cages

# 为 M001（C57BL/6J 雄性）分配笼位 A-01-01
curl -X POST http://localhost:3000/api/allocations \
  -H "Content-Type: application/json" \
  -d '{
    "request_id":"ALLOC-001",
    "animal_id":1,
    "cage_id":1,
    "action":"initial_allocation",
    "reason":"新动物入舍",
    "operator":"张实验员"
  }'

# 为 M002（C57BL/6J 雄性）分配同一笼位（品系性别都匹配）
curl -X POST http://localhost:3000/api/allocations \
  -H "Content-Type: application/json" \
  -d '{
    "request_id":"ALLOC-002",
    "animal_id":2,
    "cage_id":1,
    "action":"initial_allocation",
    "reason":"新动物入舍",
    "operator":"张实验员"
  }'

# 为 F001（C57BL/6J 雌性）分配雌性笼位
curl -X POST http://localhost:3000/api/allocations \
  -H "Content-Type: application/json" \
  -d '{
    "request_id":"ALLOC-003",
    "animal_id":3,
    "cage_id":2,
    "action":"initial_allocation",
    "reason":"新动物入舍",
    "operator":"李实验员"
  }'
```

**注意：** 系统会自动验证：
- ✅ 品系匹配：动物品系 = 笼位品系
- ✅ 性别匹配：动物性别 = 笼位性别 或 笼位性别为空
- ✅ 隔离兼容：动物隔离级别与笼位隔离级别兼容
- ✅ 容量检查：笼位有剩余空间

#### 3.2 推进分配流程

分配记录需要经过多个状态才能生效：

```
pending（待处理）→ validating（验证中）→ approved（已批准）→ allocated（已分配）→ completed（已完成）
```

```bash
# 获取分配记录ID
curl http://localhost:3000/api/allocations

# 推进状态：pending → validating
curl -X POST http://localhost:3000/api/allocations/1/advance \
  -H "Content-Type: application/json" \
  -d '{"to_status":"validating","reason":"开始品系隔离验证","operator":"王主管"}'

# 推进状态：validating → approved
curl -X POST http://localhost:3000/api/allocations/1/advance \
  -H "Content-Type: application/json" \
  -d '{"to_status":"approved","reason":"验证通过，品系性别隔离均符合要求","operator":"王主管"}'

# 推进状态：approved → allocated（此时笼位占用数+1）
curl -X POST http://localhost:3000/api/allocations/1/advance \
  -H "Content-Type: application/json" \
  -d '{"to_status":"allocated","reason":"完成分配，动物已入笼","operator":"张实验员"}'

# 推进状态：allocated → completed
curl -X POST http://localhost:3000/api/allocations/1/advance \
  -H "Content-Type: application/json" \
  -d '{"to_status":"completed","reason":"分配确认完成","operator":"张实验员"}'
```

## 三、核心规则说明

### 1. 品系规则

- 每个笼位可以绑定一个品系，或留空（通用笼位）
- 动物品系必须与笼位品系匹配（或笼位品系为空）
- 不同品系的动物不能混养在同一个笼位

### 2. 性别规则

- 每个笼位可以绑定性别：male（雄性）、female（雌性）、mixed（混合）
- 动物性别必须与笼位性别匹配（或笼位性别为空/mixed）
- 雄性和雌性动物不能混养（除非笼位明确标记为 mixed）

### 3. 隔离规则

- 每个隔离规则定义了可共存的其他隔离级别
- SPF级动物只能在SPF笼位
- 普通级动物可以在SPF或普通级笼位
- 检疫隔离动物只能在检疫笼位
- 系统会检查 `can_coexist_with` 字段判断兼容性

### 4. 状态流转规则

```
可取消状态：pending, validating, approved, allocated
可拒绝状态：仅 validating
可修正状态：pending, validating
```

## 四、边界情况处理

### 1. 重复提交

每个分配请求必须携带唯一的 `request_id`。如果使用相同的 `request_id` 重复提交：
- 系统返回已有记录，不会创建新记录
- 响应中会标记 `idempotent: true`

```bash
# 第一次提交
curl -X POST http://localhost:3000/api/allocations \
  -H "Content-Type: application/json" \
  -d '{"request_id":"TEST-001","animal_id":1,"action":"initial_allocation"}'

# 第二次提交（相同 request_id）
curl -X POST http://localhost:3000/api/allocations \
  -H "Content-Type: application/json" \
  -d '{"request_id":"TEST-001","animal_id":1,"action":"initial_allocation"}'
# 返回：{"success":true,"idempotent":true,"message":"重复请求，返回已有记录",...}
```

### 2. 状态冲突

- 不能从 `completed` 状态退回 `pending`
- 不能在 `allocated` 状态后进行修正
- 系统会返回 `INVALID_STATUS_TRANSITION` 错误码

### 3. 来源记录缺失

- 转笼操作需要动物当前有有效的分配记录
- 如果动物没有当前分配，返回 `NO_CURRENT_ALLOCATION`
- 如果来源分配记录不完整，返回 `INCOMPLETE_ALLOCATION`

## 六、验收要点

验收时应能明显看到以下主线：

### 1. 品系规则主线
- ✅ 创建品系 → 笼位绑定品系 → 动物绑定品系 → 分配时验证品系匹配

### 2. 隔离规则主线
- ✅ 创建隔离规则 → 定义共存关系 → 笼位绑定隔离级别 → 动物绑定隔离要求 → 分配时验证隔离兼容性

### 3. 转笼规则主线
- ✅ 初始分配 → 完成分配 → 尝试违规转笼 → 系统拒绝 → 合规转笼验证通过 → 执行转笼

### 4. 状态流转主线
- ✅ pending → validating → approved → allocated → completed
- ✅ 每个状态变更都有历史记录可查

### 5. 报表主线
- ✅ 看板展示整体情况
- ✅ 合规性报表识别违规分配
- ✅ 所有操作可追溯、可复核

## 七、常见问题

### Q: 如何让系统自动分配笼位？
A: 创建分配记录时不传 `cage_id`，系统会根据动物的品系、性别、隔离要求自动寻找最合适的笼位。

### Q: 如何处理临时转笼？
A: 使用 `action: "temporary_move"` 创建临时转笼记录。系统会执行同样的合规检查，但会标记为临时操作。

### Q: 如何查看一只动物的历史分配？
A: `GET /api/animals/:id` 会返回该动物的所有分配记录。

### Q: 如何导出数据？
A: 所有报表接口返回JSON格式数据，可以直接导入Excel或其他分析工具。
