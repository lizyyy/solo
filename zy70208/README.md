# 船坞维修占坞排程器

一套用于船坞维修排程的演示系统，围绕船坞同时接收多艘船维修，潮汐窗口、吊装资源和工种排班互相冲突的场景进行排程优化。

## 系统功能

### 核心功能
1. **船舶工单管理**：管理待维修船舶的维修需求、工时预估、资源需求等
2. **坞位窗口管理**：管理船坞可用时间、尺寸限制、类型匹配
3. **吊装资源管理**：管理龙门吊、浮吊、移动吊等吊装设备的可用情况
4. **潮汐窗口管理**：考虑潮汐对船舶进出坞的影响
5. **工种排班管理**：管理各工种人员的排班和可用性
6. **冲突检测与解释**：自动检测排程冲突并提供详细解释
7. **排程报告生成**：生成详细的排程结果报告

### 冲突检测类型
- **坞位冲突**：坞位时间重叠、坞位类型不匹配
- **尺寸冲突**：船舶尺寸超过坞位限制
- **潮汐冲突**：排程时间段无潮汐数据（待人工确认）
- **吊装冲突**：吊装资源不足或类型不匹配
- **工种冲突**：所需工种人员不可用

## CSV数据格式说明

### 1. 船舶工单 (work_orders.csv)

| 字段 | 说明 | 示例 |
|------|------|------|
| order_id | 工单ID（必填） | WO-2026-001 |
| ship_name | 船名（必填） | 中远之星 |
| imo_number | IMO编号 | IMO9123456 |
| ship_length | 船长(m) | 180 |
| ship_width | 船宽(m) | 28 |
| ship_depth | 吃水(m) | 10 |
| vessel_type | 船舶类型 | 集装箱船 |
| work_description | 工作描述 | 主机大修+船体清洁 |
| work_types | 工作类型（分号分隔） | 主机维修;船体清洁 |
| priority | 优先级(1-5，越大越高) | 3 |
| estimated_duration_hours | 预计工时(h) | 48 |
| required_dock_type | 需要的坞位类型 | 干船坞/浮船坞/船台 |
| required_lift_types | 需要的吊装类型（分号分隔） | 龙门吊;浮吊 |
| required_crafts | 需要的工种（分号分隔） | 焊工;机修工;电工 |
| earliest_start | 最早开始时间 | 2026-05-12 08:00 |
| latest_deadline | 最晚截止时间 | 2026-05-20 18:00 |

**坞位类型可选值**：干船坞、浮船坞、船台

**吊装类型可选值**：龙门吊、浮吊、移动吊

**工种可选值**：电工、焊工、钳工、油漆工、起重工、机修工

### 2. 坞位窗口 (docks.csv)

| 字段 | 说明 | 示例 |
|------|------|------|
| dock_id | 坞位ID | DOCK-001 |

| dock_type | 坞位类型 | 干船坞 |

| max_width | 最大船宽(m) | 40 |

### 4. 工种排班 (crafts.csv)

| 字段 | 说明 | 示例 |
|------|------|------|

### 5. 潮汐窗口 (tides.csv, 可选)

## 输出文件说明

### CSV结果文件 (`schedule_result_*.csv`)
包含所有工单的排程结果：
- 已排程的工单：显示分配的坞位、吊装设备、工种人员和时间
- 冲突工单：显示冲突原因
- 待人工确认：显示需要人工确认的原因

### 报告文件 (`report_*.txt`)
详细的排程报告，包含：
- 统计摘要（处理总数、成功数、冲突数、待确认数）
- 成功排程明细
- 冲突记录
- 待人工确认记录

### 冲突报告 (`conflicts_*.txt`)
仅在存在冲突时生成，包含：
- 冲突类型分布统计
- 各类冲突的详细分析

### 坞位使用报告 (`dock_usage_*.txt`)
各坞位的使用情况，包含：
- 坞位基本信息
- 已排程的工单列表

## 冲突场景说明

### 1. 船舶尺寸超限
- **触发条件**：船舶长度或宽度超过坞位限制
- **示例**：太平洋巨人(280m) > 1号干船坞(250m)
- **处理方式**：标记为冲突，无法排程

### 2. 坞位类型不匹配
- **触发条件**：工单需要的坞位类型与可用坞位类型不符
- **示例**：北极光需要浮船坞，但只有干船坞可用
- **处理方式**：标记为冲突

### 3. 吊装资源不足
- **触发条件**：所需吊装类型的设备已被占用
- **处理方式**：标记为冲突

### 4. 工种人员不足
- **触发条件**：所需工种的所有工人已被占用
- **示例**：电工只有1人，多个工单同时需要
- **处理方式**：标记为冲突

### 5. 潮汐数据缺失
- **触发条件**：排程时间段没有潮汐数据
- **处理方式**：标记为"待人工确认"

### 6. 坏数据
- **触发条件**：必填字段为空或格式错误
- **示例**：缺少工单ID或船名
- **处理方式**：跳过处理，在坏数据明细中显示

## 排程算法说明

排程引擎采用贪心算法，按以下优先级进行排程：

1. **优先级排序**：优先排程优先级高的工单
2. **工时排序**：相同优先级下，工时较长的优先排程
3. **坞位匹配**：按顺序尝试每个坞位，检查：
   - 船舶尺寸是否适合
   - 坞位类型是否匹配
   - 时间窗口是否可用
4. **资源检查**：检查吊装设备和工种人员是否可用
5. **潮汐检查**：检查潮汐窗口数据是否完整

## 反复演示

### 演示4：潮汐窗口
- 修改 `tides.csv` 中的日期范围
- 观察"待人工确认"的工单
