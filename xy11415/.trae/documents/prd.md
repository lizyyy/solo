# 物业维修派单异常回执状态机 - PRD

## 1. 产品概述

物业维修派单异常回执状态机系统，解决物业客服、维修师傅、项目经理在处理维修异常时信息不对称、证据链断裂、追溯困难的痛点。通过完整的状态流转和审计追踪，实现异常回执全链路可追溯、原始证据不可篡改、关键操作留痕。

- **核心问题**：维修异常处理缺乏标准化流程，项目经理需反复追问进度，原始证据易丢失，改判操作无迹可寻
- **目标用户**：物业客服、维修师傅、项目经理、财务结算人员
- **核心价值**：建立可审计的异常处理闭环，减少沟通成本，确保结算公正

## 2. 核心功能

| 角色 | 登录方式 | 核心权限 |
|------|----------|----------|
| 物业客服 | 账号密码 | 批次创建、附件上传、提交异常、撤回申请、查看进度 |
| 维修师傅 | 账号密码 | 回执上传、查看派单、确认状态 |
| 复核专员 | 账号密码 | 复核改判、添加人工理由、查看原始证据 |
| 项目经理 | 账号密码 | 冻结结算、查看汇总报表、导出数据、全链路追溯 |
| 财务人员 | 账号密码 | 确认冻结状态、执行结算、查看审计日志 |

### 2.2 功能模块

1. **异常批次管理**：批次创建、附件补传、批量导入、来源追踪
2. **状态流转引擎**：状态机驱动、自动流转、人工干预、边界处理
3. **证据链管理**：原始数据保留、改判对比、附件版本管理
4. **复核改判中心**：人工审核、理由填写、状态变更、操作留痕
5. **冻结结算模块**：冻结/解冻、结算确认、冻结前后状态对比
6. **审计追溯系统**：操作日志、权限拦截记录、完整链路追踪
7. **报表导出中心**：自定义汇总、冻结前后对比、导出明细

## 3. 核心流程

### 3.1 完整异常处理链路

1. **客服创建批次**：上传报修截图、维修回执、材料领用表，填写备注
2. **系统解析入库**：保留来源文件、原始行号、解析后标准值
3. **状态自动流转**：待处理 → 处理中 → 待复核
4. **复核专员改判**：查看原始证据，填写人工理由，改判状态
5. **项目经理冻结**：确认冻结，记录冻结前后状态
6. **财务结算**：确认冻结状态后执行结算
7. **归档或撤回**：完成后归档，或撤回后重新提交

### 3.2 边界场景处理流程

- **重复提交**：检测批次号重复，拒绝提交并提示已存在批次
- **撤回后再提交**：保留撤回记录，创建新版本号，关联原批次
- **部分失败**：批量导入时标记失败行，展示失败原因，支持重试
- **人工改判**：保留原始状态，新增改判记录，记录操作人及理由
- **导出前冻结**：导出前强制检查冻结状态，未冻结提示需先冻结

## 4. 用户界面设计

### 4.1 设计风格

- **主色调**：深蓝色 (#1e3a5f) - 专业、稳重、可信赖
- **辅助色**：橙色 (#f59e0b) - 预警、操作；绿色 (#10b981) - 成功；红色 (#ef4444) - 异常
- **按钮风格**：直角微圆角 (4px)，悬浮时轻微上浮效果，点击有按压反馈
- **字体**：标题使用 Noto Sans SC Bold，正文使用 Noto Sans SC Regular
- **布局风格**：左侧导航 + 右侧内容区，卡片式布局，清晰的信息层级
- **图标风格**：线性图标，统一 24px 尺寸，与主色调保持一致

### 4.2 页面设计概览

| 页面名称 | 模块名称 | UI 元素 |
|----------|----------|---------|
| 批次列表 | 数据表格 | 斑马纹表格、状态标签、操作列悬浮按钮、分页器 |
| 批次详情 | 时间线 | 垂直时间线、状态节点高亮、hover显示详情、点击展开 |
| 复核工作台 | 侧边对比 | 左右分栏：左侧原始数据，右侧改判表单 |
| 冻结结算 | 对比卡片 | 冻结前/冻结后并排对比，差异高亮显示 |
| 审计日志 | 拦截提示 | 权限不足时红色弹窗提示，同时记录审计日志 |

### 4.3 响应式设计

- **桌面优先**：以 1440px 宽度为基准设计
- **平板适配**：1024px 时导航收起为图标模式
- **移动适配**：768px 以下采用底部导航，表格转为卡片列表

### 4.4 动效设计

- **页面加载**：顶部进度条 + 内容区淡入
- **状态变更**：状态标签颜色渐变过渡 (300ms)
- **时间线**：滚动时节点依次出现，带有轻微滑动效果
- **按钮交互**：hover 时上移 2px + 阴影加深，click 时下移 1px
- **权限拦截**：红色边框闪烁 3 次 + 抖动效果

## 5. 数据可追溯性要求

### 5.1 原始证据保留

- 导入文件原样存储，不做任何修改
- 记录原始行号、列名、原始值
- 解析后标准值与原始值关联存储
- 改判操作不覆盖原始数据，仅新增版本

### 5.2 操作轨迹记录

- 所有操作记录：操作人、时间、IP、操作类型
- 状态变更记录：变更前状态、变更后状态、变更理由
- 权限拦截记录：尝试操作、拦截原因、用户信息
- 导出记录：导出时间、导出人、导出范围、数据快照

### 5.3 报表展示重点

- 冻结前后状态对比表
- 人工改判理由汇总
- 各状态批次数量统计
- 处理时效分析
- 权限拦截次数统计
