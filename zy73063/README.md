# 工厂管线报告复核 · 班组交接历史台

> 给设备工程师老何用的复核工具。把公式、单位、边界值摆在明处，
> 历史版本完整留痕，照片时间错位单独拎出来，月底复核一目了然。

---

## 🚀 快速开始（老何的操作顺序）

### 第 1 步：安装依赖

```bash
cd 到本目录
pip3 install -r requirements.txt
```

### 第 2 步：启动服务

```bash
python3 app.py
```

看到类似输出就成了：
```
 * Running on http://127.0.0.1:5009
```

### 第 3 步：打开浏览器

地址栏输入：**http://127.0.0.1:5009**

进来以后先看这几块（从上到下）：

| 区域 | 看什么 | 对应需求 |
|---|---|---|
| 顶部 4 个数字卡片 | 已确认 / 待补件 / 退回 / 时间错位照片数 | 月底复核一眼分清楚 |
| 筛选条件区 | 状态、管线、日期、照片异常 4 个维度筛 | 屏幕筛到啥，导出就是啥 |
| 交接记录卡片 | 公式名+输入值+结果+单位+边界告警，完整展示 | 不光吐最终数字，过程摆明处 |
| 📝 黄色补录备注条 | 班组交接后补的内容，原样保留 | 补录备注不丢 |
| 📷 红色异常照片标签 | 拍摄时间和记录日期间隔 >48h 的单独标红 | 时间错位不揉进正常结果 |
| 底部「公式库」面板 | 每个公式的单位、边界值、物理含义 | 口径统一，明处展示 |

### 第 4 步：看一条记录的**历史时间线**

随便点一张卡片底部的 **「📜 历史时间线」** 按钮：

- 左侧有时间轴（蓝色点=当前版本，灰色点=历史版本）
- 每个版本里有：**变更人、变更时间、变更说明、完整快照 JSON、旧版本截图**
- 历史版本的快照里能看「当时的状态是啥、当时补录备注写了啥、后来改了啥」
- 弹窗右下角 **「📥 导出该时间线」** 按钮可单独导出 CSV

### 第 5 步：改状态（会自动写入历史）

每张卡片底部 3 个状态按钮：
- ✅ 标记已确认
- 📦 待补件
- ↩️ 退回

改完会自动追加一个新版本到历史时间线里，不覆盖旧值。

### 第 6 步：月底导出复核表

筛选好想要的记录（比如「状态=待补件」+「照片异常=是」），
点页面右上角 **「📦 导出屏幕筛选结果」**。

> 💡 **核心保证**：导出的 CSV 文件和屏幕上看到的记录 **完全同口径**。
> 屏幕筛到哪些行，CSV 里就哪些行，不会另起一套口径。

## 📦 现场材料包（static/materials/ 目录）

这就是"一包像现场会收到的材料"：

```
static/materials/
├── 班组交接记录原件_6月7-9日.txt     ← 纸质原件OCR文本，含7条交接
├── notes/
│   └── 补录备注_6月上旬.txt          ← 老何和同事后来补写的备注条
└── screenshots/                      ← 旧版本截图（4张，SVG格式占位）
    ├── v2_rec1.png.svg
    ├── v2_rec3.png.svg
    ├── v2_rec5.png.svg
    └── v2_rec7.png.svg
```

> 第一次启动 app.py 时，这些材料会被自动灌进 SQLite 数据库，
> 生成 7 条示例交接记录 + 14 张照片（7张正常 + 7张时间错位）+
> 11 个历史版本 + 14 条公式计算结果。

## 🧠 设计要点（对应你的需求逐条拆）

| 你说的痛点 | 系统怎么解决 |
|---|---|
| 交接时不知道上一班改了啥，收尾才冒出来 | 每条记录有「历史时间线」按钮，谁、啥时候、改了啥，快照全留 |
| 公式/单位/边界值别光吐最终数字 | 卡片里公式名 + 输入值 + 结果 + 单位 + 边界告警 全展开；底部还有完整公式库 |
| 补的备注和旧截图别只保留最终值 | 补录备注单独黄色条；旧截图关联到对应历史版本；改状态是追加不是覆盖 |
| 照片时间错位别揉进正常结果 | 每条记录照片红色标签单独标；筛选条件可直接"只看含时间错位照片" |
| 月底要分已确认/待补件/退回 | 顶部 4 张统计卡片；每条记录右上角彩色标签；筛选条件按状态过滤 |
| 导出别另起一套口径 | `/api/export` 接受和列表完全相同的 query 参数；右上角按钮把当前筛选参数原样传过去 |
| 带一包现场材料，README 说清楚先跑啥再看啥 | `static/materials/` 完整一包；本 README 「快速开始」按 1→2→3→4→5→6 顺序写 |

## 🛠️ 常用排查

| 现象 | 怎么搞 |
|---|---|
| 端口 5009 被占了 | `app.py` 最后一行改 port=xxxx |
| 想清空重来 | 删掉 `data/pipeline_review.db` 再跑 `python3 app.py` |
| 导出 CSV 乱码 | 用 Excel 打开时选「UTF-8 编码」，或直接 WPS/Numbers 打开 |
| 照片标记异常的阈值 | `app.py` 的 `seed_demo_data` 里写死 >48h 算异常，按需改 |
