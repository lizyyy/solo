# 异宠温控记录复核系统

面向异宠（非犬猫类宠物）诊疗场景的体温监控记录复核平台，提供温控曲线分析、异常自动识别、结论改判追溯等完整工作流。

---

## 🚀 快速开始（3 步上手）

### ① 安装启动

```bash
# 1. 安装依赖
npm install

# 2. 同时启动前后端（Vite + Express）
npm run dev
```

启动后：
- **前端地址**：http://localhost:5173 （Vite 开发服务器，已配置代理到后端）
- **后端 API**：http://localhost:3001 （Express + lowdb，数据真实写入 `api/db/data.json`）

> 单独启动：`npm run client:dev` 或 `npm run server:dev`

---

### ② 日常复核工作流

1. **打开首页**（`/`）：按更新时间倒序展示所有温控记录，左侧导航、右侧是异常队列速览
2. **筛选记录**：使用「筛选条件」面板按状态、关键字、日期范围过滤
3. **进入详情**（`/records/:id`）：点击记录卡片进入详情页
   - 查看 **温控曲线** / **体重变化曲线** 可视化图表
   - 检查 **影响因子分析** 面板：每条因子标注影响方向（正/负/中性）和受影响条数
   - 若出现红色 **疫苗缺失警告**，需先通过「补录」按钮添加疫苗日期，禁止直接标记正常
4. **改判 / 补录**：
   - 点底部「改判」→ 选结论 + 填原因，操作人默认「阿宁」
   - 点「补录」→ 选类型（疫苗 / 体重 / 备注），支持新旧体重曲线区分
5. 成功后顶部显示绿色 Toast 提示，所有操作自动写入历史时间线

---

### ③ 评审会准备（人工修改溯源）

评审会前查阅某条记录的所有人工干预步骤：

1. 在首页或详情页点击 **「查看历史」** 按钮（进入 `/records/:id/history`）
2. 时间线中所有 **🟠 琥珀色节点** = 人工修改过的步骤（含改判、补录、异常确认）
3. **点击改判 / 补录节点**，下方展开「版本对比」卡片，逐字段展示变更前后的快照差异
4. 右侧「图例说明」卡片和「操作统计」进度条提供全局概览

## ⚠️ 坏材料排查（重点章节）

系统自动识别 4 类"坏材料"，集中展示在**异常队列页**（`/queue`）。

| 坏材料类型 | 去哪里看 | 视觉特征 | 处理建议 |
|---|---|---|---|
| **疫苗日期缺失** | 异常队列 > **疫苗缺失** Tab / 记录详情顶部红色警告块 | 朱砂红（cinnabar-600）边框卡片、⚠️ 三角感叹号图标、`vaccines[].date === null` | ① 补录疫苗日期 → 系统自动关闭异常 ② 暂时无法补录则填写待确认理由，**绝对不要标记为正常** |
| **旧版体重曲线混入** | 异常队列 > **旧版曲线** Tab / 记录详情体重曲线图 | 灰色虚线（`strokeDasharray`）+ 「旧版」水印标签、曲线背景有大写 OLD VERSION 斜体水印、灰色（mist-600）卡片 | 详情页「影响因子面板」会标注"降低结果可信度"。建议重新采集数据后改判，评审时需特别说明旧版数据来源 |
| **边界样本** | 异常队列 > **边界样本** Tab / 记录详情影响因子面板黄色标识 | 温度值在阈值 ±0.1℃ 范围内、Gauge 仪表盘图标、琥珀色（amber-500）卡片 | 需 **二次人工确认**，评审会标注"边界值"。建议结合体重曲线、疫苗记录、临床其他指标综合判断，不可单独依据体温改判 |
| **口头备注混入** | 记录详情底部备注列表，来源 = `verbal` / 影响因子面板 | 引号样式卡片（双引号大字符装饰）、MessageCircle 图标、琥珀色左边框 | 追溯备注来源人（操作人字段），必要时：① 改判为「观察」② 录入书面说明（补录 > 书面备注）。评审会必须确认口头信息真实性 |

> 💡 **快速入口**：异常队列页顶部有「坏材料排查指南」锚点卡片，点击 4 种类型可直接跳转到对应 Tab。

## 🔍 谁影响了结论？

任何结论存疑的记录，按以下顺序溯源：

1. **影响因子分析面板**（详情页）：系统自动标注每条因子的类型、影响方向、受影响记录编号。这是结论可信度的第一手依据
2. **历史时间线节点 `reason` 字段**（历史追溯页）：人工改判的原因就在 `rejudge` 节点的 reason 里，点击节点展开「版本对比」可看到具体改了哪些字段
3. **备注列表的 `source` 字段**：`verbal` = 口头转达，`written` = 书面记录；口头备注以斜体 Lora 衬线字体 + 引号呈现，需二次核实

## 🛠 技术说明

- **前端**：React 18 + React Router 7 + Zustand（状态管理）+ Tailwind CSS（森林绿/琥珀/朱砂红设计系统）+ Recharts（可视化）+ Lucide React（图标）
- **后端**：Express 4 + lowdb（`api/db/data.json` 持久化存储，零配置）
- **共享类型**：通过 `@shared/types` 别名前后端共用，保证接口类型一致
- **预置示例数据**：7 条记录（编号 R001–R007），覆盖上述 4 种坏材料场景，方便直接体验功能
  - R001/R002：疫苗缺失场景
  - R003/R004：旧版体重曲线场景
  - R005：边界样本场景
  - R006：口头备注混入场景
  - R007：完整正常案例（对照组）
