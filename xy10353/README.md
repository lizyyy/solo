# 小型仓库退货质检台

一个完整的退货质检管理系统，包含质检录入、库存管理、统计分析等功能。

## 技术栈

- **后端**: Node.js + Express + SQLite (better-sqlite3)
- **前端**: Vue 3 + Element Plus + Vite
- **导出**: Excel (.xlsx)

## 快速开始

### 1. 安装依赖

```bash
# 后端
cd backend
npm install

# 前端（新开终端）
cd frontend
npm install
```

### 2. 启动服务

```bash
# 后端 - 运行在 http://localhost:3000
cd backend
npm run dev

# 前端 - 运行在 http://localhost:5173（新开终端）
cd frontend
npm run dev
```

首次启动会自动创建 4 条样例数据，方便测试。

## 业务流程与验证说明

### 核心业务规则

| 规则 | 说明 | 拦截位置 |
|------|------|----------|
| 平台单号唯一性 | 同一平台单号只能创建一次 | 新增/导入退货单时 |
| 关键质检项必填 | 外观、配件、包装、功能测试必须填写 | 保存质检时 |
| 禁止重复处置 | 已处置的退货单不能再次处置 | 点击处置按钮时 |
| 拒收后禁止入库 | 已拒收的退货单不能再入库 | 处置逻辑中 |
| 质检后才能处置 | 必须先保存质检才能处置 | 处置前校验 |

### 样例场景操作指南

系统预置了 4 条样例退货单，对应不同的处置场景：

#### 场景 1：完好入库二次销售（耳机 TM202605010001）

**操作步骤：**

1. 打开浏览器访问 http://localhost:5173
2. 在退货单列表找到 `TM202605010001 - 无线蓝牙耳机 Pro`
3. 点击【质检/详情】按钮进入详情页
4. 填写质检项（全部选完好）：
   - 外观检查：完好
   - 配件检查：齐全
   - 包装检查：完好
   - 功能测试：正常
   - 整体结果：良品
   - 质检员：张三
5. 点击【保存质检】
6. 系统提示保存成功后，点击【入库二次销售】按钮
7. 确认处置

**验证结果：**
- 列表页状态变为【已处置】，处置方式显示【入库】
- 统计汇总页：
  - 待检数量 -1

  - 入库二次销售 +1

- 点击【导出】，Excel 中该单处置方式为"入库二次销售"

### 异常拦截测试

#### 测试 A：缺少关键质检项拦截

1. 进入任意待检退货单详情
2. 只填"外观检查"，其他三项留空
3. 点击【保存质检】

**预期结果：**
- 系统提示："缺少关键质检项：配件检查、包装检查、功能测试"
- 质检未保存，状态仍为"待检"
- 处置按钮不显示

#### 测试 B：已处置后重复入库拦截

1. 对已处置的退货单（比如场景1中处置完的耳机）
2. 刷新详情页
3. 观察页面状态

**预期结果：**
- 质检表单被禁用（灰色不可编辑）
- 处置按钮区域显示已处置的 Alert，不显示操作按钮
- 尝试通过 API 调用处置接口会返回："同一退货单禁止重复处置/入库"

#### 测试 C：拒收后禁止入库

1. 进入一条待检退货单
2. 完成质检并保存
3. 点击【拒收】按钮处置
4. （可选）尝试通过 API 调用其他处置方式

**预期结果：**
- 拒收后表单禁用
- 统计汇总页"拒收"数量 +1
- 库存**不会**增加（拒收不入库）
- 若尝试改为入库，后端返回："该退货单已拒收，禁止重新入库"

## 数据一致性保障

### 机制说明

1. **数据库事务**：处置操作使用 `db.transaction()` 包裹，确保状态更新和库存变动要么全成功要么全失败

2. **实时数据读取**：
   - 列表页每次加载从数据库查询最新数据
   - 详情页保存/处置后立即 `loadData()` 刷新
   - 统计汇总页每次进入都调用 `/api/stats` 实时计算

3. **后端硬校验**：所有拦截逻辑在后端实现，前端仅做提示；即使绕过前端调用 API，后端也会拦截

### 验证一致性的方法

处置完任意退货单后：

1. **列表与详情一致**：在列表看到的状态和处置方式，进入详情页应相同
2. **详情与统计一致**：处置后点击左侧【统计汇总】，相关计数器应该 +1
3. **统计与导出一致**：点击【导出所有数据】，打开 Excel 第二个 Sheet"统计汇总"中的数字应与页面一致
4. **库存同步**：统计页的库存汇总表中，对应 SKU 的数量应增加

## 导入功能说明

### 导入模板格式

Excel 第一行为表头，从第二行开始是数据：

| 平台单号 | 商品名称 | SKU | 退货原因 | 客户姓名 | 联系电话 |
|---------|---------|-----|---------|---------|---------|
| TM20260510001 | 无线鼠标 | MOUSE-001 | 7天无理由 | 测试用户 | 13800000001 |

### 导入验证

- 平台号重复会被拦截并报告具体行号
- 必填项缺失会报告具体行号
- 部分成功部分失败时，成功的会导入，失败的会列出来

## API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/orders | 获取退货单列表，支持 status 和 keyword 参数 |
| GET | /api/orders/:id | 获取单条详情（含质检和日志） |
| POST | /api/orders | 新增退货单 |
| POST | /api/orders/import | Excel 批量导入 |
| POST | /api/orders/:id/quality | 保存质检 |
| POST | /api/orders/:id/dispose | 处置（resell/repair/scrap/reject） |
| GET | /api/inventory | 库存列表 |
| GET | /api/stats | 统计数据 |
| GET | /api/export/orders | 导出 Excel（含两个 Sheet） |
