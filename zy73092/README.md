# 机电管综材料追踪 (MEP Material Tracker)

替代结构工程师老叶人工兜底的系统化工具，解决**材料送审表与交底清单意见不一致、批次缺失假稳定、重跑历史混淆**三大痛点。

---

## 快速开始（3 步）

```bash
# 1. 安装依赖
npm install

# 2. 启动前后端（前端 Vite :5173 + 后端 Express :3001）
npm run dev

# 3. 浏览器打开 http://localhost:5173
```

首次启动自动创建 SQLite 数据库 `api/data/mep-tracker.db`，并预置 6 条材料（含 2 条**边界样本**，方便测试确认逻辑）。

---

## 坏材料来了？看这里

| 现象 | 页面 | 你要看什么 | 怎么处理 |
|------|------|-----------|---------|
| 批次缺失 / 假稳定 | 材料**列表** 第一行红色左竖条的行（SUSPENDED / MISSING / AWAITING_PM） | 摘要面板中 🟥 **批次挂起** + 🟧 **缺材料** 卡片 | 点击卡片自动筛选 → 进入详情 → 右上角切换为「项目经理」角色 → 点击「发起挂起确认」→ 三选：① 确认缺材料（进 MISSING，不给出假结论） ② 补充批次（回 PENDING） ③ 驳回 |
| 交底清单漏了旧意见 | 材料**详情** → 意见流水 Timeline | 比较「交底清单（🔵蓝点）」与「送审表（🟢青点）」内容；若送审表多了内容而交底清单没有，就是边界样本 MEP-PL-003 的情况 | 在下方**固定改判栏**「后补备注」里补充遗漏的旧意见内容 → 提交（会被标记为 🟠琥珀「后补备注」来源） |
| 同一材料重跑分不清新旧 | 材料**详情** → 意见流水 / 或**历史记录**页 | 灰色斜纹圆点 + `opacity-70` + 「旧处理」标签 = 重跑前的记录；🟠 琥珀=后补；🟣 紫色=最新导出 | 在列表行点击「重跑」按钮，系统自动把现有意见全部打为「旧处理」，新插入的意见按来源分别标记 |
| 又要给假结论了？ | 详情页底部改判栏 | 只要批次缺失，「提交改判」按钮**强制禁用**，显示文案：「批次缺失，需项目经理确认后才能改判」 | 先按上方「批次缺失」流程走完项目经理挂起确认再说，系统不允许给出假稳定结论 |
| 给项目经理交差要汇报 | **列表页顶部 6 张摘要卡片** | ✅ 已处理（绿）/ ⏳ 待改判（黄）/ 🔴 批次挂起（红）/ 🟠 缺材料（橙）/ 💜 待PM确认（紫）/ 📊 总计 | 点击任意卡片即可跳转到对应筛选结果；下方表格按状态高亮 |

### 边界样本速查（已预置）
- **MEP-PL-003 PPR 给水管道** → 交底清单少写了旧意见（送审表多了「需提供卫生许可」，交底清单只有「符合国标」）
- **MEP-FR-004 喷淋头** → 批次 B20260315 缺失质检报告，系统挂起中

## 页面结构

```
/ (首页)                        材料追踪列表 + 6 张摘要卡片 + 筛选 + 表格
/material/:id                   详情：基本信息 / 批次 / 意见流水 / 底部固定改判栏
/history                        历史记录：全量操作流水 + 来源标记筛选
/import                         送审表导入：拖拽上传 JSON / 一键填入边界样本预览
```

## 角色切换（右上角按钮）
- **结构工程师**（默认）：改判、补备注、重跑、导入
- **项目经理**：工程师全部权限 + 挂起确认（决定是否确认缺材料，唯一能解除「批次缺失拒判」锁的角色）

## 数据目录
```
api/data/mep-tracker.db         SQLite 数据库（自动生成，可直接删除重跑）
```
