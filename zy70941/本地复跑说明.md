# 物流调度核对系统 - 本地复跑说明

## 一、环境准备

### 1. 安装依赖
```bash
cd /Users/lzy/pro/solo/workspaces/zy70941
pip install -r requirements.txt
```

### 2. 项目结构
```
zy70941/
├── main.py                    # API 入口文件
├── requirements.txt           # 依赖包
├── app/
│   ├── __init__.py
│   ├── models.py             # 数据模型定义
│   ├── services.py           # 核心核对逻辑
│   └── utils.py              # 文件解析工具
```

## 二、启动服务

### 方式1：直接运行
```bash
python main.py
```

### 方式2：使用 uvicorn
```bash
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

服务启动后访问：http://localhost:8000

## 三、API 接口说明

### 1. 健康检查
```bash
curl http://localhost:8000/api/v1/health
```

### 2. 处理本地样例数据（推荐）
```bash
curl -X POST "http://localhost:8000/api/v1/process/local" \
  -H "Content-Type: application/json" \
  -d '{
    "batch_id": "BATCH_TEST_001",
    "waybill_path": "./samples/waybills.csv",
    "track_path": "./samples/tracks.json",
    "rules_path": "./samples/rules.json"
  }'
```

### 3. 文件上传方式
```bash
curl -X POST "http://localhost:8000/api/v1/process/upload" \
  -F "batch_id=BATCH_TEST_002" \
  -F "waybill_file=@./samples/waybills.csv" \
  -F "track_file=@./samples/tracks.json" \
  -F "rules_file=@./samples/rules.json"
```

### 4. JSON 方式
```bash
curl -X POST "http://localhost:8000/api/v1/process" \
  -H "Content-Type: application/json" \
  -d '{
    "batch_id": "BATCH_TEST_003",
    "waybills": [...],
    "tracks": [...],
    "rules": [...]
  }'
```

### 5. 查询批次状态（幂等性验证）
```bash
curl http://localhost:8000/api/v1/batch/BATCH_TEST_001
```

## 五、复跑步骤

### 完整测试流程
```bash
# 1. 启动服务
python main.py &

# 2. 等待服务启动
sleep 3

# 3. 首次提交批次

  -H "Content-Type: application/json" \

  -d '{"batch_id": "BATCH_TEST_001"}'

curl http://localhost:8000/api/v1/batch/BATCH_TEST_001

# 6. 查看 Swagger 文档
open http://localhost:8000/docs
```

## 六、预期输出说明

处理结果包含三部分：
- **normal_items（正常项）**：WB001、WB004、WB006、WB007
- **pending_items（待确认项）**：WB002（中转状态异常，需人工修正）
- **failed_items（失败项）**：
  - WB003：跨中转超时 + 破损，建议核对南充中转站记录
  - WB005：干线晚点 + 跨中转超时 + 破损，建议人工复核

失败记录保留字段：
- `original_data`：运单原始数据
- `failure_reason`：失败原因
- `suggested_action`：建议处理方式
- `rule_applied`：适用的规则ID
- `penalty_amount`：扣罚金额
