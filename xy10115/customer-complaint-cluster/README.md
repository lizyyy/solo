# 客诉文本聚类复盘器

一个专注于**错误样本追踪、解释理由留存、修正历史可追溯**的客诉文本聚类工具。

## 场景

客服标签打得很乱，月底复盘时同类投诉被拆成好几类。通过这个工具，可以：
- 先进行轻量规则 + 向量聚类自动分类
- 人工复核时可以看到每条投诉的聚类历史和原因
- 发现误判可以一键回滚到之前的版本
- 每次操作都会记录到版本历史和操作日志
- 支持导出聚类结果和完整操作记录用于复盘报告

## 核心特性

1. **数据导入** - 支持 CSV、Excel (.xlsx/.xls) 格式
2. **轻量聚类引擎** - 规则匹配（关键词/正则） + 向量聚类（sentence-transformers）
3. **人工复核** - 查看投诉历史、移动到正确聚类、创建新聚类
4. **误判回滚** - 一键回滚到任意历史版本，不丢失操作记录
5. **版本管理** - 每次操作创建新版本，保留父子关系
6. **操作日志** - 所有变更都记录旧值、新值、原因和时间
7. **报告导出** - 导出聚类结果和操作日志（CSV/Excel）

## 快速开始

### 1. 安装依赖

```bash
cd customer-complaint-cluster
pip install -r requirements.txt
```

### 2. 启动服务

```bash
python backend/app.py
```

服务将在 `http://localhost:5000` 启动。

### 3. 使用流程

1. **导入数据**
   - 访问 `数据导入` 页面
   - 上传 CSV 或 Excel 文件
   - 示例数据见 `sample_data.csv`

2. **创建规则（可选但推荐）**
   - 访问 `规则管理` 页面
   - 创建关键词或正则规则
   - 例如：物流问题 → `物流,快递,配送,送货`

3. **运行聚类**
   - 访问 `聚类管理` 页面
   - 点击 `运行聚类分析`

4. **人工复核**
   - 在 `投诉列表` 或 `聚类管理` 中查看聚类结果
   - 点击 `查看历史` 查看该投诉的完整聚类历史
   - 点击 `移动` 将误判的投诉移到正确的聚类
   - 每次移动都需要填写修正原因

5. **版本管理**
   - 访问 `版本历史` 页面
   - 点击 `查看详情` 查看该版本的聚类和操作
   - 点击 `回滚` 恢复到历史状态（会创建新版本，不会删除历史）

6. **查看操作日志**
   - 访问 `操作日志` 页面
   - 可以看到所有操作的变更前、变更后和原因

7. **导出报告**
   - 访问 `报告导出` 页面
   - 导出聚类结果或操作日志

## 数据格式要求

导入的文件需要包含以下列（列名可在导入时自定义）：

| 列名 | 必填 | 说明 |
|------|------|------|
| text | 是 | 投诉文本内容 |
| tags | 否 | 客服打的原始标签（用于对照） |
| id | 否 | 原始系统中的投诉ID |

示例（见 sample_data.csv）：
```csv
text,tags
物流太慢了，等了一周还没到,物流
客服根本不解决问题，只会说抱歉,客服态度
退货申请提交了3天了还没人处理,售后服务
```

## 技术栈

- **后端**: Flask + SQLAlchemy + SQLite
- **聚类**: 
  - 规则匹配：关键词/正则（无需模型）
  - 向量聚类：sentence-transformers（可选，需要下载模型）
- **前端**: 原生 HTML/JS/CSS（无需构建工具）

## 重点功能说明

### 1. 为什么每个操作都要创建新版本？

因为我们的目标是**追踪错误样本、解释理由和修正历史**。如果直接在原版本上修改，就不知道"为什么"和"改了什么"。每次创建新版本，可以：
- 看到每一步操作的完整历史
- 放心回滚，不用担心丢失数据
- 复盘时可以分析哪些地方容易出错

### 2. 规则和向量聚类的关系

- **规则优先**：规则匹配结果优先级更高，可解释性更强
- **向量兜底**：未匹配规则的文本会用向量聚类
- **可组合**：可以先用规则分几大类，再用向量聚类细分类

### 3. 操作日志的价值

每条操作记录都包含：
- 操作类型（规则匹配/向量聚类/手动移动/回滚等）
- 变更前的值
- 变更后的值
- 操作者填写的原因（必填）
- 操作时间

这让复盘时可以回答：
- 这条投诉为什么被分到这个聚类？
- 之前被误分到哪里了？
- 是谁、什么时候、为什么修改的？

## 注意事项

1. **首次使用向量聚类**会自动下载模型（~40MB），需要联网
2. 如果不想用向量聚类，可以只使用规则匹配
3. 数据存储在 `data/db/complaints.db`，可直接备份该文件
