# I/O 模型对比实验台

一个可视化的 I/O 模型对比实验工具，用于教学展示**阻塞 I/O**、**非阻塞 I/O**、**I/O 多路复用**和**异步 I/O** 四种网络编程模型的性能差异。

## 功能特性

### 🎛️ 灵活配置
- **连接数**：可配置 1-1000 个并发连接
- **缓冲区大小**：支持 1KB 到 64KB 的缓冲区设置
- **时间参数**：
  - 数据到达时间（可配置抖动范围）
  - 处理耗时（可配置抖动范围）
  - 超时时间

### 📊 对比指标
- **线程占用**：各模型需要的线程数量
- **CPU 空转**：非阻塞轮询产生的无效检查次数
- **延迟**：平均等待时间和处理时间
- **吞吐量**：单位时间内处理的数据量
- **事件循环 Tick**：事件循环迭代次数
- **FD 状态**：实时显示文件描述符状态

### 📄 报告导出
- 导出 **Markdown** 格式报告
- 导出 **JSON** 格式数据
- 包含各模型排名和分析

### 🎯 预设样例
- **默认对比实验**：四种模型标准配置对比
- **坏样例 1**：非阻塞 I/O + 大量连接（展示 CPU 空转问题）
- **坏样例 2**：阻塞 I/O + 大量连接（展示线程开销问题）

## I/O 模型说明

### 1. 阻塞 I/O (Blocking I/O)

**工作原理：**
- 每个连接创建一个独立线程
- 调用 `read()` 时线程阻塞，直到数据到达
- 数据到达后，线程继续处理数据

**特点：**
- ✅ 实现简单，代码易读
- ❌ 线程数量随连接数线性增长
- ❌ 线程上下文切换开销大
- ❌ 大量连接时内存占用高

**适用场景：**
- 连接数少且稳定的场景
- 对实时性要求不高的应用

---

### 2. 非阻塞 I/O (Non-blocking I/O)

**工作原理：**
- 单线程处理所有连接
- 设置 `O_NONBLOCK` 标志
- 轮询检查每个 fd 是否就绪
- 数据未就绪时立即返回 `EAGAIN`

**特点：**
- ✅ 线程数量少（单线程）
- ❌ 需要频繁系统调用检查状态
- ❌ 可能产生大量空轮询（CPU 空转）
- ❌ 忙等待浪费 CPU 资源

**问题示例：**
运行"坏样例 1"可以观察到：
- 非阻塞 I/O 的 CPU 空转次数远高于多路复用
- 连接数越多，空转问题越严重

---

### 3. I/O 多路复用 (I/O Multiplexing)

**工作原理：**
- 使用 `select` / `poll` / `epoll` 机制
- 一次性监听多个文件描述符
- 内核批量返回就绪的 fd 列表
- 应用程序逐个处理就绪的 fd

**特点：**
- ✅ 线程数量少（单线程）
- ✅ 减少空轮询，提高 CPU 效率
- ✅ 适合高并发场景
- ⚠️ 需要额外处理就绪队列管理

**epoll 优势：**
- 监听 fd 数量无上限（select 默认 1024）
- 使用红黑树管理 fd，插入删除高效
- 只返回就绪的 fd，无需遍历全部

---

### 4. 异步 I/O (Asynchronous I/O)

**工作原理：**
- 提交 I/O 请求后立即返回
- 内核负责完成整个 I/O 操作
- 操作完成后通过信号或回调通知应用
- 真正的异步处理，无需等待

**特点：**
- ✅ 最理想的高并发模型
- ✅ 最少的上下文切换
- ✅ 应用层只需关注业务逻辑
- ⚠️ 实现复杂，需要内核支持
- ⚠️ 调试难度较大

---

## 对比总结

| 特性 | 阻塞 I/O | 非阻塞 I/O | I/O 多路复用 | 异步 I/O |
|------|----------|------------|--------------|----------|
| 线程数 | 连接数 | 1 | 1 | 少量 |
| CPU 效率 | 中等 | 低（空转） | 高 | 最高 |
| 实现复杂度 | 低 | 中等 | 中等 | 高 |
| 内存占用 | 高 | 低 | 低 | 低 |
| 吞吐量 | 低 | 中等 | 高 | 最高 |
| 适用场景 | 少连接 | 教学演示 | 高并发 | 极致性能 |

## 使用指南

### 新建实验

1. 填写实验名称和描述（可选）
2. 配置连接参数：
   - 连接数：建议 10-100 用于演示
   - 缓冲区大小：影响吞吐量计算
   - 超时时间：连接超时阈值
3. 配置时间参数：
   - 数据到达时间：模拟网络延迟
   - 到达时间抖动：模拟网络波动
   - 处理耗时：模拟业务处理时间
   - 处理时间抖动：模拟处理波动
4. 选择要对比的 I/O 模型（至少选择一个）
5. 点击"运行实验"开始

### 实时监控

实验运行过程中或单模型运行后，可以在"实时监控"页面查看：
- 实时指标：线程数、CPU 空转、轮询次数等
- 性能趋势图
- FD 状态网格：每个文件描述符的实时状态

### 对比分析

实验完成后，在"对比分析"页面查看：
- 结果概览表格
- 各项指标排名（🥇🥈🥉）
- 性能对比图表
- 导出报告功能

### 历史记录

- 查看所有历史实验
- 加载已有实验配置
- 删除不需要的实验
- 查看已完成的实验结果

## 教学建议

### 推荐演示流程

1. **入门演示**：使用默认配置，让学员直观感受四种模型的差异
   - 关注：线程数、总耗时、吞吐量

2. **问题展示**：运行"坏样例 1"和"坏样例 2"
   - 坏样例 1：展示非阻塞 I/O 的 CPU 空转问题
   - 坏样例 2：展示阻塞 I/O 的线程开销问题

3. **深入对比**：调整参数观察变化
   - 增加连接数：观察阻塞 I/O 线程数增长
   - 减少数据到达时间：观察多路复用的优势
   - 增加处理耗时：观察异步 I/O 的优势

### 教学重点

| 概念 | 如何演示 |
|------|----------|
| 阻塞 | 对比阻塞与非阻塞的线程数 |
| 非阻塞轮询 | 运行坏样例 1，观察 CPU 空转计数 |
| 多路复用 | 对比非阻塞和多路复用的空轮询次数 |
| 异步 | 对比总耗时和吞吐量 |
| 就绪队列 | 查看 FD 状态网格的变化 |
| 事件循环 | 观察事件循环 Tick 计数 |

## 扩展开发

### 添加新的 I/O 模型

在 `server/models/io-models.js` 中：

1. 在 `IO_TYPES` 中添加新类型
2. 实现新的模拟方法（参考 `simulateBlocking` 等方法）
3. 在 `run()` 方法中添加新类型的 case
4. 在前端 `model-selection` 区域添加复选框

### 自定义指标

在 `IOModelSimulator` 类中：
- 扩展 `metrics` 对象添加新指标
- 在模拟方法中更新指标值
- 在 `getReport()` 方法中导出新指标

在前端：
- 在 `displaySingleResult()` 中添加展示逻辑
- 在对比分析页面添加新指标的排名展示

## 常见问题

### Q: 实验运行时间过长？

A: 尝试减少连接数或减少数据到达时间。默认配置（20 连接，200ms 到达时间）通常在几秒内完成。

### Q: 为什么有些连接显示超时？

A: 检查超时时间配置，如果数据到达时间加上处理耗时超过超时时间，连接会被标记为超时。

### Q: 异步 I/O 的优势不明显？

A: 异步 I/O 的优势在高并发、长时间处理的场景下更明显。尝试：
- 增加连接数（>50）
- 增加处理耗时（>200ms）
- 对比总耗时和吞吐量

### Q: 实验数据存储在哪里？

A: 实验数据以 JSON 格式存储在 `data/experiments/` 目录下，每个实验一个文件。
