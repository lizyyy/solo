# 工厂机械臂安全包络系统

设备工程师许工和巡检组交接用的，不是评测说明书。

## 一句话说明白

这个系统解决一个问题：点云抽稀日志里经纬度和米制坐标混在一起时，谁也别瞎猜，按规则来，留好证据，三步走完再发布给现场。

## 谁用这个系统

| 角色 | 干啥 |
|------|------|
| 许工（设备工程师） | 导入点云抽稀日志，补看安全半径表，确认正常记录 |
| 巡检组 | 复核坐标混合记录，决定怎么判、怎么改、怎么回滚 |
| 现场班组 | 看已发布的安全包络，按说明作业 |
| 系统管理员 | 看边界规则，知道系统怎么跑的 |

## 三步工作流（不能跳步）

```
第一步：导入点云抽稀日志 → 第二步：许工补看安全半径表 → 第三步：更新现场说明
     （自动检测坐标混合）      （确认正常记录）              （巡检组复核混合记录后发布）
```

**前置条件：**
- 第一步→第二步：所有正常记录必须全部确认
- 第二步→第三步：所有混合记录必须全部复核

## 边界规则（别口头说，写在这里）

### rule_001：经纬度格式检测
- **怎么判**：数值在经度-180~180、纬度-90~90范围内，或包含°/E/W/N/S标记
- **怎么改**：系统自动标为 `LAT_LNG`，不用人工改
- **怎么回滚**：不用回滚，这是第一步检测
- **代码位置**：`shared/rules/coordinateRules.ts:3-24`

### rule_002：米制格式检测
- **怎么判**：数值带m/米单位标记，或x=/y=写法，或数值超出经纬度正常范围
- **怎么改**：系统自动标为 `METRIC`，不用人工改
- **怎么回滚**：不用回滚，这是第一步检测
- **代码位置**：`shared/rules/coordinateRules.ts:8-28`

### rule_003：坐标混合检测 ⚠️ 重点
- **怎么判**：以下任意一条命中即标记为混合——①同时出现经纬度标记和米制标记；②经度绝对值>50却带米制标记；③有经纬度标记但数值超出经纬度范围；④m/米单位只出现在其中一个坐标上（不对称）；⑤°/方向符号不对称且数值含工程精度尾随零（如 116.4000,39.9000°）
- **怎么改**：系统不会瞎猜，直接标 `is_mixed=1`，`status=INSPECTION_REVIEW`，留给巡检组复核
- **怎么回滚**：复核后发现改错了，点"回滚"回到混合状态重新判
- **代码位置**：`shared/rules/coordinateRules.ts:80-118`

### rule_004：坐标归一化规则
- **怎么判**：巡检组确认坐标类型后自动触发
- **怎么改**：统一转换为米制或经纬度，保留原始数据
- **怎么回滚**：转换错了可以回滚到转换前的状态
- **代码位置**：`shared/rules/coordinateRules.ts:124-159`

### rule_005：回滚规则
- **怎么判**：任何时候觉得不对都可以回滚
- **怎么改**：选要回滚到的历史状态，确认后恢复
- **怎么回滚**：回滚本身也会被记录，可以再回滚
- **代码位置**：`shared/rules/rollbackRules.ts:10-40`

### rule_006：安全半径校验
- **怎么判**：点云日志的半径值与安全半径表差值>5%
- **怎么改**：系统不自动选，标为需人工确认，`radius_source=MANUAL`
- **怎么回滚**：选错了可以回滚到待确认状态
- **代码位置**：`shared/rules/safetyRadiusRules.ts:20-45`

## 关键约定（绝对不能破）

1. **坐标混合记录绝对不能自动归正常**，必须巡检组人工复核
2. **安全半径差值>5%绝对不能自动选**，必须人工确认哪个更可信
3. **所有人工改动都留痕**：原始值、新值、操作人、时间、原始行号，缺一不可
4. **导出CSV、页面展示、API返回必须读同一份数据**，不能各算各的
5. **三步工作流不能跳步**，每步有前置条件校验

## 数据一致性保证

- 页面展示、API接口、CSV导出，三者调用同一套服务层方法
- 数据修改后自动更新所有相关缓存
- 导出CSV直接调用API获取数据，不做二次计算
- 数据库使用事务保证数据原子性

## 审计追踪（巡检组追问时能回到证据）

每次状态变更都记录：
- 原始行号（从点云日志哪来的）
- 原始值（改之前是什么）
- 新值（改成了什么）
- 操作人（谁改的）
- 时间戳（什么时候改的）
- 备注（为什么改）

回滚时也会生成一条新的审计记录，不会抹掉历史。

## API接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/envelopes` | 获取安全包络列表 |
| GET | `/api/envelopes/:id` | 获取安全包络详情（含坐标点、审计日志） |
| POST | `/api/envelopes/import` | 导入点云抽稀日志 |
| PUT | `/api/envelopes/:id/step` | 推进工作流（下一步） |
| GET | `/api/envelopes/:id/export` | 导出CSV（与页面/接口同一份数据） |
| PUT | `/api/points/:id/confirm` | 确认正常记录 |
| POST | `/api/points/:id/review` | 复核混合记录（4种处理方式） |
| GET | `/api/rules` | 获取边界规则 |
| GET | `/api/safety-radius` | 获取安全半径表 |

## 常见问题

**Q：一条记录既有经纬度特征又有米制特征，系统怎么判？**
A：系统不判，直接标混合，留给巡检组。别嫌麻烦，安全第一。

**Q：点云日志和安全半径表对不上信谁？**
A：差值≤5%信表，>5%人工判断。毕竟设备老化、环境变化都可能影响。

**Q：改错了怎么办？**
A：回滚。每次改动都留痕，能回到任何一个历史状态。

**Q：导出的CSV和页面显示的不一样怎么办？**
A：不会不一样，三者读同一份数据。如果真不一样，那是bug，提给开发。

**Q：能跳步吗？比如直接从第一步到第三步？**
A：不能。系统有前置条件校验，正常记录没确认完不能到第二步，混合记录没复核完不能到第三步。
