# AI 搜索排序申诉系统

处理 AI 搜索排序申诉工单的全流程系统，支持低置信度样本检测、版本对比、审计追踪。

## 核心特性

### 🔍 低置信度样本专项处理
- 自动检测置信度 < 60% 的样本
- 被平均指标盖住的样本特殊标记（橙底高亮 + ⚠️ 标识）
- 低置信度样本默认标记为「待复核」，不自动归为正常
- 知识库编辑可在样本详情中手动复核确认

### ✅ 四大自检机制
1. **重复导入检查**：检测同一工单编号是否重复导入、样本编号是否重复
2. **低置信度盖住检查**：统计被平均指标盖住的样本数量，确保不全部被隐藏
3. **补录重算一致性检查**：验证样本当前排名与最新版本排名一致
4. **导出一致性检查**：确保导出明细、页面展示、接口返回读取同一份数据

### 📝 完整审计追踪
- 保留线上反馈工单原始行号
- 记录每一次人工改动（操作人、变更前、变更后、备注）
- 所有操作留痕，知识库编辑追问时可回到原始证据
- 标注负责人周姐的脱敏规则备注单独存储

### 📊 模型版本对比
- 临时会前 10 分钟快速查看
- 一眼区分：哪条来自线上反馈工单、哪条还等确认
- 排名变化用颜色标识（绿色=变好，红色=变差）
- 低置信度和被盖住样本特殊标记

## 快速开始（新人 5 分钟跑通）

### 1. 安装依赖

```bash
cd ai-search-appeal
pip install -r requirements.txt
```

### 2. 初始化演示数据

```bash
python init_demo.py
```

这会自动创建：
- 1 条线上反馈工单（FEEDBACK-2024-001）
- 10 条样本（其中 4 条低置信度）
- 2 个模型版本（v2024.01.01、v2024.02.01）
- 周姐补看的脱敏规则备注
- 自检报告

### 3. 启动服务

```bash
uvicorn backend.main:app --reload --port 8000
```

### 4. 打开浏览器

访问: http://localhost:8000

## 标准业务流程（三步法）

### 第一步：第一次导入线上反馈工单

1. 点击顶部「导入工单」
2. 填写工单编号（如 `FEEDBACK-2024-002`）
3. 上传 CSV 文件（格式见下方说明）
4. 点击「导入工单」
5. 系统自动：
   - 检测低置信度样本并标记「待复核」
   - 记录原始行号
   - 生成审计日志

### 第二步：标注负责人周姐补看脱敏规则备注

1. 在工单列表点击「查看」进入详情
2. 找到「脱敏规则备注」区域
3. 填写脱敏规则审阅意见
4. 点击「保存备注」
5. 点击「补录重算」触发第一次排名重算
6. 重算时低置信度样本不会自动归为正常，保持「待复核」

### 第三步：模型版本对比更新

1. 点击顶部「版本对比」
2. 选择两个要对比的模型版本
3. 快速查看：
   - 「来自线上反馈工单」标记识别来源
   - 「待复核」标记识别哪些需要知识库编辑确认
   - 被平均指标盖住的样本橙底高亮

## CSV 导入格式

| 列名 | 说明 | 必填 |
|------|------|------|
| sample_no | 样本编号 | 是 |
| query | 查询词 | 是 |
| doc_title | 文档标题 | 是 |
| doc_url | 文档URL | 是 |
| original_rank | 原始排名 | 是 |
| expected_rank | 预期排名（可选） | 否 |
| confidence | 置信度（0-1） | 是 |

示例见: `samples/sample_ticket.csv`

## 页面说明

### 工单列表
- 展示所有申诉工单
- 可按状态筛选
- 快速查看样本数、处理人

### 工单详情
- **工单信息**：原始行号、来源、状态等
- **脱敏规则备注**：周姐填写区域
- **样本列表**：所有样本，低置信度和被盖住的特殊标记
- **自检结果**：四大自检项的通过/失败状态
- **审计追踪**：所有操作记录

### 版本对比
- 两个模型版本的排名对比
- 汇总统计：总样本数、待复核数、来自工单数
- 适合临时会前快速查看

## 常见问题

**Q: 低置信度样本被平均指标盖住后会消失吗？**
A: 不会。系统会用橙底 + ⚠️ 特殊标记，同时在自检报告中提醒，确保不会被遗漏。

**Q: 导出的 Excel 和页面显示的一致吗？**
A: 一致。导出明细、页面展示、接口返回都读取同一份数据库结果，「被平均指标盖住」字段在三个地方都有体现。

**Q: 能看到是谁改了什么吗？**
A: 可以。所有操作都在「审计追踪」里记录，包括操作人、变更前值、变更后值、备注。
