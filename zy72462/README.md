# 🚲 共享单车潮汐调度系统

> 整合网格员巡查表 + 施工告示，让每一条整改建议都有温度。不是给演示会看的空壳，是真的能用的工具。

## ✨ 核心特性

- **证据整合**：把网格员巡查表的「主流程」和施工告示的「现场说法」放到同一个结果里
- **评分无变化不糊弄**：坡道补录后评分没变化时，别急着归正常，自动留给交通协管复核
- **3D/图表也能回头**：选择3D或图表展示时，点到坡道还能回到巡查表或施工告示，不止是漂亮画面
- **有温度的整改建议**：每条建议说明「为什么被留下」「还缺什么材料」「下一步找交通协管还是社区书记周姐」
- **多入口**：命令行 CLI、REST API、网页小看板，怎么顺手怎么来
- **流程闭环**：导入巡查表 → 坡道补录 → 复核 → 补看施工告示 → 整改建议自动更新

## 📖 命令行 CLI 使用说明

### 创建案件
```bash
python cli.py create "XX社区早高峰调度"
```

### 导入网格员巡查表
```bash
# 交互式录入
python cli.py import-inspection <案件ID>

# 或从 JSON 文件导入
python cli.py import-inspection <案件ID> --json samples/inspection.json
```

### 坡道补录
```bash
python cli.py supplement-ramp <案件ID> <坡道ID> \
  --note "现场复核，仍有堆积" \
  --accessible true \
  --bike-parking false
```

**关键细节**：如果补录后评分没变化，系统会自动标记为「转交通协管」，不归为正常。

### 导入施工告示
```bash
python cli.py import-notice <案件ID> \
  --json samples/notice.json \
  --reviewed  # 加上这个参数表示社区书记周姐已审阅
```

**关键细节**：施工告示导入后，整改建议会自动跟着变。

### 交通协管复核
```bash
python cli.py review <案件ID> <坡道ID> --status confirmed
# 可选状态：confirmed（已确认）、needs_supplement（需补材料）、escalated（转交通协管）、pending（待处理）
```

### 生成报告
```bash
# 文本格式（控制台输出）
python cli.py report <案件ID>

# HTML 格式（保存到文件）
python cli.py report <案件ID> --format html --output report.html
```

### 设置展示模式
```bash
python cli.py display <案件ID> --mode 3d
# 可选模式：list（列表）、chart（图表）、3d（3D）
```

**关键细节**：即使设为 3D 或图表模式，点击坡道仍能回到巡查表或施工告示。

### 查看案件详情
```bash
python cli.py list <案件ID>
```

## 🎯 完整业务流程（三步曲）

这是社区书记周姐最关心的流程：

### 第一步：网格员巡查表第一次导入
- 网格员小李巡查，发现东门社区入口坡道共享单车堆积
- 录入系统，生成坡道记录和初步整改建议
- 此时建议：网格员继续收集证据，或联系社区书记

### 第二步：坡道补录 & 复核
- 社区书记周姐现场复核，补录坡道信息
- **如果评分没变化**：系统自动标记「转交通协管」，不糊弄成「已整改」
- 交通协管到现场确认，给出复核意见

### 第三步：社区书记补看施工告示 → 整改建议更新
- 社区书记周姐发现附近有污水管道施工
- 导入施工告示和「现场说法」，标记「书记已审阅」
- **系统自动更新整改建议**：结合施工因素，责任人从网格员变为社区书记，下一步行动也相应调整

## 💡 设计细节（产品经理会看的点）

### 1. 评分无变化 ≠ 已整改
坡道补录后，如果评分变化 ≤ 0.5 分，系统认为「没有实质改善」，自动标记为「转交通协管复核」。

**为什么这样设计？** 避免为了完成指标而糊弄，真实反映问题有没有解决。

### 2. 整改建议的「灵魂三问」
每条整改建议都回答三个问题：
- **为什么被留下**：不是冷冰冰的「不合格」，而是说明背后的原因
- **还缺什么材料**：明确告知下一步要收集什么证据
- **下一步该找谁**：交通协管？社区书记周姐？还是网格员？不甩锅

### 3. 3D/图表模式下的「回头路」
很多系统做了炫酷的3D展示，但点进去就回不到原始数据了。我们不这样：
- 即使在 3D 或图表模式下，点击坡道卡片
- 可以返回查看原始的网格员巡查表或施工告示
- 漂亮画面要有，证据溯源也要有

### 4. 施工告示的「现场说法」
施工告示不只是个公告，它的「现场说法」会直接影响整改建议：
- 没有施工告示时：建议网格员继续收集证据
- 有施工告示但书记没看：还是网格员负责
- 书记审阅了施工告示：建议升级为社区书记协调，结合施工因素给出方案

## 🤝 常见问题

**Q: 数据存在哪里？会丢吗？**
A: 案件数据以 JSON 格式存在 `data/` 目录下，只要不删文件就不会丢。

**Q: 可以对接真实的网格员系统吗？**
A: 可以。核心逻辑都在 `bike_dispatch/core.py`，你只需要写个适配器把外部系统的数据转换成 `GridInspection` 对象就行。

**Q: 我想加微信通知功能？**
A: 在 `core.py` 的 `review_ramp` 或 `supplement_ramp` 函数里加回调就行，架构是松耦合的。
