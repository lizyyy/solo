
**门禁检查点:**
| 阶段 | 检查内容 |
|------|----------|
| 示例校验 | 必须有关联示例、示例已验证、构建成功、测试通过 |

| 审核通过 | 所有发布任务必须完成 |
| 回滚操作 | 必须从已发布 (published) 状态发起 |

## 核心功能

### 数据模型

1. **SDK版本** - 发布的基本信息
   - SDK名称、版本号、语言
   - 变更日志、发布说明
   - 发布状态流转
   - 创建人、创建时间

2. **接口差异** - 接口变更记录
   - 接口名称、变更类型
   - 之前签名、新签名
   - 破坏性变更标记
   - 验证状态

3. **示例项目** - 示例代码项目
   - 项目名称、项目URL
   - 语言
   - 构建状态、测试状态
   - 验证状态

4. **兼容矩阵** - 平台兼容性声明
   - 平台名称
   - 最低版本、最高版本
   - 是否支持
   - 确认状态

5. **发布任务** - 发布前检查清单
   - 任务名称、类型
   - 负责人、优先级
   - 完成状态
   - 依赖任务

6. **状态历史** - 状态变更记录
   - 从状态、到状态
   - 操作人、时间
   - 变更原因
   - 之前数据快照

7. **回滚说明** - 发布回滚记录
   - 回滚原因
   - 回滚到版本
   - 影响组件
   - 解决方案

8. **脏数据标记** - 数据异常处理
   - 脏数据标记
   - 原因说明
   - 清理机制

### 发布状态流转

```
草稿 (draft)
  ↓
待审核 (pending_review)
  ↓
文档同步 (docs_synced)
  ↓
示例校验 (examples_verified)
  ↓
兼容确认 (compatibility_confirmed)
  ↓
审核通过 (approved)
  ↓
已发布 (published)
  ↓
已回滚 (rolled_back)
```

### 业务规则引擎

1. **版本门禁**
   - 版本号唯一性检查
   - 必填字段验证
   - 变更日志建议

2. **示例校验**
   - 示例项目关联检查
   - 构建状态验证
   - 测试状态验证
   - 人工验证确认

3. **兼容声明**
   - 兼容矩阵必填
   - 所有平台必须确认
   - 不支持平台需说明

4. **任务勾稽**
   - 所有任务必须完成
   - 依赖任务按顺序完成
   - 负责人确认机制

5. **发布记录**
   - 状态变更历史完整记录
   - 操作人、时间、原因
   - 数据快照用于审计

## 关键特性操作路径

### 1. 脏数据处理

#### 标记为脏数据

**操作路径:**
1. 调用 API: `POST /api/v1/sdk-versions/{sdk_id}/mark-dirty?reason=原因`
2. 在列表页可看到红色脉冲指示器
3. 详情页显示警告横幅

**场景:**
- 数据同步异常
- 校验发现不一致
- 人工标记需要关注

#### 清理脏数据

**操作路径:**
1. 在列表页点击"清理"按钮
2. 或在详情页点击"标记为已清理"按钮
3. 确认后脏标记移除

**API:** `POST /api/v1/sdk-versions/{sdk_id}/clean-dirty`

### 2. 防重复请求（幂等性）

**操作路径:**
1. 创建发布时自动生成幂等键 (`idempotency_key`)
2. 或客户端自定义幂等键
3. 使用相同幂等键重复调用将返回第一次创建的结果

**示例:**
```javascript
const data = {
  sdk_name: "MySDK",
  version: "1.0.0",
  idempotency_key: "my-unique-key-" + Date.now()
  // ...其他字段
};
fetch('/api/v1/sdk-versions', {
  method: 'POST',
  body: JSON.stringify(data)
});
```

**机制:**
- 后端基于 `request_idempotency_key` 字段去重
- 重复请求返回已存在的记录，不创建新记录

### 3. 补偿动作

#### 创建补偿动作

**操作路径:**
1. 调用 API: `POST /api/v1/sdk-versions/{sdk_id}/compensation-actions?executed_by=姓名`
2. 请求体: `{ "action_type": "类型", "description": "描述" }`

#### 执行补偿动作

**操作路径:**
1. 调用 API: `POST /api/v1/compensation-actions/{action_id}/execute`
2. 系统执行补偿逻辑
3. 自动清理相关脏数据标记

**补偿类型:**
- 数据同步重试
- 状态回滚
- 手动修复标记

### 4. 发布回滚

**操作路径:**
1. 在详情页点击"回滚"按钮
2. 输入回滚原因
3. 输入目标版本（可选）
4. 输入操作人姓名
5. 确认后状态变为"已回滚"

**API:**
```
POST /api/v1/sdk-versions/{sdk_id}/rollback?executed_by=姓名
Body: {
  "reason": "回滚原因",
  "rollback_version": "0.9.0",
  "affected_components": ["api1", "api2"],
  "resolution_plan": "解决方案"
}
```

### 5. 状态推进与验证

**操作路径:**
1. 在详情页选择目标状态
2. 点击"验证并推进"按钮
3. 系统执行验证规则
   - 显示错误信息（阻止推进）
   - 显示警告信息（仅提示）
4. 验证通过后点击"确认推进"
5. 输入操作人姓名和原因
6. 状态更新并记录历史

**验证层级:**
- **草稿 → 待审核**: 基本字段检查
- **待审核 → 文档同步**: 变更日志检查
- **文档同步 → 示例校验**: 示例项目验证
- **示例校验 → 兼容确认**: 兼容矩阵验证
- **兼容确认 → 审核通过**: 发布任务验证
- **审核通过 → 已发布**: 最终确认

### 6. 前后变化对比

**操作路径:**
1. 进入SDK详情页
2. 点击"变化对比"标签
3. 查看最近两次状态变更对比
4. 查看验证项完成进度统计

**对比内容:**
- 状态变化时间线
- 操作人对比
- 变更原因记录
- 验证项完成率统计

### 7. 导出发布记录

**操作路径:**
1. 在详情页点击"导出"按钮
2. 自动下载 JSON 格式文件
3. 文件包含完整发布信息

**API:** `GET /api/v1/sdk-versions/{sdk_id}/export`

## 数据验证规则

### 验证错误（阻止状态推进）

- 版本号已存在
- 版本号为空
- 兼容矩阵为空
- 兼容矩阵项未确认
- 发布任务未完成
- 依赖任务未完成

### 验证警告（仅提示，不阻止）

- 变更日志为空
- 无关联示例项目
- 示例项目未验证
- 示例项目构建失败
- 示例项目测试失败

## 使用场景示例

### 场景1: 正常发布流程

1. **创建发布**: 填写 SDK 基本信息、接口差异、示例项目、兼容矩阵、发布任务
2. **同步文档**: 确认文档已更新，推进到"文档同步"状态
3. **验证示例**: 构建并测试示例项目，确认无误后推进到"示例校验"
4. **确认兼容**: 验证各平台兼容性，推进到"兼容确认"
5. **完成任务**: 完成所有发布检查任务，推进到"审核通过"
6. **正式发布**: 最后确认，推进到"已发布"状态
7. **导出记录**: 导出完整发布记录存档

### 场景2: 发现问题需要回滚

1. 发布后发现严重问题
2. 在详情页点击"回滚"
3. 填写回滚原因和目标版本
4. 确认后状态变为"已回滚"
5. 创建补偿动作进行修复
6. 执行补偿动作后清理脏数据

### 场景3: 数据同步异常处理

1. 监控发现数据不一致
2. 调用 API 标记为脏数据，填写原因
3. 相关人员收到通知（需自行集成通知系统）
4. 定位问题并修复
5. 创建补偿动作记录修复措施
6. 执行补偿动作
7. 清理脏数据标记
8. 继续正常发布流程

## 注意事项

1. 幂等键建议使用有意义的业务标识，如 `{sdk_name}-{version}-{timestamp}`
2. 脏数据标记仅为指示器，不影响正常操作，需人工判断处理
3. 补偿动作目前为记录性质，可根据需要扩展实际执行逻辑
4. 状态历史记录不可删除，确保审计追踪完整性
5. 所有验证规则可在 `services.py` 的 `ReleaseValidationService` 中调整
