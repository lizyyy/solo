# 离线凭证验签沙盒

一个专为公益活动签到组设计的本地浏览器工具，用于离线环境下的凭证验签和入场管理。

## 功能特性

### 核心功能
- **离线验签**：使用 WebCrypto API 在本地完成签名验证，无需网络
- **多格式支持**：导入凭证 JSON/CSV、公钥包和吊销名单
- **扫码/手输**：支持扫码枪或手动输入凭证信息
- **六项校验**：签名、有效期、场次、票种、吊销状态、重复使用
- **本地存储**：入场流水持久化保存，刷新不丢失
- **批量复核**：支持离线批量验证所有导入的凭证
- **异常隔离**：将异常凭证单独隔离，便于人工处理
- **数据导出**：导出 Markdown 复盘报告和 CSV 流水数据

### 安全特性
- **防伪造**：通过非对称加密签名验证凭证真实性
- **防重复**：记录已使用凭证，防止重复入场
- **防旧码**：支持密钥轮换，使用旧密钥签名的凭证被拒绝
- **防篡改**：签名验证确保凭证数据未被篡改

## 模块说明

### 1. 加密适配模块 (`crypto.js`)

负责所有加密相关操作，使用浏览器原生 WebCrypto API。

**主要功能：**
- 公钥导入（支持 PEM、JWK、SPKI 格式）
- 签名验证（支持 RS256、ES256 等算法）
- JWT 格式凭证验证
- SHA-256 哈希计算
- 随机凭证ID生成

**支持的算法：**
- RSA: RS256, RS384, RS512, PS256
- ECDSA: ES256, ES384, ES512

### 2. 数据模型模块 (`models.js`)

定义所有数据结构和解析逻辑。

**数据模型：**
- `Credential`: 凭证信息（ID、票种、场次、有效期、签名等）
- `PublicKey`: 公钥信息（ID、密钥、算法、激活状态）
- `Revocation`: 吊销记录（凭证ID、原因、时间）
- `EntryRecord`: 入场记录（凭证ID、是否允许、时间等）
- `VerificationResult`: 验证结果（包含所有检查项）

**枚举类型：**
- `CREDENTIAL_STATUS`: 凭证状态（未验证、有效、无效、已吊销、已过期、重复、已隔离、签名无效）
- `TICKET_TYPE`: 票种类型（成人票、儿童票、VIP票、团体票、员工票）
- `VERIFICATION_STATUS`: 验证状态（成功、失败、警告、待复核）

**解析功能：**
- CSV 格式解析（支持凭证、吊销名单）
- JSON 格式解析
- JWT 格式解析

### 3. 校验规则模块 (`rules.js`)

实现六项核心校验规则，可独立调用或组合使用。

**校验规则：**

| 规则名称 | 优先级 | 说明 |
|---------|-------|------|
| `signatureRule` | 1 | 签名验证，确保凭证未被伪造或篡改 |
| `expirationRule` | 2 | 有效期校验，检查凭证是否在有效时间内 |
| `sessionRule` | 3 | 场次校验，检查凭证场次是否匹配当前场次 |
| `ticketTypeRule` | 4 | 票种校验，检查票种是否在允许范围内 |
| `revocationRule` | 5 | 吊销检查，检查凭证是否在吊销名单中 |
| `duplicateRule` | 6 | 重复检查，检查凭证是否已使用过 |

**验证流程：**
```
1. 解析凭证数据
2. 查找对应的公钥
3. 验证签名（防止伪造）
4. 检查有效期（防止过期）
5. 检查场次（防止错场）
6. 检查票种（防止错票）
7. 检查吊销名单（防止已退票）
8. 检查重复使用（防止一码多用）
9. 保存入场记录
10. 显示验证结果
```

### 4. 状态存储模块 (`storage.js`)

使用 IndexedDB 进行持久化存储，支持 LocalStorage 作为备用方案。

**对象仓库：**
- `credentials`: 导入的凭证数据
- `publicKeys`: 导入的公钥数据
- `revocations`: 吊销名单
- `entryRecords`: 入场流水记录
- `isolated`: 隔离区的异常凭证
- `settings`: 应用设置

**存储特性：**
- 完全离线使用
- 刷新页面数据不丢失
- 支持批量操作
- 支持索引查询

### 5. 界面模块 (`app.js`)

连接所有核心模块，处理用户交互。

**功能区域：**
1. **数据导入**：公钥包、凭证、吊销名单导入
2. **凭证验签**：扫码/手输入验签，实时显示结果
3. **批量复核**：批量验证所有凭证，异常隔离
4. **入场流水**：查看所有验签记录，支持过滤搜索
5. **导出复盘**：导出 Markdown 报告和 CSV 流水

### 6. 测试模块 (`tests.js`)

包含各核心模块的单元测试。

**测试覆盖：**
- 数据模型创建和验证
- 加密功能可用性
- 校验规则正确性
- 存储功能测试

**运行测试：**
在浏览器控制台执行：
```javascript
TestSuite.runAllTests()
```

## 使用指南

### 快速开始

1. **打开应用**：直接在浏览器中打开 `index.html` 文件

2. **准备数据**（主办方提前准备）：
   - 公钥包（包含验证签名用的公钥）
   - 凭证列表（JSON 或 CSV 格式）
   - 吊销名单（可选，已退票/作废的凭证）

3. **导入数据**：
   - 切换到「数据导入」标签页
   - 依次导入公钥包、凭证、吊销名单
   - 或点击「加载示例数据」快速体验

4. **验签流程**：
   - 切换到「凭证验签」标签页
   - 用扫码枪扫描凭证二维码，或手动输入凭证信息
   - 查看验证结果：
     - 🟢 绿色：验证通过，允许入场
     - 🔴 红色：验证失败，拒绝入场
     - 🟡 黄色：存在警告，需人工判断

5. **批量复核**：
   - 切换到「批量复核」标签页
   - 点击「批量验证所有凭证」
   - 查看统计结果，异常凭证可隔离

6. **导出数据**：
   - 切换到「导出复盘」标签页
   - 选择导出类型：Markdown 复盘报告 或 CSV 流水
   - 点击下载按钮

### 凭证格式说明

#### JSON 格式凭证
```json
{
  "id": "CRED-2024-001",
  "ticketType": "vip",
  "session": "morning",
  "validFrom": 1704067200000,
  "validTo": 1704153600000,
  "payload": {
    "name": "张三",
    "phone": "138****1234"
  },
  "signature": "base64_encoded_signature",
  "algorithm": "RS256",
  "keyId": "main-key-2024"
}
```

#### CSV 格式凭证
```csv
id,ticketType,session,validFrom,validTo,signature,algorithm,keyId
CRED-2024-001,vip,morning,1704067200000,1704153600000,abc123,RS256,main-key-2024
CRED-2024-002,adult,afternoon,1704067200000,1704153600000,def456,RS256,main-key-2024
```

#### JWT 格式凭证
JWT（JSON Web Token）格式的凭证会自动解析，标准格式为：
```
eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9.eyJpZCI6IkNSRUQtMjAyNC0wMDEiLCJ0aWNrZXRUeXBlIjoidmlwIiwiaWF0IjoxNzA0MDY3MjAwLCJleHAiOjE3MDQxNTM2MDB9.SignatureHere
```

### 公钥包格式

#### JSON 格式公钥包
```json
{
  "keys": [
    {
      "id": "main-key-2024",
      "algorithm": "RS256",
      "format": "pem",
      "key": "-----BEGIN PUBLIC KEY-----\nMIIBIjANBgkqhkiG9w0BAQEFAAO...\n-----END PUBLIC KEY-----",
      "isActive": true,
      "validFrom": 1704067200000,
      "validTo": 1735689600000
    }
  ]
}
```

#### PEM 格式公钥
也可以直接导入 PEM 格式的公钥文件：
```
-----BEGIN PUBLIC KEY-----
MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA...
-----END PUBLIC KEY-----
```

### 吊销名单格式

#### JSON 格式
```json
[
  {
    "credentialId": "CRED-2024-005",
    "reason": "已退票",
    "revokedAt": 1704067200000,
    "revokedBy": "admin"
  }
]
```

#### CSV 格式
```csv
credentialId,reason,revokedBy
CRED-2024-005,已退票,admin
CRED-2024-010,信息错误,system
```

## 验证流程详解

### 完整验签流程

```
┌─────────────────────────────────────────────────────────────┐
│                      验签流程                                 │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 输入凭证（扫码/手动输入）                                │
│         ↓                                                   │
│  2. 解析凭证数据                                             │
│     - 检测格式：JSON / CSV / JWT                            │
│     - 提取关键信息：ID、签名、算法、密钥ID                   │
│         ↓                                                   │
│  3. 查找公钥                                                 │
│     - 根据 keyId 查找对应的公钥                              │
│     - 如果未指定 keyId，尝试所有激活的公钥                   │
│         ↓                                                   │
│  4. 签名验证（最高优先级）                                    │
│     - 使用公钥验证签名是否有效                                │
│     - 失败 → 签名无效，可能是伪造票                           │
│         ↓                                                   │
│  5. 有效期校验                                               │
│     - 检查当前时间是否在 [validFrom, validTo] 范围内         │
│     - 失败 → 凭证已过期或尚未生效                             │
│         ↓                                                   │
│  6. 场次校验                                                 │
│     - 检查凭证场次是否匹配当前允许的场次                       │
│     - 失败 → 场次不匹配（如上午场的票下午来）                 │
│         ↓                                                   │
│  7. 票种校验                                                 │
│     - 检查票种是否在允许范围内                                │
│     - 失败 → 票种不匹配（如儿童票当作成人票）                 │
│         ↓                                                   │
│  8. 吊销检查                                                 │
│     - 检查凭证ID是否在吊销名单中                              │
│     - 失败 → 凭证已被吊销（如已退票）                         │
│         ↓                                                   │
│  9. 重复使用检查                                             │
│     - 检查凭证是否已在本场次使用过                            │
│     - 失败 → 重复入场                                         │
│         ↓                                                   │
│  10. 保存入场记录                                            │
│     - 记录凭证ID、时间、结果、操作员                          │
│         ↓                                                   │
│  11. 显示验证结果                                            │
│     - 全部通过 → 🟢 验证通过                                  │
│     - 存在错误 → 🔴 拒绝入场（显示具体原因）                   │
│     - 存在警告 → 🟡 需人工判断                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 异常情况处理

| 异常类型 | 处理方式 | 说明 |
|---------|---------|------|
| 签名无效 | 🔴 拒绝 | 可能是伪造凭证，需仔细核对 |
| 已过期 | 🔴 拒绝 | 凭证已过有效期 |
| 未生效 | 🔴 拒绝 | 凭证尚未到生效时间 |
| 场次不匹配 | 🔴 拒绝 | 当前场次不允许使用该凭证 |
| 票种不匹配 | 🔴 拒绝 | 该票种不允许入场 |
| 已吊销 | 🔴 拒绝 | 凭证已作废（如退票） |
| 重复入场 | 🔴 拒绝 | 该凭证已使用过 |
| 公钥过期 | 🟡 警告 | 密钥已轮换，可能是旧凭证 |
| 无对应公钥 | 🟡 警告 | 找不到验证用的公钥 |
| 格式错误 | 🟡 警告 | 凭证格式无法解析 |

### 密钥轮换机制

为了安全起见，主办方可能会定期更换签名密钥。系统支持密钥轮换：

1. **新密钥导入**：导入新的公钥，标记为激活状态
2. **旧密钥保留**：旧公钥保留，但标记为非激活或设置有效期
3. **自动选择**：验证时优先使用激活状态的公钥
4. **旧码处理**：使用旧密钥签名的凭证会显示警告，需人工判断

**公钥有效期设置：**
```json
{
  "id": "old-key-2023",
  "isActive": false,
  "validFrom": 1672531200000,
  "validTo": 1704067200000
}
```

## 离线使用说明

### 完全离线工作流程

1. **活动前准备**（有网络时）：
   - 主办方生成所有凭证和密钥对
   - 导出公钥包、凭证列表、吊销名单
   - 将 `index.html` 和相关文件复制到签到电脑
   - 测试所有功能正常工作

2. **活动现场**（无网络时）：
   - 打开 `index.html`
   - 导入提前准备好的数据文件
   - 开始验签工作
   - 所有数据保存在本地浏览器中

3. **活动结束后**：
   - 导出入场流水和复盘报告
   - 清空本地数据（保护隐私）

### 数据安全

- **本地存储**：所有数据仅保存在当前浏览器的 IndexedDB 中
- **不上传**：没有任何网络请求，数据不会离开本地
- **可清除**：随时可以通过「清空所有数据」按钮删除所有数据
- **隐私保护**：敏感信息建议在凭证中使用脱敏处理（如手机号 `138****1234`）

### 注意事项

1. **HTTPS 要求**：Web Crypto API 在部分浏览器中需要 HTTPS 环境
   - 本地文件（`file://` 协议）通常可以正常工作
   - 如果通过 HTTP 访问，可能需要使用 `localhost`

2. **隐私模式**：在隐私浏览模式下，IndexedDB 数据可能在关闭后清除

3. **存储限制**：浏览器对 IndexedDB 有存储限制，通常为 50MB+，足够存储数万条记录

## 常见问题

### Q1: 为什么提示"无法验证签名"？

可能的原因：
1. 未导入公钥包 → 请先在「数据导入」中导入公钥
2. 凭证使用的密钥ID与导入的公钥不匹配 → 检查密钥配置
3. 凭证被篡改 → 签名验证失败，可能是伪造凭证
4. 公钥已过期 → 密钥已轮换，使用了旧凭证

### Q2: 数据保存在哪里？刷新页面会丢失吗？

数据保存在浏览器的 IndexedDB 数据库中：
- 刷新页面：不会丢失
- 关闭浏览器：不会丢失
- 清除浏览器数据：会丢失
- 不同浏览器：不共享数据

建议活动结束后立即导出数据备份。

### Q3: 支持多少人同时签到？

本工具是单用户本地工具，设计用于单个签到点使用。

如果需要多个签到点：
1. 每个签到点使用独立的电脑
2. 提前将相同的基础数据导入所有电脑
3. 活动结束后汇总各点的流水数据

### Q4: 如何生成签名的凭证？

主办方需要使用私钥对凭证进行签名。本工具只包含验签功能（使用公钥），不包含签名功能（需要私钥）。

**签名流程（主办方）：**
1. 生成 RSA 或 ECDSA 密钥对
2. 使用私钥对凭证数据进行签名
3. 将公钥分发给签到组
4. 私钥由主办方安全保管，不对外公开

**示例签名代码（Node.js）：**
```javascript
const crypto = require('crypto');

function signCredential(credentialData, privateKey) {
    const sign = crypto.createSign('RSA-SHA256');
    sign.update(JSON.stringify(credentialData));
    return sign.sign(privateKey, 'base64');
}
```

### Q5: 凭证格式有什么要求？

系统支持多种凭证格式，核心要求：
- 必须包含唯一标识（`id` 字段）
- 如果需要签名验证，必须包含 `signature` 字段
- 有效期建议使用 `validFrom` 和 `validTo` 字段（Unix 时间戳）

可以通过「数据导入」→「加载示例数据」查看完整示例。

### Q6: 如何测试系统功能？

2. **运行单元测试**：
