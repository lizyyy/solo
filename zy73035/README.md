# 🐾 流浪动物救助记录复核 · 交班小工具

> 宠物医院前台专用 · 不用再翻疫苗本照片 · 不用再翻聊天记录 · 每次交班都对得上

---

## 👩‍💼 小温操作流程（按顺序跑）

### 第 1 步：安装（只做一次）

打开终端，进入本文件夹，执行：

```bash
npm install
```

等它装完就行。

---

### 第 2 步：初始化数据库（只做一次，或者想清空重来时做）

```bash
npm run init
```

会生成一个干净的数据库在 `data/review.db`。

---

### 第 3 步：加载示例材料（试跑用，正式用可以跳过）

```bash
npm run seed
```

这一步会往数据库里塞**一包像现场会收到的材料**，包括：
- 8 条流浪动物救助记录
- 故意留的脏数据（别名重复、疫苗照片缺失、物种缺失等）
- 1 条人工改判（带完整的改判原因，让接手人看到怎么追溯）
- 同一份材料的 2 次跑批（run1 和 run2），演示补备注后重跑怎么对比

---

### 第 4 步：启动系统（每次用都跑这条）

```bash
npm start
```

终端会显示：

```
🐾 流浪动物救助记录复核系统已启动
📍 前台界面: http://localhost:3000
```

**用浏览器打开这个地址** 就可以开始干活了。

---

### 第 5 步：交班给同事时，打开「历史时间线」讲

在前端顶部的 6 个标签页里，按这个顺序看：

| 标签页 | 用来干嘛 | 交班重点 |
|---|---|---|
| 📦 **批次管理** | 看所有复核批次 | 先告诉接手人今天跑了哪些批次 |
| 📋 **复核记录** | 改备注、改状态、加记录 | **改了备注/结论后，导出CSV会自动同步，不用手动转** |
| ⚠️ **脏数据** | 哪里数据有问题 | 不是只给一个总数，**每条问题都指向具体的宠物和字段**，还能一键跳转修 |
| 🕓 **历史时间线** | 所有变更流水账 | **人工改判前后、备注改了什么、谁改的、为什么改**，都在这里，彩排进场前照着念就行 |
| 🔍 **批次对比** | 同批次 run1 vs run2 | 补备注后重跑，差异一条条列出来，保证前后对得上 |
| 📤 **导出文件** | 看导出过哪些CSV | 3份CSV：记录、脏数据、变更历史 |

---

## 🔧 不用开浏览器的命令行版（赶时间用）

| 命令 | 作用 |
|---|---|
| `npm run check` | 交互式选批次，终端里直接看脏数据检测结果 |
| `npm run export` | 交互式选批次，导出 3 份 CSV 到 `exports/` 文件夹 |
| `npm run rerun` | 交互式选批次组，**补跑下一轮（继承上轮数据，run_number+1）** |

## ❓ 常见场景

### 场景 1：接手同事改了一条备注，导出会不会变？

> **会同步变。** 前端改完保存 → 后端数据库立刻更新 → 点"导出此批次"就是最新内容。
> 而且「历史时间线」里会留下：原来备注是什么、改成了什么、谁改的、什么时候改的。

### 场景 2：一条人工改判，接手人怎么知道为什么变了？

> 前端点记录右边的 **"改判"** 按钮，必须填 **"改判原因"** 才能保存，空了不让提交。
> 然后去「历史时间线」选这只宠物，就能看到：
> - 改判前的结论
> - 改判后的最终结论
> - 改判原因（比如"医院系统编号XXX，张医生核实"）
> - 操作人、时间

### 场景 3：同一批材料先跑一次，补完备注再跑一次，怎么对得上？

> 重跑用：
> - 前端：「批次管理」→ 新建批次，**批次名跟上一次填一样的**，系统会自动把 run_number + 1，并且继承上轮所有数据
> - 命令行：`npm run rerun`
>
> 然后去「批次对比」标签页，选 run2，系统会一条条列出：
> - 哪只宠物改了什么字段（备注/状态/最终结论...）
> - run1 的值 → run2 的值
>
> 两次导出的 CSV 文件名里都带 run1 / run2 后缀，绝对对得上。

### 场景 4：脏数据检测，会不会只告诉我有 7 条问题？

> **不会。** 每条问题都会具体说：
> ```
> 🔴 错误 · 别名重复
>   宠物名称"小黄"（别名：小黄豆）出现 2 条重复记录，ID: 1, 2
>
> 🟡 警告 · 疫苗照片缺失
>   #3 咪咪：没关联疫苗照片，异常照片散落在聊天里？
> ```
>
> 脏数据按**类型分组**展示，每组显示数量，每条有严重程度标色（红/黄/蓝），还能**点击跳转直接编辑那条记录**。

### 场景 5：怎么交班最快？

> 打开「历史时间线」→ 不选宠物（默认显示全部变更）→ 接手人就能看到：
> - 每只宠物什么时候创建的
> - 谁改了什么字段
> - 改判的来龙去脉
>
> 再切到「批次对比」→ 看补跑差异 → 切「导出文件」→ 把3份CSV发群里，搞定。

## 📁 文件夹结构

```
├── server.js              ← 后端（API + 脏数据检测 + 导出）
├── package.json           ← 脚本命令配置
├── scripts/
│   ├── init-db.js         ← 建数据库（npm run init）
│   ├── seed-sample.js     ← 塞示例材料（npm run seed）
│   ├── check-dirty.js     ← 命令行测脏数据（npm run check）
│   ├── export-csv.js      ← 命令行导出（npm run export）
│   └── rerun-batch.js     ← 命令行补跑（npm run rerun）
├── public/
│   └── index.html         ← 前端界面（所有标签页都在这里）
├── data/
│   └── review.db          ← SQLite 数据库（init 之后才出现）
└── exports/               ← 导出的 CSV 都在这
```

---

## 🚫 注意事项

1. **改判原因必填**：人工改判不填原因不让保存，就是为了交班时讲得清楚
2. **批次名相同才能重跑**：补跑时批次名必须跟上一轮完全一样，系统才会继承
3. **导出的3份CSV**：文件名带批次名+run编号+时间戳，不会覆盖
4. **数据库位置**：`data/review.db`，要备份就把这个文件拷走
