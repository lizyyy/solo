# 电商赠品库存锁定 API - 验收文档

## 一、项目概述

本文档描述了电商大促赠品库存锁定 API 的功能设计、接口规范、测试场景和验收标准。

### 核心边界
- **赠品库存锁定**：按活动、SKU 维度
- **用户资格锁定**：按用户资质（等级、订单金额等）
- **订单释放**：取消订单后库存归还（高风险环节）

---

## 二、API 接口规范

### 基础信息
- 服务端口：`3000`
- 基础路径：`/api/gifts`

### 1. 锁定赠品库存

**POST /api/gifts/lock**

#### 请求体
```json
{
  "activityId": "default",
  "giftId": "GIFT001",
  "userId": "USER001",
  "orderId": "ORDER_001",
  "orderAmount": 600
}
```

#### 校验顺序
1. 字段完整性检查
2. 活动有效性（存在、状态、时间范围）
3. 赠品有效性（存在、属于活动）
4. 用户资格（等级、订单金额、是否已领取）
5. 库存可用性
6. 防重复提交

#### 响应结构
```json
{
  "success": true,
  "resultType": "NORMAL",
  "actionRequired": "NONE",
  "errorCode": "SUCCESS",
  "lockRecordId": "LOCK_XXXXXXXX",
  "state": "LOCKED",
  "message": "赠品库存锁定成功",
  "details": {
    "activity": { "id": "...", "name": "..." },
    "gift": { "id": "...", "sku": "...", "name": "..." },
    "qualification": { "qualified": true, "checks": {...} },
    "inventory": { "available": 99, "locked": 1, "total": 100 }
  }
}
```

---

### 2. 释放赠品库存

**POST /api/gifts/release**

#### 请求体
```json
{
  "lockRecordId": "LOCK_XXXXXXXX",
  "reason": "用户取消订单"
}
```

#### 状态流转规则
```
LOCKED ──正常释放──> RELEASED
LOCKED ──重复释放──> [失败: ALREADY_RELEASED]
LOCKED ──库存不一致──> MANUAL_CORRECTION_NEEDED
MANUAL_CORRECTION_NEEDED ──任何释放──> [失败: NEEDS_MANUAL_CORRECTION]
RELEASED ──任何释放──> [失败: ALREADY_RELEASED]
```

---

### 3. 人工修正

**POST /api/gifts/manual-correct**

#### 请求体
```json
{
  "lockRecordId": "LOCK_XXXXXXXX",
  "correctionType": "FORCE_RELEASE",
  "operatorId": "ADMIN_001",
  "correctionReason": "库存数据不一致"
}
```

#### 支持的修正类型
| 类型 | 说明 | 适用场景 |
|------|------|----------|
| `FORCE_RELEASE` | 强制释放，同时调整库存 | 库存不一致、订单异常取消 |
| `RESET_TO_LOCKED` | 重置为锁定状态 | 误释放需要回滚 |
| `MARK_RESOLVED` | 标记已解决，不调整库存 | 已人工核对无需改数据 |

---

### 4. 查询锁定状态

**GET /api/gifts/status/:lockRecordId**

#### 响应关键字段
```json
{
  "found": true,
  "lockRecordId": "LOCK_XXXXXXXX",
  "state": "LOCKED",
  "needsManualCorrection": false,
  "currentInventory": { "available": 99, "locked": 1, "total": 100 }
}
```

---

### 5. 验证用户资格

**POST /api/gifts/verify-qualification**

#### 用途
用于在锁定前预校验资格，或核对资格校验是否与原始数据对得上。

#### 响应包含
- 活动规则快照
- 用户资格原始数据
- 资格判定结果
- 可与原始数据逐项对比

## 三、验收输出标志说明

### 响应字段解读

#### `resultType` - 结果类型
| 值 | 含义 | 验收判断 | 人工处理需求 |
|----|------|----------|--------------|
| `NORMAL` | 正常处理 | ✅ 通过 | 无需处理 |
| `FAILURE` | 处理失败 | ❌ 失败 | 需查看 `actionRequired` |
| `CORRECTED` | 人工修正成功 | 🔧 已修正 | 原问题已解决 |

#### `actionRequired` - 需要的动作
| 值 | 含义 | 处理方式 |
|----|------|----------|
| `NONE` | 无需处理 | 流程结束 |
| `FIX_REQUEST` | 修复请求 | 补充缺失字段、修正参数 |
| `CHECK_ACTIVITY` | 检查活动 | 确认活动状态和时间 |
| `CHECK_GIFT` | 检查赠品 | 确认赠品SKU和活动关联 |
| `CHECK_QUALIFICATION` | 检查资格 | 核对用户等级、订单金额 |
| `CHECK_INVENTORY` | 检查库存 | 确认库存数量 |
| `CHECK_DUPLICATE` | 检查重复 | 确认是否已锁定过 |
| `CHECK_STATE` | 检查状态 | 确认状态流转合法性 |
| `MANUAL_VERIFICATION` | 人工核对 | 核对库存和订单状态 |
| `MANUAL_CORRECTION` | **需要人工修正** | **使用人工修正接口** |
| `RETRY_OPERATION` | 重试操作 | 修正后重新执行原操作 |

#### `errorCode` - 错误码
| 错误码 | 触发条件 | 解决方式 |
|--------|----------|----------|
| `MISSING_FIELDS` | 缺少必要字段 | 补充 `missingFields` 列出的字段 |
| `ACTIVITY_NOT_FOUND` | 活动不存在 | 检查 `activityId` |
| `ACTIVITY_INACTIVE` | 活动未开始/已结束 | 检查活动时间和状态 |
| `GIFT_NOT_FOUND` | 赠品不存在或不属于活动 | 检查 `giftId` |
| `USER_NOT_QUALIFIED` | 用户资格不符 | 查看 `details` 中的具体原因 |
| `INSUFFICIENT_INVENTORY` | 库存不足 | 等待补货或选择其他赠品 |
| `DUPLICATE_SUBMISSION` | 重复提交 | 查看 `existingRelation` 中的已有记录 |
| `LOCK_NOT_FOUND` | 锁定记录不存在 | 检查 `lockRecordId` |
| `INVALID_STATE_TRANSITION` | 非法状态流转 | 确认当前状态是否允许该操作 |
| `ALREADY_RELEASED` | 已释放（重复释放） | **人工核对**库存是否被正确归还 |
| `NEEDS_MANUAL_CORRECTION` | **需要人工处理** | **使用人工修正接口** |
| `RELEASE_FAILED` | 释放失败 | 检查库存数据，可能需要人工介入 |

## 四、测试场景说明

运行 `npm test` 可执行以下所有场景：

### 场景 1：正常流程：锁定-释放
**目的**：验证核心功能正常工作

**执行步骤**：
1. 用户资格预校验 → ✅ NORMAL
2. 锁定赠品库存 → ✅ NORMAL
3. 查询锁定状态 → ✅ NORMAL（状态：LOCKED）
4. 取消订单，释放赠品 → ✅ NORMAL
5. 验证释放后状态 → ✅ NORMAL（状态：RELEASED）

**验收通过标准**：
- 所有步骤返回 `resultType: "NORMAL"`
- 锁定后 `inventory.locked` 增加，`inventory.available` 减少
- 释放后 `inventory.locked` 减少，`inventory.available` 增加

---

### 场景 2：缺字段场景
**目的**：验证参数校验完整性

**测试用例**：
1. 缺少 `activityId` → ❌ FAILURE (`MISSING_FIELDS`)
2. 缺少 `giftId` 和 `userId` → ❌ FAILURE (`MISSING_FIELDS`)
3. 释放时缺少 `lockRecordId` → ❌ FAILURE (`MISSING_FIELDS`)

**验收通过标准**：
- 响应 `resultType: "FAILURE"`
- `missingFields` 列出实际缺失的字段名
- `actionRequired: "FIX_REQUEST"`

---

### 场景 3：重复提交场景
**目的**：验证防重机制

**执行步骤**：
1. 首次锁定 → ✅ NORMAL
2. 使用相同订单号再次锁定 → ❌ FAILURE (`DUPLICATE_SUBMISSION`)

**验收通过标准**：
- 第二次提交返回 `errorCode: "DUPLICATE_SUBMISSION"`
- `existingRelation` 包含首次锁定的记录信息
- 库存数量不变（不会重复锁定）

---

### 场景 4：用户资格校验场景
**目的**：验证资格校验与原始数据对得上

**测试用例**：
1. 非VIP用户（USER002）→ ❌ FAILURE (`USER_NOT_QUALIFIED`)
   - 原始数据：`userLevel: "NORMAL"`
   - 要求：`requiredLevel: "VIP"`
2. 订单金额400元（门槛500元）→ ❌ FAILURE (`USER_NOT_QUALIFIED`)
   - 原始数据：`orderAmount: 400`
   - 要求：`minOrderAmount: 500`
3. 资格校验输出与原始数据对比 → ✅ NORMAL

**验收通过标准**：
- 失败时 `details` 包含 `requiredLevel`、`actualLevel` 等对比信息
- `details.checks` 显示各项校验的布尔结果
- 验证接口返回的规则与活动原始数据一致

---

### 场景 5：非法流转场景
**目的**：验证状态机正确性（订单释放环节高风险）

**执行步骤**：
1. 先锁定 → ✅ NORMAL
2. 第一次释放 → ✅ NORMAL
3. 重复释放已释放记录 → ❌ FAILURE (`ALREADY_RELEASED`)
4. 释放不存在的记录 → ❌ FAILURE (`LOCK_NOT_FOUND`)

**验收通过标准**：
- `currentState` 显示记录当前状态
- `allowedStates` 显示允许的前置状态
- `actionRequired: "MANUAL_VERIFICATION"` 提示人工核对

---

### 场景 6：人工修正场景（含修正后重跑）
**目的**：验证异常情况的人工处理流程

**执行步骤**：
1. 创建锁定记录 → ✅ NORMAL
2. 模拟库存不一致（locked=0）→ （模拟步骤）
3. 尝试释放 → ❌ FAILURE (`NEEDS_MANUAL_CORRECTION`)
4. 验证状态 → ✅ NORMAL (`needsManualCorrection: true`)
5. 执行人工修正 → 🔧 CORRECTED (`resultType: "CORRECTED"`)
6. 验证修正后状态 → ✅ NORMAL

**验收通过标准**：
- 第3步返回 `errorCode: "NEEDS_MANUAL_CORRECTION"`
- `actionRequired: "MANUAL_CORRECTION"` 明确指示需要人工处理
- 人工修正后 `resultType: "CORRECTED"`
- 修正记录包含 `correctionId`、`operatorId`、`appliedAt`

---

## 五、验收判定矩阵

### 成功标志
```
success: true
resultType: "NORMAL" 或 "CORRECTED"
actionRequired: "NONE" 或 "RETRY_OPERATION"
errorCode: "SUCCESS"
```

### 需要人工处理的标志
```
success: false
resultType: "FAILURE"
errorCode: "NEEDS_MANUAL_CORRECTION" 或 "ALREADY_RELEASED" 或 "RELEASE_FAILED"
actionRequired: "MANUAL_CORRECTION" 或 "MANUAL_VERIFICATION"
```

### 状态标志速查
| 状态 | 含义 | 能否释放 | 能否锁定 |
|------|------|----------|----------|
| `LOCKED` | 已锁定 | ✅ 可以 | ❌ 不能 |
| `RELEASED` | 已释放 | ❌ 不能（需人工核对） | ❌ 不能 |
| `MANUAL_CORRECTION_NEEDED` | 需要人工修正 | ❌ 不能（需先修正） | ❌ 不能 |

## 八、问题排查流程

### 流程图
```
收到 API 响应
    │
    ├─ resultType = NORMAL ──→ 正常结束 ✅
    │
    ├─ resultType = CORRECTED ──→ 人工修正成功 🔧
    │                              可重试原操作
    │
    └─ resultType = FAILURE ──┬─ actionRequired = FIX_REQUEST
                             │     └─ 修正请求参数后重试
                             │
                             ├─ actionRequired = CHECK_*
                             │     └─ 检查相关数据
                             │
                             ├─ actionRequired = MANUAL_VERIFICATION
                             │     └─ 人工核对（不强制修改）
                             │
                             └─ actionRequired = MANUAL_CORRECTION
                                   └─ 调用人工修正接口
                                      └─ 然后重试原操作
```
