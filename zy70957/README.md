# 后勤服务中心 - 报修数据处理API

## 项目简介

本项目用于统一处理学生报修、维修工接单和满意度评分数据，解决导入混乱问题，实现数据质量管控和可追溯性。

## 核心功能

1. **数据导入**：支持报修CSV、维修工JSON、评分JSON三种格式
2. **智能分类**：自动将记录分为正常项、待确认项、失败项
3. **规则校验**：
   - 重复报修检测
   - 超时罚分检测
   - 恶意评分识别
   - 宿舍楼栋格式校验
   - 数据完整性校验
4. **幂等性保证**：同一批材料再次提交不会重复生效
5. **完整追溯**：失败记录保留原始字段和建议处理方式

## API 接口说明

### POST /api/upload
上传并处理数据文件

**请求参数（Form-Data）：**
- `repair_csv`: 报修记录CSV文件
- `worker_json`: 维修工信息JSON文件
- `rating_json`: 评分记录JSON文件

**响应示例：**
```json
{
  "batch_id": "abc123...",
  "process_time": "2024-01-15T10:00:00",
  "total_count": 23,
  "normal_count": 10,
  "pending_count": 8,
  "failed_count": 5,
  "normal_records": [...],
  "pending_records": [...],
  "failed_records": [...]
}
```

### GET /api/batch/{batch_id}
查询批次处理状态

### GET /api/batches
查询所有批次记录

### POST /api/clear
清空历史数据（测试用）

## 业务规则说明

### 报修记录校验规则

| 规则 | 类型 | 说明 |
|------|------|------|
| 重复报修 | 失败 | 同一批次或历史记录中已存在 |
| 楼栋格式异常 | 待确认 | 需包含"号楼"、"栋"、"舍"等标识 |
| 描述过短 | 待确认 | 少于5个字符 |
| 房间号缺失 | 待确认 | 需要补充具体房间号 |
| 未来时间 | 待确认 | 提交时间超过当前时间1小时 |

### 维修工校验规则

| 规则 | 类型 | 说明 |
|------|------|------|
| 信息已存在 | 失败 | 工号重复 |
| 电话格式异常 | 待确认 | 不足11位 |
| 技能未填写 | 待确认 | 至少一项技能 |
| 姓名缺失 | 待确认 | 需要真实姓名 |

### 评分记录校验规则

| 规则 | 类型 | 说明 |
|------|------|------|
| 重复评分 | 失败 | 同一评分记录重复提交 |
| 报修单不存在 | 待确认 | 需先导入报修记录 |
| 维修工不匹配 | 失败 | 与实际处理人不一致 |
| 分数无效 | 失败 | 必须1-5分 |
| 差评无详情 | 待确认 | 1分评价需至少10字符 |
| 评分超时 | 失败 | 报修完成30天后不可评价 |
| 恶意评分 | 失败 | 检测到异常模式 |

## 样例数据说明

位于 `sample_data/` 目录下：

### repairs.csv - 报修记录（10条）
- **正常记录**：R001-R005（包含3号楼、东2楼、5号楼等宿舍楼栋）
- **重复记录**：R001（第6行，将被标记为失败）
- **待人工修正**：
  - R007：楼栋为空，需要人工确认
  - R008：楼栋名称"学生宿舍"格式不规范
  - R009：描述为空
  - R010：房间号缺失

### workers.json - 维修工信息（5条）
- **正常记录**：W001-W003
- **待确认**：W004（电话号码过短）
- **失败**：W001（重复提交）

### ratings.json - 评分记录（8条）
- **正常记录**：T001-T003
- **待确认/失败**：
  - T004：恶意评分（1分+无详情）
  - T005：关联报修单不存在
  - T006：维修工不匹配
  - T007：分数无效（6分）
  - T001：重复评分

## 如何向他人说明处理结果

### 放行记录示例
> **记录 R002（李四，东2楼205）** 已放行
> - 原因：所有字段完整且格式正确
> - 楼栋"东2楼"符合命名规范
> - 报修描述"椅子摇晃需要加固"信息充足

### 退回记录示例
> **记录 R001（第6行重复提交）** 已退回
> - 原因：重复报修
> - 说明：该报修单已在本批次第2行提交
> - 建议：删除重复记录或使用新的报修编号

### 待补材料示例
> **记录 R007（周八）** 需人工修正
> - 原因：宿舍楼栋信息缺失
> - 原始数据：楼栋字段为空
> - 建议：请确认该学生所在楼栋（如"1号楼"、"西3楼"等）并补充完整
