# 预约挂号中台医生停诊批量改约 API

## 项目概述

本项目实现了预约挂号中台的医生停诊批量改约功能，支持从创建到导出的完整流程，所有操作均可通过 curl 命令完成，不依赖前端页面。

## 核心功能

### 数据模型
- **医生**: 包含姓名、科室、职称等信息
- **号源**: 包含医生、日期、时段、剩余号数等信息
- **患者**: 包含姓名、电话、身份证号等信息
- **改约批次**: 包含批次号、医生、号源、改约原因、状态、统计信息等
- **改约记录**: 包含患者信息、原号源、目标号源、状态、操作时间等
- **操作历史**: 完整记录每一步操作，支持追溯

### 状态流转
```
PENDING (待处理) → PROCESSING (处理中) → NOTIFIED (已通知)
                                                         → REFUNDED (已退款)
                                                         → RESCHEDULED (已改约)
                                                         → FAILED (处理失败)
                                                         → CANCELLED (已取消)
```

### 特殊场景支持
1. **患者选择退款后又被自动改约**: 支持已退款状态的患者重新改约，并记录操作历史
2. **重复请求**: 重复提交批次会被正确拒绝，保证幂等性
3. **撤回后再提交**: CREATED 状态的批次可撤回，已撤回的批次不可再提交

### 导出功能
- 导出 CSV 文件使用业务语言字段名
- 导出数据与列表查询结果完全一致

## API 接口

### 基础信息
- 服务地址: `http://localhost:3000`
- API 前缀: `/api/reschedule`

### 接口列表

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/batches` | 创建改约批次 |
| POST | `/batches/:id/submit` | 提交批次 |
| POST | `/batches/:id/cancel` | 撤回批次 |
| POST | `/batches/:id/notify` | 发送通知 |
| POST | `/batches/:id/refund` | 办理退款 |
| POST | `/batches/:id/reschedule` | 执行改约 |
| POST | `/batches/:id/fail` | 标记处理失败 |
| GET | `/batches` | 批次列表 |
| GET | `/batches/:id` | 批次详情 |
| GET | `/batches/:id/records` | 批次记录列表 |
| GET | `/batches/:id/export` | 导出 CSV |
| GET | `/history` | 操作历史 |
| GET | `/doctors` | 医生列表 |
| GET | `/schedules` | 号源列表 |
| GET | `/patients` | 患者列表 |

## 快速开始

### 1. 安装依赖
```bash
npm install
```

### 2. 启动服务
```bash
npm start
```

### 3. 运行验收测试
```bash
bash test/acceptance_test.sh
```

## 验收测试覆盖场景

### 场景一：完整流转
1. 创建改约批次（张医生停诊）
2. 查看批次列表和详情
3. 提交批次
4. 发送通知
5. 部分患者选择退款，部分患者改约
6. 查看操作历史
7. 导出 CSV 文件

### 场景二：退款后自动改约
1. 创建批次（李医生停诊）
2. 提交并通知
3. 患者先选择退款
4. 患者反悔，重新改约
5. 验证历史记录中包含"自动改约"操作

### 场景三：重复提交验证
1. 尝试重复提交已提交的批次
2. 验证被正确拒绝

### 场景四：撤回后再提交
1. 创建批次
2. 在提交前撤回
3. 验证批次状态为 CANCELLED
4. 尝试提交已撤回的批次
5. 验证被正确拒绝

### 坏行处理
- 支持将记录标记为处理失败（如：患者电话为空无法通知）

## 导出 CSV 字段说明

| 字段名 | 说明 |
|--------|------|
| 改约批次号 | 批次的唯一标识号 |
| 医生姓名 | 停诊医生姓名 |
| 原就诊日期 | 患者原预约的就诊日期 |
| 原就诊时段 | 患者原预约的就诊时段 |
| 改约原因 | 医生停诊/参会/科室调整等 |
| 患者姓名 | 患者姓名 |
| 患者电话 | 患者联系电话 |
| 处理状态 | PENDING/PROCESSING/NOTIFIED/REFUNDED/RESCHEDULED 等 |
| 状态说明 | 状态的中文描述 |
| 通知时间 | 通知发送时间 |
| 退款时间 | 退款办理时间 |
| 改约完成时间 | 改约完成时间 |
| 新就诊日期 | 改约后的就诊日期 |
| 新就诊时段 | 改约后的就诊时段 |
| 错误信息 | 处理失败时的错误说明 |
| 记录创建时间 | 改约记录创建时间 |

## 测试输出

验收测试运行后会在 `test_output/` 目录下生成以下文件：
- 各步骤的 API 响应 JSON
- 导出的 CSV 文件
- 操作历史记录

## 注意事项

1. 本项目使用内存存储数据，服务重启后数据会丢失
2. 生产环境需要替换为真实的数据库存储
3. 需要对接真实的短信/消息通知系统
4. 需要对接真实的支付退款接口
