# 离线表单同步冲突演练器

一个用于模拟多设备离线编辑与同步冲突的交互式工具，帮助理解外勤巡检表在多人协作时的同步机制。

## 功能特性

### 核心功能
- **双设备视角**：同时展示两台设备（张三和李四）的独立操作界面
- **离线/在线切换**：每台设备可独立断网/联网，模拟外勤场景
- **离线编辑队列**：断网时改动先进入本地队列，联网后再同步
- **智能同步冲突处理**：
  - ✅ **不同字段自动合并**：两台设备修改同一条记录的不同字段时自动合并
  - ⚠️ **同一字段冲突**：修改同一字段时保留双方版本，需手动选择
  - 🚫 **旧版本保护**：基于旧版本的修改不能静默覆盖新版本

### 辅助功能
- **同步时间线**：清晰记录每次是谁在什么版本上改了什么、合并了什么、冲突了什么
- **冲突管理器**：可视化展示未解决和已解决的冲突，支持手动选择保留哪个版本
- **导入/导出**：
  - 导出当前服务端状态和完整同步日志为 JSON
  - 导入预置场景直接复现冲突
- **数据持久化**：刷新页面后设备草稿、服务端版本和日志都不会丢失
- **预置场景**：一键加载预设的冲突演练场景

## 技术栈

- **前端框架**：React 18
- **构建工具**：Vite 5
- **语言**：TypeScript
- **状态管理**：React Context + useReducer
- **本地存储**：localStorage

## 使用指南

### 界面布局

1. **顶部状态栏**：显示服务端当前版本、待同步更改数量、未解决冲突数量
2. **设备视角区**（左侧/上半部分）：
   - 设备A（张三）：独立的表单编辑界面
   - 设备B（李四）：独立的表单编辑界面
3. **右侧面板**：
   - 服务端状态：显示服务端当前版本、表单内容、最后同步记录
   - 冲突管理：查看和解决同步冲突
   - 数据管理：导入/导出、预置场景、重置状态
4. **时间线**（底部）：完整的同步操作日志

### 基本操作流程

1. **断网编辑**：点击设备面板上的"断开网络"按钮，设备进入离线状态
2. **修改表单**：在离线状态下修改巡检表的字段（风险等级、处理状态、备注、照片备注）
3. **查看待同步更改**：离线修改会显示在"待同步更改"区域
4. **联网同步**：点击"连接网络"恢复在线状态，然后点击"同步"按钮
5. **处理冲突**：如果同步时产生冲突，在"冲突管理"面板选择保留哪个版本

## 一键复现冲突示例

### 场景一：典型同一字段冲突（推荐新手体验）

**最快方式**：直接加载预置场景
1. 在右侧"数据管理"面板找到"预置场景"
2. 点击"⚠️ 典型冲突场景 - 同一字段修改"卡片上的"加载场景"
3. 观察两台设备都有待同步更改（都修改了同一字段：风险等级）
4. 先点击设备A的"同步"按钮 → 同步成功，版本号增加
5. 再点击设备B的"同步"按钮 → 检测到冲突！
6. 在"冲突管理"面板查看冲突详情，选择保留哪个版本

**手动操作步骤**：
1. 设备A（张三）：点击"断开网络"
2. 设备A：修改"设备A - 电源检查"的风险等级从"低风险"改为"高风险"
3. 设备B（李四）：点击"断开网络"
4. 设备B：修改"设备A - 电源检查"的风险等级从"低风险"改为"中风险"
5. 设备A：点击"连接网络" → 点击"同步" → 同步成功（版本变为2）
6. 设备B：点击"连接网络" → 点击"同步" → 检测到同一字段冲突！

### 场景二：自动合并（不同字段修改）

**最快方式**：加载预置场景
1. 点击"🔄 自动合并场景 - 不同字段修改"卡片上的"加载场景"
2. 观察两台设备修改的是不同字段（一个改风险等级，一个改状态）
3. 先同步设备A → 成功
4. 再同步设备B → **自动合并，无冲突！**

**手动操作步骤**：
1. 设备A断网 → 修改"设备A - 电源检查"的**风险等级**
2. 设备B断网 → 修改"设备A - 电源检查"的**处理状态**
3. 设备A联网同步 → 成功
4. 设备B联网同步 → 自动合并，无冲突

### 场景三：旧版本提交冲突

**最快方式**：加载预置场景
1. 点击"📋 旧版本提交场景"卡片上的"加载场景"
2. 观察：设备A已同步到版本3，设备B离线且基于版本1修改
3. 先让设备B联网（点击"连接网络"）
4. 点击设备B的"同步" → 检测到旧版本提交冲突！

## 同步规则详解

### 版本号机制
- 服务端维护全局版本号，每次成功同步后递增
- 每台设备记录自己的本地版本号
- 每次修改都基于当前本地版本号

### 冲突检测逻辑

| 场景 | 检测结果 | 处理方式 |
|------|---------|---------|
| 不同设备修改**同一记录的不同字段** | 无冲突 | 自动合并 |
| 不同设备修改**同一记录的同一字段** | 同一字段冲突 | 保留双方版本，手动选择 |
| 基于**旧版本**的修改尝试提交 | 旧版本提交冲突 | 阻止静默覆盖，手动确认 |

### 冲突解决选项
1. **保留服务端版本**：放弃客户端修改
2. **保留客户端版本**：覆盖服务端版本
3. **合并双方**（仅同一字段冲突时）：用 `|` 分隔合并两个值

## 数据持久化

应用使用 `localStorage` 自动保存状态，包括：
- 两台设备的本地草稿和待同步更改
- 服务端的当前版本和表单内容
- 冲突记录（已解决和未解决）
- 完整的同步时间线日志

刷新页面或关闭浏览器后重新打开，所有状态都会恢复。

## 预置场景说明

应用内置三个预置场景，可一键加载体验：

1. **典型冲突场景**：两台设备同时离线修改同一条巡检项的同一字段（风险等级），联网同步时产生冲突
2. **自动合并场景**：两台设备同时离线修改同一条巡检项的不同字段（一台改风险等级，一台改状态），联网同步时自动合并
3. **旧版本提交场景**：设备A在线修改并同步，设备B离线基于旧版本修改，联网同步时检测到旧版本提交冲突
