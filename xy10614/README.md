# 园区访客通行核销系统

一个基于 Node.js + Express + React + TypeScript 的园区访客通行核销管理系统。

## 功能特性

### 核心业务流程
1. **访客预约** - 创建访客预约记录
2. **被访人确认** - 被访人确认同意或拒绝访客来访
3. **车牌入园校验** - 自动校验车牌，不一致则进入人工复核
4. **门禁二维码** - 生成并扫描门禁二维码
5. **离园核销** - 访客离园时核销，支持状态拦截
6. **黑名单管理** - 支持添加/移除黑名单，影响相关记录

### 内置场景支持
- **正常完成流程** - 完整的预约→确认→入园→门禁→离园流程
- **被规则挡住** - 黑名单拦截、被访人拒绝、状态拦截等
- **人工复核** - 车牌不匹配时进入人工复核流程
- **重复提交** - 防止重复入园、重复核销等操作

### 数据审计与导出
- **操作日志** - 记录所有操作，支持按操作人、时间、类型筛选
- **详情时间线** - 每个访客的完整操作时间线展示
- **修改前后值** - 保留被访人确认、车牌入园、门禁二维码的修改前后值
- **Excel报表导出** - 支持按责任人和处理时间筛选导出
- **黑名单变更追踪** - 记录谁修改、为什么修改、影响了哪些记录

## 快速开始

### 安装依赖

```bash
# 安装后端依赖
npm install

# 安装前端依赖
cd client
npm install
cd ..
```

### 启动服务

```bash
# 启动后端服务 (端口: 3001)
npm run dev:server

# 新开终端，启动前端服务 (端口: 3000)
npm run dev:client
```

### 初始化演示场景

访问前端应用后，点击访客列表页面的 **「初始化演示场景」** 按钮，系统将自动创建以下四个场景的演示数据：

1. **正常完成流程** - 完整的访客预约、确认、入园、门禁、离园流程
2. **被规则挡住** - 黑名单拦截、被访人拒绝等场景演示
3. **人工复核** - 车牌不匹配时的人工审核流程
4. **重复提交防护** - 防止重复入园、重复核销的防护机制

初始化完成后，可前往 **操作日志** 查看所有操作记录，或前往 **报表导出** 导出Excel报表（包含黑名单变更追踪）。

## 使用说明

### 1. 创建访客预约
1. 点击访客列表页面的"新建访客预约"按钮
2. 填写访客信息、被访人信息、来访事由等
3. 提交创建预约

### 2. 被访人确认
1. 进入访客详情页
2. 点击"被访人确认"按钮
3. 选择确认或拒绝，填写拒绝原因（如拒绝）

### 3. 车牌入园校验
1. 被访人确认后，点击"车牌入园校验"
2. 输入车牌号
3. 如车牌与预约一致，直接通过入园
4. 如车牌不一致，进入"待人工复核"状态

### 4. 人工复核（如需要）
1. 当状态为"待人工复核"时，点击"人工复核"按钮
2. 选择通过或拒绝，填写原因

### 5. 生成并扫描门禁二维码
1. 入园后，点击"生成门禁二维码"
2. 点击"扫描门禁二维码"按钮
3. 输入二维码进行扫描

### 6. 离园核销
1. 完成门禁扫描后，点击"离园核销"
2. 系统会校验当前状态，防止非法核销

### 7. 查看操作日志
1. 点击左侧菜单的"操作日志"
2. 可按时间范围、操作人、操作类型、访客ID筛选

### 8. 导出报表
1. 点击左侧菜单的"报表导出"
2. 设置筛选条件（时间范围、操作人、操作类型）
3. 点击"导出 Excel 报表"按钮

## API 接口

### 访客相关
- `POST /api/visitors` - 创建访客
- `GET /api/visitors` - 获取所有访客
- `GET /api/visitors/:id` - 获取访客详情
- `POST /api/visitors/:id/host-confirm` - 被访人确认
- `POST /api/visitors/:id/plate-entry` - 车牌入园校验
- `POST /api/visitors/:id/generate-qrcode` - 生成二维码
- `POST /api/visitors/:id/scan-qrcode` - 扫描二维码
- `POST /api/visitors/:id/checkout` - 离园核销
- `POST /api/visitors/:id/manual-review` - 人工复核
- `GET /api/visitors/:id/timeline` - 获取时间线

### 黑名单相关
- `POST /api/blacklist` - 添加黑名单
- `DELETE /api/blacklist/:id` - 移除黑名单
- `GET /api/blacklist` - 获取所有黑名单

### 报表相关
- `POST /api/security-report` - 生成安保报表
- `GET /api/security-reports` - 获取所有安保报表
- `GET /api/logs` - 获取操作日志
- `GET /api/operators` - 获取所有操作人
- `POST /api/export` - 导出Excel报表

## 测试场景建议

### 场景一：正常完成流程
1. 创建访客预约
2. 被访人确认同意
3. 车牌校验（输入正确车牌）
4. 生成门禁二维码
5. 扫描门禁二维码
6. 离园核销
7. 查看操作日志和时间线

### 场景二：被规则挡住
1. 将访客加入黑名单
2. 尝试创建该访客的预约 - 预期失败
3. 创建新访客，被访人拒绝 - 查看状态变更
4. 尝试让被拒绝的访客入园 - 预期被拦截

### 场景三：人工复核
1. 创建访客预约并被访人确认
2. 车牌校验时输入错误车牌 - 进入人工复核
3. 在详情页进行人工复核（通过或拒绝）
4. 查看操作日志中的修改记录

### 场景四：重复提交测试
1. 创建访客并完成正常流程
2. 尝试再次进行车牌校验 - 预期提示已入园
3. 尝试再次扫描二维码 - 预期提示已扫描
4. 尝试再次离园核销 - 预期提示已离园

### 场景五：报表导出测试
1. 完成多个访客的各种操作
2. 添加/移除黑名单
3. 进入报表导出页面
4. 按不同条件筛选并导出Excel
5. 查看导出的报表，验证黑名单变更记录

## 核心业务规则

1. **状态流转控制** - 每个操作只能在特定状态下进行
2. **黑名单拦截** - 黑名单访客无法创建预约，已创建的会被拦截
3. **重复操作防护** - 防止重复入园、重复核销等
4. **人工复核机制** - 异常情况（如车牌不匹配）进入人工审核
5. **完整审计追踪** - 所有操作都记录操作人、时间、修改前后值

## 注意事项

1. 本系统使用内存存储，重启服务后数据会丢失
2. 生产环境建议替换为真实数据库（如 PostgreSQL、MySQL）
3. 建议添加身份认证和权限控制
4. 建议添加数据持久化和备份机制
