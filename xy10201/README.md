# 牙科椅旁耗材补货台

解决牙科诊室椅旁耗材消耗快、护士补录后库存和诊疗项目经常对不上的问题。

## 可运行入口（无需安装任何依赖）

**直接双击打开 `dental-app.html`** 即可体验完整的 Web 应用，包含：
- 仪表盘（卡点检测、处理建议、统计数据）
- 诊疗项目绑定与库存检查
- 耗材消耗（按诊疗项目 / 手动）
- 补货申请、审核、入库
- 历史追溯（消耗记录、申请记录、操作日志）

*其他入口（server/client/package.json）保留原始代码结构，但需要 npm 安装依赖后才能运行。*

## 核心特性

### 业务闭环
1. **诊疗项目绑定** - 定义诊疗项目与耗材的模板关系
2. **耗材消耗** - 按诊疗项目一键消耗，自动扣减库存
3. **补货申请** - 库存不足时触发预警，护士快速申请
4. **补录审核** - 护士长审核申请，库管执行补货
5. **历史追溯** - 完整的消耗、审核、库存变动记录

### 状态协作
- **前后端共用**同一套状态机定义（`STATUS_FLOW`）
- 页面展示**当前卡点**、**处理建议**、**历史变化**
- 关键判断**体现在**：测试输出、接口响应、页面状态

## 样例数据位置

- **数据库脚本**：`server/scripts/seed-data.js`
- **样例内容**：
  - 4 个科室（口腔内科、外科、修复、正畸）
  - 10 种耗材（车针、检查盘、树脂、粘接剂等）
  - 5 个诊疗项目（补牙、根管、拔牙、洗牙、美白）
  - 12 条项目-耗材绑定关系

## 主流程演示

### 流程 1：按诊疗项目消耗

1. 进入「耗材消耗」页面
2. 选择科室 → 选择「常规补牙」
3. **页面自动检测**：该项目绑定 5 种耗材，其中树脂、粘接剂库存不足
4. 按钮**自动禁用**，提示：「缺少 2 种耗材，无法执行」
5. 点击「库存管理」→ 找到库存不足的耗材 → 「申请补货」

### 流程 2：补货申请 → 审核 → 入库

1. **护士小王** 在「补货申请」提交：光固化复合树脂 x 20
2. 申请单号自动生成：`RP-YYYYMMDD-XXXX`
3. **护士长** 切换操作员，进入「审核中心」
4. 待审核列表显示该申请，可：
   - 通过（可调整审核数量）
   - 拒绝（必须填写原因）
5. **库管小李** 切换操作员，看到「已通过」状态的申请
6. 点击「确认补货」→ 库存自动 +20
7. 页面顶部统计：「库存不足」数量减少

### 流程 3：历史追溯

1. 进入「历史追溯」页面
2. 三个标签页：
   - **消耗记录**：查看每次消耗的耗材、数量、金额
   - **补货申请**：查看所有申请的状态流转
   - **操作日志**：JSON 格式的变更前后数据（悬停查看完整内容）

## 异常操作演示

### 异常 1：库存不足时强制消耗

**操作**：在「耗材消耗」选择库存不足的耗材，输入超过库存的数量

**结果**：
- 接口返回 `409 Conflict`
- 页面显示红色错误提示：`库存不足：当前3支，需要10支`
- 测试套件中 `库存不足时消耗应抛出错误` 用例验证

**验证**：
```bash
npm test
# 输出包含：✓ 库存不足时消耗应抛出错误
```

### 异常 2：状态机越界操作

**操作**：创建申请 → 拒绝 → 再尝试通过

**结果**：
- 后端 `canTransition()` 检测失败
- 接口返回 `409 Conflict`
- 错误信息：`当前状态"已拒绝"不允许通过`
- 前端按钮在已拒绝状态隐藏「通过」选项

**验证**：查看测试输出：
```
✓ 已拒绝状态不能再通过
```

### 异常 3：补货审核量与入库量不一致

**验证点**：测试用例 `补货审核量应与实际入库一致`

**流程**：
1. 申请 30 支 → 审核通过 25 支 → 完成补货
2. 查询库存历史，入库量必须是 25，而非 30
3. `inventory_snapshots.change_quantity === replenishment_requests.approved_quantity`

## 状态机定义

### 补货申请状态流转

```
PENDING (待审核) ──┬──→ APPROVED (已通过) ──→ FULFILLED (已补货)
                  └──→ REJECTED (已拒绝)
```

- `PENDING → APPROVED/REJECTED`：护士长审核
- `APPROVED → FULFILLED`：库管入库
- `REJECTED`：终态，不可再通过

### 库存状态

| 状态 | 条件 | 前端显示 |
|------|------|----------|
| NORMAL | 库存 ≥ 预警值 | 绿色「正常」 |
| LOW_STOCK | 0 < 库存 < 预警值 | 橙色「库存不足」 |
| OUT_OF_STOCK | 库存 = 0 | 红色「已断货」 |

## 业务辨识度

### 椅旁消耗
- 选择诊疗项目 → 自动展开绑定耗材清单
- 实时校验每种耗材库存
- 任一不足则**整体阻塞**，按钮禁用

### 项目模板
- `treatment_materials` 表存储标准用量
- 消耗时按模板自动计算
- 支持 `quantity` 倍数（一次做多个患者）

### 补录后一致性
- `inventory_snapshots` 记录每次库存变动
- `audit_records` 记录审核操作
- `operation_logs` 记录 JSON diff
- 三者通过 `reference_id` 关联，可交叉验证

## 技术栈

- **后端**：Node.js + Express + better-sqlite3
- **前端**：Vue 3 + Element Plus + Vite
- **数据库**：SQLite（嵌入式，无需额外安装）
