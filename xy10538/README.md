# 物料替代审批 CLI (Material Substitute CLI)

生产计划员缺料时的替代物料审批工具，围绕生产缺料时使用替代物料，核对 BOM、客户限制、成本和审批记录。

## 功能特性

- **BOM 核对**: 验证替代物料是否在产品BOM中有原始物料
- **替代关系检查**: 确认替代物料关系是否已定义且有效
- **库存检查**: 验证替代料库存是否满足需求
- **客户限制**: 检查客户是否禁止特定物料的替代
- **成本审批**: 成本超阈值时触发一级/二级审批
- **完整审批流**: 创建→审批→投料使用→归档
- **幂等性保证**: 重复操作不会产生副作用
- **人工修正留痕**: 所有人工修改记录前后值和操作人
- **历史追踪**: 完整的操作历史和审批记录

## 快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 初始化工作区

```bash
./ms init
```

使用 `--force` 强制重新初始化（会清除已有数据）。

### 3. 加载样例数据

```bash
./ms import-sample
```

内置样例覆盖三类物料：
- **电子料**: 电阻 (RES-001~003)、电容 (CAP-001~003)、电路板 (PCB-001)
- **包装料**: 包装箱 (BOX-001~002)
- **结构件**: 塑料边框 (FRAME-001~002)

客户限制样例：
- 苹果公司 (CUST-001): 禁止替代电容 CAP-001
- 华为技术 (CUST-002): 禁止替代所有物料

成本阈值配置：
- 一级审批阈值: 10%
- 二级审批阈值: 30%

### 4. 查看状态

```bash
./ms status
```

## 命令清单

### 基础命令

| 命令 | 说明 |
|------|------|
| `ms init [--force]` | 初始化工作区 |
| `ms status [--json]` | 查看工作区状态 |

### 业务命令

| 命令 | 说明 |
|------|------|
| `ms check <产品> <原始料> <替代料> [--customer] [--quantity]` | 检查替代可行性 |
| `ms create --product <产品> --component <原始料> --substitute <替代料>` | 创建替代申请 |

| `ms reject <申请ID>` | 拒绝申请 |
| `ms revoke <申请ID>` | 撤销申请 |
| `ms use <申请ID>` | 标记已投料使用 |
| `ms correct <申请ID> <字段> <旧值> <新值>` | 人工修正 |

| 命令 | 说明 |
|------|------|

| `ms list [--status]` | 列出所有申请 |
| `ms report [申请ID]` | 生成审批报告 |
| `ms history [--application] [--limit]` | 查看操作历史 |

## 失败路径演示

运行失败路径演示：

```bash
./demo_fail.sh
```

该脚本演示以下场景：

### 场景 1: 客户限制
- **问题**: 苹果公司 (CUST-001) 禁止替代 CAP-001
- **结果**: 检查失败，显示客户限制原因

### 场景 2: 库存不足
- **问题**: RES-003 库存只有 200，需要 500
- **结果**: 检查失败，显示库存不足

### 场景 3: 成本超阈值 - 需二级审批
- **问题**: CAP-001 → CAP-003，成本增加 233%
- **结果**: 需要二级审批，状态为 PENDING_LEVEL1

### 场景 4: 重复申请
- **问题**: 再次创建相同的替代申请
- **结果**: 提示存在重复申请

### 场景 5: 已投料不能撤销
- **问题**: 标记 USED 后尝试撤销
- **结果**: 撤销失败，已投料无法撤销

### 场景 6: 级别不足审批 + 幂等性
- **问题**: 需二级审批，只用一级审批
- **结果**: 状态变为 PENDING_LEVEL2，需二级审批
- **幂等性**: 再次执行审批命令不会重复操作

## 业务规则说明

### 替代条件判断

替代能否进行取决于以下检查：

| 检查项 | 通过条件 | 失败结果 |
|--------|----------|----------|
| BOM检查 | 产品和组件存在于BOM | 不可替代 |
| 替代关系 | 替代关系已定义且激活 | 不可替代 |
| 库存检查 | 替代料库存 ≥ 需求数量 | 不可替代 |
| 客户限制 | 客户未禁止该替代 | 不可替代 |
| 成本检查 | 成本变化在阈值内 | 需审批 |

### 审批级别规则

```
成本变化 ≤ 10%  → 自动审批 (AUTO_APPROVED)
10% < 成本变化 ≤ 30%  → 需一级审批 (PENDING_LEVEL1)
成本变化 > 30%  → 需二级审批 (PENDING_LEVEL2)
```

### 状态流转

```
CREATED → PENDING_LEVEL1 → PENDING_LEVEL2 → APPROVED → USED
              ↓                 ↓
           REJECTED          REJECTED
              ↓
           REVOKED
```

### 幂等性保证

以下操作支持幂等：
- 已审批的申请再次审批 → 返回成功，提示已审批
- 已拒绝的申请再次拒绝 → 返回成功，提示已拒绝
- 已撤销的申请再次撤销 → 返回成功，提示已撤销
- 已投料的申请再次使用 → 返回成功，提示已使用

### 禁止操作

- 已投料 (USED) 的申请：无法审批、拒绝、撤销
- 已拒绝 (REJECTED) 的申请：无法审批
- 级别不足的审批：无法通过

### 人工修正

使用 `ms correct` 命令进行人工修正时：
- 必须指定旧值和新值
- 自动记录操作人、时间、原因
- 可在 `ms detail` 中查看修正历史

## 数据文件

工作区默认位置：`./.material-substitute/`

```
.material-substitute/
├── data/                    # 数据目录
├── history/                 # 历史记录目录
├── state.json              # 主状态文件
│   ├── bom                 # 产品物料清单
│   ├── inventory           # 库存数据
│   ├── substitute_relations # 替代关系
│   ├── customer_restrictions # 客户限制
│   ├── applications        # 审批申请
│   └── history             # 操作历史
└── settings.json           # 配置文件
    ├── cost_threshold      # 一级审批阈值 (默认 0.1=10%)
    └── cost_level2_threshold # 二级审批阈值 (默认 0.3=30%)
```

## JSON 输出

所有命令支持 `--json` 参数输出 JSON 格式，便于集成到自动化系统：

```bash
./ms check SMART-TV-001 RES-001 RES-002 --json
./ms detail APP-000001 --json
./ms report --json
```

## 常见问题

**Q: 如何修改成本审批阈值？**

A: 编辑 `.material-substitute/settings.json` 中的 `cost_threshold` 和 `cost_level2_threshold`。

**Q: 如何查看所有历史申请？**

A: `./ms list` 列出所有，`./ms list --status APPROVED` 按状态筛选。

**Q: 如何导出报告？**

A: `./ms report --json > report.json` 可导出为 JSON 文件。
