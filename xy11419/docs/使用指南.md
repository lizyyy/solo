# 物业维修派单权限追责台账 API - 使用指南

## 快速开始

### 1. 安装依赖
```bash
npm install
```

### 2. 初始化样例数据
```bash
npm run seed
```

### 3. 启动服务
```bash
npm start
```
服务地址: http://localhost:3000

### 4. 运行演示
```bash
npm test
```

## 核心概念

### 三种批次样例
系统预置三种典型批次数据：

| 批次类型 | 说明 | 数据特点 |
|---------|------|---------|
| 正常批次 | 住户报修系统导入 | 3单全部完成，有证据、材料记录 |
| 待复核批次 | 门店交接纸扫描 | 1单二次确认、1单驳回，需人工处理 |
| 无法处理批次 | 材料领用表导入 | 数据缺失，已取消，关联失败任务 |

### 工作流状态机
```
草稿(draft) → 已提交(submitted) → 已派单(assigned)
                       ↓              ↓
                   已驳回(rejected) ←┘   ↓
                       ↑              ↓
                   二次确认(second_confirmation)
                                      ↓
                                进行中(in_progress)
                                      ↓
                               待审核(pending_review)
                                      ↓
                                已完成(completed) → 只读审计(audit_only)
```
所有状态均可 → 已取消(cancelled)

### 三种合并策略

| 策略 | 说明 | 适用场景 |
|-----|------|---------|
| ignore | 已存在则跳过 | 常规重复导入 |
| overwrite | 已存在则覆盖 | 修正错误数据 |
| append | 已存在则追加 | 补充备注信息 |

### 异步任务失败类型

| 失败类型 | 处理方式 | 说明 |
|---------|---------|------|
| waiting_retry | 自动重试 | 网络超时等临时问题，间隔重试 |
| waiting_manual | 人工处理 | 数据格式错误，需人工修正 |
| failed_permanent | 永久失败 | 重试超限，放弃处理 |

## API 接口清单

### 批次管理
```
GET    /api/batches              # 批次列表
POST   /api/batches              # 创建批次
GET    /api/batches/:id          # 批次详情（含工单、证据）
POST   /api/batches/:id/import   # 批量导入工单
POST   /api/batches/:batchId/evidences  # 上传证据
POST   /api/batches/:id/export   # 导出批次
DELETE /api/batches/:id          # 删除批次
```

### 工单管理
```
GET    /api/orders               # 工单列表
POST   /api/orders               # 创建工单
GET    /api/orders/:id           # 工单详情（含流转、审计、证据、材料）
PATCH  /api/orders/:id           # 修改工单
POST   /api/orders/:id/submit    # 提交工单
POST   /api/orders/:id/reject    # 驳回工单
POST   /api/orders/:id/second-confirmation  # 二次确认
POST   /api/orders/:id/assign    # 派单
POST   /api/orders/:id/start     # 开始维修
POST   /api/orders/:id/complete  # 完成工单
POST   /api/orders/:id/audit-only  # 标记只读审计
POST   /api/orders/:id/cancel    # 取消工单
GET    /api/orders/:id/history   # 变更历史
GET    /api/orders/:id/audits    # 审计日志
POST   /api/orders/:id/materials # 添加材料
```

### 报表视图
```
GET    /api/reports/project-manager    # 项目经理视图
GET    /api/reports/technician/:id     # 维修师傅视图
GET    /api/reports/auditor            # 审计员视图
GET    /api/reports/failed-items       # 失败项目导出
GET    /api/reports/export-orders      # 工单导出（支持脱敏）
GET    /api/reports/tasks/stats        # 任务队列统计
GET    /api/reports/tasks/failed-summary  # 失败任务汇总
```

### 任务管理
```
GET    /api/tasks                 # 待处理任务
POST   /api/tasks                 # 创建任务
GET    /api/tasks/:id             # 任务详情
POST   /api/tasks/:id/retry       # 手动重试
POST   /api/tasks/:id/mark-handled  # 标记人工处理完成
POST   /api/tasks/process         # 批量处理任务
```

## 角色权限说明

通过请求头传递用户信息：
```
X-User-Id: admin_001
X-User-Name: 张管理员
X-User-Role: admin
```

| 角色 | 主要权限 |
|-----|---------|
| admin | 全部权限 |
| project_manager | 批次管理、工单审核、报表导出 |
| dispatcher | 创建工单、派单、上传证据 |
| technician | 查看派给自己的工单、更新状态 |
| auditor | 查看工单、审计日志、脱敏导出 |
| resident | 查看、创建自己的工单 |

## 失败路径与修正方式

### 场景1: 数据校验失败 → waiting_manual
**触发条件**: 缺少必填字段、格式错误

**处理方式**:
1. GET /api/reports/failed-items 查看失败清单
2. 修正工单数据: PATCH /api/orders/:id
3. 重新提交: POST /api/orders/:id/submit
4. 标记任务完成: POST /api/tasks/:id/mark-handled

### 场景2: 网络超时 → waiting_retry
**触发条件**: 短信发送、第三方接口超时

**处理方式**:
- 系统自动重试（间隔5/10/15分钟）
- 或手动触发: POST /api/tasks/:id/retry

### 场景3: 重试超限 → failed_permanent
**触发条件**: 重试3次均失败

**处理方式**:
1. 分析错误日志确定问题
2. 数据修正后: POST /api/tasks/:id/retry
3. 或确认为无效数据: POST /api/orders/:id/cancel

## 样例调用

### 1. 创建批次并导入工单
```bash
# 创建批次
curl -X POST http://localhost:3000/api/batches \
  -H "X-User-Id: pm_001" -H "X-User-Role: project_manager" \
  -H "Content-Type: application/json" \
  -d '{
    "source_type": "住户报修系统导入",
    "merge_strategy": "append",
    "remark": "5月第三批报修单"
  }'

# 导入工单
curl -X POST http://localhost:3000/api/batches/{batch_id}/import \
  -H "X-User-Id: disp_001" -H "X-User-Role: dispatcher" \
  -H "Content-Type: application/json" \
  -d '{
    "orders": [{
      "order_no": "WD20240523001",
      "resident_name": "测试住户",
      "resident_phone": "13800138000",
      "room_number": "5栋2单元301",
      "repair_type": "水电维修",
      "description": "厨房下水管堵塞",
      "is_rework": false,
      "is_part_replacement": false
    }]
  }'
```

### 2. 工单流转完整流程
```bash
# 1. 调度员提交
curl -X POST http://localhost:3000/api/orders/{order_id}/submit \
  -H "X-User-Id: disp_001" -H "X-User-Role: dispatcher" \
  -d '{"reason": "信息核对无误"}'

# 2. 项目经理驳回（如需要）
curl -X POST http://localhost:3000/api/orders/{order_id}/reject \
  -H "X-User-Id: pm_001" -H "X-User-Role: project_manager" \
  -d '{"reason": "请补充住户联系方式"}'

# 3. 派单给维修师傅
curl -X POST http://localhost:3000/api/orders/{order_id}/assign \
  -H "X-User-Id: disp_001" -H "X-User-Role: dispatcher" \
  -d '{"assignee_id": "tech_001", "assignee_name": "刘师傅"}'

# 4. 维修师傅开始工作
curl -X POST http://localhost:3000/api/orders/{order_id}/start \
  -H "X-User-Id: tech_001" -H "X-User-Role: technician" \
  -d '{"reason": "已上门开始维修"}'

# 5. 项目经理验收
curl -X POST http://localhost:3000/api/orders/{order_id}/complete \
  -H "X-User-Id: pm_001" -H "X-User-Role: project_manager" \
  -d '{"reason": "住户验收合格"}'
```

### 3. 项目经理查看关键指标
```bash
curl -H "X-User-Id: pm_001" -H "X-User-Role: project_manager" \
  http://localhost:3000/api/reports/project-manager
```

返回包含：
- 总体概览（总单量、完成率、返修/换件数、总成本）
- 按状态分布
- 按维修类型分布
- 最近变更记录
- 失败任务列表
- 敏感字段变更记录

### 4. 查看失败项目去向
```bash
curl -H "X-User-Id: pm_001" -H "X-User-Role: project_manager" \
  http://localhost:3000/api/reports/failed-items
```

每条失败记录包含 `destination` 字段说明去向：
- 已取消
- 待重提
- 待人工处理
- 永久失败

## 报表变化说明

### 工单完成时
- 对应批次 success_count +1
- 批次状态可能从 partial_success → completed
- 项目视图 completed 计数 +1
- 维修类型统计 completed 计数 +1

### 工单驳回时
- 对应批次 failed_count 不变（待重提）
- 项目视图 in_progress 可能减少
- 状态流转记录增加一条驳回记录
- 审计日志记录操作人、原因

### 任务失败时
- task.status = waiting_retry / waiting_manual / failed_permanent
- 在 /reports/failed-items 中可见
- 项目经理视图 failed_tasks 列表展示
