## 🗂️ 这工具到底解决啥

之前现场签证单拿到手五花八门（编号涂改、批号磨损、缺签字），材料送审批次还经常和签证单写的"3 层/2 层"对不上，再加上 BIM 模型坐标手录抄错…… 这些关系全靠阿乔记着，久了就乱。

这个系统一次性把这些东西存下来：

| 问题 | 系统怎么做 |
|------|------------|
| 签证单 vs 材料送审对不上 | 自动比对施工口径，不一致的标成「口径对不上」 |
| 签证单坐标抄错，和模型差 0.5m 以上 | 自动生成「坐标偏移」疑点，**阻止进入最终报告** |
| 签证单脏数据（涂改、缺签字、字迹潦草） | **原样保留不清洗**，面板里加红框标「⚠ 原始内容 · 未清洗」 |
| 同一批材料先跑一次，后来阿乔补了"已与监理复核" | 点「补备注后重跑」生成**新批次号**，备注自动带过去 |
| 前后批次要对照 | 去「历史时间线」并排对比，差异单元格高亮 |
| 要留底给监理 | 一键导出 JSON / CSV |

## 🎮 三个核心点说清楚（样例 / 重跑 / 历史时间线）

### ① 样例

点顶部导航的「样例」或主页的「载入样例」绿色大卡片：

- 样例包自带 4 份签证单（含**涂改的**、**缺签字的**、**坐标写错的**）+ 4 份材料送审（含**批号磨损的**、**层数写 2 层 vs 签证单 3 层的**）+ 6 个 BIM 构件。
- 点「载入样例并跑清单」后，系统会自动创建一个批次 `B20260610-XXX`，执行比对，跳转到交底清单页。
- 到交底清单页：
  - **左上 Web3D**：橙色呼吸闪烁的就是「坐标偏移，暂缓报告」的构件，点任意构件看详情。
  - **右上清单表**：每行的「疑点」列会显示有几条问题。
  - **下中【原始来源】**：签证单和材料送审的原文一字不改列出来，涂改/磨损的地方自动标红。
  - **下左【疑点/暂缓/原因】**：三栏并排显示——疑点说什么、数据来源哪条、为啥暂缓。
  - **下右【补备注后重跑】**：写备注、导出。

### ② 重跑

在交底清单页右下，先在备注框里写：

```
已与监理王工视频复核，C-Beam-012 现场实际按 3 层碳纤维做，后续补设计变更单。坐标再测一次确实是 (12.45, 3.20, 8.88)，模型已联系 BIM 组调整。
```

点 **「补备注后重跑 · 生成新批次」**：

- 生成新批次号 `B20260610-YYY`，自动带 parent 指向老批次；
- 新批次每条构件的 remarks 自动拼接上这段话，批次总备注也保留追加痕迹；
- 自动跳转历史时间线。

### ③ 历史时间线

顶部导航点「历史时间线」：

- **左列【事件时间线】**：从新到旧，每次「批次创建 / 执行比对 / 补备注重跑 / 导出快照」都有记录，点一下就跳到对应批次的交底清单。
- **右列【前后批次对照】**：下拉选两个批次（例如老的和刚重跑的）点比较：
  - 新增构件 → 绿色
  - 删除构件 → 红色
  - 字段变化（备注、比对状态等）→ 黄色高亮，左旧右新
  - 疑点数量变化 → 橙色

## 📂 数据存哪

- 所有批次、签证单、材料送审、导出快照：存在浏览器 `localStorage` 的 `structure-checklist-state-v1` 键里。
- ⚠ 换浏览器 / 清缓存会丢，记得定期在交底清单页「导出 JSON」留底。
- 样例数据包是纯静态的：`public/mock/sampleData.json`，想改可以直接编辑。

## 🧩 技术栈（给想二开的人）

| 层 | 选型 |
|---|---|
| 前端 | React 18 + TypeScript 5 + Vite 6 |
| 路由 | react-router-dom v7 |
| 状态 | Zustand 5（3 个 store：`checklistStore` / `uiStore` / `useUiStore` 中 history 事件一起存） |
| Web3D | three 0.164 + @react-three/fiber 8 + drei 9 + postprocessing 2 |
| UI 样式 | Tailwind CSS 3 + Noto Serif SC（宋体，工程感）+ JetBrains Mono（等宽数据列） |
| 图标 | lucide-react |
| 后端 | 无，纯前端本地应用 |
| 数据持久化 | localStorage + 静态 JSON mock |
