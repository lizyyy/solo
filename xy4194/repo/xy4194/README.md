# 连续性穿帮核对台

专为剧组场记设计的本地桌面应用，帮助你检测和管理拍摄中的连续性问题。

## 功能特性

### 📁 数据导入
- **场次表 CSV**: 导入拍摄场次安排，包含场景信息、拍摄日期、演员阵容等
- **道具/服装状态 JSON**: 导入道具、服装、伤口、妆容的状态记录
- **演员通告 CSV/JSON**: 导入演员日程安排、化妆时间、服装要求等
- **照片目录**: 导入现场照片用于证据核对

### 🔍 规则校验引擎
自动检测以下连续性问题：

| 问题类型 | 检测内容 |
|---------|---------|
| 道具状态跳变 | 检测道具状态（空/满、干净/脏、开/关等）在场景间的异常变化 |
| 服装缺记录 | 检测场次表与实际服装记录的不一致 |
| 照片证据缺失 | 检测场记记录中引用的照片是否存在 |
| 补拍日期冲突 | 检测拍摄日期与剧情顺序的不一致 |
| 时间线不一致 | 检测日夜、内外景突变且无转场标记 |
| 演员日程冲突 | 检测演员在同一天内场景安排时间过近 |
| 伤口连续性 | 检测伤口状态（新伤/结痂/愈合）的异常变化 |
| 妆容连续性 | 检测妆容类型（浓妆/淡妆/素颜）的异常变化 |

### 📊 可视化展示
- **连续性时间线**: 按剧情顺序展示场景时间线
- **按演员筛选**: 查看特定演员在各场景的服装、妆容、伤口状态变化
- **按道具筛选**: 查看特定道具在各场景的状态变化
- **问题标记**: 时间线中用不同颜色标记检测到的问题

### ✅ 复核管理
- 场记可以对每个检测到的问题进行人工复核
- 支持多种复核状态：待确认、已确认、已忽略、已解决
- 复核意见保存到本地 SQLite 数据库
- 支持添加证据照片引用

### 📤 导出功能
- **Markdown 复盘单**: 格式美观的完整报告，适合打印和分享
- **CSV 问题表**: 方便导入 Excel 进行进一步分析
- **JSON 审计包**: 完整的数据导出，适合程序处理和备份

## 技术栈

- **前端**: React 18 + Ant Design + TypeScript
- **桌面框架**: Electron 28
- **构建工具**: Vite 5
- **数据库**: SQLite (sql.js)
- **数据处理**: PapaParse (CSV解析) + dayjs (日期处理)
- **测试框架**: Vitest

#### 道具/服装状态 JSON 格式

```json
[
  {
    "name": "咖啡杯",
    "type": "prop",
    "sceneNumber": "1-01",
    "actorName": "张三",
    "status": "满",
    "description": "咖啡杯里有半杯咖啡，有热气",
```

**type 字段可选值**:
- `prop`: 道具
- `costume`: 服装
- `wound`: 伤口

**状态关键词** (用于自动检测):
- 道具状态: 空、满、干净、脏、破、新、有、无、开、关
- 伤口状态: 新伤、旧伤、结痂、出血、包扎、拆除、新鲜、愈合
- 妆容状态: 浓妆、淡妆、素颜、特殊妆、老年妆、受伤妆、血迹

### 2. 导入数据

1. 打开应用，点击左侧菜单"导入数据"
2. 依次导入以下文件（至少需要导入场次表）：
   - **场次表 CSV**: 点击对应卡片选择 CSV 文件
   - **道具/服装状态 JSON**: 选择 JSON 文件
   - **演员通告**: 选择 CSV 或 JSON 文件
   - **照片目录**: 选择现场照片所在文件夹

3. 点击"开始连续性分析"按钮
4. 分析完成后，可以看到检测到的问题数量
5. 输入项目名称，点击"保存到本地数据库"

### 3. 查看时间线

1. 点击左侧菜单"连续性时间线"
2. 可以按演员或道具筛选查看
3. 有三个标签页：
   - **场景时间线**: 按剧情顺序展示所有场景
   - **道具状态时间线**: 按道具分组展示状态变化
   - **演员时间线**: 按演员分组展示其在各场景的状态

4. 检测到问题的场景会用不同颜色标记：
   - 🔴 红色: 严重问题
   - 🟡 橙色: 警告
   - 🔵 蓝色: 信息/正常

### 4. 复核问题

1. 点击左侧菜单"问题列表"
2. 可以按严重级别、问题类型、复核状态筛选
3. 点击问题展开查看详情，包括：
   - 问题描述
   - 涉及场景、演员、道具
   - 证据列表
   - 系统建议

4. 点击"添加复核意见"按钮
5. 填写复核人姓名、选择复核状态、输入复核意见
6. 点击"保存"，复核意见会保存到本地数据库

**复核状态说明**:
- **待确认**: 需要进一步核实
- **已确认**: 确认为连续性问题
- **已忽略**: 误报或不影响剧情
- **已解决**: 问题已修复

### 5. 导出报告

1. 点击左侧菜单"导出报告"
2. 选择导出选项：
   - 包含已解决的问题
   - 包含已忽略的问题

3. 选择导出格式：

#### Markdown 复盘单 (推荐)
- 格式美观，适合打印
- 包含项目信息、问题统计、问题详情、场景列表
- 适合作为正式文档存档

#### CSV 问题表
- 适合导入 Excel 进行筛选、排序
- 包含所有问题的完整信息
- 方便制作报表

#### JSON 审计包
- 包含最完整的数据
- 适合程序处理、数据备份
- 包含版本信息、统计摘要、所有原始数据

## 规则检测详解

### 道具状态跳变检测

系统会跟踪同一道具在不同场景的状态变化，检测异常跳变。

**检测逻辑**:
1. 按道具名称分组状态记录
2. 按剧情顺序排序
3. 检查相邻场景的状态关键词变化
4. 状态关键词: 空、满、干净、脏、破、新、有、无、开、关

**示例**:
- 场景 1: 咖啡杯 = "满"
- 场景 2: 咖啡杯 = "空"
- → 检测为跳变，需要确认是否有合理的剧情解释

### 伤口连续性检测

检测伤口状态变化是否符合时间逻辑。

**检测逻辑**:
1. 按演员分组伤口记录
2. 按剧情顺序排序
3. 检测异常状态变化:
   - 伤口消失但无愈合/包扎记录 → **严重问题**
   - 新伤→结痂但中间场景不足3个且无"时间流逝"标记 → **警告**

**状态关键词**: 新伤、旧伤、结痂、出血、包扎、拆除、新鲜、愈合

### 补拍日期检测

检测拍摄日期与剧情顺序的不一致。

**检测逻辑**:
1. 按剧情顺序排序场景
2. 检查拍摄日期是否合理递增
3. 如果剧情顺序早的场景拍摄日期反而晚：
   - 如果有"补拍"标记 → **信息** (正常补拍)
   - 如果没有标记 → **警告** (可能是补拍但未标记)

**备注关键词**: 补拍、reshoot

### 时间线一致性检测

检测日夜、内外景的突变是否有转场标记。

**检测逻辑**:
1. 按剧情顺序排序场景
2. 检查相邻场景的日夜/内外景变化
3. 如果变化且无转场标记 → **信息**

**转场关键词**: 转场、时间流逝、第二天、隔天、换妆、回家

### 照片证据检测

检测场记记录中引用的照片是否存在。

**检测逻辑**:
1. 检查所有有 `photoReference` 字段的记录
2. 在照片目录中查找匹配的文件名
3. 如果找不到匹配照片 → **警告**

**匹配规则**: 文件名包含照片引用、道具名+场次号

### 服装缺记录检测

检测场次表中记录的服装是否有对应的场记确认。

**检测逻辑**:
1. 检查场次表中的 costumes 字段
2. 检查是否有对应的道具状态记录 (type=costume)
3. 检查演员通告中的服装信息
4. 如果场次表有记录但没有场记确认 → **警告/信息**

### 演员日程冲突检测

检测演员在同一天的场景安排时间是否过近。

**检测逻辑**:
1. 按演员分组通告
2. 按日期分组
3. 检查同一天内相邻场景的时间间隔
4. 间隔小于2小时 → **警告** (可能没有足够时间换装/转场)

## 常见问题

### Q: 应用检测到的问题一定是穿帮吗？

不一定。系统检测的是**潜在的**连续性问题，需要场记人工复核。有些情况是合理的：
- 场景间有时间跳跃（建议在备注中添加"时间流逝"标记）
- 道具状态变化有合理的剧情解释
- 非顺序拍摄是正常的制作流程

### Q: 如何让检测结果更准确？

1. **完善场记记录**: 确保每个场景的道具、服装、伤口、妆容都有详细的状态记录
2. **使用状态关键词**: 记录状态时使用系统可识别的关键词（见前文列表）
3. **添加转场标记**: 在有时间流逝或场景跳跃的场景备注中添加"转场"、"时间流逝"等关键词
4. **标记补拍**: 补拍场景的备注中添加"补拍"关键词

### Q: 支持中文列名吗？

支持。数据解析器支持中文列名和英文列名，例如：
- `sceneNumber` 或 `场次号`
- `sceneName` 或 `场景名称`
- `shootDate` 或 `拍摄日期`
- `actors` 或 `演员`
- `props` 或 `道具`

### Q: 数据会上传到云端吗？

不会。这是一个完全本地化的桌面应用，所有数据都存储在本地 SQLite 数据库中，不会上传到任何服务器。
