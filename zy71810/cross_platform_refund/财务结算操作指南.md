# 跨平台退款补单 - 财务结算操作指南

> **适用人群**：财务结算一线同事、财务主管  
> **目标**：简单、准确、高效地完成跨平台退款补单对账

---

## 📋 一、快速上手三步法

### 第1步：准备文件 → 放对位置

**对账单文件放哪里？**
```
cross_platform_refund/data/input/
```

**文件格式要求**：
| 文件类型 | 必填列 | 可选列 |
|---------|--------|--------|
| **对账单** | 交易流水号、交易时间、交易金额、支付平台 | 商户订单号、用户账号、商品名称、备注 |
| **退款流水** | 退款流水号、原交易流水号、退款金额、退款时间、退款状态 | 退款原因、操作人、备注 |

**💡 小技巧**：
- 第一次用可以先执行 `refund generate-samples` 生成样例文件，照着格式填
- 文件名不用特意改，系统会自动记录来源
- 支持 Excel (.xlsx/.xls) 和 CSV 格式

---

### 第2步：跑起来 → 三条命令搞定

打开终端，进入项目目录：
```bash
cd cross_platform_refund
```

**命令1：导入对账单**
```bash
refund import-reconciliation data/input/对账单5月.xlsx
```
✅ 成功提示：显示新增多少条，跳过了多少条重复的

**命令2：导入退款流水**
```bash
refund import-refund data/input/支付宝退款5月.xlsx
```

**命令3：自动匹配补单**
```bash
refund match
```
✅ 匹配结果会告诉你：
- 多少条匹配成功（金额一致，可直接确认）
- 多少条金额不匹配（需要人工看看）
- 多少条找不到对账单（需要人工补录）

---

### 第3步：看结果 → 按需处理

**查看整体进度**
```bash
refund status
```
📊 会显示一个漂亮的统计表格，告诉你：
- 总记录数、总金额
- 已确认多少、待补录多少、人工修改过多少
- 按支付平台分类的金额

**查看待处理的记录**
```bash
refund list --status 待补录
```
👀 每条记录都有「处理口径说明」，告诉你为什么待处理

**查看某平台的记录**
```bash
refund list --platform 支付宝
```

**自定义筛选**
```bash
refund list --filter "补单金额>1000,补单状态=待补录"
```

## 🔧 二、日常操作详解

### ✅ 确认补单
单条确认：
```bash
refund confirm BD20240531A1B2C3 --operator 张会计
```

批量确认（推荐！选中所有没问题的一起确认）：
```bash
refund confirm BD20240531A1B2C3 BD20240531D4E5F6 --operator 张会计
```

### ✏️ 人工修改
金额不对？改！
```bash
refund modify BD20240531A1B2C3 --amount 250.50 --operator 张会计
```

补充说明？改！
```bash
refund modify BD20240531A1B2C3 --remark "客户使用优惠券，实际退款250.50" --operator 张会计
```

修改处理口径？改！
```bash
refund modify BD20240531A1B2C3 --criteria "人工核实，客户使用了50元优惠券" --operator 张会计
```

### ↩️ 撤回修正
**发现之前确认错了？先撤回再重新导入**
```bash
refund revoke BD20240531A1B2C3 --operator 张会计
```

批量撤回：
```bash
refund revoke BD20240531A1B2C3 BD20240531D4E5F6 --operator 张会计
```

> **🔄 修正流程**：撤回 → 修改原始文件 → 重新导入 → 重新匹配 → 确认

## 📤 三、给财务主管的对账说明

### 生成完整对账说明
```bash
refund report
```

📁 生成的 Excel 文件在 `data/output/` 目录，包含 **7个工作表**：

| 工作表 | 内容说明 | 给主管看什么 |
|--------|----------|-------------|
| **一、汇总概览** | 整体统计数字 | 总金额、处理进度、各平台分布 |
| **二、已确认记录** | 系统自动匹配+人工确认无误的 | 可直接入账的部分 |
| **三、待补录记录** | 需要人工处理的，带「待办事项」列 | 还有多少没搞定，分别是什么问题 |
| **四、人工修改记录** | 所有改过的记录，保留修改痕迹 | 谁改了什么、为什么改 |
| **五、操作日志** | 所有人的所有操作记录 | 审计追溯用 |
| **六、工作表说明** | 每个表是干啥的 | 帮助理解 |
| **七、复核清单** | 导出前要检查的10项 | 确保没遗漏 |

### 单独看退款挂账
```bash
refund report --hanging-account
```

📋 专门给财务主管看的挂账明细，包含：
- 每条挂账的原因
- 建议处理时限（3-7天不等，根据问题严重程度）
- 按原因分类的汇总统计

## ✅ 四、导出对账说明前必须做的复核

### 执行命令自动显示清单
```bash
refund checklist
```

### 10项复核内容（打勾完成）：
- [ ] 1. 对账单导入数 = 银行/平台给的原始文件数
- [ ] 2. 退款流水导入数 = 银行/平台退款明细数
- [ ] 3. 已确认记录没有金额异常（单笔过大/过小）
- [ ] 4. 人工修改记录的原因都写清楚了
- [ ] 5. 待补录记录都安排人跟进了
- [ ] 6. 没有重复补单（一个原交易流水号只对应一条有效记录）
- [ ] 7. 所有已确认记录的处理口径都写明白了
- [ ] 8. 已确认总金额 = 财务系统里的退款挂账金额
- [ ] 9. 操作日志完整，修改和撤回都有记录
- [ ] 10. 本次对账期间的交易都覆盖了，没遗漏

> **⚠️ 重要提醒**：第8条是红线！对不上绝对不能导出！

## 🔍 五、去哪找退款挂账？

**方法1：看状态汇总**
```bash
refund status
```
→ 「待补录记录」就是挂账，金额直接显示

**方法2：导出挂账明细**
```bash
refund report --hanging-account
```
→ 生成独立的 Excel 文件，可直接发给相关同事跟进

**方法3：筛选查看**
```bash
refund list --status 待补录
```
→ 实时查看当前挂账情况

## ❓ 六、常见问题（人话版）

### Q1：导入时提示「文件格式不对」怎么办？
**A**：
1. 看看文件是不是真的 Excel 或 CSV，别把后缀改了就完事
2. Excel 文件是不是正被你自己或别人打开着？关掉再试
3. 文件是不是损坏了？重新从银行/平台下载一份

### Q2：提示「缺少必要的列」怎么办？
**A**：照着提示补列就行。比如提示缺「交易流水号」，就在 Excel 里加一列，标题写「交易流水号」。

### Q3：导入时说有重复记录怎么办？
**A**：
- 如果是误导入了两次：忽略就行，系统自动跳过了
- 如果是要更新记录：先 `refund revoke` 撤回旧的，再重新导入

### Q4：匹配时好多「金额不匹配」怎么办？
**A**：大概率是优惠券、手续费、部分退款的问题：
1. 看看对账单和退款流水的备注有没有说明
2. 核实实际退款金额
3. 用 `refund modify` 修改金额，记得写上原因
4. 然后 `refund confirm` 确认

### Q5：记录状态不对，不能确认/撤回？
**A**：状态流转是有规矩的：
```
待补录 → 已确认 / 人工修改
已确认 / 人工修改 → （先撤回） → 待补录 → 重新处理
已撤回 → 不能再改，只能重新导入匹配
```

### Q6：筛选条件怎么写？
**A**：格式是「列名=值」，多个条件用逗号分开：
- 等于：`补单状态=已确认`
- 不等于：`对账单_支付平台!=支付宝`
- 大于：`补单金额>1000`
- 小于：`补单金额<100`
- 组合：`补单状态=待补录,补单金额>500`

### Q7：导出失败怎么办？
**A**：
1. 目标文件夹有没有权限？
2. 文件是不是正被 Excel 打开着？关掉！
3. 路径里有没有中文特殊字符？换个简单的路径试试

## 💡 八、让一线愿意用的设计原则

1. **错误提示不说人话不罢休** - 绝对没有堆栈、没有内部字段名
2. **重复导入不捣乱** - 自动检测重复，不会覆盖也不会报错卡死
3. **撤回修正超简单** - 错了就撤，撤了重来，不留糊涂账
4. **筛选导出口径一致** - 你在屏幕上看到的筛选结果，导出来就是一模一样的
5. **给主管的东西分清楚** - 已确认、待补、人工改过，三个sheet清清楚楚
6. **操作全留痕** - 谁什么时候干了什么，日志里全有，审计无忧
