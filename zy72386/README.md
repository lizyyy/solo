# 粮仓通风阻力复盘

粮仓通风阻力复盘工具，面向设备工程师和安全员，解决维修群截图一晚到后原始判断变化、返工无痕迹、传感器重启后编号变更难以追踪等痛点。

## 快速开始

```bash
# 安装依赖
npm install

# 启动开发服务器（前端 + 后端同时启动）
npm run dev
```

前端访问 http://localhost:5173，后端 API 运行在 http://localhost:3001。

## 从样例跑到报告

### 第一步：导入设备铭牌参数

1. 打开 http://localhost:5173/import
2. 填写批次标签（如"1号仓首次导入"）
3. 填写操作人（如"何工"）
4. 上传 `sample/first_import.csv`，点击上传
5. 系统显示导入结果：5 条记录，0 重复，0 异常

### 第二步：传感器重启后再次导入

1. 再次上传 `sample/second_import_after_restart.csv`
2. 系统检测到：
   - S-001：已存在，标记为"编号变更"
   - S-002-B：S-002 的传感器重启后编号变了，自动创建"待复核"记录
   - S-006：新传感器
3. 此时异常数 = 2（S-001 重复 + S-002 编号变更）

### 第三步：复盘工作台审核

1. 进入 http://localhost:5173/review，选择刚导入的批次
2. 步骤指示器显示"卡在步骤2：维修群截图补看"
3. 传感器编号变更卡片显示：
   - S-001：旧编号 → 新编号（需复核）
   - S-002 → S-002-B：传感器重启后编号变更（卡在步骤2）
4. **安全员**无需询问设备工程师，即可看到每条变更卡在哪一步
5. 确认后，记录进入步骤3（安全提醒更新）
6. 驳回则退回步骤2

### 第四步：运行自检

1. 进入 http://localhost:5173/selfcheck，选择批次
2. 点击"运行自检"
3. 查看四项自检结果：重复导入、编号变更、补录重算、导出一致性

### 第五步：导出报告

1. 进入 http://localhost:5173/export，选择批次
2. 选择导出范围（全部/仅异常/仅待复核）
3. 点击"导出"下载 CSV
4. 点击"一致性校验"验证数据一致性

## 功能概览

| 页面 | 路径 | 功能 |
|------|------|------|
| 首页仪表盘 | / | 待复核事项概览、摘要卡片、最近导入 |
| 数据导入 | /import | CSV/Excel 上传、重复检测、导入历史 |
| 复盘工作台 | /review | 三步工作流、编号变更卡片、数据明细、手动编辑 |
| 自检面板 | /selfcheck | 四项自检：重复导入、编号变更、补录重算、导出一致 |
| 审计追踪 | /audit | 变更时间线、原始行号对照 |
| 导出报告 | /export | CSV 导出、一致性校验 |

## 自检覆盖

1. **重复导入**：跨批检测 sensor_id 重复
2. **传感器编号变更**：检测待复核的编号变更记录
3. **补录后重算**：检测已编辑但未推进步骤的记录
4. **导出一致性**：SHA256 哈希校验导出数据与数据库一致

## 数据一致性保证

导出明细、页面展示、接口返回均读取同一份 SQLite 数据。导出时通过 `X-Consistency-Hash` 头和一致性校验接口确保数据不会出现"一个地方显示异常、另一个地方消失"的问题。

## 审计追踪

每条记录保留：
- 原始行号（original_row_number）
- 人工改动（manual_edits 表，含字段、旧值、新值、操作人、时间）
- 当前处理状态（status + current_step）
- 完整变更时间线（audit_log 表）

安全员追问时，可在审计追踪页面查看完整证据链。

## 交接体验

安全员打开复盘结果时：
- 顶部横幅显示"待复核事项 N 项"
- 传感器编号变更卡片明确标注"卡在步骤2：维修群截图补看"
- 底部交接信息框汇总：N 条记录 / M 条编号变更待复核 / K 条异常
- 无需询问设备工程师即可理解完整上下文

## 技术栈

- 前端：React 18 + TypeScript + Tailwind CSS + Zustand
- 后端：Express 4 + TypeScript (ESM)
- 数据库：SQLite (better-sqlite3)
- 文件解析：papaparse (CSV) + xlsx (Excel)
