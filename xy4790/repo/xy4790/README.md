# 社区共享工具柜

一个用于社区共享工具柜管理的本地全栈应用，支持工具的预约、借出、归还、报修等操作，具备完整的状态机和并发控制机制。

## 功能特性

### 核心功能
- **工具管理**: 8 种预设工具（螺丝刀套装、活动扳手、电钻、锤子、卷尺、万用表、梯子、手推车）
- **操作按钮**: 预约、取消预约、借出、归还、报修、完成维修
- **状态机控制**: 严格的状态流转验证，后端拒绝非法状态跳转
- **并发控制**: 乐观锁机制，防止重复点击和多浏览器同时操作
- **持久化存储**: SQLite 单文件数据库，重启服务数据不丢失
- **操作日志**: 完整记录所有操作，支持查看最近 50 条记录
- **CSV 导出**: 支持导出当天借还记录

### 状态流转
```
可用 (AVAILABLE)
    ↓ 预约              ↓ 报修
已预约 (RESERVED) → 维修中 (UNDER_REPAIR)
    ↓ 借出                    ↓ 完成维修
已借出 (BORROWED) ←─── 可用 (AVAILABLE)
    ↓ 归还              ↑ 完成维修
可用 (AVAILABLE) ←──────┘
```

## 技术栈

- **后端**: Node.js + Express
- **数据库**: SQLite (better-sqlite3)
- **前端**: 原生 HTML/CSS/JavaScript
- **并发控制**: 乐观锁 (version 字段) + 数据库事务

## API 接口

### GET /api/tools
获取所有工具列表（包含状态、预约人、借用人等信息）

### GET /api/tools/:id
获取单个工具详情

### POST /api/tools/:id/action
执行工具操作

**请求体:**
```json
{
  "action": "RESERVE",
  "userId": 1,
  "description": "可选，仅报修时使用"
}
```

**可用 Action:**
- `RESERVE` - 预约
- `CANCEL_RESERVATION` - 取消预约
- `BORROW` - 借出
- `RETURN` - 归还
- `REPORT_REPAIR` - 报修
- `COMPLETE_REPAIR` - 完成维修

### GET /api/logs
获取最近操作日志

### GET /api/export/today
导出当天借还记录 CSV

### GET /api/users
获取用户列表

## 并发控制机制

### 实现原理

系统采用**乐观锁**机制防止并发冲突：

1. **Version 字段**: 每个工具都有一个 `version` 字段，初始值为 1
2. **事务隔离**: 所有操作在数据库事务中执行
3. **版本校验**: 更新时检查 version 是否与读取时一致
4. **版本递增**: 更新成功后 version 自动 +1

### 关键代码

```javascript
// 伪代码示意
db.transaction(() => {
  // 1. 重新读取当前状态和版本
  const currentTool = db.prepare('SELECT * FROM tools WHERE id = ?').get(toolId);
  
  // 2. 检查版本是否一致
  if (currentTool.version !== tool.version) {
    return { success: false, error: '并发冲突' };
  }
  
  // 3. 执行更新时使用 version 做条件
  db.prepare(`
    UPDATE tools SET status = ?, version = version + 1
    WHERE id = ? AND version = ?
  `).run(newStatus, toolId, tool.version);
});
```

## 验证并发/重复点击

### 方法一：运行测试脚本

1. **启动服务**（新终端）:

2. **运行测试**（另一个终端）:

测试脚本会执行以下场景：

### 方法二：手动测试（推荐）

#### 测试重复点击

1. 打开浏览器访问 http://localhost:3000
2. 选择一个操作人
3. **快速双击**某个可用工具的"预约"按钮
4. 观察结果：
   - 第一个请求成功，工具变为"已预约"
   - 第二个请求失败，提示"工具已被预约"
   - 页面自动刷新到正确状态

#### 测试多浏览器并发

1. **浏览器 A**: 打开 http://localhost:3000，选择用户"张三"
2. **浏览器 B**: 打开 http://localhost:3000，选择用户"李四"
3. **同时**点击同一个可用工具的"预约"按钮
4. 观察结果：
   - 只有一个浏览器会预约成功
   - 另一个浏览器会收到错误提示
   - 两个浏览器刷新后显示一致的状态

#### 测试非法状态跳转

1. 使用 Postman 或 curl 直接调用 API：
```bash
# 尝试从 AVAILABLE 直接 BORROW（跳过 RESERVE）
curl -X POST http://localhost:3000/api/tools/1/action \
  -H "Content-Type: application/json" \
  -d '{"action":"BORROW","userId":1}'
```

2. 预期返回：
```json
{
  "success": false,
  "error": "无法执行操作: 当前状态 AVAILABLE 不允许 BORROW"
}
```

## 按钮禁用逻辑

按钮状态由**后端返回的真实状态**决定，前端仅做展示：

| 工具状态 | 可点击按钮 | 禁用按钮及原因 |
|---------|-----------|---------------|
| 可用 | 预约、报修 | 取消预约（工具未被预约）、借出（需要先预约）、归还（工具未被借出） |
| 已预约 | 取消预约、借出、报修 | 预约（工具已被预约）、归还（工具未被借出） |
| 已借出 | 归还、报修 | 预约（工具已被借出）、取消预约（工具未被预约）、借出（工具已被借出） |
| 维修中 | 完成维修 | 其他所有按钮（工具正在维修中） |

## 持久化存储

数据存储在 SQLite 数据库文件 `tool-cabinet.db` 中：

- **工具表**: 存储工具信息和状态
- **用户表**: 存储志愿者信息
- **预约表**: 预约记录
- **借还记录表**: 借出/归还记录
- **维修记录表**: 报修/维修记录
- **操作日志表**: 所有操作的流水记录

**重启服务后数据不会丢失**。如需重置数据，删除 `tool-cabinet.db` 文件后重启服务即可（会重新初始化 8 个工具和 3 个用户）。

## 常见问题

### Q: 为什么按钮是灰色的？
A: 可能原因：
- 未选择操作人（页面顶部下拉框）
- 工具当前状态不允许该操作（鼠标悬停可查看原因）

### Q: 操作失败后页面会自动刷新吗？
A: 是的。无论操作成功还是失败，页面都会从后端重新获取最新状态，确保数据一致。

### Q: 如何查看操作历史？
A: 页面右侧"最近操作流水"区域会显示最近 50 条操作记录。

### Q: 如何导出数据？
A: 点击页面顶部"导出今日记录"按钮，会下载当天的借还记录 CSV 文件。
