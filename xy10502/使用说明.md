# 线下培训签到补录 CLI 使用说明

## 项目概述

这是一个实用型的线下培训签到补录 CLI 工具，专门解决培训运营中"二维码签到、纸质名单和讲师补录"混杂在一起的混乱局面。工具围绕"可解释、可追溯、可审计"三大原则设计，让结课时的课时质疑有据可查。

---

## 一、本地启动

### 1. 环境准备

需要 Python 3.7+，然后安装依赖：

```bash
pip3 install click tabulate
```

或使用项目提供的 requirements.txt：

```bash
pip3 install -r requirements.txt
```

### 2. 基本使用方式

在项目目录下运行：

```bash
python3 signin <命令> [选项]
```

如果给 signin 文件赋予了执行权限，也可以直接：

```bash
./signin <命令> [选项]
```

查看帮助：

```bash
python3 signin --help
```

## 二、命令总览

| 命令 | 功能 | 说明 |
|------|------|------|
| `init` | 初始化项目 | 创建数据目录、生成样例数据 |
| `import` | 导入数据 | 支持学员名单、课程安排、扫码记录、补录表 |
| `check` | 校验数据 | 检查冲突、迟到早退、数据问题 |
| `detail` | 查看详情 | 查看学员/课程/导入批次详情和历史记录 |
| `report` | 生成报告 | 结课统计、课时结算、争议原因清单 |
| `review-makeup` | 审核补录 | 人工审核补录申请（通过/驳回） |

## 三、项目初始化与样例数据

### 1. 初始化项目

```bash
python3 signin init
```

首次运行会创建：
- `.signin/` - 数据主目录
- `.signin/input/` - 输入文件目录
- `.signin/output/` - 输出文件目录
- `.signin/meta.json` - 元数据
- `.signin/db.json` - 数据存储

同时会在 `.signin/input/` 下生成**完整样例数据**。

### 2. 强制重新初始化

如果想清空数据重新开始：

```bash
python3 signin init --force
```

### 3. 样例数据说明

`init` 命令自动生成的样例覆盖以下业务场景：

| 场景 | 样例数据 | 预期结果 |
|------|----------|----------|
| 正常签到 | 张三（08:55 扫码） | 出勤 ✓ |
| 迟到 | 李四（09:30 扫码） | 迟到，扣减 50% 课时 |

## 四、数据格式说明

所有导入文件均为 **CSV 格式**，UTF-8 编码。

### 1. 学员名单 (students.csv)

| 字段 | 说明 | 必填 |
|------|------|------|
| 姓名 | 学员姓名 | 是 |
| 手机 | 手机号（唯一标识） | 是 |
| 部门 | 所属部门 | 否 |

示例：
```csv
姓名,手机,部门
张三,13800000001,技术部
李四,13800000002,市场部
```

### 2. 课程安排 (courses.csv)

| 字段 | 说明 | 必填 |
|------|------|------|
| 课程名称 | 课程名（唯一） | 是 |
| 讲师 | 授课讲师 | 是 |
| 开始日期 | 格式：YYYY-MM-DD | 是 |
| 结束日期 | 格式：YYYY-MM-DD（跨天则不同） | 是，默认同开始日期 |
| 开始时间 | 格式：HH:MM | 否，默认 09:00 |
| 结束时间 | 格式：HH:MM | 否，默认 17:00 |
| 总课时 | 小时数 | 否，默认 8.0 |

示例（单日课程）：
```csv
课程名称,讲师,开始日期,结束日期,开始时间,结束时间,总课时
Python入门培训,王老师,2026-05-10,2026-05-10,09:00,17:00,8.0
```

示例（跨天课程）：
```csv
课程名称,讲师,开始日期,结束日期,开始时间,结束时间,总课时
数据分析进阶,李老师,2026-05-11,2026-05-12,09:00,17:00,16.0
```

### 3. 二维码扫码记录 (qr_records.csv)

| 字段 | 说明 | 必填 |
|------|------|------|
| 姓名 | 学员姓名 | 至少填一个 |
| 手机 | 学员手机号 | 至少填一个 |
| 课程 | 课程名称 | 是 |
| 扫码时间 | 格式：YYYY-MM-DDTHH:MM:SS | 否 |

示例：
```csv
姓名,手机,课程,扫码时间
张三,13800000001,Python入门培训,2026-05-10T08:55:00
李四,13800000002,Python入门培训,2026-05-10T09:30:00
```

### 4. 讲师补录表 (makeup_applications.csv)

| 字段 | 说明 | 必填 |
|------|------|------|
| 姓名 | 学员姓名 | 至少填一个 |
| 手机 | 学员手机号 | 至少填一个 |
| 课程 | 课程名称 | 是 |
| 补录原因 | **必须填写**（校验规则） | 是 |
| 提交人 | 提交补录的人（通常是讲师） | 否，默认"讲师" |
| 提交时间 | 格式：YYYY-MM-DDTHH:MM:SS | 否 |
| 状态 | pending/approved/rejected | 否，默认 pending |

示例：
```csv
姓名,手机,课程,补录原因,提交人,提交时间,状态
王五,13800000003,Python入门培训,现场纸质签到，设备故障,王老师,2026-05-10T17:30:00,approved
赵六,13800000004,Python入门培训,忘记扫码，有签到纸,王老师,2026-05-10T18:00:00,rejected
```


**报告包含**：

## 七、核心规则说明

### 1. 签到状态判定规则

| 状态 | 判定条件 | 课时处理 |
|------|----------|----------|
| 出勤 (present) | 签到时间 ≤ 课程开始+15分钟 | 100% 计课时 |
| 迟到 (late) | 签到时间 > 课程开始+15分钟 | 50% 计课时（可配置） |
| 早退 (early_leave) | 签退时间 < 课程结束-15分钟 | 50% 计课时（可配置） |
| 缺勤 (absent) | 无签到记录或签到无效 | 0% 计课时 |

### 2. 幂等性规则

重复执行同一导入命令时：
- 学员：姓名+手机号已存在 → 跳过（不报错）
- 课程：课程名称已存在 → 跳过
- 扫码：同一学员同一课程同一天已扫码 → 跳过
- 补录：同一学员同一课程已有补录申请 → 跳过

### 3. 补录审核规则

- **必填校验**：补录原因必须填写且不少于 2 个字符
- **身份校验**：补录学员必须在学员名单中
- **审核影响**：
  - `approved` → 自动创建签到记录，计入出勤
  - `rejected` → 不计入出勤，保留驳回记录用于解释
  - `pending` → 待审核，结课时会标记为"争议课时"

### 4. 名单外人员处理

扫码或补录时，人员不在学员名单 → **导入失败**，不计入任何统计。

### 5. 手机号冲突处理

多名学员使用同一手机号 → **数据冲突警告**，check 时高亮显示，但不阻止导入（运营需人工处理）。

## 八、如何判断业务是否真的闭环？

不需要看源码，只需关注 `report` 命令的 **[业务闭环检查]** 部分：

### ✅ 业务已闭环（可以结课结算）

报告末尾显示：
```
[业务闭环检查]
✓  所有数据闭环，可以结课结算
```

表示：
1. 所有学员要么有有效签到，要么补录已审核完成
2. 不存在待审核的补录申请
3. 不存在手机号冲突

### ⚠ 业务未闭环（暂不能结课）

报告末尾显示：
```
[业务闭环检查]
⚠  存在未闭环项，请先处理后再结课：
   - 课程 'Python入门培训' 有 32.00 小时争议
   - 存在 3 条补录申请待审核
   - 发现 1 个手机号冲突
```

### 需要人工处理的场景

1. **争议课时** → 查看 `[争议/不可结算明细]`，逐条处理：
   - "无任何签到/补录记录" → 核实是否真的缺勤
   - "补录待审核" → 执行 `review-makeup` 命令
   - "补录被驳回" → 确认驳回理由是否充分
   - "迟到/早退扣减" → 确认规则是否适用

2. **待审核补录** → 使用 `review-makeup` 审核：

   ```bash
   # 通过补录（先从 report 或 detail 获取 makeup_id）
   python3 signin review-makeup <makeup_id> --approve --reviewer 张主管 --comment "有纸质签到证据"
   
   # 驳回补录
   python3 signin review-makeup <makeup_id> --reject --reviewer 张主管 --comment "证据不足"
   ```

3. **手机号冲突** → 核实哪个是正确的，修正后重新导入

## 十二、常见问题

**Q: 重复导入会怎么样？**
A: 不会重复创建数据，重复记录会被"跳过"（幂等处理），可以安全地重复执行 import 命令。

**Q: 补录为什么要必填原因？**
A: 这是业务规则设计，防止随意补录，所有补录必须有正当理由并可追溯。

**Q: 名单外的人扫码了怎么处理？**
A: 导入时直接失败，不计入任何统计，避免混入无关人员。

**Q: 跨天课程的签到怎么算？**
A: 目前按单条记录处理，如果需要更精细的跨天签到，可以每天单独生成一条记录。

**Q: 数据可以备份吗？**
A: 可以，直接复制整个 `.signin/` 目录即可。
