## 一、本地启动

### 1.1 环境要求
- Node.js >= 14.0.0

### 1.2 快速开始

```bash
cd /Users/mac/pro/solo/workspaces/xy10532
```

为了方便使用，可以创建别名：
```bash

echo 'alias claim="node /Users/mac/pro/solo/workspaces/xy10532/bin/claim.js"' >> ~/.zshrc
source ~/.zshrc
```

## 三、主要演示路径（完整闭环）

### 3.1 路径一：完整审核流程（推荐）

```bash
# Step 1: 初始化
claim init

# Step 2: 导入样例
claim import --sample

# Step 3: 查看案件列表
claim list

# Step 4: 批量审核所有案件
claim check --all

# Step 5: 生成审核报告
claim report

# Step 6: 查看某个案件详情（以张三为例）
claim detail --case OP-2025001

# Step 7: 查看操作历史
claim history --case OP-2025001
```

### 3.2 路径二：需补件 → 人工补件 → 审核通过

演示：李四案件（缺少诊断证明书）

```bash
# Step 1: 查看李四案件详情
claim detail --case OP-2025002
# 观察：状态为"需补件"，错误提示"缺少必需材料: 诊断证明书"

# Step 2: 人工补件（模拟理赔专员补充材料）
claim correct --case OP-2025002 \
  --addMaterial "诊断证明书_李四.pdf|DIAGNOSIS_CERTIFICATE|hospital" \
  --operator "理赔专员-李丽"
# 观察：
# 1. 显示修正项数：1
# 2. 显示变更明细
# 3. 自动重新审核后，状态变为"✅ 可受理"

# Step 3: 再次查看报告
claim report
# 观察：李四从"需补件"列表消失，出现在"可受理"列表
# 观察：补件历史摘要显示了李丽的操作记录

# Step 4: 查看历史记录
claim history --case OP-2025002
# 观察：
# 1. 看到完整的操作链：IMPORT → CHECK → CORRECT → CHECK
# 2. CORRECT 记录显示操作者"理赔专员-李丽"
# 3. 显示变更前后的完整对比
# 4. 显示具体的差异明细
```

### 3.3 路径三：金额异常案件

演示：王五案件（发票与清单金额不一致）

```bash
# Step 1: 查看王五案件
claim detail --case OP-2025003
# 观察：
# 状态：💰 金额异常
# 错误：发票金额 ¥1250.00 与费用清单金额 ¥1150.00 不一致，差额 ¥100.00

# Step 2: 人工修正金额（假设清单正确，修正发票金额）
claim correct --case OP-2025003 \
  --materialId M008 \
  --fixAmount 1150 \
  --operator "理赔专员-王芳"

# Step 3: 再次查看详情
claim detail --case OP-2025003
# 观察：状态变为"✅ 可受理"
```

### 3.4 路径四：重复票据处理

演示：孙七案件（同一张发票上传两次）

```bash
# Step 1: 查看孙七案件
claim detail --case IP-2025002
# 观察：错误提示"重复票据: 发票号 INV-HP-2025-0056790 已存在"
# 材料 M016 和 M017 是同一张发票的两个副本

# Step 2: 移除重复的副本
claim correct --case IP-2025002 \
  --removeDuplicate \
  --materialId M017 \
  --operator "理赔专员-张伟"

# Step 3: 验证
claim detail --case IP-2025002
# 观察：状态变为"✅ 可受理"
```

### 3.5 路径五：类型不确定材料处理

演示：吴九案件（两份材料类型不确定）

```bash
# Step 1: 查看吴九案件
claim detail --case TA-2025002
# 观察：
# 错误：缺少必需材料: 病历资料 (MEDICAL_RECORD)
# 警告：2 份材料类型不确定（扫描件和照片）

# Step 2: 人工识别并标记类型 + 补充病历
# 假设扫描件是病历，照片是X光片
claim correct --case TA-2025002 \
  --materialId M027 \
  --fixType MEDICAL_RECORD \
  --operator "理赔专员-陈静"

# Step 3: 再次审核
claim check --case TA-2025002
# 观察：
# 错误已解决（因为 M027 被识别为病历）
# 仍有 1 个警告（照片类型不确定）
# 状态变为"⚠️ 可受理(有警告)"
```

## 四、失败路径演示

### 4.1 场景：缺少必需材料且未补件

目标：演示什么情况下案件无法通过审核

```bash
# Step 1: 查看李四案件（初始状态，缺少诊断书）
# 假设我们没有执行人工补件

# Step 2: 反复尝试审核（幂等性验证）
claim check --case OP-2025002
# 第1次：状态 → 需补件

claim check --case OP-2025002
# 第2次：显示"ℹ️ 幂等检测: 结果与上次一致"
# 状态保持"需补件"，不会产生新的错误

claim check --case OP-2025002
# 第3次：同样显示幂等检测
# 说明：重复执行检查不会改变结果，保证幂等性

# Step 3: 查看历史记录
claim history --case OP-2025002
# 观察：多次 CHECK 操作都会被记录
# 第1次 CHECK: status从IMPORTED→NEEDS_SUPPLEMENT
# 第2次 CHECK: 标记 idempotent: true
# 第3次 CHECK: 标记 idempotent: true

# Step 4: 查看报告
claim report
# 观察：李四始终在"需补件"列表中
# 直到人工补充诊断证明书
```

### 4.2 场景：必需材料不可豁免

系统规则：必需材料不能标记为"豁免"

```bash
# 假设某案件的诊断证明书被错误地标记为 waived: true
# 系统会检测并报错：[WAIVED_REQUIRED] 必需材料不可豁免
```

### 4.3 场景：跨案件重复票据

如果两个案件使用了同一张发票号：

```bash
# 案件A的发票号：INV-001
# 案件B的发票号：INV-001（与A重复）
# 审核案件B时会报错：
# [DUPLICATE_INVOICE] 重复票据: 发票号 INV-001 已存在 (案件 A)
```

## 六、审核规则说明

### 6.1 核心规则

1. **重复票据检测**：同一张发票号不能在同一案件或跨案件重复出现
2. **金额一致性**：发票金额必须与费用清单金额一致（允许误差 ¥0.01）
3. **必需材料**：缺少必需材料直接判定"需补件"
4. **类型不确定**：材料类型识别为 UNCERTAIN 时产生警告
5. **豁免限制**：必需材料不可豁免

### 6.2 各类理赔必需材料

**门诊理赔 (outpatient)**:
- ✅ 诊断证明书
- ✅ 门诊发票
- ✅ 门诊费用清单
- ⚪ 门诊病历（非必需）

**住院理赔 (inpatient)**:
- ✅ 出院小结
- ✅ 住院发票
- ✅ 住院费用清单
- ✅ 诊断证明书
- ⚪ 入院记录（非必需）

**交通事故理赔 (traffic_accident)**:
- ✅ 交通事故认定书
- ✅ 医疗发票
- ✅ 医疗费用清单
- ✅ 诊断证明书
- ✅ 病历资料
- ✅ 身份证
- ⚪ 驾驶证/行驶证（非必需）

## 九、业务闭环验证

通过以下步骤验证业务闭环：

1. **导入数据** → `claim import --sample`
2. **批量审核** → `claim check --all`
3. **生成报告** → `claim report`
4. **验证分类**：
   - 可受理案件：张三、赵六、周八
   - 需补件案件：李四（缺诊断书）、孙七（重复票据）、吴九（缺病历）
   - 金额异常：王五（¥1250 vs ¥1150）
5. **人工介入** → 使用 `correct` 命令补件
6. **重新审核** → `claim check --all`
7. **查看历史** → `claim history --case xxx` 验证留痕
8. **最终报告** → `claim report` 验证所有问题已解决

完成以上步骤后，如果所有案件都变为"可受理"，说明业务闭环验证通过！
