# 预约押金核销台系统

专为小型摄影工作室设计的本地预约押金管理系统，解决棚位时间冲突、押金管理无迹、月底对账麻烦等问题。

## 功能特性

### 📅 预约管理
- 新建/编辑预约：客户姓名、电话、棚位、日期、时间段、押金金额
- 日期筛选：按指定日期查看预约
- 搜索功能：按客户姓名、电话、棚位搜索

### ⏰ 棚位冲突检查
- **智能检测**：同一棚位、同一日期的时间段重叠会被拒绝保存
- **友好提示**：明确告知哪个时间段已被预约

### 🔄 状态流转（严格限制）
```
待收押金 → 已收押金 → 已核销
    ↓            ↓
  已退款       已退款
```
- **pending（待收押金）**：客户已预约但未支付押金
  - 可操作：收取押金、取消预约（退款）
- **deposited（已收押金）**：客户已支付押金
  - 可操作：核销预约、退回押金
- **verified（已核销）**：拍摄完成，押金已确认
  - 无操作：已完成状态
- **refunded（已退款）**：预约取消，押金已退回
  - 无操作：已取消状态

### ⚠️ 逾期标记
- 预约日期已过，但状态仍为"待收押金"或"已收押金"的预约
- 列表中**红色高亮**显示，醒目提醒
- 统计栏专门显示逾期数量

### 📋 审计流水
- 所有状态变更都有记录
- 记录内容：操作类型、时间、状态变化、备注
- 可追踪：每笔押金的收取、核销、退款都有迹可循

### 📊 CSV 导入导出
- **导出当日核销报表**：选择日期，导出该日所有预约
- **导出全部预约**：导出所有历史预约
- **导入历史预约**：支持中英文表头，自动识别字段

## 技术栈

- **后端**：Node.js + Express
- **数据库**：SQLite（本地文件存储）
- **前端**：原生 HTML + CSS + JavaScript
- **CSV 处理**：csv-parser + json2csv

## 快速开始

### 1. 安装依赖

```bash
npm install
```

### 2. 启动服务

```bash
npm start
```

服务启动后，访问 http://localhost:3000

### 3. 首次启动

首次启动时，系统会自动：
- 创建 SQLite 数据库文件 `data/booking.db`
- 初始化数据表
- 插入示例数据（6条预约，覆盖各种状态）

### 4. 运行测试

先确保服务已启动，然后在另一个终端运行：

```bash
npm test
```

测试内容包括：
- 服务健康检查
- 创建预约
- 棚位时间冲突检查
- 状态流转（待收押金→已收押金→已核销）
- 状态流转限制
- 搜索功能
- 直接取消预约

## API 接口

### 预约管理

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/bookings | 获取预约列表（支持日期、状态、搜索参数） |
| GET | /api/bookings/:id | 获取预约详情（含审计记录） |
| POST | /api/bookings | 创建预约 |
| PUT | /api/bookings/:id | 更新预约 |
| PATCH | /api/bookings/:id/status | 更新状态 |

### CSV 操作

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/csv/import | 导入 CSV |
| GET | /api/csv/export?date=YYYY-MM-DD | 导出指定日期核销报表 |
| GET | /api/csv/all | 导出全部预约 |

### 其他

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /health | 健康检查 |
| GET | /api/studios | 获取棚位列表 |
| GET | /api/status-info | 获取状态信息 |

## 完整业务流程演示

### 流程 1：正常预约 → 核销

```
1. 新建预约
   - 客户：张三
   - 电话：13800138001
   - 棚位：A
   - 日期：2026-05-10
   - 时间：10:00-12:00
   - 押金：500元

2. 状态变为：待收押金

3. 客户支付押金
   - 点击"收取押金"
   - 状态变为：已收押金
   - 审计记录：收取押金 ¥500

4. 拍摄完成
   - 点击"核销预约"
   - 状态变为：已核销
   - 审计记录：核销预约，押金已确认

5. 导出当日报表核对
```

### 流程 2：预约取消 → 退款

```
1. 新建预约（状态：待收押金）

2. 客户支付押金
   - 点击"收取押金"
   - 状态变为：已收押金

3. 客户取消预约
   - 点击"退回押金"
   - 状态变为：已退款
   - 审计记录：退回押金 ¥500

或：

2. 客户未支付押金直接取消
   - 点击"取消预约"
   - 状态变为：已退款
```

## CSV 导入格式

示例 CSV 文件：

```csv
客户姓名,联系电话,棚位,预约日期,开始时间,结束时间,押金金额,状态,备注
张三,13800138001,A,2026-05-10,10:00,12:00,500,已收押金,产品拍摄
李四,13900139002,B,2026-05-11,14:00,17:00,800,待收押金,人像写真
```

支持的字段名（中英文均可）：
- 客户姓名 / customer_name / name
- 联系电话 / 电话 / phone
- 棚位 / 棚位编号 / studio
- 预约日期 / 日期 / booking_date
- 开始时间 / start_time / time
- 结束时间 / end_time
- 押金金额 / deposit_amount / amount
- 状态 / status
- 备注 / note

状态值支持：
- 待收押金 / pending
- 已收押金 / deposited
- 已核销 / verified
- 已退款 / refunded

## 注意事项

1. **棚位冲突**：创建或编辑预约时，系统会自动检查同一棚位、同一日期是否有时间重叠，如有冲突会拒绝保存。

2. **状态流转限制**：
   - 待收押金 → 已收押金 / 已退款
   - 已收押金 → 已核销 / 已退款
   - 已核销 / 已退款 → 无法变更

3. **逾期判断**：预约日期 < 当前日期，且状态为"待收押金"或"已收押金"时，视为逾期。

4. **数据持久化**：所有数据存储在 `data/booking.db` SQLite 数据库文件中，重启服务不丢失。

5. **示例数据**：首次启动时会插入6条示例数据，包括1条逾期预约用于测试。
