# 民宿保洁返工追踪台

适合小民宿老板本地使用的保洁管理系统。

## 功能特性

- **房源管理**：创建、编辑、管理民宿房源
- **保洁任务派发**：创建保洁任务，指派给保洁员
- **检查结果提交**：检查保洁质量，记录问题
- **住客反馈记录**：记录住客评分和反馈
- **返工追踪**：不合格任务要求返工，防止重复返工
- **赔付管理**：处理住客投诉，记录赔付情况
- **绩效统计**：自动计算保洁员绩效评分
- **数据导出**：导出 CSV 报表，包含房源、责任人、扣分原因、处理耗时

## 技术栈

- 后端：Node.js + Express
- 数据库：SQLite（本地文件存储，无需额外服务器）
- 前端：原生 HTML + CSS + JavaScript

## 从空数据到最终导出的完整流程

### 流程概览

```
空数据 → 房源管理 → 保洁员管理 → 创建任务 → 开始保洁 → 完成保洁 → 检查保洁
                                                                 ↓
                    ┌─────────────────────────────────────────────┼─────────────────────────────────────────────┐
                    ↓                                             ↓                                             ↓
              检查通过（合格）                             检查不合格（需返工）                        住客反馈（需赔付）
                    ↓                                             ↓                                             ↓
              任务检查完成                                  返工中 → 返工完成 → 再次检查                  赔付处理
                    ↓                                             ↓                                             ↓
              任务关闭并结算                                任务关闭并结算                             任务关闭并结算
                                                                 ↓
                                                           导出报表
```

### 详细步骤

#### 步骤 1：初始化基础数据（无人工处理记录）

- **操作**：进入"房源管理"标签页，添加房源；进入"保洁员管理"标签页，添加保洁员
- **状态**：房源状态为 "active"，保洁员状态为 "active"
- **是否产生人工处理记录**：否

#### 步骤 2：创建并派发保洁任务（无人工处理记录）

- **操作**：点击"新建任务"按钮，填写房源、保洁员、入住单号、住客姓名、入住日期、退房日期等信息
- **状态流转**：`assigned`（已指派）
- **历史记录**：自动创建任务创建记录
- **是否产生人工处理记录**：否

#### 步骤 3：开始保洁（无人工处理记录）

- **操作**：保洁员点击"开始"按钮，开始保洁工作
- **状态流转**：`assigned` → `in_progress`（进行中）
- **历史记录**：自动记录开始时间和操作人
- **是否产生人工处理记录**：否

#### 步骤 4：完成保洁（无人工处理记录）

- **操作**：保洁员完成保洁后点击"完成"按钮
- **状态流转**：`in_progress` → `completed`（已完成，等待检查）
- **历史记录**：自动记录完成时间和操作人
- **是否产生人工处理记录**：否

#### 步骤 5：检查保洁质量（⚠️ 可能产生人工处理记录）

- **操作**：管理员点击"检查"按钮，填写检查结果
- **检查结果选项**：
  - `pass`（合格）：无扣分，无处罚，通过检查
  - `pass_with_issues`（有小问题但通过）：可扣分和处罚金额，记录问题
  - `fail`（不合格）：扣分、处罚，**需要返工**
- **状态流转**：
  - 合格或有小问题：`completed` → `inspected`（已检查）
  - 不合格：`completed` → `redo_needed`（需返工）
- **是否产生人工处理记录**：
  - 如果选择 `pass`（合格）或 `pass_with_issues`（有小问题但通过）：**不产生**需要返工的记录
  - 如果选择 `fail`（不合格）：**产生**返工任务记录，需要保洁员重新保洁
- **绩效影响**：扣分和处罚金额会自动累加到保洁员绩效中

#### 步骤 6：返工处理（⚠️ 需要人工处理）

- **适用情况**：当检查结果为 `fail`（不合格）时
- **操作流程**：
  1. 保洁员看到任务状态为 "需返工"，点击"开始返工"
     - 状态流转：`redo_needed` → `redo_in_progress`（返工中）
  2. 保洁员完成返工后点击"完成返工"
     - 状态流转：`redo_in_progress` → `redo_completed`（返工完成，等待检查）
  3. 管理员再次检查返工质量
     - 如果合格：状态流转到 `inspected`
     - 如果仍不合格：**系统保护**：不允许再次创建返工（防止同一入住单重复返工）
- **防重复返工机制**：
  - 每个任务只能有一次返工机会
  - 如果检查时发现已有返工记录且状态为 `redo_needed`，系统会拒绝再次创建返工
- **是否产生人工处理记录**：是，返工任务需要保洁员和管理员再次处理

#### 步骤 7：住客反馈和赔付（⚠️ 可能产生人工处理记录）

- **适用情况**：住客入住后反馈卫生问题
- **操作**：在任务详情中点击"住客反馈"，填写住客评分、问题描述、严重程度
- **反馈选项**：
  - `needs_redo`（需要返工）：住客要求重新保洁
  - `compensation_request`（要求赔偿）：住客要求经济赔偿
- **是否产生人工处理记录**：
  - 如果选择 `needs_redo`（需要返工）：产生返工记录，需要人工处理
  - 如果选择 `compensation_request`（要求赔偿）：产生赔付记录，需要人工处理
- **赔付处理**：
  - 点击"赔付处理"按钮，填写赔付原因和金额
  - 赔付金额可以选择从保洁员工资中扣除
  - 赔付金额会自动累加到保洁员的总赔付中，影响绩效评分

#### 步骤 8：任务关闭和结算（⚠️ 结算后保护）

- **操作**：任务所有流程完成后，点击"关闭"按钮
- **状态流转**：`inspected` → `closed`（已关闭）
- **结算保护机制**：
  - 任务关闭后，`is_settled` 标志会被设置为 1
  - **结算后保护**：任务关闭或结算后，所有修改操作被拒绝
  - 防止已经结算后又被随便修改
- **是否产生人工处理记录**：否，但关闭后任务被锁定，不可再修改

#### 步骤 9：导出报表（无人工处理记录）

- **操作**：点击"📥 导出报表"按钮
- **导出内容**：CSV 格式报表，包含：
  - 任务ID
  - 入住单号
  - 房源名称
  - 保洁员姓名（责任人）
  - 任务状态
  - 指派时间
  - 完成时间
  - 关闭时间
  - 处理耗时（小时）
  - 返工次数
  - 总扣分
  - 总处罚
  - 总赔付
  - 扣分原因（检查问题 + 住客反馈问题）
- **是否产生人工处理记录**：否

## 需要人工处理的关键步骤

### 1. 检查保洁质量时选择 "不合格"

- **触发条件**：检查结果选择 `fail`（不合格）
- **产生的记录**：返工任务
- **需要处理的人**：保洁员（重新保洁）、管理员（再次检查）
- **处理方式**：
  - 保洁员点击"开始返工" → 完成返工
  - 管理员再次检查返工质量

### 2. 住客反馈要求返工

- **触发条件**：住客反馈时勾选 "需要返工"
- **产生的记录**：返工任务
- **需要处理的人**：保洁员、管理员
- **处理方式**：同上

### 3. 住客反馈要求赔偿

- **触发条件**：住客反馈时勾选 "要求赔偿"
- **产生的记录**：赔付申请
- **需要处理的人**：管理员
- **处理方式**：
  - 管理员审核赔付申请
  - 决定赔付金额
  - 记录赔付原因
  - 选择是否从保洁员工资中扣除

## 数据安全机制

### 1. 防重复返工

- 每个任务只能有一次返工机会
- 检查时系统会验证是否已有返工记录
- 如果已有返工记录且状态为 `redo_needed`，拒绝再次创建返工

### 2. 结算后保护

- 任务关闭后自动结算
- 结算后的任务（`is_settled = 1` 或 `status = 'closed'`）拒绝所有修改操作
- 防止历史数据被随意篡改

### 3. 历史记录追踪

- 每次状态变更都记录到 `task_history` 表
- 记录内容：操作类型、旧状态、新状态、操作人、详细说明、时间戳
- 支持完整的审计追踪

## 保洁员绩效计算

保洁员评分根据以下因素自动调整：

- **基础评分**：5.0 分
- **返工扣分**：每次返工扣 0.2 分
- **处罚扣分**：每 ¥100 处罚扣 0.1 分
- **住客评分**：住客评分会影响保洁员的综合评分
- **最高评分**：不超过 5.0 分
- **最低评分**：不低于 1.0 分

## API 接口

### 房源管理

- `GET /api/properties` - 获取房源列表
- `POST /api/properties` - 创建房源
- `PUT /api/properties/:id` - 更新房源

### 保洁员管理

- `GET /api/cleaners` - 获取保洁员列表
- `POST /api/cleaners` - 创建保洁员
- `PUT /api/cleaners/:id` - 更新保洁员

### 任务管理

- `GET /api/tasks` - 获取任务列表（支持筛选）
- `POST /api/tasks` - 创建任务
- `GET /api/tasks/:id` - 获取任务详情
- `POST /api/tasks/:id/action` - 任务操作（开始、完成、检查、返工、反馈、赔付、关闭等）

### 统计和导出

- `GET /api/stats` - 获取统计数据
- `GET /api/export` - 导出 CSV 报表
- `POST /api/init-data` - 初始化样例数据

## 常见问题

### Q: 如何重置所有数据？

A: 删除 `data/cleaning.db` 文件，然后运行 `node scripts/init-data.js` 重新初始化。

### Q: 任务关闭后还能修改吗？

A: 不能。任务关闭后会自动结算，结算后的任务拒绝所有修改操作，这是为了保护历史数据的完整性。

### Q: 一个任务可以返工几次？

A: 每个任务只能有一次返工机会。这是为了防止同一入住单重复返工，影响住客体验。

### Q: 赔付金额如何影响保洁员绩效？

A: 赔付金额会从保洁员绩效中扣除（每 ¥100 扣 0.1 分），并且赔付金额会记录在保洁员的总赔付中。
