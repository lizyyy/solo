            ## 原始点子

            我想做一个给小型烘焙工作室用的“预订排产小助手”，场景是每天会从微信群和表格里收到蛋糕/面包预订，店主现在靠手抄经常漏掉原料和取货时间。请你从 0 开始做成一个可运行的全栈 Web 应用：前端要能录入和编辑客户预订单、取货时间、商品规格和备注；后端提供 API，并用本地 SQLite 或等价持久化保存数据，刷新页面不能丢。还要有一个商品配方/原料库存模块，例如每个商品会消耗奶油、面粉、鸡蛋等，新增或修改订单后要自动计算当天原料需求和库存缺口。

我希望首页就是工作台，不要做营销落地页。核心流程是：维护商品配方和当前库存 -> 新增/导入一批预订单 -> 系统按取货日期和时段生成排产清单 -> 标出原料不够的订单或时段 -> 可以把当天排产结果导出成 CSV。导入 CSV 时要校验缺字段、未知商品、数量不是正整数、取货时间格式错误，并在页面上逐行提示，不要一报错就整批静默失败。订单状态至少有“待确认、已确认、制作中、已完成、已取消”，取消订单不能再占用原料；修改配方或库存后，排产和缺口要跟着重新计算。

请把前后端、数据模型、校验逻辑、导入导出、README 运行说明都补齐，代码结构清楚一点，最好带一些示例数据，方便我启动后马上验证主流程。
