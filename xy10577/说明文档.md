# 企业访客餐券 API 系统

围绕企业访客用餐券与来访预约、餐厅档口、预算部门和核销状态关联的完整闭环系统。

## 一、快速开始

### 1. 安装依赖

```bash
npm install
```

### 2. 初始化样例数据

```bash
npm run seed
```

### 3. 运行正常流程演示

```bash
npm run demo
```

### 4. 运行失败路径演示

```bash
npm run demo-fail
```

### 5. 启动 API 服务

```bash
npm start
```

服务地址: http://localhost:3000

## 二、核心数据模型

### 1. 部门预算 (departments)
- `id`, `name`: 部门ID和名称
- `budget_amount`: 预算总额
- `used_amount`: 已使用金额
- `remaining_budget`: 剩余预算（计算得出）

### 2. 餐厅档口 (stalls)
- `id`, `name`, `location`: 档口信息

### 3. 访客预约 (visitor_appointments)
- 状态: `SCHEDULED`(已预约) → `ARRIVED`(已签到) → `COMPLETED`(完成)
- 关联: `host_department_id`(接待部门)

### 4. 餐券 (meal_vouchers)
- 状态: `ISSUED`(已发放) → `REDEEMED`(已核销) / `VOIDED`(已作废) / `EXPIRED`(已过期)
- 关键: `voucher_code`(券码，唯一), `valid_from`, `valid_to`(有效期)
- 关联: `appointment_id`(访客), `department_id`(预算部门)

### 5. 核销记录 (redemptions)
- 关联: `voucher_id`, `stall_id`(档口), `redeemed_at`(时间)

### 6. 状态历史 (status_history)
记录每次状态变更：
- `entity_type`/`entity_id`: 实体类型和ID
- `from_status` → `to_status`: 状态流转
- `operator`, `reason`: 操作人、原因
- `before_state`, `after_state`: 前后差异快照

### 7. 失败操作 (failed_operations)
- `operation`, `error_code`, `error_message`
- `request_data`: 原始请求数据
- 支持按操作/错误码/实体ID查询

### 8. 幂等键 (idempotency_keys)
- `key`: 幂等键（可通过 `X-Request-ID` 请求头或 `request_id` 字段传入）
- 保证重复请求只执行一次

## 三、核心业务规则

| 规则 | 错误码 | 说明 |
|------|--------|------|
| 未签到不能发券/核销 | `VISITOR_NOT_ARRIVED` | 访客需先签到状态为 `ARRIVED` |
| 部门预算不足 | `BUDGET_INSUFFICIENT` | 发券前检查 `remaining_budget >= amount` |
| 同一访客重复领券 | `VOUCHER_DUPLICATE` | 同一预约不能有两张有效券 |
| 餐券过期 | `VOUCHER_EXPIRED` | `valid_to` < 当前时间 |
| 餐券已作废 | `VOUCHER_VOIDED` | 作废券不能核销 |
| 重复核销 | `VOUCHER_ALREADY_REDEEMED` | 已核销券不能再核销 |
| 幂等冲突 | `IDEMPOTENT_CONFLICT` | 相同 request_id 重复请求 |

### 状态流转规则

```
预约: SCHEDULED → ARRIVED → COMPLETED
              ↘ NO_SHOW / CANCELLED

餐券: ISSUED ──→ REDEEMED (核销)
        │
        ├──→ VOIDED (人工作废，预算退还)
        │
        └──→ EXPIRED (过期自动回收，预算退还)
```

## 四、API 接口列表

### 健康检查
```
GET /health
```

### 部门管理
```
POST /api/departments          创建部门
GET  /api/departments          部门列表
GET  /api/departments/:id      部门详情（含预算）
GET  /api/departments/:id/expense  部门费用明细
```

### 档口管理
```
POST /api/stalls               创建档口
GET  /api/stalls               档口列表
GET  /api/stalls/:id/redemptions  档口核销明细
```

### 预约管理
```
POST /api/appointments         创建预约
GET  /api/appointments/:id     预约详情（含状态历史）
POST /api/appointments/:id/checkin  访客签到
```

### 餐券管理
```
POST /api/vouchers/issue       发放餐券
GET  /api/vouchers             餐券列表（支持过滤）
GET  /api/vouchers/:id         餐券详情
GET  /api/vouchers/code/:code  按券码查询
POST /api/vouchers/redeem      核销餐券
POST /api/vouchers/:id/void    作废餐券
POST /api/vouchers/expire      执行过期回收
```

### 查询与报告
```
GET  /api/visitors/:appointmentId/meal-status  访客用餐状态
GET  /api/reports/monthly/:year/:month         行政月报
GET  /api/reports/monthly/:year/:month/export  导出月报CSV
GET  /api/failed-operations                    失败操作记录
GET  /api/history/:entityType/:entityId        状态历史
```

### 请求头
- `X-Operator`: 操作人标识（默认 `system`）
- `X-Request-ID`: 幂等键（保证重复请求幂等）

## 五、主要演示路径

### 路径一：正常发券核销流程（张三-阿里巴巴）

```
1. 访客签到
   POST /api/appointments/appt-normal-001/checkin
   Header: X-Operator: 行政前台-小王

2. 发放餐券（检查预算）
   POST /api/vouchers/issue
   { "appointment_id": "appt-normal-001", "amount": 50 }
   Header: X-Operator: 行政前台-小王

3. 档口核销
   POST /api/vouchers/redeem
   { "voucher_code": "VXXXXXXXXX", "stall_id": "stall-1" }
   Header: X-Operator: 档口操作员-老李

4. 验证闭环：查询访客用餐状态
   GET /api/visitors/appt-normal-001/meal-status
   
   期望结果：
   - appointment_status: "ARRIVED"
   - voucher_status: "REDEEMED"
   - redeemed: true
   - stall_name: "中式快餐档口"
```

### 路径二：过期回收流程（李四-腾讯）

```
1. 访客签到
2. 发券（设置有效期为过去时间）
3. 执行过期回收
   POST /api/vouchers/expire

验证：
   GET /api/departments/dept-hr
   期望：remaining_budget 应恢复（过期券预算退还）
```

### 路径三：作废流程（孙七-美团）

```
1. 访客签到
2. 发券
3. 人工作废
   POST /api/vouchers/{voucher_id}/void
   { "reason": "访客临时取消" }
   Header: X-Operator: 行政经理-张经理

验证：
   GET /api/history/VOUCHER/{voucher_id}
   期望：记录 from=ISSUED → to=VOIDED，含操作人和原因
```

## 六、一条失败路径

### 失败路径：预算不足场景（王五-华为）

```
前置：销售部预算 10000 元

步骤：
1. 访客签到（王五）
   POST /api/appointments/appt-budget-001/checkin

2. 尝试发 11000 元的券（超过预算）
   POST /api/vouchers/issue
   { "appointment_id": "appt-budget-001", "amount": 11000 }

期望响应（400）：
{
  "success": false,
  "error": {
    "code": "BUDGET_INSUFFICIENT",
    "message": "预算不足。当前剩余: 10000元, 需要: 11000元"
  }
}

3. 验证失败记录：
   GET /api/failed-operations?operation=ISSUE_VOUCHER
   
   期望：存在一条记录，error_code = "BUDGET_INSUFFICIENT"
```

## 七、验证业务闭环

运行脚本后，通过以下接口验证数据一致性：

### 1. 访客用餐状态（判断访客是否真的用餐）
```bash
curl http://localhost:3000/api/visitors/appt-normal-001/meal-status
```

关键判断字段：
- `appointment_status`: 应为 `ARRIVED`
- `voucher_status`: 应为 `REDEEMED`
- `redeemed`: 应为 `true`
- `stall_name`: 应显示具体档口

### 2. 部门费用（判断预算是否正确扣减）
```bash
curl http://localhost:3000/api/departments/dept-it/expense
```

关键判断字段：
- `budget_total`: 部门总预算
- `budget_used`: 已使用（已核销金额）
- `budget_remaining`: 剩余预算
- `summary.redeemed`: 实际核销的券数

### 3. 档口核销明细（判断餐券是否真的在档口消费）
```bash
curl http://localhost:3000/api/stalls/stall-1/redemptions
```

关键判断字段：
- `total_count`: 核销次数
- `total_amount`: 核销总金额
- `redemptions`: 每条记录含访客姓名、公司、部门

### 4. 行政月报（全局视角）
```bash
curl http://localhost:3000/api/reports/monthly/2026/5
```

或导出 CSV：
```bash
curl http://localhost:3000/api/reports/monthly/2026/5/export
```

关键判断字段：
- `summary.vouchers_redeemed`: 总核销数
- `summary.redeemed_amount`: 总核销金额
- `summary.failed_operations`: 本月异常数
- `by_department`: 各部门核销统计
- `by_stall`: 各档口核销统计

### 5. 状态历史审计（人工修正留痕）
```bash
curl http://localhost:3000/api/history/VOUCHER/{voucher_id}
```

关键判断字段：
- `operator`: 操作人
- `reason`: 操作原因
- `before_state`/`after_state`: 前后差异快照

## 九、API 调用示例（curl）

```bash
# 健康检查
curl http://localhost:3000/health

# 创建部门
curl -X POST http://localhost:3000/api/departments \
  -H "Content-Type: application/json" \
  -H "X-Operator: 管理员" \
  -d '{"name": "财务部", "budget_amount": 5000}'

# 创建预约
curl -X POST http://localhost:3000/api/appointments \
  -H "Content-Type: application/json" \
  -d '{
    "visitor_name": "测试访客",
    "visitor_company": "测试公司",
    "host_department_id": "dept-it",
    "host_name": "张工",
    "appointment_date": "2026-05-12"
  }'

# 发券（带幂等键）
curl -X POST http://localhost:3000/api/vouchers/issue \
  -H "Content-Type: application/json" \
  -H "X-Request-ID: req-001" \
  -d '{
    "appointment_id": "appt-normal-001",
    "amount": 50
  }'

# 查询失败操作
curl "http://localhost:3000/api/failed-operations?error_code=BUDGET_INSUFFICIENT"
```
