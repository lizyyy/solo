# 电梯故障阈值预警 · 整包样例

> 维保主管阿敏专用：巡检表断断续续、设备号写法不统一也能跑

---

## 阿敏，你拿到这包东西，按这两步来就行

### 第 1 步：一条命令跑完，别管里面有啥

打开终端，进入这个目录，敲：

```bash
python run_warning.py
```

就这一条。它会把 `data/` 目录下所有 CSV 巡检表自动：
- 拼成主线（按日期 + 设备）
- 把「EL-001 / EL001 / 电梯001 / el_001 / 电梯-001」这些写法**自动归一成同一个 EL-001**
  - 注意：**原始写法没删**，全部保留在 `output/数据追溯清单.csv` 里，想找茬随时翻
- 对「门机异响 / 钢丝绳 / 振动 / 温度」的中文描述统一分级（无/轻微/严重 → 0/1/2）
  - 描述写法不在映射表里的，会被标成**断档**，不会硬改掉让你看不出痕迹
- 按阈值出预警（周故障≥3次 或 任一异常级别≥2）
- 所有**采样断档**都能追到具体哪张表第几行、巡检员当时的原始备注

跑完后终端会直接告诉你：
> 【退出提示 - 采样断档卡住的位置】

列的每一处都有设备号、日期、缺啥字段、来自哪张表、巡检表原始说法。不是一句含糊的「有数据缺失」。

---

### 第 2 步：先看哪份报告

直接打开 **`output/复核报告.md`**，这是给复核人看的，结构是：

| 章节 | 你能看到啥 | 为什么要先看 |
|---|---|---|
| 一、复核口径一览 | 汇总数字：几份表、多少条、几台预警、几处断档 | 复核人先看总数，心里有底 |
| 二、触发预警的设备 | **每台都列：原始设备号写法、涉及哪几张表、触发了啥阈值、巡检员的原始备注（带表名+行号）** | **明细直接接上汇总口径**，总数几台下面就几台明细，不会对不上 |
| 三、处理完成项 | 哪些步骤已经跑完了，列清单 | 复核人知道不用再跑这些 |
| 四、缺材料 / 待补采 | 哪些断档，附 TOP15 明细（完整的在 CSV 里） | 要补材料的直接拿这个去催 |
| 五、附件清单 | 三份输出文件的用途 | 需要深查知道看哪个 |

如果复核人说「这个设备为啥预警？给我看当时巡检员原话」——
翻 `output/数据追溯清单.csv` 或 报告第二章，每条都带「哪张表第几行 + 原始备注」。

如果需要补采——
翻 `output/采样断档明细.csv`，每一处断档都标了：断档类型、设备号、日期、缺哪个字段、来自哪张表、巡检表原始说法。

## 常见问题

**Q：设备编号 EL-001 和 电梯001 会当成两台吗？**
A：不会。脚本统一归一成 EL-001，但**原始写法保留在追溯清单**里，随时能查。

**Q：巡检表里的脏数据会不会被悄悄修掉？**
A：不会。比如运行时长空着、或者描述写了个映射表里没有的词，会被标成「断档」列出来，**不会硬猜一个值塞进去**让你看不出痕迹。

**Q：采样断档为啥不是一句「有 N 处缺失」？**
A：每一处都追到了：设备、日期、缺啥字段、哪张表第几行、巡检员原始备注写了啥。直接拿这个去补采就行。

**Q：复核人说「汇总说 2 台预警，明细咋只有 1 台」怎么办？**
A：不会出现。报告第二章的明细就是从触发预警的设备字典直接展开的，和第一章的总数同源，口径一致。
