# 塔吊维保备件排程

同一结果集驱动 **筛选 / 统计 / 明细 / 摘要**，异常单独拎出，线索可追溯，重跑不丢备注。

## 启动

```bash
npm install
npm run dev
```

然后浏览器打开 http://localhost:5173/ 即可进入塔吊维保备件排程页面。

> 说明：项目在 `postinstall` 阶段会自动给 Rollup 打补丁，
> 在原生绑定加载失败时自动 fallback 到 WASM 版本，
> 适配 Node 24 + macOS arm64 等环境。无需手动修改 `node_modules`。

## 三步操作

1. **设筛选**：选日期范围、塔吊、部件类别、状态；勾选「只看异常」可只保留异常记录。
2. **生成结果**：点「生成排程结果」。同一份结果同时驱动统计卡片、明细表格、结论面板、页面摘要。
3. **结论下钻**：在「结论与排程建议」或「异常单独拎出」面板里点关联记录 → 明细行会高亮并展开，查看 **异常证据** 和 **关联结论**（含「结论变化说明」）。

## 坏材料来了看哪里

| 现象 | 先看 | 再看 |
|---|---|---|
| 采样断档（值为空） | 右侧「异常单独拎出」→ `采样断档` 分组 | 点关联记录跳明细，展开行看「异常证据」里的巡检员和日期；结论面板有「断档数量变化会直接影响统计均值」的变化说明 |
| 实测值破阈值 | 右侧「异常单独拎出」→ `阈值突破` 分组 | 展开行看超出多少单位；对应结论里的 `⚠ 结论变化说明` 解释本次排程升级原因 |
| 在阈值内但看着怪 | 右侧「异常单独拎出」→ `被均值掩盖` 分组 | 证据里给了 Z 分数和批次均值，解释为啥没被平均盖住（以前人工巡检表容易漏掉） |
| 重跑后结论变了 | 顶部批次号 + 页面摘要「历史版本」对比 | 展开结论看 `⚠ 结论变化说明` 字段，说明本次结论和上次哪不一样 |
| 想找上次备注 | 明细最后一列「备注」直接显示 | 页面摘要「运行快照」可点回老批次重算，备注和摘要都会跟着保留 |

## 重跑数据不丢什么

- **行备注**：按记录 ID 存 localStorage，跨批次保留
- **页面摘要**：按筛选条件签名存，带 10 条历史版本，重跑不覆盖人工修改
- **运行快照**：最近 30 次生成都有快照，可一键回溯到当时的筛选条件
