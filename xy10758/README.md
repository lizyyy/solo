# 订阅续费失败补偿系统

## 系统简介

这是一个完整的订阅续费失败补偿管理系统，核心功能包括：
- 扣款事件校验与管理
- 重试策略配置
- 宽限期管理
- 降级动作记录
- 收入报告导出

## 快速开始

### 方式一：使用启动脚本
```bash
# 1. 启动服务
./start.sh

# 2. 在新终端中，导入样例数据
python3 sample_data.py
```

### 方式二：手动启动
```bash
# 1. 安装依赖
pip3 install -r requirements.txt

# 2. 启动服务
python3 app.py

# 3. 在新终端中，导入样例数据
python3 sample_data.py
```

### 访问系统
- 前端页面：http://localhost:5000
- API 文档（通过各端点直接访问）

## 核心功能

### 1. 数据校验机制

系统在导入扣款事件时，会自动执行以下校验：

- **订阅计划有效性**：验证 plan_id 是否存在于系统中
- **金额匹配检查**：检查扣款金额是否与订阅计划定价一致
- **重试状态检查**：检查重试次数是否已用尽
- **宽限期提醒**：根据扣款时间和宽限期计算提醒

### 2. 重试策略

系统内置三种重试策略：
- **标准策略 (standard)**：1小时、6小时、24小时后重试
- **激进策略 (aggressive)**：30分钟、2小时、8小时后重试
- **保守策略 (conservative)**：24小时、48小时、72小时后重试

### 3. 宽限期管理

不同订阅计划有不同的宽限期：
- 专业版月付：7天
- 专业版年付：14天
- 企业版：30天

当重试次数用尽但仍在宽限期内时，系统会提醒但不强制降级；超出宽限期后必须执行降级动作。

### 4. 降级动作

支持的降级类型：
- 降级到免费版 (downgrade_to_free)
- 降级到基础版 (downgrade_to_basic)
- 暂停服务 (suspend)
- 延长宽限期 (extend_grace)
- 手动退款 (manual_refund)

### 5. 报告导出

导出 Excel 报告包含：
- **汇总报告**：按负责人、重试策略、状态分组的统计数据
- **扣款事件明细**：完整的扣款事件列表
- **降级动作明细**：所有降级操作记录

## 样例数据说明

导入 `sample_data.py` 后，系统会包含以下测试场景：

### 正常场景
1. **EVT_001**：正常成功扣款
2. **EVT_002**：扣款失败，还有重试机会（余额不足）
3. **EVT_003**：扣款失败，重试已用尽，已执行降级（银行卡过期）
4. **EVT_004**：待处理状态
5. **EVT_005**：扣款失败，正在重试中（支付网关错误）
6. **EVT_006**：重试后成功扣款
7. **EVT_007**：重试已用尽，需要执行降级（用户取消支付）

### 脏数据场景
1. **DIRTY_001**：无效订阅计划 - 会被系统拒绝（错误示例）
2. **DIRTY_002**：金额与计划不匹配 - 系统给出警告但允许导入（警告示例）

## 失败路径测试

### 场景1：无效订阅计划
- 导入 `plan_id: "INVALID_PLAN"` 的数据
- 预期结果：返回错误，数据不入库

### 场景2：金额不匹配
- 导入 `PRO_MONTHLY` 计划但金额为 199 元（应为 99 元）
- 预期结果：警告提示，数据正常入库

### 场景3：重试用尽但在宽限期内
- 导入 `attempt_count = 3` 且 `max_attempts = 3` 的失败记录
- 预期结果：宽限期提醒，显示"需降级"标签

### 场景4：重试用尽且超出宽限期
- 扣款时间超过宽限期天数
- 预期结果：强烈警告，立即执行降级

## API 接口

### 扣款事件
- `GET /api/charge-events` - 获取扣款事件列表（支持 search 和 status 过滤）
- `POST /api/charge-events` - 创建单个扣款事件
- `POST /api/charge-events/batch` - 批量导入扣款事件

### 降级动作
- `GET /api/downgrade-actions` - 获取降级动作列表
- `POST /api/downgrade-actions` - 创建降级动作

### 基础数据
- `GET /api/plans` - 获取订阅计划列表
- `GET /api/retry-strategies` - 获取重试策略列表

### 报告与统计
- `GET /api/dashboard` - 获取仪表盘统计
- `GET /api/report/export` - 导出 Excel 报告

## 数据持久化

系统使用 SQLite 数据库（`subscription.db`），重启服务后：
- 所有历史记录保留
- 错误原因保留
- 降级动作记录保留
- 导出功能正常工作

## 技术栈

- **后端**：Python + Flask + SQLAlchemy
- **前端**：原生 HTML + JavaScript
- **数据库**：SQLite
- **报告导出**：Pandas + OpenPyXL
