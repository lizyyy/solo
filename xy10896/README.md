# 依赖破坏提醒系统

当上游接口字段变更时，自动检测并通知下游服务，避免发布后才发现问题。

## 功能特性

- ✅ **新增订阅**：服务可订阅依赖的API字段路径
- ✅ **提交变更**：上游提交Schema变更时自动计算差异
- ✅ **风险等级**：自动区分高/中/低风险
  - **高风险**：字段删除
  - **中风险**：字段类型变更
  - **低风险**：仅描述变更
- ✅ **确认流程**：确认影响 / 标记不受影响 + 备注
- ✅ **按团队分组**：前端界面按团队分组展示，方便发布前收口
- ✅ **导出功能**：一键导出未确认清单
- ✅ **重复提醒去重**：相同变更重复提交不会产生多条待办

## API接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/subscriptions` | 新增订阅 |
| GET | `/api/subscriptions` | 获取所有订阅 |
| POST | `/api/changes` | 提交Schema变更 |
| GET | `/api/changes` | 获取所有变更 |
| GET | `/api/confirmations` | 获取确认列表（支持按状态/团队筛选） |
| POST | `/api/confirmations/:id/confirm` | 确认影响 |
| POST | `/api/confirmations/:id/unaffected` | 标记不受影响 |
| GET | `/api/export/unconfirmed` | 导出未确认清单 |

## 前端页面

系统包含三个主要页面：

1. **待确认清单** - 按团队分组展示待处理的变更，支持风险等级筛选
2. **订阅管理** - 查看所有订阅，以及新增订阅表单
3. **变更记录** - 查看所有变更历史，以及提交新变更表单

## 样例数据说明

系统启动时自动加载样例数据，**四种变更场景分开提交**，清晰展示风险等级：

### 订阅的服务
- 交易团队（订单服务）：订阅用户接口的 id, name, email
- 支付团队（支付服务）：订阅用户接口的 id, balance
- 消息团队（通知服务）：订阅用户接口的 id, name, email
- 数据团队（报表服务）：订阅用户接口的 id, profile
- 交易团队（订单服务）：订阅订单接口
- 仓储团队（库存服务）：订阅订单接口

### 四种独立变更示例
1. **示例1：删除 email 字段** → 🔴 高风险（影响订单服务、通知服务）
2. **示例2：balance 类型从 number 改为 string** → 🟡 中风险（影响支付服务）
3. **示例3：name 描述从"用户名"改为"用户姓名"** → 🟢 低风险（影响订单服务、通知服务）
4. **示例4：删除 profile.phone 字段** → 🔴 高风险（影响报表服务）

### 去重验证
最后一行故意重复提交"删除email字段"的变更，验证系统**不会产生重复待办**。

## 核心设计

### 去重机制
使用 `apiPath + diff内容` 生成 SHA256 哈希作为变更的唯一标识。相同变更内容重复提交时：
- 不会创建新的变更记录
- 不会创建新的待办确认项
- 返回已存在的变更记录

### 风险等级计算
- 包含字段删除 → 高风险
- 包含类型变更（无删除）→ 中风险
- 仅描述变更 → 低风险

### 截止时间
- 高风险：24小时内
- 中风险：3天内
- 低风险：7天内
