# 审批日志时间线拼接与分析工具

一个用于审批日志时间线拼接、规则校验和审计分析的命令行工具，专为临时权限申请场景设计。

## 功能特性

- ✅ **日志时间线拼接**: 整合多系统（工作流、审批门户、邮件系统）的日志，按时间顺序拼接成完整的审批时间线
- ✅ **审批意见缺失拦截**: 重点检查审批人是否填写审批意见，缺失则自动拦截并详细说明原因
- ✅ **版本化规则引擎**: 支持按生效日期选择不同版本的审批规则，历史批次使用当时的规则口径进行解释
- ✅ **重复提交检测**: 相同内容再次提交时自动复用旧结论或标记冲突
- ✅ **报告生成**: 生成包含处理前后对比、执行时间和下一步建议的详细报告
- ✅ **人工复核追踪**: 支持添加复核意见，关联客服升级工单的原始记录，不直接覆盖原有结论

## 快速开始

### 安装依赖

```bash
npm install
```

### 使用内置样例数据运行

```bash
npm start -- run --sample
```

### 导出示例数据文件

```bash
npm start -- export-sample
```

这将导出三个文件：
- `sample-logs.json` - 示例审批日志（包含技术部、运维部、数据部的真实场景数据）
- `sample-tickets.json` - 示例工单数据
- `default-rules.json` - 默认审批规则

### 使用自定义数据运行

```bash
npm start -- run -l sample-logs.json -t sample-tickets.json
```

### 指定规则版本日期运行

```bash
npm start -- run --sample -d 2024-01-15
```

### 查看某批次的时间线

```bash
npm start -- show-timeline BATCH-2024-001 --sample
```

### 解释拦截原因

```bash
npm start -- explain BATCH-2024-001 --import processing-results.json
```

### 添加人工复核意见

```bash
npm start -- review BATCH-2024-001 AUDITOR-001 "张经理" "经核实流程合规，同意特批" --decision override --escalation-ticket CS-2024-9999 --import processing-results.json
```

## 命令说明

### run - 运行审批分析

```
选项：
  -l, --logs <path>       日志文件路径(JSON格式)
  -t, --tickets <path>    工单文件路径(JSON格式)
  -r, --rules <path>      规则文件路径(JSON格式)
  -d, --date <date>       使用指定日期的规则版本进行评估(YYYY-MM-DD)
  -o, --output <path>     报告输出路径
  -f, --format <format>   输出格式: text|json|table (默认: text)
  --sample                使用内置样例数据运行
  --test-duplicate        测试重复提交检测
```

### show-timeline - 显示时间线

```
参数：
  <batchId>               批次ID

选项：
  -l, --logs <path>       日志文件路径(JSON格式)
  --sample                使用内置样例数据
```

### explain - 解释拦截原因

```
参数：
  <batchId>               批次ID

选项：
  --import <path>         导入现有结果文件路径
```

### review - 添加复核意见

```
参数：
  <batchId>               批次ID
  <reviewerId>            复核人ID
  <reviewerName>          复核人姓名
  <comment>               复核意见

选项：
  --decision <decision>   复核决定: uphold(维持原判)|override(推翻结论)|escalate(升级处理) (默认: uphold)
  --escalation-ticket <ticketId>  升级工单编号（关联客服系统）
  --import <path>         导入现有结果文件路径
```

### export-sample - 导出示例数据

```
选项：
  -o, --output-dir <dir>  输出目录 (默认: .)
```

## 主流程说明

```
1. 数据输入阶段
   ├─ 审批日志：从多系统收集审批记录
   │  ├─ 工作流系统：提交、分配、完成记录
   │  ├─ 审批门户：审批通过/拒绝、意见填写
   │  └─ 邮件系统：超时提醒、通知记录
   ├─ 工单信息：申请单详情、审批链、当前状态
   └─ 审批规则：版本化规则，带生效日期和失效日期

2. 时间线拼接阶段
   ├─ 按批次ID过滤所有相关日志
   ├─ 按时间戳进行排序
   ├─ 解析每个事件的动作和详情
   └─ 生成结构化的审批时间线

3. 规则评估阶段
   ├─ 根据评估日期选择适用的规则版本
   ├─ 逐条验证审批流程合规性
   │  └─ 重点检查：审批通过操作是否填写意见
   ├─ 收集所有不通过项
   └─ 生成拦截原因和处理建议

4. 重复检测阶段
   ├─ 计算当前批次内容的哈希签名
   ├─ 匹配历史处理记录
   ├─ 发现重复时复用旧结论
   └─ 存在冲突时标记需要人工复核

5. 报告生成阶段
   ├─ 处理前后状态对比表格
   ├─ 拦截原因详细说明（含规则版本和条款引用）
   ├─ 执行时间统计
   └─ 下一步行动建议
```

## 失败路径说明：审批意见缺失

### 现象描述
用户提交临时权限申请，所有审批人都点击了"通过"按钮，但其中至少一位审批人未填写具体的审批意见。

### 拦截过程

1. **日志采集**：系统采集到以下事件序列
   ```
   2024-01-15 09:00 - 张三提交生产数据库查询权限申请
   2024-01-15 09:05 - 系统分配给部门经理李四审批
   2024-01-15 10:30 - 李四审批通过，填写意见："项目紧急，同意"
   2024-01-15 10:35 - 系统分配给安全管理员王五审批
   2024-01-15 11:10 - 王五审批通过，未填写意见
   ```

2. **规则匹配**：使用2024年1月15日生效的《审批管理规范V2.1》
   - 规则ID：RULE-001
   - 规则版本：2.1.0
   - 生效日期：2024-01-15

3. **拦截判断**：系统检测到王五的审批记录缺少approvalComment字段

4. **拦截说明**：
   ```
   根据2024年1月15日生效的《审批管理规范V2.1》第3.2条规定：
   所有审批通过操作必须填写具体的审批意见，说明同意的理由或确认的内容。
   
   经核查，本批次中有审批记录仅点击了"通过"但未填写任何审批意见。
   ```

5. **下一步建议**：
   - 联系审批人王五补充填写审批意见
   - 或通过工单系统提交审批意见补录申请（工单号需关联原始审批单号CS-2024-0567）
   - 经复核通过后可继续流程

### 历史数据处理原则
对于2024年1月15日之前的历史数据，如果当时生效的规则（如V1.0版）未要求必填审批意见，则系统不会拦截该历史批次，只会在报告中注明使用的规则版本。

## 人工复核机制

### 设计原则
- 人工复核意见不直接覆盖原有结论
- 保留完整的决策轨迹
- 支持关联客服升级工单

### 复核流程
1. 系统拦截有问题的批次
2. 复核人添加复核意见和决定
3. 系统记录复核人、时间、意见
4. 如决定为"escalate"，需关联客服工单编号
5. 报告中同时显示原始结论和复核意见

### 数据追踪
每条复核记录包含：
- 批次ID
- 复核人ID和姓名
- 复核时间
- 复核意见
- 复核决定（uphold/override/escalate）
- 关联升级工单编号（可选）
- 原始结果ID

## 报告内容说明

生成的报告包含以下内容：

1. **处理概览**
   - 总批次数
   - 通过批次数
   - 拦截批次数
   - 重复批次数
   - 总处理时间

2. **批次对比明细**
   - 每个批次处理前后的状态对比
   - 事件数量变化
   - 拦截原因列表

3. **详细处理结果**
   - 原始状态 → 最终状态
   - 拦截原因及规则引用
   - 下一步行动建议
   - 规则版本快照
   - 关联客服工单（如有）
   - 复核记录（如有）

4. **总体下一步建议**
   - 优先级排序的待办事项
   - 冲突检测结果
