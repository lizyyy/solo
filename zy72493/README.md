# 🏛️ 文化遗产视廊控制系统

面向社区书记、交通协管老马和网格员的文化遗产保护冲突复核工具。

## ✨ 核心特性

- **可追溯**：点到居民意见，能回到网格员巡查表或施工告示原文
- **说人话**：冲突复核表说明为什么留下、缺什么材料、下一步找谁
- **不越权**：只剩汇总无原文的意见不会自动归正常，留给社区书记复核
- **易上手**：新人照此文档 5 分钟从样例跑到报告

## 🔧 分步手动操作

如果你想一步步体验各角色的工作流程：

### 角色 1：网格员 - 导入巡查表

巡查表是 CSV 格式，字段说明见 `samples/inspection_01.csv`。

```bash
python -m heritagelab.cli import samples/inspection_01.csv
```

系统会自动：
- 给每条意见分配唯一 ID
- 标记哪些只剩汇总无原文
- 把无原文的意见自动送入冲突复核表

### 角色 2：社区书记 - 查看待复核冲突

```bash
# 查看所有待处理
python -m heritagelab.cli list

# 只看需要社区书记处理的
python -m heritagelab.cli list --action secretary

# 只看需要老马处理的
python -m heritagelab.cli list --action ma
```

### 角色 3：交通协管老马 - 补录施工告示

施工告示是 JSON 格式，字段说明见 `samples/notice_01.json`。

```bash
python -m heritagelab.cli notice samples/notice_01.json
```

系统会自动：
- 关联告示中提到的居民意见
- 更新冲突复核表（移除已补充的材料项）
- 根据施工影响调整风险等级
- 重新指定下一步处理人

### 追溯意见来源

看到冲突想查原始记录？

```bash
python -m heritagelab.cli source OP-INS-xxxxxx-002
```

会显示这条意见来自哪张巡查表、哪个网格员、有没有原文。

### 社区书记复核

```bash
python -m heritagelab.cli review CF-OP-INS-xxxxxx-002 OP-INS-xxxxxx-002
```

系统会先展示来源，然后让你选择：
1. confirm - 确认通过
2. request_more - 让老马再补充
3. resolve - 直接结案

### 生成报告

```bash
# 纯文本报告（命令行直接看）
python -m heritagelab.cli report

# HTML 报告（带图表和可追溯链接）
python -m heritagelab.cli report --format html --output my_report.html
```

## 📋 数据格式说明

### 网格员巡查表 (CSV)

| 字段 | 说明 | 必填 |
|------|------|------|
| inspector/网格员 | 巡查员姓名 | 否 |
| location/巡查区域 | 巡查区域 | 否 |
| heritage_site/遗产点 | 涉及的文化遗产 | 否 |
| 位置 | 具体位置 | 是 |
| 意见汇总 | 居民意见摘要 | 是 |
| 原文 | 居民原话（留空表示只剩汇总） | 否 |
| 反映人 | 居民姓名 | 否 |

### 施工告示 (JSON)

```json
{
    "project_name": "项目名称",
    "location": "施工位置",
    "start_date": "2026-06-10",
    "end_date": "2026-08-25",
    "construction_type": "施工类型",
    "impact_on_heritage": "对文化遗产的影响说明",
    "publisher": "发布单位",
    "related_opinion_ids": ["OP-xxx-001", "OP-xxx-002"]
}
```

## 🔄 核心工作流程

```
网格员巡查表导入
        │
        ▼
  ┌─────────────┐
  │ 自动检测：  │
  │ 有原文 → 通过
  │ 无原文 → 入冲突复核表
  └─────────────┘
        │
        ▼
  冲突复核表生成
  （说明原因、缺料、下一步）
        │
        ▼
  社区书记查看？
    /       \
  是         否（先放着）
   │
   ▼
  需要老马补施工告示？
    /       \
  是         否 → 书记直接复核
   │
   ▼

        │
        ▼

        │
        ▼
  社区书记最终复核
        │
        ▼
  生成报告
```

## 💡 设计原则

1. **不替人做决定**：只剩汇总无原文的意见，系统永远标为待复核，不会自动"转正"
2. **每件事都有说法**：冲突项里一定写清「为什么被留下、还缺什么、该找谁」
3. **能往回找**：任何结论都能追溯到原始巡查表或施工告示
4. **不花哨但好用**：报告不是演示用的空壳，是真的能指导工作

## ❓ 常见问题

**Q: 为什么有的意见自动进了冲突复核表？**
A: 因为巡查表里的「原文」字段是空的，只剩汇总。按规定必须社区书记复核。

**Q: 老马补了施工告示后，冲突表会怎么变？**
A: 系统会自动：① 从缺料清单里划掉"施工告示"；② 如果施工有明显影响，会把风险等级调高；③ 重新指派下一步该谁处理。

**Q: 报告里的「追溯来源」怎么用？**
A: HTML 报告里点「🔗 追溯来源」链接，会展开显示原始巡查表或施工告示的详细内容，不用再翻档案。

**Q: 我是新人，怎么最快上手？**
A: 先跑 `python -m heritagelab.cli demo` 看一遍完整流程，再照着「分步手动操作」走一遍就会了。
