## 一、快速启动

### 1.1 启动应用

**方式一：开发模式（推荐用于日常使用）**
```bash
cd /Users/lzy/pro/solo/workspaces/zy72025
```

- **📊 导入全部测试**：一次性导入所有测试记录（空值、重复、边界等）

## 二、核心功能操作指南

### 2.1 开始一局游戏

1. 在首页点击「开始游戏」按钮
2. 在弹窗中选择关卡：
   - **入门篇·货币政策初识**（7个节点，适合初学者）
   - **挑战篇·应对滞胀**（更复杂的经济场景）
3. 输入玩家姓名（学生姓名）
4. 点击「确认开始」

### 2.2 游戏控制

顶部控制栏提供完整的游戏控制功能：

| 按钮 | 功能 | 说明 |
|------|------|------|
| ⏸️ 暂停 | 暂停当前游戏 | 暂停后无法进行决策，可随时恢复 |
| ▶️ 继续 | 恢复暂停的游戏 | 从暂停处继续 |
| 🔄 重开 | 重新开始本局 | 保留玩家和关卡选择，清空历史步骤 |
| 🏁 结算 | 结束游戏并评分 | 显示最终得分和评级 |

### 2.3 做出决策

1. 查看左侧「资源面板」了解当前经济状态
2. 查看中间「迷宫地图」了解当前位置
3. 在右侧「决策面板」选择一项政策选项
4. 系统会自动计算资源变化并进入下一节点

### 2.4 负数资源处理（重要）

当任意资源变为负数时：
- 资源项会**红色闪烁**警示
- 决策按钮自动禁用，无法继续正常操作
- 弹出「补充材料」窗口：
  - 查看哪些资源出现问题
  - 补充材料调整资源数值
  - 点击「确认补充」后可继续游戏
- 系统会记录本次补充，作为返工标记

## 三、历史记录与回放

### 3.1 查看历史记录

1. 点击导航栏「历史记录」
2. 左侧列表显示所有已完成的游戏记录，按时间倒序排列
3. 点击任意记录查看详情：
   - 总步数、补充材料次数
   - 总得分、数据冲突次数
   - 教师评语
   - 完整的步骤时间线

### 3.2 回放一局游戏

1. 在历史记录列表中，点击记录卡片上的「▶️ 回放」按钮
2. 进入回放模式，使用底部控制栏操作：

| 控制 | 功能 | 快捷键 |
|------|------|--------|
| ⏸️/▶️ | 暂停/播放 | 空格键 |
| ⏮️ | 上一步 | ← |
| ⏭️ | 下一步 | → |
| ⏹️ | 停止回放 | Esc |
| 1x-4x | 播放倍速 | - |
| 进度条 | 跳转到任意步骤 | - |

3. 回放过程中可实时查看：
   - 每一步的资源变化（绿色上升/红色下降箭头）
   - 决策选择的时间线
   - 补充材料的标记点

### 3.3 搜索和删除记录

- 在历史记录页面顶部搜索框输入关键词（玩家名、关卡名）
- 点击记录卡片上的「🗑️」按钮删除记录
- 删除前会确认，删除后不可恢复

## 四、数据导入与冲突处理

### 4.1 导入关卡配置

1. 点击导航栏「数据导入」
2. 点击「选择关卡文件」，选择JSON格式的关卡文件
3. 系统自动验证关卡格式：
   - 检查是否有起点和终点
   - 检查路径连通性
   - 检查资源影响定义
4. 验证通过后自动保存

### 4.2 导入学生练习记录

1. 点击「选择记录文件」，选择JSON格式的记录文件
2. 记录文件格式示例：
```json
{
  "formatVersion": "1.0",
  "records": [
    {
      "id": "record-001",
      "levelId": "level-intro",
      "playerName": "张三",
      "teacherNotes": "整体思路清晰，通胀控制得当",
      "steps": [
        { "decision": "提高准备金率 +1%", "timestamp": "2024-01-15T10:30:00Z" },
        { "decision": "继续加息 +0.5%", "timestamp": "2024-01-15T10:35:00Z" }
      ]
    }
  ]
}
```

3. 导入后点击「处理记录」，系统自动重放整局游戏

### 4.3 数据冲突处理（核心功能）

当学生记录与系统计算出现冲突时，系统会：
1. **不替用户拍板**，弹出冲突处理面板
2. 展示**双方证据**：
   - 左侧：学生原始记录
   - 右侧：系统导入数据/计算结果
3. 提供**建议动作**，说明可能的原因
4. 提供5种处理方式供选择：

| 处理方式 | 适用场景 |
|----------|----------|
| ✅ 使用学生记录 | 相信学生的原始记录 |
| ✅ 使用系统数据 | 学生记录可能有误 |
| ✏️ 手动调整 | 需要人工修正数据 |
| ⏭️ 跳过此步 | 暂时不处理，继续 |
| 🚩 标记待审核 | 先标记，后续再处理 |

5. 选择处理方式后，填写处理人姓名和备注，点击「确认处理」

### 4.4 已支持的冲突类型

| 冲突类型 | 说明 |
|----------|------|
| 🔴 资源不匹配 | 记录的资源值与系统计算不符 |
| 🟡 步骤缺失 | 记录的步骤无法在关卡中找到 |
| 🟠 时间线冲突 | 步骤顺序或时间戳有问题 |
| 🟣 重复步骤 | 同一决策被记录多次 |
| ⚫ 空值记录 | 决策内容为空 |
| ⚪ 边界记录 | 资源值达到或超出合理边界 |

## 六、常见问题

### Q1: 浏览器打不开怎么办？
A: 检查端口5173是否被占用，或运行 `pnpm run dev --port 5174` 指定其他端口。

### Q2: 数据会丢失吗？
A: 所有数据保存在浏览器 LocalStorage 中，只要不清除浏览器数据就不会丢失。建议定期导出备份。

### Q3: 如何备份数据？
A: 在「数据导入」页点击「导出样例数据」，可导出当前所有关卡配置。历史记录可在浏览器开发者工具中导出。

### Q4: 如何添加新关卡？
A: 参考 `src/data/mockLevels.ts` 的格式编写JSON文件，然后在「数据导入」页导入。

### Q5: 资源负数后无法操作？
A: 这是正常设计，必须补充材料后才能继续。点击「补充材料」按钮调整资源数值即可。
