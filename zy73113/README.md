# 施工变更方案比选管理系统

解决会议纪要不完整、交底清单遗漏旧意见、数据修改无痕迹等痛点。实现施工变更方案比选记录的全链路追踪。

---

## 🚀 快速开始（给建筑师小赵的操作指南）

### 第一步：启动服务

```bash
npm install
npm run dev
```

- 前端地址：http://localhost:5173
- 后端 API：http://localhost:3002

> **开发模式下每次启动都会自动重置数据库为干净示例数据**，包含10条真实场景的方案记录。
>
> 如果端口被占用，前端会自动顺延到 5174、5175 等端口，以终端显示为准。

---

### 第二步：查看历史时间线（重点！）

系统预置了 **BGC-2026-009 重庆江北嘴金融城4号楼** 这条最完整的演示数据，推荐先看这条：

1. 打开首页 http://localhost:5173
2. 在搜索框输入 **BGC-2026-009** 快速定位
3. 点击「查看详情」按钮进入详情页
4. 切换到 **「历史时间线」** Tab

你会看到完整的处理链：
```
S1 标记异常（材料缺失）→ M1 补录材料
                            → S2 系统自动恢复正常
                            → J1 建筑师判断通过
```

每个节点都记录了：
- 操作人（现场工程师/建筑师/系统自动）
- 变更前内容
- 变更后内容
- 变更原因（必填字段）

**自动恢复 vs 人工调整**：
- 操作人为「系统自动」的记录 = 补录材料后系统自动改判
- 操作人为具体人名的记录 = 人工操作

---

### 第三步：导出结果

每条方案都可以导出完整数据，包含：
- 方案基础信息（备注、状态、判断）
- 全部历史版本记录
- 材料批次详情

**导出方式**：
1. 进入方案详情页
2. 点击右上角「导出」按钮
3. 选择 JSON 或 CSV 格式

> 导出数据与后端实时同步，改备注、补材料、调判断后立即导出就是最新数据。

## 🔄 重置数据库（恢复干净示例数据）

开发模式下每次启动都会自动重置。如果运行中想重置：

```bash
# 删除数据库文件，重启后端即可
rm -f data/construction-plans.db data/construction-plans.db-wal data/construction-plans.db-shm

# 或者设置环境变量强制重置
RESET_DB_ON_START=true npm run server:dev
```

重置后所有数据恢复为 `data/sample-plans.json` 中的干净示例。

## ✨ 核心功能

### 1. 备注同步更新
现场老师在前端修改备注后：
- ✅ 后端数据即时更新
- ✅ 自动生成历史版本（R1, R2...）
- ✅ 导出文件同步最新内容
- ✅ 旧备注不会被删除，永远留在历史中

### 2. 保留原始来源
- 原始意见和原始来源区域 **带锁图标**，**不可修改**
- 脏数据不会被修得看不出痕迹
- 所有修改都在「备注」区域进行，历史可追

### 3. 异常记录单独拎出
- 材料批次缺失自动标记为「异常」状态
- 异常记录在列表中 **橙色边框高亮**，左侧显示橙色竖条
- 顶部状态栏实时统计异常数量
- 支持按「正常/异常」筛选

### 4. 材料补录自动处理
补录材料后：
- ✅ 自动追加到材料批次字段
- ✅ 状态自动从「异常」恢复为「正常」
- ✅ 补录的材料单独标记「补录」标签
- ✅ 补录原因永久记录

### 5. 判断调整完整留痕
建筑师调整判断时：
- 必须填写「调整原因」
- 自动记录 **旧判断 → 新判断**
- 历史中 J 开头的版本号专门标识判断调整

### 6. 导出功能
支持导出 JSON 和 CSV 两种格式，导出文件包含：
- 方案完整信息
- 全部历史版本记录
- 材料批次详情
- 导出时间戳

## 📋 API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/plans` | 获取方案列表，支持 status/keyword 筛选 |
| GET | `/api/plans/:id` | 获取方案详情（含历史+材料） |
| PUT | `/api/plans/:id/remark` | 修改备注，自动生成历史版本 |
| PUT | `/api/plans/:id/judgment` | 调整判断结论，记录新旧判断 |
| POST | `/api/plans/:id/material` | 补录材料批次，自动更新状态 |
| GET | `/api/plans/:id/history` | 获取历史版本列表 |
| GET | `/api/plans/:id/export` | 导出方案数据（?format=json/csv） |

## 💡 操作提示

### 给现场老师
- 发现材料缺失？点击状态标签快速标记异常
- 修改备注时务必填写「变更原因」，这会永久留在历史中
- 补录材料后系统会自动恢复状态，不用手动改

### 给建筑师小赵
- 调整判断前先看「历史时间线」，了解来龙去脉
- 导出的 JSON 文件可以作为正式归档材料
- 异常记录优先处理，避免影响后续施工

### 版本号说明
- `V1` - 原始创建版本
- `R1, R2...` - 备注修改版本 (Remark)
- `J1, J2...` - 判断调整版本 (Judgment)
- `M1, M2...` - 材料补录版本 (Material)
- `S1, S2...` - 状态变更版本 (Status)

## 🔍 常见问题

**Q: 原始数据错了能改吗？**
A: 不能。原始意见和原始来源一旦录入就锁定，只能在备注中说明，确保数据可追溯。

**Q: 异常记录太多找不到怎么办？**
A: 用顶部筛选器选择「异常」，可以只看需要处理的记录。

**Q: 导出的文件包含历史记录吗？**
A: 是的，JSON 导出包含完整的历史版本链，可以作为审计依据。
