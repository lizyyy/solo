# 表单规则编排前端编辑器

一个用于可视化配置表单显隐、必填和联动校验规则的前端工具，帮助业务人员解决复杂规则互相冲突的问题。

## 核心功能

### 1. 规则编辑器
- 可视化创建和编辑表单规则
- 支持三种规则类型：
  - **显隐控制**：控制字段的显示/隐藏
  - **必填控制**：控制字段是否必填
  - **校验规则**：自定义条件下的校验提示
- 支持多条件组合（AND/OR 逻辑）
- 丰富的条件操作符（等于、不等于、包含、大于、小于等）
- 规则优先级设置

### 2. 依赖图可视化
- 自动分析字段间的依赖关系
- 以图形化方式展示依赖链条
- 不同颜色区分规则类型（蓝色-显隐，橙色-必填，红色-校验）
- 点击节点高亮显示相关规则
- 显示节点的依赖数量统计

### 3. 循环检测
- 自动检测循环依赖问题
- 高亮显示循环路径中的节点和边
- 提供详细的循环路径信息
- 避免"鸡生蛋、蛋生鸡"的死循环问题

### 4. 错误定位
- 检测多种规则冲突：
  - 同一字段的冲突显隐规则
  - 同一字段的冲突必填规则
  - 隐藏字段被设为必填
  - 规则引用不存在的字段
  - 规则自引用（引用目标字段自身）
- 按严重程度分级（错误/警告/提示）
- 精确定位涉及的字段和规则

### 5. 实时预览
- 即时预览规则效果
- 支持多种表单字段类型：
  - 文本输入框
  - 数字输入框
  - 下拉选择
  - 单选按钮
  - 复选框
  - 文本域
  - 文件上传
- 自动应用显隐、必填、校验规则
- 一键重置表单

### 6. JSON 导入/导出
- 将完整配置导出为 JSON 文件
- 从 JSON 文件导入配置
- 内置三个示例配置：
  - **正常示例**：展示正确的规则配置
  - **冲突示例**：展示规则冲突的检测
  - **循环示例**：展示循环依赖的检测
- 实时 JSON 格式验证

## 快速开始

### 安装依赖

```bash
cd form-rule-editor
npm install
```

### 启动开发服务器

```bash
npm run dev
```

启动后，访问浏览器显示的地址（通常是 `http://localhost:5173`）即可使用。

### 构建生产版本

```bash
npm run build
```

### 预览生产构建

```bash
npm run preview
```

## 使用指南

### 1. 查看正常示例

1. 启动应用后，点击顶部的 **"JSON 配置"** 标签
2. 点击 **"加载正常示例"** 按钮
3. 点击 **"应用到编辑器"** 按钮
4. 切换到 **"规则编辑器"** 标签，查看规则列表
5. 在右侧的实时预览区域测试规则效果：
   - 勾选 **"是否学生"**，观察 **"学校名称"** 字段显示并变为必填
   - 在 **"职业"** 中选择 **"员工"**，观察 **"公司名称"** 字段显示并变为必填
   - 在 **"职业"** 中选择非学生选项，观察 **"月收入"** 字段显示
   - 在 **"月收入"** 中输入超过 10000 的数字，观察 **"收入证明"** 字段显示
   - 输入小于 18 的 **"年龄"**，观察校验错误提示

### 2. 测试冲突检测

1. 切换到 **"JSON 配置"** 标签
2. 点击 **"加载冲突示例"** 按钮
3. 点击 **"应用到编辑器"** 按钮
4. 切换到 **"依赖分析"** 标签
5. 观察错误面板中显示的冲突信息：
   - 应该看到 **"字段「学校名称」存在冲突的显隐规则"** 的警告
   - 因为一条规则设置"显示"，另一条设置"隐藏"

### 3. 测试循环检测

1. 切换到 **"JSON 配置"** 标签
2. 点击 **"加载循环示例"** 按钮
3. 点击 **"应用到编辑器"** 按钮
4. 切换到 **"依赖分析"** 标签
5. 观察：
   - 依赖图中红色闪烁的节点和虚线边
   - 错误面板中显示的循环依赖路径
   - 应该看到类似 **"循环依赖: field_name -> field_school -> field_name"** 的错误

### 4. 编辑规则

1. 在 **"规则编辑器"** 标签中：
   - 点击规则标题展开/收起详情
   - 修改规则类型、目标字段
   - 添加/删除/修改条件
   - 设置规则动作
   - 调整规则优先级
2. 所有修改会实时同步到依赖图和预览中

### 5. 导出配置

1. 在 **"JSON 配置"** 标签中：
   - 点击 **"从编辑器刷新"** 确保数据最新
   - 点击 **"导出"** 下载 JSON 文件
   - 或直接复制 JSON 内容

## 规则配置说明

### 规则结构

```json
{
  "id": "rule_1",
  "type": "visibility",
  "targetField": "field_school",
  "conditions": [
    {
      "id": "cond_1",
      "fieldId": "field_is_student",
      "operator": "isTrue",
      "value": null
    }
  ],
  "logicOperator": "and",
  "action": { "visible": true },
  "enabled": true,
  "priority": 0
}
```

### 规则类型

| 类型 | 说明 | Action 字段 |
|------|------|-------------|
| `visibility` | 显隐控制 | `{ visible: true/false }` |
| `required` | 必填控制 | `{ required: true/false }` |
| `validation` | 校验规则 | `{ message: "错误提示" }` |

### 条件操作符

| 操作符 | 说明 | 是否需要值 |
|--------|------|-----------|
| `equals` | 等于 | 是 |
| `notEquals` | 不等于 | 是 |
| `contains` | 包含 | 是 |
| `notContains` | 不包含 | 是 |
| `greaterThan` | 大于 | 是 |
| `lessThan` | 小于 | 是 |
| `isEmpty` | 为空 | 否 |
| `isNotEmpty` | 不为空 | 否 |
| `isTrue` | 为真 | 否 |
| `isFalse` | 为假 | 否 |

### 字段类型

| 类型 | 说明 | 示例值 |
|------|------|--------|
| `text` | 单行文本 | `"hello"` |
| `number` | 数字 | `100` |
| `email` | 邮箱 | `"test@example.com"` |
| `date` | 日期 | `"2024-01-01"` |
| `select` | 下拉选择 | `"option1"` |
| `radio` | 单选按钮 | `"yes"` |
| `checkbox` | 复选框 | `["option1", "option2"]` |
| `textarea` | 多行文本 | `"long text"` |
| `file` | 文件上传 | `"filename.pdf"` |

## 常见问题

### Q: 为什么我的规则没有生效？

A: 请检查：
1. 规则是否启用（开关是否打开）
2. 条件字段的值是否满足条件
3. 是否有更高优先级的规则覆盖了当前规则
4. 是否存在循环依赖或冲突

### Q: 如何避免规则冲突？

A: 建议：
1. 避免对同一字段设置多个相反的显隐/必填规则
2. 不要让隐藏字段成为必填
3. 定期检查"依赖分析"页面的错误提示
4. 使用规则优先级来控制执行顺序

### Q: 什么是循环依赖？

A: 循环依赖是指两个或多个字段互相依赖，形成闭环。例如：
- 字段 A 的显隐依赖字段 B 的值
- 字段 B 的显隐又依赖字段 A 的值

这种情况下，系统无法确定应该先显示哪个字段，会导致不可预测的行为。

## 技术栈

- **框架**: Vue 3 (Composition API)
- **构建工具**: Vite
- **样式**: 原生 CSS
- **状态管理**: Vue 响应式系统
- **依赖分析**: 深度优先搜索 (DFS) 算法
