**使用对象**：结构工程师老叶 / 现场老师

## 一、先跑哪条命令

```bash
# ① 最常用：用内置示例数据跑一遍，看看输出长啥样（不依赖任何外部文件）
python3 run_checklist.py --use-sample --show-metrics

# ② 正式跑：读取 data/ 目录下的真实数据（首次运行 data/ 为空时会自动回退到示例数据）
python3 run_checklist.py

# ③ 指定输出目录 + 打印指标
python3 run_checklist.py -o ./output -d ./data --show-metrics
```

> 依赖：**仅 Python 3.9+ 标准库**，不需要 `pip install` 任何东西。

## 三、关键机制说明（给老叶的交代）

### 1. 旧意见不再漏 —— 会议纪要追踪
- 所有历史交底意见都登记在 `节点.opinions` 里，带 **"来源 + 会议轮次 + 追溯说明"** 三要素；
- 导入新一轮会议纪要时：
  - **重复意见自动去重**（内容相同跳过，并在追溯说明里打勾）；
  - **新旧意见冲突自动抓出**（比如"加大焊缝" vs "维持原焊缝"），生成 `OPINION_CONFLICT` 异常；
  - **旧意见没在本轮出现自动标红提醒**（追溯说明里写 ⚠ 并进入 warnings）；
- 产物见 `03_会议纪要意见追溯清单.csv` 的「追溯说明」列。

### 2. 三统一 —— 场景标注 / 侧边说明 / 异常队列不说三套话
- **一张映射表管到底**：`SceneLabel → SIDE_NOTE_MAP → EXCEPTION_NOTE_MAP`；
- 节点同步一次，异常自动跟同步；
- 跑完 `consistency_check` 会自检，如果哪里没同步会把警告打在 README 和终端里。

### 3. 人工改判看得清怎么影响结果
- 每条改判独立生成 `HUMAN_OVERRIDE` 异常并 `pulls_summary=True`，**自动在汇总表里拉动**；
- `06_各节点判定追溯链/<节点号>_判定追溯链.csv` 里是 **步骤0(自动)→步骤N(改判)→最终** 的全链路；
- `04_人工改判影响报告.csv` 是跨节点的改判总表，最后一列标明"直接决定最终结果 / 被后续改判覆盖"。

### 4. 材料缺失宁可挂起不给假稳定
- 节点里只要有任一 `MaterialBatch.missing=True`；
- 自动判定直接跳 `PENDING（待确认-挂起）`；
- 强制最终判定不得为稳定（除非人工改判特意覆盖，并打警告提醒确认）；
- 挂起的异常状态为 `HUNG（已挂起）`，下一步动作写清楚"等待现场补齐证明"。

### 5. 汇总不悬空 —— 点到异常明细看哪里拉动了
- 汇总表 `01_幕墙节点交底清单_汇总表.csv` 里有两列：
  - `拉动汇总的异常数`：告诉你这个节点总共有几条异常在影响最终判定；
  - `拉动汇总的异常编号` + `拉动汇总的异常明细定位`：**编号直接对应到 02_异常队列表里的行**；
- 队列表反过来也带「关联节点」「是否拉动汇总」「处理状态」「人工改判详情」，双向打通。

### 6. 收尾 —— 异常队列里处理状态和改判说清
- 异常队列每条都带：
  - 「处理状态」：`待处理 / 处理中 / 现场已确认 / 设计已确认 / 已闭环 / 已挂起`；
  - 「人工改判详情」：如果这条异常是改判触发的，直接把改判的「原→新/理由/操作人/时间」打印在单元格里；
  - 「下一步动作」：按当前状态自动建议，现场老师直接照着做。
