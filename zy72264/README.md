# 隧道照明暗区巡检管理系统

## 项目简介

面向设备工程师的安全半径表管理、变更追踪、去重导入系统。

## 核心功能

### 安全半径表导入

- CSV 文件上传，自动解析并入库
- 去重校验，防止重复数据翻倍
- 异常检测，自动标记长度不一致记录

### 审阅工作台

- 保留原始行号，便于追溯源头
- 人工改动标注，区分自动检测与手动编辑
- 坐标原点说明查看

### 变更历史

- 改前改后对比视图
- 按字段差异高亮显示
- 支持回滚操作

### 导出与归档

- 截图导出为 PNG 或 CSV
- 归档锁定，防止已确认数据被随意修改

## 边界规则

### 4.1 补录路线没有重新计算长度

- **判定**：当 `length !== calculatedLength` 时，系统自动将该行标记为"待复核"状态
- **处理**：设备工程师不能将"待复核"状态直接改为"正常"，必须由展陈客户复核确认
- **回滚**：工程师修正长度数据后，变更历史中保留改前改后记录

### 4.2 重复导入去重

- **判定**：以"原始行号 + 隧道名称 + 坐标原点"组合作为唯一标识
- **处理**：导入时自动检测，已有记录跳过，不翻倍
- **回滚**：无（跳过的记录未入库，无需回滚）

### 4.3 编辑限制

- **判定**：状态为"已归档"的行不可编辑
- **处理**：需先取消归档（展陈客户确认解锁），再编辑
- **回滚**：编辑操作生成变更记录，可通过变更历史回滚

### 4.4 归档权限（角色强制校验）

- **判定**：`canArchive(row, userRole)` 函数在代码层强制执行以下规则：
  - 待复核（review）行：仅 `client` 角色可归档，`engineer` 角色不可操作
  - 已修改（modified）行：`engineer` 和 `client` 角色均可归档
  - 已归档（archived）行：不可重复归档
- **解锁判定**：`canUnarchive(userRole)` 函数在代码层强制执行以下规则：
  - 仅 `client` 角色可取消归档（解锁），`engineer` 角色不可操作
- **处理**：
  - Store 层 `archiveRow` 返回 `boolean`：角色不匹配时返回 `false`，操作不生效
  - Store 层 `unarchiveRow` 返回 `boolean`：角色不匹配时返回 `false`，操作不生效
  - 前端页面根据 `canArchive`/`canUnarchive` 控制按钮可见性和可操作性
  - 工程师视角：review 行显示"需展陈客户确认"提示，归档按钮不可点击
  - 展陈客户视角：可正常归档 review 行，可解锁已归档行
- **回滚**：归档/解锁操作本身不生成变更记录，但归档后行不可编辑，解锁后恢复可编辑

### 4.5 回滚规则

- **判定**：所有变更记录均可回滚
- **处理**：回滚操作将字段值恢复为变更前的值
- **回滚**：回滚操作本身也生成一条变更记录（changeType=rollback），保留完整审计链

### 4.6 数据校验

- **必填字段**：原始行号、隧道名称、坐标原点、安全半径、长度、计算长度
- **数值约束**：安全半径 > 0，长度 ≥ 0，计算长度 ≥ 0

## 状态流转

| 操作 | 目标状态 | 说明 |
|------|----------|------|
| 首次导入 | 待处理（pending） | CSV 导入后的初始状态 |
| 长度异常 | 待复核（review） | length !== calculatedLength 时自动标记，代码强制 |
| 工程师编辑 | 已修改（modified） | 人工编辑后状态变更 |
| 展陈客户确认归档 | 已归档（archived） | review 行仅 client 角色可归档，代码强制 |
| 取消归档 | 已修改（modified） | 仅 client 角色可解锁，代码强制 |
