# 老旧小区电梯加装协商系统

> 不是给演示会看的空壳，是能解决街道规划员小姜实际问题的工具。

## 这玩意儿解决什么问题？

网格员巡查表导进来，点位刚好落在两个街道的边界上，谁来管？规划员小姜犯愁。

这个系统：
1. **自动识别边界点位** - 不会急着归为正常，留给项目经理复核
2. **施工告示补录联动** - 小姜补录后，地图导出自动更新
3. **报告不说空话** - 每条说明：为什么被留下、缺什么材料、下一步找谁

---

## 快速开始（三步走，新人也能跑）

### 第一步：初始化样例数据

```bash
# 生成测试用的街道边界和巡查表
python -m elevator_negotiation init-sample
```

你会得到：
- `data/streets.json` - 三个街道的边界数据（和平、团结、新华）
- `data/sample_inspection.csv` - 3个巡查点位，其中 **P001 阳光花园3号楼** 刚好在和平街道和团结街道的边界线上

> 🔍 注意：P001 的坐标是 (116.405, 39.911)，正好压在两个街道的分界线上，就是故意这么设计的。

---

### 第二步：网格员导入巡查表

```bash
python -m elevator_negotiation import data/sample_inspection.csv
```

**预期输出：**
```
✅ 成功导入 3 条巡查记录

🔴 [P001] 阳光花园3号楼
   地址: 和平区阳光路88号
   涉及街道: 和平街道、团结街道
   状态: 边界待复核
   下一步: 找项目经理复核
   缺少材料: 施工告示、问题排查记录

🟢 [P002] 幸福里5号楼
   ...

⚠️  发现 1 个边界点位，已标记为待项目经理复核
```

> 🎯 关键设计：边界点位不会自动归入正常流程，必须项目经理拍板。

---

### 第三步：街道规划员小姜补录施工告示

```bash
# 给边界点位 P001 补录施工告示
python -m elevator_negotiation supplement P001 \
  --notice-id N001 \
  --unit "XX建筑工程有限公司" \
  --date 2024-01-15 \
  --content "阳光花园3号楼电梯加装施工告示，公示期7天"
```

**预期输出：**
```
✅ 施工告示已补录!
   点位: 阳光花园3号楼
   告示编号: N001
   新状态: 已补录施工告示
   下一步: 找项目经理复核
⚠️  该点位仍在边界上，需项目经理复核确认归属
```

> 🎯 关键设计：即使补录了告示，只要还在边界上，下一步还是找项目经理，不会偷偷溜走。

---

### （可选）项目经理复核

```bash
# 项目经理确认 P001 确实是边界点位
python -m elevator_negotiation review P001 \
  --notes "经核实，该小区大门在和平街道，主体在团结街道，按双街道协同处理" \
  --confirm-boundary
```

---

### 第四步：导出地图报告

```bash
python -m elevator_negotiation export
```

**预期输出：**
```
✅ 报告已导出: data/exports/电梯加装协商报告_2024xxxx_xxxxxx.html
```

用浏览器打开这个 HTML 文件，你会看到：
- 统计概览（总点位、边界待复核、已补录告示等）
- 🔴 **边界点位详情** - 明确写出：为什么被留下（在两个街道边界上）、缺什么材料、下一步找谁
- 🟢 正常点位详情
- 状态统计图表
- 图例说明

> ✨ 报告不是冷冰冰的系统日志，每一条都告诉你该干什么、找谁。

## 常用命令速查

| 命令 | 角色 | 用途 |
|------|------|------|
| `import <csv>` | 网格员 | 导入巡查表，自动检测边界点位 |
| `list` | 任何人 | 查看所有点位状态 |
| `list --boundary-only` | 项目经理 | 只看边界待复核的 |
| `view <point_id>` | 任何人 | 查看单个点位完整详情（含操作历史） |
| `supplement <point_id> ...` | 街道规划员小姜 | 补录施工告示 |
| `review <point_id> ...` | 项目经理 | 复核边界点位 |
| `export` | 任何人 | 导出带说明的地图报告 |

---

## 边界检测是怎么工作的？

1. **多边形包含判定** - 用射线法判断坐标点在哪个街道多边形内
2. **边界临近检测** - 计算点到多边形每条边的距离，小于阈值就算靠近边界
3. **只要命中两个街道或靠近边界** - 自动标记为 `边界待复核`，下一步指向项目经理
