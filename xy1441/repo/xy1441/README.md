# 共享冷藏柜取餐登记系统

项目编号：xy1441

## 项目简介

这是一个为小区"共享冷藏柜取餐"场景设计的全栈登记系统，支持本地运行。系统包含值班员管理、居民取餐、异常处理三个主要模块。

## 功能特性

### 🧑‍💼 值班员功能
- 创建当天批次（如：午餐、晚餐）
- 录入每个格口的餐品和取餐人手机号后四位
- 系统自动生成6位一次性取餐码
- 查看所有批次和格口状态
- 删除不需要的批次

### 👤 居民取餐功能
- 输入手机号后四位和取餐码
- 系统验证后标记格口为已取
- 记录取餐时间
- **防重复取餐**：已取餐品无法重复取餐

### ⚠️ 异常处理功能
- 自动识别**超过4小时**未取的超时餐品
- 支持批量将超时餐品标记为"待联系"
- 查看已标记为待联系的餐品列表
- **导出CSV**：将当天取餐记录导出为CSV文件

### 💾 数据持久化
- 所有数据（批次、格口、取餐记录）存储在本地JSON文件
- 刷新页面、重启服务后数据不丢失
- 数据目录：`data/`

## 技术栈

- **后端**：Node.js + Express
- **前端**：纯HTML/CSS/JavaScript（无框架依赖）
- **数据存储**：JSON文件（本地持久化）

## 使用流程

### 1. 值班员录入流程
1. 打开 **值班员页面**
2. 点击"创建新批次"，输入批次名称和格口数量
3. 在批次列表中点击刚创建的批次
4. 在"录入格口餐品"区域，依次填入：
   - 格口号（如：1）
   - 餐品名称（如：宫保鸡丁套餐）
   - 取餐人手机号后四位（如：1234）
5. 点击"录入"，系统自动生成取餐码并显示成功提示
6. 格口状态区域可实时查看所有格口状态

### 2. 居民取餐流程
1. 居民打开 **取餐页面**
2. 输入手机号后四位（如：1234）
3. 输入6位取餐码（值班员提供）
4. 点击"确认取餐"
5. 验证通过后显示取餐成功页面，包含格口号、餐品名称、取餐时间

### 3. 异常处理流程
1. 值班员打开 **异常处理页面**
2. 页面自动显示：
   - 超时未取统计（超过4小时未取的餐品）
   - 已标记待联系统计
3. 在"超时未取餐品"列表中：
   - 勾选需要处理的格口（支持全选）
   - 点击"批量标记为待联系"
4. 已标记的格口会出现在"已标记待联系"列表
5. 点击"导出今日记录CSV"可下载当天所有取餐记录

## API接口

### 批次管理
- `GET /api/batches` - 获取所有批次
- `POST /api/batches` - 创建新批次
  ```json
  { "batchName": "午餐批次", "slotCount": 20 }
  ```
- `DELETE /api/batches/:batchId` - 删除批次

### 格口管理
- `GET /api/batches/:batchId/slots` - 获取批次下所有格口
- `POST /api/slots` - 录入格口餐品
  ```json
  { "batchId": "xxx", "slotNumber": 1, "foodName": "宫保鸡丁", "phoneLastFour": "1234" }
  ```

### 取餐
- `POST /api/pickup` - 取餐验证
  ```json
  { "phoneLastFour": "1234", "pickupCode": "123456" }
  ```

### 异常处理
- `GET /api/exception` - 获取异常数据（超时、待联系）
- `POST /api/exception/mark-contact` - 批量标记待联系
  ```json
  { "slotIds": ["id1", "id2"] }
  ```
- `GET /api/export/csv` - 导出当天记录CSV

## 数据模型

### 批次 (Batch)
```json
{
  "id": "时间戳",
  "name": "批次名称",
  "date": "2026-05-01",
  "slotCount": 20,
  "createdAt": "ISO时间"
}
```

### 格口 (Slot)
```json
{
  "id": "唯一标识",
  "batchId": "所属批次ID",
  "slotNumber": 1,
  "foodName": "餐品名称",
  "phoneLastFour": "1234",
  "pickupCode": "123456",
  "status": "pending", // pending:待取, picked:已取, contacted:待联系
  "createdAt": "ISO时间",
  "pickedAt": "取餐时间或null"
}
```

### 取餐记录 (Record)
```json
{
  "id": "时间戳",
  "batchId": "批次ID",
  "slotId": "格口ID",
  "slotNumber": 1,
  "foodName": "餐品名称",
  "phoneLastFour": "1234",
  "pickupCode": "123456",
  "action": "pickup", // pickup:取餐, mark_contacted:标记待联系
  "timestamp": "操作时间"
}
```

## 校验规则

| 字段 | 规则 | 错误提示 |
|------|------|----------|
| 批次名称 | 非空 | 批次名称不能为空 |
| 格口数量 | 1-100 | 格口数量必须在1-100之间 |
| 格口号 | 1-批次格口数 | 格口号必须在1-N之间 |
| 餐品名称 | 非空 | 餐品名称不能为空 |
| 手机号后四位 | 4位数字 | 手机号后四位必须是4位数字 |
| 取餐码 | 6位数字 | 取餐码必须是6位数字 |

## 防重复取餐机制

取餐时系统会检查：
1. 格口状态是否为 `pending`（待取）
2. 如果状态为 `picked`（已取），提示"该餐品已被取走，不能重复取餐"
3. 如果状态为 `contacted`（待联系），提示"该餐品已标记为待联系，请联系值班员处理"

## 超时判定规则

- 超过 **4小时** 未取餐的格口会被判定为超时
- 超时时长 = 当前时间 - 格口录入时间
- 超时格口会显示在异常处理页面，供值班员批量标记

## 注意事项

1. **数据存储**：所有数据存储在 `data/` 目录下的JSON文件中，删除这些文件会清空所有数据
2. **取餐码**：每次录入格口时自动生成6位随机数字，确保同一批次内不重复
3. **日期**：批次按自然日期管理，每天的批次会自动关联当天日期
4. **无认证**：本系统为本地运行版本，未实现用户认证，适合内部使用场景
