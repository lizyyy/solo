# 自来水抢修阀门影响 API - 使用说明

## 一、系统概述

本系统是一个完整的自来水抢修阀门影响分析 API 系统，用于在管网抢修时快速判断关闭阀门对小区、医院、消防栓和优先级用户的影响范围。

### 核心功能模块

| 模块 | 功能说明 | 差异点 |
|------|----------|--------|
| **阀门拓扑** | 基于管网节点、管道、阀门的图结构计算停水范围 | 采用广度优先搜索(BFS)算法，从水源站出发计算不可达区域 |
| **抢修工单** | 完整的工单生命周期管理 | pending -> assigned -> in_progress -> waiting_review -> completed |
| **影响分析** | 自动分析影响范围并预警 | 一级优先级用户、三级医院无备用水源自动触发人工复核 |
| **停水报表** | 完整的影响报告导出 | 包含小区、医院、消防栓、优先级用户的详细清单 |

### 技术栈
- 后端：Node.js + Express
- 数据库：SQLite + Sequelize ORM
- 接口文档：Swagger UI

## 三、测试场景详解

### 场景一：顺利样例 - 南分支管道抢修

**目标**：关闭V007（南分支控制阀），影响N007区域

**影响范围**：
- 小区：河畔新村C004（560户，1680人）
- 医院：仁爱医院H003（二级，有备用水源）
- 消防栓：FH004
- 优先级用户：化工园区PU003（2级）、污水处理厂PU006（2级）

**预期结果**：无高危预警，顺利执行

**执行流程**：
```
创建工单 → 指派 → 阀门推荐 → 影响分析(无复核) 
  → 确认 → 关闭阀门 → 开始抢修 → 提交复核 → 完成(自动恢复阀门) → 导出报表
```

**关键接口**：
- `POST /api/repair-orders` - 创建工单
- `POST /api/valves/recommend` - 查询推荐阀门
- `POST /api/repair-orders/:id/impact-analysis` - 创建影响分析
- `PUT /api/repair-orders/:id/impact-analysis/:aid/finalize` - 最终确认并关闭阀门
- `PUT /api/repair-orders/:id/complete` - 完成工单（自动恢复阀门）
- `GET /api/repair-orders/:id/report` - 导出停水报表

---

### 场景二：待复核样例 - 北分支管道抢修

**目标**：关闭V006（北分支控制阀），影响N006区域

**影响范围**：
- 小区：民生家园C003（280户，840人）
- 医院：社区卫生服务中心H002（一级，无备用水源）
- 消防栓：FH003
- 优先级用户：重点中学PU002（**1级，学校**）

**触发预警**：
1. `LEVEL1_PRIORITY_USER` - 影响1个一级优先级用户（严重，需复核）
2. `SCHOOL_AFFECTED` - 影响学校（一般）

**预期结果**：需要人工复核才能继续

**执行流程**：
```
创建工单 → 影响分析(触发预警，needsReview=true)
  → 人工复核确认 → 指派 → 关闭阀门 → 开始抢修
```

**复核逻辑**：
- 当影响分析包含 `critical: true` 的预警时，`needsReview` 自动设为 `true`
- 必须先调用 `PUT /api/repair-orders/:id/impact-analysis/:aid/confirm` 确认
- 确认时需指定 `reviewer`（复核人）和 `notes`（复核备注）

## 四、核心业务规则

### 1. 工单状态流转

```
pending (待处理)
   ↓ assign()
assigned (已指派)
   ↓ 必须完成影响分析并finalize
in_progress (进行中)
   ↓ submitForReview()
waiting_review (待复核)
   ↓ complete()
completed (已完成)
```

### 2. 影响分析预警规则

系统自动检测以下情况并设置预警：

| 预警类型 | 触发条件 | 级别 | 是否需要复核 |
|----------|----------|------|--------------|
| CRITICAL_HOSPITAL | 三级医院且无备用水源 | 严重 | ✅ 是 |
| LEVEL1_PRIORITY_USER | 优先级等级为'1'的用户 | 严重 | ✅ 是 |
| LARGE_SCALE_IMPACT | 影响人口 > 5000人 | 一般 | ❌ 否 |
| SCHOOL_AFFECTED | 影响学校类型用户 | 一般 | ❌ 否 |

**注意**：只要有一个 `critical: true` 的预警，`needsReview` 就为 `true`

### 3. 阀门自动恢复机制

- 工单完成时（`complete()`）：自动将 `closedValveIds` 中的阀门状态恢复为 `open`
- 工单取消时（`cancel()`）：同样自动恢复已关闭的阀门
- 无需手动调用阀门开启接口

## 十、核心算法说明

### 阀门影响分析算法（TopologyService.js）

**输入**：要关闭的阀门ID列表 `valveIds`

**算法步骤**：
1. 构建管网图：节点 + 管道边
2. 标记被关闭阀门所在节点的所有连接边为 `blocked`
3. 从水源节点（`nodeType: 'source'`）出发，执行 BFS
4. 所有从水源不可达的节点即为受影响区域
5. 查询受影响节点关联的小区、医院、消防栓、优先级用户

**数据结构**：
```javascript
graph = {
  nodes: { 'N001': { id, name, connectedNodes: [...] }, ... },
  edges: [{ id, startNodeId, endNodeId }, ...]
}
```
