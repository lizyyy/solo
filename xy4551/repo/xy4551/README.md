# 🐾 宠物医院夜班护士工具

一个专为宠物医院夜班护士设计的本地全栈小工具，帮助管理手术排班、术后笼位、氧气流量、麻醉苏醒记录，并自动检测风险。

## ✨ 功能特性

### 📥 数据导入
- 支持导入 **CSV** 和 **JSON** 格式文件
- 5 种数据类型：
  - 手术排班
  - 术后笼位
  - 氧气流量日志
  - 麻醉苏醒记录
  - 主人接送备注

### ⚠️ 自动风险检测
系统会自动检测以下风险：

| 风险类型 | 检测规则 | 严重程度 |
|---------|---------|---------|
| **笼位冲突** | 同一笼位在重叠时间段内安排了多只宠物 | 🔴 严重 |
| **吸氧中断** | 氧气流量为 0 且状态不是"停止" | 🔴 严重 |
| **记录间隔过长** | 两次氧气记录间隔超过 30 分钟 | 🟡 警告 |
| **苏醒超时** | 手术结束后超过 120 分钟未完全苏醒 | 🔴 严重 |
| **拔管后延迟** | 拔管后超过 60 分钟未完全苏醒 | 🟡 警告 |
| **禁食备注漏交接** | 有手术安排但无主人接送交接记录 | 🟡 警告 |

### 🔧 人工改判与补备注
- 对自动检测出的风险进行人工改判
- 支持三种改判状态：
  - 忽略此风险
  - 确认风险存在
  - 标记为已解决
- 可为任意记录添加补充备注
- 所有改判和备注都会持久化存储

### 📤 导出功能
- **Markdown 交班单**：格式化的交班文档，包含所有数据、备注和改判记录
- **JSON 明细**：完整的结构化数据，便于备份和二次处理

### 💾 数据持久化
- 所有数据存储在本地 `data/stored-data.json` 文件中
- 刷新页面后数据不会丢失
- 支持一键清空所有数据

## 🚀 快速开始

### 环境要求
- Node.js 14.0 或更高版本
- npm 或 yarn 包管理器

### 安装步骤

1. **安装依赖**
```bash
npm install
```

2. **启动服务**
```bash
npm start
```

3. **打开浏览器访问**
```
http://localhost:3000
```

### 验证功能

1. **使用示例数据测试**

项目目录下的 `samples/` 文件夹包含了带风险场景的示例数据：

```
samples/
├── surgery-schedule.csv      # 手术排班 (有禁食要求)
├── post-op-cages.csv         # 术后笼位 (包含笼位冲突)
├── oxygen-logs.csv           # 氧气日志 (包含流量为0和间隔过长)
├── anesthesia-recovery.csv   # 苏醒记录 (包含苏醒超时)
├── owner-notes.csv           # 主人备注 (部分宠物无交接)
├── surgery-schedule.json     # JSON 格式示例
```

2. **导入示例数据**

- 打开页面后，点击「数据导入」标签
- 依次导入 5 种类型的示例数据
- 每种数据导入后点击「导入」按钮

3. **查看风险检测**

- 切换到「风险检测」标签
- 点击「重新检测风险」按钮
- 系统会自动检测出以下风险：
  - 笼位 A01 冲突（豆豆和花花时间重叠）
  - 贝贝的氧气流量为 0
  - 豆豆的氧气记录间隔过长（60 分钟）
  - 贝贝和毛毛的苏醒超时
  - 部分宠物的禁食备注漏交接

4. **测试人工改判**

- 点击任意风险项的「人工改判」按钮
- 选择改判状态并添加说明
- 保存后风险列表会实时更新

5. **测试导出功能**

- 切换到「导出交班」标签
- 点击「导出 Markdown」或「导出 JSON」
- 查看生成的文件内容

## 🎯 风险检测规则详解

### 1. 笼位冲突检测
- **触发条件**：同一笼位号的两条记录，时间区间存在重叠
- **时间比较**：开始时间和结束时间都支持 `YYYY-MM-DD HH:mm` 格式
- **字段匹配**：支持中英文关键字段名（`cageNumber`、`cage_number`、`笼位号`）

### 2. 氧气中断检测
- **流量为 0**：流量字段值为 0，且状态不是 "completed" 或 "停止"
- **间隔过长**：同一只宠物的两次记录间隔超过 30 分钟

### 3. 苏醒超时检测
- **正常阈值**：手术结束后 120 分钟内应完全苏醒
- **拔管后延迟**：拔管后 60 分钟内应完全苏醒
- **状态判断**：未填写「完全苏醒时间」且状态不是 "completed" 或 "完成"

### 4. 禁食备注漏交接
- **检测逻辑**：有手术安排的宠物，没有对应的主人接送备注
- **关键字匹配**：手术类型或备注中包含「禁食」「禁水」等关键词
- **备注检查**：主人备注中无「交接」「告知」「禁食」等关键词

## ⚠️ 注意事项

1. **数据安全**：本工具为本地运行，所有数据仅存储在本地 `data/` 目录下，不会上传到任何服务器

2. **时间格式**：建议使用 `YYYY-MM-DD HH:mm` 格式（如 `2026-05-05 09:00`），便于时间比较

3. **中文支持**：导入的 CSV/JSON 文件支持中文字段名，系统会自动识别

4. **数据备份**：建议定期导出 JSON 格式数据进行备份

5. **刷新页面**：由于数据存储在后端，刷新页面后数据不会丢失

## 🛠️ 常见问题

**Q: 导入 CSV 文件时乱码怎么办？**
A: 请确保 CSV 文件使用 UTF-8 编码保存。可使用记事本打开后另存为 UTF-8 格式。

**Q: 风险检测结果为空？**
A: 请确保已导入数据，且数据中确实存在可检测的风险场景。可使用 samples 目录下的示例数据进行测试。

**Q: 数据保存在哪里？**
A: 所有数据保存在项目目录下的 `data/stored-data.json` 文件中。可手动备份此文件。

**Q: 如何修改风险检测阈值？**
A: 可编辑 `server/utils/riskDetector.js` 文件中的常量：
- `NORMAL_RECOVERY_MINUTES`：正常苏醒时间（默认 120 分钟）
- 氧气间隔阈值（默认 30 分钟）
