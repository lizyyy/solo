# 厌氧发酵罐交接班复盘看板

一个用于餐厨垃圾处理站工艺员交接班前复盘厌氧发酵罐运行状态的 Streamlit 交互式看板应用。

## 功能特性

- **多源数据整合**: 自动读取并归一化传感器数据、投料事件和工艺规则
- **关键指标计算**: 实时计算 pH 趋势、温度稳定性、VFA 变化、投料负荷和产气效率
- **智能风险检测**: 自动识别酸化风险、温控漂移、投料过载、产气骤降和传感器断采等问题
- **交互式筛选**: 支持按罐体和日期/班段筛选数据，联动更新所有图表和列表
- **可视化展示**: 多维度趋势图、投料事件列表和风险详情展示
- **报告导出**: 一键导出风险清单 (CSV) 和交接班报告 (Markdown)

## 快速开始

### 1. 环境准备

确保已安装 Python 3.8 或更高版本。

### 2. 安装依赖

```bash
pip install -r requirements.txt
```

### 3. 运行应用

```bash
streamlit run app.py
```

应用启动后，浏览器会自动打开 `http://localhost:8501`

### 4. 浏览功能

应用启动后，你可以：

1. **选择罐体**: 在侧边栏选择要分析的厌氧发酵罐（D1 或 D2）
2. **设定时间范围**: 
   - 选择"夜班数据（覆盖午夜）"模式来测试跨午夜数据处理
   - 或选择特定日期和班段（白班/夜班）
3. **查看运行概览**: 顶部指标卡片显示 pH、温度、VFA 和产气量的关键统计
4. **分析趋势图**: 交互式多子图展示参数变化趋势
5. **检查投料事件**: 查看该时间段内的所有投料记录
6. **识别风险项**: 查看系统检测到的各类运行风险及建议措施
7. **导出报告**: 下载风险清单和完整的交接班复盘报告

## 数据格式说明

### 1. 传感器数据 (sensor_readings.csv)

包含 pH、温度、VFA 和产气量等传感器的时间序列数据。

**字段说明**:
- `timestamp`: 采样时间戳 (格式: YYYY-MM-DD HH:MM:SS)
- `digester_id`: 罐体编号 (如 D1, D2)
- `sensor_type`: 传感器类型 (pH, temperature, VFA, gas_production)
- `value`: 测量值
- `unit`: 单位

**示例数据特性**:
- D1 罐体包含酸化风险场景（pH 持续下降、VFA 升高、产气量骤降）
- D1 包含跨午夜数据（5月2日 22:00 至 5月3日 06:00）
- D1 包含传感器断采场景（2:00-3:00 无数据）
- D2 罐体运行相对平稳，用于对比展示

### 2. 投料事件 (feed_events.jsonl)

记录每次投料的详细信息，采用 JSON Lines 格式。

**字段说明**:
- `timestamp`: 投料时间
- `digester_id`: 罐体编号
- `feed_type`: 原料类型
- `quantity_kg`: 投料重量 (kg)
- `operator`: 操作员姓名
- `remarks`: 备注信息

**示例数据特性**:
- D1 在 22:30 有一次过载投料（8000kg，超过设计负荷）
- 包含夜间跨午夜的投料记录

### 3. 工艺规则 (process_rules.yaml)

定义正常运行参数范围和风险检测阈值的配置文件。

**主要配置项**:
1. **罐体配置**: 设计容积、负荷限值、标称温度等
2. **参数阈值**: pH、温度、VFA、产气量的正常范围和警戒值
3. **风险检测规则**: 各类风险的触发条件和严重程度定义
4. **采样配置**: 预期采样间隔、缺失数据容忍度

## 边界情况处理

应用已内置处理以下边界情况的能力：

### 1. 跨午夜数据

**场景**: 夜班数据跨越两天（如 20:00 次日 08:00）

**处理方式**:
- 时间线归一化函数会自动处理跨日期的时间范围
- `normalize_timeline` 方法支持任意开始和结束时间
- 在 UI 中提供"跨夜班数据"模式，直接选择开始和结束日期
- 趋势图的 X 轴会正确显示日期变更点

**测试方法**:
- 在侧边栏选择"跨夜班数据（覆盖午夜）"模式
- 开始日期选择 2026-05-02，结束日期选择 2026-05-03
- 观察趋势图如何展示跨午夜的连续数据

### 2. 缺采样/数据缺失

**场景**: 传感器故障或通讯中断导致部分时间点无数据

**处理方式**:
- 归一化过程中会识别插值点并标记 `is_interpolated=True`
- 趋势图中用红色标记显示缺失/插值数据点
- 指标计算时自动忽略 NaN 值，基于有效数据计算统计量
- 风险检测包含"传感器断采"规则，识别连续缺失超过阈值的情况
- 数据质量检查区域会显示插值点占比

**测试方法**:
- 查看 D1 罐体的数据，02:00-03:00 时间段被设置为传感器断采
- 观察趋势图中对应时间点的红色标记
- 检查"数据质量检查"区域是否提示存在插值点
- 查看风险检测结果中是否有"传感器断采"警告

## 风险检测规则

### 1. 酸化风险 (Acidification)

**触发条件**:
- pH 值低于 6.8 并持续超过 60 分钟
- 同时 VFA 高于 3000 mg/L

**严重程度**:
- pH < 6.5: Critical
- 6.5 ≤ pH < 6.8 或 VFA > 3000: Warning

**建议措施**:
- 立即停止投料
- 检查碱度，必要时投加 NaOH 或 NaHCO3
- 增加监测频率

### 2. 温控漂移 (Temperature Drift)

**触发条件**:
- 实际温度偏离标称温度超过 2℃
- 或温度变化速率超过 1℃/小时

**严重程度**:
- 偏离 ≥ 2℃: Critical
- 偏离 ≥ 1.5℃ 或速率过快: Warning

**建议措施**:
- 检查加热/冷却系统
- 核对蒸汽流量和循环泵状态
- 确认温度传感器校准

### 3. 投料过载 (Overloading)

**触发条件**:
- 单次投料超过日限额的 30%
- 或日累计投料超过设计值的 110%

**严重程度**:
- 超过 120% 或单次超大投料: Critical
- 超过 110%: Warning

**建议措施**:
- 减少后续投料量
- 监测 pH 和 VFA 变化
- 必要时延长停留时间

### 4. 产气骤降 (Gas Production Drop)

**触发条件**:
- 产气量在 2 小时内下降超过 40%
- 与前期基准值相比显著降低

**严重程度**:
- 下降 ≥ 60%: Critical
- 下降 ≥ 40%: Warning

**建议措施**:
- 检查进料成分变化
- 核对 pH 和 VFA
- 评估是否发生酸中毒

### 5. 传感器断采 (Sensor Failure)

**触发条件**:
- 连续缺失超过 3 个采样点
- 或缺失数据占比超过 30%

**严重程度**:
- 连续缺失 ≥ 6 个点: Critical
- 连续缺失 ≥ 3 个点: Warning

**建议措施**:
- 检查传感器供电和通讯线路
- 必要时进行校准或更换
- 采用人工监测补全数据

## 导出功能

### 1. 风险清单导出 (issues.csv)

包含以下字段：
- 罐体编号
- 分析时间范围

- 严重程度

- 详细信息（JSON 格式）
- 建议措施
- 检测时间

### 2. 交接班报告导出 (digester_report.md)

包含以下章节：
- 基本信息
- 运行指标摘要（pH、温度、VFA、产气、投料负荷、产气效率）
- 风险检测结果（按严重程度分组）
- 交接班建议

## 常见问题

### Q: 如何添加新的罐体？

A: 在 `process_rules.yaml` 的 `digesters` 配置块中添加新罐体的定义，包括名称、设计容积、标称温度等参数。

### Q: 如何调整风险检测的灵敏度？

A: 修改 `process_rules.yaml` 中的 `risk_detection_rules` 部分，调整各风险类型的触发条件阈值（如持续时间、偏离程度等）。

### Q: 数据缺失时如何处理？

A: 应用会自动：
1. 在归一化时标记插值点
2. 统计时忽略无效数据
3. 检测到连续缺失时触发传感器断采警告

建议：
- 及时修复传感器故障
- 必要时采用人工监测补充关键数据
- 在交接班记录中注明数据缺失情况

### Q: 如何实现与实时数据库的对接？

A: 可以修改 `load_sensor_data` 和 `load_feed_events` 方法，从数据库接口或 API 获取实时数据，而不是读取本地文件。需要保持返回的 DataFrame 结构不变。
