# 乡村快递共配结算台

一个专为乡村快递共配点设计的多快递公司包裹管理与费用结算系统。解决了派件、退件和滞留件结算口径不同的问题。

## 项目特色

- **多快递公司共配**：同时管理顺丰、圆通、中通、韵达、申通等多家快递
- **三种结算口径**：
  - **派件**：按快递公司配置的派件费计算
  - **退件**：退件费 + 滞留保管费（扣除免费天数）
  - **滞留**：按滞留规则计算保管费
- **费用分摊**：自动计算派件费、退件费、保管费的明细和汇总
- **数据持久化**：SQLite数据库，刷新不丢数据
- **批量导入**：支持CSV批量导入包裹
- **结算导出**：生成带费用明细的CSV结算报告

## 启动命令

### 方式一：分别启动（开发模式）

1. **安装依赖**
```bash
# 后端
cd backend
npm install

# 前端
cd ../frontend
npm install
```

2. **导入样例数据**（首次运行建议执行）
```bash
cd backend
npm run seed
```

3. **启动后端**
```bash
cd backend
npm run dev
# 服务运行在 http://localhost:3001
```

4. **启动前端**（新终端窗口）
```bash
cd frontend
npm run dev
# 访问 http://localhost:3000
```

## 主流程演示

1. **数据概览** → 查看整体统计和费用分摊

2. **快递公司管理** → 配置各公司的派件费、退件费、保管费

3. **滞留规则配置** → 设置免费天数和保管费率
   - 全局规则：适用于所有未单独配置的公司
   - 公司规则：特定公司的专属规则（优先级更高）

4. **包裹管理**
   - 扫描运单号 → 快速查询
   - 新建包裹 → 手动录入
   - 导入CSV → 批量录入
   - 签收/退件 → 状态推进，费用自动计算

5. **结算中心**
   - 新建结算单 → 选择快递公司和时间段
   - 查看明细 → 确认费用分摊
   - 导出CSV → 生成正式报告
   - 确认结算 → 锁定状态

## 关键业务规则

### 费用计算逻辑

| 状态 | 费用构成 |
|------|----------|
| 待处理(pending) | 仅记录派件费基础（未结算） |
| 已签收(delivered) | 总费用 = 派件费 |
| 已退件(returned) | 总费用 = 退件费 + 保管费 |

### 滞留保管费计算

```
保管费 = max(0, (滞留天数 - 免费天数) × 每日保管费)
```

- **滞留天数**：退件时间 - 扫描时间
- **免费天数**：由滞留规则决定（公司规则 > 全局规则 > 默认3天）
- **每日保管费**：由滞留规则或公司配置决定

## 异常操作演示

系统在以下情况会明确报错（接口响应/页面弹窗/命令输出）：

| 操作 | 预期异常 |
|------|----------|
| 重复运单号 | "该运单号已存在" |
| 重复编码的快递公司 | "该公司编码已存在" |
| 已签收包裹退件 | "该包裹已签收，不可退件" |
| 已退件包裹签收 | "该包裹已退件，不可签收" |
| 删除有包裹的快递公司 | "该快递公司存在关联包裹，无法删除" |
| 已确认结算单再次确认 | "该结算单已确认，不可重复确认" |
| 创建多个全局滞留规则 | "已存在全局滞留规则，请先删除后再创建" |
| 开始日期晚于结束日期 | "开始日期不能晚于结束日期" |
| 导入CSV缺少必填字段 | 提示具体行号和错误原因 |

## API接口说明

### 快递公司 (`/api/courier-companies`)
- `GET /` - 获取列表
- `POST /` - 创建
- `PUT /:id` - 更新
- `DELETE /:id` - 删除

### 滞留规则 (`/api/retention-rules`)
- `GET /` - 获取列表
- `POST /` - 创建
- `PUT /:id` - 更新
- `DELETE /:id` - 删除

### 包裹 (`/api/packages`)
- `GET /` - 获取列表（支持筛选）
- `GET /stats` - 获取统计
- `GET /:id` - 获取详情
- `POST /` - 创建
- `POST /scan` - 扫描运单号
- `POST /import` - 批量导入CSV
- `PATCH /:id/deliver` - 签收
- `PATCH /:id/return` - 退件（自动计算滞留费）
- `DELETE /:id` - 删除

### 结算 (`/api/settlements`)
- `GET /` - 获取列表
- `GET /stats` - 获取统计
- `GET /:id` - 获取详情
- `POST /` - 创建结算单
- `PATCH /:id/confirm` - 确认结算
- `GET /:id/export` - 导出明细

## 技术栈

- **后端**：Node.js + Express + TypeScript + SQLite (better-sqlite3)
- **前端**：React 18 + TypeScript + Vite + React Router + Axios
- **数据持久化**：SQLite 本地文件（WAL模式）
