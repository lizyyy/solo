# 售后照片清点 CLI 工具

用于售后维修照片的批量清点，检测缺失的前后对比照片，识别重复文件，生成归档报告。

## 功能特性

- 📁 **目录扫描**: 递归扫描目录中的所有图像文件
- 🔍 **智能命名解析**: 支持多种命名格式（中英文、不同字段顺序）
- ⚠️ **缺图检测**: 自动检测工单缺失的照片类型（维修前/后等）
- 🔄 **重复识别**: 识别同一工单同一类型的重复照片
- 📊 **多格式输出**: 终端摘要、JSON 机器可读结果、Markdown 归档报告
- 🧪 **自检功能**: 内置测试用例，验证边界处理和导出功能
- 📝 **异常保留**: 无法解析的文件单独记录，保留原始位置信息

## 支持的命名格式

工具支持以下文件名格式（不区分大小写）：

```
{客户编号}-{工单号}-{照片类型}[-{序号}].{扩展名}
{客户编号}-{照片类型}-{工单号}[-{序号}].{扩展名}
{工单号}-{客户编号}-{照片类型}[-{序号}].{扩展名}
客户{客户编号}-工单{工单号}-{照片类型}[-{序号}].{扩展名}
C{客户编号}-WO{工单号}-{照片类型}[-{序号}].{扩展名}
```

### 照片类型映射

| 输入 | 标准化 |
|------|--------|
| before, 维修前, pre | before |
| after, 维修后, post | after |
| repair, 维修中 | repair |
| inspection, 检查 | inspection |

### 支持的图像格式

.jpg, .jpeg, .png, .gif, .bmp, .webp, .heic

## 安装

```bash
npm install
```

## 使用方法

### 1. 清点照片目录

```bash
# 基本用法
node src/index.js audit -d /path/to/photos

# 指定输出目录
node src/index.js audit -d /path/to/photos -o ./output

# 指定照片类型
node src/index.js audit -d /path/to/photos -t before,after,repair

# 按客户或工单过滤
node src/index.js audit -d /path/to/photos -c CUST001
node src/index.js audit -d /path/to/photos -w WO001

# 只显示摘要，不导出
node src/index.js audit -d /path/to/photos --no-export

# 只导出，不显示终端摘要
node src/index.js audit -d /path/to/photos --no-summary
```

### 2. 运行自检

```bash
# 运行所有自检，测试完成后清理数据
npm test
# 或
node src/index.js self-test

# 运行自检，保留测试数据
node src/index.js self-test --keep
```

### 3. 调试单个文件名解析

```bash
node src/index.js parse "CUST001-WO001-before.jpg"
```

## 命令选项

### `audit` 命令

| 选项 | 缩写 | 说明 | 默认值 |
|------|------|------|--------|
| --directory | -d | 照片目录路径（必填） | - |
| --output | -o | 输出目录路径 | ./audit-output |
| --customer | -c | 客户编号过滤 | - |
| --workorder | -w | 工单号过滤 | - |
| --types | -t | 照片类型列表，逗号分隔 | before,after |
| --no-summary | - | 不显示终端摘要 | false |
| --no-export | - | 不导出结果文件 | false |

### `self-test` 命令

| 选项 | 缩写 | 说明 | 默认值 |
|------|------|------|--------|
| --keep | -k | 保留测试数据目录 | false |

## 输出文件说明

运行清点后，输出目录会包含以下文件：

### 1. `audit-result-{时间戳}.json`

机器可读的完整结果，包含：
- 所有有效解析的文件信息
- 无法解析的文件及原因
- 缺失照片的工单一览
- 重复文件组详情

### 2. `audit-report-{时间戳}.md`

给同事查看的 Markdown 格式报告，包含：
- 工单完整性统计及完成率
- 缺失照片明细表格
- 重复文件明细
- 无法解析的文件列表
- 按客户的统计汇总

### 3. `invalid-files-{时间戳}.txt`（如有）

仅包含无法解析的文件，每条记录包含：
- 文件完整路径
- 解析失败原因
- 原始文件名

## 常见问题

### Q: 文件名无法被解析怎么办？

A: 请检查文件名是否符合支持的格式。无法解析的文件会被单独记录在 `invalid-files-*.txt` 中，包含具体原因。

### Q: 如何添加新的照片类型？

A: 修改 `src/scanner.js` 中的 `normalizePhotoType` 函数，添加新的类型映射。

### Q: 自检失败了怎么办？

A: 请运行 `node src/index.js self-test` 查看具体失败的测试项，根据错误信息修复问题。自检会验证：
- 文件名解析正确性
- 目录扫描功能
- 缺失照片检测
- 重复文件识别
- 导出功能
- 边界情况处理
