我想做一个给医院药房和社区配送员一起用的本地桌面 GUI 应用，叫“冷藏药品交接温控追溯台”。我们每天会把胰岛素、疫苗、试剂这类需要冷链的药品从药房交给配送员，再送到门诊或社区点；现在温度记录仪导出的 CSV、交接签收单照片和异常备注都散在文件夹里，最怕某一段超温没人发现、箱号和批号对不上，事后追责也说不清。请从 0 到 1 做一个能直接运行的桌面应用：左侧维护冷藏箱、药品批号、配送路线和收货点；中间是交接任务看板，任务状态包括待装箱、运输中、待签收、需复核、已归档；右侧能查看每个任务的温度曲线、装箱清单、签收附件、异常记录和审计日志。应用要支持导入温度记录仪 CSV，字段包含设备号、时间戳、温度、箱号和电量，导入时要校验时间倒序、采样间隔缺口、设备号不在配置里、箱号和任务不匹配、温度单位混乱、低电量和重复记录，坏行进入隔离区并说明原因。状态流转要有规则：没有装箱清单不能开始运输，运输期间如果连续超温超过阈值要自动转为需复核，签收前必须有关联的收货点和签收附件，归档前必须生成一份包含温度风险、处理意见和附件哈希的审计包。附件导入时要复制到本地数据目录并计算 SHA256，识别同名不同内容和缺失签收照片。数据要保存在本地 SQLite 或文件数据库里，重启后能继续；还要支持从药房 CSV 批量导入装箱任务、导出 Markdown 交接复盘、CSV 超温风险清单和 JSON 审计包。请把 GUI 入口、数据模型、温度 CSV 解析、规则校验、任务状态机、附件归档、持久化、导入导出、报告生成、示例数据和测试拆成多个文件，不要写成一个大脚本。README 里写清楚安装方式、启动命令，以及如何用临时目录验证创建任务、导入温度 CSV、触发超温复核、补充签收附件、归档和导出审计包这些核心流程。
