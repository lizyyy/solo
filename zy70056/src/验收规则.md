# 反洗钱名单命中复核 API 系统验收规则

## 一、启动和基础检查

### 1.1 服务启动
**验收现象：**
- 执行 `npm install` 和 `npm run dev` 后，控制台显示服务运行在 http://localhost:3000
- 访问 GET http://localhost:3000/health 返回 `{"status": "ok", ...}`

### 1.2 API 文档
**验收现象：**
- 访问 GET http://localhost:3000/ 可以看到所有可用的 API 端点列表
- 返回数据包含版本号和每个模块的具体路由

---

## 二、名单版本管理

### 2.1 创建名单版本
**验收操作：** POST /api/list-versions
**请求体：**
```json
{
  "name": "高风险客户名单",
  "description": "国际制裁名单及高风险地区客户",
  "version": "v2024.01",
  "createdBy": "admin"
}
```

**验收现象：**
- 返回创建成功的名单版本对象，包含 id、name、version 等字段
- status 为 "active"
- createdBy 为 "admin"
- createdAt 和 updatedAt 时间戳正确

### 2.2 查询名单版本列表
**验收操作：** GET /api/list-versions
**验收现象：**
- 返回数组，包含所有名单版本
- 可以用 `?status=active` 或 `?status=archived` 过滤
- 按创建时间倒序排列

### 2.3 归档名单版本
**验收操作：** POST /api/list-versions/{id}/archive
**请求体：** `{"actor": "manager"}`
**验收现象：**
- 返回更新后的对象，status 变为 "archived"
- 再查询列表时，该版本不再出现在 active 列表中

---

## 三、命中记录与账户冻结（核心流程）

### 3.1 首次命中名单
**验收操作：** POST /api/hits
**请求体：**
```json
{
  "listVersionId": "{名单版本ID}",
  "accountId": "ACC-001",
  "transactionId": "TX-2024-001",
  "matchReason": "账户名与制裁名单高度匹配",
  "matchScore": 0.95,
  "createdBy": "system"
}
```

**验收现象：**
- 返回数据中 `isRepeatHit` 为 false
- `freeze` 字段不为空，包含账户冻结记录
- `freeze.status` 为 "frozen"
- `hitRecord.status` 为 "pending_review"
- `hitRecord.currentBlock` 为 "review"
- 响应中有提示："首次命中，账户已冻结，等待人工复核"

### 3.2 重复命中同一账户
**验收操作：** 用相同的 accountId 再调用一次 POST /api/hits

**验收现象：**
- 返回数据中 `isRepeatHit` 为 true
- `freeze` 字段为 null（不重复冻结）
- 响应中有提示："检测到重复命中，账户已存在活跃冻结，本次仅记录命中不重复冻结"
- 但新的命中记录被创建（status 同样为 pending_review）

### 3.3 查询账户汇总
**验收操作：** GET /api/accounts/ACC-001/summary

**验收现象：**
- `isFrozen` 为 true
- `currentStatus` 显示 "账户已冻结，有 X 条记录卡在复核环节"
- `activeFreeze` 字段显示当前活跃的冻结记录
- `summary.totalHits` 为命中总次数
- `summary.totalFreezes` 为实际冻结次数（应该只算一次，因为重复命中不重复冻结）
- `summary.blockedInReview` 显示卡在复核环节的数量
- `summary.totalBlocked` 显示所有卡点记录总数

## 四、人工复核流程

### 4.1 查看命中详情（复核前）
**验收操作：** GET /api/hits/{hitId}

**验收现象：**
- `hitRecord.status` 为 "pending_review"
- `statusDescription` 为 "等待人工复核 - 交易刚命中名单，账户已冻结，需要人工确认命中是否有效"
- `currentBlock` 显示 "当前卡点: review"
- `hasBlock` 为 true
- `blockInfo.description` 说明卡在人工复核环节
- `reviewRecords` 数组为空（尚未复核）
- `lastReview` 为 null
- `previousReview` 为 null
- `auditLogs` 数组包含命中记录和冻结创建的日志

### 4.2 复核驳回
**验收操作：** POST /api/hits/{hitId}/review
**请求体：**
```json
{
  "decision": "rejected",
  "reviewer": "zhangsan",
  "comment": "经核实，该账户与名单中的人员同名不同人，为误判"
}
```

**验收现象：**
- 返回的 `hitRecord.status` 变为 "review_rejected"
- 返回的 `review` 对象记录了这次复核：
  - `decision` 为 "rejected"
  - `reviewer` 为 "zhangsan"
  - `comment` 为驳回原因
  - `previousStatus` 为 "pending_review"

### 4.3 查看详情（复核驳回后）
**验收操作：** 再次 GET /api/hits/{hitId}

**验收现象：**
- `hitRecord.status` 为 "review_rejected"
- `statusDescription` 为 "复核被驳回 - 上一次复核不通过，需要重新处理后再次提交复核"
- `currentBlock` 仍显示 "当前卡点: review"（表示还在复核环节）
- `hasBlock` 仍为 true
- `blockInfo.description` 变为 "在人工复核环节被驳回，需要查看上次复核意见并重新处理"
- `reviewRecords` 数组有 1 条记录
- `lastReview` 显示最近一次复核（被驳回的那一次）
- `previousReview` 为 null（因为只有 1 条）
- `auditLogs` 增加了 "复核命中记录" 类型的日志

### 4.4 再次复核（通过）
**验收操作：** 再次调用 POST /api/hits/{hitId}/review
**请求体：**
```json
{
  "decision": "approved",
  "reviewer": "zhangsan",
  "comment": "补充资料后确认是误判，但业务要求走完整流程，通过"
}
```

**验收现象：**
- 返回的 `hitRecord.status` 变为 "review_approved"
- 返回的 `review` 对象 `previousStatus` 为 "review_rejected"（记录了驳回前的状态）

### 4.5 查看详情（复核通过后）
**验收操作：** 再次 GET /api/hits/{hitId}

**验收现象：**
- `hitRecord.status` 为 "review_approved"
- `statusDescription` 为 "复核通过，可申请解冻 - 人工确认命中有效，可以发起解冻申请"
- `currentBlock` 显示 "当前卡点: unfreeze"（进入解冻审批环节）
- `blockInfo.description` 变为 "卡在解冻审批环节，等待审批"
- `reviewRecords` 数组有 2 条记录（第一次驳回，第二次通过）
- `lastReview` 是通过的那一次
- `previousReview` 是驳回的那一次（可以看到前一次处理记录！）
- 可以清晰对比两次复核的意见、决策和操作人

## 五、解冻审批流程

### 5.1 未复核通过不能申请解冻
**验收操作：** 找一个 status 为 pending_review 或 review_rejected 的冻结记录
**调用：** POST /api/freezes/{freezeId}/request-unfreeze

**验收现象：**
- 返回 400 错误
- 如果是 pending_review：错误信息为 "该冻结尚未完成人工复核，不能申请解冻"
- 如果是 review_rejected：错误信息为 "复核被驳回，需要先重新复核通过才能申请解冻"

### 5.2 提交解冻申请
**验收操作：** POST /api/freezes/{freezeId}/request-unfreeze
**请求体：**
```json
{
  "requestedBy": "lisi",
  "unfreezeReason": "客户已提交证明材料，确认非风险账户，申请解冻"
}
```

**验收现象：**
- 返回的 `freeze.unfreezeRequestedBy` 为 "lisi"
- `freeze.unfreezeRequestedAt` 有时间戳
- `freeze.unfreezeReason` 为申请原因
- `hitRecord.status` 变为 "pending_unfreeze"
- `hitRecord.currentBlock` 仍为 "unfreeze"

### 5.3 审批驳回解冻
**验收操作：** POST /api/freezes/{freezeId}/reject-unfreeze
**请求体：**
```json
{
  "approver": "manager",
  "comment": "证明材料不充分，需要补充更多资料"
}
```

**验收现象：**
- 返回的 `hitRecord.status` 变为 "unfreeze_rejected"
- `hitRecord.currentBlock` 仍为 "unfreeze"
- 返回的 `approval` 对象记录了驳回决定
- `approval.decision` 为 "rejected"

### 5.4 查看冻结详情（审批驳回后）
**验收操作：** GET /api/freezes/{freezeId}

**验收现象：**
- `freeze.status` 仍为 "frozen"（账户没有被解冻）
- `approvalRecords` 有 1 条记录（驳回的）
- `lastApproval` 显示驳回详情
- `previousApproval` 为 null
- `auditLogs` 增加了 "审批驳回解冻" 类型的日志
- 日志详情中包含驳回原因

### 5.5 查看命中详情（审批驳回后）
**验收操作：** GET /api/hits/{hitId}

**验收现象：**
- `statusDescription` 为 "解冻申请被驳回 - 上一次解冻申请不通过，可以重新申请"
- `currentBlock` 显示 "当前卡点: unfreeze"
- `blockInfo.description` 变为 "在解冻审批环节被驳回，需要查看上次审批意见并重新申请"
- `lastApproval` 显示驳回详情
- `approvalRecords` 有 1 条记录

### 5.6 再次申请解冻并通过
**验收操作：**
1. 再次调用 POST /api/freezes/{freezeId}/request-unfreeze
2. 然后 POST /api/freezes/{freezeId}/approve-unfreeze
**请求体（第二步）：**
```json
{
  "approver": "manager",
  "comment": "补充材料充分，同意解冻"
}
```

**验收现象：**
- 第二步返回的 `freeze.status` 变为 "unfrozen"
- `freeze.unfrozenAt` 有时间戳
- `freeze.unfrozenBy` 为 "manager"
- `hitRecord.status` 变为 "unfreeze_approved"
- `hitRecord.currentBlock` 变为 "none"（没有卡点了）

### 5.7 查看最终详情
**验收操作：** GET /api/hits/{hitId}

**验收现象：**
- `hitRecord.status` 为 "unfreeze_approved"
- `statusDescription` 为 "解冻审批通过 - 账户已解除冻结，流程完成"
- `currentBlock` 显示 "无卡点"
- `hasBlock` 为 false
- `blockInfo.description` 为 "无当前卡点"
- `approvalRecords` 有 2 条记录（第一次驳回，第二次通过）
- `lastApproval` 是通过的那一次
- `previousApproval` 是驳回的那一次（可以看到前一次处理记录！）
- `auditLogs` 包含完整的操作历史：
  - 记录命中
  - 冻结账户
  - 复核驳回
  - 复核通过
  - 提交解冻申请
  - 审批驳回解冻
  - 提交解冻申请
  - 审批通过解冻
  - 解除冻结

## 六、审计导出功能

### 6.1 查询审计日志
**验收操作：** GET /api/audit
**验收现象：**
- 返回所有审计日志，按时间倒序
- 每条日志包含：
  - `actionType`：操作类型（如 "hit_reviewed"）
  - `entityType`：实体类型
  - `entityId`：实体ID
  - `actor`：操作人
  - `details`：JSON 对象，包含操作详情和 note 字段的说明
  - `timestamp`：时间戳

**可选过滤参数：**
- `?entityType=hit_record` 按实体类型过滤
- `?entityId={id}` 按实体ID过滤
- `?actionType=hit_reviewed` 按操作类型过滤
- `?actor=zhangsan` 按操作人过滤
- `?startDate=2024-01-01&endDate=2024-12-31` 按时间范围过滤

### 6.2 导出 CSV
**验收操作：** GET /api/audit/export/csv

**验收现象：**
- 下载一个 CSV 文件
- 包含列：序号、时间戳、操作类型、实体类型、实体ID、操作人、详情、说明
- 操作类型显示中文（如"复核命中记录"而非 "hit_reviewed"）
- 实体类型显示中文（如"命中记录"而非 "hit_record"）
- 可以配合过滤参数使用

### 6.3 导出 JSON
**验收操作：** GET /api/audit/export/json

**验收现象：**
- 下载一个 JSON 文件
- 包含 `exportTime`（导出时间）
- 包含 `params`（本次导出使用的过滤参数）
- 包含 `totalCount`（记录总数）
- 包含 `records` 数组，每条记录有 `actionTypeLabel` 和 `entityTypeLabel` 中文字段

### 6.4 导出单个命中记录的完整报告
**验收操作：** GET /api/audit/hit/{hitId}/report

**验收现象：**
- 下载一个结构化的 JSON 报告
- 包含：
  - 报告生成时间
  - 命中记录完整信息（状态、卡点、匹配原因等）
  - 冻结情况
  - 复核记录列表（含序号、复核人、决策、意见）
  - 审批记录列表
  - 审计日志列表（中文操作类型）

### 6.5 导出账户完整报告
**验收操作：** GET /api/accounts/ACC-001/report

**验收现象：**
- 下载账户完整报告
- 包含当前状态、是否冻结、统计汇总、活跃冻结详情
- 统计汇总清晰列出：总命中次数、总冻结次数、待复核、复核被驳回、待解冻审批、解冻被驳回等
- 包含所有命中记录列表和冻结记录列表

## 七、仪表盘汇总

**验收操作：** GET /api/dashboard

**验收现象：**
- 返回全局统计数据：
  - `totalHits`：总命中次数

    - `unfreezeRejected`：解冻被驳回
    - 等等

## 八、关键验收点汇总（文字描述）

### 用户应该看到的状态：

1. **命中后**：
   - 状态：pending_review
   - 卡点：review
   - 状态说明：等待人工复核
   - 审计日志有：记录命中、冻结账户

2. **复核被驳回后**：
   - 状态：review_rejected
   - 卡点：仍在 review
   - 状态说明：复核被驳回，需要重新处理
   - 卡点说明：在人工复核环节被驳回，需要查看上次复核意见
   - 能看到 lastReview（被驳回的那条）
   - 审计日志增加：复核命中记录

3. **复核通过后**：
   - 状态：review_approved
   - 卡点：移到 unfreeze
   - 状态说明：复核通过，可申请解冻
   - 如果之前被驳回过，previousReview 指向驳回记录
   - 能比较两次复核的不同意见

4. **申请解冻后**：
   - 状态：pending_unfreeze
   - 卡点：仍在 unfreeze
   - 冻结记录有 unfreezeRequestedAt、unfreezeReason 等字段

5. **审批被驳回后**：
   - 状态：unfreeze_rejected
   - 卡点：仍在 unfreeze
   - 状态说明：解冻申请被驳回
   - 卡点说明：在解冻审批环节被驳回，需要查看上次审批意见
   - 账户仍为 frozen

6. **审批通过后**：
   - 状态：unfreeze_approved
   - 卡点：none（无卡点）
   - 账户变为 unfrozen
   - 如果之前被驳回过，previousApproval 指向驳回记录

### 用户应该看到的记录：

- 每个命中记录的详情页面包含：
  - 所有复核记录（历史）
  - 所有审批记录（历史）
  - 完整的审计日志（按时间排序）
  - 最近一次处理记录（lastReview、lastApproval）
  - 前一次处理记录（previousReview、previousApproval）- 用于对比分析被驳回的原因

- 每个账户的汇总页面包含：
  - 当前状态描述（自然语言）
  - 是否冻结
  - 各种状态的计数
  - 卡点分布（卡在复核环节 X 条，卡在解冻审批 Y 条）

### 用户应该看到的汇总：

- 仪表盘显示全局统计
- 账户维度的统计汇总
- 审计导出支持多种格式（CSV、JSON）
- 单个实体的完整报告导出

### 日志和历史：

- 所有关键操作都有审计日志
- 日志详情包含操作说明（note 字段）
- 不需要读源码就能知道发生了什么
- 可以按实体、操作人、时间等维度过滤审计日志
- 审计日志包含操作前后的状态变化（如 previousStatus）
