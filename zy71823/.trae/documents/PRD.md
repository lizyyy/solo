## 1. 产品概述

社群运营证据链工具，将排行榜截图、活动复盘和关卡草表统一到一条时间线上查看，并通过"古城巡逻解谜"自动对账，区分"仅补材料"和"真正改了结论"两种变更，让活动负责人不看代码也能看懂原因和下一步。

- 目标用户：社群运营活动负责人，不需要技术背景
- 核心价值：三类证据同线可查，自动判断+人工确认双保险，结论变更有迹可循

## 2. 核心功能

### 2.1 用户角色

| 角色 | 权限 |
|------|------|
| 活动负责人 | 查看时间线、确认/驳回对账结果、导出证据链 |
| 数据录入员 | 上传排行榜截图、补录活动复盘、编辑关卡草表 |

### 2.2 功能模块

1. **时间线总览页**：三类证据按时间合并展示，支持按来源/状态筛选，时间线上用图标和颜色区分排行榜截图（📷 早到）、活动复盘（📝 晚补）、关卡草表（✏️ 手工改）
2. **古城巡逻解谜页**：自动对账面板，列出每条对账结果的判断（补材料 vs 改结论），展示判断理由和下一步操作建议，支持人工确认/驳回
3. **证据管理页**：上传排行榜截图、补录活动复盘、编辑关卡草表，导出完整证据链为 JSON 文件，人工确认记录持久化到 localStorage

### 2.3 页面详情

| 页面名称 | 模块名称 | 功能描述 |
|----------|----------|----------|
| 时间线总览 | 时间轴线 | 三类证据按时间排列，每条显示来源类型、时间、摘要、对账状态标签 |
| 时间线总览 | 筛选栏 | 按来源类型（截图/复盘/草表）和对账状态（待对账/仅补材料/改了结论/已确认）筛选 |
| 时间线总览 | 统计卡片 | 顶部显示总数、待对账数、改结论数、已确认数 |
| 古城巡逻解谜 | 对账结果列表 | 每条显示：对账对象、自动判断（补材料/改结论）、判断理由、下一步建议 |
| 古城巡逻解谜 | 判断理由展开区 | 点击展开详细推理过程，用自然语言描述，不含代码术语 |
| 古城巡逻解谜 | 人工确认操作 | 确认/驳回按钮，确认时需填写确认备注，驳回时需填写驳回原因和修正结论 |
| 证据管理 | 上传排行榜截图 | 填写活动名、时间、上传截图文件，自动生成缩略图 |
| 证据管理 | 补录活动复盘 | 填写活动名、复盘内容、关联的排行榜截图 |
| 证据管理 | 编辑关卡草表 | 填写关卡名、草表内容、变更说明（区分新增/修改/删除） |
| 证据管理 | 证据链导出 | 一键导出所有证据+对账结果+确认记录为 JSON 文件 |
| 证据管理 | 证据链导入 | 导入 JSON 文件恢复历史证据链 |

## 3. 核心流程

用户打开工具后，在时间线总览页看到所有证据的合并视图。数据录入员上传排行榜截图、补录活动复盘、编辑关卡草表后，系统自动触发"古城巡逻解谜"对账。对账结果自动判断每条变更是"仅补材料"还是"改了结论"，并给出理由。活动负责人查看对账结果，确认或驳回。确认/驳回记录持久化存储，可导出完整证据链。

## 4. 用户界面设计

### 4.1 设计风格

- 整体风格：工业实用风（Industrial Utilitarian），干净克制，信息密度高但不杂乱
- 主色：锌灰色系（zinc）为基底，深色背景配浅色文字
- 强调色：琥珀色（amber）标记"改了结论"，翠绿色（emerald）标记"仅补材料"，石板蓝（slate）标记"待对账"
- 按钮：圆角方形，小号紧凑，状态色填充
- 字体：正文用 Noto Sans SC，标题用 LXGW WenKai，兼顾美观和中文可读性
- 布局：顶部导航栏+左侧边栏+右侧内容区，卡片式内容块
- 图标：lucide-react 图标库

### 4.2 页面设计概览

| 页面名称 | 模块名称 | UI 元素 |
|----------|----------|---------|
| 时间线总览 | 统计卡片 | 四张卡片横排，数字大号+标签小号，amber/emerald/slate/zinc 配色 |
| 时间线总览 | 筛选栏 | 水平排列的 tag 按钮组，选中态有底色 |
| 时间线总览 | 时间轴线 | 左侧竖线+节点圆点，右侧卡片，节点颜色按来源类型区分 |
| 古城巡逻解谜 | 对账结果列表 | 卡片列表，每张卡片左侧竖条颜色标识判断结果，右侧展开/收起 |
| 古城巡逻解谜 | 判断理由展开区 | 缩进区块，浅灰底，自然语言文字 |
| 古城巡逻解谜 | 人工确认操作 | 底部两个按钮（确认/驳回），点击驳回弹出文本输入框 |
| 证据管理 | 上传/录入表单 | 紧凑表单，标签在上输入在下，必填项有标记 |
| 证据管理 | 导出/导入 | 两个图标按钮，导出下载 JSON，导入弹出文件选择 |

### 4.3 响应式

桌面优先设计，内容区最小宽度 1024px。移动端暂不支持（运营工具主要在电脑上使用）。

### 4.4 3D 场景

不适用
