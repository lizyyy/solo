# 滑雪场雪道压雪排程台

## 项目简介

这是一个夜间压雪车作业排程管理系统，用于滑雪场根据雪道开放时间、积雪厚度和设备故障状态智能安排压雪任务。

### 核心业务闭环
- **雪道档案**：管理雪道基本信息、开放窗口、积雪厚度要求
- **压雪任务**：创建、分配、确认、拒绝、完成压雪任务
- **车辆状态**：管理压雪车状态，支持故障报告和自动改派
- **作业报告**：记录作业结果，支持审核和导出

### 关键特性（辨识度）
1. **雪道开放窗口限制**：压雪任务只能安排在雪道非开放时间（通常为夜间）
2. **压雪车故障改派**：车辆故障时自动将任务重新分配到待分配队列
3. **夜间作业排程**：基于积雪厚度和优先级自动生成夜间排程

## 技术栈

- **后端**：Node.js + Express + TypeScript + Prisma (SQLite)
- **前端**：React + TypeScript + Vite
- **数据存储**：SQLite（便于演示和迁移）
- **导出功能**：ExcelJS（支持导出为 Excel）

## 主流程演示

### 场景：夜间压雪排程完整流程

#### 步骤1：查看总览页面
访问 http://localhost:5173/dashboard
- 查看雪道积雪状态（哪些需要压雪）
- 查看车辆状态（哪些可用）
- 查看任务统计

#### 步骤2：创建压雪任务
访问 http://localhost:5173/tasks
1. 点击"新增任务"
2. 选择需要压雪的雪道（如"高级雪道1号"）
3. 设置计划时间（必须在雪道开放窗口之外，如 22:00 - 次日 02:00）
4. 点击"创建任务"

**关键验证**：
- 如果尝试在雪道开放时间（如 10:00-12:00）创建任务，系统会报错
- 错误信息会显示："压雪任务不能安排在雪道开放时间内"

#### 步骤3：分配任务
1. 在任务列表找到刚创建的任务（状态：待分配）
2. 点击"分配"
3. 选择可用的压雪车
4. 点击"确认分配"

任务状态变为：**待执行**

#### 步骤4：确认任务开始
1. 在任务列表找到分配好的任务
2. 点击"确认"

任务状态变为：**执行中**

#### 步骤5：完成任务
1. 在任务列表找到执行中的任务
2. 点击"完成"
3. 填写作业后积雪厚度（如 45cm）和质量评分（如 9分）
4. 点击"确认完成"

任务状态变为：**已完成**

#### 步骤6：创建作业报告
访问 http://localhost:5173/reports
1. 点击"新增报告"
2. 选择刚完成的任务
3. 填写报告人、遇到的问题等信息
4. 点击"创建报告"

#### 步骤7：审核报告
1. 在报告列表找到刚创建的报告
2. 点击"审核通过"
3. 输入审核人姓名

报告状态变为：**已审核**

#### 步骤8：导出数据
- 任务列表：点击"导出Excel"或"导出JSON"
- 报告列表：点击"导出Excel"或"导出JSON"

### 一键自动排程

如果不想手动创建任务，可以使用自动排程功能：

1. 访问 http://localhost:5173/tasks
2. 点击"🤖 自动排程"
3. 系统会自动：
   - 找出所有积雪厚度不足的雪道
   - 按优先级排序
   - 分配可用的压雪车
   - 设置夜间作业时间

## 异常操作演示

### 场景1：在雪道开放时间内创建任务

**操作**：
1. 在任务排程页面点击"新增任务"
2. 选择任意雪道
3. 设置时间在雪道开放窗口内（如 09:00-11:00）
4. 点击"创建任务"

**预期结果**：
- 创建失败
- 显示错误："压雪任务不能安排在雪道开放时间内，必须安排在夜间作业窗口"

**验证方式**：
- 前端页面会显示红色错误提示
- 后端日志会输出错误信息
- API 返回 400 错误

### 场景2：车辆故障导致任务改派

**操作**：
1. 访问 http://localhost:5173/vehicles
2. 找到状态为"作业中"或"可用"的车辆
3. 点击"报告故障"
4. 确认操作

**预期结果**：
- 车辆状态变为"故障"
- 如果该车辆有未完成的任务，任务会被重新分配到"待分配"队列
- 任务的"改派"标记变为"是"
- 任务的原始车辆 ID 会被记录

**验证方式**：
- 车辆状态卡片变为红色（故障）
- 任务列表中可以看到该任务重新回到"待分配"
- 任务的"改派"列显示"是"

### 场景3：拒绝任务

**操作**：
1. 创建一个任务并分配车辆（状态：待执行）
2. 点击"拒绝"
3. 输入拒绝原因（如"车辆需要先加油"）

**预期结果**：
- 任务状态变为"已拒绝"
- 车辆被释放，可以分配其他任务
- 任务记录显示拒绝原因
- 任务标记为"改派"

**验证方式**：
- 任务状态变为灰色（已拒绝）
- 车辆重新出现在可用列表中
- 任务列表显示拒绝原因

### 场景4：没有可用车辆时自动排程

**操作**：
1. 将所有车辆设置为"故障"或"维修中"
2. 访问任务排程页面
3. 点击"🤖 自动排程"

**预期结果**：
- 自动排程会尝试为所有需要压雪的雪道分配车辆
- 由于没有可用车辆，所有排程都会失败
- 结果显示"失败：没有可用的压雪车"

**验证方式**：
- 前端会显示每个雪道的排程结果
- 成功数量为 0，失败数量等于需要压雪的雪道数

### 场景5：删除有未完成任务的雪道

**操作**：
1. 找到有未完成任务的雪道（任务状态：待分配/待执行/执行中）
2. 在雪道档案页面点击"删除"
3. 确认删除

**预期结果**：
- 删除失败
- 显示错误："该雪道有未完成的任务，无法删除"

**验证方式**：
- 前端显示红色错误提示
- 雪道仍然存在于列表中

## 数据模型

### 雪道（Slope）
- id: 唯一标识
- name: 雪道名称
- difficulty: 难度（初级/中级/高级/专业）
- length: 长度（米）
- area: 面积（平方米）
- openWindowStart: 开放开始时间（如 08:00）
- openWindowEnd: 开放结束时间（如 18:00）
- minSnowThickness: 最小积雪厚度（cm）
- targetSnowThickness: 目标积雪厚度（cm）
- currentSnowThickness: 当前积雪厚度（cm）
- status: 状态（开放/关闭/维护中）
- priority: 优先级（1-10，1最高）

### 压雪车（Vehicle）
- id: 唯一标识
- name: 车辆名称
- model: 型号
- status: 状态（可用/维修中/作业中/故障）
- capacityPerHour: 每小时作业能力（平方米）
- currentLocation: 当前位置
- lastMaintenance: 上次维护时间
- assignedTaskId: 当前分配的任务 ID

### 压雪任务（Task）
- id: 唯一标识
- slopeId: 雪道 ID
- vehicleId: 车辆 ID
- scheduledStartTime: 计划开始时间
- scheduledEndTime: 计划结束时间
- actualStartTime: 实际开始时间
- actualEndTime: 实际结束时间
- status: 状态（待分配/待执行/执行中/已完成/已拒绝/已取消）
- reason: 拒绝/取消原因
- snowThicknessBefore: 作业前厚度
- snowThicknessAfter: 作业后厚度
- qualityScore: 质量评分（1-10）
- notes: 备注
- isReassigned: 是否改派
- originalVehicleId: 原始车辆 ID

### 作业报告（Report）
- id: 唯一标识
- taskId: 任务 ID
- reporter: 报告人
- reportTime: 报告时间
- snowThicknessBefore: 作业前厚度
- snowThicknessAfter: 作业后厚度
- qualityScore: 质量评分
- issues: 遇到的问题
- remarks: 备注
- isApproved: 是否审核
- approver: 审核人
- approveTime: 审核时间

## 核心业务逻辑

### 1. 开放窗口检查
任务创建时会检查是否在雪道开放时间内：
- 雪道开放时间内（如 08:00-18:00）不允许创建压雪任务
- 只能安排在夜间作业窗口（如 22:00-次日 08:00）
- 支持跨零点的开放窗口检测

### 2. 作业时间估算
根据雪道面积和车辆能力估算作业时间：
```
预计作业时间 = 雪道面积 ÷ 车辆每小时作业能力（向上取整）
```

### 3. 自动排程算法
1. 找出所有积雪厚度 < 最小要求的雪道
2. 按优先级排序（1 最高）
3. 为每条雪道查找可用车辆
4. 分配车辆并设置夜间作业时间（默认 22:00 开始）

### 4. 故障改派机制
当车辆报告故障时：
1. 检查车辆是否有未完成的任务
2. 如果有，将任务状态改为"待分配"
3. 记录原始车辆 ID，标记为改派
4. 释放车辆的任务分配

## 常见问题

### Q1: 无法创建任务，提示"压雪任务不能安排在雪道开放时间内"
**A**: 请检查雪道的开放窗口设置，压雪任务必须安排在非开放时间。大部分雪道开放时间为 08:00-18:00，建议将任务安排在 22:00 - 次日 08:00 之间。

### Q2: 车辆报告故障后任务去哪里了？
**A**: 故障车辆的未完成任务会自动进入"待分配"队列，您可以在任务列表中重新分配给其他可用车辆。

### Q3: 自动排程为什么没有生成任务？
**A**: 可能的原因：
1. 所有雪道积雪厚度都达标
2. 没有可用的压雪车（都在故障或维修中）
3. 所有可用车辆都已分配了任务

### Q4: 为什么删除雪道失败？
**A**: 如果雪道有未完成的任务（待分配/待执行/执行中），系统会阻止删除。请先取消或完成相关任务。

### Q5: 数据存储在哪里？
**A**: 使用 SQLite 数据库，文件位于 `backend/prisma/dev.db`。可以使用任何 SQLite 查看工具打开查看数据。
