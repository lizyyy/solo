# 黑胶预售缺货提醒系统

管理音乐演出合同页截图的导入、核对与追踪。确保证据链完整，每一步改动可追溯，边界规则代码化。

## 核心目标

1. **证据链完整**：合同页截图的原始行号、人工改动、当前处理状态全部保留，巡演统筹追问时能回到证据
2. **边界规则明确**：判定、修改、回滚方式全部写在代码和文档里，不靠口头约定
3. **去重导入**：重复导入同一批合同页截图不会导致数量翻倍
4. **历史可追溯**：音乐老师改了一条备注，历史里能看出改前改后的差别
5. **人工判断空间**：边界场景（如请假课时被算进已消耗）不自动确认，留给人工复核

## 三步核心流程

### 1. 合同页截图第一次导入
- 系统识别原始行号与内容
- 去重检测（文件哈希 + 内容指纹）
- 生成待处理记录
- **原始行号和内容永久保留，不可修改**

### 2. 音乐老师许老师补看曲目别名表
- 将合同中的曲目名与标准曲目名进行映射匹配
- 别名表后来才补的也没关系，随时可以补充映射

### 3. 曲目核对表更新
- 核对完成后，正常记录可确认
- **异常记录（如请假课时被算进已消耗）标记为"待巡演统筹复核"**
- 边界场景不急着归正常，留给巡演统筹复核

## 边界规则（全部代码化）

所有规则定义在 `src/utils/boundaryRules.ts` 中，同步展示在系统「边界规则」页面。

### 规则 1：请假课时被算进已消耗

**判定逻辑**：备注或原始内容中包含"请假"、"缺勤"、"补课"、"已消耗"、"课时"等关键词之一，且缺货/已消耗数量 > 0

**处理方式**：
1. 自动标记为边界场景，状态设为 `review_needed`（待巡演统筹复核）
2. 音乐老师许老师不可直接确认，必须由巡演统筹操作
3. 巡演统筹需核对实际出勤记录，确认是否应计入
4. 确认正常：状态改为 `reviewed`；标记异常：状态改为 `rejected` 并注明原因

**回滚方式**：
1. 在记录详情中找到对应变更日志
2. 点击"回滚到上一状态"
3. 重新触发边界规则检测
4. 巡演统筹需再次复核

---

### 规则 2：缺货数量逻辑矛盾

**判定逻辑**：缺货数量 > 预售总量，或缺货数量为负数，或同一场演出同一曲目缺货数量前后不一致

**处理方式**：
1. 标记为边界场景，高亮显示
2. 音乐老师需核对原始合同，修正数量后重新提交
3. 巡演统筹确认修正后的数据

**回滚方式**：
1. 恢复原始数量
2. 重新核对合同页截图
3. 修改后重新走复核流程

---

### 规则 3：曲目名无别名映射

**判定逻辑**：曲目名精确匹配不到，且编辑距离 > 3（无法模糊匹配）

**处理方式**：
1. 停留在 `alias_mapped` 之前的状态
2. 提示音乐老师补充曲目别名表
3. 补完全部别名映射后才能进入下一步

**回滚方式**：
1. 删除错误的别名映射
2. 重新匹配曲目名
3. 或在别名表中新增正确的标准曲目名

---

### 规则 4：同一曲目多条冲突记录

**判定逻辑**：同一场演出（同一snapshotId）中，同一standardTrackName出现多条记录，且缺货数量/备注不一致

**处理方式**：
1. 全部标记为边界场景
2. 音乐老师需核对原始合同，保留正确的一条，删除重复/错误记录
3. 巡演统筹复核最终结果

**回滚方式**：
1. 恢复所有冲突记录
2. 重新核对原始行号和内容
3. 合并或删除记录后重新确认

## 去重机制

实现于 `src/utils/deduplication.ts`：

1. **文件级去重**：通过文件 SHA256 哈希检测完全相同的文件
2. **内容级去重**：通过内容指纹（关键行+行号的哈希）检测内容相同的文件
3. **行级去重**：通过原始行号 + 原始内容精确匹配，避免同一行被重复导入
4. **结果**：重复导入同一批合同页截图不会导致数量翻倍

## 变更历史追踪

实现于 `src/utils/changeTracker.ts`：

1. 每次修改自动对比前后差异
2. 对每个变更字段生成一条 ChangeLog
3. 记录操作人、时间、修改原因
4. 保留原始值，支持回滚
5. 按时间分组展示，能清楚看出改前改后的差别

## 数据持久化

使用 LocalStorage 持久化，数据存储键名：`vinyl-shortage-store`

持久化内容：
- 缺货提醒记录
- 合同页快照信息
- 变更日志
- 曲目别名表
- 当前用户信息

## 技术栈

- **框架**：React 18 + TypeScript
- **构建工具**：Vite
- **状态管理**：Zustand（带 persist 中间件）
- **路由**：React Router DOM
- **样式**：TailwindCSS 3
- **图标**：Lucide React

## 角色说明

| 角色 | 权限 |
|------|------|
| 音乐老师（许老师） | 导入合同、补看曲目别名表、修改备注、确认正常记录 |
| 巡演统筹 | 复核边界场景记录、查看完整证据链、最终确认/驳回 |
| 运营 | 查看汇总数据、导出 |

## 核心原则

> 「我不介意界面简单，怕的是结论看着很满，追证据时断在半路。」

- 界面可以简单，但证据链必须完整
- 边界场景留给人判断，系统不自动吞掉异常
- 所有规则代码化，不靠口头约定
- 每次改动留痕，改前改后都能看到
