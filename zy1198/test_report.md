### 技术对比

```
【epoll】特点:
  - 使用红黑树 + 就绪链表
  - 只需要一次注册，不需要每次拷贝
  - 内核只返回就绪的 fd（就绪链表）
  - 复杂度: O(1) 就绪 fd 数量相关
  - 支持水平触发(LT)和边缘触发(ET)

【水平触发(LT)】:
  - 只要有数据就持续通知
  - 可以分次读取
  - 安全，不容易漏读
  - 是默认模式，也是大多数场景的推荐选择
```

## 术语解释

### 水平触发 (Level Triggered, LT)

- 只要 fd 上有数据，就会持续通知
- 可以分次读取数据
- 安全，不容易漏读
- 是 select/poll/epoll 的默认模式

### 边缘触发 (Edge Triggered, ET)

- 只在 fd 状态变化时通知一次
- 必须一次性读完所有数据
- 效率高，但容易漏读
- 必须配合非阻塞 IO 使用

### 惊群效应 (Thundering Herd)

- 多个进程/线程等待同一事件
- 事件发生时，所有等待者都被唤醒
- 但只有一个能获取到资源，其他的是空转
- 导致大量无效的上下文切换

### EPOLLEXCLUSIVE

- epoll 的一个标志位
- 只唤醒一个等待的 worker
- 有效避免惊群效应
- Linux 4.5+ 支持
