# 公益物资发放台

一个完整的公益物资发放管理系统，专门解决现场发放时的重复领取、代领验证、库存管理等问题。

## 🌟 核心功能

### 🔍 防重复领取拦截
- 自动检测同一家庭在同一批次内的重复申请
- 基于周期天数检测领取间隔
- 拦截记录保留在系统中，可追溯

### 👥 代领管理
- 代领人信息登记（姓名、身份证号）
- 代领人身份证明核验标记
- 未核验的代领自动标记为"需人工复核"

### 📦 物资与批次管理
- 多类型物资管理
- 发放批次配置（周期天数、时间范围）
- 实时库存跟踪

### ↩️ 退回与库存恢复
- 物资退回登记
- 自动库存恢复
- 退回记录可追踪

### 📊 看板与导出
- 实时数据看板（家庭、发放、库存统计）
- 家庭领取历史查询
- 库存数据CSV导出

### ⚠️ 人工复核标记
系统自动标记以下情况为"需人工复核"：
- 代领人未提供身份证明
- 领取时间接近周期边界（±2天）
- 退回数量异常

## 🚀 快速启动

### 前置要求
- Node.js 18+
- npm 或 yarn

### 安装依赖

```bash
# 方式1：使用根目录脚本
npm run install:all

# 方式2：分别安装
cd backend && npm install
cd ../frontend && npm install
```

### 启动开发环境

```bash
# 终端1：启动后端服务 (端口 3001)
cd backend && npm run dev

# 终端2：启动前端服务 (端口 5173)
cd frontend && npm run dev
```

### 访问系统
打开浏览器访问：http://localhost:5173

## 🧪 核心业务规则验证

### 1. 重复领取拦截测试
1. 进入「发放登记」→ 点击「新发放」
2. 选择已领取过物资的家庭（如张三家庭）
3. 选择同一批次，提交
4. 系统弹出提示："发放被拦截：该家庭已在本批次中领取过物资，不能重复领取"
5. 在发放列表中可以看到这条被拦截的记录

### 2. 代领复核标记测试
1. 新增发放记录，勾选「代领」
2. 填写代领人信息
3. **不勾选**「已核验代领人身份证明」
4. 提交后该记录自动标记为「需人工复核」

### 3. 库存变化跟踪
1. 审核通过一笔发放 → 库存减少
2. 将已发放的物资退回 → 库存自动恢复
3. 在「库存管理」页面查看实时库存变化

## 📋 API 接口

### 家庭管理
- `GET /api/families` - 获取家庭列表
- `POST /api/families` - 新增家庭
- `PUT /api/families/:id/approve` - 审核通过
- `PUT /api/families/:id/reject` - 审核拒绝

### 发放管理
- `GET /api/distributions` - 获取发放记录
- `POST /api/distributions` - 新增发放（自动拦截检测）
- `PUT /api/distributions/:id/approve` - 审核发放
- `PUT /api/distributions/:id/reject` - 拒绝发放
- `POST /api/distributions/:id/return` - 退回物资

### 库存管理
- `GET /api/inventory` - 获取库存列表
- `GET /api/export/inventory` - 导出库存CSV

### 看板
- `GET /api/dashboard/stats` - 统计数据
- `GET /api/dashboard/recent` - 最近发放记录

## ⚠️ 必须人工复核的记录类型

| 类型 | 触发条件 | 说明 |
|------|----------|------|
| 代领缺证明 | 代领人身份证明未核验 | 防止冒领 |
| 周期边缘领取 | 距离上次领取时间在(周期-2天)至周期之间 | 防止钻周期空子 |
| 退回数量异常 | 退回数量 > 实际发放数量 | 防止库存异常 |
| 重复导入 | 同一批次重复导入数据 | 防止数据错误 |

## 📝 数据可追溯性

所有操作都会留下历史记录：
- 发放记录状态变化
- 审核操作人
- 退回操作记录
- 库存恢复记录

在发放详情页面可查看完整的操作历史。

## 🔒 安全特性

- 重复领取自动拦截
- 未审核家庭无法领取
- 已关闭批次无法领取
- 库存不足无法发放
- 代领信息强制登记
