## 1. 产品概述

面向交通协管人员的社区托育步行可达性核查系统，解决路口照片与公交刷卡数据多源校验、小区新旧名称混淆、数据补录追溯等核心业务痛点。

- 核心价值：确保数据证据链完整可追溯，避免自动汇总掩盖细节问题
- 目标用户：交通协管员（老马）、市政巡检员、街道办事处

## 2. 核心特性

### 2.1 用户角色

| 角色 | 说明 | 核心权限 |
|------|------|----------|
| 交通协管员 | 日常数据录入与核查人员 | 导入路口照片、补录公交数据、确认冲突、生成摘要 |
| 市政巡检员 | 负责小区名称复核 | 审核小区新旧名称对应关系 |
| 街道查看者 | 只查看汇总结果 | 查看摘要和历史记录 |

### 2.2 功能模块

1. **数据导入工作台**：三步工作流主界面，路口照片导入、公交时段补录、摘要生成
2. **冲突检测中心**：数据矛盾自动识别，证据清单展示，人工确认/驳回
3. **自检仪表盘**：重复导入检测、小区新旧名称检测、补录重算校验、导出一致性校验
4. **历史追溯面板**：摘要版本、操作日志、数据变更记录
5. **小区名称复核池**：待市政巡检员确认的新旧名称对应关系

## 3. 核心流程

### 3.1 三步工作流

路口照片导入 → 公交刷卡时段补录 → 街道摘要更新

### 3.2 冲突处理流程

数据导入 → 系统自动检测冲突 → 列出冲突证据 → 交通协管员确认或驳回 → 确认后进入正常汇总，驳回后标记需重核

### 3.3 小区新旧名称处理

检测到疑似新旧名称 → 自动归入复核池 → 市政巡检员复核确认 → 确认后建立映射关系 → 后续汇总自动归并

```mermaid
flowchart LR
    A["路口照片导入"] --> B["系统自检：重复导入"]
    B --> C["公交刷卡时段补录"]
    C --> D["系统自检：补录重算"]
    D --> E["冲突检测：照片 vs 公交"]
    E --> F{"有冲突？"}
    F -->|是| G["列出冲突证据"]
    G --> H["协管员确认/驳回"]
    H --> I["确认后进入汇总"]
    F -->|否| I
    I --> J["检测小区新旧名称"]
    J --> K{"有歧义？"}
    K -->|是| L["归入市政复核池"]
    L --> M["巡检员复核"]
    M --> N["建立名称映射"]
    N --> O["生成街道摘要"]
    K -->|否| O
    O --> P["自检：导出一致"]
    P --> Q["导出交付街道"]
```

## 4. 用户界面设计

### 4.1 设计风格

- 主色调：交通蓝 (#1E40AF) + 警示橙 (#F97316) + 成功绿 (#10B981)
- 按钮风格：方角微圆，实心按钮有轻微按压效果
- 字体：思源黑体（正文）+ 等宽字体（数据表格）
- 布局风格：左侧导航 + 主内容区，卡片式模块，数据优先
- 图标风格：线性图标，色彩与状态关联

### 4.2 页面设计概览

| 页面名称 | 模块名称 | UI 元素 |
|----------|----------|---------|
| 主工作台 | 三步流程 | 顶部进度条，步骤卡片带状态标记，当前步骤高亮 |
| 主工作台 | 数据区 | 左右分栏：左侧照片列表，右侧公交数据表格 |
| 冲突检测 | 冲突卡片 | 红边警示卡片，冲突点加粗，证据并排对比 |
| 自检中心 | 自检项 | 四个大卡片带状态指示灯，点击展开详情 |
| 历史记录 | 时间轴 | 垂直时间轴展示操作记录，版本差异高亮 |
| 名称复核 | 复核列表 | 每行展示旧名/新名/来源，右侧操作按钮 |

### 4.3 响应式

- 桌面端优先设计，主内容区最小宽度 1200px
- 平板端自适应调整卡片布局
- 移动端折叠导航为抽屉式，表格支持横向滚动

### 4.4 交互细节

- 冲突证据展示：悬停高亮关联数据项
- 三步流程：步骤间切换有平滑过渡动画
- 自检运行：进度条动画，问题项逐个浮现
- 数据导入：拖拽区域有视觉反馈，上传后显示缩略预览
