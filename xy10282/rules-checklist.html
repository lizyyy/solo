📦 模块一：设备档案管理规则

RULE-D1: 设备编号唯一性检查 设备档案
相同设备编号不允许重复创建，防止档案混乱。
  1. 在「设备档案」新增设备：编号 INT-001，名称 博世接收机，频道范围 1-16
  2. 保存成功后，再次尝试创建编号为 INT-001 的设备
✓ 第二次创建失败，提示「设备编号 INT-001 已存在」
代码位置: app.js:253-256 (DeviceManager.create)
RULE-D2: 频道范围格式验证 设备档案
频道范围必须为「数字-数字」格式，如 1-16、0-99。
  1. 在「设备档案」新增设备，频道范围填 "1到16"（非标准格式）
  2. 或填 "A-B"、"16"、"16-1"
✓ 提示「频道范围格式错误，应为"数字-数字"格式」
代码位置: app.js:38-48 (Utils.parseChannelRange), app.js:258-261
RULE-D3: 电量值范围验证 (0-100) 设备档案
电量值必须在 0-100 之间，拒绝无效值。
  1. 在「设备档案」新增设备，初始电量填 150
  2. 或填 -10、"abc"
✓ 提示「电量必须在0-100之间」或「电量必须是数字」
代码位置: app.js:86-95 (Utils.validateBatteryLevel)
RULE-D4: 借出中设备禁止删除 设备档案 · 关键
状态为「借出中」的设备不允许删除，防止数据丢失。
  1. 先将某设备借出（借还登记 → 借出登记）
  2. 在「设备档案」尝试删除该设备
✓ 删除失败，提示「借出中的设备不能删除」
代码位置: app.js:366-368 (DeviceManager.delete)

🔄 模块二：借还登记规则

RULE-B1: 借出频道必须在设备频道范围内 借还登记 · 关键
借出时指定的频道必须在设备的频道范围内，防止设置错误频道。
  1. 创建设备 INT-001，频道范围 1-16
  2. 借出该设备时，频道填 20（超出范围）
✓ 借出失败，提示「频道超出设备范围 (1-16)」
代码位置: app.js:426-429 (BorrowManager.borrow)
RULE-B2: 借出电量低于 70% 触发警告并记录问题 借还登记 · 关键
借出时电量低于建议值 70%，借出可以完成，但会自动记录到「问题列表」。 【关键点】：不静默跳过，问题可追踪。
  1. 借出设备时，电量填 60（低于 70）
  2. 提交借出登记
  3. 查看「问题列表」页面
✓ 借出成功但显示警告
✓ 问题列表中出现「电量问题」类型的记录，来源为「借出检查」
代码位置: app.js:437-445 (BorrowManager.borrow)
RULE-B3: 借出配件缺失自动记录问题 借还登记 · 关键
借出时检查的配件与设备档案中的标准配件比对，缺失的配件自动记录到问题列表。 【关键点】：配件不允许静默跳过。
  1. 创建设备 INT-001，标准配件填「耳机,电池盒,挂绳」
  2. 借出该设备时，配件检查只填「耳机」（缺少电池盒和挂绳）
  3. 提交借出登记
✓ 借出成功但显示警告
✓ 问题列表中出现「配件问题」，描述包含缺失的配件名称
代码位置: app.js:447-460 (BorrowManager.borrow)
RULE-B4: 借出后设备状态变更为「借出中」 借还登记
借出成功后，设备状态自动从「可用」变为「借出中」，防止重复借出。
  1. 确认某设备状态为「可用」
  2. 借出该设备
  3. 查看「设备档案」列表
✓ 设备状态显示为「借出中」（橙色标签）
✓ 该设备不在「借出登记」的下拉列表中（只能借可用设备）
代码位置: app.js:485-489 (BorrowManager.borrow)
RULE-B5: 归还时电量低于 40% 自动记录问题 借还登记 · 关键
归还时检查电量，低于 40% 自动记录电量问题。
  1. 先借出一台设备
  2. 归还时电量填 30（低于 40）
  3. 提交归还登记
✓ 归还成功但显示警告
✓ 问题列表中出现「电量问题」，来源为「归还检查」
代码位置: app.js:525-534 (BorrowManager.return)
RULE-B6: 归还时频道超出范围自动记录问题 借还登记 · 关键
归还时频道超出设备范围，自动记录频道问题（不阻止归还，但记录异常）。
  1. 借出设备 INT-001（频道范围 1-16）
  2. 归还时频道填 99（超出范围）
  3. 提交归还登记
✓ 归还成功
✓ 问题列表中出现「频道问题」，来源为「归还检查」
代码位置: app.js:536-547 (BorrowManager.return)
RULE-B7: 归还后设备状态恢复为「可用」 借还登记
归还成功后，设备状态恢复为「可用」，可再次借出。
  1. 确认某设备状态为「借出中」
  2. 完成该设备的归还登记
  3. 查看「设备档案」和「借出登记」下拉列表

🔋 模块三：电量检查规则

RULE-C1: 电量 < 20% 判定为「不通过」并记录问题 电量检查 · 核心
电量低于严重阈值 20%，检查结果为「不通过」，自动记录问题。
  1. 在「电量检查」选择任一设备
  2. 电量填 15（低于 20）
  3. 提交检查
✓ 检查结果显示「不通过」（红色）
✓ 问题列表中出现「电量问题」，描述含「电量严重不足」
✓ 检查记录中可查看问题详情
代码位置: app.js:625-635 (CheckManager.check)
RULE-C2: 电量 20% ~ 40% 判定为「警告」并记录问题 电量检查 · 核心
电量在警告区间，检查结果为「警告」，自动记录问题。
  1. 电量检查时填 30（在 20-40 之间）
  2. 提交检查
✓ 检查结果显示「警告」（橙色）
✓ 问题列表中出现「电量问题」，描述含「电量偏低」
代码位置: app.js:636-645 (CheckManager.check)
RULE-C3: 电量 ≥ 40% 判定为「通过」 电量检查
  1. 电量检查时填 85
  2. 提交检查
✓ 检查结果显示「通过」（绿色）
✓ 不产生问题记录
代码位置: app.js:621-645 (CheckManager.check)
RULE-C4: 频道超出范围记录问题 电量检查 · 核心
检查时频道超出设备范围，检查结果降为「警告」并记录频道问题。
  1. 检查设备 INT-001（频道范围 1-16）
  2. 电量填 85（正常），频道填 99（超出范围）
  3. 提交检查
✓ 检查结果显示「警告」（因频道问题，从通过降级）
✓ 问题列表中出现「频道问题」
代码位置: app.js:647-660 (CheckManager.check)
RULE-C5: 配件缺失记录问题 电量检查 · 核心
检查时配件与标准配件比对，缺失项自动记录问题。
  1. 检查设备 INT-001（标准配件：耳机,电池盒,挂绳）
  2. 电量填 85，配件只填「耳机」
  3. 提交检查
✓ 检查结果显示「警告」
✓ 问题列表中出现「配件问题」，列出缺失配件
代码位置: app.js:662-680 (CheckManager.check)
RULE-C6: 批量检查脏数据不静默跳过，进入问题列表 电量检查 · 核心
【关键需求】：批量检查中，格式错误或无效数据不静默跳过， 必须进入「问题列表」并保留原始数据供追溯。
  1. 切换到「批量检查」模式
  2. 输入以下测试数据：
    INT-001,85,5,耳机,挂绳
    这是一行无效数据
    INT-999,50,3
    INT-001,25,100,耳机
  3. 点击「批量检查」
✓ 显示检查汇总：成功 X 条，失败 X 条
✓ 第 2 行（无效格式）：进入问题列表，类型「数据异常」，保留原始行数据
✓ 第 3 行（设备不存在）：显示失败，如开启 createProblem 则记录问题
✓ 第 4 行（电量 25<40 且频道 100 超范围）：检查完成但产生 2 条问题
代码位置: app.js:718-761 (CheckManager.batchCheck)

✓ 数据保存在 localStorage，刷新页面不丢失
