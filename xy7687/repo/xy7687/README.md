# 手机维修店工单系统

一个专为小型手机维修店设计的本地工单管理系统，帮助你告别微信群和纸本登记，实现数字化管理。

## 功能特性

### 核心功能
- **看板视图**：按状态分组显示所有工单，一目了然
- **工单管理**：新建、编辑、查看工单详情
- **状态流转**：严格的状态流转限制，防止误操作
- **操作记录**：完整记录每次状态变更和操作人
- **搜索筛选**：支持按姓名、手机号、工单号、设备型号搜索
- **CSV 导入导出**：方便迁移旧数据和月底对账

### 状态流转规则

```
待检测 → 报价中 → 维修中 → 待取机 → 已完成
   ↓         ↓         ↓         ↓
  取消      取消      取消      取消
```

**状态说明**：
- **待检测**：新创建的工单，等待技术人员检测
- **报价中**：检测完成，正在给客户报价
- **维修中**：客户同意报价，开始维修
- **待取机**：维修完成，等待客户取机
- **已完成**：客户已取机，工单结束
- **已取消**：客户取消维修，工单结束

## 技术栈

- **后端**：Node.js + Express + SQLite
- **前端**：Vue 3 + Element Plus + Vite
- **数据持久化**：SQLite 本地数据库
- **功能支持**：CSV 导入导出、表单校验、状态流转

## 快速开始

### 环境要求

- Node.js >= 14.0.0
- npm 或 yarn

### 安装步骤

1. **克隆项目**（如果从仓库拉取）
```bash
# 进入项目目录
cd xy7687
```

2. **安装后端依赖**
```bash
cd backend
npm install
```

3. **安装前端依赖**
```bash
cd ../frontend
npm install
```

4. **初始化数据库（首次运行）**
```bash
cd ../backend
npm run init-db
```
这会创建数据库并插入示例数据，方便你测试。

5. **启动后端服务**
```bash
# 在 backend 目录下
npm start
```
后端服务将运行在 http://localhost:3000

6. **启动前端服务（新开一个终端）**
```bash
cd ../frontend
npm run dev
```
前端服务将运行在 http://localhost:5173

### 访问系统

打开浏览器访问：http://localhost:5173

## 完整测试流程

以下是一个完整的"登记-报价-维修-取机完成"流程示例：

### 1. 新建工单（登记）

1. 点击顶部"新建工单"按钮
2. 填写工单信息：
   - 客户姓名：王小明
   - 联系电话：13900139999
   - 设备型号：iPhone 13
   - 故障描述：屏幕碎裂，无法正常显示
   - 报价金额：0（还未检测，暂不报价）
   - 维修配件：（留空）
   - 预计取机时间：（留空）
   - 备注：客户比较着急
3. 点击"创建工单"
4. 系统会自动跳转到工单详情页，此时状态为"待检测"

### 2. 开始报价

1. 在工单详情页，查看当前状态为"待检测"
2. 点击"报价中"按钮（状态流转按钮）
3. 确认状态变更
4. 状态变为"报价中"，操作记录会显示这次变更

### 3. 编辑报价信息

1. 点击"编辑工单"按钮
2. 修改信息：
   - 报价金额：1200
   - 维修配件：原装屏幕总成
   - 预计取机时间：选择明天下午
3. 点击"保存修改"

### 4. 开始维修

1. 回到工单详情页
2. 点击"维修中"按钮
3. 确认状态变更
4. 状态变为"维修中"

### 5. 完成维修

1. 维修完成后，点击"待取机"按钮
2. 确认状态变更
3. 状态变为"待取机"

### 6. 客户取机

1. 客户来取机时，点击"已完成"按钮
2. 确认状态变更（完成后无法再修改）
3. 状态变为"已完成"
4. 查看操作记录，可以看到完整的状态变更历史

### 7. 在看板查看

1. 点击顶部"看板视图"
2. 可以看到新创建的工单按照状态正确分布
3. 使用搜索框输入"王小明"或手机号，可以快速找到该工单

## CSV 导入导出

### 导出数据

1. 在看板视图，点击"导出CSV"按钮
2. 可以选择导出全部或按状态导出

**状态可选值**：待检测、报价中、维修中、待取机、已完成、已取消

## 注意事项

1. **数据安全**：SQLite 数据库文件存储在 `backend/data/repair.db`，请定期备份

2. **状态流转限制**：
   - 已完成和已取消的工单无法修改任何信息
   - 状态只能按顺序流转，不能跳步
   - 界面上会明确提示为什么某些状态按钮不可用

3. **手机号格式**：系统要求手机号为 11 位中国大陆手机号（以 13-19 开头）

4. **开发模式**：后端开发时可使用 `npm run dev` 启动热重载模式

## 常见问题

**Q: 刷新页面后数据还在吗？**
A: 是的，数据存储在 SQLite 数据库中，刷新页面或重启服务都不会丢失。

**Q: 如何修改已完成工单的信息？**
A: 设计上不允许修改已完成工单，这是为了保证数据完整性。如果确实需要修改，可以考虑重新创建工单或联系技术人员。

**Q: CSV 导入时支持哪些状态？**
A: 支持以下状态值（不区分大小写）：
- 待检测 / pending_inspection
- 报价中 / quoting
- 维修中 / repairing
- 待取机 / pending_pickup
- 已完成 / completed
- 已取消 / cancelled

**Q: 数据库文件在哪里？**
A: 首次运行 `npm run init-db` 或启动服务后，会在 `backend/data/` 目录下创建 `repair.db` 文件。
