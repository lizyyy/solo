## 原始点子

我想做一个给小团队用的“轮班交接风险看板”。场景是客服主管每天要把白班、晚班交接的问题整理出来，但现在大家都在群里发零散消息，容易漏掉高风险事项。请从 0 到 1 做一个可运行的全栈 Web 应用：左侧是交接录入区，可以按班次、负责人、客户/工单、风险等级、截止时间、标签和处理状态新增事项；右侧是实时看板，按“即将超时、高风险未处理、待复盘、已关闭”分组展示。要求前端有筛选、排序、批量改状态和导入/导出 CSV，后端提供 REST API 并把数据持久化到本地数据库或文件中，刷新页面后数据不能丢；还要有一个简单的规则引擎，自动把截止时间 2 小时内且未关闭的事项标成即将超时，并在看板顶部给出风险摘要。请补齐必要的项目结构、运行脚本、README 和少量测试，保证我按说明能本地启动并完成新增、筛选、批量处理、导出再导入的完整流程。
