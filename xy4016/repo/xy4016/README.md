# 轮班交接风险看板

一个专为小团队客服设计的轮班交接管理系统，帮助客服主管高效管理白班、晚班交接问题，防止高风险事项遗漏。

## 功能特性

### 📝 交接录入区
- 支持录入班次（白班/晚班）、负责人、客户/工单信息
- 风险等级：低/中/高/紧急四级分类
- 截止时间设置 + 标签系统
- 处理状态：待处理 → 处理中 → 待复盘 → 已关闭

### 📊 实时看板
四列分组展示，一目了然：
- **即将超时**：截止时间 2 小时内且未关闭的事项（规则引擎自动识别）
- **高风险未处理**：高/紧急风险的待处理事项
- **待复盘**：需要团队跟进复盘的事项
- **已关闭**：已完成的历史记录

### 🔍 筛选与操作
- 按班次、负责人、风险等级筛选
- 复选框批量选择，一键更新状态
- CSV 导入/导出（支持数据备份和迁移）
- 顶部风险摘要统计，实时刷新

### ⚙️ 规则引擎
自动检测即将超时事项：
- 截止时间 2 小时内 + 未关闭 → 标为「即将超时」
- 看板顶部实时展示风险统计
- 事项卡片有脉冲动画提醒

## 技术栈

- **后端**: Node.js + Express
- **数据库**: SQLite + Sequelize ORM（本地文件存储，数据不丢失）
- **前端**: 原生 HTML/CSS/JavaScript（零框架依赖，轻量快速）
- **测试**: Jest + Supertest

## API 接口

所有接口前缀为 `/api/issues`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 获取所有事项（支持筛选参数） |
| GET | `/summary` | 获取风险摘要统计 |
| GET | `/grouped` | 获取看板分组数据 |
| GET | `/:id` | 获取单个事项详情 |
| POST | `/` | 新建交接事项 |
| PUT | `/:id` | 更新事项信息 |
| PATCH | `/:id/status` | 更新单个事项状态 |
| PATCH | `/batch/status` | 批量更新状态 `{ ids: [1,2,3], status: "已关闭" }` |
| DELETE | `/:id` | 删除事项 |
| GET | `/export/csv` | 导出所有数据为 CSV |
| POST | `/import/csv` | 从 CSV 导入数据（multipart/form-data） |

## CSV 格式说明

导出/导入 CSV 支持以下列（表头支持中英文）：

| 列名（中文） | 列名（英文） | 必填 | 说明 |
|-------------|-------------|------|------|
| 班次 | shift | 否 | 白班/晚班，默认白班 |
| 负责人 | assignee | 是 | 处理人姓名 |
| 客户 | customer | 否 | 客户名称 |
| 工单号 | ticketNo | 否 | 工单编号 |
| 风险等级 | riskLevel | 否 | 低/中/高/紧急，默认中 |
| 截止时间 | deadline | 是 | YYYY-MM-DD HH:mm:ss 格式 |
| 标签 | tags | 否 | 多个标签用逗号分隔 |
| 状态 | status | 否 | 待处理/处理中/待复盘/已关闭，默认待处理 |
| 描述 | description | 是 | 问题详细描述 |

示例 CSV 内容：
```csv
班次,负责人,客户,风险等级,截止时间,标签,状态,描述
白班,张三,科技公司,高,2024-05-20 18:00:00,紧急,退款,待处理,用户投诉充值未到账
晚班,李四,电商平台,紧急,2024-05-20 22:00:00,新用户,待处理,新人首单优惠未生效
```

## 使用指南

### 新增交接事项
1. 在左侧表单填写班次、负责人、客户等信息
2. 选择风险等级并设置截止时间
3. 添加标签（多个用逗号分隔）
4. 填写问题描述后点击「添加交接事项」

### 筛选与批量处理
1. 在左侧「筛选条件」区域设置过滤条件
2. 点击「应用筛选」，看板自动刷新
3. 勾选看板上事项卡片的复选框
4. 在「批量操作」区域选择新状态，点击「批量更新状态」

### CSV 导出导入
- 导出：点击右上角「导出 CSV」，下载当前所有数据
- 导入：点击「导入 CSV」选择本地文件，数据自动入库

### 规则引擎效果
- 当某个事项的截止时间在 2 小时内且未关闭时，它会自动出现在「即将超时」列
- 该列的卡片有红色脉冲动画提醒
- 顶部统计栏实时显示即将超时、高风险、待复盘的数量

## 数据持久化

应用使用 SQLite 文件型数据库，数据存储在 `backend/database/shift-board.db` 文件中：
- 重启应用数据不丢失
- 可以直接备份此文件进行数据迁移
- 无需安装额外的数据库服务

## 常见问题

**Q: 如何修改即将超时的时间阈值？**  
A: 编辑 `backend/src/services/ruleEngine.js` 中的 `OVERDUE_SOON_HOURS` 常量（默认 2 小时）。

**Q: 为什么刷新页面数据还在？**  
A: 所有数据持久化到 SQLite 本地数据库文件，不是存在内存或浏览器 localStorage 中。

**Q: 支持多人同时使用吗？**  
A: 可以，所有用户连接同一后端服务，看板实时共享。前端每 60 秒自动刷新一次。

**Q: 如何在测试环境运行？**  
A: 运行 `npm test` 会使用独立的测试数据库，不会影响生产数据。
