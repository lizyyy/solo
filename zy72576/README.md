# 分桶校准概率回看系统

推荐模型评测运营工具，用于负样本校准全流程的回看、复核、自检。

## ✨ 核心特性

- **三步工作流**: 导入负样本 → 补看召回候选表 → 更新可解释摘要
- **智能自检**: 自动检测重复导入、特征缺失、默认分使用、补录未重算、数据不一致
- **证据留存**: 保留原始行号、人工改动历史、处理状态全程可追溯
- **三端一致**: 页面展示、导出明细、API接口读取同一份数据
- **异常拦截**: 特征缺失/使用默认分的样本禁止直接标记正常，必须经负责人复核

## 🚀 快速开始

### 1. 安装依赖

```bash
npm install
```

### 2. 运行自检测试

```bash
npm test
```

### 3. 启动服务

```bash
npm start
```

然后访问: http://localhost:3000

### 4. 跑通样例流程

1. 打开页面后，点击「加载样例数据」按钮
2. 系统会自动创建任务并导入 7 条样例负样本（含 3 条特征缺失、1 条重复）
3. 点击「执行自检」查看自动检测结果
4. 点击任意样本的「详情」按钮查看完整信息和操作
5. 对特征缺失样本进行「补录重算」，或直接标记异常
6. 完成所有样本的召回复核和摘要更新
7. 点击「导出CSV」获取完整报告

## 🔍 自检项说明

| 自检项 | 检查内容 | 典型问题 |
|--------|----------|----------|
| 重复导入检测 | 检查是否存在相同 (userId, itemId) 重复导入 | 评测运营小孟可能多次粘贴同一份数据 |
| 特征缺失/默认分检测 | 检查样本是否特征缺失或使用了默认概率分 | 线上特征缺失时系统给了 0.5 默认分但没标记 |
| 补录后重算检测 | 人工补录特征后是否标记为重算状态 | 补录了特征但忘了重新计算校准概率 |
| 导出一致性检测 | 页面、导出、API三处数据是否一致 | 一个地方显示异常另一个地方消失 |

## 📊 样本状态流转

```
已导入 (imported)
    ↓ 检测到特征缺失/默认分
待负责人复核 (pending_review)  ←──┐
    ↓ 负责人复核                    │
已复核 (reviewed)                  │
    ↓ 或 补录特征后重算            │
已重算 (recomputed)  ──────────────┘
    ↓ 负责人最终确认
正常 (normal) / 异常 (abnormal)
```

## 🔌 API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/runs | 创建校准任务 |
| GET | /api/runs | 获取任务列表 |
| POST | /api/runs/:id/import | 导入负样本（支持CSV文件或JSON） |
| GET | /api/runs/:id/samples | 获取样本列表（支持筛选、分页） |
| GET | /api/samples/:id | 获取单样本详情 |
| POST | /api/samples/:id/recompute | 补录特征并重算 |
| POST | /api/samples/:id/mark-normal | 标记为正常（特征缺失时会被拦截） |
| POST | /api/samples/:id/mark-abnormal | 标记为异常 |
| POST | /api/samples/:id/update-summary | 更新可解释摘要 |
| GET | /api/runs/:id/export | 导出CSV |
| GET | /api/runs/:id/self-check | 执行全部自检 |
| GET | /api/runs/:id/workflow | 获取工作流状态 |

## 💡 使用提示

1. **推荐负责人开会前10分钟**: 直接看「待负责人复核」数量，点详情看证据链
2. **评测运营小孟**: 导入后先看自检结果，有问题先处理，特征缺失的别急着归正常
3. **新人上手**: 点「加载样例数据」→「执行自检」→ 逐个点开详情熟悉流程
4. **数据一致性**: 所有展示、导出、API 都走 `unifiedData.js`，改数据只需改一处
