# 跨时区工单筛选工具

一个用于精准筛选跨地区工单的本地全栈工具，解决因时区差异导致的跨天、跨月工单统计错误问题。

## 功能特性

- **三种筛选模式**：
  - **门店本地时间**：每个工单按其所属门店的时区独立计算
  - **总部时区**：统一使用北京时间（Asia/Shanghai）计算
  - **UTC时间**：统一使用UTC时间计算

- **时间范围选择**：
  - 快捷范围：今天、本周、本月
  - 自定义范围：自由选择起止日期

- **结果展示**：
  - 筛选结果摘要（统计卡片、按状态/门店分组）
  - 工单列表（分标签展示：范围内、范围外、全部）
  - 导出Markdown格式核对报告

## 技术栈

- **后端**：Node.js + Express + SQLite (better-sqlite3)
- **前端**：原生 HTML/CSS/JavaScript
- **时间处理**：dayjs + dayjs-timezone

## 本地启动步骤

### 1. 环境要求

- Node.js >= 16.x
- npm 或 yarn

```bash

cd zy8274

# 安装依赖
npm install
```

### 3. 启动服务

```bash
# 启动本地服务器
```

## 核心演示工单详解

系统内置了 4 个关键演示工单，专门用于展示跨时区、跨月边界的差异：

### TK-DEMO-001 - 北京门店
- **UTC创建时间**：2024-02-29 23:00:00
- **北京时间**：2024-03-01 07:00:00
- **差异点**：
  - 按「总部时区/北京时间」筛选：属于 3月 → ✅ 范围内
  - 按「UTC时间」筛选：属于 2月 → ❌ 范围外
  - 这是最典型的"同一天UTC是2月，北京已是3月"场景

### TK-DEMO-002 - 洛杉矶门店
- **UTC创建时间**：2024-02-29 08:00:00
- **洛杉矶时间**：2024-02-28 16:00:00
- **差异点**：
  - 这是一个"UTC是2月29日，但洛杉矶还在2月28日"的场景
  - 用于说明即使在同一个月内，不同时区也可能有日期边界差异

### TK-DEMO-003 - 北京门店
- **UTC创建时间**：2024-03-01 00:00:00
- **北京时间**：2024-03-01 08:00:00
- **差异点**：
  - UTC时间刚进入3月
  - 北京时间已是3月1日早上8点
  - 所有筛选模式下都属于3月

### TK-DEMO-004 - 洛杉矶门店
- **UTC创建时间**：2024-03-01 07:00:00
- **洛杉矶时间**：2024-02-29 23:00:00
- **差异点**：
  - 按「总部时区/北京时间」筛选：属于 3月 → ✅ 范围内
  - 按「UTC时间」筛选：属于 3月 → ✅ 范围内
  - 按「门店本地时间」筛选：洛杉矶还在 2月29日 → ❌ **范围外**
  - 这是与 TK-DEMO-001 对称的反向场景

## API 接口

### GET /api/tickets
获取工单列表（带筛选）

**参数：**
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| filter_mode | string | 否 | 筛选模式：`store-local`/`hq-timezone`/`utc`，默认 `hq-timezone` |
| range_type | string | 否 | 时间范围：`today`/`week`/`month`/`custom`，默认 `today` |
| custom_start | string | 否 | 自定义开始日期，格式 YYYY-MM-DD（range_type=custom 时必填） |
| custom_end | string | 否 | 自定义结束日期，格式 YYYY-MM-DD（range_type=custom 时必填） |
| store_id | string | 否 | 按门店ID筛选 |

**响应：**
```json
{
  "success": true,
  "data": {
    "tickets": [...],
    "summary": {
      "total": 54,
      "inRange": 23,
      "outOfRange": 31,
      "statusBreakdown": {...},
      "storeBreakdown": {...},
      "rangeInfo": {...}
    }
  }
}
```

### POST /api/report/markdown
导出 Markdown 格式报告

**请求体：** 同 GET /api/tickets 参数

**响应：** text/markdown 文件下载

### GET /api/timezones
获取时区配置信息

### POST /api/reset-data
重置数据库并重新初始化样例数据

## 常见问题

### Q: 数据库文件在哪里？
A: 首次启动后会在项目根目录生成 `tickets.db` 文件，可以直接删除来重置数据，或点击页面上的「重置数据」按钮。

### Q: 如何添加新的门店时区？
A: 在 `server/timeService.js` 的 `STORE_TIMEZONES` 对象中添加新的门店ID与时区映射。

### Q: 支持哪些时区？
A: 使用 dayjs-timezone，支持所有 IANA 时区标识符。
