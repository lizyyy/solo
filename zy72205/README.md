# 银行理财净值公告核验系统

## 概述

本系统用于银行理财净值公告核验中对税费率备注的全生命周期管理。核心目标：**结论看着满，追证据不断路**。

每条税费率备注都保留原始行号、人工改动记录、当前处理状态，基金经理追问时可回到完整证据链。

---

## 三步工作流

净值公告核验的标准流程为三步，不可跳步：

| 步骤 | 名称 | 前置条件 | 完成标志 |
|------|------|---------|---------|
| Step 1 | 税费率备注导入 | 无 | 备注导入系统，状态为 `imported` |
| Step 2 | 补看柜台流水尾号 | Step 1 完成，且已填写柜台流水尾号 | 状态推进为 `tail_reviewed` |
| Step 3 | 对账说明更新 | Step 2 完成，且已填写对账说明 | 状态推进为 `reconciliation_updated` |

**关键约束**：三步必须顺序执行，不可跳步。每步推进时系统校验前置条件是否满足。

---

## 边界规则

### 规则 1：结算周期延长必须标记（SETTLEMENT_SHIFT_001）

**场景**：T+1 到账被手工改成 T+2（支付平台产品阿南每隔几天就碰到一次）。

**判定**：
- 结算周期从短周期改为长周期（如 T+0→T+1、T+1→T+2）→ **标记待基金经理复核**
- 结算周期从长周期改为短周期（如 T+2→T+1）→ **允许自动处理**（缩短对客户有利）
- 结算周期未变更 → **允许**

**修改**：
1. 操作人修改结算类型时，边界规则引擎自动评估
2. 若触发标记，系统将状态设为 `flagged_for_manager`，冻结工作流推进
3. 所有变更记录在 `history` 中，含改前改后值、操作人、原因

**回滚**：
1. 调用 `rollback_settlement()` 回滚到原始结算类型
2. 回滚操作本身也记录在 history 中
3. 回滚后状态变为 `pending_review`，清除基金经理标记

### 规则 2：偏离原始结算类型必须记录（ORIGINAL_DEVIATION_002）

**场景**：任何偏离导入时原始结算类型的改动。

**判定**：
- 偏差 0 级（与原始一致）→ **允许**
- 偏差 1 级（如原始 T+1，改为 T+2）→ **标记待基金经理复核**
- 偏差超过 1 级（如原始 T+0，改为 T+2）→ **阻止修改**，必须基金经理书面确认

### 规则 3：已标记备注禁止自动修改（ALREADY_FLAGGED_003）

**场景**：已被标记待基金经理复核的备注。

**判定**：
- 备注处于 `flagged_for_manager` 状态 → **阻止**任何自动修改
- 必须先由基金经理复核通过后才能继续操作

## T+1→T+2 完整处理流程

```
导入备注（原始 T+1）
  → 阿南手工改为 T+2
  → 边界规则引擎判定：结算周期延长 → 标记待基金经理复核
  → 状态变为 flagged_for_manager，工作流冻结
  → 基金经理复核：
     ├─ 通过 → 清除标记，状态恢复，可继续工作流
     └─ 未通过 → 需修正，可回滚到原始 T+1
```

**切记**：T+1 被手工改成 T+2 不是罕见边角料，是正常流程中会反复出现的场景，必须标记给基金经理复核，不要急着归正常。

## 重复导入去重

同一批税费率备注重复导入时：

1. **批次级去重**：通过内容哈希判断是否为同一批次，完全重复的批次直接跳过
2. **行级合并**：如果同一行（产品代码+行号+税率相同）有字段变更，更新字段并记录变更历史
3. **不翻倍**：不会因为重复导入而使备注数量翻倍

---

## 变更历史追踪

每条备注的每次变更都记录：

- **原始行号**：导入时的行号，永不变更
- **原始结算类型**：导入时的结算类型，作为回滚基准
- **改前改后差异**：每个字段的 old_value / new_value
- **操作人**：谁做的修改
- **原因**：为什么修改
- **是否涉及结算覆盖**：settlement_override 标记

基金经理追问时可通过 `get_audit_trail()` 获取完整证据链，通过 `get_evidence(keyword)` 搜索关键字定位具体变更。

---

## 数据模型关键字段

| 字段 | 说明 |
|------|------|
| `original_line_number` | 导入时的原始行号 |
| `original_settlement_type` | 导入时的原始结算类型 |
| `settlement_type` | 当前结算类型（可能被人工改动） |
| `flagged_for_manager` | 是否标记待基金经理复核 |
| `flag_reason` | 标记原因 |
| `status` | 当前处理状态 |
| `counter_flow_tail` | 柜台流水尾号（Step 2 填写） |
| `reconciliation_note` | 对账说明（Step 3 填写） |
| `history` | 变更历史列表 |
