# 渠道激励达标复核服务 - 业务规则文档

## 1. 概述

本文档详细描述渠道激励达标复核服务的核心业务规则，包括：
- 目标快照规则
- 达标口径规则
- 保护期规则
- 跨区归属规则
- 争议复核规则
- 激励明细计算规则
- 状态流转规则

## 2. 目标快照规则

### 2.1 快照创建规则

**成功条件（自动处理）：**
- 渠道ID、年份、季度唯一
- 目标金额 > 0
- 阶梯配置完整且无重叠
- 快照来源明确

**进入人工复核的情况：**
- 目标金额与历史季度偏差超过50%
- 阶梯配置超过4级
- 目标类型为「复合指标」

### 2.2 快照锁定规则

**锁定后不可修改：**
- 目标金额
- 阶梯配置
- 目标类型

**锁定时机：**
- 创建达标记录前必须锁定
- 锁定后可通过管理员权限解锁（需记录原因）

### 2.3 重复提交处理

**已锁定的快照：**
```
错误信息：该渠道在YYYY年QN的目标快照已锁定，无法重复创建。如需修改，请联系管理员解锁。
```

**未锁定的快照：**
- 创建新版本，旧版本保留在历史记录中
- 记录版本变更日志

## 3. 达标口径规则

### 3.1 自动审核通过条件

**全部满足以下条件：**
1. 所有数据源已验证（verificationStatus = VERIFIED）
2. 数据源总和与申报金额差异 ≤ 5%
3. 达成率 ≤ 200%
4. 未达到最高阶梯（TIER_4）
5. 无活跃保护期
6. 无跨区归属记录
7. 无未解决的争议

### 3.2 自动进入人工复核的情况

**满足任一条件即进入人工复核：**
1. **数据源验证不完整**
   - 存在未验证的数据源
   - 状态流转：INITIAL → MANUAL_REVIEW
   - 原因：存在未验证的数据源，需要人工确认

2. **金额差异过大**
   - 数据源总和与申报金额差异 > 5%
   - 状态流转：INITIAL → MANUAL_REVIEW
   - 原因：数据源总和与申报金额差异超过5%，需要人工复核

3. **异常高达成**
   - 达成率 > 200%
   - 状态流转：INITIAL → MANUAL_REVIEW
   - 原因：达成率超过200%，异常高达成需要人工确认

4. **最高阶梯奖励**
   - 达到 TIER_4
   - 状态流转：INITIAL → MANUAL_REVIEW
   - 原因：达到最高阶梯奖励，需要人工复核确认

5. **保护期内**
   - 存在活跃且已审批的保护期
   - 状态流转：INITIAL → MANUAL_REVIEW
   - 原因：该渠道处于保护期内，需要人工复核保护期规则应用

6. **跨区归属**
   - 存在跨区归属记录
   - 状态流转：INITIAL → MANUAL_REVIEW
   - 原因：存在跨区归属记录，需要人工确认归属关系

### 3.3 阶梯计算规则

**阶梯匹配逻辑：**
```
从最高阶梯开始匹配，第一个满足条件的阶梯即为适用阶梯

TIER_4: 达成金额 ≥ 150% 目标
TIER_3: 达成金额 ≥ 120% 目标
TIER_2: 达成金额 ≥ 100% 目标
TIER_1: 达成金额 ≥ 80% 目标（基础达标）
```

**计算明细包含：**
- 目标金额
- 实际达成
- 达成率
- 适用阶梯
- 计算公式
- 详细分解项

## 4. 保护期规则

### 4.1 保护期类型

| 类型 | 说明 | 必需参数 |
|------|------|----------|
| TIER_PROTECTION | 阶梯保护 | protectedTier |
| THRESHOLD_PROTECTION | 阈值保护 | protectedThreshold |
| RATE_PROTECTION | 比率保护 | protectedRate |
| FULL_INCENTIVE_PROTECTION | 全额保护 | protectedAmount |

### 4.2 保护期生效条件

**自动生效：**
- 保护期已审批通过（isApproved = true）
- 当前日期在保护期内
- 渠道匹配

**保护期审批：**
- 创建时状态：待审批
- 需要审批人角色确认
- 审批记录进入审计日志

### 4.3 保护期应用规则

**阶梯保护：**
- 如果实际达成阶梯 < 保护阶梯，使用保护阶梯
- 如果实际达成阶梯 ≥ 保护阶梯，使用实际阶梯

**阈值保护：**
- 如果实际达成 < 保护阈值，给予固定金额补偿
- 补偿金额在保护期条款中定义

**比率保护：**
- 使用保护比率替代基础比率计算激励
- 保护比率 > 基础比率时生效

**全额保护：**
- 保证最低激励金额
- 如果计算金额 < 保护金额，补足差额

### 4.4 保护期冲突处理

**同一渠道同一季度：**
- 只能有一个活跃的保护期
- 新保护期创建时检查冲突
- 错误信息：该渠道已存在活跃的保护期，不能重复创建

## 5. 跨区归属规则

### 5.1 归属类型

| 类型 | 说明 | 分配比例 |
|------|------|----------|
| FULL_TRANSFER | 全额转移 | 必须为100% |
| PARTIAL_SPLIT | 部分分割 | 0 < 比例 < 100 |
| SHARED_CREDIT | 共享业绩 | 按约定比例 |

### 5.2 归属审批流程

**自动处理条件：**
- 原渠道和新渠道在同一区域
- 分配比例 ≤ 50%
- 有客户迁移证明

**进入人工复核：**
- 跨区域归属
- 分配比例 > 50%
- 多个渠道共享同一业绩

### 5.3 激励分配计算

**计算公式：**
```
原渠道激励 = 总激励 × (1 - 分配比例)
新渠道激励 = 总激励 × 分配比例
```

**分配记录包含：**
- 原渠道信息
- 新渠道信息
- 分配比例
- 分配金额
- 归属原因
- 审批状态

### 5.4 归属冲突处理

**同一达标记录：**
- 只能有一个有效的跨区归属
- 新归属创建时检查现有归属
- 错误信息：该达标记录已存在跨区归属记录

**取消现有归属：**
- 将现有归属状态改为 CANCELLED
- 记录取消原因
- 允许创建新归属

## 6. 争议复核规则

### 6.1 争议类型

| 类型 | 说明 | 可争议状态 |
|------|------|------------|
| TARGET_SNAPSHOT | 目标快照争议 | 已验证、已审批 |
| ACHIEVEMENT_AMOUNT | 达成金额争议 | 已验证、已审批、已付款 |
| PROTECTION_PERIOD | 保护期争议 | 已验证、已审批 |
| CROSS_REGION_ASSIGNMENT | 跨区归属争议 | 已验证、已审批 |
| TIER_CALCULATION | 阶梯计算争议 | 已验证、已审批 |
| INCENTIVE_AMOUNT | 激励金额争议 | 已审批、已付款 |

### 6.2 争议状态流转

```
OPEN (提出争议)
    ↓
ASSIGNED (分配处理人)
    ↓
UNDER_REVIEW (复核中) ← AWAITING_EVIDENCE (补充证据)
    ↓
RESOLVED (已解决)
    ↓
CLOSED (已关闭)
```

### 6.3 争议解决结果

| 结果类型 | 说明 | 对原状态的影响 |
|----------|------|----------------|
| UPHELD | 支持争议 | 根据争议内容调整 |
| PARTIALLY_UPHELD | 部分支持 | 部分调整 |
| REJECTED | 驳回争议 | 维持原状态 |

### 6.4 争议对状态的影响

**提出争议时：**
- 原记录状态变更为 DISPUTED
- 阻止自动付款流程
- 通知相关人员

**争议解决后：**
- 支持争议：根据决议调整状态
- 驳回争议：恢复原状态
- 记录所有变更到历史日志

### 6.5 重复争议处理

**同一记录存在未解决争议：**
```
错误信息：该达标记录已存在未解决的争议（ID: xxx），请先处理现有争议。
```

**争议解决后：**
- 可以提出新的争议
- 新争议与已解决争议独立

## 7. 激励明细计算规则

### 7.1 计算流程

```
1. 基础计算
   ↓
2. 阶梯加成
   ↓
3. 保护期调整 ← (如有)
   ↓
4. 跨区分配 ← (如有)
   ↓
5. 其他扣除
   ↓
6. 最终金额
```

### 7.2 计算公式

**基础激励：**
```
基础金额 = 达成金额 × 基础比率(5%)
```

**阶梯激励：**
```
阶梯金额 = 根据阶梯配置计算（已在达标记录中确定）
```

**保护期调整：**
```
保护期调整 = 保护条款定义的金额
（可为正数或负数）
```

**跨区分配：**
```
跨区扣除 = 阶梯金额 × 分配比例
```

**最终金额：**
```
最终金额 = 阶梯金额 + 保护期调整 - 跨区扣除 - 其他扣除
```

### 7.3 计算明细透明度

**每笔激励明细包含完整的计算分解：**
- 基础计算详情
- 阶梯计算详情
- 保护期调整详情（如有）
- 跨区分配详情（如有）
- 扣除项详情（如有）
- 最终计算公式

## 8. 状态流转规则

### 8.1 完整状态图

```
null
  ↓
INITIAL (初始状态)
  ↓
PENDING_VERIFICATION (待审核)
  ↙       ↘
VERIFIED  MANUAL_REVIEW (人工复核)
  ↓ ↓      ↓   ↓   ↓
  ↓ ↓      ↓   ↓   ↘
  ↓ ↓      ↓   ↓   REJECTED (已拒绝)
  ↓ ↓      ↓   ↓
  ↓ DISPUTED ↓ APPROVED (已审批)
  ↓    ↓    ↓    ↓
  ↓    ↘ MANUAL_REVIEW
  ↓         ↓
  ↓     APPROVED/REJECTED
  ↓
APPROVED (已审批)
  ↓
PAYOUT_SCHEDULED (付款待安排)
  ↓       ↘
PAID     CANCELLED
```

### 8.2 允许的状态流转

| 起始状态 | 允许的目标状态 | 触发条件 |
|----------|----------------|----------|
| null | INITIAL | 创建新记录 |
| INITIAL | PENDING_VERIFICATION | 提交审核 |
| INITIAL | MANUAL_REVIEW | 需要人工复核 |
| PENDING_VERIFICATION | VERIFIED | 自动审核通过 |
| PENDING_VERIFICATION | MANUAL_REVIEW | 需人工复核 |
| VERIFIED | DISPUTED | 提出争议 |
| VERIFIED | APPROVED | 审批通过 |
| VERIFIED | REJECTED | 审批拒绝 |
| DISPUTED | MANUAL_REVIEW | 争议进入复核 |
| DISPUTED | VERIFIED | 争议驳回 |
| MANUAL_REVIEW | APPROVED | 复核通过 |
| MANUAL_REVIEW | REJECTED | 复核拒绝 |
| MANUAL_REVIEW | VERIFIED | 争议解决 |
| APPROVED | PAYOUT_SCHEDULED | 安排付款 |
| APPROVED | DISPUTED | 付款前争议 |
| PAYOUT_SCHEDULED | PAID | 付款完成 |
| PAYOUT_SCHEDULED | CANCELLED | 取消付款 |
| REJECTED | MANUAL_REVIEW | 申请重新审核 |
| REJECTED | CANCELLED | 取消记录 |
| PAID | DISPUTED | 付款后争议 |

### 8.3 非法流转拦截

**拦截逻辑：**
- 检查目标状态是否在允许列表中
- 如不允许，返回错误信息
- 错误信息包含允许的状态列表

**错误示例：**
```
错误信息：不能从「已验证」直接流转到「已付款」。允许的流转状态：「有争议」、「已审批」、「已拒绝」
```

## 9. 重复提交保护

### 9.1 目标快照

**检查条件：**
- 渠道ID + 年份 + 季度 组合
- 已锁定的快照阻止创建

**处理策略：**
- 未锁定：创建新版本
- 已锁定：返回错误

### 9.2 达标记录

**检查条件：**
- 渠道ID + 年份 + 季度 组合
- 非初始/拒绝状态阻止创建

**处理策略：**
- 初始/拒绝状态：覆盖
- 其他状态：返回错误

### 9.3 保护期

**检查条件：**
- 渠道ID + 年份 + 季度 组合
- 活跃状态阻止创建

**处理策略：**
- 返回错误，提示先终止现有保护期

### 9.4 跨区归属

**检查条件：**
- 达标记录ID
- 非取消状态阻止创建

**处理策略：**
- 返回错误，提示先取消现有归属

### 9.5 争议

**检查条件：**
- 达标记录ID
- 存在未解决争议阻止创建

**处理策略：**
- 返回错误，提示先处理现有争议

## 10. 审计日志规则

### 10.1 日志记录内容

**每条日志包含：**
- 日志ID
- 时间戳
- 模块
- 操作类型
- 操作人信息
- 目标实体类型和ID
- 变更前状态
- 变更后状态
- 变更字段详情
- 操作原因
- 成功/失败标识
- 错误信息（如有）

### 10.2 日志保留

**日志保留策略：**
- 永久保留
- 按实体ID查询
- 按操作人查询
- 支持人类可读的历史摘要

## 11. 处理成功 vs 人工复核总结

### 11.1 自动处理成功

**适用场景：**
- 标准达标（达成率 80%-200%）
- 数据源完整验证
- 无保护期、无跨区归属、无争议
- 阶梯在 TIER_1 ~ TIER_3

**结果：**
- 自动流转到 VERIFIED
- 可继续审批和付款流程

### 11.2 需要人工复核

**触发条件（任一）：**
- 数据源验证不完整
- 金额差异 > 5%
- 达成率 > 200%
- 达到 TIER_4
- 存在保护期
- 存在跨区归属
- 存在争议

**结果：**
- 流转到 MANUAL_REVIEW
- 需要人工确认
- 记录复核原因

### 11.3 处理失败

**失败原因：**
- 重复提交（状态冲突）
- 非法状态流转
- 必要数据缺失
- 业务规则违反

**结果：**
- 返回明确的错误信息
- 包含允许的操作列表
- 不改变原状态
