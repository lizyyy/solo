## 系统概述

本系统用于法务合同的条款智能抽取与审核管理，主要解决以下问题：

- **分散管理**: 统一管理合同文件、抽取结果和审核意见
- **效率低下**: 自动化条款抽取，减少人工重复劳动
- **风险遗漏**: 系统化的风险标注和分级机制
- **数据混乱**: 完整的版本控制和操作审计

### 核心设计原则

1. **数据完整性**: 所有操作均有记录，可追溯
2. **容错性**: 失败任务自动重试，支持补偿动作
3. **幂等性**: 重复请求不会导致数据异常
4. **可视化**: 时间线展示完整操作历史

## 核心功能操作指南

### 1. 合同上传

#### 操作路径
1. 点击顶部导航栏的"批量上传"标签
2. 点击拖拽区域或直接拖拽文件到上传区
3. 确认文件列表（可删除不需要的文件）
4. 点击"开始上传"按钮

#### 支持格式
- PDF (.pdf)
- Word (.doc, .docx)
- 文本文件 (.txt)

#### 注意事项
- 单个文件大小不超过 50MB
- 支持同时上传多个文件
- 上传失败的文件会显示错误信息，可重新上传

#### 后端验证逻辑
```python
# 文件大小检查
if file_size > 50 * 1024 * 1024:
    raise ValidationError("文件超过50MB限制")

# 文件名去重
# 相同内容的重复上传会被检测并阻止
request_hash = generate_request_hash(file_data)
if deduplicator.is_duplicate(request_hash):
    raise ConflictError("文件已在处理中")
```

### 3. 启动条款抽取

#### 批量抽取（推荐）
1. 在合同列表中勾选需要抽取的合同
2. 点击"批量抽取"按钮
3. 确认后系统后台异步处理
4. 等待状态从 `uploaded` → `extracting` → `extracted`

#### 单个抽取
1. 点击合同行的"查看"按钮
2. 在详情页点击"开始抽取"按钮

#### 抽取流程
```
用户请求
    ↓
API接收 → 去重检查（60秒内相同请求只处理一次）
    ↓
状态变更为 extracting
    ↓
后台异步任务执行（模拟AI抽取）
    ↓
    ├─ 成功 → 状态 extracted，保存条款数据
    └─ 失败 → 状态 failed，记录错误信息
```

#### 技术实现说明
- 使用 FastAPI BackgroundTasks 实现异步处理
- 模拟AI抽取延迟约 2-3 秒
- 生成4种标准类型的模拟条款
- 自动计算合同整体风险等级

1. 在合同详情的"条款列表"标签页
2. 找到需要修订的条款

- 记录修订前后的文本对比
- 显示版本号和修订时间
- 最多展示最近3条历史（数据库保留全部）

#### 技术说明
```python
# 修订时自动创建历史记录
revision = ClauseRevision(
    clause_id=clause_id,
    version_number=next_version,
    text_before=old_revised_text,
    text_after=new_revised_text,
    revised_by=current_user,
    revision_note=note
)

```

## 异常处理与补偿机制

### 1. 抽取失败处理

#### 失败场景
- AI服务不可用
- 文件格式不支持
- 内容解析错误
- 网络超时

#### 自动补偿流程
```
抽取失败 → status = failed
    ↓
用户点击"重试"按钮
    ↓
retry_count += 1
status = extracting
    ↓
再次尝试抽取
```

#### 重试限制
- 每个合同最多自动重试 **3次**
- 达到上限后需要人工干预
- 可在详情页查看重试次数

#### 批量重试
1. 在合同列表页点击"重试失败任务"按钮
2. 系统自动找出所有 failed 状态的合同
3. 对 retry_count < 3 的合同批量重试

---

### 2. 重复请求防护

#### 实现机制
系统使用基于内容哈希的去重机制：

```python
# 生成请求内容的MD5哈希
def generate_request_hash(request_data: dict) -> str:
    data_str = json.dumps(request_data, sort_keys=True)
    return hashlib.md5(data_str.encode()).hexdigest()

# 检查是否重复
if deduplicator.is_duplicate(request_hash, ttl_seconds=300):
    raise HTTPException(status_code=409, detail="重复请求")
```

#### 生效范围
| 操作 | 去重时间窗口 |
|------|-------------|
| 创建合同 | 300秒（5分钟） |
| 启动抽取 | 60秒（1分钟） |

#### 前端防护
- 按钮在请求处理中自动禁用
- 显示加载状态
- 请求完成后恢复可用

### 3. 脏数据处理

#### 文件验证
```python
# 上传时的检查项
validation_errors = []

if not filename:
    validation_errors.append("文件名不能为空")
    
if file_size > 50 * 1024 * 1024:  # 50MB
    validation_errors.append("文件大小超过限制")
    
if validation_errors:
    return BulkUploadResponse(
        success_count=0,
        failed_count=1,
        failed_files=[f"{filename}: {'; '.join(validation_errors)}"],
        contract_ids=[]
    )
```

#### 文本清洗
所有用户输入的文本会经过以下处理：
1. 去除前后空白字符
2. 移除 NULL 字符（\x00）
3. 统一换行符为 \n
4. 移除非法控制字符

#### 数据验证
- 置信度分数必须在 0-1 之间
- 必填字段非空检查
- 枚举值合法性验证
- 字符串长度限制检查

---

### 4. 数据完整性保障

#### 事务处理
所有数据库操作使用事务保障：
```python
try:
    db.add(contract)
    db.add(timeline_event)
    db.commit()  # 只有全部成功才提交
except Exception as e:
    db.rollback()  # 任何错误全部回滚
    raise
```

#### 级联删除
- 删除合同会级联删除所有关联条款
- 条款删除会级联删除修订历史
- 所有相关时间线记录也会被清理

## 常见问题

### Q1: 上传文件一直显示"上传中"怎么办？
A: 检查文件大小是否超过50MB，或刷新页面重新上传。大文件建议分批上传。

### Q2: 抽取任务一直卡在"抽取中"状态？
A: 可能是后台任务异常，点击详情页的"重试抽取"按钮重新启动。

### Q3: 导出Excel后中文乱码？
A: 建议使用 Excel 打开（WPS可能有编码问题），或选择 CSV 格式用 UTF-8 编码打开。

### Q4: 为什么有些操作没有记录到时间线？
A: 只有关键操作会被记录（创建、状态变更、抽取、修订、风险标注等），普通查询操作不记录。

### Q5: 数据库文件在哪里？可以备份吗？
A: SQLite 数据库文件在 `backend/contract_extraction.db`，可以直接复制备份。建议定期备份。

### Q6: 如何接入真实的AI抽取模型？
A: 修改 `services.py` 中的 `ExtractionService.extract_clauses_async` 方法，替换模拟逻辑为真实的 API 调用即可。

### Q7: 支持多少用户同时使用？
A: 当前版本为单用户设计，如需多用户建议添加用户认证模块（JWT/OAuth2）和权限控制。
