## 三步流程，别跳步

### 第一步：灰度批次第一次导入
- 系统拉取灰度批次数据
- 模型初判结果自动落库
- 置信度低于0.7的自动标黄
- **关键点**：这一步只看模型输出，别着急改

### 第二步：老唐补看标注员留言
- 逐条过标注员留言区
- 看到"旧口径""拿不准""之前是"这类关键词重点看
- 涉及历史口径的，翻Q1/Q2口径文档确认
- **关键点**：标注员留言是金矿，别漏

### 第三步：评测报告更新
- 顺利记录 → 归正常，批量过
- 人工改判被覆盖 → **打回安全审核复核**，别自己定
- 补录旧口径 → 更新评测数据，成本重新计提
- **关键点**：三种结果分开报，别混在一个总数里

## 重点：人工改判被下一次批跑覆盖怎么处理？

> 这是咱们俩部门最容易扯皮的地方，单独说。

**场景还原：**
1. 第一批跑：模型判中风险
2. 老唐人工改判：升为高风险（有明确诱导特征）
3. 第二批跑（重跑）：模型又判回低风险了
4. 系统提示：人工改判被批跑覆盖

**老唐的处理原则：**
- 我不会直接把第二条批跑结果当最终结果
- 系统会自动标记"待安全审核复核"
- 成本先挂中间态，不等你们复核完不算数

**安全审核同事需要做的：**
1. 打开"待复核"列表
2. 看内容本身，结合最新口径判断
3. 拍板最终风险等级
4. 备注复核意见

**为什么这么设计？**
- 模型重跑可能是特征波动，不一定对
- 人工改判有具体理由，不能被机器无声覆盖
- 安全口径你们说了算，我们只负责把问题抛出来

## 跑验证的注意事项

你说要拿正常材料、错口径材料、补录材料各跑一遍，重点看：

1. **评测报告里的处理类型字段** → 三种场景是不是能区分开
2. **历史记录追踪** → 每一步操作是不是都留痕了，特别是人工改判
3. **待复核标记** → 人工改判被覆盖时，是不是真的没自动归正常
4. **标注员留言关联** → 旧口径补录后，能不能回溯到是哪条留言触发的
