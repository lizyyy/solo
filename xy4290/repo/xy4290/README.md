# 应急广播抢修 - 策略小游戏

一款本地可运行的「应急广播抢修」策略小游戏。玩家在一张街区网格上调度维修车、临时发电机和广播点，目标是在倒计时内恢复尽量多的广播覆盖。

## 游戏规则

### 游戏目标
在限定时间内，通过调度维修车和发电机，激活广播点，恢复尽可能多的广播覆盖区域，达到目标覆盖率即可通关。

### 游戏元素

#### 格子类型
- **道路 (road)**：可通行的正常道路，显示为深灰色
- **建筑 (building)**：不可通行的建筑物，显示为暗红色
- **水域 (water)**：不可通行的水域，显示为深蓝色
- **阻断 (blocked)**：被积水/塌方阻断的道路，可维修，显示为棕色带红叉
- **广播点 (broadcast_point)**：广播设施，需要发电机部署才能激活，显示为黄色/绿色圆形

#### 单位类型
- **维修车 (repair_vehicle)**：
  - 可以移动、维修阻断道路、给发电机补给
  - 有油量限制，移动消耗油量
  - 有载重和修复速度属性
  - 显示为橙色矩形带扳手图标

- **发电机 (generator)**：
  - 可以移动、部署到广播点激活广播
  - 有油量限制，油量不足时无法部署
  - 部署后固定，不可再移动
  - 显示为蓝色圆形带电图标

### 游戏机制

#### 路径查找
使用 A* 算法自动计算最短路径，考虑可通行性约束。

#### 指令类型
- **移动 (move)**：将单位移动到目标位置
- **维修 (repair)**：维修车修复阻断的道路
- **补给 (supply)**：维修车给发电机补充油量
- **部署 (deploy)**：发电机部署到广播点激活广播

#### 资源消耗
- **移动**：维修车每移动一格消耗 2 单位油量
- **维修**：根据修复速度和修复成本计算时间
- **部署**：消耗发电机油量（部署后持续消耗）

#### 广播覆盖
- 每个激活的广播点会覆盖一定范围内的格子（默认为 2 格曼哈顿距离）
- 覆盖的格子会显示为绿色调
- 总覆盖率 = 覆盖格子数 / 总格子数

#### 评分系统
- **覆盖率分数**：最多 500 分，根据覆盖率比例计算
- **时间分数**：最多 300 分，越快完成分数越高
- **效率分数**：最多 200 分，覆盖率越高分数越高
- **评级**：
  - S：900-1000 分
  - A：750-899 分
  - B：600-749 分
  - C：400-599 分
  - D：0-399 分

## 安装和启动

### 环境要求
- 现代浏览器（Chrome、Firefox、Safari、Edge）
- Python 3（用于启动本地服务器）

### 启动步骤

#### 方式一：使用 Python 服务器（推荐）

1. 打开终端，进入项目目录：
```bash
cd /path/to/xy4290
```

2. 启动本地 HTTP 服务器：
```bash
python3 -m http.server 8080
```

3. 打开浏览器访问：
```
http://localhost:8080/
```

#### 方式二：直接在浏览器打开

1. 直接双击 `index.html` 文件
2. 注意：某些浏览器可能会因为跨域策略限制，无法加载本地 JSON 关卡文件。如果遇到此问题，请使用方式一。

### 验证游戏是否正常运行

1. 启动服务器后，在浏览器中访问 `http://localhost:8080/`
2. 应该能看到游戏界面，包含：
   - 顶部标题栏（显示关卡名称、时间、覆盖率、评分）
   - 左侧控制面板（操作指南、选中单位信息、资源状态、待执行指令、游戏状态）
   - 中央游戏区域（Canvas 渲染的网格地图）
   - 底部游戏日志
3. 点击维修车或发电机，应该能选中单位
4. 选中单位后点击其他可通行格子，应该能添加待执行指令
5. 点击「执行指令」按钮，应该能执行指令并更新游戏状态

## 游戏操作说明

### 基本操作

1. **选择单位**：点击地图上的维修车或发电机图标
2. **下达指令**：选中单位后，点击目标位置
   - 点击道路：添加移动指令
   - 点击阻断区域：添加维修指令（维修车）
   - 点击广播点：添加部署指令（发电机）
   - 点击发电机：添加补给指令（维修车）
3. **取消选择**：右键点击地图任意位置
4. **执行指令**：点击「执行指令」按钮，所有待执行指令将按顺序执行

### 高级操作

- **撤销**：点击「撤销」按钮，回退到上一步状态
- **重做**：点击「重做」按钮，恢复撤销的操作
- **保存进度**：点击「保存进度」按钮，当前状态保存到浏览器本地存储
- **加载进度**：点击「加载进度」按钮，从本地存储恢复保存的状态
- **重新开始**：点击「重新开始」按钮，重置到关卡初始状态
- **导入关卡**：点击「导入关卡」按钮，选择自定义的 JSON 关卡文件
- **导出关卡**：点击「导出关卡」按钮，将当前关卡配置下载为 JSON 文件

### 操作技巧

1. **规划路径**：选中单位后，鼠标悬停在目标位置会显示预览路径（青色虚线）
2. **批量操作**：可以为多个单位分别添加指令，然后一次性执行
3. **优先维修**：先维修阻断道路，打通关键路径
4. **合理部署**：将发电机部署到能覆盖更多区域的广播点
5. **及时补给**：注意维修车和发电机的油量，及时补给

## 关卡配置说明

关卡使用 JSON 格式配置，可以通过「导入关卡」功能加载自定义关卡。

### 基本结构

```json
{
  "id": "level_1",
  "name": "关卡名称",
  "description": "关卡描述",
  "timeLimit": 300,
  "targetCoverage": 60,
  "grid": {
    "width": 10,
    "height": 8,
    "cells": [
      ["road", "road", "road"],
      ["road", "broadcast_point", "road"],
      ["road", "blocked", "road"]
    ]
  },
  "initialUnits": [
    {
      "id": "repair_1",
      "type": "repair_vehicle",
      "position": { "x": 0, "y": 0 },
      "moveSpeed": 5,
      "capacity": 100,
      "currentLoad": 0,
      "repairSpeed": 1,
      "fuel": 100,
      "maxFuel": 100
    }
  ],
  "scoring": {
    "perfectTime": 90,
    "goodTime": 180,
    "perfectCoverage": 100,
    "goodCoverage": 80
  }
}
```

### 字段说明

#### 顶级字段
- `id`：关卡唯一标识
- `name`：关卡名称
- `description`：关卡描述文本
- `timeLimit`：时间限制（秒）
- `targetCoverage`：目标覆盖率（百分比，0-100）

#### grid 字段
- `width`：网格宽度（列数）
- `height`：网格高度（行数）
- `cells`：二维数组，表示每个格子的类型

#### cells 格子类型
可以使用字符串简写或对象形式：

**字符串简写**：
- `"road"` - 道路
- `"building"` - 建筑
- `"water"` - 水域
- `"blocked"` - 阻断道路
- `"broadcast_point"` - 广播点
- `"empty"` - 空白

**对象形式**（用于自定义属性）：
```json
{
  "type": "blocked",
  "isRepairable": true,
  "repairCost": 30
}
```

#### initialUnits 初始单位
- `id`：单位唯一标识
- `type`：单位类型（`repair_vehicle` 或 `generator`）
- `position`：初始位置 `{ x: 0, y: 0 }`
- `moveSpeed`：移动速度（秒/格）
- `fuel`：初始油量
- `maxFuel`：最大油量

**维修车特有属性**：
- `capacity`：载重能力
- `currentLoad`：当前载重
- `repairSpeed`：修复速度倍数

**发电机特有属性**：
- `powerOutput`：输出功率
- `isDeployed`：是否已部署

#### scoring 评分规则
- `perfectTime`：完美时间（秒），在此时间内完成获得满分时间分数
- `goodTime`：良好时间（秒）
- `perfectCoverage`：完美覆盖率（百分比）
- `goodCoverage`：良好覆盖率（百分比）

## 模块架构说明

项目采用模块化设计，包含以下核心模块：

### 目录结构

```
xy4290/
├── index.html              # 主入口页面
├── package.json            # 项目配置
├── README.md              # 本文档
├── css/
│   └── style.css          # 样式文件
├── js/
│   ├── main.js            # 主入口脚本
│   ├── types.js           # 类型定义
│   ├── levelParser.js     # 关卡解析模块
│   ├── stateManager.js    # 状态管理模块
│   ├── rulesEngine.js     # 规则计算模块
│   ├── renderer.js        # 渲染交互模块
│   ├── saveManager.js     # 存档管理模块
│   └── importExport.js    # 导入导出模块
├── levels/
│   └── level1.json        # 示例关卡
└── tests/
    ├── levelParser.test.js  # 关卡解析测试
    └── stateManager.test.js # 状态管理测试
```

### 模块说明

#### 1. types.js
定义所有类型和枚举：
- `CellType`：格子类型枚举
- `UnitType`：单位类型枚举
- `CommandType`：指令类型枚举
- `GameState`：游戏状态枚举
- 各种数据结构的 JSDoc 类型定义

#### 2. levelParser.js
关卡解析模块：
- 解析 JSON 字符串为关卡配置对象
- 验证关卡配置的完整性和一致性
- 提供默认值处理
- 支持简写格式（字符串）和完整格式（对象）

#### 3. stateManager.js
状态管理模块（核心）：
- 管理游戏状态的存储和更新
- 实现撤销/重做功能（历史栈模式）
- 管理待执行指令队列
- 提供状态快照和恢复功能
- 支持事件监听机制

#### 4. rulesEngine.js
规则计算模块（核心）：
- A* 路径查找算法
- 各种指令的验证（移动、维修、补给、部署）
- 广播覆盖范围计算
- 指令执行和状态更新
- 游戏结束条件判断
- 评分计算

#### 5. renderer.js
渲染交互模块：
- Canvas 游戏地图渲染
- 格子、单位、路径的绘制
- 鼠标交互处理（点击、悬停、右键）
- 路径预览功能
- 响应式画布调整

#### 6. saveManager.js
存档管理模块：
- localStorage 本地存储
- 存档的保存、加载、删除
- 存档列表管理
- 存档数据验证
- 存档导入导出（剪贴板支持）

#### 7. importExport.js
导入导出模块：
- 关卡文件的导入导出
- 文件选择对话框处理
- 关卡配置验证
- 关卡模板创建
- 剪贴板导入导出支持

#### 8. main.js
主入口脚本：
- 整合所有模块
- UI 事件绑定
- 游戏主循环
- 日志记录
- 默认关卡加载

## 常见问题

### Q: 为什么直接打开 index.html 无法加载关卡？
A: 浏览器的安全策略限制了直接从文件系统加载本地 JSON 文件。请使用本地 HTTP 服务器启动游戏。

### Q: 如何创建自定义关卡？
A: 参考 `levels/level1.json` 的格式创建 JSON 文件，然后通过「导入关卡」功能加载。

### Q: 游戏进度保存在哪里？
A: 保存在浏览器的 localStorage 中，清除浏览器数据会丢失存档。

### Q: 撤销/重做的历史记录有多少？
A: 默认最多保存 50 步历史记录。

### Q: 发电机部署后还能移动吗？
A: 不能，发电机一旦部署就固定在该位置，不可再移动。

## 开发说明

### 扩展功能

如果需要扩展游戏功能，可以：

1. **添加新格子类型**：在 `types.js` 中添加枚举，在 `levelParser.js` 中添加转换规则，在 `renderer.js` 中添加绘制逻辑。

2. **添加新单位类型**：在 `types.js` 中添加枚举，在 `rulesEngine.js` 中添加指令验证逻辑，在 `renderer.js` 中添加绘制逻辑。

3. **添加新指令类型**：在 `types.js` 中添加枚举，在 `rulesEngine.js` 中添加验证和执行方法。

4. **自定义评分规则**：修改 `rulesEngine.js` 中的 `calculateScore` 方法。

### 调试技巧

- 打开浏览器开发者工具查看控制台日志
- 游戏状态变更会触发事件，可以在 `stateManager.js` 中添加断点
- 路径查找问题可以在 `rulesEngine.js` 的 `findPath` 方法中调试
