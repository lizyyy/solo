# 变更单关联告警 CLI - 补充说明文档

## 一、工具简介

**变更单关联告警 CLI** 是一个用于故障复盘的证据链分析工具，能够：
- 自动关联变更（发布、配置变更、扩容）与告警
- 提供可解释的多维度关联评分
- 支持人工标记根因和排除误关联
- 生成适合复盘会直接讨论的报告

---

## 二、主要边界条件

### 2.1 数据边界

| 边界 | 说明 | 处理方式 |
|------|------|----------|
| **时间窗口** | 默认 60 分钟，超过窗口的告警不关联 | 可通过 `--time-window` 参数调整 |
| **服务名匹配** | 必须通过标准化或别名映射才能匹配 | 支持别名配置，见 `service_aliases.json` |
| **实例匹配** | 实例 ID 完全匹配或主机名部分匹配 | 无实例信息时降级为服务级别匹配 |
| **租户匹配** | 多租户场景下必须租户一致 | 无租户信息时给中等评分（0.5） |
| **指标类型** | 变更类型与指标类型有预设关联规则 | 见 `correlator.py` 中的 `change_metric_impact` |

### 2.2 评分权重边界

```
时间相关性:   30% （变更后多久告警）
服务匹配:     25% （是否同一个服务）
实例匹配:     15% （是否同一个实例）
租户匹配:     10% （是否同一个租户）
指标类型:     20% （变更类型是否影响该指标）
```

### 2.3 功能边界

1. **只读分析**：工具只读取和分析数据，不修改任何生产系统
2. **本地存储**：所有数据存在本地 JSON 文件，不依赖数据库
3. **离线使用**：不需要网络连接，所有计算在本地完成
4. **不做预测**：只做历史关联分析，不预测未来故障
5. **需要人工确认**：高评分只是建议，最终根因需要人工 `mark-cause`

## 三、一个失败路径

### 3.1 场景描述

**场景**：服务名没有配置别名，导致真实关联被遗漏

### 3.2 失败路径步骤

```
步骤1: 数据导入
   └─ 变更记录: service = "payment-service"
   └─ 告警记录: service = "payment-svc"
   └─ 别名配置: 空（未配置 payment-svc → payment-service）

步骤2: 执行 correlate
   └─ 服务名匹配失败 (payment-service vs payment-svc)
   └─ 服务评分 = 0.0
   └─ 总分大幅下降，可能从 0.9+ 降到 0.4 以下

步骤3: 生成报告
   └─ 这对关联被归类为"低关联"
   └─ 复盘时可能被忽略，错失真实根因

步骤4: 复盘讨论
   └─ 大家凭记忆认为是配置变更导致的
   └─ 但工具报告不支持这个结论
   └─ 证据链断裂，无法说服所有人
```

### 3.3 失败原因

1. **服务名标准化缺失**：不同系统使用不同命名约定
2. **别名配置遗漏**：`service_aliases.json` 没有维护
3. **依赖完全匹配**：当前算法没有模糊匹配（如编辑距离）

### 3.4 如何发现这个问题

运行 `explain` 命令查看评分详情：

```bash
python3 run.py explain --change-id CHG-003 --alert-id ALT-004
```

查看服务评分部分：
```
服务评分: 0.0 - 服务名不匹配: payment-service vs payment-svc
```

### 3.5 解决方案

1. **配置别名**：编辑 `data/service_aliases.json`
```json
[
  {
    "canonical": "payment-service",
    "aliases": ["payment-svc", "pay-service"]
  }
]
```

2. **重新关联**：
```bash
python3 run.py correlate
python3 run.py report
```

## 四、一次重复执行路径

### 4.1 场景描述

**场景**：第一次分析遗漏了重要关联，补充信息后重新分析

### 4.2 重复执行路径步骤

#### 第一轮：初始分析

```
步骤1: 初始化样例数据
   $ python3 run.py init-samples

步骤2: 查看数据
   $ python3 run.py list

步骤3: 执行关联分析
   $ python3 run.py correlate --output summary
   输出:
     🔍 高关联(≥0.7): 5 对
     ⚖️  中关联(0.4-0.7): 3 对
     ❓ 低关联(<0.4): 7 对

步骤4: 查看高关联详情
   $ python3 run.py explain --change-id CHG-001

步骤5: 生成报告
   $ python3 run.py report --format text
```

**发现的问题**：
- CHG-002（扩容）和 ALT-003（CPU告警）有一定关联
- 但实际上扩容是预防性的，CPU高是新实例启动正常现象
- 需要排除这个误关联

#### 第二轮：排除误关联

```
步骤6: 排除变更
   $ python3 run.py exclude CHG-002 "扩容是预防性操作，在告警前已完成，CPU告警是新实例启动正常现象"

   输出:
     ✅ 已将变更 CHG-002 排除出关联分析
     🔄 已重新生成关联结果和报告

步骤7: 查看更新后的报告
   $ python3 run.py report --format summary

   输出:
     🚫 已排除: 1 个变更
     报告中保留了 CHG-002，但注明了排除原因
```

#### 第三轮：确认根因

```
步骤8: 标记根因
   $ python3 run.py mark-cause CHG-001 "发布 v2.3.1 引入了订单创建逻辑的 bug，导致 500 错误率飙升"

   输出:
     ✅ 已将变更 CHG-001 标记为根因
     🔄 已重新生成关联结果和报告

步骤9: 生成最终报告
   $ python3 run.py report --format text
```

**最终报告特点**：
- 已确认根因区块显示 CHG-001
- 所有关联到 CHG-001 的告警都标注 `[★ 已标记为根因]`
- 已排除的变更区块显示 CHG-002 及排除原因
- 报告适合直接在复盘会上投影讨论

## 五、快速使用指南

### 5.1 基本工作流

```bash
# 1. 初始化样例数据（或导入自己的数据）
python3 run.py init-samples

# 2. 查看数据
python3 run.py list

# 3. 执行关联分析
python3 run.py correlate --output full

# 4. 详细解释某个关联
python3 run.py explain --change-id CHG-001

# 5. 排除误关联
python3 run.py exclude CHG-002 "排除原因..."

# 6. 标记根因
python3 run.py mark-cause CHG-001 "根因说明..."

# 7. 生成最终报告
python3 run.py report --format text
```

### 5.2 数据文件格式

所有数据存储在 `./data/` 目录：

- `changes.json` - 变更记录（发布、配置变更、扩容）
- `alerts.json` - 告警记录
- `service_aliases.json` - 服务别名映射
- `correlations.json` - 关联结果
- `reports/report_*.json` - 历史报告

### 5.3 导入自定义数据

可以直接编辑 JSON 文件，格式参考样例数据：

```bash
# 查看样例数据结构
cat ./data/changes.json
cat ./data/alerts.json
```

## 六、样例数据说明

样例数据包含三个典型场景：

### 场景1：发布导致错误率升高（CHG-001 + ALT-001/ALT-002）
- **变更**：发布 v2.3.1，订单创建逻辑重构
- **告警**：错误率从 0.1% 飙升至 15%
- **关联评分**：1.0（满分）
- **结论**：明确的根因，应 `mark-cause`

### 场景2：扩容无关告警（CHG-002 + ALT-003）
- **变更**：扩容 user-service 3→6 实例
- **告警**：新实例 CPU 85%
- **关联评分**：有一定关联但实际无关
- **处理**：应 `exclude`，注明原因

### 场景3：配置变更导致延迟上升（CHG-003 + ALT-004/ALT-005）
- **变更**：支付超时从 10s 改为 30s
- **告警**：P99 延迟从 500ms 升至 2.5s
- **关联评分**：0.94（高关联）
- **特殊点**：服务名别名 `payment-svc` → `payment-service`
