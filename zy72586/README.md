# 推荐探索率周报系统

面向推荐算法团队的负样本全链路追踪系统，支持导入、补录、复核、自检全流程。

## ✨ 核心特性

- **全链路审计**：负样本保留原始行号、原始数据、人工改动、处理状态，评测运营追问可回溯
- **四大自检**：重复导入检测、离线线上分差一桶检测、补录后重算检测、导出一致性校验
- **数据一致性**：页面展示、API接口、CSV导出读同一份数据，异常不会一处显示一处消失
- **三步工作流**：导入负样本 → 林姐补录召回候选 → 实验对比更新，异常留待复核

## 🚀 快速开始（新人照着跑就行）

### 1. 安装依赖

```bash
npm install
```

### 2. 加载样例数据（可选，推荐）

```bash
npm run init-data
```

会生成一份 `2024-W23` 的样例周报，包含：
- 10 条负样本（其中若干条离线线上分差一桶的异常）
- 3 条林姐补录的召回候选（未关联）
- 完整的审计日志

### 3. 启动服务

```bash
npm run dev
```

然后浏览器打开：**http://localhost:3001**

## 📋 完整操作流程演示

### 从零新建一份周报

1. 点击右上角 **「+ 新建周报」**，填入：
   - 周次：`2024-W24`
   - 标题：`2024年第24周推荐探索率周报`
   - 创建人：`你的名字`

2. **第一步：导入负样本列表**
   - 进入周报详情页，点击工作流第一步的「开始导入」
   - 系统会自动：①分配原始行号 ②计算分桶 ③标记分差一桶异常 ④写入审计日志

3. **第二步：数据科学家林姐补看召回候选表**
   - 点击工作流第二步「补录召回」
   - 填入召回候选数据（JSON格式）
   - 确认后状态推进到第二步
   - 点击「关联后重算」按钮，将召回候选关联到负样本并重算（**异常状态保留，不会自动归正常**）

4. **第三步：实验对比更新**
   - 点击工作流第三步「更新实验」
   - 状态推进到「实验对比已更新」
   - **分差一桶的异常记录保留红色高亮**，等待评测运营复核

5. **评测运营复核**
   - 在负样本列表点击「查看」进入详情
   - 可更新处理状态（复核中/已复核/正常/确认异常）
   - 可填写人工备注，所有操作留痕在「审计追踪」里

## 🔍 自检功能说明

点击右上角 **「运行自检」**，系统检查四项：

| 检查项 | 说明 |
|--------|------|
| 重复导入检测 | 检查是否有重复的 item_id |
| 离线线上分差一桶检测 | 列出所有分桶差值=1的记录（需人工复核，不会自动判定通过） |
| 补录后重算检测 | 检查是否有召回候选补录了但没关联到负样本 |
| 导出一致性校验 | 校验当前数据与上次导出是否一致 |

## 📤 导出一致性 & 导出历史

页面展示、API接口、CSV导出 **读的是同一份数据**，保证：
- 红色高亮的分差一桶异常，在页面、导出文件、API里都能看到
- 不会出现"页面显示异常、导出后消失"的问题

### 导出历史功能

切换到「导出历史」标签页，可以查看所有导出记录：

| 功能 | 说明 |
|------|------|
| 导出列表 | 每次导出的 ID、时间、导出人、样本数、异常数、内容哈希 |
| 导出明细查看 | 点击「查看明细」进入导出时的完整快照页面 |
| 历史快照导出 | 可基于历史快照重新导出 CSV |

### 导出明细页面

进入导出明细页面，可以看到：

1. **结果说明**：明确承诺数据一致性
2. **异常记录汇总**：分差一桶异常的记录单独列出，红色高亮
3. **与上次导出的差异**：自动对比两次导出的变化（状态变更、备注修改等）
4. **完整导出明细**：所有记录列表，含审计记录数
5. **单条证据链快照**：点击「查看证据链」，看到导出时刻的完整历史留痕：
   - 导出时的状态和分数
   - 状态流转历史（分步展示，带操作人、时间、备注）
   - 关联召回候选历史
   - 重算历史
   - 人工备注历史
   - 完整审计日志

### 单条证据链功能

在负样本列表点击「查看」，或在导出明细点击「查看证据链」，可以看到：

- **基本信息**：原始行号、物料信息、离线/线上分数、分桶情况
- **状态流转历史**：从"首次导入"到当前状态的每一步变更
- **关联召回历史**：林姐补录召回候选的记录
- **重算历史**：补录后重算分桶的记录
- **人工备注历史**：所有备注修改的历史
- **完整审计日志**：每一条操作的时间、操作人、新旧值

> 📌 **证据链说明**：评测运营追问时，可直接对照此证据链回复，不是只看一个汇总数。
> 即使后续数据有变动，导出时的证据快照保持不变，可追溯。

## 🎯 问题样例完整流程演示

已预置脚本，可一键走完完整问题场景：

```bash
npm run demo-problem
```

**场景说明**：
负样本列表先导入，后来林姐才补看召回候选表。回看周报时发现负样本列表结论不能直接照抄，尤其是离线和线上分数差了一个桶的记录。

**脚本自动完成**：
1. **第一步：导入负样本列表** → 检测分差一桶异常记录 → 第一次导出
2. **第二步：林姐补录召回候选** → 关联负样本 → 重算（异常保留，不归正常）→ 第二次导出
3. **第三步：实验对比更新** → 添加人工备注 → 更新状态为"复核中" → 第三次导出
4. 运行自检 → 停在导出明细查看状态

**运行后访问**：http://localhost:3001 → 进入【问题样例演示】周报 → 导出历史 → 查看最新导出明细

## ⚠️ 重要设计原则

1. **异常不急着归正常**：离线和线上分数差了一个桶的记录，重算时保留异常标记，必须等评测运营人工确认
2. **所有改动留痕**：状态变更、备注修改、关联召回，全部写入 audit log，可回溯到操作人和时间
3. **数据单一来源**：展示、导出、接口都查同一张表，避免数据不一致
4. **导出快照留痕**：每次导出保存完整证据快照，即使后续数据变动，导出时的状态可追溯
5. **证据链完整**：单条记录可查看从导入到当前的完整历史，评测运营追问时可直接回复
