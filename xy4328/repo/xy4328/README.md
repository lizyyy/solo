# 器械包放行追踪台

医院消毒供应室器械包追踪管理系统，确保灭菌合格的器械包才能放行，异常包可快速追溯召回。

## 功能特性

- 📦 **器械包管理**：新增、编辑、查询器械包，支持按条码、科室、状态筛选
- 🔥 **灭菌锅次管理**：管理锅次记录，记录物理/化学/生物监测结果
- 📋 **领用记录**：记录科室领用情况，追溯包的流向
- 📥 **CSV 导入**：批量导入锅次、器械包、领用记录
- ⚠️ **异常检测**：自动识别不合格锅次、过期包、领用时间异常
- 📤 **召回导出**：按条件查询并导出召回清单 CSV
- 💾 **本地持久化**：使用 SQLite 数据库，刷新不丢数据

## 技术栈

- **后端**：Node.js + Express + SQLite (better-sqlite3)
- **前端**：原生 HTML + CSS + JavaScript
- **数据格式**：CSV 导入导出

## 业务规则校验

系统自动执行以下校验规则：

### 1. 锅次合格判定

锅次需要同时满足以下条件才判定为**合格**：
- 物理监测 = 合格
- 化学监测 = 合格
- 生物监测 = 合格

### 2. 器械包放行规则

放行前自动校验：
- ✅ 所属锅次必须合格
- ✅ 器械包未过期
- ❌ 不合格锅次的包无法放行
- ❌ 过期包无法放行

### 3. 领用规则

- 必须已放行的包才能领用
- 领用时间不能早于放行时间
- 每个包只能被领用一次

### 4. 异常判定

器械包状态为**异常**的情况：
- 所属锅次不合格
- 已过期
- 领用时间早于放行时间
- 锅次不存在

## API 接口

### 锅次管理

| 方法 | 路径 | 描述 |
|------|------|------|
| GET | /api/cycles | 获取所有锅次 |
| GET | /api/cycles/:id | 获取单个锅次 |
| POST | /api/cycles | 新增锅次 |
| PUT | /api/cycles/:id | 更新锅次 |

### 器械包管理

| 方法 | 路径 | 描述 |
|------|------|------|
| GET | /api/packages | 查询器械包（支持 barcode, department, status 参数） |
| POST | /api/packages | 新增器械包 |
| PUT | /api/packages/:id | 更新器械包 |
| POST | /api/packages/:id/release | 放行器械包 |

### 领用记录

| 方法 | 路径 | 描述 |
|------|------|------|
| GET | /api/distributions | 获取所有领用记录 |
| POST | /api/distributions | 新增领用记录 |

### 数据导入

| 方法 | 路径 | 描述 |
|------|------|------|
| POST | /api/import/cycles | 导入锅次 CSV |
| POST | /api/import/packages | 导入器械包 CSV |
| POST | /api/import/distributions | 导入领用记录 CSV |

### 召回查询

| 方法 | 路径 | 描述 |
|------|------|------|
| GET | /api/recall | 召回查询（支持 cycle_number, department, start_date, end_date 参数） |
| GET | /api/stats | 获取统计数据 |

## CSV 文件格式

### 锅次 CSV

```csv
锅次号,灭菌日期,物理监测,化学监测,生物监测
GC20260501001,2026-05-01,合格,合格,合格
```

监测结果可选值：`合格`、`不合格`、空（未检测）

### 器械包 CSV

```csv
条码,包名称,锅次号,有效期
PKG001,手术器械包A,GC20260501001,2026-11-01
```

### 领用记录 CSV

```csv
条码,科室,领用人,领用时间
PKG001,外科,张医生,2026-05-02 10:30:00
```

## 注意事项

1. **导入顺序**：必须先导入锅次，再导入器械包，最后导入领用记录
2. **日期格式**：使用 `YYYY-MM-DD` 格式，时间使用 `YYYY-MM-DD HH:MM:SS`
3. **中文编码**：CSV 文件建议使用 UTF-8 编码（带 BOM）以避免中文乱码
4. **数据库**：数据存储在 `data/tracking.db`，备份该文件即可备份所有数据

## 故障排查

### 启动失败

检查 Node.js 版本是否 >= 14，重新安装依赖：

```bash
rm -rf node_modules
npm install
```

### 导入乱码

确保 CSV 文件为 UTF-8 编码。Windows Excel 导出时可选择「CSV UTF-8 (逗号分隔)」格式。

### 数据丢失

数据库文件位于 `data/tracking.db`，确保该目录有写入权限。
