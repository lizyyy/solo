# 餐厨油脂回收游戏

一个用于城市管理科宣传的2D浏览器策略游戏，玩家需要规划回收车路线，避免餐馆油桶溢出，体验餐厨垃圾回收的日常工作。

## 🚀 快速启动

### 环境要求
- Node.js >= 16
- npm 或 yarn

### 安装依赖
```bash
npm install
```

### 启动开发服务器
```bash
npm run dev
```

### 构建生产版本
```bash
npm run build
```

### 类型检查
```bash
npm run check
```

## 🎮 玩法说明

### 游戏目标
在限定回合内完成餐厨油脂回收任务，达到目标分数。需要平衡：
- **路线效率**：减少行驶距离，节省时间
- **容量管理**：合理安排回收顺序，避免车辆满载
- **风险控制**：防止油桶溢出和投诉事件

### 核心操作
1. **规划路线**：点击地图上的餐馆或回收站，按顺序添加到路线中
2. **自动规划**：点击「自动规划」按钮，系统会生成最优路线
3. **执行回合**：确认路线后点击「执行回合」完成一次回收
4. **处理事件**：随机事件会影响游戏进程，需要灵活应对

### 游戏规则

#### 油桶容量
- 每个餐馆都有油桶，每回合会增加一定量的油脂
- 容量条颜色：
  - 🟢 绿色：< 60%，安全
  - 🟠 橙色：60% - 90%，需要注意
  - 🔴 红色：> 90%，即将溢出
- **油桶溢出会导致游戏失败**

#### 车辆限制
- 回收车有最大行驶距离限制
- 回收车有最大容量限制
- 超出限制的路线无法执行

#### 投诉系统
- 餐馆油脂长时间不回收会产生投诉
- 投诉积累到一定程度会导致游戏失败

#### 评分规则
| 项目 | 分值 | 说明 |
|------|------|------|
| 基础分 | +100/回合 | 成功完成一回合 |
| 效率奖 | 剩余距离 × 2 | 行驶距离越短奖励越高 |
| 容量奖 | 利用率 × 50 | 车辆容量利用率奖励 |
| 溢出惩罚 | -200 | 油桶溢出扣分 |
| 投诉惩罚 | -150 | 收到投诉扣分 |
| 回合奖励 | 剩余回合 × 300 | 提前完成游戏奖励 |

### 边界案例（4关）

#### 1. 容量极限
- **特点**：车辆容量极小，餐馆产油量高
- **挑战**：必须频繁返回回收站卸载，路线规划需要精确计算
- **提示**：每次只回收1-2个餐馆就必须返程

#### 2. 路线绕行
- **特点**：地图存在障碍，部分道路不可通行
- **挑战**：无法直线行驶，需要绕路，距离计算更复杂
- **提示**：优先规划绕行距离最短的路线

#### 3. 投诉危机
- **特点**：投诉门槛极低，事件频率高
- **挑战**：必须优先处理高投诉风险的餐馆
- **提示**：关注投诉进度条，及时处理危险餐馆

#### 4. 回合极限
- **特点**：回合数极少，目标分数高
- **挑战**：每回合都必须达到最高效率
- **提示**：追求完美路线，充分利用自动规划功能

## 🎴 事件系统

游戏中会随机触发事件卡，影响游戏进程：

### 正面事件（绿色）
- **产量下降**：某餐馆本回合产油量减少
- **容量提升**：回收车本回合容量增加
- **奖励分数**：直接获得额外分数
- **距离缩短**：本回合行驶距离减少

### 负面事件（红色）
- **产量激增**：某餐馆本回合产油量翻倍
- **道路封闭**：部分区域不可通行
- **容量减少**：回收车本回合容量降低
- **投诉增加**：投诉进度直接增加

### 中性事件（蓝色）
- **临时检查**：需要额外行驶距离
- **调度调整**：回收车位置变化

## 📊 结算与回放

### 结算报告
游戏结束后会显示详细的结算报告，包括：
- 胜负状态和失败原因
- 最终得分和得分明细
- 每回合的详细数据
- 支持导出JSON和复制报告

### 历史回放
- 所有游戏记录会自动保存（最多50条）
- 可以回放任意历史对局
- 支持进度拖动和倍速播放（0.5x / 1x / 2x）
- 支持导出回放数据

## ⚠️ 边界案例说明

### 案例1：容量极限挑战
```
场景：车辆容量20，每个餐馆每回合产油15
策略错误：一次性选择2个餐馆 → 容量不足 → 无法执行
正确策略：先回收1个 → 返回回收站 → 再回收1个
```

### 案例2：路线绕行困境
```
场景：A到B直线距离3，但中间有障碍需要绕行到8
错误判断：按直线距离规划 → 实际行驶超出限制
正确做法：使用自动规划或手动验证路线
```

### 案例3：投诉连锁反应
```
场景：投诉门槛5，有3个餐馆接近阈值
错误：先处理远的餐馆 → 近的餐馆投诉 → 游戏失败
正确：按投诉风险优先级排序处理
```

### 案例4：回合极限压力
```
场景：10回合限制，需要1500分
错误：每回合只拿基础分 → 10回合只有1000分
正确：追求效率奖和容量奖，每回合得分最大化
```
