# 医院物流机器人避障系统

障碍物备注 · 楼层剖面草图 · 安全距离报告

## 功能特点

- ✅ **告警标签遮挡检测** - 自动检测移动端截图是否挡住告警标签
- ✅ **施工经理复核** - 遮挡情况需施工经理确认，不急着归正常
- ✅ **楼层剖面草图** - 园区运维小陶可补录和复核楼层剖面图
- ✅ **安全距离报告** - 说明为什么被留下、缺什么材料、下一步找谁
- ✅ **证据摘要** - API/CLI都返回障碍物备注和楼层剖面草图的证据
- ✅ **三种入口** - 命令行(CLI)、API接口、小看板(Web界面)

## 快速开始

### 1. 安装依赖

```bash
npm install
```

### 2. 从样例跑到报告（新人必读）

```bash
# 运行完整工作流测试
npm test
```

这个命令会自动走完以下三步：
1. **导入障碍物备注** - 导入一条告警标签被遮挡的障碍物记录
2. **施工经理复核** - 对告警标签遮挡情况进行复核
3. **园区运维小陶补看楼层剖面草图** - 创建并关联楼层剖面草图
4. **安全距离报告自动更新** - 每一步操作后报告都会跟着变

### 3. 使用CLI命令行

```bash
# 查看帮助
node src/cli.js --help

# 导入障碍物（从样例文件）
node src/cli.js import examples/obstacle-blocked-tag.json

# 列出所有障碍物
node src/cli.js list

# 查看障碍物详情
node src/cli.js show <障碍物ID>

# 施工经理复核（通过）
node src/cli.js manager-review <障碍物ID> --approved --remark "已现场确认"

# 创建楼层剖面草图
node src/cli.js create-floorplan --floor B1 --name "B1层西侧走廊"

# 关联楼层剖面草图
node src/cli.js attach-floorplan <障碍物ID> <草图ID>

# 园区运维小陶复核
node src/cli.js tao-review <障碍物ID> --approved

# 查看统计
node src/cli.js stats
```

### 4. 使用API接口

```bash
# 启动API服务
npm start
```

服务启动后：
- **API地址**: http://localhost:3000
- **小看板地址**: http://localhost:3000

#### API 端点

```
GET  /api/health           - 健康检查
GET  /api/stats            - 统计数据
GET  /api/obstacles        - 障碍物列表
POST /api/obstacles        - 导入障碍物
GET  /api/obstacles/:id    - 障碍物详情（含证据摘要）
POST /api/obstacles/:id/manager-review - 施工经理复核
POST /api/obstacles/:id/attach-floorplan - 关联楼层剖面
POST /api/obstacles/:id/tao-review - 小陶复核
GET  /api/floor-plans      - 楼层剖面列表
POST /api/floor-plans      - 创建楼层剖面
GET  /api/reports          - 安全距离报告列表
GET  /api/reports/:id      - 报告详情
```

#### API 返回示例

导入障碍物后，返回中包含证据摘要：

```json
{
  "obstacle": { ... },
  "report": { ... },
  "evidenceSummary": {
    "obstacleRemark": "现场测量突出约30cm",
    "floorPlanSketch": "",
    "alarmTagBlocked": true
  }
}
```

### 5. 使用小看板

启动服务后，在浏览器打开 http://localhost:3000

小看板功能：
- 📊 实时统计看板
- 📋 障碍物列表管理
- ➕ 导入障碍物表单
- 🗺️ 楼层剖面草图管理
- 📄 安全距离报告查看

## 核心工作流

```
┌─────────────────────────────────────────────────────────┐
│ 第一步：导入障碍物备注                                    │
│  - 自动检测告警标签是否被遮挡                            │
│  - 如果被遮挡 → 标记为"待施工经理复核"                   │
│  - 自动生成第一版安全距离报告                            │
└──────────────────────────┬──────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│ 第二步：施工经理复核（如告警标签被遮挡）                  │
│  - 施工经理确认障碍物真实位置                            │
│  - 通过后 → 状态变为"待补楼层剖面"                       │
│  - 负责人变为"园区运维小陶"                              │
│  - 安全距离报告自动更新                                  │
└──────────────────────────┬──────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│ 第三步：园区运维小陶补看楼层剖面草图                      │
│  - 创建/关联楼层剖面草图                                 │
│  - 小陶复核确认草图正确                                  │
│  - 安全距离报告最终更新                                  │
└─────────────────────────────────────────────────────────┘
```

## 安全距离报告说明

报告包含四个部分：

1. **为什么被留下**
   - 告警标签被遮挡？
   - 缺少必要材料？
   - 需要人工复核？

2. **还缺什么材料**
   - 障碍物备注说明
   - 楼层剖面草图
   - 其他补充材料

3. **下一步该找谁**
   - 施工经理（复核遮挡情况）
   - 园区运维小陶（补录楼层剖面）
   - 相关负责人

4. **当前状态**
   - 告警标签是否可见
   - 是否已关联楼层剖面
   - 是否已完成复核

## 数据存储

所有数据保存在 `data/` 目录下：
- `obstacles.json` - 障碍物记录
- `floor_plans.json` - 楼层剖面草图
- `safety_reports.json` - 安全距离报告
