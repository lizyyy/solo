原始想法：
我想做一个给智能售货柜运维小组用的本地后端工具，叫“离线补账包回放器”。柜机断网时会把开门、拿取、归还、称重、支付回调和人工补录这些事件缓存成本地 JSONL，恢复网络后再上传；现在最怕同一批事件被重复补传、事件时间乱序、支付成功但库存没扣、称重异常被当成正常销售，最后库存和账款对不上。请从 0 到 1 做一个可运行的 Python 后端/CLI 项目：init 命令能创建配置，维护柜机清单、商品 SKU、货道容量、事件去重窗口、允许的时钟漂移、异常称重阈值和输出目录；import-bundle 命令能导入一个或多个柜机离线补账包 JSONL，保留原始文件并记录批次号；check 命令要校验字段缺失、事件 ID 重复、时间倒序、未知柜机或 SKU、货道库存越界、支付单号冲突、称重变化和商品数量不匹配这些问题，坏事件进入 quarantine.json 并说明原因。replay 命令要按柜机和订单重建可信事件流，支持 dry-run，正确处理重复上传、开门未关门、先支付后取货、人工补录覆盖自动识别、跨批次同订单续传这些情况；apply 命令确认后写入本地 SQLite 或 JSON 账本，更新每台柜机的库存、订单状态、支付核对状态和异常标记，必须保证同一批次重复 apply 幂等；undo 命令能撤销最近一次已应用批次。还要提供一个小型 REST API，可以查询柜机库存、订单回放轨迹、隔离事件和批次历史，并支持导出 Markdown 对账报告、CSV 库存差异表和 JSON 审计证据。请把 CLI 入口、配置模型、事件解析校验、回放状态机、幂等账本、隔离区、REST 路由、报告导出、示例数据和测试拆成清晰的多文件结构，不要写成单文件脚本。README 里写清楚安装、启动、示例命令，以及如何用临时目录验证初始化、导入两台柜机补账包、校验、回放、确认入账、重复入账幂等、撤销和 API 查询这些核心流程。
