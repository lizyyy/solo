# 基金销售尾佣拆分系统

Fund Sales Trail Commission Splitting System

## 系统概述

本系统用于基金销售尾佣金的拆分计算，支持完整的审批流程和审计追踪。特别针对以下场景做了优化：

- **节假日顺延处理**：风控值班老秦可以补看节假日顺延说明，调整清算日期
- **审批人拼音检测**：自动检测审批人是否仅为拼音，留待客户经理复核
- **审计追踪**：完整记录每一条记录的原始行号、人工改动、处理状态
- **余额变化表**：清晰展示每条记录的来源和确认状态，方便临时会议快速查看
- **统一数据源**：导出明细、页面展示、接口返回读同一份结果，确保一致性

```bash
python3 -m pip install -r requirements.txt
```

```bash
python3 generate_samples.py
```

系统将在 `http://localhost:8000` 启动。

## 完整操作流程（从样例到报告）

### 第一步：导入清算批次号

1. 点击"1. 导入清算批次"标签页
2. 输入批次号：`QY20240101`

4. 选择文件：`samples/sample_batch_1.xlsx`
5. 点击"导入"按钮

**导入后系统会自动：**
- 检测到 **1条重复记录**（张三的华夏成长混合）并标记
- 检测到 **2条审批人拼音**（zhang wei、liu yang）并标记为待客户经理复核
- 保留原始行号，方便后续对账

### 第二步：风控补看节假日顺延说明

1. 点击"2. 节假日审核"标签页
2. 选择刚导入的批次 `QY20240101`
3. 查看工作流状态，确认当前处于第二步
4. 添加节假日调整：
   - 原日期：`2024-01-01`
   - 调整后日期：`2024-01-04`
   - 调整原因：`元旦假期顺延`
5. 点击"添加调整"按钮
6. 点击"完成节假日审核"（审核人：老秦）

**审核后系统会自动：**
- 调整王五（嘉实沪深300ETF）的清算日期从 2024-01-01 到 2024-01-04
- 重算所有修改过的记录的尾佣金额
- 记录审计日志，保留修改痕迹

### 第三步：客户经理复核审批人拼音

1. 回到"1. 导入清算批次"标签页
2. 查看当前批次详情，可以看到标记为黄色的待复核记录
3. 点击"复核"按钮处理审批人拼音记录：
   - 记录ID 2（zhang wei）：输入复核人姓名，确认通过或拒绝
   - 记录ID 4（liu yang）：输入复核人姓名，确认通过或拒绝

**注意**：系统不会自动将拼音审批人归为正常，必须留待客户经理复核。

### 第四步：余额变化表更新

1. 点击"3. 余额变化表"标签页
2. 选择批次 `QY20240101`
3. 点击"更新余额"按钮（如果还有待复核记录，系统会阻止）
4. 查看余额变化明细，可以看到：
   - 每条记录的**来源**：清算批次导入 / 节假日调整 / 手工录入
   - 每条记录的**状态**：待确认 / 已确认
   - 客户经理的余额变动

**临时会议场景**：即使只有10分钟，只看余额变化表也能清楚知道：
- 哪条来自清算批次号
- 哪条还等确认

### 第五步：运行自检

1. 点击"自检报告"标签页
2. 选择批次 `QY20240101`
3. 点击"运行自检"按钮

**自检覆盖以下项目：**
1. ✅ **重复导入检测** - 检查同一基金、同一客户、同一日期、同一金额的重复记录
2. ✅ **审批人拼音检测** - 检测审批人名称是否仅为拼音，需客户经理复核
3. ✅ **补录后重算验证** - 检查修改后金额是否正确重算
4. ✅ **导出一致性检查** - 确保导出、页面、接口数据一致
5. ✅ **审计追踪完整性** - 确保所有修改都有审计日志
6. ✅ **节假日顺延审核** - 检查日期调整是否经过风控审核

### 第六步：导出报告

1. 点击"导出"标签页
2. 选择批次 `QY20240101`
3. 点击"导出Excel"或"导出CSV"
4. 点击"验证一致性"确认导出数据与页面、接口一致

**导出的Excel包含三个工作表：**
- **尾佣拆分明细** - 完整的明细数据，异常记录用红色标记
- **审计追踪** - 所有操作的完整日志
- **汇总** - 统计汇总信息

## 核心功能详解

### 自检功能（Self Check）

系统提供6项基本自检，覆盖最容易出错的点：

| 检查项目 | 检查内容 |
|---------|---------|
| 重复导入检测 | 相同基金代码、客户账号、交易日期、交易金额视为重复 |
| 审批人拼音检测 | 自动识别纯英文字母的审批人名称，标记待复核 |
| 补录后重算验证 | 确保人工修改后尾佣金额正确重算 |
| 导出一致性检查 | 导出、页面、接口使用同一份数据源 |
| 审计追踪完整性 | 所有修改都有审计日志记录 |
| 节假日顺延审核 | 日期调整必须经过风控审核 |

### 审计追踪（Audit Trail）

每条清算批次号的记录都会保留：
- **原始行号**：Excel中的原始行号，方便回溯
- **人工改动**：所有字段修改都记录旧值、新值、操作人、时间
- **处理状态**：已导入 → 待审核 → 节假日已调整 → 待经理复核 → 余额已更新

查看审计追踪：点击任意记录的"审计"按钮。

### 统一数据源

系统确保导出明细、页面展示、接口返回读取同一份结果：
- 核心函数：`get_unified_record_data()` in [crud.py](file:///Users/lzy/pro/solo/workspaces/zy72236/app/crud.py#L320-L364)
- 审批人拼音记录在任何地方都不会"消失"，状态始终一致

### 余额变化表

余额变化表特别设计为照顾临时会议场景：
- **来源标签**：清晰标记每条记录是来自清算批次导入、节假日调整还是手工录入
- **待确认标记**：待经理复核的记录标记为黄色，一眼就能看到
- **来源参考**：显示对应的清算批次号，方便快速追溯

## 数据库表结构

### 核心表

1. **clearing_batches** - 清算批次主表
   - 批次号、导入时间、状态、节假日审核状态

2. **commission_records** - 尾佣拆分明细表
   - 原始行号、基金信息、客户信息、客户经理、审批人
   - 交易金额、佣金率、尾佣金额、拆分比例、最终金额
   - 审批人拼音标记、重复标记、人工修改标记、待复核标记
   - 余额更新状态

3. **audit_logs** - 审计日志表
   - 操作类型、字段名、旧值、新值、操作人、时间
   - 关联批次ID和记录ID

4. **balance_changes** - 余额变化表
   - 客户经理、变动金额、前后余额
   - 来源类型、来源参考、待确认标记

5. **self_check_results** - 自检结果表
   - 检查类型、是否通过、消息、详情、影响的记录ID

6. **holiday_adjustments** - 节假日调整表
   - 原日期、调整后日期、原因、审核人

## 设计亮点

### 1. 返工留明面

风控值班老秦希望工具能把返工留在明面上。系统通过：
- 明确的三步工作流，每一步都有状态标记
- 自检报告清晰列出所有问题和影响的记录
- 审计日志完整记录每一次修改

### 2. 审批人拼音留待复核

碰到审批人只留了拼音时，系统：
- 自动检测并标记为黄色警告
- 设置 `needs_manager_review` 状态
- 阻止余额更新，直到客户经理复核完成
- **不会**自动归为正常，必须人工确认

### 3. 证据链完整

客户经理追问时能回到证据：
- 保留原始行号，可追溯到Excel原始数据
- 完整的审计日志，每一步修改都有记录
- 节假日调整记录审核人（老秦）和原因
- 余额变化表关联原始记录ID

### 4. 临时会议友好

余额变化表设计为：
- 一眼就能看出哪些是清算批次导入，哪些是节假日调整
- 黄色高亮待确认记录
- 显示对应的清算批次号
- 支持按客户经理筛选

## 常见问题

### Q: 如何处理重复记录？
A: 系统会自动检测并标记重复记录，但不会自动删除。需要人工确认后在数据库中处理。

### Q: 审批人拼音如何复核？
A: 在"导入清算批次"页面，点击待复核记录的"复核"按钮，输入复核人姓名，选择通过或拒绝。

### Q: 余额更新失败怎么办？
A: 系统会提示具体原因，通常是因为还有待复核的审批人拼音记录或未处理的重复记录。

### Q: 可以修改已经更新余额的记录吗？
A: 可以修改，但需要重新运行余额更新。系统会记录所有修改的审计日志。
