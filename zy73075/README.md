# 🛡️ 盾构刀盘工单回放 · 复核工作台

> 面向盾构施工项目的工单复核与交接管理工具。项目经理可一键加载样例、导入工单、回放异常、判定交接、导出结果；安全员可按 **🔴 公式 / 🟠 单位 / 🟣 阈值** 三类问题逐一复核，月底不再被平均值盖住。

---

## 一、快速开始

```bash
# 1. 安装依赖
npm install

# 2. 启动开发服务器
npm run dev
# 打开浏览器访问终端显示的 http://localhost:xxxx

# 3. 类型检查（可选）
npm run check

# 4. 生产构建
npm run build
```

> 启动后首页如果为空，直接点击右上角工具栏的 **「加载样例数据」** 即可看到 4 条工单、8 条备件、2 条异常撤回记录。

## 三、走一遍完整流程（照着做就能验证可用）

### 步骤 1：加载样例 & 看交接状态

1. 首页点击 **「加载样例数据」**
2. 顶部 4 张状态卡应该显示：
   - ✅ 可放行：1
   - 🟠 缺材料待补：1
   - 🔴 异常待核：1
   - ⏳ 待交接：1
3. 点击任一状态卡可筛选下方工单列表。

### 步骤 2：看一条「顺利工单」

1. 打开 **WO-2026-0601** 详情页
2. 交接判定卡显示：**可放行：备件齐全，异常归零**
3. 备件清单 2 行，金额计算正确：
   - 硬质合金滚刀 `8 × 12,500 = 100,000`
   - 刀盘密封螺栓 `48 × 85 = 4,080`

### 步骤 3：看「异常归因」&「撤回留痕」

1. 打开 **WO-2026-0603** 详情页
2. **设备编号 SDJ-001** 会显示为琥珀色重复条纹（业务合法但便于关注）
3. 备件清单：
   - 第一行（硬质合金滚刀）：显示 **🔴 公式异常：申报数量不能为负数** 和 **🟠 单位异常：应使用个/套**
   - 第二行（主轴承修复环）：显示 **🟣 阈值异常：申报数量超过上限 1000 / 出库超过申报 150%**
4. 右侧「撤回/异常记录」时间线：
   - 第一条：🟠 单位问题，左侧原始值（红底删除线）vs 右侧正确示例（绿底下划线）
   - 第二条：🟣 阈值问题，同样双列对比
   - 每条都有处理状态和安全员确认勾选框 —— **撤回记录不藏在备注里**

### 步骤 4：测试「重复导入不翻倍 + 人工备注不被覆盖」

> 关键验证：**重复导入时工单数量不会增加，已有的人工备注不会被新导入覆盖。**

1. 先进入 **WO-2026-0602** 详情页，记住它的人工备注是：
   > 「5 号检修漏录，今日补录；含临时采购的密封圈——原计划用库存但发现老化」
2. 回到首页，点击工具栏 **「导入 JSON」** 进入导入回放页
3. 点击左侧 **「加载固定样例数据包」**（或拖入 `public/sample-data.json`）
4. 预览区：
   - **WO-2026-0601 ~ 0604 全部被标为黄色对角条纹 + 右上角「已存在」角标**（不新增）
   - **人工备注**列显示「将被保留不覆盖」，新备注置灰对比
   - 每条异常备件上带 🔴/🟠/🟣 徽章
5. 点击 **「确认导入」**
6. 回到首页：工单数量仍然是 **4**（没变成 8，没有翻倍 ✅）
7. 打开 WO-2026-0602：人工备注 **还是原来那段话**（没被覆盖 ✅）

### 步骤 5：异常复核（安全员老唐视角）—— 处理动作真的写回工单

> 核心验证：**异常卡片有真实处理按钮，状态变化写回工单，列表/详情/导出都能看到变化；交接状态随处理自动联动。**

#### 5.1 打开工作台看初始全景

1. 左侧导航进入 **「异常复核」** 页
2. 顶部 4 张状态卡显示：
   - 🔴 待处理：0（样例已预标了状态）
   - 🔵 处理中：1（主轴承修复环阈值问题）
   - 🟢 已修正待确认：0
   - 🟡 需项目经理介入：1（硬质合金滚刀单位+公式问题）
3. 顶部分类标签：全部 / 🔴 公式问题 / 🟠 单位问题 / 🟣 阈值问题
4. 右上角安全员确认进度：`0 / 2`（两条都还没确认）

#### 5.2 操作第一条：单位+公式问题（原状态「需人工确认」）

1. 在分类标签切到 **🟠 单位问题**，找到「硬质合金滚刀」卡片
2. 卡片显示：
   - **处理人**：安全员·老唐（预填）
   - **处理时间**：2026-06-08 14:50（预填）
   - **处理备注**：安全员老唐已标记异常，待班组长核实后修正
   - 左侧红底删除线「原始值」vs 右侧绿底下划线「正确示例」
3. 先在 **处理备注（可选）** 输入框里写：`班组长李工确认数据录入错误，已修正为 8 个`
4. 点击 **「标记已修正」** 按钮（4 个按钮中主色）
   → 卡片右上状态胶囊从「需人工确认」→「已修正」
   → 自动写入新的处理人和时间（安全员·老唐 + 当前时间）
5. 再勾上右下 **「安全员确认」** 复选框
   → 复选框勾上后，卡片会展示「安全员确认：安全员·老唐 · 当前时间」
   → 顶部 4 张卡自动刷新：已修正待确认从 0→0（因为立刻勾了确认），需项目经理介入从 1→0
   → 顶部进度条变成 `1 / 2`

#### 5.3 操作第二条：阈值问题（原状态「处理中」）

1. 切到 **🟣 阈值问题** 标签，找到「主轴承修复环」卡片
2. 处理备注写：`仓库核对确实多敲了 0，改为 15 个，出库改为 22 个`
3. 点 **「标记已修正」**
   → 胶囊从「处理中」→「已修正」
4. 勾上 **「安全员确认」**
   → 进度条变成 `2 / 2`，满格

#### 5.4 立刻验证：处理动作已写回工单

1. 回到详情页看 **WO-2026-0603**，交接状态卡已经从「🔴 异常待核」自动变成 **✅ 可放行** —— 因为 updateRecall 时自动联动重算了工单 handover_status！
2. 顶部总览页的状态卡：
   - ✅ 可放行：从 1 → **2**（WO-2026-0603 成功晋升）
   - 🔴 异常待核：从 1 → **0**
3. 点「导出全量 JSON」，用编辑器打开会看到两条 recall_records 的 process_status 都变成「已修正」，safety_confirmed = true，process_by / process_time / safety_by / safety_time 都已写入。

### 步骤 6：看「临时材料」怎么被归并或标缺

1. 打开 **WO-2026-0602**（补录记录）
2. 备件清单第一行「主驱动密封圈」：
   - `is_temp = true`，整行带浅紫底色 + 「临时材料」紫色徽章
   - 备注说明：临时采购件 + 原计划用库存但发现老化
3. 交接建议自动显示：**「待交接：含 1 项临时材料（主驱动密封圈），建议复核」**
4. 交接状态因此为「待交接」而非直接「可放行」——临时材料不会静默混入正常料。
   → 项目经理可点「按异常复核结果重算」看系统建议，也有权手动点「可放行」强制放行（会显示 60% 透明度以提示风险）。

### 步骤 7：交接状态完整闭环 —— 可放行 vs 缺材料待补 vs 异常待核

> 4 条工单，4 种状态，每条都能说清「卡在哪、谁处理、怎么放行」。

| 工单编号 | 初始交接状态 | 阻塞原因 | 处理方式 | 处理后交接状态 |
|---|---|---|---|---|
| WO-2026-0601 | ✅ 可放行 | 无 | — | 可放行（始终） |
| WO-2026-0602 | ⏳ 待交接 | 1 项临时材料（主驱动密封圈） | 项目经理复核后手动放行，或补录正式采购单号后点「按复核结果重算」 | 待交接（默认）/ 可放行（手动） |
| **WO-2026-0603** | **🔴 异常待核** | **1 条需人工确认 + 1 条处理中** | 异常复核工作台：两条全部「标记已修正 + 安全员确认」 | **✅ 可放行**（自动联动 ✨） |
| WO-2026-0604 | 🟠 缺材料待补 | 主轴承大齿圈缺料 | 等厂家到货，把备件 material_status 从「缺料」改为「正常」后点「按复核结果重算」 | 缺材料待补（默认）/ 可放行（补料后） |

#### 7.1 验证「手动放行 + 自动判定协作逻辑」

1. 打开 WO-2026-0603，确认状态已是「✅ 可放行」，交接建议显示：
   > 可放行：备件齐全，异常归零（2 条异常已修正并确认）
2. 打开 WO-2026-0604，缺材料大齿圈：
   - 想点「✅ 可放行」按钮会显示 60% 透明度（因为 still 阻塞）
   - 按钮 title/hover 提示：「仍有未处理异常/缺料/临时材料，项目经理仍可手动放行」
   - 下方琥珀色警告框列出当前所有阻塞项：「· 缺料：主轴承大齿圈」
3. 项目经理依然可以强制点「可放行」—— 业务上紧急放行时用，但系统会保留警告痕迹。
4. 点「**按异常复核结果重算**」按钮会立刻根据 recall + 缺料重新计算，不覆盖项目经理已经手动设置的状态。

## 四、数据结构速查

```
Workorder      ──1:N──  SparePart（备件清单，含 is_temp 临时材料标记）
    │
    └──1:N──  RecallRecord（撤回记录，异常分类：公式问题/单位问题/阈值问题/数据缺失）
```

核心字段（不推倒重来）：
- 工单编号、**设备编号**、刀盘型号、工单类型、施工部位、班组、工单日期
- **备件清单**（关联）含：备件名/编码/规格/单位/申报数/出库数/单价/是否临时材料/材料状态/撤回标记
- **撤回记录**（独立表，不在备注里）：异常分类、涉及字段、原始值、正确示例、处理状态、安全员确认
- **人工备注**（`handover_note`）：独立字段，导入保护策略明确写在导入页侧边

## 五、异常归因引擎规则（内置）

| 类别 | 触发条件 |
|------|----------|
| 🔴 公式问题 | 数值字段为 NaN；申报 / 出库 / 单价 < 0 |
| 🟠 单位问题 | 螺栓→个、密封/圈→个/套、油管/管→米、油脂/油→公斤、焊丝/线→卷；不匹配即触发 |
| 🟣 阈值问题 | 申报 > 1000；单价 > 10 万 且 申报 > 10；主轴承申报 > 2；出库 > 申报 × 1.5 |

## 六、技术栈

- React 18 + TypeScript 5 + Vite 5
- Tailwind CSS 3（自定义 shield 工业深青主题色、JetBrains Mono 等宽字体）
- Zustand 5（localStorage 持久化，刷新不丢失）
- React Router 7
- Lucide React 图标

纯前端运行，无需后端；所有数据在浏览器 localStorage，可随时 JSON 导出/复建。
