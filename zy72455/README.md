# 历史街区招牌整治 - 路口照片管理系统

## 项目概述

用于管理历史街区招牌整治工作中的路口照片数据，重点解决：
- **数据溯源**：保留原始行号、源文件，街道规划员追问时能回到证据
- **变更追踪**：人工改动全留痕，改前改后可对比
- **边界规则**：夜间缺采样等异常情况有明确的判定、处理、回滚机制，不靠口头约定
- **数据去重**：重复导入同一批照片不翻倍

## 快速开始

### 1. 安装依赖

```bash
pip3 install -r requirements.txt
```

### 2. 运行演示脚本（推荐新同事先跑这个）

```bash
python3 demo_script.py
```

演示脚本会走完完整流程：导入照片 → 补录公交刷卡时段 → 生成热力图 → 发现夜间缺采样 → 复核 → 回滚

### 3. 启动Web界面

```bash
python3 app.py
```

访问 http://localhost:5000

## 核心设计原则

### 1. 证据优先，结论可追溯

每一条路口照片记录都永久保留：
- **原始行号**：在源文件中的第几行
- **源文件名称**：从哪个文件导入的
- **导入时间**：精确到秒
- **原始行数据**：完整的原始JSON，不可篡改

> 代码位置：[models.py](src/models.py) 中的 `OriginalRow` 类

### 2. 人工改动全留痕

任何字段修改（哪怕只是改一条备注）都会记录：
- 改前值
- 改后值
- 操作人
- 修改时间
- 修改原因

> 代码位置：[data_manager.py](src/data_manager.py) 中的 `update_field` 方法和 `ManualChange` 类

### 3. 重复导入不翻倍

通过 `源文件名 + 行内容` 生成唯一MD5作为photo_id，重复数据自动跳过。

> 代码位置：[data_manager.py](src/data_manager.py) 中的 `_generate_photo_id` 和 `import_photos` 方法

## 边界规则（已写入代码，不靠口头约定）

### RULE_001: 夜间缺采样判定规则

**判定条件**：
- 夜间时段定义：22:00 - 次日06:00
- 阈值：夜间平均采样 < 日间平均采样的 30%

**处理方式**：
- 自动标记为"夜间缺采样导致热力图偏低"
- 状态强制进入"待复核"
- **不得**直接归为正常

**修改方式**：
1. 补充夜间采样数据
2. 回滚到"公交刷卡时段已补录"状态
3. 重新生成热力图

**回滚支持**：是

> 代码位置：[boundary_rules.py](src/boundary_rules.py) 中的 `detect_night_low_sampling` 方法

### RULE_002: 公交刷卡时段缺失规则

**判定条件**：未补录公交刷卡时段

**处理方式**：不得生成最终热力图结论，必须先补录

**修改方式**：市政巡检员补录公交刷卡时段

**回滚支持**：是

> 代码位置：[boundary_rules.py](src/boundary_rules.py) 中的 `validate_before_heatmap_generation` 方法

### RULE_003: 数据去重规则

**判定条件**：同一源文件中相同内容的行

**处理方式**：自动跳过，记录跳过数量，总数不翻倍

**修改方式**：无（自动执行）

**回滚支持**：否

> 代码位置：[data_manager.py](src/data_manager.py) 中的 `import_photos` 方法

### RULE_004: 历史追踪规则

**判定条件**：任何字段修改（包括备注）

**处理方式**：自动记录改前快照、改后快照、操作人、时间、描述

**修改方式**：历史记录不可删除

**回滚支持**：是

> 代码位置：[data_manager.py](src/data_manager.py) 中的 `_add_history_record` 方法

### RULE_005: 人工复核强制规则

**判定条件**：热力图存在异常标记

**处理方式**：必须经过街道规划员复核才能标记为最终状态

**修改方式**：街道规划员填写复核意见后标记

**回滚支持**：是

> 代码位置：[workflow.py](src/workflow.py) 中的 `step3_generate_heatmap` 方法

## 标准三步流程

### 步骤1：路口照片导入

**角色**：数据导入员

**操作**：
1. 准备路口照片数据（JSON数组）
2. 指定源文件名和操作人
3. 执行导入

**系统自动处理**：
- 生成唯一photo_id
- 保留原始行号、源文件、原始数据
- 自动去重，重复数据跳过

**状态变迁**：无 → 已导入

### 步骤2：补录公交刷卡时段

**角色**：市政巡检员（小付）

**操作**：
1. 回看"历史街区招牌整治"
2. 发现遗漏的公交刷卡时段
3. 补录时段信息

**系统自动记录**：
- 补录前的状态快照
- 补录后的状态快照
- 操作人、时间、原因

**状态变迁**：已导入 → 公交刷卡时段已补录

### 步骤3：生成热力图

**角色**：系统自动 / 分析员

**前置条件**：已补录公交刷卡时段（RULE_002）

**系统自动处理**：
1. 校验前置条件
2. 生成热力图数据
3. 自动检测夜间缺采样（RULE_001）
4. 如检测到异常 → 进入待复核（RULE_005）
5. 如无异常 → 热力图已生成

**状态变迁**：
- 无异常：公交刷卡时段已补录 → 热力图已生成
- 有异常：公交刷卡时段已补录 → 待复核

### 步骤4（可选）：街道规划员复核

**角色**：街道规划员

**操作**：
1. 查看热力图
2. 查看原始数据溯源
3. 填写复核意见
4. 选择：标记为正常 / 确认夜间缺采样

**状态变迁**：
- 待复核 → 复核通过-正常
- 待复核 → 复核通过-夜间缺采样

## 回滚机制

支持从以下状态回滚：

| 当前状态 | 可回滚到 | 清除的数据 |
|---------|---------|-----------|
| 复核通过-正常/夜间缺采样 | 待复核 | 复核意见 |
| 待复核 | 热力图已生成 | 无 |
| 热力图已生成 | 公交刷卡时段已补录 | 热力图数据、异常标记 |
| 公交刷卡时段已补录 | 已导入 | 公交刷卡时段、热力图数据 |

> 代码位置：[boundary_rules.py](src/boundary_rules.py) 中的 `can_rollback` 和 `get_rollback_target` 方法

## 新同事验证指南

### 任务：只凭热力图找到夜间缺采样的来源和下一步动作

1. 运行 `python3 demo_script.py` 生成演示数据
2. 启动Web界面 `python3 app.py`
3. 访问 http://localhost:5000
4. 在首页找到"待复核"状态的记录
5. 点击"查看详情"
6. 观察热力图——夜间（22-06点）颜色明显偏浅
7. 查看异常检测提示和下一步操作建议
8. 查看"原始数据溯源"确认数据来源
9. 查看"变更历史"了解数据处理过程

### 预期结果：
- 能从热力图的颜色深浅判断出夜间采样不足
- 能看到系统给出的明确异常提示
- 能看到5条具体的下一步操作建议
- 能追溯到原始行号、源文件、导入时间

## 数据存储

所有数据以JSON格式存储在 `data/storage/` 目录：
- `photos.json`：路口照片主数据
- `history.json`：全部变更历史记录

可直接查看JSON文件验证数据完整性。
