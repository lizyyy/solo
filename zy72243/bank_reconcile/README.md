# 🏦 银行流水摘要归并系统

> 解决港币和人民币写在同一列的对账难题，让托管对接人能看懂、对账运营阿芬不用口头兜底

---

## ✨ 核心特性

| 功能 | 说明 |
|------|------|
| 🔍 **智能检测** | 自动识别金额列中的港币和人民币符号混合 |
| 📝 **审计明细** | 每条记录说明：为什么被留下、缺什么材料、下一步找谁 |
| 👩‍💼 **角色分工** | 托管对接人 ↔ 对账运营阿芬，职责清晰 |
| 📊 **3D图表** | 币种分布可视化，点击可回溯清算批次号和节假日说明 |
| 🔄 **自动更新** | 节假日顺延说明补录后，审计明细自动同步更新 |
| ⚠️ **谨慎原则** | 币种混合记录不自动归正常，必须人工复核 |

## 🚀 快速开始（新人照做就能跑通）

### 1. 安装依赖

```bash
cd bank_reconcile
pip3 install -r requirements.txt
```

### 2. 初始化数据库

```bash
# 首次使用
python3 -m src.cli init

# 如需清空旧数据重新开始
python3 -m src.cli init --reset
```

### 3. 运行自动化测试（完整三步流程）

```bash
python3 test_three_step_flow.py
```

你会看到完整的测试过程：
- ✅ 步骤1：导入样例数据，自动检测4条币种混合
- ✅ 步骤2：对账运营阿芬补录节假日说明，审计自动更新
- ✅ 步骤3：托管对接人复核，币种混合不自动归正常
- ✅ 最终生成完整审计报告

### 4. 用命令行自己试一遍

```bash
# 先确保干净环境（可选，如之前跑过测试）
python3 -m src.cli init --reset

# 步骤1：导入清算批次
python3 -m src.cli import-batch samples/sample_batch_20240601.csv --batch-no DEMO-001

# 查看待复核项
python3 -m src.cli pending --batch-no DEMO-001

# 步骤2：补录节假日顺延说明（对账运营阿芬）
python3 -m src.cli add-holiday DEMO-001 \
  --original-date 2024-06-01 \
  --adjusted-date 2024-06-03 \
  --reason "香港特别行政区成立纪念日" \
  --operator-note "已核对金管局公告"

# 查看某笔交易详情（含关联的清算批次号和节假日说明）
python3 -m src.cli view-transaction 3

# 步骤3：复核币种混合（托管对接人）- 不标记为正常
python3 -m src.cli review-mixed 3 \
  --review-note "确认为双币种结算，需分别记账" \
  --reviewed-by "托管对接人-王经理"

# 生成审计报告
python3 -m src.cli report DEMO-001 --format text
python3 -m src.cli report DEMO-001 --format html -o report.html
```

> **注意**：如果导入时报"清算批次号已存在"，说明之前已导入过同批次号。用 `python3 -m src.cli init --reset` 清空后重新开始。

### 5. 启动小看板（Web界面）

```bash
python3 -m src.cli dashboard
# 打开浏览器访问 http://127.0.0.1:5000
```

小看板功能：
- 🏠 首页：批次列表 + 待处理事项
- 📦 批次详情：所有交易明细
- 🔍 交易详情：点币种混合可查看清算批次号、节假日说明、审计明细
- 📊 3D图表：币种分布可视化，点击跳转详情

## 📋 业务流程详解

### 三步核心流程

```
┌─────────────────────────────────────────────────────────┐
│ 步骤1：清算批次号第一次导入                              │
│  ───────────────────────────────────────────────────── │
│  • 导入Excel/CSV文件                                    │
│  • 自动检测金额列中的港币+人民币符号                     │
│  • 生成审计明细：标记"需托管对接人复核"                 │
│  • 标记"缺少节假日顺延说明"                             │
└──────────────────────────┬──────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│ 步骤2：对账运营阿芬补看节假日顺延说明                    │
│  ───────────────────────────────────────────────────── │
│  • 补录节假日顺延日期和原因                             │
│  • 系统自动更新审计明细："缺少节假日说明" → 已解决       │
│  • 🔴 币种混合项保持待复核状态（不自动归正常）           │
└──────────────────────────┬──────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│ 步骤3：审计明细更新 + 托管对接人复核                     │
│  ───────────────────────────────────────────────────── │
│  • 托管对接人查看币种混合的交易                          │
│  • 可以：仅填写复核意见（保留待复核）                    │
│  • 或：确认无误后标记为正常（谨慎操作）                  │
│  • 审计明细实时更新，完整记录全过程                      │
└─────────────────────────────────────────────────────────┘
```

### 审计明细字段说明

每条审计记录都会清晰说明：

| 字段 | 说明 | 示例 |
|------|------|------|
| **为什么被留下** | 解释这条记录为什么还不能归并 | "金额列包含港币和人民币符号（CNY,HKD），需要托管对接人复核" |
| **还缺什么材料** | 明确缺少的凭证或说明 | "需要清算批次号来源说明和币种区分凭证" |
| **下一步该找谁** | 明确责任人 | "请托管对接人复核此笔交易" |
| **责任人** | 具体角色 | "托管对接人" / "对账运营阿芬" |

### 2. API 接口

启动后可调用 RESTful API：

```bash
# 启动服务
python3 -m src.api

# 获取批次列表

# 获取交易详情（点击3D图后调用）

# 补录节假日说明
curl -X POST http://127.0.0.1:5000/api/holiday \
  -H "Content-Type: application/json" \
  -d '{"batch_no":"DEMO-001","original_date":"2024-06-01","adjusted_date":"2024-06-03","reason":"节假日"}'

# 复核币种混合
curl -X POST http://127.0.0.1:5000/api/review \
  -H "Content-Type: application/json" \
  -d '{"transaction_id":3,"review_note":"确认无误","mark_normal":false}'

# 获取图表数据
curl http://127.0.0.1:5000/api/chart/currency_3d/DEMO-001
```

## 📊 3D/图表展示说明

### 币种分布3D散点图

- **X轴**：交易序号
- **Y轴**：金额
- **Z轴**：时间轴
- **颜色**：
  - 🟢 绿色 = CNY正常
  - 🔵 蓝色 = HKD正常
  - 🔴 红色 = CNY币种混合 ⚠️
  - 🟠 橙色 = HKD币种混合 ⚠️

**重要特性**：
- 点击红色/橙色点 → 跳转交易详情页
- 交易详情页显示：关联清算批次号、节假日顺延说明、审计明细
- **不会只剩漂亮画面** - 每个数据点都可回溯到原始凭证

### 其他图表

- **审计状态饼图**：已完成/待处理比例
- **复核状态饼图**：已复核/待复核比例
- **处理时间线**：完整记录导入→检测→补录→复核全过程

## ❓ 常见问题

**Q: 导入时报"清算批次号已存在"怎么办？**
A: 说明之前已导入过同批次号的数据。运行 `python3 -m src.cli init --reset` 清空后重新开始。

**Q: 为什么币种混合的记录不能自动归正常？**
A: 这是系统的谨慎原则。港币和人民币在同一列可能有多种情况（双币种结算、录入错误、系统bug等），必须由托管对接人人工确认。

**Q: 补录节假日说明后，为什么有些审计项还在？**
A: 节假日补录只会更新"缺少节假日说明"类型的审计项。币种混合类型的审计项会保留，需要托管对接人单独复核。

**Q: 点击3D图的点后，能看到什么？**
A: 会跳转到交易详情页，包含：
- 交易的完整信息
- 关联的清算批次号（可继续点击查看批次详情）
- 已补录的节假日顺延说明
- 完整的审计明细（为什么被留下、缺什么材料、下一步找谁）

**Q: 报告格式有哪些？**
A: 支持三种格式：
- `text` - 纯文本，适合打印或快速查看
- `html` - 带样式的网页，适合分享
- `json` - 结构化数据，适合系统对接
