# 管道阀门解谜游戏

一个面向水务展厅的2D浏览器游戏，玩家通过开关阀门隔离管网漏点，同时尽量减少对居民用户的影响。

## 🚀 快速启动

```bash
# 安装依赖
npm install

# 启动开发服务器
npm run dev

# 构建生产版本
npm run build

# 类型检查
npm run check

# 代码检查
npm run lint
```

启动后访问 `http://localhost:5173` 即可开始游戏。

## 🎮 玩法说明

### 游戏目标
在规定时间和步数内，通过开关阀门将所有漏点与水源隔离，同时尽可能减少对居民用户的影响。

### 核心规则
1. **阀门操作**：点击管道上的阀门图标可以开关阀门
2. **压力传递**：水源通过管道向用户区供水，压力随距离衰减
3. **连通性判定**：使用并查集算法实时计算管网连通状态
4. **漏点隔离**：关闭足够的阀门，使漏点无法从任何水源获得供水即为隔离成功
5. **用户影响**：用户区无法从水源获得供水或压力不足时即为受影响

### 操作界面
- **左侧状态面板**：实时显示漏点隔离数、受影响用户、压力值、剩余时间、步数
- **中间管网视图**：SVG渲染的2D管网图，可缩放拖拽
  - 🔵 蓝色节点：水源（供水起点）
  - 🟢 绿色节点：用户区（用水区域）
  - 🔴 红色节点：漏点（需要隔离的位置）
  - ⚪ 灰色节点：普通连接点
  - 💧 蓝色管道：有水流动
  - ⚫ 灰色管道：已断流
  - 🟢 绿色阀门：开启状态
  - 🔴 红色阀门：关闭状态
- **底部工具栏**：暂停/继续、撤销、重开、提交结算

### 计分规则
```
最终得分 = 基础分(1000) 
         + 漏点隔离奖励(200分/个) 
         - 用户影响惩罚(50分/个) 
         - 压力不足惩罚(30分/个) 
         - 步数超额惩罚(20分/超出步数) 
         + 时间奖励(剩余秒数×2)
```

### 胜负判定
**胜利条件**：
- 所有漏点都被成功隔离
- 受影响用户数不超过关卡限制
- 平均压力不低于关卡最低要求

**失败原因**（可在结算页和历史回放中查看）：
1. ❌ 漏点未完全隔离
2. ❌ 受影响用户过多
3. ❌ 管网压力过低
4. ❌ 误关主阀（水源完全断流）
5. ❌ 操作步数超出限制
6. ❌ 游戏时间耗尽

## 🗺️ 关卡说明

### 关卡 1：初识管网 ⭐
- **难度**：简单
- **目标**：隔离 1 个漏点
- **限制**：最多影响 0 个用户，最低压力 2.0
- **特点**：简单的线性管网，只有一条主管道，适合新手熟悉阀门操作

### 关卡 2：分支挑战 ⭐⭐
- **难度**：普通
- **目标**：隔离 2 个漏点
- **限制**：最多影响 1 个用户，最低压力 2.0，限 10 步
- **特点**：带有分支的管网，需要正确选择关闭哪些阀门

### 关卡 3：主阀警戒 ⭐⭐⭐
- **难度**：困难
- **目标**：隔离 2 个漏点
- **限制**：最多影响 1 个用户，最低压力 2.5，限 8 步
- **特点**：包含主阀门，误关会导致大面积断流，考验玩家的全局观

### 关卡 4：压力危机 ⭐⭐⭐⭐
- **难度**：专家
- **目标**：隔离 3 个漏点
- **限制**：最多影响 1 个用户，最低压力 3.0，限 12 步，限时 90 秒
- **特点**：长距离输送导致压力衰减明显，需要精细规划阀门策略

### 关卡 5：综合调度 ⭐⭐⭐⭐⭐
- **难度**：大师
- **目标**：隔离 4 个漏点
- **限制**：最多影响 2 个用户，最低压力 3.0，限 15 步，限时 120 秒
- **特点**：复杂的环状管网，多水源、多漏点、多用户，考验综合调度能力

## ⚠️ 边界案例

### 案例 1：误关主阀
**现象**：玩家关闭了靠近水源的主阀门，导致整个管网断流。
**后果**：所有用户区受影响，直接判定失败。
**建议**：先定位漏点位置，再从漏点附近开始关闭阀门，避免触动主管道阀门。

### 案例 2：影响区重复计算
**现象**：关闭一个阀门导致多个用户区同时断流，但系统只统计一次影响。
**说明**：系统使用BFS算法计算连通区域，每个用户区只判断一次是否与水源连通，不会重复计算。

### 案例 3：压力过低但未断流
**现象**：用户区与水源连通，但由于管道过长或阀门调节不当，压力低于最低要求。
**后果**：该用户区被判定为受影响，计入惩罚。
**建议**：优先保证靠近用户区的管道畅通，避免在用户区上游进行不必要的阀门操作。

### 案例 4：漏点与用户区连通
**现象**：漏点和用户区在同一个连通分支内，关闭阀门隔离漏点必然影响用户。
**策略**：寻找最优的阀门组合，在隔离漏点的同时，让尽可能多的用户区保持连通。

### 案例 5：多水源环状管网
**现象**：关闭一条路径后，水流可以通过另一条路径到达漏点。
**说明**：系统会计算所有可能的连通路径，只有当漏点与所有水源都断开时才视为隔离成功。

## 🎬 历史回放

游戏支持完整的操作历史回放：
- 从关卡选择页点击"历史记录"查看所有游戏记录
- 支持 0.5x~4x 倍速播放
- 支持逐帧前进/后退
- 支持时间轴拖动跳转
- 可在回放中查看每一步操作后的管网状态变化
- 失败原因会在结算页和历史记录中永久保存

## 📊 报告导出

每局游戏结束后可导出详细的隔离报告（TXT格式），包含：
- 关卡信息和最终得分
- 操作历史记录（时间、阀门ID、状态变化）
- 已隔离漏点列表
- 受影响用户区列表
- 最终管网状态（压力、连通性）
- 评估建议

## 🛠️ 技术栈

- **前端框架**：React 18 + TypeScript 5
- **构建工具**：Vite 5
- **状态管理**：Zustand 4
- **样式方案**：TailwindCSS 3
- **图标库**：Lucide React
- **渲染方案**：SVG 2D 渲染
- **核心算法**：并查集(Union-Find)、BFS广度优先搜索
- **数据持久化**：LocalStorage
