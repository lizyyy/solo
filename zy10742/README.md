# 客服质检导出复议改分核对 CLI

一个用于核对客服质检复议改分数据同步情况的命令行工具。

## 功能特性

- ✅ 核对复议后最终得分是否与复议得分一致
- ✅ 核对最终扣分项是否与复议扣分项同步
- ✅ 检测多轮复议中原始分是否正确继承上轮最终分
- ✅ 支持 JSON 和 CSV 格式输入
- ✅ 默认摘要输出，详细模式显示每条记录处理过程
- ✅ 内置 diff 功能，可对比规则变更前后的结果
- ✅ 自动生成样例数据

## 安装

```bash
npm install
npm link  # 全局安装命令
```

## 快速开始

### 1. 生成样例数据

```bash
cs-recheck sample -o samples
```

### 2. 核对正常数据

```bash
cs-recheck check samples/normal.json
```

### 3. 核对异常数据（详细模式）

```bash
cs-recheck check samples/abnormal.json -v
```

### 4. 输出结果到目录

```bash
cs-recheck check samples/normal.json -o output
```

### 5. Diff 对比规则变更

```bash
cs-recheck check samples/abnormal.json --diff samples/normal.json
```

## 命令说明

### `cs-recheck check <file>`

核对质检复议改分数据

**参数:**
- `file` - 质检数据文件 (JSON/CSV)

**选项:**
- `-v, --verbose` - 显示详细处理过程
- `-o, --output <dir>` - 输出结果目录
- `--diff <baseFile>` - 与基准文件做 diff 对比

### `cs-recheck sample`

生成样例数据

**选项:**
- `-o, --output <dir>` - 输出目录 (默认: samples)

## 业务规则

### 1. 得分同步核对

- 有复议时：最终得分必须等于复议得分
- 无复议时：最终得分必须等于原始得分

### 2. 扣分项同步核对

- 复议删除的扣分项必须在最终扣分项中同步删除
- 复议新增的扣分项必须在最终扣分项中同步存在
- 最终扣分项不能有无来源的扣分项（原始和复议中都没有）

### 3. 多轮复议继承核对

- 第 N 轮复议的原始得分必须等于第 N-1 轮的最终得分

## 数据格式

### JSON 格式

```json
[
  {
    "质检编号": "QC-2024-001",
    "客服工号": "CS001",
    "质检日期": "2024-01-15",
    "原始得分": 85,
    "复议得分": 90,
    "最终得分": 90,
    "复议状态": "approved",
    "复议轮次": 1,
    "原始扣分项": ["服务态度", "响应超时"],
    "复议扣分项": ["服务态度"],
    "最终扣分项": ["服务态度"],
    "复议原因": "经核实响应超时为系统原因",
    "处理人": "质检主管A",
    "处理时间": "2024-01-16"
  }
]
```

### CSV 格式

```csv
质检编号,客服工号,质检日期,原始得分,复议得分,最终得分,复议状态,复议轮次,原始扣分项,复议扣分项,最终扣分项,复议原因,处理人,处理时间

```

## 字段说明

| 字段 | 说明 | 必填 |
|------|------|------|
| 质检编号 | 质检记录唯一标识 | 是 |
| 客服工号 | 客服人员编号 | 否 |
| 质检日期 | 质检日期 | 否 |
| 原始得分 | 初评得分 | 是 |
| 复议得分 | 复议后得分，无复议则为 null | 否 |
| 最终得分 | 最终确认得分 | 是 |
| 复议状态 | pending/approved/rejected/partial | 否 |
| 复议轮次 | 第几次复议 | 否 |
| 原始扣分项 | 初评扣分项列表 | 否 |
| 复议扣分项 | 复议后扣分项列表 | 否 |
| 最终扣分项 | 最终确认扣分项列表 | 否 |
| 复议原因 | 复议申请原因 | 否 |
| 处理人 | 复议处理人 | 否 |
| 处理时间 | 复议处理时间 | 否 |

## 输出文件

使用 `-o` 选项时会输出以下文件：

1. **summary.json** - 汇总统计信息
2. **results.json** - 每条记录的详细核对结果
3. **diffable.json** - 可用于 diff 对比的简化结果

## 使用场景示例

### 场景1: 日常核对

每天导出质检数据，运行核对工具检查数据同步情况：

```bash
cs-recheck check data/2024-01-15.json -o output/2024-01-15
```

### 场景2: 规则变更验证

修改核对规则后，对比新旧结果：

```bash
cs-recheck check new-rules/normal.json --diff old-rules/normal.json
```

### 场景3: 问题定位

发现异常后，使用详细模式定位问题：

```bash
cs-recheck check abnormal.json -v
```
