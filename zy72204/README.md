# 期权保证金压力试算系统

支付平台产品阿南专用 - 解决柜台流水尾号和客户经理补充邮件互相补台又互相打架的问题。

## 核心功能

### 1. 柜台流水管理
- 支持CSV/Excel文件拖拽或点击导入
- 自动去重：以 `tailNumber`（柜台流水尾号）作为唯一标识，重复导入不会翻倍
- 支持单独修改备注，不影响去重逻辑
- 三步工作流进度可视化

### 2. 保证金试算
- 支持三种压力场景：轻度、中度、重度
- 自动检测同一业务号拆分为本金和手续费的情况
- 拆分记录标记为"待复核"，由结算主管确认
- 支持回滚到上一版本

### 3. 3D/图表展示
- 柱状图：基础保证金 vs 压力保证金对比
- 饼图：试算状态分布
- 折线图：保证金比例趋势
- **数据溯源**：点击任意图表项可回溯原始柜台流水和补充邮件

### 4. 历史版本追踪
- 所有操作（创建、更新、回滚）都记录历史
- 即使只修改一条备注，也能清晰看到改前改后的差别
- 支持按实体类型和操作类型筛选
- 版本号自动递增（v1, v2, v3...）

### 5. 边界规则说明
- 所有业务规则在代码和文档中双重记录
- 杜绝口头约定，一切以代码和本文档为准
- 内置规则页面可随时查看

## 边界处理规则

### 规则一：同一业务号拆分为手续费和本金两行

**检测条件**：同一业务号下同时存在 `transactionType` 为 "PRINCIPAL"（本金）和 "FEE"（手续费）的两条记录

**处理方式**：
1. 系统自动检测并标记为 **"拆分待复核"** 状态
2. **不急着归为"正常"**，留给结算主管复核确认
3. 结算主管可选择：
   - "确认拆分正常" → 状态更新为 **"正常"**
   - "标记为有争议" → 状态更新为 **"有争议"**

**代码位置**：`src/services/businessLogic.ts - detectSplit()`

---

### 规则二：重复导入同一批柜台流水尾号

**去重依据**：`tailNumber`（柜台流水尾号）

**处理方式**：
1. 导入时检查尾号是否已存在
2. 已存在的尾号直接 **跳过**，不会创建重复记录
3. 保证金数量 **不会** 因为重复导入而翻倍
4. 允许单独修改 `remark`（备注）字段，不影响去重逻辑

**代码位置**：`src/store/calculationStore.ts - importTransactions()`

---

### 规则三：修改备注的历史版本追踪

**追踪范围**：
1. 所有字段修改都记录历史版本
2. **即使只改一条备注，也要能看出改前改后的差别**
3. 支持版本号递增（v1, v2, v3...）

**记录内容**：
- 操作类型：CREATE / UPDATE / DELETE / ROLLBACK
- 变更字段：old value → new value（对比展示）
- 操作人、操作时间、备注说明

**回滚支持**：支持回滚到上一版本，回滚操作本身也会被记录

**代码位置**：`src/store/calculationStore.ts - updateRemark() / rollbackCalculation()`

---

### 规则四：3D/图表展示的数据溯源

**服务复核要求**：
1. **不能只剩漂亮画面**，必须能追溯原始数据
2. 点击图表中的业务号可打开溯源抽屉
3. 展示关联的 **柜台流水尾号记录**
4. 展示关联的 **客户经理补充邮件**
5. 展示拆分详情（如果存在）

**溯源内容**：
1. 柜台流水：尾号、类型、金额、日期、备注
2. 拆分信息：本金 + 手续费 = 合计
3. 补充邮件：主题、发件人、内容、发送时间

**代码位置**：`src/pages/ChartView.tsx - 溯源抽屉组件`

---

### 规则五：三步工作流处理顺序

| 步骤 | 操作 | 角色 | 状态标记 |
|------|------|------|----------|
| 第一步 | 柜台流水第一次导入 | 支付平台产品阿南 | `STEP1_IMPORTED` |
| 第二步 | 补看客户经理补充邮件 | 支付平台产品阿南 | `STEP2_EMAIL_SUPPLEMENTED` |
| 第三步 | 差异清单更新 | 结算主管复核 | `STEP3_DIFF_UPDATED` |

**关键节点**：同一业务号拆成手续费和本金两行时，在 **第三步** 由结算主管复核

**代码位置**：`src/types/index.ts - WorkflowStep 类型定义`

## 数据导入格式

### 柜台流水 CSV 格式

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `tailNumber` | string | 是 | 柜台流水尾号（去重依据） |
| `businessNumber` | string | 是 | 业务号 |
| `transactionDate` | string | 是 | 交易日期（YYYY-MM-DD） |
| `amount` | number | 是 | 金额（必须>0） |
| `amountType` | string | 否 | PRINCIPAL/FEE/COMBINED |
| `counterparty` | string | 否 | 对手方 |
| `remark` | string | 否 | 备注 |

## 设计原则

1. **边界规则代码化**：所有规则都写在代码里，不依赖口头约定
2. **操作留痕**：所有修改都有历史记录，可追溯、可回滚
3. **错误说人话**：不吐内部字段名，直接告诉用户该怎么做
4. **图表可溯源**：漂亮画面背后要有真实数据支撑
5. **流程不跳跃**：三步工作流按顺序走，拆分记录必须复核
