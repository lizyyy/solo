## 1. 产品概述

生鲜分拣损耗异常回执状态机服务，解决生鲜配送中坏果扣款、二次分拣损耗重复计算问题，实现从收货到结算全流程可追溯。

- 核心目标：统一管理供应商送货单、称重记录、退筐照片、外部回执，提供完整状态追踪
- 目标用户：采购经理、录入员、复核员、主管领导
- 核心价值：避免重复扣款、保留审计轨迹、支持数据修正与重新汇总

## 2. 核心功能

### 2.1 用户角色

| 角色 | 描述 | 核心权限 |
|------|------|----------|
| 录入员 | 基础数据录入人员 | 创建批次、上传附件、录入单据、查看自己录入的数据 |
| 复核员 | 数据审核人员 | 复核异常、改判状态、补传材料、查看所有待复核数据 |
| 主管 | 管理人员 | 冻结结算、撤回归档、查看汇总、导出报表 |
| 只读查看 | 审计或其他人员 | 仅查看已完成数据、不可操作 |

### 2.2 功能模块

1. **批次管理**：创建批次、补传附件、查看批次详情
2. **状态流转**：状态机流转、动作记录、轨迹查询
3. **异常处理**：脏记录识别、保留原始数据、修正重新汇总
4. **冻结结算**：冻结前后状态对比、人工理由记录、结算锁定
5. **报表导出**：汇总数据导出、状态变化追踪、来源追溯

## 3. 核心流程

### 3.1 主流程

创建批次 → 录入材料 → 系统校验 → 复核改判 → 冻结结算 → 撤回归档

### 3.2 状态机流程图

```mermaid
stateDiagram-v2
    [*] --> "草稿(DRAFT)"
    "草稿(DRAFT)" --> "待复核(PENDING_REVIEW)" : 提交复核
    "待复核(PENDING_REVIEW)" --> "已复核(REVIEWED)" : 复核通过
    "待复核(PENDING_REVIEW)" --> "需修正(NEEDS_FIX)" : 退回修正
    "需修正(NEEDS_FIX)" --> "待复核(PENDING_REVIEW)" : 重新提交
    "已复核(REVIEWED)" --> "已冻结(FROZEN)" : 冻结结算
    "已冻结(FROZEN)" --> "已归档(ARCHIVED)" : 撤回归档
    "已冻结(FROZEN)" --> "待复核(PENDING_REVIEW)" : 解冻
    "草稿(DRAFT)" --> "已取消(CANCELLED)" : 取消
```

### 3.3 脏记录处理流程

数据录入 → 系统校验 → 识别异常 → 标记脏记录 → 保留原始数据 → 人工修正 → 重新汇总

## 4. 用户界面设计

### 4.1 设计风格

- 主色调：深青色(#0891b2)，体现专业性和可靠性
- 辅助色：琥珀色(#f59e0b)用于警告，红色(#ef4444)用于异常，绿色(#10b981)用于成功
- 字体：现代无衬线字体，清晰易读
- 按钮风格：圆角8px，悬停效果明显
- 布局：卡片式设计，清晰的信息层级
- 图标风格：线性图标，简洁明了

### 4.2 页面设计概述

| 页面名称 | 模块名称 | UI Elements |
|-----------|-------------|-------------|
| 批次列表页 | 筛选区域 | 下拉选择、日期范围、搜索框 |
| 批次列表页 | 批次卡片 | 状态标签、供应商名称、日期、核心数据、操作按钮 |
| 批次详情页 | 时间线 | 状态流转时间线、操作人、备注 |

### 4.3 响应性

- 桌面端优先设计，支持1280px及以上分辨率

## 5. 数据校验与异常类型

### 5.1 脏记录类型

| 类型 | 描述 | 处理方式 |
|------|------|----------|
| 缺字段 | 必填字段缺失 | 标记后人工补全 |
| 跨日 | 日期跨天或逻辑错误 | 确认后调整日期 |
| 改名 | 供应商或商品名称不一致 | 映射统一名称 |
| 金额冲突 | 送货单与称重金额不符 | 人工判定以哪个为准 |
| 数量冲突 | 送货数量与称重数量不符 | 人工判定以哪个为准 |

### 5.2 核心数据追踪

- 冻结前状态：原始数据汇总
- 冻结后状态：修正后数据汇总
- 人工理由：每次状态变更的原因记录
- 来源追溯：每条数据的来源单据
