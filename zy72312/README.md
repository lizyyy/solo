# 凸包围栏面积复核系统

整合**手算反例**（主流程）与**问卷原始行**（现场说法）证据，实现精准的凸包围栏面积复核。

---

## ✨ 核心特性

| 功能 | 说明 |
|------|------|
| 📐 几何分析 | 自动检测凹点、重复坐标、顺逆时针问题 |
| 🔴 问题边标注 | 面积结果旁边用红色画出问题边 |
| 📋 双版本检测 | 同一学生交了两版答案时，留待业务运营复核 |
| 📝 智能误差说明 | 说明为什么被留下、缺什么材料、下一步找谁 |
| 🖥️ 三种入口 | 命令行 / API / 小看板 |
| 🔄 数据联动 | 补录问卷后误差说明自动更新 |

```bash

```

```bash

```

### 批准记录

```bash
npm run cli -- approve <record-id> "吴老师"
```

## 🔍 复核流程详解

### 三步标准流程

```
第一步：导入手算反例
    ↓
第二步：系统自动复核
    ↓ 发现同一学生多版答案 → 标记【需运营复核】
    ↓ 发现几何问题 → 标记【待处理】
第三步：吴老师补看问卷原始行
    ↓
误差说明自动更新
```

### 同一学生多版答案处理

> **关键设计原则：别急着归正常，留给业务运营复核**

当系统检测到：
- 同一 `studentId` + `answerId`
- 存在多条不同版本的答案

系统会：
1. 标记状态为 `needs-operation-review`（需运营复核）
2. 分配给：**先找业务运营**
3. 在误差说明中明确指出有几版答案
4. 保留所有版本的提交时间和来源

### 几何边界检测

系统自动分离以下问题，分别提示：

| 问题类型 | 提示方式 |
|----------|----------|
| 🔷 **凹点** | "发现凹点: (x, y) 位于多边形凹处" |
| 🔴 **重复坐标** | "发现重复坐标: (x, y)，第N点与之前重复" |
| ↩️ **顺逆时针** | "坐标顺序为顺时针，标准应为逆时针" |

### 误差说明模板

报告中的误差说明包含：

```
【几何问题】
• 凹点、重复坐标等具体问题

【缺少材料】
• 缺少手算反例 / 缺少问卷原始行

【面积差异】
• 原始面积、凸包面积、差值百分比

【下一步行动】
• 先找业务运营  OR
• 找教研负责人吴老师
```

## 🔬 核心算法

### Graham 扫描法求凸包

时间复杂度：O(n log n)

1. 按 x 坐标排序所有点
2. 构建下凸包（从左到右）
3. 构建上凸包（从右到左）
4. 过程中检测并报告凹点
5. 合并结果得到凸包

### 鞋带公式计算面积

```
面积 = 1/2 × |Σ(xi×yi+1 - xi+1×yi)|
```

### 环绕方向检测

通过有向面积的正负值判断：
- 负值：逆时针（标准）
- 正值：顺时针
- 零：共线

## 💡 设计理念

### 为什么要整合两边证据？

- **手算反例**：反映学生的**计算主流程**，看过程对不对
- **问卷原始行**：反映**现场说法**，看实际情况是什么
- 两边对照，才能判断误差是计算错误还是现场特殊情况

### 报告不能写成冷冰冰的系统日志

每条复核记录都会回答：
1. **为什么被留下** - 误差说明列出具体问题
2. **还缺什么材料** - 明确缺少手算反例还是问卷
3. **下一步该找谁** - 业务运营还是教研负责人吴老师

### 漂亮画面不能丢了证据

- 点击可视化图可以溯源
- 3D/图表展示时保留"查看原始数据"入口
- 每版答案都记录提交时间和来源

## ❓ 常见问题

**Q: 多版本答案为什么不自动合并？**

A: 因为不知道哪版是学生最终意愿，必须由业务运营跟学生确认后才能定。

**Q: 顺时针输入但面积正确，为什么还要提示？**

A: 因为有规范要求，虽然面积结果对了，但输入顺序不符合标准，需要提醒学生注意。

**Q: 凹点一定是错误吗？**

A: 不一定。如果问卷原始行说明现场有特殊情况（如障碍物），凹点就是合理的。系统只检测，不直接判错。
