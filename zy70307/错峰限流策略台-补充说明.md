# 错峰限流策略台 - 补充说明

本文档围绕"错峰限流策略台"的主要边界、一个失败路径和一次重复执行路径进行详细说明，方便后续复查。

---

## 一、主要边界（系统边界与使用边界）

### 1.1 功能边界

| 边界项 | 说明 | 所在位置 |
|--------|------|----------|
| **规则状态生命周期** | DRAFT（草稿）→ ACTIVE（生效）→ PAUSED（暂停）/ DEPRECATED（弃用）/ ROLLED_BACK（已回滚）。只有 DRAFT 状态可编辑/删除，ACTIVE 状态规则不可直接修改 | `server/src/routes/rules.js:24-47` |
| **发布批次生命周期** | PENDING（待发布）→ ACTIVE（生效中）→ PAUSED（已暂停）/ DEPRECATED（已弃用）/ ROLLED_BACK（已回滚） | `server/src/routes/releases.js` |
| **VIP豁免双重判断** | 豁免需要同时满足两个条件：(1) 租户自身 `vipExempt = true`；(2) 规则 `vipExempt = true`。二者缺一不可 | `server/src/services/rateLimitEngine.js:70-76` |
| **规则优先级排序** | 同一接口可能匹配多条规则，按 `priority` 从高到低（数值越大越优先）排序，高优先级规则先命中，触发限制即停止检查 | `server/src/services/rateLimitEngine.js:17-39` |
| **地区规则叠加逻辑** | 特定地区规则（如 CN-EAST）优先于全国规则（DEFAULT），但最终仍按 priority 排序。同一请求可同时匹配地区规则+租户规则，但只取最高优先级生效的规则 | `server/src/services/rateLimitEngine.js:26-30` |
| **重复发布同一版本** | 相同规则组合再次发布会自动递增版本号（如 20260512.1 → 20260512.2），不会创建完全相同的版本 | `server/src/routes/releases.js:64-70` |
| **发布冲突检测** | 同一规则组合如果已存在 ACTIVE 发布，再次创建会返回错误，防止重复激活 | `server/src/routes/releases.js:53-62` |
| **回滚后日志可追溯** | 回滚后旧版本日志仍保留 `releaseId`、`releaseVersion` 关联，可按发布批次查询历史命中记录 | `server/src/routes/hitLogs.js:90-112` |
| **数据持久化** | 数据存储为本地 JSON 文件（`server/src/data/db.json`），首次启动自动初始化默认数据 | `server/src/utils/dataStore.js:84-92` |

### 1.2 技术边界

| 边界项 | 说明 |
|--------|------|
| **限流引擎类型** | 当前为**模拟引擎**，使用确定性哈希模拟阈值超限，不包含真实的滑动窗口/令牌桶实现 |
| **并发安全** | 单进程文件存储，未做分布式锁，适合单机演示/小规模场景 |
| **日志上限** | 模拟日志写入时限制最多 5000 条，防止数据文件无限增长 |
| **规则匹配精度** | 接口路径匹配为前缀匹配（startsWith）或精确匹配 |

### 1.3 使用边界

```
┌─────────────────────────────────────────────────────────────────┐
│                        正常使用流程                              │
├─────────────────────────────────────────────────────────────────┤
│  租户管理 → 接口分组 → 规则管理(DRAFT) → 策略预演 → 发布批次     │
│     │           │            │            │          │         │
│  VIP分级     接口归类    设置优先级    验证效果    发布/回滚    │
│  豁免开关     多接口      地区/租户     VIP豁免    版本管理     │
└─────────────────────────────────────────────────────────────────┘
```

## 二、一个失败路径（发布失败场景）

### 2.1 场景描述

**场景名称：VIP租户核心下单被限流**

**触发条件：**
- 租户A为VIP，但租户配置的 `vipExempt = false`（漏掉了）
- 规则R1开启了 `vipExempt = true`，但由于租户自身未标记VIP，豁免不生效
- 规则R2是全局规则且 `vipExempt = false`，优先级高于R1

**执行链路：**

```
请求到达（VIP租户 + 核心下单接口）
    │
    ▼
获取租户信息 → tenant.vipExempt = false ❌
    │
    ▼
匹配规则列表（按优先级排序）
    ├─ 规则R2 (priority=80, vipExempt=false)
    │   └─ 匹配条件满足 → VIP豁免判断跳过（因为租户没标记VIP）
    │   └─ 阈值超限 → 触发拒绝
    │
    └─ 规则R1 (priority=50, vipExempt=true)
        └─ 因R2已命中，不再检查
    │
    ▼
结果：请求被拒绝 ❌（VIP租户的核心下单被误伤）
```

### 2.2 问题定位

1. **租户配置遗漏** → 租户管理页未勾选 VIP 豁免开关
2. **规则优先级设计问题** → 非VIP豁免的全局规则优先级高于VIP豁免规则
3. **预演未覆盖** → 预演时未选择 VIP 租户样本，未发现问题

### 2.3 解决方案

| 步骤 | 操作 | 页面 |
|------|------|------|
| 1 | 修正租户配置，开启VIP豁免 | 租户管理 → 编辑 |
| 2 | 调整规则优先级，VIP豁免规则设更高优先级 | 规则管理 → 编辑 |
| 3 | 预演时添加VIP租户样本验证豁免逻辑 | 策略预演 → 编辑请求样本 |
| 4 | 发布新版本或回滚到上一稳定版本 | 发布批次 → 发布/回滚 |
| 5 | 查看命中日志确认 VIP 租户不再被限制 | 命中日志 → 筛选租户 |

### 2.4 系统如何展示此问题

- **命中日志展开详情**：显示"规则R2触发QPS限制，拒绝"，未显示"VIP豁免"标签
- **策略预演说明**：在"规则优先级说明"Tab中可看到优先级排序，R2排在R1前面
- **发布批次对比**：对比发布前后拦截率，可发现VIP租户拦截率异常升高

## 三、一次重复执行路径（回滚后重新发布）

### 3.1 场景描述

**场景名称：策略发布 → 发现问题 → 回滚 → 修复后重新发布**

**目标：** 验证回滚后日志可追溯，重复发布版本号正确递增

### 3.2 执行路径

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                        重复执行路径完整链路                                    │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  【Step 1: 首次发布】                                                         │
│  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐                    │
│  │ 创建规则R1-3 │───▶│ 创建发布批次 │───▶│ 发布 v1.0    │                    │
│  │ (DRAFT状态)  │    │ PENDING状态  │    │ ACTIVE状态   │                    │
│  └──────────────┘    └──────────────┘    └──────────────┘                    │
│         │                    │                    │                          │
│         ▼                    ▼                    ▼                          │
│  rules.status=DRAFT   release.status=PENDING  rules.status=ACTIVE            │
│                        version=20260512.1     currentRelease=v1              │
│                                                                              │
├──────────────────────────────────────────────────────────────────────────────┤
│  【Step 2: 模拟流量生成日志】                                                  │
│  ┌─────────────────────────────────────────────────────────────────┐         │
│  │  hit_logs.releaseId = release.id                                │         │
│  │  hit_logs.releaseVersion = 20260512.1                           │         │
│  │  hit_logs.releaseName = "活动高峰策略v1"                        │         │
│  └─────────────────────────────────────────────────────────────────┘         │
│                                                                              │
├──────────────────────────────────────────────────────────────────────────────┤
│  【Step 3: 发现问题，执行回滚】                                                │
│  ┌──────────────┐    ┌─────────────────────────────────────────────┐          │
│  │ 点击回滚按钮 │───▶│ release.status = ROLLED_BACK                │          │
│  └──────────────┘    │ release.rolledBackAt = now                 │          │
│                      │ rules.status = ROLLED_BACK                 │          │
│                      │ currentRelease = null (或上一版本)          │          │
│                      └─────────────────────────────────────────────┘          │
│                                                                              │
│  关键点：老日志仍保留 v1.0 版本关联，可在命中日志中按发布批次筛选追溯            │
│                                                                              │
├──────────────────────────────────────────────────────────────────────────────┤
│  【Step 4: 修复问题】                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐         │
│  │ 方案A：修改规则优先级/VIP豁免开关（只能改DRAFT规则，需新建）       │         │
│  │ 方案B：创建新规则R4，加入发布批次                                 │         │
│  │ 方案C：直接回滚到更早的稳定版本                                   │         │
│  └─────────────────────────────────────────────────────────────────┘         │
│                                                                              │
├──────────────────────────────────────────────────────────────────────────────┤
│  【Step 5: 重新发布（相同规则组合）】                                          │
│  ┌─────────────────────────────────────────────────────────────────┐         │
│  │ 创建发布批次（选择R1-3，规则组合与v1相同）                        │         │
│  │ 检测到相同规则组合已存在，自动递增版本号                          │         │
│  │ version = 20260512.2  ✅（不是 20260512.1）                      │         │
│  │ release.status = PENDING → ACTIVE                               │         │
│  └─────────────────────────────────────────────────────────────────┘         │
│                                                                              │
├──────────────────────────────────────────────────────────────────────────────┤
│  【Step 6: 效果验证】                                                         │
│  ┌─────────────────────────────────────────────────────────────────┐         │
│  │ 命中日志可分别筛选：                                             │         │
│  │   - releaseVersion = 20260512.1 → 回滚前的命中记录               │         │
│  │   - releaseVersion = 20260512.2 → 重新发布后的命中记录           │         │
│  │                                                                 │         │
│  │ 发布批次对比统计：                                               │         │
│  │   - v1.0 拦截率：45% ❌                                          │         │
│  │   - v1.1 拦截率：28% ✅                                          │         │
│  └─────────────────────────────────────────────────────────────────┘         │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 3.3 关键验证点

| 验证项 | 预期结果 | 验证位置 |
|--------|----------|----------|
| **版本号不重复** | 相同规则组合第二次发布应为 `20260512.2` | 发布批次列表 |
| **日志可追溯** | 筛选 releaseVersion=20260512.1 仍能看到记录 | 命中日志 → 发布批次筛选 |
| **回滚后规则状态** | 规则状态变为 `ROLLED_BACK`，不可编辑 | 规则管理 → 状态列 |
| **发布对比统计** | 发布批次对比Tab可看到v1.0和v1.1的拦截率差异 | 总览页/命中日志统计 |
| **策略预演对比** | 可在预演页选择不同规则组合验证差异 | 策略预演页 |

### 3.4 复查清单（下一轮直接照着走）

1. ☐ **租户管理**：确认VIP租户的 `vipExempt` 开关已开启
2. ☐ **规则管理**：确认VIP豁免规则优先级高于非豁免规则
3. ☐ **策略预演**：用VIP租户样本执行预演，展开详情确认豁免生效
4. ☐ **发布批次**：创建新批次 → 发布 → 观察当前生效版本
5. ☐ **模拟流量**：生成30条模拟流量
6. ☐ **命中日志**：确认VIP租户请求未被限制，查看展开详情
7. ☐ **故意回滚**：执行回滚，观察版本状态变为ROLLED_BACK
8. ☐ **日志追溯**：筛选旧版本，确认历史记录仍可查询
9. ☐ **重复发布**：用相同规则创建新批次，确认版本号递增
10. ☐ **报表导出**：导出CSV，检查包含releaseVersion字段

## 四、API速查

### 核心API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/releases/preview` | 策略预演 |
| POST | `/api/releases` | 创建发布批次 |
| POST | `/api/releases/:id/publish` | 发布 |
| POST | `/api/releases/:id/pause` | 暂停 |
| POST | `/api/releases/:id/rollback` | 回滚 |
| GET | `/api/hit-logs/stats` | 效果统计 |
| POST | `/api/hit-logs/simulate` | 模拟流量 |
| GET | `/api/hit-logs/export?format=csv` | 导出报表 |

### 优先级判断伪代码

```javascript
// server/src/services/rateLimitEngine.js
// 执行顺序：
// 1. 按priority降序排序规则
// 2. 依次检查匹配条件（接口组、地区、租户等级）
// 3. 检查VIP豁免（租户.vipExempt && 规则.vipExempt）
// 4. 第一条触发限制的规则即为最终结果
```
