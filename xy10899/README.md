# 发布就绪度 API 管理平台

一个偏技术方向的全栈 Web 应用，用于管理和追踪软件版本发布前的各项检查项、阻塞原因、豁免审批和就绪度评分。

## 功能特性

### 后端功能
- ✅ **重复调用处理**: API 接口支持幂等性调用
- ✅ **状态追踪**: 完整的操作日志记录所有变更
- ✅ **数据导出**: 支持 CSV 格式导出发布概览和详情
- ✅ **异常处理**: 统一的错误处理和响应机制

### 前端功能
- ✅ **总览页面**: 发布列表统计，包含总数量、进行中、就绪状态
- ✅ **详情页面**: 完整的发布详情，包含版本信息、就绪度评分
- ✅ **检查清单**: 按分类展示检查项，支持状态流转（待处理→进行中→通过/失败）
- ✅ **阻塞原因管理**: 标记阻塞、解决阻塞，支持关联具体检查项
- ✅ **豁免审批流程**: 申请豁免、批准豁免
- ✅ **操作日志**: 完整的历史操作记录，可追踪所有变更

### 数据模型
- **发布版本 (Releases)**: 版本号、标题、描述、状态、就绪度评分、创建人
- **检查项 (Check Items)**: 分类（文档/迁移/告警/预案）、名称、状态、结果、责任人
- **阻塞原因 (Block Reasons)**: 原因描述、报告人、解决状态、解决人
- **豁免记录 (Exemptions)**: 豁免理由、申请人、审批状态、审批人
- **操作日志 (Operation Logs)**: 操作类型、操作人、详情、时间戳

### 核心规则
- **检查项聚合**: 按分类聚合展示，自动计算完成率
- **阻塞状态**: 阻塞会影响检查项状态，解决后自动恢复
- **豁免审批**: 豁免需审批，批准后检查项计入完成率
- **评分计算**: 就绪度 = (通过数 + 豁免数) / 总检查项数 × 100
- **就绪报告**: 支持导出概览和详细检查结果

## 快速开始

### 环境要求
- Node.js 16+
- npm 或 yarn

### 1. 启动后端服务

```bash
cd backend
npm install
npm run init-db  # 初始化数据库（首次运行）
npm start        # 或 npm run dev 开发模式
```

后端服务将运行在 `http://localhost:3000`

### 2. 启动前端应用

```bash
cd frontend
npm install
npm run dev
```

前端应用将运行在 `http://localhost:5173`

## API 接口文档

### 发布版本
- `POST /api/releases` - 创建新发布
- `GET /api/releases` - 获取发布列表（支持按状态过滤）
- `GET /api/releases/:id` - 获取发布详情
- `PUT /api/releases/:id/status` - 更新发布状态

### 检查项
- `PUT /api/releases/:releaseId/check-items/:checkItemId/status` - 更新检查项状态

### 阻塞原因
- `POST /api/releases/:releaseId/blocks` - 添加阻塞原因
- `PUT /api/releases/blocks/:blockId/resolve` - 解决阻塞

### 豁免审批
- `POST /api/releases/:releaseId/exemptions` - 申请豁免
- `PUT /api/releases/exemptions/:exemptionId/approve` - 批准豁免

### 数据导出
- `GET /api/releases/:id/export` - 导出发布概览 CSV
- `GET /api/releases/:id/export/detail` - 导出检查详情 CSV

### 健康检查
- `GET /health` - 服务健康状态检查

## 默认检查项

创建发布时会自动创建以下 8 个检查项，分为 4 大类：

### 📄 文档
1. 技术方案评审 - 技术方案已完成评审并归档
2. 用户手册更新 - 用户操作手册已更新至最新版本

### 🔄 迁移
3. 数据库迁移脚本 - 数据库迁移脚本已编写并测试
4. 回滚脚本验证 - 数据库回滚脚本已验证可行

### 📊 告警
5. 监控大盘配置 - 相关业务监控大盘已配置完成
6. 告警规则设置 - 告警规则和通知渠道已设置

### 📋 预案
7. 回滚预案 - 回滚预案已制定并全员周知
8. 灰度发布方案 - 灰度发布方案已确认

## 使用流程

1. **创建发布**: 填写版本号、标题、描述、创建人等信息
2. **检查项流转**: 逐个确认检查项，标记为进行中、通过或失败
3. **标记阻塞**: 如遇问题可标记阻塞，填写阻塞原因
4. **申请豁免**: 对无需检查的项可申请豁免，需审批
5. **导出报告**: 导出就绪度报告用于评审
6. **状态更新**: 全部检查通过后标记为就绪，发布完成后标记为已发布

## 验收说明

验收时可以通过以下方式验证：

1. **页面操作流程**:
   - 访问 `http://localhost:5173`
   - 创建新发布 → 查看检查项 → 更新状态 → 标记阻塞 → 解决阻塞 → 申请豁免 → 批准豁免 → 导出数据

2. **接口验证**:
   - 使用 Postman 或 curl 调用各 API 接口
   - 验证重复调用的幂等性
   - 验证操作日志的完整性

3. **重点功能验证**:
   - ✅ 重复操作稳定性：同一操作多次调用不会产生异常
   - ✅ 历史可追踪：所有操作都记录在操作日志中
   - ✅ 状态流转正确性：检查项状态流转、阻塞处理、豁免审批流程
