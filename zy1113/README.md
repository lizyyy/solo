# 售后语音纪要归因和跟进建议台

一个本地运行的售后语音纪要归因分析系统，用于帮助小家电维修点或本地服务团队管理售后通话记录、自动归类问题、跟踪承诺事项并生成复盘报告。

## 功能特性

### 🎯 核心功能

- **数据导入**：支持导入客户、订单、分类标签和通话纪要数据（CSV/JSON格式）
- **智能归因**：自动文本分析和关键词匹配，将通话纪要归类到预设问题分类
- **聚类看板**：可视化展示问题分类占比、客服统计、客户频率等
- **承诺跟踪**：自动识别"明天回电"、"补寄配件"等承诺，生成跟进任务
- **人工修正**：支持人工修改归因结果，修改后会作为样本影响后续自动归因
- **风险提示**：对快到期或已逾期的承诺自动标记风险等级
- **报告导出**：支持导出 Markdown、HTML、CSV、JSON 四种格式的复盘报告

### 📊 预设问题分类

- 安装误解（看不懂说明书、安装步骤问题）
- 配件缺货（缺件、没货、缺货）
- 师傅爽约（没来、迟到、爽约）
- 收费争议（太贵、价格问题、乱收费）
- 产品质量（坏了、故障、反复出问题）
- 配送延迟（送货晚、没收到、物流问题）
- 售后服务（客服态度、服务不满意）
- 退换货（退货、换货、退款）
- 其他

## 数据导入

### 数据文件格式

系统支持导入以下四种数据文件：

#### 1. 客户数据 (customers.csv)

| 字段 | 必填 | 说明 |
|------|------|------|
| customer_id / id | 是 | 客户唯一标识 |
| name | 是 | 客户姓名 |
| phone | 否 | 联系电话 |
| email | 否 | 电子邮箱 |
| region | 否 | 地区 |
| address | 否 | 地址 |

示例：
```csv
customer_id,name,phone,email,region,address
C001,张三,13800138001,zhangsan@example.com,北京朝阳区,北京市朝阳区建国路88号
C002,李四,13800138002,lisi@example.com,上海浦东区,上海市浦东新区世纪大道100号
```

#### 2. 订单数据 (orders.csv)

| 字段 | 必填 | 说明 |
|------|------|------|
| order_id / id | 是 | 订单唯一标识 |
| customer_id | 否 | 关联客户ID |
| product_name | 是 | 产品名称 |
| category | 否 | 产品分类 |
| purchase_date | 否 | 购买日期 |
| status | 否 | 订单状态 |

示例：
```csv
order_id,customer_id,product_name,category,purchase_date,status
O001,C001,美的智能电饭煲,厨房电器,2024-01-15,active
O002,C002,海尔滚筒洗衣机,大家电,2024-01-20,active
```

#### 3. 分类标签 (taxonomy.json)

用于自定义问题分类和关键词，格式如下：

```json
{
  "categories": [
    {
      "code": "install_misunderstand",
      "name": "安装误解",
      "keywords": "安装,不会装,看不懂说明书,安装说明,怎么装",
      "description": "客户对安装步骤不理解"
    },
    {
      "code": "parts_shortage",
      "name": "配件缺货",
      "keywords": "缺货,没货,配件,零件,缺少,缺件",
      "description": "配件或零件缺货"
    }
  ]
}
```

#### 4. 通话纪要 (call-notes.csv)

| 字段 | 必填 | 说明 |
|------|------|------|
| call_id / id | 是 | 通话唯一标识 |
| customer_id | 否 | 客户ID |
| order_id | 否 | 订单号 |
| call_time / time | 否 | 通话时间 |
| agent_name / agent | 否 | 客服姓名 |
| product_category | 否 | 产品分类 |
| region | 否 | 地区 |
| raw_text / notes / content | 是 | 通话纪要内容 |

示例：
```csv
call_id,customer_id,order_id,call_time,agent_name,product_category,region,raw_text
CALL001,C001,O001,2024-03-01 09:30:00,王小明,厨房电器,北京朝阳区,客户张三打电话来咨询美的智能电饭煲的安装问题。他说收到货后按照说明书操作，但还是不会装。我已经详细解释了安装步骤，说明天会安排师傅上门指导安装。
```

### 导入顺序建议

1. **客户数据** → 建立客户基础信息
2. **订单数据** → 建立订单与客户的关联
3. **分类标签**（可选）→ 自定义问题分类
4. **通话纪要** → 导入核心数据，系统自动进行归因和承诺提取

### 异常处理

系统对以下异常情况会给出警告或错误提示：

| 异常类型 | 处理方式 | 提示级别 |
|----------|----------|----------|
| 缺少必填字段 | 使用默认值或跳过该行 | 警告 |
| 客户ID不存在 | 订单和通话仍可导入，但标记警告 | 警告 |
| 订单号不存在 | 通话仍可导入，但标记警告 | 警告 |
| 日期格式无效 | 支持多种格式，无法解析时给出警告 | 警告 |
| ID重复 | 更新现有记录而非跳过 | 警告 |
| 文件格式错误 | 拒绝导入 | 错误 |

支持的日期格式：
- `YYYY-MM-DD` / `YYYY/MM/DD`
- `DD/MM/YYYY` / `MM/DD/YYYY`
- `YYYY-MM-DD HH:mm:ss`
- JavaScript Date 可解析的格式

## 智能归因机制

### 关键词匹配算法

系统使用基于关键词的匹配算法进行归因：

1. **文本清洗**
   - 移除特殊字符、换行符、制表符
   - 标准化空格
   - 过滤非中文/英文/数字字符

2. **关键词提取**
   - 按双字词切分
   - 过滤停用词（的、了、是、在、我等）
   - 按词频排序

3. **分类匹配**
   - 对于每个预设分类，检查提取的关键词是否匹配分类的关键词
   - 计算匹配度 = 匹配关键词数 / 分类关键词数
   - 选择匹配度最高的分类

### 人工样本学习

当用户人工修改归因结果后：

1. 系统记录 `is_manual = 1`
2. 后续导入新数据时，会与历史人工样本进行相似度计算
3. 如果相似度 > 30%，会提升对应分类的置信度
4. 实现「越用越准」的效果

### 相似度计算

使用 Jaccard 相似度计算两个文本的相似程度：

```
相似度 = 交集关键词数 / 并集关键词数
```

### 承诺识别

使用正则表达式识别以下承诺类型：

| 承诺类型 | 识别模式 | 截止日期 |
|----------|----------|----------|
| 回电 | 明天/后天/下周 + 回电/打电话/联系/回复 | 1-7天 |
| 补寄配件 | 补寄/补发/寄/发/送 + 配件/零件/产品 | 3天 |
| 安排上门 | 安排/预约/约 + 师傅/安装/维修/上门 | 3天 |
| 退换货 | 退款/退钱/退货/换货 | 3天 |
| 后续跟进 | 下周/下个月/下一次/等通知 | 7天 |

优先级判定：
- 截止日期 <= 1天：高优先级 (high)
- 截止日期 2-3天：中优先级 (medium)
- 截止日期 > 3天：低优先级 (low)

## 常见问题

### Q: 数据存储在哪里？

所有数据都存储在本地 SQLite 数据库文件中，位于 `data/service_calls.db`。不会上传到任何服务器，完全本地运行。

### Q: 如何备份数据？

直接备份 `data/` 目录即可。数据库是单文件，可以直接复制。

### Q: 如何清空数据重新开始？

删除 `data/service_calls.db` 文件，重启服务后会重新创建空数据库。

### Q: 人工修改归因后，什么时候会影响新数据？

立即生效。每次导入新数据时，系统都会查询所有 `is_manual = 1` 的记录作为样本进行相似度匹配。

### Q: 支持哪些日期格式？

系统支持多种常见日期格式：
- ISO 格式：`2024-03-15`、`2024/03/15`
- 欧美格式：`03/15/2024`、`15/03/2024`
- 带时间：`2024-03-15 14:30:00`
- JavaScript Date 可解析的任何格式

如果日期格式无法解析，系统会给出警告但仍会导入记录，只是日期字段为空。

### Q: 承诺的截止日期是怎么计算的？

根据承诺类型和上下文推断：
- "明天回电" → 1天后
- "后天回电" → 2天后  
- "3天内" → 3天后
- "下周" → 7天后

如果通话记录中有明确的通话时间，则从通话时间开始计算；否则从当前时间开始计算。
