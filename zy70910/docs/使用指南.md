## 1. 系统概述

新能源对账服务是用于处理充电桩订单与支付数据核对的专业工具，能够自动检测以下异常：

- **未扣费异常**: 有充电记录但无支付记录
- **重复退款异常**: 同一订单存在多次退款
- **跨平台订单异常**: 订单来源与支付渠道不一致
- **金额不匹配异常**: 订单金额与支付金额不符
- **时间不匹配异常**: 充电结束与支付时间差异过大
- **状态不匹配异常**: 订单状态与支付状态不一致

## 2. 如何导入数据

### 2.1 数据准备

在导入数据前，请确保您已准备好以下文件：

| 文件类型 | 格式 | 说明 |
|----------|------|------|
| 订单数据 | CSV | 包含所有充电订单信息 |
| 桩端日志 | JSON | 充电桩记录的充电过程日志 |
| 支付记录 | CSV/JSON | 第三方支付平台的支付明细 |

### 2.2 导入步骤

**步骤1: 导入订单数据**

使用 API 接口导入订单CSV文件：

```bash
curl -X POST http://localhost:3000/api/v1/import/orders/csv \
  -F "file=@订单数据.csv"
```

**注意事项：**
- CSV文件必须包含以下列：`order_id`, `user_id`, `charger_id`, `start_time`, `end_time`, `charge_amount`, `amount`, `status`, `platform_source`
- 时间格式请使用 ISO 8601 格式（如：2024-01-01T08:00:00Z）
- 金额单位为元，保留两位小数

**步骤2: 导入桩端日志**

```bash
curl -X POST http://localhost:3000/api/v1/import/charger-logs/json \
  -F "file=@桩端日志.json"
```

**注意事项：**
- 请确保 JSON 格式正确
- 每条日志必须包含 `log_id`, `charger_id`, `event_time`, `event_type` 等字段
- `event_type` 应为 `CHARGE_START` 或 `CHARGE_END`

**步骤3: 导入支付记录**

```bash
curl -X POST http://localhost:3000/api/v1/import/payment-records \
  -F "file=@支付记录.csv"
```

**注意事项：**
- 支持 CSV 和 JSON 两种格式
- 必须包含 `payment_id`, `order_id`, `payment_time`, `amount`, `payment_status` 等字段

### 2.3 导入结果验证

导入成功后，系统会返回：
- `traceId`: 本次导入的追踪ID，用于问题排查
- `successCount`: 成功导入的记录数量
- `results`: 每条记录的详细导入结果

如遇导入失败，请检查：
1. 文件编码是否为 UTF-8
2. 必填字段是否完整
3. 数据格式是否符合要求

## 3. 如何发起对账

### 3.1 创建对账任务

**接口地址**: `POST /api/v1/reconciliation/tasks`

**请求示例**:
```bash
curl -X POST http://localhost:3000/api/v1/reconciliation/tasks \
  -H "Content-Type: application/json" \
  -d '{
    "name": "2024年1月第一周对账",
    "startDate": "2024-01-01",
    "endDate": "2024-01-07"
  }'
```

**参数说明**:
- `name`: 任务名称，建议包含时间范围和对账类型
- `startDate`: 对账开始日期（YYYY-MM-DD）
- `endDate`: 对账结束日期（YYYY-MM-DD）

### 3.2 执行对账任务

创建任务后，执行对账：

```bash
curl -X POST http://localhost:3000/api/v1/reconciliation/tasks/{任务ID}/execute
```

系统将自动进行以下核对：
1. 订单与支付记录匹配
2. 订单与桩端日志匹配
3. 检测各类异常差异
4. 生成差异报告

### 3.3 查看对账状态

可通过以下接口查看任务状态：

```bash
curl http://localhost:3000/api/v1/reconciliation/tasks/{任务ID}
```

**状态说明**:
- `PENDING`: 待执行
- `PROCESSING`: 处理中
- `COMPLETED`: 已完成
- `FAILED`: 执行失败

## 4. 如何查看差异和解释

### 4.1 获取差异列表

```bash
curl "http://localhost:3000/api/v1/discrepancies?taskId={任务ID}"
```

**可筛选条件**:
- `status`: 按状态筛选（PENDING/APPROVED/REJECTED/INFO_REQUESTED）
- `type`: 按差异类型筛选

### 4.2 差异类型详解

| 类型 | 严重程度 | 说明 | 典型场景 |
|------|----------|------|----------|
| **UNDEDUCTED** | 高 | 有充电记录但无支付 | 用户支付失败、网络中断导致 |
| **DUPLICATE_REFUND** | 极高 | 多次退款 | 系统bug、人工操作失误 |
| **CROSS_PLATFORM** | 中 | 平台不匹配 | 用户跨平台操作、渠道转接 |
| **AMOUNT_MISMATCH** | 高 | 金额不一致 | 手续费、优惠活动、计费错误 |
| **TIME_MISMATCH** | 低 | 时间差异大 | 支付延迟、异步通知 |
| **STATUS_MISMATCH** | 中 | 状态不一致 | 状态流转异常、数据同步延迟 |

### 4.3 查看差异详情

```bash
curl http://localhost:3000/api/v1/discrepancies/{差异ID}
```

系统返回字段说明：
- `typeName`: 差异类型中文名称
- `severity`: 严重程度（高/中/低）
- `explanation`: 差异原因说明
- `recommendedAction`: 建议处理措施

**示例说明**:
> 【未扣费异常】
> 解释：该订单存在已完成的充电记录，但系统中没有对应的支付记录。
> 建议：请核查支付状态，如确实未扣费，建议联系用户补扣或走坏账处理流程。

## 5. 如何进行复核操作

### 5.1 复核流程

1. 查看差异详情和系统解释
2. 核实原始数据（订单、支付、日志）
3. 根据实际情况作出复核决定
4. 填写复核备注（必填）
5. 提交复核结果

### 5.2 通过差异（确认异常）

当确认差异为真实异常时，执行通过操作：

```bash
curl -X POST http://localhost:3000/api/v1/review/discrepancies/{差异ID}/approve \
  -H "Content-Type: application/json" \
  -d '{
    "operator": "客服张三",
    "remark": "已联系用户，确认未支付，将进行补扣处理"
  }'
```

**适用场景**:
- 确实存在未扣费情况
- 重复退款属实
- 金额计算错误确认
- 状态异常需要修复

**备注填写规范**:
- 说明核实的方式（电话/系统查询/第三方核实）
- 描述核实的结果
- 说明后续处理措施

### 5.3 驳回差异（误报）

当差异为系统误报时，执行驳回操作：

```bash
curl -X POST http://localhost:3000/api/v1/review/discrepancies/{差异ID}/reject \
  -H "Content-Type: application/json" \
  -d '{
    "operator": "客服李四",
    "remark": "经查实为支付延迟，T+1到账，交易已完成"
  }'
```

**适用场景**:
- 支付延迟到账
- 数据同步滞后
- 正常业务流程导致的表面差异
- 系统规则未覆盖的特殊情况

**备注填写规范**:
- 说明驳回的具体原因
- 提供证据来源（如：支付平台查询记录截图）
- 说明为何属于正常情况

### 5.4 请求补充信息

当信息不足无法判断时，申请补充信息：

```bash
curl -X POST http://localhost:3000/api/v1/review/discrepancies/{差异ID}/request-info \
  -H "Content-Type: application/json" \
  -d '{
    "operator": "客服王五",
    "remark": "请提供该订单的用户支付截图和充电桩现场照片"
  }'
```

**适用场景**:
- 需要用户提供支付凭证
- 需要技术部门提供日志
- 需要现场人员核实情况

### 5.5 查看复核历史

```bash
curl http://localhost:3000/api/v1/review/discrepancies/{差异ID}/history
```

返回信息包含：
- 所有操作记录（通过/驳回/申请信息）
- 操作人
- 操作时间
- 状态变更轨迹
- 每一步的备注说明

## 6. 如何下载报告

### 6.1 生成报告

对账完成后，生成对账报告：

```bash
curl -X POST http://localhost:3000/api/v1/reports/{任务ID}/generate \
  -H "Content-Type: application/json" \
  -d '{
    "format": "excel"
  }'
```

**支持格式**:
- `excel`: Excel格式（.xlsx），推荐用于数据分析
- `pdf`: PDF格式，推荐用于存档和打印

### 6.2 下载报告

获取报告下载链接后，执行下载：

```bash
curl -O http://localhost:3000/api/v1/reports/{报告ID}/download
```

### 6.3 报告内容说明

Excel报告包含以下工作表：

| 工作表 | 内容说明 |
|--------|----------|
| 对账概览 | 统计汇总、差异数量、完成率等 |
| 差异明细 | 所有差异记录及状态 |
| 未扣费异常 | 未扣费订单详情 |
| 重复退款异常 | 重复退款订单详情 |
| 金额不匹配 | 金额差异对比 |
| 复核记录 | 所有复核操作日志 |

## 7. 如何向他人说明处理理由

### 7.1 向用户解释

**模板1 - 未扣费补扣**
> 尊敬的用户，您好！
>
> 关于您于 2024年1月1日 在 A001号充电桩 的充电订单（订单号：ORD_20240101_001），
> 经系统对账发现当时由于网络原因未能成功扣费。
>
> 充电明细：
> - 充电时长：1小时30分钟
> - 充电电量：45.5度
> - 应扣金额：68.25元
>
> 我们将进行补扣操作，给您带来的不便深表歉意，感谢您的理解与支持！

**模板2 - 重复退款致歉**
> 尊敬的用户，您好！
>
> 非常抱歉通知您，由于系统故障，您的一笔退款（订单号：ORD_20240101_007）被重复处理。
>
> 明细如下：
> - 原支付金额：93.00元
> - 应退款金额：93.00元
> - 实际退款：186.00元（多退93.00元）
>
> 为方便您操作，我们已通过短信发送了补款链接，您也可联系客服协助处理。
> 再次为我们的失误向您诚挚道歉！

### 7.2 向上级汇报

**汇报要点**:
1. **差异概况**: 共发现X条差异，其中高风险Y条
2. **处理进度**: 已复核Z条，通过A条，驳回B条
3. **典型案例**:
   - 案例1：未扣费异常，已联系用户补扣
   - 案例2：重复退款，正在与用户协商退回
4. **问题总结**: 本次对账暴露的系统问题和改进建议
5. **下一步计划**: 后续处理安排

### 7.3 向技术部门反馈

**反馈模板**:
> 【问题反馈】对账系统异常
>
> 问题描述：
> 在 2024年1月 对账中，发现 X 笔订单存在跨平台支付异常。
>
> 具体现象：
> 订单 platform_source 为 alipay，但实际支付渠道为 wechat。
>
> 影响范围：
> 涉及订单 5 笔，总金额 320.50 元。
>
> 建议排查方向：
> 1. 订单创建时的平台标识逻辑
> 2. 支付回调的渠道映射关系
> 3. 是否存在渠道切换场景
>
> 附件：差异订单列表.xlsx

## 附录：常见问题FAQ

**Q1: 对账需要多长时间？**
A: 根据数据量大小，通常1-5分钟。数据量超过10万条时可能需要更长时间。

**Q2: 可以重复执行对账吗？**
A: 可以。但建议在导入新数据后再重新执行，避免重复劳动。

**Q3: 复核后发现判断错误怎么办？**
A: 可以再次进行复核操作，系统会记录完整的变更历史。

**Q4: 报告可以自定义格式吗？**
A: 当前版本支持Excel和PDF格式，如有特殊需求请联系技术部门。

**Q5: 数据导入失败如何处理？**
A: 请检查：1）文件格式 2）编码格式（建议UTF-8）3）必填字段是否完整。如仍有问题请联系技术支持。
