## 一、为什么需要这套机制？

原先前台小温人工兜底时出现过三类问题：

| 现象 | 本系统如何解决 |
|------|---------------|
| 主人微信备注字段名前后不一（主人留言/主人补充说明/客户留言…） | **字段别名映射表** 登记所有别名，导入时按映射匹配到标准字段「主人微信备注」，并在主表 **微信备注原始字段名** 列保留来源 |
| 重复导入同一份 Excel 导致记录翻倍 | 主表自带公式字段 **唯一去重键 = 宠物姓名 + 主人姓名 + 上课日期(YYYYMMDD)**；导入脚本命中相同键直接跳过 |
| 重复导入覆盖了主管手工写的微信备注 | 主表 **人工备注保护标记(checkbox)** 勾选后，导入脚本在 `UPDATE` 阶段跳过「主人微信备注」这一列，**保留旧值不被覆盖** |
| 疫苗日期缺失但不知道哪批受影响 | **异常记录表** 的「人工确认理由」+「影响范围」两个字段让你把判断依据和波及范围都写下来，不会因为下次再导就丢 |

## 二、四张表与核心字段（速查）

### 1. 宠物训练课报告主表（tblUcXaYYXNDsKfP）

关键字段：

| 字段 | 类型 | 作用 |
|------|------|------|
| 报告编号 | auto_number | 自动递增主键，形如 RPT-000001 |
| 宠物姓名 / 主人姓名 / 上课日期 | 文本 + 日期 | **组成唯一去重键的三要素** |
| 主人微信备注 | 文本 | 实际业务字段，可能被手工覆盖 |
| 微信备注原始字段名 | 文本 | 记录运营主管本次导入用的别名（主人留言/客户留言…），用于追溯 |
| 人工备注保护标记 | 复选框 | ☑️ 勾选 = 下次导入时本记录的「主人微信备注」列**禁止覆盖** |
| 数据来源 | 单选 | 系统导入 / 人工录入 / 微信同步 / 历史迁移 —— 保住「来源」 |
| 处理状态 | 单选 | 已处理 / 待补材料 / 人工改判 —— 保住「处理状态」，也是视图筛选依据 |
| 疫苗接种日期 | 日期 | 为空时「疫苗缺失标记」会变为 "缺失" |
| 唯一去重键 | 公式 | `CONCATENATE(宠物姓名, "_", 主人姓名, "_", TEXT(上课日期, "YYYYMMDD"))`，**不可手工修改** |
| 疫苗缺失标记 | 公式 | `IF(ISBLANK(疫苗接种日期), "缺失", "正常")`，**不可手工修改** |

### 2. 导入日志表（tblLlcdq3ozZ74Ix）

每次导入必须写一条记录，便于回溯：

- 导入批次号、文件名、导入时间、导入人
- **新增条数 / 跳过重复条数 / 人工备注保护条数 / 异常条数** 四个计数器
- 导入状态（已完成/部分完成/失败）+ 备注说明

### 3. 异常记录表（tblx2Y63lE047DWV）

所有异常必须进此表，不能只在导入日志里写一句话。要求字段：

| 字段 | 必须填写吗？ | 说明 |
|------|------------|------|
| 异常类型 | ✅ | 疫苗日期缺失 / 微信备注冲突 / 字段名不一致 / 数据不一致 / 其他异常 |
| 关联报告编号 + 关联宠物姓名 | ✅ | 能跳回主表 |
| 人工确认理由 | ✅（疫苗缺失时） | 你是凭什么判断的？主人电话？医院系统？ |
| 影响范围 | ✅（疫苗缺失时） | 这个异常波及了哪些课/哪些报告？ |
| 来源材料链接 | ✅ | 跳回原始 Excel、微信截图、飞书文档 URL，**异常点要能一路点回材料** |
| 处理状态 | ✅ | 待确认 / 已确认 / 已忽略 / 已修复 |

### 4. 字段别名映射表（tbl6S3Xe2UyouFAh）

当运营主管的 Excel 列名和系统标准字段名不一致时，**先在此表登记映射**，再导入：

| 标准字段名 | 运营主管使用的别名 | 使用场景说明 | 是否启用 |
|-----------|-----------------|------------|---------|
| 主人微信备注 | 主人留言 | 运营3月起开始使用此别名 | ☑️ |
| 主人微信备注 | 主人补充说明 | 交接时写的习惯叫法 | ☑️ |
| 主人微信备注 | 客户留言 | 某周临时导出用的名字 | ☑️ |
| 疫苗接种日期 | 疫苗有效期 | 主管偶尔会把日期写成有效日期 | ☐ |
| 宠物姓名 | 犬猫名 | 和门诊系统统一的叫法 | ☑️ |
| 上课日期 | 训练当日日期 | 新手运营容易写错字段名 | ☑️ |

## 三、标准导入流程（6 步，防坑）

### Step 1：检查字段别名映射表
- 打开「字段别名映射表」→ 切换到 **已启用映射** 视图
- 确认本次 Excel 的列名都能匹配到标准字段名
- 找不到？新增一条映射并勾选启用

### Step 2：准备 Excel，3 列必填
- **宠物姓名、主人姓名、上课日期** 三列绝对不能空（唯一去重键依赖它们）
- 「主人微信备注」这一列的列名可以是任何别名，但**只能有一列**（多列时以第一条匹配的映射为准）

### Step 3：首次导入
- 本目录提供可执行导入器 `import_training_reports.py`，会对每条记录生成 `唯一去重键`，在当前结果文件里查是否存在
- 不存在 → 插入新记录，**处理状态默认为「已处理」**
- 命中的「主人微信备注」列名不是标准名 → 在「微信备注原始字段名」里把原始列名写下来，然后在异常记录表登记一条 **字段名不一致**

本地验证命令：

```bash
cd /Users/maca/pro/solo/workspaces/zy73033
./import_training_reports.py reset
./import_training_reports.py run --input data_main_records.json --file-name 训练课_2025年4月第1批.json
```

导入结果会写入：

| 文件 | 内容 |
|------|------|
| `output/main_records.json` | 主表导入后的真实状态，含报告编号、唯一去重键、疫苗缺失标记 |
| `output/import_logs.json` | 每次导入的新增、重复、保护、异常计数 |
| `output/exceptions.json` | 字段名不一致、疫苗缺失、微信备注冲突等异常 |
| `output/复核明细.csv` | 给运营主管查看或转交的 CSV 明细 |

### Step 4：疫苗缺失检测（插入后）
- 插入完成后扫一遍本批次所有新记录的「疫苗缺失标记」
- 标记 = "缺失" → 在**异常记录表**登记：
  - 异常类型 = 疫苗日期缺失
  - **人工确认理由**：写清楚「主人说」「医院病历系统查得」「未提供」等
  - **影响范围**：如「仅本次课程报告；下次上课前补即可」「需补签疫苗免责书」
  - 来源材料链接：贴疫苗卡照片/微信截图的 URL
  - 处理状态 = 待确认
- 主表记录的「处理状态」改成 **待补材料**

### Step 5：重复导入（⚠️ 关键步骤）
重复导入指的是同一份 Excel 再次上传，命中了同一个「唯一去重键」。此时分两种情况：

**情况 A：主表记录的 人工备注保护标记 = 未勾选**
- 除「报告编号、唯一去重键、疫苗缺失标记、创建时间/人」4 类不可写字段外，其余字段整体覆盖（来源和处理状态会被更新）
- 导入日志的「跳过重复条数」+ 1

**情况 B：主表记录的 人工备注保护标记 = ☑️ 已勾选**
- **只跳过「主人微信备注」这一列**，其他列仍按 A 规则覆盖
- 导入日志的「人工备注保护条数」+ 1
- 在异常记录表登记一条 **微信备注冲突**，来源材料链接指向本次 Excel

> 💡 **怎么勾选人工备注保护标记？**
> 每次手工在主表修改了「主人微信备注」列（比如主管写了改判说明），请**务必顺手勾上同一行的「人工备注保护标记」**。否则下次导入会把你写的话覆盖掉。

可执行的重复导入验证：

```bash
cd /Users/maca/pro/solo/workspaces/zy73033
./import_training_reports.py reset
./import_training_reports.py run --input data_main_records.json --file-name 训练课_2025年4月第1批.json
./import_training_reports.py protect-note --pet 团子 --owner 陈月 --date 2025-04-06 --note "主管手写：原记录漏填课后作业，已电话确认并改判，重复导入不得覆盖"
./import_training_reports.py run --input data_repeat_records.json --file-name 训练课_2025年4月第1批_重复导入验证.json
```

验证口径：

| 目标 | 应看到的结果 |
|------|--------------|
| 正常记录别翻倍 | `output/main_records.json` 仍为 7 条主表记录 |
| 重复导入走更新链路 | `output/import_logs.json` 最后一条显示新增 0、跳过重复 2 |
| 人工备注不被覆盖 | 团子的「主人微信备注」仍是 `protect-note` 写入的主管手写内容 |
| 保护事件有留痕 | 最后一条导入日志「人工备注保护条数」为 1，`output/exceptions.json` 新增「微信备注冲突」 |

### Step 6：写导入日志 + 查仪表盘
- 在「导入日志表」填一条记录，4 个计数器必须如实填
- 切到「运营主管驾驶舱」仪表盘看一眼：
  - 处理状态分布环图 → 待补材料是不是突然多了？
  - 异常类型分布饼图 → 疫苗缺失是不是又有新增？
  - 待补材料指标卡 → 点一下数字会跳去「待补材料」视图

## 四、重复导入自测清单（你在需求里说的所有场景）

| 测试点 | 期望结果 | 验证方式 |
|--------|---------|---------|
| 同一份 Excel 重复导入两次 | 第二次 0 新增、N 跳过，记录总数不变（不翻倍） | 主表 → 全部记录视图，按报告编号数一遍 |
| 第 1 次导入后勾选某条「人工备注保护标记」，修改「主人微信备注」；再导一次同文件 | 该条的「主人微信备注」保留你手工改的文字，**不被覆盖** | 主表 → 人工改判视图，看团子那条 |
| 疫苗日期为空 | 自动标「疫苗缺失标记=缺失」，处理状态=待补材料，异常表多出一条记录 | 异常表 → 疫苗日期缺失视图 |
| 字段名用了「主人留言」而非标准「主人微信备注」 | 主表「微信备注原始字段名」列记录「主人留言」，异常表登记字段名不一致 | 异常表 → 字段名不一致视图 |
| 主管手工改判某条记录的处理状态 | 下次导入时处理状态列仍会被覆盖（除非在脚本里加入更多保护列）；建议走「人工改判」视图后**只改备注列和勾保护标记**，不要直接改其他列 | 导入日志「备注说明」字段里说明 |

## 五、异常追溯链路（图表 → 明细 → 材料）

```
运营主管驾驶舱（异常类型分布饼图 / 待补材料指标卡）
     ↓ 点击数字或图例
对应筛选视图（例如：异常表 → 待确认异常 视图）
     ↓ 打开一条异常记录
   ① 关联报告编号（可跳主表对应行）
   ② 人工确认理由 + 影响范围（已写好判断依据）
   ③ 来源材料链接（一键打开微信截图/原始Excel）
     ↓
主表对应行 → 「数据来源」知道是哪来的，「处理状态」知道当前阶段
```
