# 少儿体操积分赛 - 赛后复核工具

一个用于少儿体操积分赛赛后复核的本地数据分析与可视化工具，支持数据导入、对齐、分析、可视化和导出。

## 功能特性

### 📊 核心功能
- **数据导入**：支持 CSV 和 JSON 格式数据导入
- **自动对齐**：按运动员、项目、动作段智能对齐所有数据
- **差异检测**：自动检测裁判分数差异、难度组别问题
- **申诉分析**：匹配申诉与分数问题，检测重复申诉
- **排名影响**：分析申诉成功可能带来的排名变化

### 🎨 可视化界面
- **概览仪表板**：关键指标一目了然（高优先级问题、申诉统计、风险等级）
- **成绩差异分析**：详细展示裁判分差、异常值标注
- **申诉分析面板**：潜在命中申诉高亮、复核状态管理
- **排名影响分析**：当前排名展示、风险预警、申诉影响预测
- **数据浏览**：运动员信息、项目成绩、动作段详情

### 📝 复核与导出
- **人工复核**：支持复核备注保存到本地存储
- **Markdown 导出**：生成完整的复核报告
- **JSON 导出**：导出审计明细数据

## 验证流程

### 第一步：加载数据

工具提供两种数据加载方式：

#### 方式 A：使用示例数据（推荐用于测试）
1. 启动工具后，点击「加载示例数据」按钮
2. 系统会自动加载预设的示例数据（包含5名运动员、多个项目、申诉记录）

#### 方式 B：导入自定义数据
1. 准备以下数据文件（至少需要**运动员信息**和**裁判分数**）：
   - `athletes.json` - 运动员基本信息
   - `judge_scores.csv` - 裁判打分记录
   - `difficulty_declaration.json` - 难度申报数据（可选）
   - `video_timecodes.json` - 视频时间码（可选）
   - `appeals.json` - 申诉记录（可选）

2. 拖拽文件到上传区域，或点击选择文件
3. 确认文件类型识别正确后，点击「处理数据」

---

### 第二步：查看概览

数据加载完成后，顶部会显示4个关键指标：

| 指标 | 说明 |
|------|------|
| 运动员总数 | 参赛运动员数量和队伍数 |
| 高优先级问题 | 检测到的严重问题数（高/中/低等级） |
| 申诉统计 | 总申诉数、潜在命中数、重复申诉数 |
| 风险等级 | 综合评估（高/中/低风险） |

---

### 第三步：分析成绩差异

切换到「成绩差异」标签页：

1. **问题列表**：按严重程度排序的问题列表
   - 高优先级（红色）：分差超过阈值2倍
   - 中优先级（黄色）：分差超过阈值
   - 低优先级（蓝色）：分差接近阈值

2. **展开详情**：点击任意问题卡片展开查看
   - 裁判打分明细表
   - 统计分析（最高分、最低分、分差、方差）
   - 相关申诉（如果有）

3. **异常值识别**：表格中红色标注的是偏离平均值超过5%的分数

---

### 第四步：处理申诉

切换到「申诉分析」标签页：

1. **顶部统计**：
   - 总申诉数
   - 潜在命中（与分数问题关联的申诉）
   - 重复申诉（同一段动作多次申诉）

2. **重复申诉检测**：
   - 已标记重复的申诉会高亮显示
   - 显示原始申诉和重复申诉的关联关系

3. **潜在命中申诉**：
   - 展开查看申诉详情、命中原因
   - 填写复核状态（待复核/复核中/已解决/已驳回）
   - 填写复核决定（支持申诉/部分支持/驳回申诉）
   - 保存复核备注（自动保存到本地存储）

4. **待复核申诉**：未与分数问题关联的申诉列表

---

### 第五步：排名影响分析

切换到「排名影响」标签页：

1. **当前排名表**：
   - 显示完整排名
   - 与上一名的分差（红色标注分差<0.2，黄色标注分差<0.5）
   - 有申诉的运动员行背景色标注

2. **排名风险预警**：
   - 分差较小的运动员对会高亮显示
   - 高风险（红色）：分差<0.2
   - 中风险（黄色）：分差<0.5

3. **申诉可能带来的排名变化**：
   - 显示可能加分的运动员
   - 计算潜在总分
   - 预测可能超越的运动员

---

### 第六步：数据浏览

切换到「数据浏览」标签页：

1. **运动员列表**：
   - 支持按姓名或队伍搜索
   - 显示排名、总分、申诉数
   - 点击「查看详情」查看完整数据

2. **运动员详情**：
   - 各项目成绩（难度分、执行分、扣分、总分）
   - 动作段详情（时间码、难度等级、相关申诉）

---

### 第七步：导出复核报告

点击页面右上角的导出按钮：

#### 导出 Markdown 复核单
- 生成完整的复核报告
- 包含：
  - 基本信息和复核概览
  - 裁判分数差异分析
  - 难度组别问题分析
  - 申诉分析（潜在命中、待复核、重复申诉）
  - 排名影响分析
  - 复核结论与建议
  - 数据来源和工具信息

#### 导出 JSON 审计明细
- 导出完整的审计数据
- 包含：
  - 对齐后的数据快照
  - 分析结果（分数差异、申诉分析、排名影响）
  - 复核记录
  - 审计追踪

## 数据格式说明

### 1. 运动员信息 (athletes.json)

```json
{
  "competition": {
    "name": "赛事名称",
    "category": "组别",
    "date": "2024-06-15",
    "location": "地点"
  },
  "athletes": [
    {
      "id": "A001",
      "name": "运动员姓名",
      "age": 10,
      "team": "队伍名称",
      "events": ["自由操", "跳马", "高低杠", "平衡木"]
    }
  ]
}
```

### 2. 裁判分数 (judge_scores.csv)

| 字段 | 类型 | 说明 |
|------|------|------|
| athlete_id | string | 运动员ID |
| athlete_name | string | 运动员姓名 |
| event | string | 项目名称 |
| judge_id | string | 裁判ID |
| difficulty_score | number | 难度分 |
| execution_score | number | 执行分 |
| penalty_score | number | 扣分 |
| total_score | number | 总分 |

示例：
```csv
athlete_id,athlete_name,event,judge_id,difficulty_score,execution_score,penalty_score,total_score
A001,李小雅,自由操,J01,3.20,8.50,0.00,11.70
A001,李小雅,自由操,J02,3.20,8.45,0.00,11.65
```

### 3. 难度申报 (difficulty_declaration.json)

```json
{
  "declarations": [
    {
      "athlete_id": "A001",
      "athlete_name": "李小雅",
      "event": "自由操",
      "segments": [
        {
          "segment_number": 1,
          "declared_difficulty": "C",
          "declared_value": 0.3,
          "description": "前手翻",
          "start_time": "00:15",
          "end_time": "00:22"
        }
      ]
    }
  ]
}
```

### 4. 视频时间码 (video_timecodes.json)

```json
{
  "videos": [
    {
      "video_id": "V001",
      "athlete_id": "A001",
      "athlete_name": "李小雅",
      "event": "自由操",
      "duration": "01:30",
      "timecodes": [
        {
          "start": "00:15",
          "end": "00:22",
          "segment_description": "前手翻",
          "notes": "动作完成流畅"
        }
      ]
    }
  ]
}
```

### 5. 申诉记录 (appeals.json)

```json
{
  "appeals": [
    {
      "appeal_id": "AP001",
      "athlete_id": "A001",
      "athlete_name": "李小雅",
      "event": "跳马",
      "submit_time": "2024-06-15 16:30",
      "submitter": "张三（教练）",
      "status": "待复核",
      "timecodes": {
        "start": "00:12",
        "end": "00:20"
      },
      "complaint": "申诉内容...",
      "related_segment": 2,
      "segment_description": "动作描述",
      "evidence": "证据说明",
      "review_status": "未处理",
      "review_notes": "",
      "is_duplicate": false,
      "original_appeal_id": null
    }
  ]
}
```

## 本地存储说明

工具使用浏览器的 localStorage 存储复核记录：

- **存储键名**: `gymnastics_review_notes`
- **存储内容**: 所有复核备注（申诉复核、问题复核、运动员备注）
- **数据持久化**: 刷新页面后数据不会丢失
- **清除数据**: 可通过浏览器开发者工具清除，或使用 `ReviewService.clearAllReviews()`

## 常见问题

### Q1: 数据导入后没有显示？
A: 请检查以下几点：
- 至少需要导入 **运动员信息** 和 **裁判分数** 两个文件
- 确保文件格式正确（CSV 或 JSON）
- 检查文件名是否包含关键词（如 "athlete"、"score" 等）

### Q2: 如何让工具正确识别数据类型？
A: 工具通过以下方式识别：
1. 文件名包含关键词（如 "运动员"、"裁判"、"难度"、"申诉" 等）
2. 数据结构特征（如包含 `athletes` 数组的 JSON 被识别为运动员信息）
3. 可以手动修改文件名以确保正确识别

### Q3: 申诉为什么没有被标记为「潜在命中」？
A: 申诉被标记为潜在命中需要满足以下条件之一：
1. 申诉内容包含「难度」关键词，且存在难度分差异问题
2. 申诉内容包含「扣分」关键词，且存在扣分记录
3. 申诉与分数问题关联（同一运动员、同一项目）

### Q4: 如何检测重复申诉？
A: 工具通过以下方式检测：
1. `is_duplicate` 字段为 true（已标记）
2. 同一运动员、同一项目、时间码重叠
3. 针对同一段动作（related_segment 相同）

### Q5: 导出的文件在哪里？
A: 点击导出按钮后，文件会下载到浏览器的默认下载目录：
- Mac: 下载文件夹 (~/Downloads)
- Windows: 下载文件夹
- 可以通过浏览器的下载历史查看
