## 接口说明

### 1. 健康检查

```
GET /api/health
```

### 2. 获取默认规则

```
GET /api/rules
```

### 3. 批量处理审批

```
POST /api/approval/process
Content-Type: multipart/form-data

参数：
- batch_id: 批次号（唯一标识，重复提交会被拒绝）
- csv_file: 申请表CSV文件
- contracts_json: 合同元数据JSON文件
- rules_json: （可选）自定义规则JSON文件
```

## 结果字段说明

每条处理结果包含：

| 字段 | 说明 |
|------|------|
| record_id | 记录唯一标识（MD5哈希） |
| status | 处理状态：NORMAL/ NEED_CONFIRM/ FAILED |
| original_data | 原始申请数据（保留完整字段） |
| matched_rules | 匹配到的规则名称列表 |
| suggestion | 建议处理方式（法务可直接用于沟通） |
| explanation | 详细说明（解释为什么触发规则） |

## 自定义规则格式

如需使用自定义规则，创建 rules.json 并按以下格式：

```json
[
    {
        "rule_id": "CUSTOM001",
        "rule_name": "自定义规则",
        "rule_type": "custom",
        "condition": {
            "approval_level": {"$lt": 2},
            "amount": {"$gt": 500000}
        },
        "action": "REJECT",
        "suggestion": "自定义规则的建议处理方式"
    }
]
```

## 常见问题

**Q: 如何区分待确认和失败？**
- 失败(FAILED): 严重违规，直接拒绝，必须修正后重新提交
- 待确认(NEED_CONFIRM): 材料不全或需补充手续，确认后可放行
- 正常(NORMAL): 符合所有规则，可直接处理

**Q: 同一批材料再次提交会怎样？**
- 通过 batch_id 做幂等控制
- 重复提交直接返回400错误
- 需使用新的批次号重新提交

**Q: CSV字段可以扩展吗？**
- 可以，extra_fields 会自动收集未定义字段
- 规则引擎只需相应扩展 condition 判断即可
