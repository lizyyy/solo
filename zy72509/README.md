# 聊天机器人越权拦截知识库管理系统

## 快速开始（根目录执行）

### 1. 安装全部依赖
```bash
npm run install:all
```

### 2. 生成示例数据（可选）
```bash
npm run seed
```

### 3. 启动前后端（根目录一键启动）
```bash
npm run dev
```
- 后端接口: http://localhost:3001
- 前端页面: http://localhost:3000

### 4. 常用命令

| 命令 | 说明 |
|------|------|
| `npm run install:all` | 安装根目录+后端+前端全部依赖 |
| `npm run seed` | 生成示例测试数据 |
| `npm run dev` | 同时启动前后端开发服务 |
| `npm run dev:backend` | 仅启动后端（端口3001） |
| `npm run dev:frontend` | 仅启动前端（端口3000） |
| `npm run build` | 构建前端生产包 |
| `npm start` | 启动后端生产服务 |
| `npm run selfcheck:run` | 触发后端自检（需先启动后端） |
| `npm run export:run` | 导出Excel测试（需先启动后端） |

## 核心功能说明

### 三项最常见错口径处理

#### 1. 标注员留言 vs 模型输出 冲突检测
- 自动识别双方在"拦截/放行"判定上的关键词矛盾
- 列出冲突证据，不自动拍板
- 知识库编辑在「冲突处理中心」选择「确认」或「驳回」

#### 2. 补录返工（版本重算）
- 记录每次更新后版本号自动+1
- 版本>1且状态为待处理时，自检会提示「补录待重算」
- 明细、历史、导出均读取同一条最新记录

#### 3. 手机号脱敏与漏遮复核
- 导出Excel自动对手机号脱敏（138****5678）
- 用户问题、标注留言、模型输出中出现明文手机号 → 自检标记「手机号漏遮」（高危）
- 提供「算法复核」按钮，标记为 `need_algorithm_review` 状态，**不自动归为正常**

### 四项自检（自检中心）
| 自检项 | 严重程度 | 检查内容 |
|--------|----------|----------|
| 重复导入 | 中 | 同一会话ID存在多条记录 |
| 手机号漏遮 | 高 | 文本中存在未脱敏的11位手机号 |
| 补录待重算 | 中 | 记录更新（版本>1）后仍为待处理状态 |
| **导出一致** | 高 | ①同批次同手机号去重（防重传翻倍）②导出脱敏与页面展示一致 ③可从导出手机号追溯原始记录ID |

### 导出一致保障
- **去重口径**：导出时按「脱敏手机号」去重，同一批重传不会导致数量翻倍
- **数据溯源**：导出Excel包含「记录ID」「原始手机号后4位」「漏遮溯源位置」三列，可从追回触发导出一致的原始材料
- **单一数据源**：页面展示、接口返回、Excel导出 均调用 `records.getAll()` 读取同一份内存数据

## 完整三步验证流程（重点核对手机号）

### Step 1: 标注员留言第一次导入
```bash
npm run seed          # 生成示例数据（5条，含3条带手机号记录）
npm run dev           # 启动服务
```

### Step 2: 知识库编辑小乔补看模型输出片段
打开 http://localhost:3000 → 「标注记录管理」
- 点击「查看」核对标注员留言 + 模型输出
- 冲突记录（状态=存在冲突）→ 点「确认」或「驳回」
- 涉及手机号漏遮 → 点「算法复核」，不直接归正常

### Step 3: 脱敏导出更新 & 核对
1. 前端点「导出Excel」或执行 `npm run export:run`
2. 核对导出的Excel中：
   - 「手机号脱敏」列: 138****5678（已脱敏）
   - 「原始手机号后4位」: 用于溯源
   - 「记录ID」列: 可直接关联原始记录
   - 「是否存在手机号漏遮风险」: 标记需算法复核
3. 打开「自检中心」→ 点「执行自检」
   - 确认「导出一致」自检项已覆盖
   - 确认「手机号漏遮」自检项数量与导出中标记数量一致
