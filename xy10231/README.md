# 地铁失物招领匹配器

解决地铁失物描述和乘客报失文本口径不一、人工匹配效率低的问题。

## 安装运行

```bash
# 1. 安装依赖
npm run install:all

# 2. 启动服务（前后端同时运行）
npm run dev

# 3. 打开浏览器访问
# 前端: http://localhost:5173
# 后端: http://localhost:3001
```

**环境要求**：Node.js 18+

## 样例入口

1. 打开首页后，点击「加载示例」按钮
2. 系统会自动填充3组对应的数据：
   - 报失："今天上午8点半在1号线人民广场站丢了一个黑色的苹果手机..."
   - 招领："今天早上在1号线人民广场站发现一部黑色苹果手机..."
3. 点击「开始匹配处理」

## 核心操作

### 1. 数据导入
- 在「数据导入」页面输入 JSON 格式的失物/招领描述
- 每条记录至少需要 `description` 字段
- 可选字段：`finder`（捡拾人）

### 2. 匹配处理
系统自动执行：
- 文本清洗（提取物品分类、颜色、线路、站点、时间等特征）
- 特征匹配（多维度加权评分）
- 候选排序（按匹配分数从高到低）

### 3. 人工审核
- 在「人工审核」页面查看匹配候选
- 点击「查看详情」对比两侧描述
- 提交反馈：确认匹配 / 驳回 / 添加备注

### 4. 历史追踪
- 「历史记录」页面查看处理流程历史
- 追踪状态变更和操作人记录

## 如何检查结果

### 查看处理状态
- 页面顶部「处理流程状态」显示当前所在阶段
- 数据导入 → 文本清洗 → 特征提取 → 特征匹配 → 候选排序 → 人工审核

### 查看匹配质量
- 每条匹配显示分数（0-100）和置信度
- 80+ 高置信，50-80 中置信，<50 低置信
- 系统会给出处理建议

### 验证闭环
1. 确认一条匹配后，对应失物/招领状态变为「已匹配」
2. 统计面板数字实时更新
3. 变更日志记录操作历史
4. 重跑同一批数据时，重复数据不会重复入库

## 数据格式示例

**失物数据（乘客报失）**：
```json
[
  { "description": "今天上午在1号线人民广场站丢失黑色iPhone手机" }
]
```

**招领数据（失物招领）**：
```json
[
  { "description": "人民广场站捡到黑色苹果手机一部", "finder": "张师傅" }
]
```
