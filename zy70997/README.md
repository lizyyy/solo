# 工会福利券核销系统 - 本地运行说明

## 📋 项目简介

本系统用于解决工会福利发放中的核销混乱问题，支持节日福利券、线下领取和快递寄送三种场景的统一处理。

### 核心功能
- ✅ **离职拦截**：自动识别已离职员工，阻止其领取福利
- ✅ **重复领取检测**：同一员工同一福利类型只能领取一次
- ✅ **代领留痕**：代领场景需登记代领人信息，留痕可追溯
- ✅ **快递信息校验**：快递寄送需验证收货地址和联系电话
- ✅ **批次幂等性**：同一文件重复提交不会重复生效
- ✅ **详细可解释**：每条记录的放行/退回/待确认都有可读说明

## 🔧 核心接口

### 1. 导入员工数据

**接口**: `POST /import/employees`

**支持格式**: CSV / JSON

**CSV 字段示例**:
| employee_id | name | department | is_active |
|-------------|------|------------|-----------|
| E001        | 张三 | 技术部     | true      |
| E002        | 李四 | 市场部     | false     |

**说明**: `is_active` 为 `false/0/否/离职` 表示已离职。

### 2. 导入券码数据

**接口**: `POST /import/coupons`

**CSV 字段示例**:
| coupon_code | coupon_type     | value |
|-------------|-----------------|-------|
| C2024001    | 端午节礼品券   | 200元 |

### 3. 提交领用名单核销

**接口**: `POST /upload/process`

**CSV 字段说明**:

| 字段名            | 必填 | 说明                                                                 |
|-------------------|------|----------------------------------------------------------------------|
| employee_id       | 是   | 员工工号                                                             |
| employee_name     | 是   | 员工姓名                                                             |
| coupon_code       | 否   | 券码（券类福利必填）                                                 |
| claim_type        | 是   | 福利类型，如"端午节礼品券"                                           |
| is_proxy          | 否   | 是否代领，true/false                                                 |
| proxy_employee_id | 否   | 代领人工号（代领时必填）                                             |
| proxy_employee_name | 否 | 代领人姓名（代领时必填）                                             |
| delivery_method   | 否   | 领取方式：线下领取/快递                                              |
| address           | 否   | 收货地址（快递时必填）                                               |
| contact_phone     | 否   | 联系电话（快递时必填）                                               |

**响应格式**:
```json
{
  "batch_id": "BATCH-20240527120000-ABC12345",
  "total_count": 10,
  "success_count": 4,
  "pending_count": 2,
  "failed_count": 4,
  "success_items": [
    {
      "original_data": {...},
      "status": "success",
      "reason": "员工信息正常，端午节礼品券福利发放条件满足",
      "suggestion": "正常发放"
    }
  ],
  "pending_items": [...],
  "failed_items": [
    {
      "original_data": {...},
      "status": "failed",
      "reason": "员工 赵六 (E004) 已离职，状态为非在职",
      "suggestion": "请联系人事部门确认员工状态，或从本次名单中移除"
    }
  ]
}
```

### 4. 查询历史批次

**接口**: `GET /batches`

### 5. 查询批次详情

**接口**: `GET /batches/{batch_id}`

## 🎯 业务规则说明

### 🔴 直接失败（拦截）

1. **离职拦截**
   - 触发条件：员工 `is_active = false`
   - 说明：`员工 XXX (E00X) 已离职，状态为非在职`
   - 建议：请联系人事部门确认员工状态，或从本次名单中移除

2. **重复领取**
   - 触发条件：同一员工 + 同一福利类型已有发放记录
   - 说明：`员工 E00X 已领取过 端午节礼品券 福利。领取时间: 2024-05-20 10:00:00, 批次号: BATCH-XXX`
   - 建议：该员工已领取过此福利，无需重复发放

3. **券码无效**
   - 触发条件：券码不存在 / 已使用 / 类型不匹配
   - 说明：`券码 XXXX 已被 张三 于 2024-05-20 使用`
   - 建议：请核对券码有效性，或更换未使用的券码

### ⚡ 待确认（人工复核）

1. **代领留痕**
   - 触发条件：`is_proxy = true` 且代领人信息完整
   - 说明：`代领留痕: 由 李四 (E002) 代领`
   - 建议：信息完整，请人工确认后代为发放

2. **快递寄送**
   - 触发条件：`delivery_method = 快递` 且地址电话完整
   - 说明：`快递寄送: 北京市朝阳区XXX, 联系电话: 138XXXX0001`
   - 建议：信息完整，请人工确认后安排快递

### ✅ 正常通过

- 员工在职
- 未重复领取
- 券码有效（如有）
- 无需代领或快递

## 🔍 常见问题

**Q: 为什么同一份文件提交两次没有反应？**
A: 系统通过文件内容哈希实现幂等性，同一文件只会处理一次。如需重新处理，请修改文件内容（如添加备注列）或删除数据库重置。

**Q: 如何处理待确认的记录？**
A: `pending_items` 中的记录信息完整但需要人工操作（如代领需要核实、快递需要安排），确认后可手动发放。系统记录了完整信息便于追溯。

**Q: 失败项的原始数据会保留吗？**
A: 是的，每条失败记录在 `original_data` 中完整保留了上传时的所有字段，同时附带 `reason`（原因）和 `suggestion`（建议处理方式），可以直接复制粘贴给相关同事说明。
