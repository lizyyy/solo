# 影院排片核对工具 (Cinema Review Tool)

一个用于影院值班经理在开场前核对当天排片和放映设备状态的桌面GUI工具。

## 功能特性

### 核心功能
- **数据导入**: 支持导入四种格式的数据文件
  - `screenings.csv` - 排片信息
  - `projector_logs.jsonl` - 放映机日志
  - `lamp_hours.csv` - 灯泡小时数记录
  - `hall_rules.yaml` - 影厅规则配置

- **智能筛选**: 按影厅和时间段筛选排片数据

- **时间线重建**: 可视化每场放映的完整设备时间线
  - 理论预热/冷却时间
  - 实际开机/关机时间
  - 实际放映开始/结束时间

- **问题检测**: 自动检测四种常见问题
  1. **排片重叠/间隔不足** - 同一影厅两场排片时间重叠或间隔小于要求
  2. **放映机预热不足** - 实际开机时间距离放映开始时间不足规定预热时间
  3. **灯泡小时数超限** - 灯泡使用小时数接近或超过最大限制
  4. **跨午夜场次归属错误** - 跨越午夜的场次未正确标记或日期归属错误

- **状态管理**: 保存和加载问题处理状态
  - 标记问题为"已解决"或"已忽略"
  - 添加问题备注
  - 持久化保存到本地

- **报告导出**: 支持导出审核报告和问题列表
  - `projection_review.md` - 格式良好的Markdown审核报告
  - `issues.csv` - 完整的问题列表CSV文件

## 数据文件格式说明

### 1. screenings.csv (排片信息)

| 字段名 | 说明 | 示例 |
|--------|------|------|
| id | 排片ID | SCR-H1-1 |
| hall_id | 影厅ID | H1 |
| hall_name | 影厅名称 | 1号厅 |
| film_name | 影片名称 | 流浪地球3 |
| start_time | 开始时间 | 2026-05-04 10:00:00 |
| end_time | 结束时间 | 2026-05-04 12:15:00 |
| duration_minutes | 时长(分钟) | 135 |
| date | 日期 | 2026-05-04 |
| is_midnight | 是否午夜场 | false |
| language | 语言 | 中文 |

> 注意：也支持中文列名，如"影厅ID"、"开始时间"等

### 2. projector_logs.jsonl (放映机日志)

每行一个JSON对象：

```json
{
  "id": "LOG-001",
  "hall_id": "H1",
  "event_time": "2026-05-04 09:45:00",
  "event_type": "power_on",
  "status": "success",
  "lamp_hours": 1850.5,
  "message": "放映机开机完成"
}
```

支持的事件类型：
- `power_on` / `开机` / `startup` - 放映机开机
- `power_off` / `关机` / `shutdown` - 放映机关机
- `play_start` / `播放开始` - 开始播放
- `play_end` / `播放结束` - 结束播放

### 3. lamp_hours.csv (灯泡小时数)

| 字段名 | 说明 | 示例 |
|--------|------|------|
| hall_id | 影厅ID | H1 |
| date | 日期 | 2026-05-04 |
| start_hours | 今日开始小时数 | 1850.5 |
| end_hours | 今日结束小时数 | 1859.0 |
| used_hours | 今日使用小时数 | 8.5 |
| projector_model | 放映机型号 | Barco DP2K-20C |
| lamp_model | 灯泡型号 | Ushio DXL-20SN |
| max_lamp_hours | 最大灯泡小时数 | 2000.0 |

### 4. hall_rules.yaml (影厅规则配置)

```yaml
halls:
  - hall_id: H1
    hall_name: 1号厅
    warmup_minutes: 15        # 预热时间（分钟）
    cooldown_minutes: 5       # 冷却时间（分钟）
    cleanup_minutes: 10       # 清场时间（分钟）
    max_lamp_hours: 2000.0    # 最大灯泡小时数
    lamp_warning_threshold: 1800.0  # 警告阈值
    capacity: 200             # 座位数
    projector_id: PRJ-001     # 放映机ID
    audio_system: Dolby Atmos # 音响系统
```

## 使用指南

### 主界面介绍

应用启动后显示主界面，分为四个主要区域：

1. **顶部筛选面板**
   - 审核日期：选择要核对的日期
   - 影厅：按影厅筛选（或选择"全部"）
   - 时间段：按时间段筛选
   - 应用筛选：应用当前筛选条件
   - 保存状态：保存当前筛选和问题处理状态

2. **左侧时间线面板**
   - 可视化显示各影厅的排片时间线
   - 绿色块表示正常排片
   - 红色块表示存在问题的排片
   - 时间刻度显示在顶部

3. **右侧问题列表**
   - 表格显示检测到的所有问题
   - 按严重程度排序（严重 > 中等 > 轻微）
   - 显示问题类型、影厅、影片、状态
   - 已解决/已忽略的问题显示为灰色

4. **右下问题详情**
   - 描述：问题详细描述
   - 备注：添加处理备注
   - 操作按钮：
     - 标记已解决
     - 标记已忽略
     - 重置状态

### 工作流程

1. **准备数据**
   - 将数据文件放入 `data/` 目录（或 `data/sample/` 目录）
   - 确保文件名正确：`screenings.csv`、`projector_logs.jsonl`、`lamp_hours.csv`、`hall_rules.yaml`

2. **启动应用**
   - 运行 `python main.py`
   - 应用会自动加载数据并检测问题

3. **查看和筛选**
   - 查看时间线可视化
   - 使用筛选面板按影厅或时间段过滤
   - 在问题列表中查看检测到的问题

4. **处理问题**
   - 选中问题查看详情
   - 添加备注说明
   - 标记为"已解决"或"已忽略"

5. **导出报告**
   - 点击菜单 `文件` -> `导出审核报告 (MD)`
   - 点击菜单 `文件` -> `导出问题列表 (CSV)`
   - 文件保存在 `output/` 目录

## 问题检测规则

### 1. 排片重叠检测

**检测条件**：
- 同一场次的结束时间 > 下一场次的开始时间 → 排片重叠（严重）
- 场次间隔 < (冷却时间 + 清场时间 + 预热时间) → 间隔不足（中等）

**默认规则**（可在 hall_rules.yaml 中配置）：
- 冷却时间：5分钟
- 清场时间：10分钟
- 预热时间：15分钟
- 最小间隔：30分钟

### 2. 预热不足检测

**检测条件**：
- 实际开机时间 → 放映开始时间 < 规则要求的预热时间

**严重程度**：
- 实际预热 < 要求的一半 → 严重
- 实际预热 < 要求但 > 一半 → 中等

### 3. 灯泡小时数超限检测

**检测条件**：
- 当前小时数 >= 最大限制 → 已超限（严重）
- 当前小时数 >= 警告阈值 → 即将超限（中等）

**默认规则**：
- 最大限制：2000小时
- 警告阈值：1800小时

### 4. 跨午夜场次归属错误检测

**检测条件**：
- 结束时间日期 > 开始时间日期（跨午夜）但 `is_midnight=false` → 未标记（中等）
- `is_midnight=true` 但实际上不跨午夜 → 错误标记（轻微）
- 开始时间在 00:00-06:00 但日期归属错误 → 日期归属错误（中等）

## 状态保存

应用会自动管理以下状态：

### 保存的内容
- 问题处理状态（已解决/已忽略）
- 问题备注
- 上次使用的筛选条件（影厅、时间段）
- 审核日期

### 文件位置
- `output/review_state.json`

### 注意事项
- 状态按日期隔离，不同日期的状态互不影响
- 每次退出前建议手动点击"保存状态"

## 常见问题

### Q1: 应用启动后没有数据？

请检查：
1. 数据文件是否存在于 `data/` 或 `data/sample/` 目录
2. 文件名是否正确（区分大小写）
3. 数据格式是否符合要求

### Q2: 如何切换到其他日期的数据？

1. 在顶部筛选面板修改"审核日期"
2. 点击"应用筛选"
3. 应用会重新加载对应日期的数据

### Q3: 如何添加自己的数据？

1. 参考 `data/sample/` 目录下的文件格式
2. 创建自己的数据文件
3. 放入 `data/` 目录（优先级高于 sample）
4. 重启应用或点击菜单 `文件` -> `重新加载数据`

### Q4: 状态保存在哪里？会丢失吗？

- 状态保存在 `output/review_state.json`
- 只要不删除该文件，状态会永久保存
- 不同日期的状态互不影响
