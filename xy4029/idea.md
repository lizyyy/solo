## 原始点子

我想做一个给小型运维/SRE 值班组用的本地自动化工具，叫“故障复盘拼图器”。我们每次线上故障结束后，材料都散在监控告警 CSV、值班群导出的 Markdown/JSON、服务日志片段和人工补充时间点里，靠人手工拼时间线很容易漏掉重复告警、时区差和关键恢复动作。请从 0 到 1 做一个可以直接在终端运行的 Python CLI 项目：init 命令能创建项目配置，维护服务名、环境、默认时区、告警去重窗口、日志时间格式和敏感字段脱敏规则；import-alerts 能导入监控告警 CSV，import-chat 能导入值班群消息 Markdown 或 JSON，import-logs 能导入多份服务日志片段，所有原始文件都不能被覆盖。reconcile 命令要把这些材料统一成一条可信事件时间线，能按配置修正时区和设备时钟偏移，合并重复告警，识别“告警触发、人工确认、变更操作、错误日志激增、恢复验证、复盘待办”等事件类型；遇到时间戳缺失、日志格式不匹配、同一事件来源冲突、敏感字段命中但无法脱敏时，要写入 quarantine.json 并给出清楚原因，而不是静默丢掉。report 命令能导出 Markdown 复盘报告和 CSV 事件清单，报告里要包含影响时长、检测到确认耗时、确认到恢复耗时、关键证据片段和待办项；history 命令能从本地 SQLite 或 JSON 数据目录按服务、日期、严重级别查询过去的复盘。希望代码拆成 CLI 入口、配置模型、导入解析器、时间线归并/去重规则、脱敏与隔离区、存储层、报告导出、示例数据和测试等多个文件，不要做成单文件脚本。README 里请写清楚安装方式、示例命令，以及如何用临时目录验证 init、导入三类材料、归并时间线、导出报告和查询历史这些核心流程。
