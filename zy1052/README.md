# WebGPU 图片滤镜管线体检台

一个基于 WebGPU 的本地图片滤镜管线体检台，用于对比 GPU 路径与 CPU fallback 路径的输出一致性和性能差异。

## 功能特性

### 🎯 核心功能
- **图片导入**: 支持拖放或点击选择图片文件
- **滤镜管线**: 支持添加、删除、排序、启用/禁用多个滤镜节点
- **参数调节**: 每个滤镜都有详细的参数控制面板
- **双路径执行**: GPU (WebGPU) + CPU fallback 双路径并行执行
- **实时预览**: 双路径输出结果并排对比
- **像素差异分析**: 自动计算两条路径输出的像素差异（PSNR、差异百分比等）
- **性能统计**: 每个节点和总耗时的详细统计
- **失败定位**: 精确识别执行失败的节点及其参数

### 📦 导出功能
- **项目 JSON 导出**: 保存当前滤镜管线配置
- **项目 JSON 导入**: 加载之前保存的滤镜管线配置
- **Markdown 报告**: 导出详细的测试报告，包含环境信息、性能数据、差异分析
- **HTML 报告**: 导出格式美观的交互式 HTML 报告

### 🎨 支持的滤镜

| 分类 | 滤镜 | 描述 | GPU 支持 | CPU 支持 |
|------|------|------|----------|----------|
| 变换 | 裁切 (Crop) | 从原始图像中裁切指定区域 | ✅ | ✅ |
| 变换 | 缩放 (Resize) | 将图像缩放到指定尺寸，支持多种插值算法 | ✅ | ✅ |
| 颜色 | 灰度 (Grayscale) | 将彩色图像转换为灰度图像 | ✅ | ✅ |
| 颜色 | 色阶 (Levels) | 调整图像的亮度、对比度和色调范围 | ✅ | ✅ |
| 滤镜 | 锐化 (Sharpen) | 增强图像边缘和细节 | ✅ | ✅ |
| 滤镜 | 马赛克 (Mosaic) | 将图像分块并应用马赛克效果 | ✅ | ✅ |
| 合成 | 水印 (Watermark) | 在图像上叠加水印文本 | ❌ | ✅ |

## 系统要求

### 必要环境
- **Node.js**: >= 18.0.0
- **npm** 或 **pnpm** 或 **yarn**
- **现代浏览器**: 支持 WebGPU 或至少支持 Canvas 2D

### WebGPU 支持情况

| 浏览器 | 支持版本 | 启用方式 |
|--------|----------|----------|
| Chrome | >= 113 | 默认启用 |
| Edge | >= 113 | 默认启用 |
| Firefox | 开发中 | 需手动启用 flag |
| Safari | 技术预览版 | 需启用 WebGPU 实验功能 |

**如果 WebGPU 不可用**: 应用会自动降级到纯 CPU 路径执行，所有功能保持可用，只是性能较低。

## 使用指南

### 基础流程

1. **导入图片**: 将图片拖放到左侧"源图片"区域，或点击选择文件
2. **添加滤镜**: 点击"+ 添加滤镜"按钮，从菜单中选择需要的滤镜
3. **调节参数**: 点击滤镜节点展开参数面板，调节各项参数
4. **排序节点**: 拖拽滤镜节点上下移动，调整执行顺序
5. **执行管线**: 点击右下角"执行管线"按钮
6. **查看结果**: 观察双路对比预览，查看底部的差异分析和性能统计
7. **导出报告**: 点击"Markdown 报告"或"HTML 报告"导出详细报告

### 使用示例管线

项目中包含两个预设的示例管线配置：

1. **电商商品图处理管线** (`public/samples/example-pipeline-1.json`)
   - 包含：裁切 → 缩放 → 灰度（禁用）→ 色阶 → 锐化
   - 适用于商品图片的标准化处理

2. **活动海报处理管线** (`public/samples/example-pipeline-2.json`)
   - 包含：马赛克（禁用）→ 色阶增强 → 边缘增强 → 水印
   - 适用于活动海报的视觉增强

**如何使用示例管线**：

2. 导航到 `public/samples/` 目录

4. 导入后，添加图片并点击"执行管线"即可

## WebGPU 不可用时的行为

当浏览器不支持 WebGPU 或 WebGPU 初始化失败时：

### 你会看到
1. 页面顶部的状态指示器中，"WebGPU" 显示为 **"不可用"**（灰色圆点）
2. "CPU" 始终显示为 **"可用"**（绿色圆点）
3. 预览区域只有 **"CPU 路径"** 的输出
4. 所有滤镜节点仍然可以正常添加和配置

### 功能差异

| 功能 | WebGPU 可用时 | WebGPU 不可用时 |
|------|---------------|-----------------|
| 滤镜执行 | GPU + CPU 双路径 | 仅 CPU 路径 |
| 性能对比 | 完整的双路径耗时对比 | 无对比数据 |
| 像素差异分析 | 自动计算双路径差异 | 无差异数据 |
| 滤镜支持 | 全部支持 | 全部支持（水印仅 CPU） |
| 执行速度 | 取决于 GPU 性能 | 取决于 CPU 性能 |

### 建议的测试场景

即使没有 WebGPU，你仍然可以：
1. 测试滤镜的参数效果
2. 构建和调试复杂的滤镜管线
3. 导出项目配置和报告
4. 在支持 WebGPU 的设备上验证结果一致性

## 像素差异指标说明

执行管线后，底部面板会显示以下差异指标：

### 差异像素占比 (Differing Percent)
- 计算公式：`(差异像素数 / 总像素数) × 100%`
- **参考标准**：
  - `< 0.1%`: 优秀（人眼几乎无法察觉）
  - `0.1% - 1%`: 良好（差异极小）
  - `> 1%`: 需关注（可能存在实现差异）

### PSNR (峰值信噪比)
- 衡量两幅图像质量差异的标准指标
- 单位：dB（分贝）
- **参考标准**：
  - `>= 40 dB`: 优秀（差异可忽略）
  - `30 - 40 dB`: 良好（差异极小）
  - `20 - 30 dB`: 一般（差异明显）
  - `< 20 dB`: 较差（差异显著）

### 其他指标
- **RMS 差异**: 像素差异的均方根值
- **最大差异**: 单通道的最大差异值
- **平均差异**: 差异像素的平均差异值

## 常见问题

### Q: 为什么 GPU 路径比 CPU 路径慢？
A: WebGPU 有固定的初始化开销。对于小尺寸图片或简单滤镜，CPU 可能更快。对于大尺寸图片或复杂滤镜管线，GPU 应该展现出优势。建议使用 1080p 以上的图片测试。

### Q: 为什么两条路径的输出有差异？
A: 这是正常现象，原因包括：
- 浮点数精度差异（GPU 通常使用 f32，CPU 使用更高精度）
- 采样和插值算法的细微差异
- 不同的舍入策略
- 通常 PSNR > 30dB 即表示实现正确

### Q: 水印滤镜为什么不支持 GPU？
A: 水印滤镜依赖 Canvas 2D 的文本渲染 API，这在 WebGPU 中实现较为复杂。该滤镜始终走 CPU 路径，不影响其他滤镜的 GPU 加速。

### Q: 如何验证我的 WebGPU 实现正确性？
A: 使用本工具的双路径对比功能：
1. 用同一张图片同时执行 GPU 和 CPU 路径
2. 检查像素差异指标
3. 如果 PSNR > 35dB，说明实现基本一致
4. 如果存在显著差异，导出报告并检查失败节点
