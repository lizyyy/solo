# 城市骑行活动签到台

一个完整的骑行活动管理系统，包含骑手报名、装备检查、多签到点管理、途中退赛、补给领取和完赛统计功能。

## 功能特性

### 核心功能
- **骑手报名管理**：添加新骑手、查看报名列表、状态筛选
- **装备检查**：检查头盔、前后灯、反光条、维修工具等强制装备，支持审批意见记录
- **签到点看板**：查看各签到点签到人数、快速签到、待签到骑手列表
- **退赛登记**：记录退赛原因、地点、确认意见
- **补给领取**：途中补给和完赛补给发放，支持业务规则校验
- **完赛统计**：完赛时间、用时统计、报告导出

### 业务规则
1. **装备检查校验**：未通过装备检查不能出发签到
2. **漏签到校验**：漏签签到点不能直接完赛
3. **退赛限制**：退赛后不能领取完赛补给
4. **完赛限制**：退赛骑手不能完赛

### 审批历史
- 所有重要操作（装备检查、退赛登记）都会保存审批意见
- 导出报告中可以还原为什么通过或拒绝

## 快速开始

### 1. 安装依赖
```bash
# 后端
cd backend
npm install

# 前端（新终端）
cd frontend
npm install
```

### 2. 初始化样例数据
```bash
cd backend
npm run seed
```

这将创建 5 个骑手，涵盖所有场景：
- **张明**：正常完赛（所有流程通过）
- **李华**：装备缺失（尾灯缺失，不能出发）
- **王芳**：漏签到（缺少 CP2 签到）
- **赵强**：途中退赛（身体不适，在 CP2 退赛）
- **周明**：初始状态（等待装备检查）

### 3. 启动服务
```bash
# 启动后端 (端口 3001)
cd backend
npm run dev

# 启动前端 (端口 5173)
cd frontend
npm run dev
```

### 4. 访问应用
- 前端地址：http://localhost:5173
- 后端 API：http://localhost:3001/api

## 使用指南

### 仪表盘
- 查看各状态骑手统计
- 各签到点签到情况
- 补给发放统计
- 异常情况（漏签到、退赛）
- 样例场景说明

### 报名列表
- 查看所有骑手报名信息
- 按状态筛选（已报名、装备检查通过/未通过、比赛中、已退赛、已完赛）
- 搜索骑手
- 新增报名

### 签到点看板
- 按签到点查看签到人数
- 快速签到（按号码布搜索）
- 查看待签到骑手

### 装备检查
- 搜索骑手进行装备检查
- 检查项目：头盔、前后灯、反光条、维修工具
- 记录检查状态（正常、缺失、损坏）及备注
- 填写审批意见（保存到报告）

### 退赛登记
- 搜索骑手进行退赛登记
- 记录退赛原因、地点
- 填写确认意见（保存到报告）

### 补给状态
- 途中补给发放
- 完赛补给发放（仅完赛骑手可领，退赛骑手限制）

### 骑手详情
- 完整的骑手历程
- 装备检查历史
- 签到进度
- 退赛/完赛记录
- 补给领取情况
- 审批意见历史（用于复盘）

### 导出报告
- 点击导航栏右上角的「导出报告」按钮
- 下载 JSON 格式的完整活动报告
- 包含：活动摘要、各骑手详细历程、审批历史

## 业务规则演示

### 场景 1：装备缺失
1. 尝试让李华（#1002）在起点签到
2. 系统提示：「未通过装备检查，不能出发」
3. 查看李华详情页，可看到装备检查记录和审批意见

### 场景 2：漏签到
1. 王芳（#1003）缺少 CP2（东方明珠）签到
2. 如果试图直接在终点完赛，系统会提示漏签的签到点

### 场景 3：途中退赛
1. 赵强（#1004）已在 CP2 退赛
2. 尝试给他发放完赛补给，系统会拒绝
3. 查看赵强详情页，可看到退赛记录和确认意见

### 场景 4：正常完赛
1. 张明（#1001）已完成所有流程
2. 可领取途中补给和完赛补给
3. 查看详情页可看到完整历程
