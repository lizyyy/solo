## 四、状态流转说明

```
DRAFT(草稿) 
  │
  ├── SUBMIT ──► PENDING_APPROVAL(待审批)
  │                 │
  │                 ├── APPROVE ──► APPROVED(已通过)
  │                 │
  │                 ├── REJECT ──► REJECTED(已拒绝)
  │                 │                 │
  │                 │                 └── 可修改 ──► MODIFIED
  │                 │
  │                 └── 可撤回 ──► WITHDRAWN(已撤回)
  │
  └── WITHDRAW ──► WITHDRAWN(已撤回)

MODIFIED(已修改) 
  └── SUBMIT ──► PENDING_APPROVAL(待审批)

APPROVED(已通过)
  └── 可撤回 ──► WITHDRAWN(已撤回)
```

## 五、关键校验逻辑

### 1. 设备功率校验
- 每个设备功率必须 > 0
- 设备数量必须 ≥ 1
- 自动计算总功率：Σ(功率 × 数量)

### 2. 时段冲突校验
- 同一摊位的两个申请，如果时间段有重叠，则冲突
- 只有 `APPROVED` 和 `PENDING_APPROVAL` 状态的申请会占用时段

### 3. 楼层容量校验
- 同一时段内，同楼层所有申请的总功率不能超过楼层可用容量
- 可用容量 = 总容量 - 永久预留量
- 只有 `APPROVED` 和 `PENDING_APPROVAL` 状态的申请会占用容量

## 六、幂等性说明

所有写操作（创建、推进、撤回、修改）都需要提供 `X-Request-Id` 请求头。

- 同一个 `X-Request-Id` 只能执行一次
- 重复发送相同 `X-Request-Id` 的请求，会直接返回第一次的结果，**不会**重复执行

**用途：** 防止网络超时导致的重复提交

## 七、常见问题

### Q: 服务端口被占用怎么办？

**A:** 可以指定其他端口启动：
```bash
PORT=3001 npm start
```

### Q: 想重新开始测试怎么办？

**A:** 删除数据库文件，重新启动：
```bash
rm approval.db
npm start
```

### Q: curl 返回的 JSON 不好看怎么办？

**A:** 安装 `jq` 工具：
```bash
# Mac
brew install jq

# 使用方式
curl http://localhost:3000/api/health | jq
```
