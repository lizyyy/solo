# 施工噪声投诉复核台

一个专为城市环保夜间值守人员设计的本地数据分析与可视化工具，用于处理居民噪声投诉的复核工作。

## 功能特性

### 核心功能
- **多站点数据导入**：支持导入多个监测站点的声级计CSV数据、气象记录和投诉清单
- **智能数据分析**：
  - 自动校验时间戳、站点编号、分贝范围、采样间隔和缺测数据
  - 自动对齐时间线
  - 检测超标窗口、突增峰值、传感器离线时段
  - 分析投诉附近的证据

- **可视化界面**：
  - 时间轴图：实时展示噪声数据与阈值对比
  - 站点对比：多站点数据横向对比
  - 异常标记：高亮显示超标、峰值、离线等异常事件

- **人工复核**：
  - 投诉列表与详细信息展示
  - 分析证据辅助决策
  - 复核状态记录与保存

- **报告导出**：
  - Markdown复核报告
  - CSV异常事件表
  - JSON审计包

### 方式二：使用自己的数据

#### 数据格式要求

##### 1. 噪声数据 CSV 格式

必需列：
- `timestamp`: 时间戳（支持多种格式：YYYY-MM-DD HH:MM:SS 等）
- `laeq`: 等效连续声级（dB）

可选列：
- `site_id`: 站点编号
- `lmax`: 最大声级
- `lmin`: 最小声级
- `l10`, `l50`, `l90`: 累积百分声级

示例：
```csv
timestamp,site_id,laeq,lmax,lmin,l10,l50,l90
2026-05-01 22:00:00,SITE-001,45.2,48.5,42.1,46.3,45.0,43.8
2026-05-01 22:00:01,SITE-001,44.8,47.2,41.9,45.8,44.7,43.5
```

##### 2. 气象数据 CSV 格式

必需列：
- `timestamp`: 时间戳

可选列：
- `site_id`: 站点编号
- `temperature`: 温度（摄氏度）
- `humidity`: 湿度（百分比）
- `wind_speed`: 风速（m/s）
- `wind_direction`: 风向（度）
- `rainfall`: 降雨量（mm）
- `barometric_pressure`: 气压（hPa）

示例：
```csv
timestamp,site_id,temperature,humidity,wind_speed,wind_direction,rainfall,barometric_pressure
2026-05-01 22:00:00,SITE-001,15.2,65.3,3.2,180,0.0,1013.2
2026-05-01 22:01:00,SITE-001,15.1,65.5,3.5,185,0.0,1013.1
```

##### 3. 投诉数据 CSV 格式

必需列：
- `timestamp`: 投诉时间
- `site_id`: 关联站点编号

可选列：
- `complaint_id`: 投诉ID
- `complainant_name`: 投诉人姓名
- `complainant_phone`: 投诉人电话
- `complainant_address`: 投诉人地址
- `complaint_type`: 投诉类型（noise, vibration 等）
- `complaint_content`: 投诉内容
- `expected_noise_source`: 投诉人认为的噪声源
- `review_status`: 复核状态
- `severity`: 严重程度

示例：
```csv
complaint_id,timestamp,site_id,complainant_name,complainant_address,complaint_content,severity
CMPL-2026-001,2026-05-01 23:00:00,SITE-001,张三,幸福小区1号楼,楼下工地夜间施工，噪声很大，无法入睡,high
```

## 分析算法说明

### 1. 超标窗口检测

- 根据时间判断使用昼间或夜间阈值
- 检测连续超过阈值的时段
- 计算窗口内的最大值、平均值和持续时间

### 2. 突增峰值检测

- 计算当前值与前10秒基线值的差异
- 当差异超过设定阈值（默认15dB）时判定为突增峰值
- 估计峰值持续时间

### 3. 传感器离线检测

- 计算相邻数据点的时间间隔
- 当间隔超过设定阈值（默认60秒）时判定为离线时段
- 计算预计缺失的采样数

### 4. 投诉证据分析

对每条投诉，在投诉时间前后的分析窗口内检查：
- 是否存在噪声超标
- 是否存在突增峰值
- 是否存在传感器离线
- 是否存在显著天气干扰（强风、降雨）

根据检查结果给出复核建议：
- **确认超标**：存在明确的噪声超标证据
- **建议驳回**：未发现明显噪声异常或存在天气干扰
- **进一步核查**：存在离线时段或天气干扰，需现场核实

## 状态存储

复核状态会保存在本地：
- Windows: `C:\Users\<用户名>\.noise_review\states\`
- macOS/Linux: `~/.noise_review/states/`

每个状态文件为 JSON 格式，包含：
- 所有投诉的复核状态和备注
- 异常事件的验证状态
- 分析配置参数

## 常见问题

### Q1: 支持哪些时间戳格式？
A: 支持多种常见的时间戳格式，包括：
- `YYYY-MM-DD HH:MM:SS`
- `YYYY/MM/DD HH:MM:SS`
- `MM/DD/YYYY HH:MM:SS`
- 以及其他 pandas 能够解析的格式

### Q2: 如果数据中没有 site_id 列怎么办？
A: 可以在导入时手动指定站点编号，系统也会自动生成默认的站点编号。

### Q3: 如何处理缺失数据？
A: 系统会自动检测缺失数据并标记为缺测。在分析时，缺测数据会被排除，但连续缺测可能会被判定为传感器离线。

### Q4: 天气数据如何影响分析结果？
A: 当存在强风（>10 m/s）或降雨时，系统会标记为"天气干扰"，这可能影响复核建议（建议驳回或进一步核查）。

### Q5: 导出的报告包含哪些内容？
A: 
- **Markdown报告**：完整的复核报告，包含数据概览、异常统计、投诉详情、复核记录
- **CSV事件表**：所有异常事件的列表，包含时间、站点、类型、严重程度等信息
- **JSON审计包**：完整的数据包，包含所有原始分析结果和复核状态，适合存档和审计
