# 地铁夜间检修调度小游戏

一款基于网格线路图的策略调度小游戏，玩家需要在末班车运营期间安排检修车进行轨道维修，同时避免列车冲突。

## 功能特性

### 核心玩法
- **网格线路图**：基于Canvas渲染的地铁线路图
- **检修车控制**：移动检修车到目标位置进行维修
- **封锁区管理**：放置封锁区引导末班车绕行
- **末班车调度**：末班车按预设时刻自动运行
- **关键轨段维修**：在截止时间前完成所有维修任务

### 游戏规则
- **避免冲突**：检修车不能与末班车出现在同一位置
- **电量管理**：检修车移动和维修会消耗电量
- **超时惩罚**：关键轨段超时未修则游戏失败
- **通关条件**：完成所有关键轨段的维修

### 辅助功能
- **撤销/重做**：支持最多50步的撤销和重做操作
- **通关评分**：基于时间、剩余电量等因素进行评分（S/A/B/C级）
- **本地存档**：自动保存最多5个游戏进度
- **关卡导入导出**：支持自定义关卡的导入和导出

## 游戏操作

### 工具栏
- **选择工具 (1)**：点击选中单元格或检修车
- **检修车控制 (2)**：移动和控制检修车
- **封锁区工具 (3)**：放置或移除封锁区
- **移除工具 (4)**：移除已放置的封锁区

### 基本操作
1. **选中检修车**：点击红色的检修车图标
2. **移动检修车**：选中后点击相邻的轨道单元格
3. **维修轨段**：检修车在关键轨段上时再次点击进行维修
4. **放置封锁区**：选择封锁区工具后点击空轨道
5. **进入下一回合**：点击"下一回合"按钮，末班车会按时刻移动

### 快捷键
| 快捷键 | 功能 |
|--------|------|
| `1` | 选择工具 |
| `2` | 检修车控制 |
| `3` | 封锁区工具 |
| `4` | 移除工具 |
| `Ctrl+Z` | 撤销 |
| `Ctrl+Y` | 重做 |

| `Esc` | 取消选择/关闭弹窗 |

## 关卡配置

### 关卡格式
关卡使用JSON格式配置，以下是完整的配置说明：

#### 基本结构
```json
{
  "id": "关卡唯一标识",
  "name": "关卡名称",
  "description": "关卡描述",
  "grid": [],           // 网格数据
  "maintenanceCars": [], // 检修车列表
  "lastTrains": [],      // 末班车列表
  "criticalSegments": [], // 关键轨段列表
  "winConditions": {},    // 胜利条件
  "timeLimit": 20,        // 回合数限制（可选）
  "startingTurn": 0       // 起始回合（可选）
}
```

#### 网格数据格式
网格是一个二维数组，每个单元格可以是字符串或对象：

**字符串格式**（推荐）：
```
格式: 类型-方向
例如: "T-NS" 表示南北方向的轨道
```

**单元格类型**：
| 代码 | 类型 | 说明 |
|------|------|------|
| E | empty | 空地，不可通过 |
| T | track | 普通轨道 |
| S | station | 车站 |
| J | junction | 交汇点 |
| D | depot | 车库 |
| X | terminus | 终点站 |

**方向代码**：
| 代码 | 方向 |
|------|------|
| N | 北（上） |
| S | 南（下） |
| E | 东（右） |
| W | 西（左） |

**示例网格**：
```json
[
  ["E", "E", "E", "E", "E"],
  ["E", "S-NS", "T-NS", "S-NS", "E"],
  ["E", "E", "J-NSWE", "E", "E"],
  ["E", "S-EW", "T-EW", "S-EW", "E"],
  ["E", "E", "E", "E", "E"]
]
```

#### 检修车配置
```json
{
  "id": "car_1",           // 唯一标识
  "name": "检修车 A",       // 显示名称
  "x": 2,                   // 初始X坐标
  "y": 2,                   // 初始Y坐标
  "battery": 100,           // 初始电量
  "maxBattery": 100,        // 最大电量
  "movementCost": 10,       // 移动消耗电量
  "repairCost": 5           // 维修消耗电量
}
```

#### 末班车配置
```json
{
  "id": "train_1",          // 唯一标识
  "name": "1号线末班车",     // 显示名称
  "route": [                // 行驶路线（坐标数组）
    {"x": 1, "y": 1},
    {"x": 2, "y": 1},
    {"x": 3, "y": 1}
  ],
  "startTime": 3,           // 开始行驶的回合
  "speed": 1                // 每回合移动格数
}
```

#### 关键轨段配置
```json
{
  "id": "seg_1",            // 唯一标识
  "x": 2,                   // X坐标
  "y": 1,                   // Y坐标
  "repairTime": 2,          // 需要的维修回合数
  "deadline": 10,           // 截止回合（不设限制为 Infinity）
  "priority": "high"        // 优先级：high/normal/low
}
```

#### 胜利条件
```json
{
  "repairAllCritical": true,    // 是否需要修复所有关键轨段
  "avoidAllConflicts": true,    // 是否需要避免所有冲突
  "maintainBattery": true,      // 是否需要维持电量
  "additionalConditions": []     // 额外条件（预留）
}
```

## 评分系统

游戏通关时会根据以下因素进行评分：

| 等级 | 分数要求 | 说明 |
|------|----------|------|
| S | ≥130 | 完美通关 |
| A | 115-129 | 优秀 |
| B | 100-114 | 良好 |
| C | <100 | 合格 |

**评分构成**：
- **基础分**：100分
- **时间奖励**：剩余回合×2（最多+40）
- **电量奖励**：剩余电量百分比×20（最多+20）

## 失败条件

游戏会在以下情况失败：

1. **列车冲突**：检修车与末班车出现在同一位置
2. **电量耗尽**：任何检修车电量降为0
3. **维修超时**：关键轨段未在截止时间前修复
4. **时间超限**：超过关卡设定的最大回合数

每次失败时，游戏会显示详细的失败原因，并提供"撤销一步"的选项。

## 技术说明

### 模块职责

| 模块 | 职责 | 核心文件 |
|------|------|----------|
| 关卡解析 | 解析和验证JSON关卡配置 | parser.js, levelManager.js |
| 规则引擎 | 处理游戏逻辑、冲突检测、胜负判断 | rulesEngine.js |
| 状态管理 | 管理游戏状态、支持撤销/重做 | gameState.js, historyManager.js |
| 渲染交互 | Canvas渲染、用户输入处理 | renderer.js, controller.js |
| 存档管理 | 本地存储、进度保存 | saveManager.js |

### 数据流程

```
用户操作 → UIController → Game → RulesEngine 
                                    ↓
                              GameState (状态变更)
                                    ↓
                              HistoryManager (保存状态)
                                    ↓
                              Renderer (渲染视图)
```

## 开发指南

### 添加新关卡
1. 在 `src/levels/data/` 目录创建新的JSON文件
2. 参考现有关卡格式编写配置
3. 在 `levelManager.js` 的 `loadBuiltInLevels` 方法中添加新关卡路径

### 扩展游戏规则
1. 在 `rulesEngine.js` 中添加新的验证方法
2. 更新 `advanceTurn` 方法中的检查逻辑
3. 如有需要，更新 `gameState.js` 中的状态模型

### 自定义UI样式
1. 修改 `css/style.css` 中的样式定义
2. 如需修改Canvas渲染逻辑，编辑 `renderer.js`

## 常见问题

### Q: 游戏加载失败，显示空白页面？
A: 请确保：
- 使用支持ES Modules的现代浏览器
- 通过本地服务器访问（不要直接打开HTML文件）
- 检查浏览器控制台是否有错误信息

### Q: 如何创建自定义关卡？
A: 参考 `src/levels/data/tutorial.json` 的格式，使用文本编辑器创建JSON文件，然后通过游戏内的"导入关卡"功能导入。

### Q: 存档数据存储在哪里？
A: 存档数据存储在浏览器的LocalStorage中，不同浏览器之间不共享。清除浏览器数据会丢失存档。

### Q: 最多支持多少步撤销？
A: 默认支持最多50步的撤销/重做历史。可以在 `historyManager.js` 中修改 `maxHistory` 参数。
