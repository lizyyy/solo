## 1. 产品概述

光纤弯曲损耗记录系统——面向设备工程师的工业级光纤测试数据管理工具，解决维修群截图备注比正式表格更关键却易丢失的痛点。系统保留原始材料痕迹，禁止将备注清洗为"一行干净数据"，确保异常工况可追溯、冲突可裁决、补录可审计。

- 目标用户：设备工程师（如何工）、现场施工师傅、实验老师
- 核心价值：让光纤弯曲损耗数据从"录入→冲突发现→复核→归档"全链路可审，杜绝自动拍板

## 2. 核心功能

### 2.1 用户角色

| 角色 | 进入方式 | 核心权限 |
|------|----------|----------|
| 设备工程师 | 首页登录 | 导入铭牌参数、查看维修群截图、确认/驳回冲突、导出报告 |
| 现场施工师傅 | 首页登录 | 录入弯曲损耗数据、上传维修群截图、补录历史数据 |
| 实验老师 | 首页登录 | 复核异常工况（如负方向写"向左"）、标记最终结论 |

### 2.2 功能模块

1. **数据录入页**：设备铭牌参数首次导入、弯曲损耗数据录入、维修群截图上传与备注
2. **异常工况表**：冲突检测与证据展示、设备工程师裁决、实验老师复核区
3. **历史记录页**：完整操作日志、补录追溯、数据变更时间线
4. **自检与导出页**：系统自检面板（重复导入/负方向异常/补录重算/导出一致性）、报告导出

### 2.3 页面详情

| 页面名称 | 模块名称 | 功能描述 |
|----------|----------|----------|
| 数据录入页 | 铭牌参数导入 | CSV/手动录入设备铭牌参数，首次导入后锁定为基准，后续冲突以此为准 |
| 数据录入页 | 弯曲损耗数据录入 | 录入弯曲半径、方向、损耗值；方向字段支持"向左/向右"与"+/-"双模式，负方向写"向左"自动标记待复核 |
| 数据录入页 | 维修群截图上传 | 上传截图并关联到具体记录，截图备注与正式数据并列展示，不可被清洗 |
| 异常工况表 | 冲突检测引擎 | 自动比对铭牌参数与截图备注，发现矛盾时生成冲突条目，列出双方证据 |
| 异常工况表 | 工程师裁决面板 | 冲突条目展示：铭牌参数原文 vs 截图备注原文，工程师选择"确认铭牌/确认截图/驳回"三选一 |
| 异常工况表 | 实验老师复核 | 负方向写"向左"等模糊表述不自动归正常，留待实验老师标记最终方向与结论 |
| 历史记录页 | 操作时间线 | 每条记录的创建、修改、补录、裁决等操作按时间排列，不可删除 |
| 历史记录页 | 补录追溯 | 补录数据标黄显示，关联原始记录，补录后自动触发重算 |
| 自检与导出页 | 自检面板 | 一键运行四项自检：重复导入检测、负方向异常检测、补录重算验证、导出一致性校验 |
| 自检与导出页 | 报告导出 | 导出含原始数据+截图备注+冲突裁决+自检结果的完整报告（JSON/CSV） |

## 3. 核心流程

### 3.1 主流程：铭牌导入 → 截图审核 → 异常表更新

设备工程师何工首次导入设备铭牌参数，随后查看维修群截图，系统自动比对发现冲突后更新异常工况表，实验老师对模糊表述进行最终复核。

```mermaid
flowchart TD
    "A[设备铭牌参数首次导入]" --> "B[录入弯曲损耗数据]"
    "B" --> "C[上传维修群截图+备注]"
    "C" --> "D{铭牌参数 vs 截图备注是否冲突?}"
    "D" -->|"无冲突"| "E[数据归入正常记录]"
    "D" -->|"有冲突"| "F[生成冲突条目-列出双方证据]"
    "F" --> "G[设备工程师何工裁决]"
    "G" -->|"确认铭牌"| "H[以铭牌为准-标记截图为参考]"
    "G" -->|"确认截图"| "I[以截图为准-标记铭牌需修正]"
    "G" -->|"驳回"| "J[退回现场重新采集]"
    "B" --> "K{负方向写为'向左'?}"
    "K" -->|"是"| "L[标记待复核-不自动归正常]"
    "K" -->|"否"| "E"
    "L" --> "M[实验老师复核]"
    "M" --> "N[标记最终方向与结论]"
```

### 3.2 自检流程

```mermaid
flowchart TD
    "A[触发自检]" --> "B[重复导入检测]"
    "A" --> "C[负方向异常检测]"
    "A" --> "D[补录后重算验证]"
    "A" --> "E[导出一致性校验]"
    "B" --> "F[生成自检报告]"
    "C" --> "F"
    "D" --> "F"
    "E" --> "F"
    "F" --> "G{自检是否全部通过?}"
    "G" -->|"通过"| "H[允许导出]"
    "G" -->|"未通过"| "I[展示失败项-引导修复]"
```

## 4. 用户界面设计

### 4.1 设计风格

- **主色调**：深青蓝 (#0F4C5C) 搭配警告橙 (#E36414)，体现工业严谨与异常警示的对比
- **辅助色**：浅灰底 (#F7F9FC)，补录数据标黄 (#FBBF24)
- **按钮风格**：圆角 6px，主操作实心填充，次要操作描边
- **字体**：标题用 Noto Sans SC Bold，正文用 Noto Sans SC Regular，数据表格用 JetBrains Mono
- **布局**：左侧固定导航栏 + 右侧内容区，表格为主的信息密度型布局
- **图标**：使用 Lucide Icons 线性图标集，简洁工业风

### 4.2 页面设计概览

| 页面名称 | 模块名称 | UI要素 |
|----------|----------|--------|
| 数据录入页 | 铭牌参数导入 | 卡片式表单，顶部状态指示器显示"基准已锁定/待导入"，CSV拖拽上传区 |
| 数据录入页 | 弯曲损耗数据录入 | 表格式录入行，方向字段为下拉选择（+X/-X/向左/向右），负方向"向左"行橙色边框 |
| 数据录入页 | 维修群截图上传 | 左右分栏：左侧截图缩略图列表，右侧放大预览+备注文本框 |
| 异常工况表 | 冲突检测引擎 | 表格行内红色标签"冲突"，点击展开侧边抽屉显示双方证据 |
| 异常工况表 | 工程师裁决面板 | 侧边抽屉：上部对比展示铭牌 vs 截图，下部三个裁决按钮 |
| 异常工况表 | 实验老师复核 | 黄色标签"待复核"行，复核按钮弹出模态框填写最终结论 |
| 历史记录页 | 操作时间线 | 垂直时间线组件，补录节点黄色圆点，裁决节点蓝色圆点 |
| 历史记录页 | 补录追溯 | 补录行黄色背景高亮，hover显示关联原始记录链接 |
| 自检与导出页 | 自检面板 | 四个自检卡片，通过绿色对勾/失败红色叉号，失败项可展开详情 |
| 自检与导出页 | 报告导出 | 导出按钮组（JSON/CSV），导出前自动触发自检，未通过则禁止导出 |

### 4.3 响应式

- 桌面优先设计，最小支持 1280px 宽度
- 表格在窄屏下可横向滚动
- 截图预览支持放大缩小手势
