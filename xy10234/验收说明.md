# 影棚道具借用押金 CLI - 验收说明

## 系统概述

本系统实现了影棚道具借用押金管理的核心规则，覆盖：
1. 道具档案管理
2. 借用单管理
3. 押金冻结与结算
4. 损坏和延期费用计算
5. 脏数据处理
6. 报告生成

---

## 核心业务规则验证方式

### 规则 1：押金冻结规则

**规则说明**：
- 所需押金 = 道具价值 × 押金比例
- 默认押金比例：1.0（100%）
- 押金比例范围：0 - 2（0% - 200%）
- 押金不足时，借用单状态为 PENDING（待确认）
- 押金足额时，借用单状态为 ACTIVE（活动中），道具状态变为 BORROWED（已借用）

**验证方式**：
```bash
# 1. 查看道具档案，确认押金计算
python3 cli.py query props
# 观察：所需押金 = 价值 × 押金比例

# 2. 查看借用单详情
python3 cli.py query borrow B001
# 观察：所需押金与道具档案一致
# 观察：状态为 active（押金已足额）
```

**测试用例**（示例数据中的 P003）：
- 道具价值：¥15,000
- 押金比例：150%
- 所需押金：¥22,500
- 结果：借用单 B003 状态为 active

---

### 规则 2：归还时的费用计算

**规则说明**：

#### 2.1 延期费用
- 延期费 = 所需押金 × 0.1 × 逾期天数
- 逾期天数 = 实际归还日期 - 计划归还日期（> 0 时）
- 按时归还不产生延期费

#### 2.2 损坏费用
| 损坏程度 | 费率 | 计算规则 | 最低费用 |
|---------|------|---------|---------|
| 无损坏 (none) | 0% | 0 | - |
| 轻微损坏 (minor) | 10% | 道具价值 × 0.1 | ¥50 |
| 严重损坏 (major) | 30% | 道具价值 × 0.3 | ¥50 |
| 报废 (total) | 100% | 道具价值 × 1.0 | ¥50 |

#### 2.3 退款计算
- 应退押金 = 已交押金 - (损坏费 + 延期费)
- 应退押金 < 0 时，退款为 0

**验证方式**：
```bash
# 1. 处理按时归还、无损坏的借用单
python3 cli.py process-return B004 --return-date 2026-05-08 --damage none
# 验证：
# - 计划归还: 2026-05-08
# - 实际归还: 2026-05-08
# - 预期：延期费 ¥0，损坏费 ¥0，退款 ¥30,000

# 2. 处理逾期、轻微损坏的借用单
python3 cli.py process-return B005 --return-date 2026-05-07 --damage minor
# 验证（道具 P005）：
# - 道具价值: ¥2,000，所需押金: ¥1,000
# - 计划归还: 2026-05-05，实际归还: 2026-05-07 → 逾期 2 天
# - 延期费 = 1000 × 0.1 × 2 = ¥200
# - 轻微损坏费 = 2000 × 0.1 = ¥200 (> ¥50 最低)
# - 总费用 = ¥400
# - 退款 = 1000 - 400 = ¥600
```

### 规则 3：状态流转规则

**规则说明**：

#### 道具状态流转
```
AVAILABLE (可借用)
    ↓ 创建借用单（押金足额）
BORROWED (已借用)
    ↓ 归还
MAINTENANCE (维护中) ← 严重损坏/报废时
AVAILABLE (可借用)    ← 无损坏/轻微损坏时
```

#### 借用单状态流转
```
PENDING (待确认)   ← 押金不足
    ↓ 补足押金
ACTIVE (活动中)    ← 押金足额
    ↓ 超过计划归还日期
OVERDUE (逾期)
    ↓ 归还
RETURNED (已归还)
    ↓ 结算
SETTLED (已结算)
```

**验证方式**：
```bash
# 1. 检查逾期借用单
python3 cli.py check overdue --date 2026-05-11
# 观察：B001 计划归还 2026-05-10，检查日期 2026-05-11 → 状态变为 overdue

# 2. 查看所有借用单状态
python3 cli.py query borrows
# 观察各借用单的状态流转

# 3. 查看道具状态变化
python3 cli.py query props
# 观察已借用道具的状态变化
```

### 规则 4：脏数据处理

**规则说明**：
- 脏数据**不静默跳过**，进入问题列表
- 问题记录包含：来源文件、行号、原始数据、错误类型、错误信息
- 重复数据自动跳过（不报错、不进入问题列表）
- 问题记录可查询、可标记为已修复

**验证方式**：
```bash
# 1. 导入包含脏数据的文件
python3 cli.py import props sample_data/dirty_props.xlsx
# 观察输出：
# - 成功: 0 条
# - 跳过: 1 条（重复ID P001）
# - 失败: 4 条
# - 显示每个失败的具体错误

# 2. 查看问题记录
python3 cli.py query problems
# 观察：
# - 来源文件、行号
# - 错误类型、错误信息
# - 原始数据保留

# 3. 查看问题报告
python3 cli.py report problems
# 生成 Excel 报告，包含所有问题详情
```

**脏数据测试用例**（sample_data/dirty_props.xlsx）：
| 行号 | 测试内容 | 预期错误 |
|-----|---------|---------|
| 2 | 缺少道具ID | 缺少必需字段: prop_id |
| 3 | 缺少道具名称 | 缺少必需字段: name |
| 4 | 价值为负数 | 道具价值必须大于0: -500.0 |
| 5 | 押金比例超范围 | 押金比例应在0-2之间: 3.0 |
| 6 | 重复ID P001 | 跳过（不报错） |

---

### 规则 5：一致性检查

**规则说明**：
系统自动检查以下一致性：
1. 道具状态与借用单状态一致
   - 道具状态为 BORROWED 时，必须有活动借用单
   - 有活动借用单时，道具状态必须为 BORROWED
2. 押金金额一致性
   - 借用单的所需押金必须等于当前道具的计算值
3. 退款计算正确性
   - 已归还借用单的退款金额必须重新计算验证

**验证方式**：
```bash
# 运行一致性检查
python3 cli.py check consistency
# 输出："数据一致性检查通过，未发现异常" 或列出所有异常

# 业务报告中也包含一致性检查结果
python3 cli.py report business
# 报告的"警告与异常"标签页包含所有一致性问题
```

## CLI 命令清单

### 导入数据
```bash
python3 cli.py import props <文件路径>     # 导入道具档案
python3 cli.py import borrows <文件路径>   # 导入借用单
python3 cli.py import returns <文件路径>   # 导入归还记录
```

### 查询数据
```bash
python3 cli.py query props                 # 列出所有道具
python3 cli.py query props --status borrowed  # 按状态筛选
python3 cli.py query props --category 家具     # 按分类筛选

python3 cli.py query borrows               # 列出所有借用单
python3 cli.py query borrows --status active  # 按状态筛选
python3 cli.py query borrows --crew 时光协奏曲  # 按剧组筛选

python3 cli.py query prop <道具ID>         # 查看道具详情
python3 cli.py query borrow <借用单ID>     # 查看借用单详情
python3 cli.py query problems              # 查看问题记录
```

### 检查和验证
```bash
python3 cli.py check summary               # 汇总统计
python3 cli.py check overdue               # 检查逾期（基于今天）
python3 cli.py check overdue --date 2026-05-11  # 基于指定日期检查
python3 cli.py check consistency           # 数据一致性检查
```

### 业务操作
```bash
python3 cli.py process-return <借用单ID> \
    --return-date 2026-05-10 \
    --damage none|minor|major|total
    [--damage-fee 金额] [--delay-fee 金额]

python3 cli.py settle <借用单ID> \
    [--additional-payment 追加付款金额]
```

### 报告生成
```bash
python3 cli.py report summary              # 押金汇总报告
python3 cli.py report overdue              # 逾期报告
python3 cli.py report damage               # 损坏报告
python3 cli.py report problems             # 问题记录报告
python3 cli.py report business             # 业务负责人汇总报告
```

### 其他
```bash
python3 cli.py info                        # 系统信息
python3 cli.py fix problem <问题ID>        # 标记问题已修复
```

## 快速开始

