# 报销票据匹配系统

一个面向财务场景的全栈Web应用，解决员工上传票据后需要手工匹配行程、预算和重复发票的问题。

## 功能特性

### 核心功能
- ✅ **票据列表筛选**：支持按状态、员工、类别、日期范围筛选票据
- ✅ **票据详情时间线**：记录票据的完整状态变更历史
- ✅ **批量导入**：支持JSON格式批量导入票据数据
- ✅ **匹配报告下载**：生成Excel格式的匹配报告，包含完整统计信息

### 匹配规则引擎
- ✅ **自动匹配**：基于行程日期、金额、类别自动匹配
- ✅ **重复检测**：基于发票号码、金额+日期自动检测重复票据
- ✅ **人工匹配**：支持财务人员手动关联行程和预算科目
- ✅ **匹配确认**：支持确认匹配结果，锁定状态

### 数据模型
- 📊 **票据图片**：存储发票的完整信息（号码、代码、日期、金额、销售方等）
- 📋 **报销单**：报销申请单据
- 🚗 **行程记录**：员工出差行程信息
- 💰 **预算科目**：预算分类和额度管理
- 🚩 **重复票据**：重复检测结果记录
- ✅ **匹配结果**：匹配过程和结果记录

## 技术栈

### 后端
- **Node.js** + **Express** - 服务端框架
- **TypeScript** - 类型安全
- **SQLite** - 持久化数据库（无需额外安装）
- **ExcelJS** - 报表生成

### 前端
- **React 18** + **TypeScript** - 前端框架
- **Ant Design 5** - UI组件库
- **Vite** - 构建工具
- **Axios** - HTTP客户端

## 快速开始

### 1. 安装依赖

```bash
# 安装所有依赖
npm run install:all
```

或者分别安装：

```bash
# 安装后端依赖
cd server && npm install

# 安装前端依赖
cd ../client && npm install
```

### 2. 初始化演示数据

```bash
# 在项目根目录执行
npm run seed
```

这将创建：
- 5个预算科目
- 4条行程记录
- 10+条票据数据（包含自动匹配、重复检测等场景）

### 3. 启动开发服务

```bash
# 同时启动前后端（推荐）
npm run dev

# 或单独启动
npm run dev:server  # 后端服务 (http://localhost:3001)
npm run dev:client  # 前端服务 (http://localhost:5173)
```

### 4. 访问应用

打开浏览器访问：**http://localhost:5173**

## API接口说明

### 票据相关
- `GET /api/invoices` - 获取票据列表（支持分页筛选）
- `GET /api/invoices/:id` - 获取票据详情
- `POST /api/invoices` - 创建票据
- `POST /api/invoices/batch` - 批量导入票据
- `POST /api/invoices/:id/match` - 人工匹配

### 匹配相关
- `POST /api/matches/:id/confirm` - 确认匹配结果

### 重复票据相关
- `POST /api/duplicates/:id/resolve` - 处理重复票据

### 基础数据
- `GET /api/trips` - 获取行程列表
- `GET /api/budgets` - 获取预算科目列表

### 统计和报表
- `GET /api/statistics` - 获取统计数据
- `POST /api/reports` - 生成匹配报告
- `GET /api/reports/:fileName` - 下载报告

## 使用流程演示

### 1. 票据上传
- 员工上传票据（支持单条创建或JSON批量导入）
- 系统自动提取发票号码、金额、日期等信息
- 自动触发重复检测

### 2. 自动匹配
- 系统根据员工、日期、金额等维度自动匹配行程
- 根据票据类别自动匹配预算科目
- 生成匹配得分，高于阈值自动确认

### 3. 重复检测处理
- 检测到重复票据时标记状态
- 财务人员可以选择：
  - 保留原始，驳回重复
  - 用新票据替换原始
  - 两张都保留（特殊场景）

### 4. 人工匹配
- 待匹配的票据支持人工操作
- 选择关联的行程记录
- 选择预算科目
- 添加备注说明

### 5. 生成报告
- 导出所有票据的匹配情况
- 包含统计汇总（总数、已匹配、待匹配、重复等）
- Excel格式，便于存档和审计

## 状态流转

```
待匹配 (pending)
    ↓
[自动匹配/人工匹配]
    ↓
已匹配 (matched)
    ↓
[确认匹配]
    ↓
已确认 (confirmed)

待匹配 (pending)
    ↓
[重复检测]
    ↓
重复 (duplicate)
    ↓
[处理重复]
    ↓
已驳回 / 待匹配 (重新匹配)
```

## 数据持久化

所有数据存储在 `server/data/` 目录下：
- `reimbursement.db` - SQLite数据库文件
- `reports/` - 生成的Excel报告文件

重启服务后所有状态和历史数据都会保留。
