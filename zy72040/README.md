## 📖 操作指南

### 一、开始游戏

1. **输入学员姓名**：在首页输入框填写学员姓名（默认"张三"）
2. **选择关卡**：点击关卡卡片开始游戏
   - `汛期第一轮洪峰` - 正常难度，3个事件
   - `多阶段综合调度` - 困难难度，4个事件
   - 测试关卡（带 🧪 标记）：用于系统测试

### 二、游戏流程

1. 阅读当前事件描述
2. 查看入库流量变化
3. 选择应对方案（点击决策按钮）
4. 观察资源变化：
   - 🌊 水位（警戒185m，防洪195m）
   - 📦 库容（警戒4200万m³，防洪4800万m³）
   - 💧 下泄流量
   - ⭐ 得分
5. 处理完所有事件后自动进入结算

### 三、结算说明

结算页面包含：
- **基本信息**：得分、评级、用时、处理事件数
- **扣分详情**：列出每一次扣分的事件、选择、原因和扣分值
- **决策回顾**：时间线展示完整决策过程，包括每一步后的资源状态
- **异常标记**：资源负值、边界越界、重复事件等会高亮显示

### 四、查看历史记录

1. 点击顶部导航 `📚 历史记录`
2. **筛选功能**：
   - 按状态筛选：全部/正常/有警告/待确认/已复核
   - 按关卡筛选
   - 只看旧口径记录
3. **记录操作**：
   - 查看详情：查看完整决策过程
   - 标记已复核：对待确认记录添加复核备注
   - 删除：删除单条记录
4. **快速统计**：顶部显示各类状态的记录数量

### 五、导入旧口径数据

点击历史记录页面的「导入旧口径」按钮，可导入老师错题本中的历史记录。导入的记录会标记 `📜 旧口径` 标签，并注明来源。

## 🔄 更换关卡

### 方法一：直接修改配置文件

编辑 `data/levels.json` 文件，添加或修改关卡配置。

#### 关卡配置格式：
```json
{
  "id": "level_001",
  "name": "关卡名称",
  "description": "关卡描述",
  "difficulty": "easy|normal|hard|test",
  "events": [
    {
      "id": "evt_001",
      "timePoint": 0,
      "title": "事件标题",
      "description": "事件详细描述",
      "inflowChange": 20,
      "decisions": [
        {
          "id": "dec_001_a",
          "label": "选项1",
          "effects": { "discharge": 50, "score": 0 },
          "explanation": "选择后的分析说明"
        }
      ]
    }
  ]
}
```

#### 资源类型说明：
| 资源 | 说明 | 单位 | 初始值 | 警戒值 | 防洪值 | 范围 |
|------|------|------|--------|--------|--------|------|
| waterLevel | 水位 | m | 150 | 185 | 195 | 0-200 |
| storage | 库容 | 万m³ | 3000 | 4200 | 4800 | 0-5000 |
| discharge | 下泄流量 | m³/s | 50 | - | - | 0-500 |
| score | 得分 | 分 | 100 | - | - | 0-100 |

#### effects 可用字段：
- `waterLevel`: 水位变化量
- `storage`: 库容变化量
- `discharge`: 下泄流量变化量
- `score`: 得分变化量（正数加分，负数扣分）

### 方法二：准备全新配置

将新的配置文件保存为 `data/levels.json`，刷新页面即可生效。

## ⚠️ 异常场景处理

系统已内置以下异常场景的处理逻辑：

### 1. 空关卡
- 检测：`events` 为空数组或 `null`
- 处理：直接结算，标记 `empty_level` 原因

### 2. 重复事件ID
- 检测：同一关卡内出现相同 `event.id`
- 处理：记录继续执行，但标记重复ID，结算时显示警告

### 3. 资源超出边界
- 检测：资源值超过配置的 `min`/`max`
- 处理：自动钳位到边界值，记录越界警告，标记 `has_warnings` 状态

### 4. 资源负值
- 检测：任何资源变为负数
- 处理：
  - 标记 `needs_manual_review` 状态
  - 弹出确认框询问是否继续
  - 结算时高亮显示，需要讲师人工确认
  - 历史记录中标记为"待确认"

### 5. 补录材料
从错题本导入的旧数据会：
- 自动标记 `isOldCaliber: true`
- 记录来源 `source` 字段
- 显示 `📜 旧口径` 标签
- 可单独筛选查看

## 📝 给老冯的交接说明

### 日常使用流程：
1. 启动服务器 → 学员输入姓名 → 选择关卡 → 完成演练 → 查看结算
2. 历史记录页面随时查看所有学员记录
3. 待确认的记录会红色标记，点击「标记已复核」添加备注
4. 旧口径数据可通过「导入旧口径」按钮录入

### 常见问题：
- **数据加载失败**：确保通过HTTP服务器访问，而非直接打开文件
- **记录丢失**：数据存在浏览器 localStorage，换浏览器/清缓存会丢失
- **需要导出数据**：可在浏览器控制台执行 `copy(localStorage.getItem('flood_sandbox_history'))` 复制

### 扩展建议：
- 新增关卡直接编辑 `data/levels.json`
- 调整资源边界修改 `levels.json` 中的 `resourceConfig`
- 修改评分规则在 `gameEngine.js` 的 `getGameResult` 方法
