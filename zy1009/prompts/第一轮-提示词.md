我想给小区团购团长做一个本地可运行的预售订单小工具。每周三晚上截单，团长会先录入本周商品、每个用户的订单和取货时间段；如果某个商品临时缺货，要能把受影响的订单标成“待确认替换”，给出可替换商品和差价，用户确认后再自动更新订单金额。

请从零做一个全栈 Web 应用，前端要有商品维护、订单录入/编辑、缺货替换处理、按取货时间分组的发货清单，以及一个能查看每个用户待付款/已确认/需替换状态的页面；后端要提供对应 API 并把数据持久化到本地文件或轻量数据库里，刷新页面后不能丢。还需要支持把本周订单导入 CSV、把最终发货清单导出 CSV，并在 README 里写清楚怎么安装、启动和验证核心流程。

我希望它不是只有静态页面：请把金额计算、替换确认、订单状态流转、CSV 导入导出这些逻辑真正串起来，至少准备一组示例数据，启动后可以直接跑通“录商品 -> 录订单 -> 标记缺货 -> 确认替换 -> 导出发货清单”的流程。
