# 轨交站口雨棚排查系统

市政巡检和街道规划工作中的雨棚排查、数据溯源和复核流程管理系统。

## 核心特性

### 📋 三步标准工作流
1. **导入路口照片** - 批量上传 CSV，自动去重，保留原始行号
2. **补看公交刷卡时段** - 规划员逐条处理，补充数据，添加备注理由
3. **更新街道会摘要** - 汇总统计，可钻取查看详情和保留理由

### 🔍 数据溯源与证据链
- 每条记录保留**原始行号**、导入文件信息
- 所有字段修改记录**完整历史**（改前值、改后值、操作人、时间、原因）
- 支持**回滚**到任意历史版本，回滚操作本身也记录历史
- 市政巡检员追问时可一键回到原始证据

### ⚠️ 同一小区新旧名称边界规则
> **规则写在代码里，不靠口头约定！**

| 规则类型 | 判定逻辑 | 处理方式 | 是否可回滚 |
|---------|---------|---------|-----------|
| 常见后缀差异 | 阳光新村 ≈ 阳光小区 ≈ 阳光花园（提取核心词匹配） | 自动标记「待复核」，不自动归正常 | ✅ 是 |
| 期数/方位前缀 | 东方明珠一期 ≈ 东方明珠二期 ≈ 明珠东区 | 自动标记「待复核」，不自动归正常 | ✅ 是 |
| 全称/简称差异 | 上海市浦东新区阳光小区 ≈ 阳光小区 | 自动标记「待复核」，不自动归正常 | ✅ 是 |
| 编辑距离接近 | 编辑距离 ≤ 1 且同轨交站 | 自动标记「待复核」 | ✅ 是 |

**重要原则**：疑似同名小区**绝不自动归为正常**，必须留给市政巡检员人工复核确认。

### 🚫 重复导入保护
- 按「小区名称 + 轨交站 + 原始行号」三元组去重
- 重复条目不增加排查总数
- 导入前预览显示哪些是新增、哪些重复将跳过

### 📊 街道会摘要（可钻取）
- 不是只给一个汇总数
- 每条疑似同名、每条问题记录都可以**点开看详情**
- 能看到街道规划员小姜当时**保留它的理由**
- 包含原始行号、照片描述、公交刷卡时段等完整证据

## 使用指南

### 第一次使用
1. 进入「第一步：导入路口照片」页面
2. 点击「加载示例数据（演示用）」体验完整流程
3. 或上传自己的 CSV 文件（列名：小区名称、轨交站、照片描述）

### 标准作业流程
1. **街道规划员小姜**：
   - 导入路口照片数据
   - 切换到第二步，逐条补看公交刷卡时段
   - 对疑似同名小区，在「规划员备注」中写明判断理由
   - 处理完后进入第三步生成摘要

2. **市政巡检员**：
   - 切换身份为「市政巡检员」
   - 重点查看标记为「待复核」的疑似同名记录
   - 在「巡检员备注」中写明复核意见
   - 最终判定状态为「已确认正常」或「有问题」

3. **街道会汇报**：
   - 打开摘要页面
   - 领导问到某条时，点击展开查看完整证据链
   - 包含规划员理由、巡检员意见、原始行号等

### 历史追溯
- 在记录详情页点击「查看变更历史 / 回滚」
- 看到每次修改的改前改后对比
- 需要时点击「回滚到此版本」

## 数据持久化

- 所有数据存储在浏览器 LocalStorage 中
- 刷新页面数据不会丢失
- 建议定期导出 JSON 备份（功能开发中）

## 技术栈

- React 18 + TypeScript
- Vite 构建工具
- TailwindCSS 样式
- Zustand 状态管理（带持久化）
- Lucide React 图标
- PapaParse CSV 解析
