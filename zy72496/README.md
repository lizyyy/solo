# 轨交站口雨棚排查系统

市政巡检和街道规划工作中的雨棚排查、数据溯源和复核流程管理系统。

## 核心特性

### 📋 三步标准工作流
1. **导入路口照片** - 批量上传 CSV，自动去重，保留原始行号
2. **补看公交刷卡时段** - 规划员逐条处理，补充数据，添加备注理由
3. **更新街道会摘要** - 汇总统计，可钻取查看详情和保留理由

### 🔍 数据溯源与证据链
- 每条记录保留**原始行号**、导入文件信息
- 所有字段修改记录**完整历史**（改前值、改后值、操作人、时间、原因）
- 支持**回滚**到任意历史版本，回滚操作本身也记录历史
- 市政巡检员追问时可一键回到原始证据

### ⚠️ 同一小区新旧名称边界规则
> **规则写在代码里，不靠口头约定！**

| 规则类型 | 判定逻辑 | 处理方式 | 是否可回滚 |
|---------|---------|---------|-----------|
| 常见后缀差异 | 阳光新村 ≈ 阳光小区 ≈ 阳光花园（提取核心词匹配） | 自动标记「待复核」，不自动归正常 | ✅ 是 |
| 期数/方位前缀 | 东方明珠一期 ≈ 东方明珠二期 ≈ 明珠东区 | 自动标记「待复核」，不自动归正常 | ✅ 是 |
| 全称/简称差异 | 上海市浦东新区阳光小区 ≈ 阳光小区 | 自动标记「待复核」，不自动归正常 | ✅ 是 |
| 编辑距离接近 | 编辑距离 ≤ 1 且同轨交站 | 自动标记「待复核」 | ✅ 是 |

**重要原则**：疑似同名小区**绝不自动归为正常**，必须留给市政巡检员人工复核确认。

### 🚫 重复导入保护（三模式 + 备注全程不丢）
> **不把备注覆盖成最终值，历史里永远留住原话、修改人、修改原因！**

| 模式 | 适用场景 | 行为 |
|------|---------|------|
| **模式一：完全跳过（推荐）** | 只是补传，原记录已维护 | 复用原记录 ID，不动任何字段，备注/状态/历史全保留，总数不翻倍 |
| **模式二：覆盖照片保留备注** | 照片更新但规划员工作不丢 | 只更新照片描述，备注/状态/公交刷卡全部保留，覆盖原因写入历史 |
| **模式三：全部覆盖（慎用）** | 需连公交刷卡一起更 | 覆盖照片+公交刷卡，但备注/状态仍保留并记录历史原因 |

- 导入预览表格**单独标注「真新增」「复用记录（有差异待更新）」**
- 导入结果卡片**四区分离：处理总数/真新增/复用记录/覆盖更新**
- 任何覆盖操作都**不直接覆盖备注**，规划员原话和修改人永远可追溯

### 🔄 怎么改、怎么回滚（闭环保证）
> **同一字段可无限回滚仍可追溯，改前改后每一步都能解释！**

| 环节 | 在哪里做 | 留下的证据 |
|------|---------|-----------|
| **① 怎么改（改备注）** | 详情页字段 → 编辑按钮 → 保存 | 自动生成历史：操作人、时间、改前值、改后值、原因「字段编辑」 |
| **② 改后查看** | 详情页字段下方 → 点击「变更 X 次」展开 | 按时间倒序显示所有改动：谁改的、什么时候、改了什么、为什么改 |
| **③ 怎么回滚** | 在展开的变更列表 → 点「回滚到此版本」按钮 | 弹窗完整显示：改前、改后、操作人、原时间、回滚链说明，二次确认 |
| **④ 回滚结果闭环** | 回滚本身生成一条新历史 | 变更原因写：`回滚至 [时间] XXX 的改动：从 "A" → "B"`，仍可再回滚 |

> **回滚闭环保证**：任何时点的状态都能「从哪来回哪去」，回滚操作不删除任何历史，而是追加一条新记录。同一份可解释结果永远可复现。

### 📊 街道会摘要（可钻取）
- 不是只给一个汇总数
- 每条疑似同名、每条问题记录都可以**点开看详情**
- 能看到街道规划员小姜当时**保留它的理由**
- 包含原始行号、照片描述、公交刷卡时段等完整证据

## 使用指南

### 第一次使用
1. 进入「第一步：导入路口照片」页面
2. 点击「加载示例数据（演示用）」体验完整流程
3. 或上传自己的 CSV 文件（列名：小区名称、轨交站、照片描述）

### 标准作业流程
1. **街道规划员小姜**：
   - 导入路口照片数据
   - 切换到第二步，逐条补看公交刷卡时段
   - 对疑似同名小区，在「规划员备注」中写明判断理由
   - 处理完后进入第三步生成摘要

2. **市政巡检员**：
   - 切换身份为「市政巡检员」
   - 重点查看标记为「待复核」的疑似同名记录
   - 在「巡检员备注」中写明复核意见
   - 最终判定状态为「已确认正常」或「有问题」

3. **街道会汇报**：
   - 打开摘要页面
   - 列表中每条可一眼看到：「复用记录」「X 次变更」「备注改前改后可查」等标签
   - 领导问到某条时，点击展开查看完整证据链：原始行号、导入批次、规划员理由、巡检员意见、变更统计
   - 每条详情底部有「查看变更历史/回滚」入口，可进入完整溯源页

### 实际复现：怎么改、怎么回滚闭环
> **街道规划员小姜只改一条备注，如何完整闭环？**

1. **怎么改**
   - 工作区打开某条记录，在「规划员备注」字段点击 ✏️ 编辑按钮
   - 写入备注后点击「保存」
   - 此时字段下方出现一条「变更 1 次 · 最近操作：小姜 · XX:XX」的提示，点击展开

2. **查看改前改后**
   - 展开后看到：时间、操作人（小姜）、变更原因（字段编辑）、改前值（删除线）→ 改后值（绿色高亮）
   - 每个历史条目都是一条完整的独立证据

3. **怎么回滚**
   - 在展开的历史列表中，找到要回滚到的那条，点击「回滚到此版本」
   - 确认弹窗显示：完整的改前、改后、操作人、原时间、回滚链说明
   - 二次确认后，字段值还原

4. **闭环验证**
   - 回滚完成后，历史列表最上方新增一条「回滚操作」标签的记录
   - 变更原因写明：「回滚至 [时间] 小姜 的改动：从 A → B」
   - 此时仍可从最新的回滚操作再点击「回滚到此版本」回到改后值

**保证**：回滚永远不删除任何证据，只会在历史链上继续追加新的节点。

### 实际复现：重复导入不翻倍、备注不覆盖
> **同一批路口照片第一次导入后第二次导入，如何正确处理？**

1. **第一次导入**
   - 上传 CSV，预览表格区分：「真新增」(绿色) 与其他
   - 结果显示：处理总数 / 真新增 / 复用记录（0） / 覆盖更新（0）

2. **第二次导入同一批**
   - 回到导入页，点击「模拟重复导入同一批」（或上传相同文件）
   - 预览表格区分：
     - **真新增**（绿色）：新文件比上一批多的
     - **复用记录**（蓝色）：与之前三元组匹配的
     - **有差异待更新**（黄色）：同样的记录但照片描述变了
   - 选择处理模式：推荐「模式一：完全跳过」或「模式二：覆盖照片保留备注」

3. **结果验证**
   - 导入后统计：真新增 X 条，复用记录 Y 条（总数 = 之前 + X，**不会**变成 2x）
   - 打开之前写过备注的那条记录：备注**保留原话**，修改人仍是小姜
   - 若选了模式二且有差异：「路口照片描述」字段下方展开历史，可看到一条「重复导入覆盖」记录，保留覆盖前后值，可回滚到覆盖前的描述

### 历史追溯（两种入口）
- **入口一（详情页快速回滚）**：每个可编辑字段下方 → 点击「变更 X 次」展开 → 直接回滚
- **入口二（完整溯源页）**：详情页底部「查看完整变更历史 / 回滚」按钮 → 按字段分组的时间线视图，包含回滚链说明、变更/回滚操作统计、闭环规则文档

## 数据持久化

- 所有数据存储在浏览器 LocalStorage 中
- 刷新页面数据不会丢失
- 建议定期导出 JSON 备份（功能开发中）

## 技术栈

- React 18 + TypeScript
- Vite 构建工具
- TailwindCSS 样式
- Zustand 状态管理（带持久化）
- Lucide React 图标
- PapaParse CSV 解析
