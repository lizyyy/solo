# 水轮机效率回放系统

## 一、系统定位

这不是一个功能清单，而是一份**可复盘的记录**和**可重新跑的命令集**。
所有数据变更都有迹可循，所有边界规则都写死在代码里，不靠口头约定。

---

## 二、边界规则（代码与本文档同步生效）

### 规则 1：采样时间缺半小时判定

**判定条件**：
- 相邻两条记录的采样时间间隔 > 30 分钟
- 或者单条记录的采样时长 < 理论值的 50%

**处理方式**：
1. 自动标记为 `NEED_QC_REVIEW`（待质检员复核）
2. **绝不**自动归为正常，**绝不**在任何视图中隐藏
3. 页面、导出、API 接口三处显示完全一致
4. 必须由质检员手动确认后才能变更状态

**回滚方式**：
- 任何状态变更都记录在 `audit_log` 中
- 执行 `npm run replay -- --record-id=<id>` 可回退到任意历史版本

---

### 规则 2：传感器编号审计追踪

每条传感器记录必须保留：
- `original_line_no`：原始导入行号（不可篡改）
- `import_batch_id`：导入批次号
- `manual_changes[]`：所有人工改动的历史（谁、什么时候、改了什么、为什么）
- `current_status`：当前处理状态
- `status_history[]`：状态流转全记录

---

### 规则 3：三步工作流强制

```
传感器编号导入 → 设备工程师补看工况照片 → 实验复盘图更新
     ↓                    ↓                        ↓
 STATUS_IMPORTED    STATUS_ENGINEER_REVIEWED    STATUS_FINALIZED
```

- 不能跳步
- 每步执行人、时间、备注都留痕
- 中间碰到「采样时间缺半小时」，强制停在 `NEED_QC_REVIEW`

---

### 规则 4：返工场景支持

允许结论被推翻重来，但必须：
1. 新的工况照片作为证据上传
2. 写明返工原因
3. 旧结论不删除，标记为 `SUPERSEDED`
4. 实验复盘图更新时，新旧两版都能看到对比

---

## 三、快速开始

```bash
# 安装依赖
npm install

# 运行完整演示场景（包含返工场景）
npm run demo

# 启动服务（访问 http://localhost:3000）
npm start

# 重放某条记录的审计日志
npm run replay -- --record-id=REC-001

# 导入传感器数据
npm run import -- --file=data/sample-sensors.csv

# 导出数据（页面、API、导出共用同一份）
npm run export -- --format=csv

# 边界规则单元测试
npm run test:boundary
```

---

## 四、数据一致性保证

**单一数据源原则**：
- 所有读取操作（页面展示、API 返回、文件导出）都走 `dataStore.getUnifiedView()`
- 不存在多份数据副本
- 「采样时间缺半小时」的记录，在任何地方都以同样的状态显示
