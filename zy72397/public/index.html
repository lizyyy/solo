📋 可重新跑的命令集（参数规范写死在代码里，不靠口头）

npm run demo — 从0开始：导入→三步流程→(采样缺半小时QC复核)→结论→返工→回滚→核对导出
重点核对：REC-002(采样缺半小时) 旧结论 SUPERSEDED + superseded_by 写入
npm run verify — 端到端核对（16项断言）：返工SUPERSEDED标记、回滚派生字段、三方字段一致性
失败会打印具体哪条记录哪一字段对不上
npm run replay -- --record-id=REC-002 — 重放指定记录审计日志
输出：状态流转时间线、人工改动、历史结论版本
npm run rollback -- --record-id=REC-002 --version=1 — 回滚到指定status_history索引
同步恢复 qc_review_required / boundary_issues 等派生字段
npm run export -- --format=csv --output=report.csv --needs-qc-review=true — 导出需QC复核记录
字段与页面表格、/api/records 完全同一份 UNIFIED_FIELDS
npm run test:boundary — 边界规则单元测试：间隔/时长阈值、综合判定
README 与 BOUNDARY_RULES 代码同步
