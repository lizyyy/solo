# 热像仪温差校准

## 给何工和训练教练看的交接说明

### 这个工具解决什么问题

热像仪导出的温度校准记录里，同一行有时候同时写了摄氏度（°C）和开尔文（K），原来的判断逻辑会偷偷归成"正常"，结果：

- **导出明细**显示有异常
- **页面展示**又消失了
- **接口返回**又是另一个结果

训练教练追问的时候，找不到原始证据，只能对着汇总数扯皮。

这个工具把所有改动都留在明面上，同一套数据三端都读同一份，谁改了什么、改前改后是什么、为什么改，都查得到。

---

## 三步工作流

### 第一步：采样间隔说明导入

把原始记录整行导入，保留原始行号、原始文本。系统自动检测每一行的单位。

**关键点**：碰到摄氏度和开尔文混用的行，**不会自动归正常**，先标记成"待教练复核"。

### 第二步：设备工程师何工补看

何工看到有混用单位的记录，可以补看备注，但不能直接拍板改单位——必须留给训练教练复核。

**关键点**：如果还有待教练复核的冲突，状态锁在 `PENDING_COACH_REVIEW`，交接报告更新按钮是灰的。

### 第三步：交接报告更新

教练把所有混用单位都复核完、没有待处理冲突了，才能更新交接报告。

## 边界规则（写死在代码里，不靠口头约定）

### 1. 怎么判：摄氏度和开尔文混用的判断

**判断条件**：同一行原始文本里同时检测到摄氏度标识和开尔文标识。

**摄氏度标识**（大小写不敏感）：
- `°C`、`℃`（摄氏度符号）
- `degc`、`deg c`、`degree c`、`celsius`

**开尔文标识**（大小写不敏感）：
- `K`（独立出现，前后有空格或边界）
- `kelvin`、`deg k`、`degk`

**数值合理性辅助判断**（热像仪量程 -40°C ~ 2000°C）：
- 如果数值按开尔文算合理（233.15K ~ 2273.15K）、按摄氏度算不合理：自动转成摄氏度，不需要教练复核
- 比如 `298 K °C`，数值 298 按开尔文算合理（25°C），但按摄氏度算算算算不合理（298°C 超量程），这种自动转
- 两边都能说通的（比如 `300 K °C`，按开尔文算 26.85°C 合理，按摄氏度算 300°C 也合理），必须留给教练复核

### 2. 怎么改：教练复核

教练复核时必须填三个东西：
- `resolved_value`：确认后的数值（比如 25.0）
- `resolved_unit`：确认后的单位（`celsius` 或 `kelvin`）
- `coach_note`：为什么这么判（比如"设备规格书明确是摄氏度"）

**改动留痕**：
```
changed_at: 时间戳
changed_by: 谁改的（训练教练）
field_name: unit_conflict_line_{行号}
old_value: 原始文本
new_value: "25.0 celsius"
reason: 教练备注
```

### 3. 怎么回滚：撤销教练判断

教练判完了又觉得不对，可以回滚。回滚后：
- 冲突记录回到原始状态
- `needs_coach_review` 重新设为 `True`
- 状态回到 `ROLLED_BACK`
- **回滚操作本身也留痕**，可以看到是谁回滚的、为什么回滚

---

## 数据一致性保证

导出明细、页面展示、API 返回，**三者读同一份数据**，都走 `ResultStore` 这一层：

- `get_full_result(record_id)` → 完整数据，给页面展示用
- `export_detail(record_id)` → 同一份数据的 JSON 字符串，给导出用
- `get_summary(record_id)` → 汇总数，但汇总数是从同一份完整数据算出来的

**代码里保证**：没有第二条写数据的路径，所有改动都通过 `CalibrationWorkflow` 接口，改完立刻存回 `ResultStore`。

---

## 原始证据怎么查

训练教练追问的时候，不看汇总数，直接看：

1. **original_line_number**：这条记录在原始文件的第几行
2. **raw_text**：原始文本长什么样，一个字符都没改
3. **manual_changes**：谁在什么时候改了什么字段，改前改后是什么，原因是什么
4. **unit_conflicts**：每一个冲突的处理过程，从检测到判断到回滚，全链路可追溯
