# 喷嘴流量系数标定系统

## 快速开始

### 1. 安装依赖

```bash
npm install
```

### 2. 启动系统

```bash
npm start
```

### 3. 打开浏览器

访问 http://localhost:3000

## 三步完成标定流程

### 第一步：导入设备铭牌参数

- 方式一：拖拽CSV文件到上传区域
- 方式二：点击上传区域选择文件
- 方式三：点击下方**样例数据**按钮快速体验

系统会自动：
- 保留原始行号
- 自动检测温度单位（摄氏度/开尔文）
- 自动执行自检（重复导入、单位混用、计算一致性、导出一致性）

### 第二步：质检员小白补看维修群截图

1. 在【记录明细】标签页查看导入的记录
2. 点击【补录】按钮补充缺失信息
3. 保存后系统会**自动重算流量系数**
4. 发现温度单位混用的记录会标记为**黄色待复核**状态

> ⚠️ **重要**：碰到摄氏度和开尔文混用的记录，**别急着归正常**，留给训练教练复核。

### 第三步：生成交接报告

1. 训练教练点击【复核】按钮
2. 选择处理状态并填写保留理由
3. 点击【生成/更新报告】完成交接

## 自检功能说明

系统自动检查以下四项最容易出错的点：

| 检查项 | 说明 |
|--------|------|
| ✅ 重复导入检查 | 检测同一批次内是否有重复的喷嘴编号 |
| 🌡️ 温度单位混用检查 | 检测摄氏度和开尔文混用情况，自动标记待复核 |
| 🔢 补录重算检查 | 验证补录后流量系数计算的一致性 |
| 📊 导出一致性检查 | 确保页面展示、接口返回、CSV导出使用同一份数据 |

## 数据溯源能力

每条记录都保留：
- **原始行号**：对应CSV文件中的行号，训练教练追问时可回溯
- **人工改动记录**：谁、什么时候、改了什么字段、从什么改到什么
- **当前处理状态**：待处理/待复核/已复核/正常/错误
- **复核备注**：质检员小白保留温度混用记录的理由

## 样例数据说明

`samples/` 目录下提供三个样例文件：

| 文件名 | 用途 |
|--------|------|
| normal-data.csv | 正常数据，单位混用但都正确 |
| mixed-units.csv | 故意混合单位，用于测试自检功能 |
| incomplete-data.csv | 包含缺失字段，用于测试补录功能 |

## API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/import | 导入CSV文件 |
| GET | /api/records | 获取所有记录及自检结果 |
| GET | /api/records/:id | 获取单条记录详情 |
| PUT | /api/records/:id | 补录/修改记录 |
| PUT | /api/records/:id/review | 教练复核 |
| POST | /api/recalculate | 批量重算流量系数 |
| GET | /api/export | 导出CSV |
| POST | /api/handover | 生成交接报告 |
| GET | /api/handover | 获取交接报告 |
| GET | /api/self-check | 执行自检 |
| DELETE | /api/data | 清空所有数据 |

## 数据存储

所有数据保存在 `data/calibration-data.json` 文件中，可直接备份或迁移。
