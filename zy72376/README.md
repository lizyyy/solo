# 喷嘴流量系数标定系统

> 训练教练开会前10分钟也能跑完的标定系统 —— 从样例导入到交接报告全链路可追溯。

## 快速开始（新人也能照做5步出报告）

### 0. 安装依赖

```bash
npm install
```

### 1. 启动系统

```bash
npm start
```

浏览器打开 **http://localhost:3000**（如果端口被占用，使用 `PORT=8888 npm start` 启动）

### 2. 新人5步跑完完整标定闭环

| 步骤 | 操作 | 观察要点（训练教练追问看这里） |
|------|------|--------------------------------|
| **① 清空数据** | 点击「清空所有数据（重置全链路）」按钮 | 这一步是为了确保你不是看演示，而是真的从 0 跑 |
| **② 导入 mixed-units.csv** | 点样例区第一个按钮 `mixed-units.csv` | 弹窗自动区分：**新记录 X 条**、**本次内重复 X 条**、**历史重复 X 条**、**℃/K混用 X 条** |
| **③ 再导一次同文件** | 再点一次 `mixed-units.csv` | 观察「文件内容整份重复：是」—— 同一文件重复导入不会因为新批次就逃过错检 |
| **④ 补录 + 复核** | 切到【记录明细】，随便点一条「补录」改喷嘴编号 → 再点一条待复核的「复核」→ 选择已复核保留，填写理由：**维修群截图确认铭牌单位确实混用** | 补录后弹窗会确认：导出CSV已同步新值 |
| **⑤ 导出 + 交接报告** | 点【📊 导出CSV】→ 再切到【交接报告】→ 点【生成/更新报告】 | 打开下载的 CSV，检查「处理理由全链路」列是否与页面详情完全一致 |

### 3. 导入时4种查重类型（直接看颜色不翻铭牌）

| 类型标签 | 颜色 | 含义 | 处理方式 |
|----------|------|------|----------|
| 🟢 新记录 | 绿色 | 历史从未出现过的新喷嘴编号 | 自动计算流量系数 |
| 🔴 本次内重复 | 红色 | 同一份CSV里喷嘴编号重复了 | 待复核，确认是否同一台设备 |
| 🟠 历史重复 | 橙色 | 之前别的CSV批次已导入过这个喷嘴 | 待复核，确认是否新的一次标定 |
| 🟣 文件整份重复 | 紫色 | 文件MD5哈希完全相同 | 每次再导入都能检测到，不会因新批次绕过 |

### 4. 温度混用的处理规则（重点！10分钟会议里最容易被问）

1. **全量标记**：一个批次内只要同时出现 ℃ 和 K，**所有带温度的记录** 一律标 `pending_review`（待复核）
   - ❌ 不再出现「前面的记录待处理、后面的待复核」的割裂
2. **不许自动归正常**：混用记录流量系数为空，训练教练确认后才可计算
3. **保留理由必写**：复核时必须填写理由（如「维修群截图-2026-06-12确认℃是现场仪表，K是实验室校准报告」）
4. **全链路留存**：理由写入 `processingReason`，页面详情弹窗、导出 CSV「处理理由全链路」列、交接报告「为什么待复核」列 三处同步可见

### 5. 三位数据一致性（训练教练追问：这个数哪来的？）

下面三处读取的是**同一份内存对象 `calibrationData.records`**，改一处三处全变：

- 🖥️ **页面表格**（记录明细 + 交接报告）
- 📡 **API 接口**（`GET /api/records`、`GET /api/records/:id`）
- 📊 **导出 CSV**（`GET /api/export` 的喷嘴编号、导入批次、温度、单位、流量系数、状态、复核备注、处理理由全链路）

补录保存后不需要做任何额外操作，**下次点击导出就是最新值**。

### 6. 单条记录详情能看到的证据链（训练教练追问能立刻回证）

点任意记录的【详情】按钮，能看到：
- 📌 **基础标识**：原始行号、导入批次(短+长)、导入文件名、查重类型
- 📐 **测量参数**：流量、压差、温度、单位
- 🧭 **处理理由全链路**（最重要）：从导入查重 → 温度混用判定 → 补录 → 复核 的每一步都带时间戳和操作人
- 📝 **复核备注**：训练教练写的理由
- 🔧 **人工改动记录**：每次改了什么字段，从什么值变到什么值
- ✅ **一致性声明**：字段来源、与哪三处一致

## 样例数据说明

`samples/` 目录：

| 文件 | 设计用途 | 预期现象 |
|------|----------|----------|
| `mixed-units.csv` | 正常业务场景：8条记录，4条℃+4条K混用 | 8条全部标记待复核，4项自检里温度项黄色告警 |
| `incomplete-data.csv` | 补录场景：5条记录，2条缺流量、1条缺压差、1条缺温度 | 部分记录可点补录，补录后流量系数自动重算 |
| `normal-data.csv` | 无混用基线：8条混合单位但业务上都正确 | 若前面没导入过同编号喷嘴，则都是新记录（正常计算系数） |

## API 接口一览

| 方法 | 路径 | 新人能看懂的说明 |
|------|------|------------------|
| POST | `/api/import` | 导入CSV，返回查重结果+混用记录+自检结果 |
| GET | `/api/records` | 拉所有记录（页面每次刷新都调这个） |
| GET | `/api/records/:id` | 拉单条详情（详情弹窗用） |
| PUT | `/api/records/:id` | 补录修改（保存后自动重算+检测仍否混用） |
| PUT | `/api/records/:id/review` | 教练复核（写理由+改状态+重算） |
| POST | `/api/recalculate` | 批量重算所有非错误/待复核的系数 |
| GET | `/api/export` | 下载CSV（含处理理由全链路列） |
| GET | `/api/self-check` | 4项自检结果（重复/混用/重算/一致性） |
| POST | `/api/handover` | 生成/刷新交接报告（含喷嘴编号+批次+导出一致性说明） |
| GET | `/api/handover` | 拿最新一份交接报告 |
| DELETE | `/api/data` | 清空一切（新人重头跑的起点） |

## 数据存哪里

- 运行时：内存中的 `calibrationData`
- 落盘：`data/calibration-data.json`（JSON格式，直接打开能看到每条记录的 `processingReason` 全链路）
- 删除：直接删 `data/` 目录或点页面的清空按钮即可
