原始想法：
我想做一个给现场设备维护工程师用的本地命令行工具，叫“固件校准包投递员”。我们给一批离线巡检终端、传感器网关和手持采集器升级时，常常拿着 U 盘到现场拷固件、校准参数和回滚包；现在靠人工看文件名和 Excel 记录，很容易把设备型号、区域批次、校准日期或固件版本弄错，等设备上线才发现没法追溯。请从 0 到 1 做一个可运行的 Python CLI 项目：init 命令能创建项目配置，维护设备型号、区域、允许的固件版本、校准包有效期、签名公钥、投递目录和审计输出目录；import-device 能导入设备清单 CSV，字段包括设备号、型号、区域、当前固件、当前校准版本、最后上线时间和负责人；import-package 能导入一个升级包目录，读取 manifest.json，校验固件文件、校准参数、回滚包、版本依赖、SHA256 和签名信息，发现缺文件、同名不同内容、manifest 版本不兼容、校准包过期、设备型号不匹配时要进入 quarantine.json 并说明原因。plan 命令要按设备清单和包清单生成 dry-run 投递计划，支持按区域灰度，识别跨版本跳升、缺少回滚包、设备当前版本未知、同一设备被多个包命中、负责人未确认这些阻断项；apply 命令只能执行无阻断计划，把文件复制到每台设备的投递目录，写入 journal，并在复制后重新计算哈希校验；rollback 命令能根据最近一次 journal 生成安全回滚计划，遇到目标目录被人工改过时要停止并提示；report 命令导出 Markdown 投递报告、CSV 设备结果和 JSON 审计包，history 命令能按设备号、区域、版本和执行日期查询历史投递记录。请把 CLI 入口、配置模型、CSV 解析、manifest/签名校验、投递计划、执行器、回滚 journal、隔离区、持久化、报告导出、示例数据和测试拆成多个文件，不要写成一个大脚本。README 里写清楚安装方式、示例命令，以及如何用临时目录验证 init、导入设备、导入升级包、生成计划、执行投递、校验哈希、回滚和导出审计包这些核心流程。
