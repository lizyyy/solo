# 自助洗衣店故障赔付 API - 使用说明

## 一、项目概述

这是一套用于演示自助洗衣机中途停机后用户申请赔付全流程的 API 系统。核心设计围绕 **订单、设备日志、赔付申请** 三者一致性，以及 **幂等性保证**。

### 核心特性

- ✅ **订单状态机**：严格的状态流转校验
- ✅ **设备日志联动**：故障自动记录，赔付自动匹配
- ✅ **赔付幂等**：重复请求不乱状态
- ✅ **重复拦截**：同一订单不能重复申请
- ✅ **补偿一致性**：赔付与优惠券一一对应
- ✅ **统计汇总**：一键导出全量数据

## 三、手动演示步骤

### 步骤 1：重置数据环境

每次演示前建议重置：

```bash
curl -X POST http://localhost:3000/api/stats/reset
```

### 步骤 2：造数 - 创建洗衣订单

**用户下单 → 支付 → 开始洗涤**

```bash
# 2.1 创建订单
curl -X POST http://localhost:3000/api/orders \
  -H "Content-Type: application/json" \
  -d '{
    "userId": "USER_001",
    "deviceId": "WASH-001",
    "amount": 35.00,
    "washType": "standard",
    "duration": 45
  }'
```

记下返回的 `orderNo`（如：`ORD202605100001`）

```bash
# 2.2 支付（推进状态）
curl -X POST http://localhost:3000/api/orders/{orderNo}/advance \
  -H "Content-Type: application/json" \
  -d '{"status": "paid"}'

# 2.3 开始洗涤
curl -X POST http://localhost:3000/api/orders/{orderNo}/advance \
  -H "Content-Type: application/json" \
  -d '{"status": "washing"}'

# 2.4 模拟洗涤进度
curl -X POST http://localhost:3000/api/orders/{orderNo}/progress \
  -H "Content-Type: application/json" \
  -d '{"steps": [10, 25, 40]}'
```

### 步骤 3：造数 - 模拟设备故障

**关键：设备故障时同时更新订单状态和记录设备日志**

```bash
curl -X POST http://localhost:3000/api/orders/{orderNo}/advance \
  -H "Content-Type: application/json" \
  -d '{
    "status": "interrupted",
    "extra": {
      "errorCode": "E201",
      "progress": 40
    }
  }'
```

此时系统自动：
- 订单状态 → `interrupted`
- 记录 `error` 事件设备日志
- 记录 `stop` 事件设备日志

**验证一致性：**

```bash
curl http://localhost:3000/api/orders/{orderNo}
```

检查返回的：
- `order.status` = "interrupted"
- `deviceLogs` 包含 `event: "error"` 且 `details.errorCode` = "E201"

### 步骤 4：用户申请赔付

**带幂等键，防止重复提交**

```bash
curl -X POST http://localhost:3000/api/claims \
  -H "Content-Type: application/json" \
  -d '{
    "orderNo": "{orderNo}",
    "userId": "USER_001",
    "reason": "洗衣机中途停机，电机过载，衣服未洗完",
    "expectedCompensation": 35.00,
    "idempotencyKey": "claim-20260510-001"
  }'
```

记下返回的 `claimNo`（如：`CLM202605100001`）

**验证幂等性（重复提交同一请求）：**

```bash
curl -X POST http://localhost:3000/api/claims \
  -H "Content-Type: application/json" \
  -d '{
    "orderNo": "{orderNo}",
    "userId": "USER_001",
    "reason": "洗衣机中途停机，电机过载，衣服未洗完",
    "expectedCompensation": 35.00,
    "idempotencyKey": "claim-20260510-001"
  }'
```

返回会带有 `duplicate: true`，且 `claimNo` 与第一次相同。

### 步骤 5：管理员审核赔付

```bash
curl -X POST http://localhost:3000/api/claims/{claimNo}/review \
  -H "Content-Type: application/json" \
  -d '{
    "action": "approve",
    "actualCompensation": 35.00,
    "reviewNote": "设备日志匹配E201故障，同意全额赔付",
    "operator": "admin_001"
  }'
```

审核操作选项：
- `"action": "approve"` - 批准
- `"action": "reject"` - 拒绝
- `"action": "review"` - 标记待复核

### 步骤 6：发放优惠券补偿

```bash
curl -X POST http://localhost:3000/api/claims/{claimNo}/compensate \
  -H "Content-Type: application/json" \
  -d '{
    "idempotencyKey": "coupon-20260510-001",
    "operator": "system"
  }'
```

**验证补偿幂等：**

```bash
curl -X POST http://localhost:3000/api/claims/{claimNo}/compensate \
  -H "Content-Type: application/json" \
  -d '{
    "idempotencyKey": "coupon-20260510-001",
    "operator": "system"
  }'
```

返回 `duplicate: true`，不会重复发券。

### 步骤 7：查询与汇总

```bash
# 查看赔付详情（含订单、设备日志、优惠券）
curl http://localhost:3000/api/claims/{claimNo}

# 查看统计数据
curl http://localhost:3000/api/stats

# 导出全量数据（JSON格式）
curl http://localhost:3000/api/stats/export -o laundry-data.json
```

## 四、异常场景演示

### 场景 1：无设备日志 → 触发待复核

用户在没有设备故障记录时申请赔付：

```bash
# 创建订单但不制造故障
curl -X POST http://localhost:3000/api/orders \
  -H "Content-Type: application/json" \
  -d '{"userId": "USER_002", "deviceId": "WASH-002", "amount": 45.00}'

# 推进到washing但不中断
# ...（省略支付和开始步骤）

# 用户直接申请赔付
curl -X POST http://localhost:3000/api/claims \
  -H "Content-Type: application/json" \
  -d '{
    "orderNo": "{orderNo}",
    "userId": "USER_002",
    "reason": "我觉得机器有问题",
    "expectedCompensation": 45.00
  }'
```

返回 `needsReview: true`，申请需要人工复核。

### 场景 2：同一订单重复申请 → 触发拦截

```bash
# 第一次申请（成功）
curl -X POST http://localhost:3000/api/claims ...

# 第二次申请（同一订单）
curl -X POST http://localhost:3000/api/claims \
  -H "Content-Type: application/json" \
  -d '{
    "orderNo": "{已申请过的订单号}",
    "userId": "USER_001",
    "reason": "再次申请",
    "expectedCompensation": 35.00
  }'
```

返回：
```json
{
  "error": "DUPLICATE_CLAIM",
  "message": "该订单已有进行中的赔付申请",
  "existingClaim": { ... }
}
```

### 场景 3：赔付金额修正

```bash
# 先完成一个赔付流程
# ...

# 管理员发现金额不对，修正
curl -X POST http://localhost:3000/api/claims/{claimNo}/correct \
  -H "Content-Type: application/json" \
  -d '{
    "actualCompensation": 17.50,
    "reason": "经复核，按50%比例赔付",
    "operator": "admin_001"
  }'
```

赔付状态变为 `corrected`，保留原始金额记录。

### 场景 4：用户撤回申请

```bash
curl -X POST http://localhost:3000/api/claims/{claimNo}/withdraw \
  -H "Content-Type: application/json" \
  -d '{
    "userId": "USER_001",
    "reason": "我想重启机器试试"
  }'
```

只有 `pending` 或 `pending_review` 状态的申请可撤回。

## 五、API 接口速查

### 订单管理

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/orders` | 创建订单 |
| GET | `/api/orders` | 查询订单列表 |
| GET | `/api/orders/:orderNo` | 订单详情（含日志、赔付、优惠券） |
| POST | `/api/orders/:orderNo/advance` | 推进订单状态 |
| POST | `/api/orders/:orderNo/progress` | 模拟洗涤进度 |

**订单状态流转：**
```
created → paid → washing → interrupted → refunded/washing
                              ↓
                           completed
```

### 赔付管理

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/claims` | 申请赔付（支持幂等键） |
| GET | `/api/claims` | 查询赔付列表 |
| GET | `/api/claims/:claimNo` | 赔付详情 |
| POST | `/api/claims/:claimNo/review` | 审核（approve/reject/review） |
| POST | `/api/claims/:claimNo/compensate` | 发放补偿（支持幂等键） |
| POST | `/api/claims/:claimNo/withdraw` | 撤回申请 |
| POST | `/api/claims/:claimNo/correct` | 修正赔付金额 |

**赔付状态流转：**
```
pending → pending_review → approved → compensated → corrected
   ↓            ↓            ↓
rejected     withdrawn    (无法撤销)
```

### 设备日志

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/devices/:deviceId/logs` | 上报设备事件 |
| GET | `/api/devices/:deviceId/logs` | 查询设备日志 |

**设备事件类型：**
- `start` - 启动
- `water_fill` - 注水
- `heating` - 加热
- `wash_cycle` - 主洗
- `rinse` - 漂洗
- `spin` - 脱水
- `error` - 故障
- `stop` - 停止
- `restart` - 重启

**故障码：**
- E101: 水压异常
- E102: 水温异常
- E103: 门锁故障
- E201: 电机过载
- E202: 转速异常
- E301: 通信中断
- E999: 未知故障

### 优惠券

| GET | `/api/coupons/:couponNo` | 查询优惠券详情 |

### 统计与工具

## 六、一致性与幂等性设计要点

### 1. 三者一致性保证

| 维度 | 校验点 |
|------|--------|
| **订单 ↔ 设备日志** | 订单 `interrupted` 必须有对应的 `error` 日志 |
| **赔付 ↔ 订单** | 赔付必须关联订单，且订单状态合法 |
| **赔付 ↔ 优惠券** | 一个赔付最多一张优惠券，双向关联 |
| **状态一致** | 赔付 `compensated` 时，优惠券必须存在 |

### 2. 幂等性实现

**赔付申请幂等：**
- 使用 `idempotencyKey` 参数
- 相同 key 返回已存在的申请
- 不产生重复记录

**补偿发放幂等：**
- 使用 `idempotencyKey` 参数
- 相同 key 返回已发放的优惠券
- 检查赔付单是否已有优惠券关联

**订单状态幂等：**
- 状态机严格校验
- 同一状态转换多次无副作用

### 3. 重复赔付拦截

- 创建赔付时检查：同一订单是否有未完成的赔付
- 未完成状态：`pending`, `pending_review`, `approved`, `compensated`, `corrected`
- 已完成但可重新申请：`withdrawn`, `rejected`

## 八、常见问题

### Q: 演示数据会保存吗？
A: 不会。使用内存存储，服务重启后数据清空。每次演示前可调用 reset 接口。

### Q: 如何验证三者一致性？
A: 调用 `GET /api/claims/{claimNo}`，返回结构包含：
- `claim` - 赔付申请
- `order` - 关联订单
- `deviceLogs` - 设备日志
- `coupons` - 发放的优惠券

### Q: 幂等键如何生成？
A: 建议使用业务唯一标识，如：
- 赔付申请：`claim-{userId}-{orderNo}-{timestamp}`
- 优惠券：`coupon-{claimNo}`

### Q: 如何测试重复请求？
A: 使用相同的 `idempotencyKey` 或对同一订单重复提交申请。
