# 试制件版本装车追踪系统

一个完整的试制件全生命周期管理系统，包含后端API服务和前端管理界面。

## 功能特性

### 后端功能
- **幂等设计**: 支持通过 `request_id` 实现接口幂等性，避免重复提交
- **状态流转控制**: 严格的状态流转校验，确保业务流程规范
- **版本校验**: 试制版本格式校验（V1.0、V2.1 等格式）
- **完整历史记录**: 状态历史、修改历史（原值/新值对比）
- **数据导出**: Excel格式导出，支持按时间范围筛选
- **错误处理**: 统一的错误返回格式和错误信息

### 前端功能
- **统计卡片**: 直观展示各状态零件数量
- **状态操作按钮**: 根据当前状态显示允许的操作
- **数据筛选**: 支持按零件图号和状态筛选
- **详情查看**: 多标签页展示完整信息（状态历史、修改记录、检测报告、装车记录、返工工序、报废记录）
- **导出报告**: 一键导出Excel报告

## 业务流程

```
待处理 → 检测中 → 合格 → 装车中 → 已装车 → 完成
              ↓        ↓        ↓
          不合格    复核中    装车失败
              ↘        ↘        ↙
                    返工中 → 返工完成
                        ↓
                      报废
```

## 技术栈

- **后端**: Node.js + Express + SQLite
- **前端**: React + Ant Design + Axios
- **数据导出**: ExcelJS
- **其他**: Moment.js、UUID

## 安装和运行

### 1. 安装依赖

```bash
# 安装后端依赖
npm install

# 安装前端依赖
cd client
npm install
cd ..
```

### 2. 初始化数据库和样例数据

```bash
node server/seedData.js
```

### 3. 运行系统

方式一：同时启动后端和前端（开发模式）
```bash
npm run dev
```

方式二：分别启动
```bash
# 启动后端服务 (端口: 5000)
npm run server

# 启动前端 (端口: 3000，新开终端)
cd client
npm start
```

### 4. 访问系统

- 前端地址: http://localhost:3000
- 后端API: http://localhost:5000/api

## API接口说明

### 零件管理
- `GET /api/parts` - 获取零件列表（支持分页和筛选）
- `GET /api/parts/:id` - 获取零件详情
- `POST /api/parts` - 创建零件（支持request_id幂等）
- `PUT /api/parts/:id` - 更新零件（记录修改历史）
- `POST /api/parts/:id/status` - 状态变更

### 业务记录
- `POST /api/parts/:id/inspection` - 添加检测报告
- `POST /api/parts/:id/installation` - 添加装车记录
- `POST /api/parts/:id/rework` - 添加工序记录
- `POST /api/parts/:id/scrap` - 报废零件

### 其他
- `GET /api/statistics` - 获取统计数据
- `GET /api/scrap-records` - 查询报废记录（支持筛选）
- `GET /api/export` - 导出Excel报告

## 验收要点

### 1. 试制版本校验
- 创建零件时输入非法版本格式（如 1.0、v1.0）会被拒绝
- 只有 V 开头、数字和点号组合的格式才允许（如 V1.0、V2.1.3）

### 2. 返工工序留痕
- 在零件详情页的"返工工序"标签页可查看所有工序记录
- 包含工序名称、操作员、时间、结果、备注等信息

### 3. 报废去向查询
- **页面查询**: 零件详情页的"报废记录"标签页
- **接口查询**: `GET /api/scrap-records?responsible_person=XXX&start_date=XXX&end_date=XXX`

### 4. 修改历史记录
- 在零件详情页的"修改历史"标签页可查看
- 记录了字段名、原值、新值、修改人、修改时间
- 特别保留了零件图号、试制版本的修改记录

### 5. 状态流转控制
- 系统会自动校验状态流转是否合法
- 例如：不能直接从"待处理"跳到"已装车"

### 6. 幂等测试
- 重复提交相同 request_id 的创建请求，只会创建一次
