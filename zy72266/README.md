# 水库闸门开度展示 — 安全半径表管理系统

## 系统简介

为现场班组与培训教官提供的闸门开度数据管理工具，解决安全半径表导入后口径不一致、Z 轴方向按旧习惯写反等常见错口径问题。

核心原则：**导出明细、页面展示和接口返回读取同一份结果数据**。

## 快速启动

```bash
npm install
npm run dev
```

## 边界规则

### Z 轴方向判断规则

| 规则编号 | 规则描述 | 判断条件 | 处理方式 |
|----------|----------|----------|----------|
| ZR-001 | Z 轴正方向数值为负（按旧习惯写反） | `zAxisValue < 0` | 标记"待复核"，**不自动修正**，留给现场班组复核 |
| ZR-002 | Z 轴正方向数值为正（符合规范） | `zAxisValue >= 0` | 标记"已确认正常" |
| ZR-003 | Z 轴数值缺失 | `zAxisValue === null` | 标记"数据缺失"，要求补录 |

### Z 轴方向异常处理：判、改、回滚

#### 判（如何判断 Z 轴方向按旧习惯写反）

判断逻辑位于 `src/services/zAxisDetection.ts` 中的 `detectZAxisDirection` 函数：

- Z 轴值为负数 → 判定为"按旧习惯写反"（ZR-001）
- Z 轴值为正数 → 判定为"符合规范"（ZR-002）
- Z 轴值为 null → 判定为"数据缺失"（ZR-003）

**关键机制**：`autoCorrectSuppressed` 标志。当 ZR-001 触发时，该标志为 `true`，系统**禁止自动修正** Z 轴方向，必须由现场班组手动确认。

#### 改（如何更正 Z 轴方向）

Z 轴方向异常的更正**必须**遵循以下状态机流程，不可跳过：

1. 导入时检测到 Z 轴方向异常 → 状态变为"待复核"
2. 培训教官审核 → 确认异常后标记为"待现场复核"
3. 现场班组复核 → 选择"确认更正"或"确认无需更正"

**绝对不可**：
- 在导入时自动将 Z 轴负值翻正
- 在教官审核时自动归为正常
- 绕过现场班组复核直接修改数据

状态机逻辑位于 `src/services/stateMachine.ts`，所有状态变更必须通过 `validateTransition` 校验。

#### 回滚（如何回滚错误操作）

回滚逻辑位于 `src/store/useGateStore.ts` 中的 `rollbackRecord` 方法：

- 回滚将记录状态恢复至"已回滚"，同时恢复 Z 轴原始值和方向
- 回滚操作**必须**填写回滚原因
- 回滚操作本身写入审计日志（操作人、时间、原因）
- 回滚前的数据快照保存在 `rollbackSnapshots` 中，确保可追溯

### 数据一致性规则

1. **统一数据源**：所有组件通过 Zustand store 读取数据，导出功能从同一 store 生成数据
2. **状态变更统一入口**：所有状态变更通过 `transitionRecord` 方法，确保审计日志同步写入
3. **审计不可删除**：所有操作留痕，审计记录不可删除

### 操作权限规则

| 角色 | 可执行操作 |
|------|-----------|
| 培训教官 | 导入安全半径表、标记确认正常/异常、发起回滚 |
| 现场班组 | 复核异常（确认更正/确认无需更正）、不可直接修改数据 |

## 核心流程：三步工作流

1. **第一步：安全半径表首次导入** — 上传文件，系统解析数据，Z 轴方向异常自动检测并标记为"待复核"
2. **第二步：培训教官补看坐标原点说明** — 教官逐条审核，对 Z 轴方向按旧习惯写反的记录标记"待现场复核"，**不自动归正常**
3. **第三步：路径回放更新** — 现场班组复核后，更新处理状态，路径回放记录完整变更链路

## 技术栈

- React 18 + TypeScript + TailwindCSS 3 + Vite
- Zustand（统一数据源 + localStorage 持久化）
- React Router DOM（路由管理）
- Lucide React（图标库）
