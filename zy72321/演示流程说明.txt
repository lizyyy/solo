【核心数据架构：student_registry（按学号为唯一KEY
══════════════════════════════════════════════════════════════
student_registry[学号] = {
    "学号", "姓名", "班级",
    "原始提交",       ← 从CSV导入后再也不覆盖
    "提交记录数", "原始记录ID", "答案版本",
    "关联参数",       ← 从参数调试表挂接
    "各轮快照",       ← { "正常材料":{...}, "错口径材料":{...}, "补录材料":{...} }
    "最新状态",       ← 列表/详情/摘要/历史 统一从这里取数
        ├── 处理结果 / 处理方式 / 口径版本
        ├── 需要复核 / 误差说明 / 处理建议 / 优先级
        └── 运行标签
    "复核留痕"          ← 永远保留，不被后续结果覆盖
        ├── 原始说法     （系统第一次检测到时的人话）
        ├── 改后值       （人工确认后的处理结果
        ├── 处理原因     （为什么这么改）
        ├── 下一步找谁   （流程交接给谁）
        └── 复核状态     （待业务运营复核 / 已复核 / 系统提示）
}

【五步标准流程】
══════════════════════════════════════════════════════════════
步骤1：导入抽样名单
  → 建 registry，按学号聚合成5名学生
  → 记录历史：导入抽样名单

步骤2：实验助理小穆查看参数调试表
  → 把参数表里「关联学号」挂到对应 student 上
  → 记录历史：查看参数调试表

步骤3：层次聚类归并（跑三轮，每轮都同步6份导出文件
  ├─ 第一轮 正常材料：
  │    张三 → 正常归并（无误差
  │    李四 → 待业务运营复核 + 写复核留痕
  │    王五 → 正常归并（错口径不触发旧口径）
  │    赵六 → 正常归并
  │    孙七 → 正常归并
  │    本轮异常数=1  （李四1条）
  │
  ├─ 第二轮 错口径材料：
  │    同第一轮（只是展示口径差异
  │    本轮异常数=1
  │
  └─ 第三轮 补录材料：
       张三 → 正常归并
       李四 → 待业务运营复核
       王五 → 旧口径补录 + 系统提示
       赵六 → 正常归并
       孙七 → 正常归并
       本轮异常数=2  （李四 + 王五

  每轮结束 _sync_all_exports() 同时写：
    归并结果 / 误差说明 / 学生详情 / 处理摘要 / 人工修正记录 / 操作历史

步骤4：人工修正（李四）
  → 「复核留痕」 四字段全部写齐
      原始说法：同一学生(李四)提交了2版答案...
      改后值  ：正常归并(以v2版为准)
      处理原因：经业务运营逐字比对...
      下一步找谁：已由 业务运营-王经理 确认，下一步交实验助理小穆重跑同步
  → 更新 registry["最新状态
  → 历史记录写入同样4字段
  → 记录人工修正记录.csv

步骤5：修正后重跑
  → 基于最新 registry 同步所有导出
  → 不覆盖原始各轮快照
  → 生成「归并结果_修正后.csv」和「误差说明_修正后.csv」

【三种处理结果对比（补录材料轮）
══════════════════════════════════════════════════════════════
类型            学生      处理结果          口径       需要复核
──────────────────────────────────────────────────────────────

同一学生两版    李四2023002  待业务运营复核    当前口径    是  ← 不会提前归并
旧口径补录      王五2023003  旧口径补录       旧口径      否  ← 系统提示不进入复核

★ 关键：李四在「待业务运营复核」时，
  - 最新状态.需要复核=True
  - 复核留痕.复核状态=待业务运营复核
  - 人工修正记录.csv 里作为待办行
  - 处理摘要.csv 里待复核数=1
  - 历史记录异常学生列表里含2023002
  全部同一份数据，不会出现一边显示正常一边待复核

【给新人讲解要点（比旧版更扎实）
══════════════════════════════════════════════════════════════
1. 为什么异常数不是0了？
   → 因为 _process_student 真正把误差写入了 error_log + registry 快照
   → 历史记录中的异常数就是从快照里有误差说明的人统计

2. 李四待复核时，会不会被误归正常？
   → 不会。需要复核=True、复核状态=待业务运营复核、人工修正记录里有待办行
     三份地方都卡着，绝不会偷偷归到正常

3. 「复核留痕」为什么单独保存？
   → 改后值会覆盖最新状态，但原始说法、处理原因、下一步找谁永远留着
     业务运营来查时，看得到「来龙去脉」

4. 各导出文件为什么能对齐？
   → 全部从同一个 student_registry 取，不存在列表改了详情没改这种事
