# 数据库索引实验台 📊

一个本地运行的数据库索引对比实验平台，用于深入对比 B+ 树索引和哈希索引的性能差异。

## 功能特性

### 🎯 核心功能
- **索引模拟**：完整实现 B+ 树索引和哈希索引的完整模拟
- **查询类型**：
  - 等值查询 (`=`)
  - 范围查询 (`>`, `<`, `>=`, `<=`, `BETWEEN`)
  - 前缀查询 (`LIKE "prefix%"`)
  - 插入操作 (`INSERT`)
  - 删除操作 (`DELETE`)

### 🔍 过程模拟
- **B+ 树**：页分裂、页合并、节点重平衡
- **哈希索引**：哈希冲突（拉链法）、桶扩容、重哈希

### 📈 数据采集
- 页访问次数（磁盘 I/O）
- 哈希冲突次数
- 回表查询次数
- 估算耗时（模拟磁盘 I/O + CPU 开销）

### 🖼️ 可视化展示
- B+ 树层级结构可视化（内部节点、叶子节点、链表连接）
- 哈希桶分布可视化（链长、负载因子、冲突热区）
- 性能对比图表（柱状图、雷达图、饼图）

### 💾 数据管理
- 实验记录自动保存（localStorage）
- 导出 Markdown/JSON 报告
- 配置导入/导出

## 快速启动

### 环境要求
- Node.js >= 16.0.0
- npm  >= 7.0.0

### 步骤 1: 安装依赖

```bash
# 安装后端依赖
cd backend
npm install

# 安装前端依赖
cd ../frontend
npm install
```

### 步骤 2: 启动后端服务

```bash
cd backend
npm run dev
```

后端服务将在 http://localhost:3001 启动

### 步骤 3: 启动前端服务

**新开一个终端窗口**：

```bash
cd frontend
npm start
```

前端服务将在 http://localhost:3000 启动

### 步骤 4: 访问应用

打开浏览器访问 http://localhost:3000

## 异常样例

### 场景 1: 哈希冲突严重

**触发条件**：
- 数据规模大（> 1000 条）
- 哈希桶数量小（<= 8）
- 键值分布不均匀

**现象**：
- 哈希索引查询性能下降
- 部分桶链长超过 5
- 等值查询需要遍历链表

**建议**：
- 增加初始桶数量
- 调整负载因子阈值
- 考虑使用更好的哈希函数

### 场景 2: B+ 树频繁分裂

**触发条件**：
- B+ 树阶数小（<= 3）
- 插入顺序键值（如 1, 2, 3, 4...）

**现象**：
- 插入操作触发多次页分裂
- 页访问次数增加
- 树高度快速增长

**建议**：
- 增大 B+ 树阶数
- 使用随机顺序插入（模拟真实场景）

### 场景 3: 范围查询对比

**触发条件**：
- 执行范围查询或前缀查询

**现象**：
- B+ 树：正常返回结果
- 哈希索引：需要全表扫描（实际不支持范围查询）
- 性能差距巨大

**结论**：
- 范围查询必须使用 B+ 树索引
- 哈希索引不适合此类场景

### 场景 4: 哈希扩容

**触发条件**：
- 持续插入数据
- 负载因子超过阈值（默认 0.75）

**现象**：
- 哈希桶数量翻倍
- 所有键值重新哈希
- 插入性能短暂下降

**建议**：
- 预估数据量，设置合适的初始桶数
- 避免在高峰期大量插入数据

## 性能估算模型

### 时间估算规则

| 操作 | 估算耗时 | 说明 |
|------|----------|------|
| 页读取 | 5ms | 模拟磁盘 I/O |
| 页写入 | 10ms | 模拟磁盘写入 |
| 回表查询 | 2ms | 从表中获取数据 |
| 哈希冲突遍历 | 3ms | 链表遍历开销 |

### 复杂度对比

| 操作 | B+ 树 | 哈希索引 |
|------|--------|----------|
| 等值查询 | O(log n) | O(1) 平均 / O(n) 最坏 |
| 范围查询 | O(log n + k) | O(n) 全表扫描 |
| 前缀查询 | O(log n + k) | O(n) 全表扫描 |
| 插入 | O(log n) | O(1) 平均 |
| 删除 | O(log n) | O(1) 平均 |

## 注意事项

1. **这是一个模拟系统**：实际数据库的实现要复杂得多，本系统仅用于教学演示

2. **性能数据是估算值**：基于磁盘 I/O 和 CPU 开销的简化模型，与真实数据库不完全一致

3. **哈希冲突模拟**：使用拉链法处理冲突，真实数据库可能使用更复杂的策略（如开放寻址、线性探测等）

4. **B+ 树实现**：简化的 B+ 树实现，没有实现并发控制、事务日志等高级特性

5. **数据持久化**：前端使用 localStorage 存储实验记录，刷新页面不会丢失，但清除浏览器缓存会丢失

## 常见问题

### Q: 为什么范围查询哈希索引这么慢？
A: 哈希索引的键值是无序的，无法高效地按范围查找。要实现范围查询，必须遍历所有桶中的所有条目，即全表扫描。

### Q: B+ 树的阶数是什么意思？
A: 阶数（order）决定了每个节点最多可以有多少个子节点。对于阶数为 m 的 B+ 树，每个节点最多有 m 个子节点，最多包含 m-1 个键。

### Q: 负载因子是什么？
A: 负载因子 = 条目数 / 桶数。当负载因子超过阈值时，哈希表会进行扩容（桶数翻倍），然后进行重哈希。

### Q: 如何复现实验结果？
A: 使用相同的随机种子（seed）可以生成相同的测试数据，确保实验可复现。
