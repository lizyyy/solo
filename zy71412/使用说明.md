# 银行授信抵押物复估系统 - 使用说明

## 一、快速启动（3步）

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 启动服务
python main.py
# 服务地址: http://localhost:8000
# API文档: http://localhost:8000/docs

# 3. 导入样例数据（新开一个终端）
python sample_data.py
```

---

## 二、核心概念

| 概念 | 说明 |
|------|------|
| **Material 材料** | 抵押物清单、评估报告、授信合同的原始上传记录，带文件哈希和上传人 |
| **Collateral 抵押物** | 抵押物主信息，一个抵押物对应多个评估版本 |
| **CollateralVersion 评估版本** | 每次评估生成一个新版本，保留完整历史，可追溯哪份材料导入的 |
| **CreditContract 授信合同** | 银行授信合同，关联原始材料 |
| **CreditOccupancy 授信占用** | 某笔合同占用某个抵押物的具体金额和版本 |
| **Reassessment 复估任务** | 一次复估工作，包含多个抵押物任务 |
| **Warning 预警** | 异常检测结果，明确：触发材料、卡点位置、下一步补什么 |

## 三、标准复估流程（4步）

### 第1步：录入 - 导入材料和数据

**场景1：导入抵押物+评估报告**
```bash
POST /api/collaterals/import
{
  "collateral_no": "DY2024001",
  "name": "北京市朝阳区建国路88号...",
  "appraised_value": 8000000,
  "appraisal_date": "2024-01-15",
  "appraisal_expiry_date": "2025-01-14",
  "mortgage_rate": 0.7,
  "uploaded_by": "客户经理-张三"
}
```

**场景2：导入授信合同+关联抵押物**
```bash
POST /api/contracts/import
{
  "contract_no": "SX20240001",
  "borrower": "张三",
  "credit_amount": 5600000,
  "start_date": "2024-02-01",
  "end_date": "2025-01-31",
  "collateral_no": "DY2024001",
  "occupancy_amount": 5600000,
  "uploaded_by": "综合岗-李四"
}
```

**场景3：抵押物重新评估，新增版本**
```bash
POST /api/collaterals/versions
{
  "collateral_id": 1,
  "appraised_value": 9500000,
  "appraisal_date": "2025-03-01",
  "appraisal_expiry_date": "2026-02-28",
  "mortgage_rate": 0.7,
  "remark": "重新评估，较上版增值150万"
}
```

### 第2步：处理 - 创建复估任务并自动检测

```bash
# 创建复估任务
POST /api/reassessments
{
  "name": "2025年Q2抵押物批量复估",
  "collateral_ids": [1, 2, 3],
  "triggered_by": "季度常规复估",
  "max_rate": 0.7
}

# 执行处理（自动检测三类异常）
POST /api/reassessments/{id}/process?handler=客户经理-王芳
```

**自动检测三类异常：**

| 异常类型 | 检测逻辑 | 输出内容 |
|----------|----------|----------|
| 🔴 **appraisal_expired** | 当前日期 > 评估有效期 | 触发材料、过期天数、卡在哪（有效期检查）、补什么（重新评估） |
| 🔴 **mortgage_rate_exceed** | 授信余额 / 评估价 > 抵押率上限 | 触发材料、当前抵押率、卡在哪（计算公式）、补什么（补抵押物或还款） |
| 🟡 **duplicate_guarantee** | 同一抵押物被多笔有效授信占用 | 触发材料、涉及合同列表、卡在哪（重复担保检查）、补什么（核实担保顺序） |

### 第3步：复核 - 人工审核

```bash
POST /api/reassessments/{id}/review
{
  "reviewer": "风险经理-老赵",
  "review_opinion": "预警情况属实，请客户经理尽快联系客户补充抵押物",
  "approve": true
}
```

### 第4步：导出 - 完整报告

```bash
GET /api/reassessments/{id}/export
```

**导出内容包含：**
- 复估任务基本信息（创建人、处理人、复核人、时间线）
- 每个抵押物的：
  - 基本信息
  - 当前版本评估数据
  - **完整版本历史**（每次评估的评估价、日期、来源材料）
  - 所有授信占用明细（合同、金额、来源材料）
  - 抵押率计算过程
  - 所有预警记录（含触发材料、卡点、下一步）

## 四、日常排查常用接口

### 1. 查看某抵押物完整历史
```bash
GET /api/collaterals/{id}/history
```
→ 可以看到：所有评估版本链 + 所有授信占用记录 + 所有历史预警

### 2. 实时检测单抵押物
```bash
GET /api/detect/{collateral_id}?max_rate=0.7
```
→ 即时计算当前抵押率，检测所有异常

### 3. 查看所有未解决预警
```bash
GET /api/warnings?unresolved_only=true
```

### 4. 查看全局统计
```bash
GET /api/statistics
```

### 5. 查看所有上传的原始材料
```bash
GET /api/materials
```
→ 区分谁、什么时候、从哪发来的什么材料

## 六、数据追溯说明

每条预警都完整记录可追溯链路：

```
预警记录
├── warning_type: 抵押率超限
├── message: 当前 110.00%，最高允许 70.00%
├── blocked_at: 抵押率计算：550万 / 500万 = 110%
├── next_action: 需要补充抵押物50万...
├── trigger_material (来源材料): PG20240128_广州珠江新城评估报告.pdf
├── material_id: 3
├── collateral_version_id: 5
└── contract_id: 4
```

点击 `material_id` → 跳转到原始材料记录，看谁传的、什么时候传的  
点击 `collateral_version_id` → 跳转到具体评估版本，看版本号、评估价  
点击 `contract_id` → 跳转到授信合同，看借款人、金额
