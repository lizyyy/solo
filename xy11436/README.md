# 民宿保洁排班多源导入巡检 CLI (hci)

> 解决主管翻旧账时"漏房结论不能漂"的问题 - 真实交接、多源核对、证据留存、全程可追溯

## 核心特性

### ✅ 真实交接处理
- **订单日历** - 从PMS系统导出的退房名单
- **保洁群消息** - 微信/钉钉群的排班消息
- **维修备注** - 维修后需要清洁的房间
- **扫码明细** - 保洁员扫码开工/完工记录

### ✅ 冲突检测全覆盖
- **重复提交** - 同一房间同一天多源导入重复
- **多源重叠** - 订单和群消息数据不一致
- **连住换布草** - 长住客布草更换提醒
- **临时退房** - 钟点房/临时取消无验证
- **部分失败** - 导入文件部分行解析失败

### ✅ 证据链完整
- 保留**来源文件名**
- 保留**原始行号**
- 保留**解析后的标准值**
- 人工改判**不覆盖原始证据**

### ✅ 状态变化全记录
每次操作都记录：
- **时间戳** - 精确到秒
- **操作者** - 谁做的操作
- **原因** - 为什么这么改

### ✅ 边界情况处理
- 重复提交防重
- 撤回后再提交（快照历史）
- 部分失败不中断
- 人工改判留痕
- 导出前冻结防篡改

## 核心命令

```bash
hci init      # 初始化工作目录
hci import    # 导入数据文件（4种格式都支持）
hci check     # 执行冲突检测
hci fix       # 修复冲突（自动+人工）
hci report    # 生成报表（重点看原始行号！）
hci history   # 查看操作历史/快照对比
hci export    # 导出排班表（可冻结）
```

## 为什么报表一定要显示原始行号？

> 主管翻旧账时，拿着原始Excel说"你看第5行明明有这个房间"，如果你只给一个汇总数字，说不清楚。

本系统报表的核心设计原则：
1. **每个失败任务都能追溯到来源文件和行号**
2. **点击就能定位到原始材料的具体位置**
3. **人工改判不删除原始证据**
4. **改判原因和操作者永久记录**

## 数据模型设计

### Task (任务)
```
├── id: UUID
├── roomNumber: 101
├── date: 2026-05-23
├── type: 退房清洁
├── status: pending/failed/fixed/frozen
├── sourceEvidences: [           # 原始证据链（不会被覆盖！）
│   ├── sourceType: order_calendar
│   ├── fileName: 订单日历.csv
│   ├── lineNumber: 2            # 👈 原始行号！
│   ├── rawContent: '{"房间号":"101"...}'
│   └── parsedValue: {...}
│   ... 可以有多个来源证据
]
├── conflicts: [冲突列表]
├── manualOverride: null         # 人工改判（附加，不覆盖原始）
├── auditTrail: [                # 完整审计轨迹
│   ├── timestamp: 2026-05-23T10:00:00
│   ├── operator: 店长
│   └── reason: 'manual_override: 客人实际续住'
│   ...
]
└── isFrozen: false
```

## 冲突类型

| 类型 | 说明 | 自动修复? |
|------|------|----------|
| duplicate | 重复任务 | ✓ 合并 |
| overlap | 多源数据重叠 | ✓ 以订单为准合并 |
| linen_change | 连住未换布草 | ✓ 自动开启 |
| early_checkout | 临时退房无验证 | ✗ 需人工确认 |
| missing_room | 漏房 | ✗ 需人工确认 |

## 翻旧账时怎么查？

场景：主管说"上周三103房怎么漏了？"

```bash
# 1. 查看那天的历史快照
hci history --snapshots

# 2. 对比当时和现在的数据
hci history --diff snapshot-2026-05-20-xxx.json

# 3. 查看当时的完整报告（含原始行号）
hci report --date 2026-05-20 --format json

# 4. 看谁改的、为什么改
# 打开 report-audit-xxx.csv → 按任务ID筛选 → 看操作历史
```

## 设计原则

1. **异常不吞没** - 错了就报错，不静默跳过
2. **证据不删除** - 改了就记录，原始留着
3. **操作留痕迹** - 谁改的、什么时候、为什么
4. **报表讲人话** - 给店长看的，不是给程序员看的
5. **冻结防篡改** - 导出那一刻的数据要能定案
