# 音频样本情绪标签管理系统

专为音乐团队打造的音频样本情绪标签管理工具，解决同一首歌现场名与版权名混淆、重复导入、数据不一致等核心痛点。

---

## ✨ 核心特性

### 🎯 四大核心问题解决

| 问题 | 解决方案 |
|------|----------|
| **重复导入** | 自动检测跨版本重复记录，导入时高亮预警 |
| **同名映射** | 智能识别现场名/版权名关联，默认待复核，不急着归正常 |
| **补录重算** | 许老师补录音频备注后自动触发情绪标签重算 |
| **导出一致** | 页面、接口、导出文件读取同一份数据源，哈希校验 |

### 📋 三步标准工作流

1. **第一步：票务导出表导入**
   - 支持CSV/Excel格式上传
   - 自动预览前20行，标记异常
   - 保留原始行号，全程可追溯

2. **第二步：许老师补看音频文件备注**
   - 点击单元格即可编辑备注
   - 待复核记录高亮显示，专属复核区
   - 同一首歌分组展示，便于对比

3. **第三步：店长周报更新**
   - 一键导出多Sheet Excel周报
   - 导出前自动运行自检
   - 情绪分布、处理进度一目了然

### 🔍 四项自动自检

系统内置自检引擎，自动检测以下风险：

1. ✅ **重复导入检测** - 跨导入版本的重复记录
2. ✅ **同名映射检查** - 分组内情绪标签/状态不一致
3. ✅ **补录重算验证** - 备注更新后标签是否重算
4. ✅ **导出一致性校验** - 页面与导出数据哈希比对

## 🚀 快速开始

### 环境要求

- Node.js >= 18
- pnpm (推荐) 或 npm

### 安装与运行

```bash
# 1. 安装依赖
pnpm install

# 2. 启动开发服务器
pnpm run dev

# 3. 浏览器访问 http://localhost:5173
```

### 从零开始体验（新人操作指南）

#### 第一步：查看样例数据

系统启动后自动加载样例数据，包含：
- 11条示例记录（含重复导入场景）
- 3个待复核同名分组
- 人工改动历史示例

首页点击「查看样例数据」或直接进入「情绪标签」页面即可看到。

#### 第二步：走一遍完整流程

**场景：模拟票务导出表导入 → 许老师复核 → 导出周报**

1. **导入数据**
   - 下载 [样例CSV文件](./samples/ticket-export-sample.csv)
   - 进入「数据导入」页面
   - 拖拽或点击上传CSV文件
   - 查看预览，确认标记的异常行
   - 点击「确认导入」

2. **许老师复核**
   - 进入「异常复核区」页面
   - 查看所有待复核分组
   - 点击「确认关联」合并同一首歌的不同版本
   - 或点击「标记独立」确认为不同歌曲
   - 进入「情绪标签」页面，点击单元格补录音频备注

3. **运行自检**
   - 进入「自检中心」页面
   - 点击「立即运行自检」
   - 查看四项自检结果
   - 点击「处理」跳转至异常记录

4. **导出周报**
   - 进入「周报生成」页面
   - 查看汇总统计和情绪分布
   - 点击「导出周报Excel」
   - 打开下载的文件，验证三个Sheet数据

## 🔧 核心设计原则

### 单一数据源 (Single Source of Truth)

所有数据通过 Zustand Store 统一管理：

```
                    ┌─────────────────────┐
                    │   Zustand Store     │
                    │  (Single Source)    │
                    └─────────┬───────────┘
                              │
          ┌───────────────────┼───────────────────┐
          │                   │                   │
┌─────────▼─────────┐ ┌───────▼───────┐ ┌─────────▼─────────┐
│  明细表格展示     │ │  导出文件     │ │  自检引擎         │
│  (5个页面)        │ │  (CSV/Excel)  │ │  (四项检查)       │
└───────────────────┘ └───────────────┘ └───────────────────┘
```

- ✅ 禁止组件内部缓存数据
- ✅ 导出函数直接使用 store.records
- ✅ 所有修改通过统一 action
- ✅ 状态变更自动触发自检

### 数据可追溯

每条记录保留：
- `originalRowNumber` - 票务导出表原始行号
- `importVersion` - 导入版本号
- `manualChanges` - 人工改动历史（操作人、时间、原因）
- `createdAt` / `updatedAt` - 时间戳

### 异常处理原则

> 同一首歌有现场名和版权名时，别急着归正常，留给音乐老师复核。

- 系统检测到疑似同名记录 → 自动标记为「待复核」
- 不自动合并、不自动覆盖
- 音乐老师确认后才统一情绪标签

## 📊 数据导出说明

### CSV导出包含字段

| 列名 | 说明 |
|------|------|
| 原始行号 | 票务导出表中的原始行号 |
| 现场名 | 演出现场使用的名称 |
| 版权名 | 版权登记的正式名称 |
| 情绪标签 | 当前标记的情绪分类 |
| 置信度 | 情绪标签的置信度百分比 |
| 处理状态 | 待处理/待复核/已确认/异常 |
| 音频备注 | 许老师补录的备注信息 |
| 分组规范名 | 同名分组的统一名称 |
| 分组状态 | 待复核/已确认/已拒绝 |
| 导入版本 | 所属导入批次 |
| 数据校验哈希 | 用于验证导出一致性 |

### Excel周报包含三个Sheet

1. **周报** - 店长看的汇总统计
2. **明细数据** - 完整的歌曲列表
3. **统计汇总** - 各维度计数统计

## ❓ 常见问题

### Q: 数据存在哪里？会丢失吗？

A: 数据保存在浏览器 LocalStorage 中，只要不清空浏览器数据就不会丢失。建议定期导出Excel备份。

### Q: 可以多人同时使用吗？

A: 当前版本为单机版，数据仅保存在本地浏览器。如需多人协作，建议后续接入后端服务。

### Q: 如何清空数据重新开始？

A: 打开浏览器开发者工具 → Application → Local Storage → 删除 `emotion-label-storage` 即可。

### Q: 情绪标签是怎么计算的？

A: 基于歌曲名和备注的关键词匹配，置信度仅供参考。许老师可以随时手动调整标签。
