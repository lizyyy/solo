# 电子发票抬头纠错 CLI

企业员工报销时，电子发票抬头少字、税号错一位、金额和报销单不一致是财务审核中常见的问题。本工具提供完整的自动化核对纠错能力，帮助财务人员高效发现问题，确保报销业务闭环。

## 功能特性

- ✅ **多维度自动检查**：抬头、税号、金额与报销单自动比对
- 🔍 **智能规则引擎**：
  - 同一发票重复报销检测
  - 抬头近似但主体不同识别（如：`创新科技北京有限公司` vs `创新科技（北京）有限公司`）
  - 跨集团公司抬头检测
  - 金额拆分报销风险提醒
- 📊 **四种审核结果**：自动通过 / 需补开 / 人工复核 / 纠错建议
- 📝 **完整审计追踪**：所有操作留痕，人工修正记录前后差异和操作者
- 🔄 **幂等设计**：重复执行或重复回调结果一致
- 🎯 **内置样例数据**：覆盖餐饮、差旅、采购三种发票类型

## 操作链路

```
init → import → check → detail → report
```

### 1. init - 初始化项目

```bash
# 初始化并导入样例数据
npm run dev -- init --sample
# 或全局命令
invoice init --sample
```

这将创建 `.invoice-checker` 数据目录，并导入完整的样例数据。

### 2. import - 导入数据

```bash
# 查看导入的发票列表
invoice list invoices

# 查看报销单
invoice list reimbursements

# 查看公司抬头库
invoice list headers
```

也可以从外部 JSON 文件导入：

```bash
invoice import invoices ./my-invoices.json
invoice import reimbursements ./my-reimbursements.json
```

### 3. check - 执行审核检查

```bash
# 检查所有发票
invoice check

# 检查单个发票（按发票号）
invoice check 20241201001
```

### 4. detail - 查看详情

```bash
# 查看某张发票详情
invoice detail 20241201001

# 同时查看操作历史
invoice detail 20241201001 --history
```

### 5. report - 查看汇总报告

```bash
# 查看所有报告
invoice report

# 筛选特定结果类型
invoice report needs_reissue
invoice report manual_review
```

## 一条失败路径

演示业务确实无法闭环的场景（税号错误必须重开）：

```bash
# 1. 初始化
npm run dev -- init --sample

# 2. 执行检查
npm run dev -- check

# 3. 查看汇总，应该能看到"需补开"的发票
npm run dev -- report

# 4. 查看税号错误的发票 20241201003
npm run dev -- detail 20241201003
```

**输出会清晰展示：**
- 发票税号：`91110108MA00C1235X`
- 预期税号：`91110108MA00C1234X`
- 错误类型：`税号不匹配`
- 纠错建议：`税号错误，需重新开具正确税号的发票`
- 最终判定：`[需补开]`

## 审核规则详解

### 1. 同一发票重复报销

**检测逻辑**：发票号 + 发票代码 组合唯一匹配。

**处理结果**：人工复核，需核实业务真实性。

### 2. 抬头近似但主体不同

**检测逻辑**：使用归一化 + 汉明距离算法，识别如：
- `创新科技北京有限公司` vs `创新科技（北京）有限公司`

**处理结果**：纠错建议，系统列出疑似正确的公司名称供人工确认。

### 3. 跨公司抬头

**检测逻辑**：根据员工部门 → 允许的抬头 → 集团 ID 三级校验。

**处理结果**：需补开，跨集团报销需走特殊审批流程。

### 4. 金额拆分报销

**检测逻辑**：同一发票关联多个报销单，累计金额超过发票总额。

**处理结果**：纠错建议，提醒核实拆分业务的真实性。

## 结果判断指南

不看源码的人员可按以下判断：

| 结果 | 图标 | 含义 | 下一步 |
|------|------|------|--------|
| 自动通过 | ✅ | 所有检查通过 | 可进入报销下一环节 |
| 纠错建议 | ℹ️ | 存在潜在风险 | 建议人工核实后继续 |
| 人工复核 | ⚠️ | 存在异常情况 | 需财务人员判断 |
| 需补开 | ✗ | 存在严重错误 | 必须退回重开发票 |
