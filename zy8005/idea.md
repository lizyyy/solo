            ## 原始点子

            我想做一个本地命令行工具，帮客户成功团队在把小型 CRM 数据迁到新系统之前做一次离线预检。场景是旧系统导出了几张 CSV，比如 accounts、contacts、activities，新系统这边有一份目标表结构 JSON，还有一份字段映射配置，可以用 YAML 或 JSON；工具运行后要先告诉我哪些数据能迁、哪些会出问题，再生成迁移 SQL、回滚 SQL 和一份可读的预检报告。不要做成单文件脚本，最好是一个清楚的 Python 包加 CLI 入口，能在本机直接跑示例数据。

具体流程希望是：我在命令行传入 `--source-dir`、`--schema`、`--mapping` 和 `--out`，工具会读取多张 CSV，按映射配置把字段转换到目标表，检查必填字段、类型长度、枚举值、邮箱/手机号这类格式、跨表外键引用、重复客户、孤儿联系人和跟进记录引用不存在的客户等问题。预检结果要有风险分级，能区分阻断迁移的错误和只需要人工确认的警告；如果预检存在阻断错误，默认不要生成最终迁移 SQL，但可以通过 `--force` 生成带注释的草稿，报告里要说明为什么不建议直接执行。

迁移脚本部分不要只是把 CSV 行拼成 insert。请根据目标表之间的依赖关系排序，先写 accounts 再写 contacts 和 activities，并为每条记录生成稳定的源数据追踪注释；同时生成 rollback SQL，能按相反顺序删除本次导入的数据。需要考虑字段值里有引号、换行、空字符串、超长文本、重复自然键、映射配置漏字段、目标 schema 里存在默认值、CSV 表头大小写不一致、时间格式混乱这些边界情况，错误信息要能定位到文件名、行号和字段名。

请附带一套最小但真实的 sample 数据、schema 和 mapping，让我可以一条命令跑出完整的 `out/report.md`、`out/report.json`、`out/migrate.sql`、`out/rollback.sql`。README 里写清楚安装和运行方式，最好有 `python -m ...` 或 console script 的例子；代码结构请拆出配置解析、CSV 加载与规范化、校验规则、依赖排序、SQL 生成、报告生成和 CLI 几个模块，并补一些针对解析、校验和 SQL 转义的测试，方便我判断不是只做了一个表面 demo。
