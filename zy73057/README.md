# 电梯故障备件排程系统

解决月底靠维修照片手工核对时「异常被平均值盖住」的问题。核心三件事：人工改判影响链路讲得清、备件替换落到可执行动作、补录重跑历史不中断且导出口径一致。

## 快速开始

```bash
pnpm install
pnpm dev       # 同时启动前端 5173 + 后端 3001
# 浏览器访问 http://localhost:5173
```

## 两三步操作指南

### ① 查一批排程、导出、留筛选签名

1. 打开首页「排程列表」→ 左侧抽屉筛选（日期段 / 批次号 / 电梯号 / 是否人工改判 / 备件型号 / 状态）。
2. 顶部点击 **导出 CSV 并生成筛选签名**，下载文件后，签名会显示在按钮旁（按钮上同时标注该批命中的批次/行数），复制保存。
3. 之后需要追回同一批记录：顶部导航「按签名追回」→ 粘贴签名 → **还原筛选并定位同批**，即可回到当时的筛选结果；页面会显示签名保存时记录数与当前记录数对比，若数量一致为绿色通过，若不一致（有补录重跑）会高亮提示。

#### 复核人两三步（坏材料来了先按页面筛选导出，再用签名追回同一批）

1. **导出口径**：在「排程列表」左侧按实际复核维度筛选（例：选日期=2026-06-08 当天，或状态=已改判）→ 点 **导出 CSV 并生成筛选签名**；按钮旁会展示该批命中了多少个批次、多少条排程，CSV 明细严格限定在这些批次内。
2. **签名追回**：把 CSV 连同签名一起发给复核人；复核人回系统点顶部「按签名追回」→ 粘贴签名，系统会自动把筛选条件还原为导出时的同一套，并定位到同一批 ID。
3. **口径核对**：追回页显示"签名时记录数 / 当前记录数"对比，数量一致则直接点「前往排程列表查看」开始复核；若数量不一致（期间有补录重跑），页面会用警示黄提示差异，并以导出签名保存的记录数为准。

### ② 人工改判一条，看为什么影响结论

1. 任意批次卡片展开，找「操作」列 → 点 **人工改判**（或直接找 `B-2026-06-W2` 批次，样例已预置 1 条改判）。
2. 填改判后备件号 / 数量 / 原因 / 影响说明后提交。
3. 卡片头点 **查看改判分析 →** 进入分析页：
   - 第 1 张指标卡是改判数量；第 3 张若差额超均值 10%，会出现红色呼吸脉冲（异常没被平均值盖住）。
   - 下方横向 4 节点链路（改判记录 → 影响排程行 → 备件型号差 → 月度汇总差），点节点看详情。
   - 最下方历史版本并排对比，断档会出红色警示横幅（没断档是绿色）。

### ③ 补录照片后重跑，检查历史是否断档

1. 首页选有 `draft` 状态的批次（样例 `B-2026-06-W1` 父版本就是断档）。
2. 点顶部或底部的 **补录重跑当前筛选批次**，填写补录说明。
3. 系统生成新版本并自动对比，进入分析页的「历史版本对比」区即可看到差异行高亮与「断档风险 / 已修复」横幅。

## 坏材料来了，该看哪里

> 对应替换动作 `blocked` 状态的 `blockingNote` 字段，样例见批次 `B-2026-06-W2` 的改判分析页「备件替换动作清单」第 1 行。

按 3 步走：

1. **入口**：改判分析页 → 「备件替换动作清单」→ 找到 `状态 = blocked` 的行，点击行首 ▶ 展开 `blockingNote`。
2. **Note 里写什么**：仓库坏料反馈（批次号 / 检测值 / 退回原因）+ 明确下一步（联系谁 / 换哪一批次备用料 / 截止日期）。
3. **落地动作**：直接在同一行操作列 → 下拉切换状态（`in_progress` 处理中 → `done` 完成；处理不了标回 `blocked` 并补充阻碍说明）。指派人输入框 blur 即保存，不要手工记到 Excel。

如果 blockingNote 仍指向「排查路径见 README 第 2 条」，说明管理员还没填，联系备件管理员将 Note 更新为实际坏料处置记录。
