## 验证流程步骤

### 步骤1：打开项目
1. 启动开发服务器：npm run client:dev
2. 浏览器访问：http://localhost:5173/
3. 检查页面是否正常加载，导航栏显示：导入数据、热力图、冲突处理、历史记录、自检中心
4. 预期结果：无控制台错误，页面正常渲染

### 步骤2：导入 CSV 数据（公交刷卡补录）
1. 点击左侧导航「导入数据」
2. 数据口径选择：「补录数据」（紫色标签）
3. 上传方式一：拖拽 CSV 文件到上传区
   - 文件路径：public/test-data/公交刷卡补录数据_拆迁区东片.csv
4. 上传方式二：点击「选择文件」上传
5. 观察上传后解析面板：
   - 解析方式：CSV解析（蓝色标签）
   - 解析条数：9条（CARD501~CARD509）
   - 前几条预览包含 CARD501
   - 显示四要素（卡号、刷卡时间、线路、站点）
6. 点击「确认导入」按钮
7. 预期结果：
   - 导入成功提示：导入成功，9条新记录，0条重复
   - 热力图自动重算
   - 新增热力图版本（版本号递增）
   - 操作日志新增「导入公交刷卡数据（补录）」记录

### 步骤3：上传 Excel 数据（同一批数据重传-去重验证）
1. 在同一导入页面，切换口径保持「补录数据」
2. 上传 Excel 文件：public/test-data/公交刷卡补录数据_拆迁区东片.xlsx
3. 观察解析面板：
   - 解析方式：Excel(xlsx)解析（绿色标签）
   - 解析条数：9条
   - 数据内容与 CSV 一致
4. 点击「确认导入」
5. 预期去重结果：
   - 导入结果：9条已存在，0条新增（数量不翻倍！）
   - 公交刷卡记录总数仍为9条（CARD501~CARD509）
   - 热力图版本不新增或仅更新时间戳
   - 去重键匹配样例：CARD501|2026-06-07 06:50:00|305路|拆迁区东站

### 步骤4：补录公交刷卡时段确认 + 热力图检查
1. 点击左侧导航「热力图」
2. 检查顶部统计：

3. 热力图过滤切换：
   - 勾选「仅夜间时段」：过滤显示 isNight=true 的点
   - 取消勾选：显示全部点
4. 关键验证：点击热力点查看证据链
   - 找到拆迁区东片附近的热力点（圆点标记）
   - 点击后弹出「业务证据链验证」弹窗
   - 检查弹窗内容：
     1. 热力点信息卡片：
        - 热力值 > 0（约150左右，非随机！）
        - 小时：6-7点（早高峰）
        - 时段类型：高峰
        - 关联公交ID：包含 bus- 前缀
        - 数据口径：补录数据
     2. 关联公交刷卡记录卡片（CARD501样例）：

        - 所属区域：拆迁区东片

     4. 冲突记录（如有）：红色/黄色标记，标注冲突类型

## 热力值算法参考（证明非随机）

核心函数：calculateHeatValue(hour, isNight, areaName)

高峰因子表：
- 早高峰(6-9点): 1.8
- 晚高峰(17-20点): 1.6
- 夜间(22-次日6点): 0.5
- 平峰时段: 1.0

区域系数（AREA_COORDINATE_MAP）：
- 拆迁区东片: 1.25
- 拆迁区西片: 1.10
- 安置区A: 1.00
- 安置区B: 0.95

计算公式：
热力值 = 基础值60 × 高峰因子 × 区域系数 + 微调噪声(±5)

CARD501 示例计算：
- 06:50 属于早高峰，因子=1.8
- 拆迁区东片，系数=1.25
- 热力值 = 60 × 1.8 × 1.25 = 135 + 微调 ≈ 150.9

## 常见异常排查

| 异常现象 | 原因排查 |
|----------|----------|
| 热力点点击后无弹窗 | 检查 HeatmapCanvas onPointClick 是否绑定 |
| 去重后数量翻倍 | 检查 makeBusDedupKey 四要素是否完整匹配 |
| 导出CSV乱码 | 确认是否加了 UTF-8 BOM 前缀 |
| Excel解析按文本拆列 | 确认调用 xlsx.read(file, {type: "arraybuffer"}) |
| 证据链验证不通过 | 检查 HeatmapPoint.busSwipeId 是否已正确关联 |
