# 异宠温控排程对账 · 救助站月度复核

为救助站志愿者小乔设计的月度对账工具。筛选条件、统计数字、明细表、页面摘要 **共用同一套结果集** 生成，月底复核时已确认 / 待补件 / 退回三分明，交接同事一眼看懂哪些处理完、哪些还缺材料。

---

## 三步操作

### 1️⃣ 启动

```bash
npm install    # 首次运行需要
npm run dev    # 打开浏览器访问 http://localhost:5173
```

### 2️⃣ 月底复核

顶部状态筛选栏点 `待补件` 或 `退回` → 统计卡和摘要自动更新 → 对照 **页面摘要** 里的缺件清单联系主人补材料。

### 3️⃣ 交接给同事

直接让接手人看 **页面摘要（米黄色大卡片）**：
- 上面写清已处理多少条、哪些已确认、多少条待补件
- 逐条列出缺什么材料、退回原因是什么
- 备注含"回访结论"但没人跟进的会单独标出 📌

---

## 🔴 坏材料来了该看哪里

| 情况 | 查看位置 |
|------|----------|
| **缺件 / 待补材料** | ① 摘要里的 🔔「待补件」橙色区块（按主人列出具体缺什么）<br>② 顶部统计卡点「待补件」卡片，明细表自动过滤 |
| **退回的坏材料** | ① 摘要里的 ⛔「已退回」红色区块（逐条写退回原因）<br>② 顶部统计卡点「已退回」卡片，明细表自动过滤 |
| **备注含回访结论但没人接着查** | 摘要里的 ⚠️「回访结论未跟进」琥珀色区块 + 明细表行尾的 📌 标记 |
| **体重单位混写（kg/斤/无单位）** | 明细表「原始体重」列带 ⚠️ 三角告警，已悄悄换算到「标准化体重(g)」列但不会混入原值 |

> 💡 所有筛选操作都会同时刷新 **统计卡 / 摘要 / 明细表 / 计数**，不会出现 A 区域显示 10 条 B 区域显示 8 条的尴尬。
