# 诊疗预约冲突检查 CLI

一个用于检测医院诊疗预约冲突的命令行工具，帮助识别医生、诊室和设备资源占用冲突，特别是处理临时加号后的冲突问题。

## 功能特性

- **排班导入**: 支持 JSON 和 CSV 格式的排班数据导入
- **资源占用检测**: 同时检测医生、诊室、设备三种资源的时间冲突
- **跨午夜处理**: 自动处理跨午夜的预约（如夜间急诊）
- **冲突解释**: 提供详细的冲突原因和严重程度分级
- **历史记录**: 保存检查历史，支持与上次检查对比
- **报告导出**: 生成 JSON 和 Markdown 格式的冲突报告及修复建议
- **数据验证**: 导入前验证数据完整性，避免坏数据

## 快速开始

### 安装依赖

```bash
npm install
```

### 查看帮助

```bash
node cli.js --help
```

## 命令详解

### 1. 导入排班数据

```bash
# 导入 JSON 数据
node cli.js import examples/schedule_normal.json

# 仅验证数据，不保存
node cli.js import examples/schedule_bad_data.json --validate

# 覆盖已存在的重复记录
node cli.js import examples/schedule_conflict.json --overwrite

# 导入 CSV 数据
node cli.js import examples/schedule_csv_sample.csv
```

**说明**:
- 支持格式: `.json`, `.csv`
- `--validate` / `-v`: 只验证数据格式，不写入数据库
- `--overwrite` / `-o`: 遇到相同 ID 时覆盖原记录（默认跳过）

### 2. 检测预约冲突

```bash
# 全量检测
node cli.js check

# 指定日期范围检测
node cli.js check --start 2024-05-10 --end 2024-05-11

# 仅检测特定资源类型
node cli.js check --resource doctor   # 医生
node cli.js check --resource room     # 诊室
node cli.js check --resource equipment # 设备

# 禁用跨午夜拆分检测
node cli.js check --no-midnight

# 保存检测结果到历史
node cli.js check --save-history
```

**冲突严重程度**:
- 🔴 **严重**: 重叠 > 30 分钟
- 🟡 **中等**: 重叠 1-30 分钟  
- 🟢 **轻微**: 边界接触

### 5. 导出报告

```bash
# 导出 Markdown 格式报告

# 导出 JSON 格式报告
```

### 6. 运行完整工作流

```bash
node cli.js workflow
```

这将自动执行以下步骤：
1. 导入正常排班数据
2. 验证冲突数据（不保存）
3. 导入冲突数据（含临时加号）
4. 检测所有冲突
5. 导出 JSON 和 Markdown 报告

### 7. 清除数据

```bash
# 交互式清除
node cli.js clean

# 强制清除（跳过确认）
node cli.js clean --force
```

## 数据格式

### JSON 格式

```json
[
  {
    "id": "apt_001",
    "patientId": "P001",
    "patientName": "张三",
    "startTime": "2024-05-10T08:00:00.000Z",
    "endTime": "2024-05-10T08:30:00.000Z",
    "doctorId": "D001",
    "roomId": "R001",
    "equipmentId": "E001",
    "appointmentType": "regular",
    "description": "常规门诊"
  }
]
```

### CSV 格式

```csv
id,patient_id,patient_name,start_time,end_time,doctor_id,room_id,equipment_id,appointment_type,description
apt_001,P001,张三,2024-05-10T08:00:00.000Z,2024-05-10T08:30:00.000Z,D001,R001,E001,regular,常规门诊
```

### 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| id | 否 | 预约唯一标识（自动生成） |
| patientId | 是 | 患者ID |
| patientName | 是 | 患者姓名 |
| startTime | 是 | 开始时间 (ISO 格式) |
| endTime | 是 | 结束时间 (ISO 格式) |
| doctorId | 是 | 医生ID |
| roomId | 是 | 诊室ID |
| equipmentId | 否 | 设备ID |
| appointmentType | 否 | 预约类型 |
| description | 否 | 描述 |

## 典型使用场景

### 场景 1: 日常排班检查

```bash
# 1. 导入当天排班
node cli.js import schedule_20240510.json

# 2. 检测冲突
node cli.js check --save-history

# 3. 如有冲突，导出报告
node cli.js export
```

### 场景 2: 临时加号后复查

```bash
# 1. 先查看当前状态
node cli.js list
node cli.js check

# 2. 导入加号数据（覆盖模式）
node cli.js import emergency_additions.json --overwrite

# 3. 重新检测
node cli.js check --save-history

# 4. 对比上次检查（查看变化）
node cli.js history
```

### 场景 3: 跨午夜排班

```bash
# 导入夜间排班
node cli.js import night_shift.json

# 检测（自动处理跨午夜）
node cli.js check

# 查看跨午夜预约
node cli.js list --only-midnight
```

### 场景 4: 数据质量检查

```bash
# 验证数据但不导入
node cli.js import new_schedule.json --validate

# 查看无效记录的详细错误
# 输出中会显示："第 1 行: 结束时间必须早于开始时间"
```

## 注意事项

1. **时间格式**: 请使用 ISO 8601 格式（如 `2024-05-10T08:00:00.000Z`）
2. **时区**: 建议统一使用 UTC 时间，避免时区问题
3. **ID 唯一**: 相同 ID 的记录在默认模式下会被跳过，使用 `--overwrite` 覆盖
4. **跨午夜**: 跨午夜预约会被自动拆分到两天进行检测，结果会标记 `(跨午夜)`
